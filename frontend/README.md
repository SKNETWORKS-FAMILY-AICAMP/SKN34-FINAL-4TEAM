# STORYFORK Web

React·TypeScript·Vite·Tailwind CSS 기반의 개발 화면입니다.
이름 기반 작품·Fork·서재는 데모 데이터입니다. `/content`·`/studio/{UUID}`는 같은 출처의 Content API, 인증·프로필·기기 관리는 Core API를 호출합니다.
이메일 확인 전 자동 로그인하지 않으며 운영 약관은 미정입니다. 알 수 없는 UI 경로는 `/`로 이동합니다.

## 목표 서비스 경계 (DEC-41)

[4개 백엔드 서비스 구조](../docs/design/service-boundaries.md)에 따라 Core는 회원·인증·크레딧·회원 알림, 별도 Kotlin/Spring Boot 콘텐츠 앱은 창작·독서·콘텐츠 정본과 인가, 별도 Kotlin/Spring Boot 운영 앱은 문의·공지·신고 사건·운영 결정·감사·작업 감시를 담당합니다. Python AI 앱은 허용 문맥에서 생성·검토를 실행하며 정본·권한·발행·정산을 확정하지 않습니다. LLMOps는 운영 영역이며 Langfuse 도입 시 별도 제품으로 배포합니다. 자체 UI와 운영 화면 API 통합 중 방식은 미정입니다.

nginx/Vite는 기존 `/api/v1/works`·`/api/v1/public/works`·`/api/v1/public/genres`·`/api/v1/public/card-categories`와 하위 경로를 Content:8081, `/api/v1/operations/{reports,members,admins,support,works,comments,genres,credits,world-studios,card-categories,feedback-reports,admin/notices,public/notices,admin/events,public/events,admin/activities,dashboard,llmops,alerts,jobs}`와 하위 경로를 Operations:8082(서비스 토큰용 `/api/v1/operations/{notices,events,inquiries}`는 열지 않음), 나머지 `/api`를 Core:8080으로 분기합니다. 관리자 대시보드(예전 개요)·사용자·관리자 계정·작품·댓글·신고·공지·이벤트·활동 로그·LLM Ops·정기 작업·장르·카드 카테고리·세계관·크레딧 탭(작품 표의 행을 누르면 작품 상세 드로어에서 회차·연결 세계관을 보고 회차를 제한), 제보·문의 탭의 회원 고객지원 문의와 작가 검토 제보(운영 독자 제보 열람 API로 최신순 읽기만 하며 처리는 작가가 하고, `--mode mockup`만 메모리 데모, [계약](../docs/design/feedback-report-suggestion-contract.md#운영자-열람-750-사용자-결정-2026-11-24)), `/me/inquiry`(문의하기·내 문의), 회원 공지사항(`/me/notice`, 로그인 불필요)과 회원 `/me/event`(비로그인 열람 가능), 공개 작품 신고(서버 작품의 검색 카드 더보기 메뉴·작품 상세 ‘소설 신고’ 버튼)와 회차 신고(독자 회차 화면 ‘신고’)·세계관 신고(공개 세계관 상세 ‘세계관 신고’), `/reports`(내 신고)는 운영 API를 호출하며 그 밖의 관리자 탭(캐릭터챗)은 메모리 데모입니다. 운영 API 탭의 조치는 메모리 데모 조회(댓글·캐릭터챗 등)의 로딩·실패와 무관하게 실행됩니다. 관리자 대시보드의 '서비스 지표(전체 기간)'는 대시보드 응답의 `funnel`(Content 집계)을 단계 막대 4묶음·회차당 반응·Fork 기준 회차 분포로 그리고 비율마다 오차 ±1/√n(%p)와 n을 적으며(분모 0은 —) Content를 읽지 못하면 0으로 채우지 않고 '불러오지 못함'으로 보입니다. 크레딧 탭은 열면 전체 회원(최신 가입순)과 행별 보유 크레딧을 보이고(검색은 좁힘) 회원을 골라 잔액·내역을 읽고 지급·회수(금액 정수 1~100,000, 사유 필수 200자, 확인 대화, 처리 중 잠금, 잔액 초과 회수는 409 안내)를 요청하며, 이벤트의 '이동 경로(선택)'는 사이트 안 경로만 받아 회원 이벤트 안내(`/me/event`)에 '바로 가기' 버튼을 만듭니다([계약](../docs/design/operations-funnel-credit-contract.md), DEC-57). 관리자 작품 탭은 운영 작품 API로 공개·비공개·운영 제한 작품 전체를 읽어 '운영 제한'·'제한 해제'를 요청하며(`--mode mockup`은 데모 작품 메모리), 분류·검색·정렬은 받은 목록에서 화면이 계산합니다([계약](../docs/design/operations-work-contract.md)). 작품·세계관 장르 선택지와 홈·세계관 장르 칩은 하드코딩 목록 없이 공개 장르 목록 `GET /public/genres`를 읽고(읽지 못하면 실패와 다시 불러오기), 관리자 장르 탭(`/admin?tab=genres`)이 운영 장르 API(`/api/v1/operations/genres`)로 그 목록을 관리합니다([계약](../docs/design/genre-management-contract.md), DEC-56). 관리자 활동 로그 탭은 운영 활동 기록 API로 관리자 변경 조치 최신 100건을 최신순으로 읽어 시각·수행자(닉네임, 없으면 ID)·조치·대상·내역을 보이며 서버가 정렬·권한(`admins`)을 맡고 `--mode mockup`은 데모 조치 메모리를 보입니다([계약](../docs/design/operations-admin-activity-contract.md)). 관리자 대시보드는 운영 대시보드 API로 회원·답변 대기 문의·접수 신고·작가 검토 대기 카드를 보이고 읽지 못한 출처의 칸은 0이 아니라 ‘불러오지 못함’입니다(AI 요청·진행 중 작업·미확인 경고 카드와 최근 7일 AI 사용 차트는 LLM Ops 에이전트 지표 위로 옮겼고, 차트는 지표 API로 따로 읽어 `llm` 권한이 없으면 권한 안내만 보입니다). LLM Ops는 사이드바 세 메뉴(주소 `?tab=llm&view=`, 없거나 모르는 값은 에이전트 지표, 옛 `view=traces`·`quality`·`eval`은 새 위치로 이어짐)로 나뉘어, ‘에이전트 지표’(기본)는 AI 요청·경고 요약 카드와 최근 7일 차트 아래에 기능(에이전트)별 카드(요청 수·실패율·p95 지연·비용 숫자와 처리 결과·지연 작은 막대, 같은 값은 표에도)를 보이고 보기 전환 ‘추적’에서 Langfuse를 운영 서비스가 중계한 추적(요청 ID로 찾기·단계 표)을 보이며, ‘프롬프트·평가’는 전체(AI 파이프라인: 노드 목록·기록 패널의 ‘프롬프트 보기’, 사이드바 ‘프롬프트·평가’ 아래 하위 탭(전체·인물 시뮬레이션·원고 전처리·원고 검수·고증 조사·기획·집필·수정)으로 고르는 내부 흐름 — 서버 노드가 없는 단계는 점선 노드. 고른 흐름은 프롬프트 목록·에이전트별 평가 표도 그 흐름의 프롬프트·짝 세트로 거르고 표 위에 ‘전체 보기’ 해제 링크가 있음)를 기본 보기로 두고 에이전트별 평가 표(행 이름은 한국어로 자세히)·프롬프트의 개선 루프(① 프롬프트 ② 평가 세트(평가 데이터셋 목록(세트 종류 평가 게이트·최적화 풀·범용 표시·거르기, 고른 흐름의 게이트와 그 풀만)·문항·JSONL 업로드(서버 `DatasetRules`와 같은 세트 종류별 필수 칸·정답표의 설정 core·파일 안 중복을 올리기 전에 검사): 운영 서버 API #868로 Langfuse Dataset을 읽고 있는 세트에 올림, `--mode mockup`은 같은 계약의 메모리) ③ 평가 ④ 자동 개선 ⑤ 게이트(③·⑤는 짝 세트가 기준 Run보다 늦게 바뀌었으면 ‘세트가 바뀌어 다음 평가에서 기준 버전을 먼저 다시 평가해요(비용 두 배)’를 알림) ⑥ 서비스 반영, 승격은 평가 통과 뒤)·모델 단가를 보이며(프롬프트 이름은 한국어 이름이 주·코드는 작은 보조 글씨, 모델을 고르지 않은 버전은 서버가 주는 실제 기본 모델 ‘기본 모델 · gpt-…’, 서버가 못 알려 줄 때만 파이프라인 기록에서 찾은 ‘기본 모델 · 최근 사용 …’), ‘경고·누설 감시’는 운영 경고 알림이 여는 화면에서 메모와 함께 확인·조치 완료를 기록하고 경고 기준을 정하며(`llm`·`jobs` 권한이 없으면 안내) 누설 검사 기록·표본 비율을 보이며, 정기 작업은 전처리와 운영 정기 작업의 실행 기록(실패 재실행은 확인 뒤, 앞쪽 1,000건까지만 쪽 이동)과 일정 관리(수정은 기존 종류를 담은 전체 본문)를 보입니다([계약](../docs/design/operations-llmops-contract.md)). 정기 작업·LLM Ops의 조회가 403(권한 없음)이면 일반 실패 문구와 다시 불러오기 대신 필요한 권한(‘정기 작업’·‘LLM Ops 조회’)만 안내하고 모델 등록·평가 실행 폼도 숨깁니다. 관리자는 Langfuse 웹에 들어가지 않으므로 Langfuse 링크는 없고, `--mode mockup`은 같은 모양의 예시 메모리입니다. 신고 메뉴·버튼은 남의 공개 작품에서만 보이고(본인·비공개 작품은 숨김이며 접수 권한은 서버가 검사. 검색 카드의 메뉴는 카드 위 오른쪽 모서리에 떠 있는 44px 더보기 버튼이 열고, 검색 조건이 바뀌면 열려 있던 신고 시트는 닫힘), `--mode mockup`의 메모리 작품 신고는 메모리에만 기록됩니다. 브라우저는 상대 URL·기존 Bearer/쿠키/CSRF를 유지하며 내부 인증 endpoint·AI·DB·모델을 직접 호출하지 않습니다. 소스 연결과 hosted CI·실제 DB 전환·배포는 구분하며 운영·알림 데모를 서버 완료로 간주하지 않습니다.

## 실행

Node **24.x**, pnpm **11.22.x** (`packageManager: pnpm@11.22.0`)가 필요합니다.

```bash
pnpm install --frozen-lockfile
pnpm dev
```

네이티브 web/Core/Content는 `http://localhost:5173`/8080/8081입니다. 콘텐츠는 같은 origin의 상대 `/api`로 호출하며 `VITE_DEV_PROXY_TARGET`과 `VITE_CONTENT_DEV_PROXY_TARGET`이 각각 Core/Content를 지정합니다.
직접 실행할 때는 공개 `VITE_CORE_API_BASE_URL` 등 필요한 변수만 터미널에 설정합니다. 루트 `.env`는 자동으로 읽지 않습니다.
루트 설정 자동 전달은 Compose를 사용하며 서비스별 `.env`는 만들지 않습니다.
`VITE_*`는 브라우저에 노출되므로 비밀값을 넣지 않습니다. 백엔드는 별도로 실행합니다.

루트의 [Compose 안내](../infrastructure/README.md)는 공통 `docker-compose.yaml`에 prod 또는 dev를 병합합니다.
prod는 소스에서 정적 배포 이미지를 빌드해 기본 `http://127.0.0.1:8088`로 검증하고, dev는 현재 개발 배포 서버에서 CI의 `:develop` 이미지를 pull·실행합니다.
두 조합 모두 Nginx가 정적 화면과 works 경로 → `content-service:8081`, 나머지 `/api` → `core-api:8080` 프록시를 제공합니다. 소스/HMR Compose는 제거했으며 hot reload는 위 `pnpm dev`를 사용합니다.
loopback 검증용이며 인터넷 운영 준비를 뜻하지 않습니다.

## 프론트엔드 구조와 상태 소유

- `app/di`에서 Repository·UseCase와 Health·알림 SSE 외부 함수를 조립합니다. Presentation은 Data 함수를 직접 import하지 않으며, 공유 Health·SSE 계약은 Domain에 둡니다. HTTP 응답의 Zod 검증은 Data에 남깁니다.
- Redux `session`은 인증·로그인 안내와 기존 조회 무효화 신호를, `ui`는 테마·화면 ID·읽기 설정·홈 표시 상태를 소유합니다. UI 상태는 로그인·로그아웃 때 유지하며 브라우저 저장소에 영속화하지 않습니다. `dataVersion`은 여전히 데모 전역 재조회 신호이며 기능별 캐시로 바꾸지 않았습니다.
- 관계 패널의 draft 상태·적용 handler는 `useRelationPairViewModel`, 순수 초기화·방향 변환은 Domain의 `relationDraft`가 담당합니다. 최초 baseline을 유지하고 기존 `applyRelationChanges`로 검증하며, 저장 전 편집과 실제 저장을 구분합니다.
- 집필실·서재가 함께 쓰는 `PublishSettingsSheet`는 `presentation/shared`에, Wiki 편집 화면은 `StudioWikiView`에 둡니다. 데모 피드백함과 실제 알림함의 ViewModel은 별도 파일입니다.
- 서버 집필실(`/studio/{UUID}`)은 왼쪽 회차 목록·버전 그래프 / 가운데 원고 / 오른쪽 AI 채팅의 3단입니다. 그래프 행의 순서·라벨·배지는 Domain의 `versionGraph`가 계산하고, 채팅은 이후 캐릭터챗도 쓰는 표시용 `presentation/shared/chat/ChatPanel`입니다. ChatPanel은 API를 부르지 않으며 메시지·전송·첨부는 호출하는 화면이 넘깁니다(집필 AI 채팅은 공용 `WritingChat`이 Content API로 연결하고, 첨부는 아직 "준비 중"입니다). 상단 `시뮬레이션` 버튼은 편집기를 대신하는 인물 시뮬레이션 무대(`shared/chat/SimulationStage`)를 가운데에 열고, 채팅에는 진행 상태 한 줄과 `무대 열기`만 남습니다([AGENTS.md](AGENTS.md)의 '인물 시뮬레이션 무대'). 창이 1200px 이하면 AI 채팅은 접힌 채로 시작하고, 900px 이하에서는 회차 목록이 한 줄 가로 스크롤 띠가 됩니다. 자동 저장은 화면을 잠그거나 알림을 띄우지 않고 상단 저장 상태만 바꾸며, 버전 저장 같은 완료 안내는 그 상태 줄에 이어 적습니다.
- 서버 집필실 본문은 Toast UI Editor 3(`@toast-ui/editor`, 마크다운 쓰기 모드) 기반 `ManuscriptEditor`이고 `LazyManuscriptEditor`로 늦게 불러옵니다(원작 기준 회차는 편집기 없이 공용 `ManuscriptBody`로 읽기 전용 본문을 그립니다). 툴바는 `굵게 · 기울임 | 소제목 · 인용 · 구분선 | 이미지` 여섯 개이고 `쓰기 | 미리보기`의 미리보기는 `ManuscriptBody`가 그립니다. 저장 글은 편집 영역의 글자 그대로이며(왕복 무손실) 서식 기호는 그릴 때만 해석합니다([계약](../docs/design/manuscript-format-contract.md), DEC-48). 편집 영역의 구문 강조는 계약의 서식만 보이도록 Toast의 강조를 다시 정했고, 이미지 표식 줄은 `widgetRules`와 포털로 실제 이미지로 보입니다. 40,000자 한도·잠금·이미지 줄 보호는 Toast의 `dispatchTransaction` 앞에서 거르고, 계약에 없는 서식을 넣는 Toast 단축키(취소선 Ctrl+S, 목록 Ctrl+U·O, 코드 Ctrl+Shift+C·P)는 받지 않습니다. Toast의 알려진 결함(열자마자 되돌리기로 글이 지워짐, 일부 글에서 구문 강조 예외, 줄 사이 편집에서 줄바꿈을 잃음)은 `presentation/shared/toastFixes.ts`가 막고 카드 편집기(`shared/MarkdownEditor`)도 같은 보정을 씁니다. 글자 수·공개 분량(5,000자, 서버가 검사하지 않는 화면 규칙) 판정은 `manuscriptLength`가 맡습니다. 화면 테스트는 `test/manuscriptEditorFake`(textarea 대역)를 쓰고 실제 편집기 동작은 `ManuscriptEditor.test.tsx`가 실제 Toast로 검증합니다.
- 순수 함수라도 Presentation 소유의 테스트는 해당 feature 옆에 둡니다. 현재 CI는 경로 기준으로 분류하므로 이 테스트는 Domain/Data 단위 명령이 아니라 기존 통합 선택에서 발견됩니다.

## 실제 호출 흐름

`/status`의 연결 확인은 `App → CoreApiConnectionStatus → useCoreApiHealth → DI 외부 함수 → Fetch·Zod → 공개 Core API`입니다. 해당 화면의 Health 전용 안내가 앱 전체의 구현 상태를 뜻하지는 않습니다.

- Core: `GET /api/v1/health`, `storyfork-core-api`와 `up` 검증.
- AI: `GET /api/v1/health/ai-service`, `storyfork-ai-service`와 `up` 검증.
- AI 내부 주소나 OpenAI를 브라우저에서 직접 호출하지 않습니다.
- Health는 OpenAI 키·모델 접근 검증이 아닙니다.

인증·계정 기능은 View → ViewModel → UseCase → Repository → Core API 흐름으로 요청합니다.

| UI 경로·진입점 | 화면·동작 | Core endpoint |
|---|---|---|
| `/me/signup` | 가입 요청 → 이메일 확인 대기 (자동 로그인 없음) | `POST /api/v1/auth/signup` |
| `/auth/resend-verification`, 로그인·가입·인증 실패 화면의 안내 | 이메일 1항목으로 확인 메일 재발송 (계정 존재 여부를 구분하지 않는 안내) | `POST /api/v1/auth/resend-verification` |
| `/auth/verify-email#token=…` | 메일 링크의 이메일 확인 → 로그인. 409(같은 이메일 회원이 이미 있음)는 가입 비밀번호 오류가 아니라 "이미 가입된 이메일이에요. 로그인해 주세요."로 안내하고, 그 밖의 거절은 가입 비밀번호·링크 만료 안내 | `POST /api/v1/auth/verify-email` |
| `/login` | 이메일·비밀번호 로그인, Core가 반환한 사용자·권한 반영. 빈 값·이메일 형식 오류는 요청을 보내지 않고 화면 오류로 안내하며 쓰던 비밀번호를 지우지 않음(요청을 보낸 뒤에만 지움). 403 + `code: "ACCOUNT_RESTRICTED"`는 이용 제한 안내(로그인 문의 링크 가리킴), 코드 없는 403은 일반 오류 | `POST /api/v1/auth/login` |
| 앱 시작 | HttpOnly refresh 쿠키를 통한 세션 복원 | `POST /api/v1/auth/refresh` |
| 상단 계정 메뉴 | 현재 기기 로그아웃 | `POST /api/v1/auth/logout` |
| 상단 계정 메뉴 | 보유 크레딧 한 줄(소수 첫째 자리까지, 버림 표시. 메뉴가 열릴 때 잔액만 조회, 닫히면 취소). 운영자 계정에는 `/admin` 바로가기 | `GET /api/v1/me/credits` |
| `/me/profile` | 서버 프로필 조회·오류 재시도, 닉네임 저장 | `GET /api/v1/me`, `PATCH /api/v1/me` |
| `/me/profile`의 이메일 저장 | 새 주소로 확인 메일 요청, 확인 전 기존 이메일 유지 | `POST /api/v1/me/email-change` |
| `/auth/verify-email-change#token=…` | 이메일 변경 확인 → 프로필로 돌아가 새로 조회 또는 로그인 | `POST /api/v1/auth/verify-email-change` |
| `/auth/forgot-password`, 프로필의 계정 보안 | 비밀번호 재설정 메일 요청 (계정 존재 일반화) | `POST /api/v1/auth/forgot-password` |
| `/auth/reset-password#token=…` | 새 비밀번호 검증·저장 → 로그인, 만료 시 새 링크 요청 | `POST /api/v1/auth/reset-password` |
| `/me/profile`의 로그인 기기 | 기기 조회·오류 재시도·개별 연결 종료 | `GET /api/v1/auth/sessions`, `DELETE /api/v1/auth/sessions/{id}` |
| `/me/profile`의 모든 기기 로그아웃 | 서버 성공 후 현재 세션 해제 | `POST /api/v1/auth/logout-all` |

- 변경 요청 전에 `GET /api/v1/auth/csrf`로 CSRF 토큰을 받습니다. 인증 링크의 fragment는 읽은 즉시 주소에서 제거하며, 토큰을 로그나 브라우저 저장소에 남기지 않습니다.
- access token은 메모리에만 두고 refresh 쿠키는 Core가 HttpOnly로 관리합니다. 인증 변경은 기존 Web Locks와 계정 소유자 검증을 사용하고, 보호된 요청의 401은 세션 갱신 후 한 번만 재시도합니다.
- 가입·비밀번호 재설정은 공백뿐인 비밀번호를 거부하고 8자 이상·UTF-8 72바이트 이하를 확인합니다. 재설정 입력 오류는 해당 필드에 안내하며 입력을 보존하고, 완료되거나 만료된 토큰은 다시 제출하지 않습니다.
- 프로필·기기 조회는 화면 이탈·재시도 시 AbortController로 취소합니다. 로그인·가입의 늦은 응답은 화면 이탈 후 상태나 자동 이동을 덮어쓰지 않도록 무시합니다. 이미 서버에 전달한 요청을 되돌린다는 뜻은 아닙니다.
- 로딩·실패·완료·빈 목록을 구분하고 중복 요청을 막습니다. Health 조회는 별도로 20초 제한과 취소를 사용합니다. 내부 예외는 화면에 노출하지 않습니다.
- 로그인·가입·재발송·복구·이메일 확인은 같은 인증 화면을 사용합니다. 데스크톱의 기존 STORYFORK 브랜드는 보존하고 모바일은 작은 로고와 현재 입력부터 표시합니다. 테마 전환은 일반 문서 흐름에 두며 페이지 이동은 링크를 사용합니다.
- 가입 오류는 해당 필드에 연결하고 첫 오류로 초점을 이동합니다. 복구·재발송 접수 후 입력한 주소와 스팸함 안내, 주소 수정·재요청 경로를 표시합니다. 이 주소 문맥은 화면 상태에만 두고 브라우저 저장소에 보관하지 않습니다.
- 상태 알림은 live region, 버튼은 키보드 포커스를 지원하고 애니메이션은 reduced-motion을 따릅니다. 기존 색상·타이포그래피·상태 스타일을 재사용합니다.
- 터치 대상 44px 보정은 `storyfork.css` 맨 끝의 `@media (max-width:600px),(pointer:coarse)` 블록 한 곳에서 하고 터치 기기에서는 입력 글자를 16px로 올립니다. 기능 CSS가 같은 속성을 다시 정하면 그 화면이 직접 보정합니다. 맨 위 스크롤은 다른 화면으로 넘어가는 이동(경로가 바뀌거나, 같은 경로에서 화면 내용이 통째로 바뀌는 쿼리 — 관리자 `tab`(LLM Ops는 쪽 `view`도), 공지·이벤트 `id`, 작품 관리 `work`, 검색 `q` — 가 바뀌는 PUSH·REPLACE)에서만 하고(`GlobalChrome`의 `SCREEN_QUERY`), 뒤로·앞으로와 그 밖의 쿼리(탭·필터·정렬) 변경은 보던 위치를 지킵니다. 토스트는 `role=status` 노드 하나를 유지하며 글자 수에 비례해 2.6~8초 머뭅니다.

실제 약관 동의·계정탈퇴·소셜 로그인·운영 메일 서비스·비용 정책은 이 연결 범위에 포함하지 않습니다. 계정탈퇴 UI는 기존 데모이며 실제 계정을 삭제하지 않습니다.

## 공개 열람 (기능 20)

- `/read/:id`·`/read/:id/:n`은 비회원도 로그인 없이 공개 회차를 읽습니다(UC-01). 세션 복원이 끝난 뒤 열어 로그인 회원이 새로 고칠 때 두 번 불러오지 않습니다. 포크 등 회원 전용 동작은 해당 화면(`RequireRole`)의 로그인 안내를 그대로 쓰고, 메모리 데모 작품 회차 화면의 댓글·댓글 좋아요·피드백도 비회원이 누르면 같은 로그인 화면으로 보내며 메모리에 저장하지 않습니다(`useReaderViewModel.requireMember`). 비회원의 열람은 서버 조회 기록을 보내지 않습니다.
- 실서버의 캐릭터챗 목록과 대화방 주소는 회원·비회원 모두에게 준비 중을 안내합니다(#512). `--mode mockup`에서는 누구나 데모 목록(`/chat`)을 볼 수 있고, 대화방(`/chat/:작품`·`/chat/:작품/:인물`)은 로그인 후 그 주소로 돌아와 이용합니다(#506). 검색의 전체 탭과 캐릭터챗 탭은 실행 모드에 맞춰 안내합니다.
- `/content`·`/studio/{id}`는 `RequireRole`로 가려 비로그인은 "로그인이 필요한 화면이에요" 안내와 함께 `/login`으로 보내고 로그인 뒤 그 주소(`?work=`·`?ep=` 포함)로 돌려보냅니다(#605). 소설 상세의 `소설 신고`도 좋아요처럼 비로그인이 서버 작품에서 누르면 시트 대신 로그인으로 보냅니다. 로그인한 소유자는 자기 비공개 작품(막 만든 Fork의 `/forked/:id` 등)을 보고, 운영자(관리자)는 소유권 없이 모든 작품을 열람합니다(남의 작품 집필실은 열람 모드로 쓰기를 막고, 내용 수정은 서버도 소유자만 받습니다, 2026-11-23).
- 로그인한 채 `/login`·`/me/signup`에 들어오면(세션 복원이 끝난 뒤 들어온 순간 한 번만 판단, `RequireGuest`) 메인(`/`)으로 보냅니다. 이 화면에서 방금 한 로그인은 위의 `requireLogin.next`로 돌아가고, 보호 화면이 다시 로그인을 요구해 보낸 경우(`next`가 있음: 세션 만료·관리자 계정 요구)는 로그인한 채여도 폼을 보입니다. 어떤 화면에도 맞지 않는 주소는 홈으로 보내지 않고 주소를 그대로 둔 채 404 화면('페이지를 찾을 수 없어요', 홈·작품 둘러보기 링크)을 보입니다(#620). `/write`→`/lib?tab=write`·`/new`→`/content` 같은 의도된 이동은 그대로입니다.
- 등록되지 않은 `/me` 하위 주소도 입력한 주소를 유지한 채 같은 404 화면을 보입니다(#734). `/me`는 프로필을 열고, `/me/signup`은 별도 가입 화면으로 처리합니다.
- 서버(정본) 작품의 작품 상세는 `설정 위키` 링크로 `/work/:id/wiki` 페이지(U45)를 열어 `readWorld`가 채운 공개 설정을 읽기 전용으로 보여 주고, 회차 화면 상단 `설정` 링크도 같은 페이지를 `?upto=n`으로 엽니다(돌아가기는 그 회차로). 서버가 기준 회차(작품 상세는 최신 공개 회차, 회차 화면은 그 회차)까지 공개한 설정만 주므로 화면은 거르지 않고 분류별로 묶어 표시하고, 없으면 "공개된 설정이 없어요"를 보입니다. 메모리 데모 작품에는 링크가 없고 위키 주소는 작품 상세로 돌려보냅니다.
- 서버(정본) 작품에서 AI 자율 집필이 켜져 있으면 소설 상세의 탭 `회차 | 정보 | 소식` 옆에 `다음 회차` 탭(`SerialBoard`, AI 자율 연재 UC-18, [계약](../docs/design/ai-serial-contract.md))이 있고 안은 하위 탭 `투표 | 제안 게시판`입니다. 로그인 회원은 AI가 만든 선택지 4개 중 1개에 투표(옮기기·취소)하고 제안 글(일반·시뮬레이션)을 개수 제한 없이 쓰고 추천하며, 소유자는 제안 글을 숨기고 비로그인은 읽기와 로그인 안내만 봅니다. 작품 관리의 `AI 집필` 탭은 하위 탭 `연재 설정 | 게시판 기록`입니다. 운영 설정의 집필 방식에서 `AI 자율 집필`을 새로 저장하려 하면 세계관 연결과 인물 카드(성격·말투·목표·관계) 작성을 경고하는(없으면 회차 실행이 실패합니다) 확인 대화 상자(`세계관·설정집으로`·`계속 저장`·`취소`)가 먼저 뜨고(경고일 뿐 저장을 막지 않습니다), 저장하면 AI 집필이 켜지고, 그동안 작가는 1화만 쓸 수 있어 서버가 2화부터의 원고 쓰기를 409 `SERIAL_LOCKED`로 막습니다. 집필실(1화가 아니면 읽기 전용·안내, 새 회차는 회차가 있으면 잠금)과 작품 관리(회차 목록의 `수정하기`는 1화 외에 잠금)가 같은 이유를 보입니다(켜짐 여부를 읽지 못하면 잠그지 않고 서버가 판정합니다).
- 작품에 연결된 세계관이 있으면(DEC-46, [계약](../docs/design/public-world-contract.md)) U45는 그 세계관의 **독자 공개 설정 카드**로 채웁니다. `useWorkWikiViewModel`이 작품을 읽은 뒤 `ReadingUseCase.linkedWorldCards` → `HttpWorkRepository.readWorldCards`로 `GET /api/v1/public/works/{id}/world-cards`를 Bearer 없이 읽고(주소에 `?upto=n`이 있을 때만 그 값을 보내며 없으면 생략해 서버가 발행된 마지막 회차로 정함), 응답의 `worldId`가 있으면 `reading/viewmodel/worldCardWiki.ts`가 카드를 같은 나무위키 형식의 문서로 바꿉니다: 카드 유형 8가지 순서의 묶음, 본문은 `CardMarkdown`(`## 제목`은 문서 제목 아래 소제목), 정보 상자에 별칭·태그·'N화부터'(카드에 `imageId`가 있으면 맨 위에 `GET /api/v1/public/works/{id}/world-card-images/{imageId}?upto=`를 위키가 받은 기준 회차 그대로 붙여 `<img>`로 직접 읽고 읽지 못하면 감춤, `Doc.cardImage`), 관계 `A → B 「관계명」`은 'B는 A의 관계명'으로 읽어(DEC-54) 보내는 쪽(A) 문서에 `B — 관계명` 소제목(B는 B 문서로 가는 링크)과 관계 설명(`body`, 마크다운)의 문단을, 받는 쪽(B) 문서에는 '이 설정을 가리키는 관계' 줄의 `A(관계명)` 링크를 둡니다(링크를 누르면 A 문서의 그 관계 문단(`relationAnchor`, 관계 id 기반)으로 이동해 초점을 옮기고 짧게 강조하며 `prefers-reduced-motion`이면 움직임 없이 고정 강조합니다). `direction`이 `symmetric`이거나 없으면 양쪽 문서 모두 문단이고 같은 상대·라벨의 별도 관계도 각각 문단입니다. 선택적인 `category`·`polarity`와 방향 미상은 소제목 옆 작은 글자로 알립니다. 「동일 인물」(`identity`)도 같은 규칙입니다(다른 이름 문서에 '본체 — 동일 인물' 문단, 본체 문서에 받는 쪽 링크). `worldId`가 null이면 위의 기존 작품 설정 위키 그대로입니다. "N화까지 공개된 설정만 보여요"와 회차로 돌아가기는 서버가 적용한 `upto`를 쓰고, 관계를 불러오지 못한 응답(`relationshipStatus: unavailable`)은 "설정 사이의 연결을 불러오지 못했어요"로 빈 연결과 구분해 알리며, 카드 조회가 실패하면 빈 위키로 바꾸지 않고 로드 실패(다시 시도)를 보입니다. 서버가 독자 공개 회차로 이미 걸러 주므로 화면은 거르지 않습니다.

## 서버 이미지·파일 (#92)

`MediaPanel / useMediaViewModel → MediaUseCase → MediaRepository → HttpMediaRepository`를 Awilix에서 조립합니다. 실제 작품·설정 UUID만 허용하고 데모 ID·실패 시 메모리 성공 fallback을 보내지 않습니다.

- `/content`: 작품 설정 전용 관리 화면이며 **주소가 화면을 정합니다**. `/content`는 새 작품 만들기(소설 상세 히어로 모양의 입력 화면, 만들면 `/content?work=<새 ID>`로 바꿔 관리 화면을 보임), `/content?work=<작품ID>`(서재 '집필 중인 작품' 카드를 누르면)는 그 내 작품의 관리 화면이며 내 작품이 아니면 '작품을 찾을 수 없어요'와 서재 링크를 보입니다. 작품 목록·고르기는 서재(`/lib?tab=write`)가 맡아 이 화면에는 작품 목록과 공개 작품 둘러보기가 없고, '내가 쓰는 소설' 링크(작품 관리는 사이드바 맨 위, 새 작품 만들기는 본문 맨 위)가 서재로 돌아갑니다. 관리 화면은 왼쪽 사이드바 메뉴(개요·공개 회차·세계관·설정집·이야기 분기·AI 집필·받은 피드백·내 댓글·제보·운영 설정·저장·AI·발행 이력은 읽기 전용)가 오른쪽 내용 열에 보일 내용을 고르고, 기본 탭 '개요'가 소설 상세 페이지처럼 히어로(표지·제목·장르·유형·AI 자율 연재 켜짐 칩·공개 상태·소개·해시태그)를 보이고 그 아래에 현황(작품 지표 카드: 공개 회차·작성 중인 초안·총 글자 수·포크 수·받은 피드백·누적 회원 조회·좋아요 — 비공개 작품의 독자 지표는 '공개 전', 모르는 값은 0으로 채우지 않음 · 최근 발행 이력 5건 · 바로가기: 집필실 열기, 공개 작품이면 소설 상세 보기)을 보입니다(독자 지표는 새 API 없이 공개 상세 `GET /public/works/{id}`의 `likes`·`episodeViews`를 `ReadingUseCase.readerStats`로 읽습니다. 공개 회차 탭은 회차 목록만). 히어로는 쉴 때 88px 표지 썸네일 + 제목·칩·소개(두 줄까지)·태그 한 덩어리로 줄고, 작품 정보·표지를 편집하는 동안만 옛 큰 히어로로 펴지며 그동안 다른 탭은 잠깁니다. 분기 정책(분기 작품은 포크 정보)과 작품 삭제는 모든 탭 위가 아니라 '운영 설정' 탭 안에 있습니다(운영 설정 탭은 집필 방식·자동 처리·설정 변경 이력·분기 정책(포크 정보) 카드이고 넓은 화면은 왼쪽에 집필 방식 카드(두 줄)·오른쪽에 자동 처리·설정 변경 이력, 그 아래 전체 폭의 분기 정책(포크 정보) 카드와 맨 끝 작품 삭제 위험 카드). 탭 구획의 폭은 모두 내용 열 폭이고, 각 탭 본문의 제목(h2)은 메뉴 탭 이름과 똑같은 글입니다(탭 안의 묶음 제목은 h3). 작품 관리는 세계관 관리처럼 공용 상단바(Gnb)·푸터 없이 사이드바(공용 `ManageMenu`)가 상단바 역할을 합니다: 맨 위 줄(로고·접기 토글)·돌아가기 링크·메뉴·맨 아래 줄(알림·테마·계정)이고(도구 묶음은 없습니다), 901px 이상에서는 화면 왼쪽 끝에 붙어 화면 높이를 쓰며 접을 수 있고 900px 이하에서는 로고·알림·테마·계정이 맨 위 한 줄, 메뉴가 그 아래에서 줄바꿈해 탭이 모두 보입니다. 사이드바 맨 앞의 '본문으로 바로가기'가 공용 상단바의 같은 링크를 대신해 내용 열로 초점을 옮깁니다(공용 틀 `.ep-manage`·`.ep-menu`·`.ep-menu-*`·`.ep-content`, `shared/episode.css` 한 곳). 메뉴를 눌러 탭이 바뀌면 그 내용 머리로 스크롤하고(첫 렌더·새로 고침은 그대로, 초점은 누른 버튼에 남음). 작품 정보(제목·소개·장르 1~2개·해시태그 10개까지, `PUT /works/{id}`)·표지·분기 정책(`PUT /works/{id}/policy`)은 영역마다 '편집' 버튼이 하나씩이며 저장/취소로 바꿉니다(한 번에 한 영역, 저장이 성공해야 읽기 표시로 돌아가고 실패하면 입력을 남김). 장르·해시태그는 생성 화면과 같은 선택지·검증을 쓰고 서버 값과 달라진 쪽만 본문에 실으며(생략하면 서버가 유지, 빈 배열은 비움) 장르가 없던 옛 작품도 제목만 고쳐 저장할 수 있습니다. 작품 유형은 등록 때 정해져 읽기 전용이고 공개 상태는 회차 공개 흐름이 정합니다. 공개 회차 행에는 그 회차에서 갈라진 공개 포크 수가 소설 상세와 같은 작품 목록(`ReadingUseCase`, 새 API 없음)으로 계산돼 branch 아이콘과 함께 보이고, 0편이거나 읽지 못하면 숨깁니다(0으로 채우지 않음). '받은 피드백' 탭은 작가 피드백함과 같은 조회에 `?workId=`를 보내 서버가 이 작품의 제보·수정 제안만 주며(`/inbox`는 쿼리 없이 전체) 화면이 다시 거르지 않습니다. '내 댓글·제보' 탭은 계정 메뉴의 `/content?view=reports` 화면과 같은 내용(`MyCommentsReports`)이 탭 안에 들어간 것으로, 쪽 제목 없이 구획 제목은 h3입니다. 원작은 '운영 설정' 탭 맨 끝의 '작품 삭제' 구획(분기 정책 아래)에서 확인 후 `DELETE /works/{id}`를 요청합니다(다른 영역을 편집하는 중에는 잠김). 소프트 삭제에 성공하면 서재로 돌아가고 기존 포크는 유지되며, 실패하면 맨 위 알림에 서버 사유를 보이고 관리 화면에 머뭅니다. 분기 작품은 포크 정보(분기 기준·방향, 원작으로 가기 — 원작이 삭제됐으면 안내만, 공개 중일 때 '포크 공개 중단' `DELETE /works/{id}/fork-publication`, '포크 삭제' `DELETE /works/{id}` 뒤 서재로 이동)를 보이고, 이야기 분기를 만들면 새 분기의 관리 화면으로 이동합니다. 원고 작성·AI 이어쓰기·회차 공개는 `/content`에서 제거됐고(집필실 이전은 후속), 집필실로 가는 버튼은 개요 바로가기와 공개 회차 탭 머리의 '집필실 열기' 둘뿐이고(사이드바에는 없고, 회차가 0개여도 집필실에서 1화를 만듭니다) 그 버튼들과 각 공개 회차의 '수정하기'(행 전체 클릭 포함)가 집필실(`/studio/{id}`, 회차는 `?ep=n`)로 보냅니다(작성 중인 초안은 집필실의 회차 목록에서 엽니다. 집필실 상단의 '뒤로'는 앱 안 이전 화면으로, 없으면 `/content?work=<id>`로 돌아갑니다. 실서버 집필실은 `?ep=n`의 회차를 처음에 열고, 없거나 범위 밖이면 첫 회차를 엽니다. 회차를 바꾸면 주소의 `?ep=n`도 기록을 쌓지 않고 따라 바뀌어 새로 고쳐도 보던 회차로 열립니다). 작품 만들기·분기 만들기의 실패 사유는 그 폼 안(버튼 위)에, 이력 탭의 불러오는 중·실패는 그 구획 안에 보이고, 그 밖의 요청은 맨 위 알림에 보이며 화면 밖이면 보이는 데까지 스크롤합니다. 이력 탭의 저장 버전 본문은 '원고 보기'로 펼칠 때만 그립니다.
- `/content` 세계관 연결(DEC-46): 세계관·설정집 탭의 `세계관 연결` 카드(`LinkedWorldPanel`, 그 위에 `원고로 세계관 만들기` 카드)가 이 소설과 내 세계관(WorldStudio)의 1:1 연결을 맡습니다. 연결돼 있으면 `연결된 세계관: {이름}`(→ `/worldstudio/<id>`)과 `연결 해제`(확인 뒤)를, 아니면 다른 소설에 연결되지 않은 내 세계관을 고르는 `세계관 연결`(검색 화면과 같은 `세계관 검색` 입력으로 이름을 거른 표지 카드 목록(표지·이름·설정 카드 수)에서 고르며, 처음에는 아무것도 고르지 않아 고르기 전에는 버튼이 잠기고 이유를 알립니다. 고른 세계관이 검색으로 목록에서 빠지면 선택을 비우고, 연결을 해제하면 선택과 검색어를 비웁니다)을 보이고 `PUT /api/v1/works/{id}/world-studio`(`EpisodeUseCase.linkWorldStudio`, `worldId: null`이 해제)로 바로 적용하며 응답의 연결로 열린 작품의 `worldStudioId`를 바꿉니다(작품 revision은 그대로). 내 세계관 목록(`worldStudioUseCase.list()`의 `linkedWorkId`)은 탭을 열 때 한 번 읽어 불러오는 중·실패(다시 불러오기)·고를 세계관 없음(세계관 만들기 링크)을 따로 보이고, 남의 것·없는 세계관(404)이나 이미 다른 소설에 연결된 세계관(409 `WORLD_ALREADY_LINKED`)은 서버 문구를 그 카드 안에 그대로 알리고, 연결·해제 완료 안내도 카드 안에 보입니다. 자기 세계관이 없는 Fork(DEC-37, #583)는 이 카드 위에 `이어받는 원작 세계관` 카드를 따로 보입니다(`useInheritedWorld` → `EpisodeUseCase.inheritedWorld`): '원작 「제목」 세계관을 N화 기준으로 이어받는 중'과 카드 유형별 수·제목·관계 수를 읽기 전용으로 보이고(관계 상태를 모르면 0개로 채우지 않고 '불러오지 못했어요', 읽지 못하면 빈 상태로 바꾸지 않고 실패와 다시 불러오기, 이어받은 카드가 없으면 독립 버튼을 잠그고, 이어받는 것이 없으면 카드를 그리지 않습니다), `내 세계관으로 만들어 수정하기`는 확인('독립하면 원작 세계관의 이후 변경은 따라오지 않아요…') 뒤 `POST /api/v1/works/{id}/inherited-world/detach`(`EpisodeUseCase.detachInheritedWorld`, 본문 없음, 201 `{workId, worldId}`)를 보냅니다. 요청 중에는 `useEpisodeViewModel`의 busy가 버튼·탭을 잠가 중복 전송을 막고, 성공하면 열린 작품의 `worldStudioId`를 새 세계관으로 바꾼 뒤 `/worldstudio/{worldId}`로 이동하며, 거절(이어받을 것 없음·이미 독립 409 `FORK_WORLD_NOT_INHERITED`, 관계 상태 불명 503)은 서버 문구를 그 카드 안에 그대로 알립니다(`origin: 'detach'`). `--mode mockup`은 '데모에서는 지원하지 않아요' 오류입니다. 그 아래 설정집 요약 카드는 작품 설정집의 이름·상태·최초 분기 기준을 보이고, 원작을 따라가며 따라가던 설정이 있는 옛 작품 설정집 방식 Fork(원작에 세계관이 없음, #737)에는 같은 `내 세계관으로 만들어 수정하기`(같은 확인·요청·이동·실패 알림, 설정을 내 세계관의 카드로 복사해 독립)를, 독립해 세계관이 연결된 설정집에는 그 세계관으로 가는 `연결된 세계관 열기` 링크를 보입니다.
- `/content` 표지: 작품 생성 시 PNG/JPEG 표지 선택(생성 화면도 같은 히어로 모양), 생성된 작품의 표지 조회·교체(편집에서 고른 파일은 '저장'을 눌러야 올라감)·삭제·새로고침. 작품만 생성되고 표지 업로드가 실패하면 생성된 작품을 유지하며 표지만 재시도합니다. 표지 편집과 생성 화면의 'AI로 생성'은 아직 연결 전이라 비활성이며 보이는 글자로 '준비 중'을 알리고 API를 호출하지 않습니다.
- `/content` 설정집: 세계관·설정집 탭의 `설정 첨부` 카드(`WorldPanel`)는 옛 작품 설정이 있는 작품의 기존 첨부를 그대로 보이고 받는다: 확정했거나 저장한 초안인 설정을 고르면 그 설정의 `MediaPanel`이 붙어 이미지·TXT/MD/CSV/PDF 목록/업로드/다운로드/교체/이름 변경/삭제를 합니다(업로드 중에는 탭 이동이 잠기고, 옛 설정이 없는 새 작품은 '세계관 스튜디오의 설정 카드에서 첨부하라'고 안내합니다). 이름 변경은 확장자를 고정하고 서버의 거부 사유를 그대로 보이며 실패하면 입력을 남깁니다. following 설정은 로컬 독립 전 첨부하지 않습니다. 공개 설정도 첨부 자체는 소유자 전용입니다.
- 설정 카드 첨부(#735): `/worldstudio/{id}?card=` 카드 편집 화면의 개요 탭 맨 아래 `이미지·파일 첨부`(`WorldCardAttachments`)가 서버에 저장된 카드를 대상(`{ kind: 'card', worldId, cardId }`)으로 같은 `MediaPanel`을 붙여 올리기·목록·다운로드·교체·이름 변경·삭제를 합니다. 세계관을 저장하는 동안은 잠기고 아직 저장하지 않은 새 카드는 '세계관을 저장하면 이 카드에 참고 파일·이미지를 첨부할 수 있어요'로 안내하며, 서버 저장소가 없는 데모(메모리)에는 첨부 영역이 없습니다. 첨부는 세계관 소유자 전용이라 공개 세계관·독자 설정 위키에는 나오지 않고, 카드 대표 이미지(`CardImageControl`)와는 별개입니다.
- `/studio/{UUID}`: 실제 회차 본문의 커서/선택 영역에 불변 이미지 `[[image:<UUID>]]` 참조 삽입, 초안·버전 저장/재진입/복원/발행 및 읽기 미리보기. 업로드 후 초안이나 버전을 저장해야 참조가 보존됩니다. 과거 버전을 위해 원본을 지우지 않으므로 회차당 업로드 총 10개는 marker 삭제로 반환되지 않습니다.
- 같은 출처의 Bearer/CSRF multipart 요청을 사용하며 JSON Content-Type을 강제하지 않습니다. 비공개 이미지 bytes를 인증 fetch 후 Blob URL로 표시하되 같은 이미지를 함께 그리는 곳들은 한 번 받은 주소를 나눠 쓰고 마지막 사용처가 사라질 때 revoke하며, 화면 가까이 올 때까지는 내려받지 않습니다. 토큰·스토리지 URL·base64를 서버 원고에 저장하지 않습니다.
- 중복 요청을 막고 취소·이탈 뒤 늦은 결과를 적용하지 않습니다. 취소/네트워크 응답 유실은 서버 rollback을 의미하지 않으므로 목록 새로고침으로 실제 상태를 확인합니다. 실패하면 기존 파일/원고를 유지합니다.
- PNG/JPEG 표지·본문 및 설정 파일은 파일당 10 MiB 이하입니다. 서버가 바이트·픽셀·권한·한도를 최종 검증합니다. 집필실 원고 내보내기는 아래 절처럼 서버가 만든 TXT(이미지 제외)·EPUB(이미지 포함)입니다.

실서버에서는 내 서재의 **새 소설 쓰기** 카드와 '집필 중인 작품' 제목 줄 오른쪽의 `+ 새 소설` 버튼(같은 주소), 기존 주소 `/new`가 `/content`의 작품 만들기로 연결됩니다. 목록 행의 주 버튼은 연보라 톤이고, 채운 보라 버튼은 제목 줄 `+ 새 소설`·`+ 새 세계관` 하나입니다. 서재 '집필 중인 작품' 카드에는 공개 범위 칩(`공개 중`·`비공개`)이 있고 AI 자율 집필이 켜진 작품이면 `AI 자율 연재` 칩(카드마다 소유자 `GET /works/{id}/ai-serial`로 읽고, 읽는 중·읽기 실패는 칩 없음)이, 분기 작품이면 `분기 작품` 칩과 `「원작」 N화에서`가 이어지며, 서재 카드의 버튼은 보조 → 주(줄 오른쪽 끝) 순입니다(집필 중인 작품은 `회차 작성하기` 하나, 내가 만드는 세계관은 버튼 없이 카드 전체가 작업실을 열고, 읽는 중은 글자 버튼 `기록 삭제` → `▶ N화 이어 읽기`, 읽는 중 행 제목은 `h3`). 세계관 작업실의 소설 버튼(관리 모드는 '소설 연결' 탭, 작성 모드는 헤더 행동 줄)은 한 자리입니다: 그 세계관에 연결된 소설이 있으면 그 작품 관리(`/content?work=<id>`)로 가는 **소설 작성하기**, 없으면 같은 자리의 **소설 연결하기**이고 그 시트의 `새 소설 만들기`가 작품 만들기(`/content`)로 갑니다(만든 소설은 자동으로 연결되지 않아 돌아와서 연결합니다). 작품을 만들면 전용 설정집과 첫 회차 초안이 함께 생성됩니다. 만들 때 세계관을 고르는 입력·조합, 연재 요일, 연령 제한, 생성 시 인물 입력은 데모 폼에서만 제공되고, 실서버의 세계관 연결은 만든 뒤 작품 관리의 세계관·설정집 탭이나 세계관 작업실의 소설 연결 탭에서 합니다. `--mode mockup`에서는 `/new`의 기존 새 소설 폼이 브라우저 메모리에서 동작하고 세계관 작업실의 `소설 작성하기`도 그 폼으로 갑니다.

이름 기반 `/studio/starlight` 등의 개요·Wiki 이미지 선택은 브라우저 메모리 데모입니다. 인접 안내·toast에서 서버 미저장을 알리고 `/content`로 연결합니다. 표지 논리 삭제·미참조 원본 보존과 API/권한/운영 한계는 [Core 계약](../backend/core-api/README.md#작품-표지원고-이미지-92)을 참고하세요.

## 공개 세계관 둘러보기

상단 Gnb의 **세계관**은 `/worlds`(홈과 같은 구성의 공개 세계관 추천 대시보드: 장르 칩 → 홈 상단과 같은 2단(왼쪽 'STORYFORK 세계관 지도', 오른쪽 '실시간 인기' 세계관 순위) → 세계관 모아 보기(서버에 인기 지표가 없어 '인기 세계관' 선반이 없고, 순위·모아 보기와 같은 세계관을 되풀이하는 '새로 공개된 세계관' 선반도 두지 않음), 추천이 아닌 칩은 2단과 그 장르 목록 하나)와 `/worlds/:id`(제목·작가 아래 설정 그래프·인물관계도·설정집·개요 네 탭을 읽기만 하는 상세)를 엽니다. 로그인 없이 볼 수 있고 이 화면에서 편집하지는 않습니다. 로그인한 회원에게는 가져오기 진입점 둘이 보입니다(DEC-46, 아래): 설정집 게시판의 `선택한 설정 가져오기`, 설정 카드 페이지의 `이 설정 가져오기`(상세 헤더의 `내 세계관으로 가져오기`는 없앴고, 설정과 관계를 함께 가져오는 길은 내 세계관 관리 화면의 `다른 세계관에서 가져오기`입니다).
**데이터**는 Content 공개 세계관 API([계약](../docs/design/public-world-contract.md))입니다. `View → useWorldsViewModel → PublicWorldUseCase → HttpPublicWorldRepository`를 Awilix에서 조립하고, 목록 `GET /api/v1/public/world-studios?genre=&page=&size=`(공개 + 저장 버전이 있는 세계관, 최근 공개 순)와 상세 `GET /api/v1/public/world-studios/{id}`(마지막 저장 버전의 **공개** 설정 카드 + 그 카드끼리의 현재 관계. 설정 카드는 기본 비공개이고 서버가 공개 카드만 주므로 화면은 거르지 않습니다, DEC-46)를 Bearer·CSRF 없이 읽고 Zod로 검증합니다(Vite·nginx는 `public/world-studios`를 Content로). `/search`는 `?type=all|work|world|card|chat` 탭입니다(`searchTabOf`: `type`이 없거나 모르는 값이면 전체이고, 탭이 생기기 전의 작품 검색 링크처럼 `f`·`sort`가 주소에 있으면 작품). 세계관·설정 카드 탭([계약](../docs/design/work-search-ranking-contract.md#세계관설정-카드-검색-505))은 같은 저장소로 목록의 `q`(이름·설명·작가)와 `GET /api/v1/public/world-studios/cards?q=&page=&size=`(`searchCards`, 독자에게 보이는 카드의 제목·별칭·태그)를 `searchWorlds`·`searchCards`가 읽습니다. 두 탭은 쪽당 24개이고 서버가 센 `total`로 만든 번호 쪽(`이전 1 2 3 … 다음`, 공용 `Pager`와 순수 함수 `paginate.pageNumbers`·`pageParam`)으로 넘기며, 현재 쪽은 주소 `?page=`(1부터)에 남아 새로 고쳐도 같은 쪽이고 탭·검색어를 바꾸면 1쪽입니다. 쪽을 바꾸면 결과 머리(h1)로 스크롤·초점이 가고, 읽는 중·실패에도 번호 줄이 남으며, 마지막 쪽을 넘은 `page`는 마지막 쪽으로 바꿉니다. 작품 탭은 총 개수를 몰라 '더 보기'를 유지합니다. 전체 탭은 작품(첫 쪽의 앞 6개)·세계관·설정 카드(`size` 6)를 묶음마다 따로 읽어 불러오는 중·실패(다시 불러오기)·결과 없음을 묶음별로 보이고(한 묶음의 실패가 다른 묶음을 가리지 않습니다) 묶음마다 '‘검색어’ … 더 보기 ›'로 그 탭에 가며, 설정 카드 묶음·탭은 검색어가 없으면 요청 없이 안내하고 캐릭터챗(묶음·탭)은 검색 없이 안내와 `/chat` 링크만 보입니다. 빠른 이동(Ctrl/Cmd+K, `useQuickViewModel`)은 검색어가 있으면 작품 후보 뒤에 같은 `PublicWorldUseCase`로 세계관·설정 카드를 3개씩 찾아(입력이 250ms 멈춘 뒤 한 번, 새 입력·닫기에는 이전 요청 취소) `세계관`·`설정 카드` 배지로 붙이고 `/worlds/:id`·`/worlds/:worldId/cards/:cardId`로 이동하며, 한 묶음이 실패하면 그 묶음만 빼고 목록 끝에 안내 한 줄을 보입니다. Enter의 '검색 결과 모두 보기'는 `/search?q=`(전체 탭)입니다. UseCase는 목록을 24개씩 최대 4쪽까지 이어 붙이고(그보다 많으면 최근 공개 순 앞쪽만 보이며 지도 통계 줄과 모아 보기 머리가 전체 수를 알림), 지도·'실시간 인기'는 늘 전체 목록으로 만들고 장르 칩은 `genre` 쿼리(칩 라벨 ↔ 서버 코드 `worldGenres.ts`)로 '모아 보기' 목록만 다시 읽습니다. 불러오는 중·실패(다시 시도)·공개된 세계관 없음("아직 공개된 세계관이 없어요 · 내 서재에서 세계관을 공개해 보세요", `/lib?tab=worlds` 링크)·비공개/없는 세계관(404 → "찾을 수 없는 세계관")을 실제 조회 결과대로 그리고, 화면을 떠나거나 장르·세계관이 바뀌면 이전 요청을 취소하며 늦은 응답은 버립니다(`useAsyncData`). 파생·조합은 서버에 없어(설정 가져오기가 대신합니다, DEC-46) 실제 모드는 해당 표시를 숨기고, 연결된 소설은 상세 응답의 `linkedWork`(공개 작품일 때만, #329)로 받습니다(아래 각 항목). 실제 모드의 목록 위에는 가져오기를 어디서 하는지 한 줄로 알립니다(로그인 회원 "설정 가져오기는 각 세계관 상세에서 할 수 있어요", 비로그인 "로그인하면 각 세계관 상세에서 공개 설정을 내 세계관으로 가져올 수 있어요"). `--mode mockup`은 같은 계약을 `data/mock/InMemoryPublicWorldRepository`가 `demoPublicWorlds.ts`의 데모 세계관 26개(파생 12·조합 6, 카드 점·카드 연관·작품·한 줄 소개 포함)로 답하고 칩 줄 아래에 "데모" 안내를 띄웁니다. 서버에 없고 데모에만 있는 값은 `domain/entities/publicWorld.ts`의 "데모 전용" 선택 필드입니다.
**세계관 지도**는 홈 히어로가 있던 왼쪽 칸(`.herow`, 캔버스 높이 데스크톱 380px·모바일 340px)에 놓인 노드 그래프(`react-force-graph-2d`, 라이트·다크 모두 어두운 캔버스, 통계 줄은 카드 아래쪽, 범례는 데모 지도만 그 아래, 카드 높이는 오른쪽 '실시간 인기' 패널과 같고 남는 높이는 지도 면이 받습니다)로, 공개 세계관이 장르별로 모인 모습을 보여 줍니다. 노드는 장르(큰 고정 크기)·세계관(설정 카드 수와 상관없이 모두 같은 크기)이고 장르→세계관은 옅은 선입니다. 맞춤(`zoomToFit`)과 화살표 끝은 그린 반지름으로 잽니다(`nodeVal`). 서버 목록은 장르와 카드 수만 주므로 실제 모드의 지도는 여기까지이고 범례는 두지 않습니다(범례에 남는 것이 장르 색뿐인데 장르 이름이 노드에 늘 그려집니다). 파생(한 세계관을 가져다 새로 만듦)·조합(여러 세계관을 섞어 만듦)과 설정 카드 점(작은 점, WorldStudio 지도와 같은 유형 색)은 메모리 데모에만 있습니다(세계관→카드는 옅은 선, 원본→파생은 실선 화살표, 원본들→조합은 점선 화살표, 통계 줄과 범례에 파생·조합). 세계관·카드 노드를 누르면 그 세계관 상세로, 장르 노드를 누르면 그 장르 칩이 골라지며(장르가 없는 세계관의 '미지정' 노드는 칩이 없어 누르지 않음), 장르 칩이 골라지면 그 장르(데모는 파생·조합으로 바로 이어진 노드까지)만 밝고 나머지는 흐려집니다. 캔버스에 늘 그리는 이름은 장르뿐이고 세계관·카드 이름은 마우스를 올린 노드 하나만 그립니다(HTML 툴팁이 아니라 캔버스에 직접 그리며 확대 정도와는 연동하지 않습니다). 터치 기기(`pointer: coarse`)에서는 한 손가락 끌기가 페이지 스크롤이 되도록 지도 이동·노드 끌기를 끄고(`worlds/view/useNodePointer.ts`), 이름이 숨은 노드는 첫 탭에 이름을 보인 뒤 다음 탭에 엽니다. 캔버스 아래 컨트롤(`MapControls`)의 방향 이동 버튼 넷(한 번에 보이는 영역의 4분의 1, `worlds/view/mapPan.ts`)은 터치 기기와 키보드로 컨트롤에 들어온 동안에만 보이며, 세계관 상세의 두 그래프도 같은 규칙입니다. 마우스 휠이 페이지 스크롤을 가로채지 않도록 Ctrl(⌘)+휠일 때만 확대합니다. `prefers-reduced-motion`이면 배치를 미리 계산해 움직이지 않습니다. 지도는 눈으로 훑는 용도라 캔버스는 `role="img"`와 요약 `aria-label`로 알리고, 이름 탐색은 오른쪽 순위와 아래 모아 보기가 맡습니다.
**세계관 상세**(`/worlds/:id`)는 제목·(데모만 한 줄 소개)·작가만 위에 두고 그 아래에 네 탭(설정 그래프·인물관계도·설정집·개요, `role="tablist"`, 좌우 화살표·Home·End로 이동, 선택은 `?tab=graph|people|book|overview`에 남아 새로고침·공유해도 그대로이며 기본은 설정 그래프, 탭을 옮길 때는 기록을 쌓지 않음)을 둡니다. **설정 그래프**는 세계관을 중심으로 설정 카드(WorldStudio 지도와 같은 유형 색)가 이어진 노드 그래프이고 중심→카드는 옅은 선, 카드끼리의 연관은 진한 선이며 노드가 30개 이하라 이름을 늘 캔버스에 그립니다(HTML 툴팁 없음). **인물관계도**는 인물 카드만 노드로 하고 인물 사이의 관계를 라벨 있는 선(캔버스 텍스트)으로 그리며, 인물이 2명 미만이면 빈 상태 문구를 보이고, 서버가 관계를 불러오지 못했다고 알리면(`relationshipStatus: unavailable`, 카드는 그대로 오고 관계만 비어 옴) 빈 그래프와 구분해 "관계를 불러오지 못했어요"를 보이며(설정 그래프의 연결 수도 0 대신 그렇게 알림), 메모리 데모만 위에 "데모 · 공개 범위 확정 전"을 둡니다. 두 그래프는 세계관 지도와 같은 어두운 캔버스 카드·컨트롤(`useMapCanvas`·`MapControls`)을 쓰고 캔버스 높이만 데스크톱 460px·모바일 340px이며, 노드를 누르면 그 설정 카드의 페이지(`/worlds/:id/cards/:cardId`)로 이동합니다(세계관 중심 노드는 설정집 탭). 캔버스는 `role="img"`와 요약 `aria-label`로 알리고 같은 내용은 설정집 게시판과 카드 페이지가 글로 대신합니다. **설정집**은 설정 카드를 카테고리별로 보는 게시판입니다: 위에 한 줄 요약(장르·작가·설정 카드 수, 데모는 파생·조합된 세계관 수), 왼쪽에 분류 메뉴(전체·카드가 있는 유형별 장수, 선택은 `aria-current`이고 `?tab=book&type=<유형>`에 남음), 오른쪽에 검색(제목·본문)·정렬(설정집 순·연결 많은 순·가나다순)·결과 수 도구와 게시판 표(`<table>`, 번호 · 분류(유형 색 점) · 제목(굵은 링크, 옆에 인물은 관계·그 밖은 연결 수 `[3]`) · 요약(한 줄 말줄임) · 연결 수)를 둡니다. 행 전체가 아니라 제목 링크가 카드 페이지로 가는 주 링크이고, 좁은 화면(720px 이하)에서는 분류 메뉴가 가로 스크롤 칩이 되고 표는 번호·요약 열을 숨깁니다. 설정집 탭에는 개요를 두지 않습니다. **개요** 탭(`view/WorldOverview.tsx`)이 세계관 설명(비어 있으면 '아직 세계관 설명이 없어요.')과 정보 상자(작품 설정 위키(`PublicWikiArticle`)와 같은 `nw-*` 클래스·CSS(`reading/view/publicWiki.css`): 세계관 이름·표지·장르·작가·설정 카드 수, 데모는 파생·조합 출처)를 보이고, 계보가 있는 데모는 설명 아래에 출처 한 줄과 이 세계관에서 파생·조합된 세계관 줄이 붙습니다. 600px 이하에서는 네 탭이 사이 간격 없이 폭을 나눠 한 줄에 들어갑니다. 필터·정렬·번호(`bookRows`)·분류 장수·`?type=` 해석은 `features/worlds/worldDetail.ts`의 순수 함수이고 단위 테스트가 있습니다. 카드와 관계는 서버 응답의 카드 id·현재 관계(양 끝 카드 id)로 만들고, 같은 두 카드 사이의 여러 관계는 ID마다 그래프에 그리고 카드별 관계 수에도 각각 셉니다. 상세 헤더에는 가져오기 버튼을 두지 않습니다. 로그인한 회원은 설정집 게시판에서 줄마다 체크박스(머리 칸은 `보이는 설정 모두 선택`)로 고른 뒤 **`선택한 설정 가져오기 (N)`**(`WorldAddMenu`, 공용 `PopMenu`)를 엽니다: 열 때 내 세계관(`worldStudioUseCase.list()`, 원본 세계관 자신은 제외)을 읽어 불러오는 중·실패(다시 시도)·가져갈 세계관 없음(세계관 만들기 `/worldstudio`)을 따로 보이고, 내 세계관을 고르면 이동 없이 고른 설정만 그 세계관 **초안에 바로 추가·저장**합니다(`worlds/viewmodel/useWorldImport.ts`: `worldStudioUseCase.read` → 공용 `presentation/shared/importCards.ts`의 `importCards`·`appendImported` → `save`. 관계 제외·비공개·출처 기록). 진행·결과와 실패 사유·`다시 시도`는 그 자리에 보이고 실패를 성공으로 바꾸지 않습니다.
**설정 카드 페이지**(`/worlds/:id/cards/:cardId`, 로그인 없이 읽기만, `cardId`는 서버 카드 id이고 데모는 카드 위치)는 카드 한 장이 나무위키 형식 문서 한 편입니다: 빵부스러기(세계관 › 유형 › 카드, 유형은 설정집의 그 분류로 돌아감) → 분류 상자 → 문서 제목 → 오른쪽 정보 표(대표 이미지가 있으면 맨 위에 그 이미지(공개 `GET /api/v1/public/world-studios/{id}/card-images/{imageId}`를 `<img>`로 직접 읽고 읽지 못하면 감춤, 설정집 게시판 줄은 제목 앞 작은 썸네일), 이어서 유형 색 칩, 인물은 소속(이어진 조직)·관계 수, 그 밖은 연결 수, 세계관) → 번호 목차 → 번호 매긴 접이식 문단(본문은 마크다운(`react-markdown`+`remark-gfm`, 원시 HTML·이미지는 렌더하지 않음)이고 `#`·`##`·`###` 제목마다 문단이 나뉘어 하위 문단이 상위 문단 안에 들고(번호 `1`·`1.1`·`1.1.1`, `####` 이하는 본문 소제목) 목차는 그 제목들이며 첫 제목 앞의 글은 '개요' 같은 제목을 지어 붙이지 않고 목차 아래에 제목·번호 없이 그립니다(`shared/cardSections.splitCardSections`). 이어서 관계(이 카드가 보내는 관계와 방향 없는 관계마다 `상대 — 관계명` 하위 문단과 관계 설명, 번호 목차에 `3.1.`처럼 듦), 이 설정을 가리키는 관계(받는 쪽 링크 `상대(관계명)`, 본문 링크로 가리킨 카드는 `상대(본문 링크)`), 같은 유형의 다른 설정 — 내용이 없는 문단은 빠지고 번호는 끊기지 않음). 받는 쪽 링크는 보내는 쪽 카드 페이지의 그 관계 문단(`#rel-…` 앵커, 관계 id 기반)으로 이동해 초점을 옮기고 짧게 강조하며(`prefers-reduced-motion`이면 고정 강조) 접힌 문단이면 펼칩니다(DEC-54). 모든 목록은 설정집 순서입니다. 아래에 설정집 순서의 이전·다음 설정과 세계관으로 돌아가기(`/worlds/:id?tab=book`)가 있고, 그 세계관에 없는 카드 id·비공개/없는 세계관은 "찾을 수 없는 설정"·"찾을 수 없는 세계관"으로, 읽는 동안·실패는 불러오는 중·다시 시도로 따로 알리며 같은 세계관의 다른 카드로 옮겨도 세계관을 다시 읽지 않습니다. 목차 링크는 기본 이동을 막고 `scrollIntoView`와 `focus({preventScroll:true})`로 이동합니다(`prefers-reduced-motion`이면 부드럽게 스크롤하지 않음, 공용 `shared/Jump`). 내용 구성(`cardPage`)은 `worldDetail.ts`의 순수 함수입니다. 로그인한 회원에게는 빵부스러기 아래에 `이 설정 가져오기`가 보이고, 내 세계관을 고르면 이 카드 하나를 그 세계관 초안에 바로 추가·저장합니다(이동 없음, 관계 제외, 진행·결과·실패는 버튼 아래).

목록(초점이 있을 때 보임: 설정마다 버튼 하나, Enter 정보 편집·Delete 삭제·메뉴 키, 초점이 간 설정의 관계 목록은 Enter 관계 편집·Delete 관계 삭제)이 같은 일을 하고 캔버스는 `role="img"`(설정·관계 수)입니다. 관리 모드의 관계도 보기는 세계관 머리 없이 캔버스가 내용 열 전체 폭 × 화면 끝까지를 채우고(위쪽은 관계 기준 회차 한 줄뿐이고 삭제된 설정 알림이 있을 때만 한 줄이 더 생기며 안내문은 캔버스 아래 가운데에 겹친 작은 글입니다) 관리 모드에는 푸터가 없습니다. 카드 삭제는 설정집 편집 화면의 `카드 삭제`와 같은 확인(이어진 관계 수)을 거치고 지운 뒤 `삭제 되돌리기` 알림이 남습니다. 삭제된 설정과 이어진 관계는 그릴 노드가 없어 위 한 줄이 개수만 알립니다(저장 때는 그대로 유지). `관계 기준 회차` 칸('이 회차 시점으로 보기', DEC-51: 소설을 연결한 서버 세계관만, 비우면 최신 — 고르면 그 회차 시점의 관계를 다시 읽고 저장에도 그 회차를 보내지만 그 회차로 기록되는 것은 삭제한 관계뿐이며(바꾸거나 새로 쓴 관계는 관계 행의 `[ ]화부터`가 정합니다), 저장하지 않은 변경·AI 후보 검토·확정 버전 요청 중·데모·소설 미연결이면 이유와 함께 잠기고, 지난 회차를 연 채 관계를 삭제하면 저장 영역이 `삭제한 관계 N개는 M화에서 끝나는 것으로 저장돼요`를 알리며, 회차를 고른 동안은 설정 삭제가 잠기고(삭제는 최신 회차에서만) 삭제된 설정을 끝점으로 하는 지난 회차 관계는 `삭제된 설정: 이름`으로 읽기 전용), 관계 작성은 기존 초안·적용 흐름 그대로 '편집본에 적용'·세계관 저장으로 반영합니다(선·카드의 삭제는 확인 뒤 편집본에서만 지우고 저장해야 서버에 반영됩니다). 관계 편집 행마다 `[ ]화부터` 입력이 있어 그 관계가 보이기 시작하는 회차를 정하고(DEC-54 2단계, 소설을 연결한 서버 세계관은 1 이상의 정수가 필수라 비었거나 잘못되면 `aria-invalid`로 이유를 알리고 '편집본에 적용'과 저장을 막으며, 연결하지 않은 세계관은 칸을 숨기고 1화로 저장합니다). 이미 기록된 시작 회차보다 늦춘 값은 독자에게 기록된 회차부터 보인다고 칸 아래에서 알립니다. 관계 작성 패널의 `동일 인물`(DEC-53, #485) 칸은 인물 카드끼리만 다른 이름 카드 → 본체 카드로 잇고(본체는 select로 고르며 사슬·순환·본체 둘은 `assertIdentityLinks`가 막고 서버도 거절), 새로 쓰거나 바꾸는 적용은 그 행의 `[ ]화부터`가, 끝내는(지우는) 적용은 관계 기준 회차가 있어야 합니다(소설을 연결하지 않은 세계관은 1화 하나뿐이라 `HttpWorldStudioRepository`가 `episode: 1`로 보냅니다). 설정 삭제는 회차를 지정할 수 없어 서버가 422로 거절하므로 같은 저장소가 「동일 인물」을 새로 쓰거나 바꾸거나 끝내는 저장을 설정 삭제(그 관계와 상관없는 설정 포함)와 함께 보내지 않고 둘로 나눠 저장하라고 알립니다. 본체가 '작가 전용'이면 다른 인물이 본체를 알 수 있다고 경고하고, 다른 이름 카드의 편집 화면은 성격·목표·회차 기억을 본체 카드에 적도록 안내하며, 시뮬레이션 시작 양식은 같은 사람의 두 카드를 함께 고르지 못하게 막습니다(내 세계관은 읽은 identity 관계로, Fork가 이어받은 원작 세계관은 `GET /works/{id}/inherited-world` 응답의 identity 쌍(`InheritedWorld.identity`, 부정 제외)으로 후보에 본체 카드 id(`person`)를 달아 막습니다). `/worldstudio`(세계관 없음)는 새 작품 만들기와 같은 모양의 새 세계관 만들기 화면이고, 내 세계관 목록은 그 아래에 작게 남아 다른 세계관 열기에 쓰입니다. 이 만들기·목록 화면은 `/worldstudio`에서만 그리며 관리 주소(`/worldstudio/:id`)에는 숨겨서라도 두지 않습니다. '세계관 만들기'가 성공하면 `/worldstudio/{id}?new=1`로 이동해 마법사로 엽니다.

세계관을 읽지 못하면 오류 곁에 `다시 시도`(같은 주소를 다시 읽습니다)와 `내가 만드는 세계관으로 돌아가기`가 보입니다. 편집 중 저장 실패에는 다시 시도를 두지 않습니다(다시 읽으면 입력이 사라집니다).

세계관 초안을 읽을 때는 카드·관계의 정본 필드(제목·본문·영역·분류·태그·별칭, 관계의 양 끝·극성·관계명·설명)가 항상 이기고 `semanticMetadata.studio`는 시간 표기·순서·관계 종류 같은 보조값만 보탭니다. 모양이 틀린 studio와 모르는 키는 읽을 때 버리고(`preprocessing`·`manuscriptBuild`·관계 `evidence`만 저장 때 되돌려 보냅니다) 고쳐 저장한 카드만 정리됩니다. 정본의 enum·id·관계 끝점이 어긋난 응답만 세계관 전체를 읽지 않습니다([계약](../docs/design/worldstudio-independent-schema.md#초안-semanticmetadata-계약-541)).

## 원고 가져오기·내보내기 (기능 17·18)

[계약](../docs/design/manuscript-import-export-contract.md)대로 `ManuscriptRepository`·`ManuscriptUseCase`·`HttpManuscriptRepository`를 Awilix에서 조립합니다.

- `/import`(실제 모드): 내 작품 선택(`?work=<UUID>`로 사전 선택) → 권리 확인 3가지 → `.txt`·`.epub` 파일 → 서버 미리보기(회차별 제목 수정·제외·다음 회차와 합치기·경고) → 확정 → 회차별 성공·일부 성공·실패 결과(저장한 회차가 있으면 서버가 세계관 추출을 자동으로 접수하므로 확정 버튼 곁에 OpenAI 전송 안내 한 줄을 두고, 결과에 접수 결과 `worldBuild`를 알립니다). 작품이 없으면 `/content`에서 만들고, **세계관 만들기**는 `/worldstudio`를 엽니다(만든 세계관은 작품과 연결되지 않음). 가져오기 입력이 있으면 두 링크로 이동하기 전에 입력을 버릴지 확인합니다. 확정 회차 번호는 조정 목록의 순서이고 제외한 회차도 번호를 차지합니다. 실패 항목은 확정 응답에만 있어 화면을 떠나면 다시 볼 수 없습니다. `--mode mockup`은 기존 데모 가져오기 화면(`ImportPage`)을 그대로 씁니다.
- `/studio/{UUID}` 내보내기: 형식(TXT·EPUB)·범위(현재 회차·작품 전체)·원본(초안·발행본)을 골라 서버 GET을 Blob으로 받고 `Content-Disposition`의 `filename*`로 저장합니다. 서버에 저장된 원고를 내보내므로 입력 중·저장 중에는 잠급니다.
- `--mode mockup`의 가져오기·EPUB/발행본 내보내기·첨부 이름 변경은 성공을 흉내 내지 않고 "데모에서는 지원하지 않아요" 오류를 냅니다. 데모 집필실의 TXT 초안 내보내기만 메모리 원고로 실제 파일을 만듭니다(`createMockupManuscriptRepository`).
- nginx(`frontend/nginx.conf`, `infrastructure/nginx.dev.conf`)의 `/api/v1/works/`는 요청 본문을 51MB까지 받습니다.

## 회차 이미지 설명·본문에서 빼기 (기능 16-C)

[계약 5절](../docs/design/manuscript-import-export-contract.md)대로 `MediaRepository`에 회차 이미지 목록·대체 텍스트 PATCH·공개 대체 텍스트 조회를 두고 응답은 Zod로 검증합니다(소유자 목록의 `url`은 기존 다운로드 경로와 같아야 합니다).

- `/studio/{UUID}`의 `EpisodeImagePanel`: 현재 회차에 올린 이미지(파일명·크기·본문 사용 여부), 이미지별 설명(최대 300자) 저장, '다운로드'(기존 소유자 다운로드 경로를 인증 읽기로 받아 파일로 저장), '본문에서 빼기'. 빼기는 현재 초안에서 `[[image:ID]]` 표식(과 앞뒤 빈 줄)만 지우고 기존 초안 저장(`PUT .../draft`, revision 검사)으로 저장한 뒤 집필실의 `reload`로 최신 초안을 다시 읽습니다. 저장하지 않은 입력이 있거나 저장 중이면 막고 먼저 저장하도록 안내하며, 저장이 실패(revision 충돌 등)하면 서버 사유와 다시 불러오기 안내를 보이고 입력한 설명은 그대로 둡니다. 이미지 파일은 저장 버전·발행본이 참조할 수 있어 지우지 않습니다.
- 독자 화면: 회차 열람(`/read`)은 발행본을 원고 기본 서식(DEC-48, [계약](../docs/design/manuscript-format-contract.md))대로 그립니다. `ReadingUseCase.openEpisode`가 `domain/entities/feedback.ts`의 `readerBody`로 그릴 블록(`blocks`: 문단·인용·소제목·구분선·이미지·빈 줄)과 고를 문장(`paragraphs`)을 함께 주고, 문장의 `t`(댓글 인용·피드백·수정 제안에 보내는 글)는 줄 안 기호를 포함한 원문 조각입니다(줄 맨 앞 `## `·`> `·`\`는 빼고, 인용은 줄마다 나눔). 문단·인용 안의 줄바꿈은 줄바꿈으로 보입니다. 본문 이미지는 공개 작품이면 공개 경로와 `GET /api/v1/public/works/{id}/episodes/{n}/images`의 대체 텍스트로(이미지가 있을 때만 익명으로 읽음), 작가가 자기 비공개 작품을 미리 읽을 때는 소유자 경로로 받으며 설명이 없거나 읽지 못하면 `본문 이미지 N`을 씁니다. 저장 버전 보기·버전 비교·체크포인트·작품 관리 '원고 보기'·집필실 미리보기는 공용 `ManuscriptBody`가 같은 문법(`domain/entities/manuscriptFormat.ts`의 `manuscriptLine`·`inlineParts`·`manuscriptBlocks`)으로 그립니다. 한 줄의 내용이 2,000자를 넘으면 그 줄의 굵게·기울임은 해석하지 않습니다(길이 상한).
- `--mode mockup`에서는 목록·설명 저장·공개 설명 조회가 "데모에서는 지원하지 않아요" 오류입니다(성공을 흉내 내지 않음).

## 검증

대형 세계관은 공개·소유자 설정집과 편집 레일을 50개씩 보여 주며 검색·정렬 뒤 페이지를 옮겨 모든 카드에 접근한다. 공개 카드 상세의 연결 목록도 페이지로 나누고 마크다운 원문과 출처는 그대로 표시한다. 같은 두 카드 사이의 관계는 ID마다 그래프에 그리고 카드 상세에도 모두 표시한다. 공개 그래프는 카드 최대 50개와 관계 최대 20개씩 표시하며, 설정을 검색해 선택하면 다른 페이지의 인접 카드와 관계도 49개 이웃씩 그래프에 표시한다. 소유자 관계도는 쪽으로 나누지 않고 모든 카드와 그 사이 관계를 한 캔버스에 그리며, `설정 찾기`(한 번에 200개)로 이름을 골라 그 카드로 옮겨 가 선택한다. 삭제된 설정과 이어진 관계는 그릴 카드가 없어 개수만 알리고 저장 때 그대로 유지한다. 공개 그래프의 이웃 보기에서 서로 다른 페이지의 끝점도 함께 볼 수 있다.

작성 모드의 검토는 열 때만 그리며 카드·관계·저장 전 확인을 각각 50개씩 나눠 보여 준다. 설정집의 선택 공개·비공개는 현재 페이지에 보이는 선택만 바꾸고 다른 페이지의 선택은 유지한다. 공개 관계가 선택적 `direction`·`polarity`·`body`를 제공하면 카드 상세에 단방향·대칭, 극성과 본문을 표시하고 그래프에 단방향 화살표·대칭·부정을 알린다. 이전 응답이나 null 방향은 방향 미상으로 표시하며 기록 순서는 실제 방향을 뜻하지 않는다. 공개 세계관 목록에서 `relationshipCount`가 null이면 관계 수 확인 불가로 알린다. 이 필드들의 서버 제공은 별도 백엔드 작업에 달려 있다.

관리 설정집은 현재 페이지 선택 수와 다른 페이지·필터에 남은 선택 수를 각각 알리고 선택 공개·비공개는 현재 페이지에만 적용하며 그 결과 문구에도 `현재 페이지`를 적는다. 관리 관계도는 모든 카드를 한 캔버스에 그리므로 `설정 찾기`로 어느 설정이든 골라 관계를 편집할 수 있다. 공개 카드 상세의 대칭·방향 미상 관계는 양쪽 카드 모두에 관계 문단으로 보이고 단방향 관계만 받는 쪽에 '이 설정을 가리키는 관계' 링크로 보인다(DEC-54).

세계관 머리의 행동 줄에는 `N화까지 읽은 독자로 보기`(연결된 소설의 가장 뒤 발행 회차까지 읽은 독자의 설정 위키 `/work/:id/wiki?upto=N`을 새 탭으로 연다. 소설 연결이 없거나 발행한 회차가 없으면 이유와 함께 잠기고, 확정 버전과 발행 회차 기준이라 저장하지 않은 초안은 보이지 않는다)와 `내보내기 ▸ JSON·Markdown`(저장한 세계관을 브라우저에서 `세계관이름-YYYYMMDD.json|md` 파일로 내려받는다. 서버를 부르지 않고, 다시 가져오는 기능은 없다)이 있다.

시간선 보기는 저장한 설정의 사건을 회차 열로 묶은 가로 시간축입니다(공개 회차 → 관계의 시작 회차 → 앞선 사건 순으로 열을 정하고, 정하지 못한 사건은 맨 오른쪽 `시점 미정`). 한 쪽에 회차 열 20개만 그리며 사건이 6개를 넘는 열은 `사건 N`으로 접혀 사건이 1,600개여도 화면이 무거워지지 않습니다.

로컬 개발은 변경·직접 영향 범위의 **단위 테스트 파일만** 지정합니다. 전체 suite·빌드·React 조립·브라우저/E2E는 로컬 개발 검증으로 실행하지 않습니다.

```bash
pnpm exec vitest run src/domain/__tests__/LibraryUseCase.test.ts
# Data 단위 테스트도 실제 서버 대신 fetch 대역을 사용합니다.
pnpm exec vitest run src/data/api/auth.test.ts
```

CI는 [공통 검증 정책](../docs/development.md#검증)에 따라 web 서비스의 단위(Domain/Data/HTML)와 나머지 React/Hook/App 통합을 분리 실행하고 lint/build도 수행합니다.
워크플로가 이 디렉터리에서 `pnpm exec vitest run src/domain src/data src/index-html.test.js`와 해당 파일들을 `--exclude`한 통합 명령을 직접 호출합니다. 별도 테스트 runner나 shell wrapper는 없습니다.
앱·라우트 횡단 통합 테스트는 `src/test/integration/`에, 기능별 테스트는 기존 기능 파일 옆에 둡니다. 공통 테스트 도구는 `src/test/`에 두고, HTML 단위 테스트는 CI 명시 경로인 `src/index-html.test.js`에 유지합니다.
Core API 변경 시 web 소비자 회귀도 선택합니다. 실제 HTTP 시스템 시나리오는 CI Compose에서 실행하며 브라우저 UI 검증이 아닙니다.
`App.admin`, `App.reading`, `App.studio`, `App.studio-wiki`는 사용하는 지연 라우트 모듈을 테스트 파일에서 미리 가져옵니다. Vite의 첫 모듈 변환은 테스트 실행 전에 끝나고, 테스트는 실제 라우터와 화면에서 사용자 흐름을 검증합니다.
Aside는 별도 요청·승인 시에만 사용합니다. hosted `Required CI` 결과 확인 전에는 검증 대기로 보고합니다.

서버 작품은 `/studio/{UUID}`에서 회차별 실제 저장 API를 사용합니다. 데모 세션 대신 Core의 인증 결과를 따르며, 기존 이름 기반 데모 집필실과 구분합니다. 자동저장·버전 저장·복원과 검증 범위는 [이슈 #50 대응](../docs/issue-50-alignment.md)을 참고하세요.
