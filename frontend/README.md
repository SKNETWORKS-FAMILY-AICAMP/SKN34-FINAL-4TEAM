# STORYFORK Web

React·TypeScript·Vite·Tailwind CSS 기반의 개발 화면입니다.
이름 기반 작품·Fork·서재는 데모 데이터입니다. `/content`·`/studio/{UUID}`는 같은 출처의 Content API, 인증·프로필·기기 관리는 Core API를 호출합니다.
이메일 확인 전 자동 로그인하지 않으며 운영 약관은 미정입니다. 알 수 없는 UI 경로는 `/`로 이동합니다.

## 목표 서비스 경계 (DEC-41)

[4개 백엔드 서비스 구조](../docs/design/service-boundaries.md)에 따라 Core는 회원·인증·크레딧·회원 알림, 별도 Kotlin/Spring Boot 콘텐츠 앱은 창작·독서·콘텐츠 정본과 인가, 별도 Kotlin/Spring Boot 운영 앱은 문의·공지·신고 사건·운영 결정·감사·작업 감시를 담당합니다. Python AI 앱은 허용 문맥에서 생성·검토를 실행하며 정본·권한·발행·정산을 확정하지 않습니다. LLMOps는 운영 영역이며 Langfuse 도입 시 별도 제품으로 배포합니다. 자체 UI와 운영 화면 API 통합 중 방식은 미정입니다.

nginx/Vite는 기존 `/api/v1/works`·`/api/v1/public/works`와 하위 경로를 Content:8081, `/api/v1/operations/{reports,members,admins,support,works,comments,admin/notices,public/notices,admin/events,public/events,admin/activities}`와 하위 경로를 Operations:8082(서비스 토큰용 `/api/v1/operations/{notices,events,inquiries}`는 열지 않음), 나머지 `/api`를 Core:8080으로 분기합니다. 관리자 사용자·관리자 계정·작품·댓글·신고·공지·이벤트·활동 로그 탭, 제보·문의 탭의 회원 고객지원 문의(작가 검토 제보는 메모리 데모), `/me/inquiry`(문의하기·내 문의), 회원 공지사항(`/me/notice`, 로그인 불필요)과 회원 `/me/event`(비로그인 열람 가능), 공개 작품 신고(서버 작품의 검색 카드·작품 상세 ‘소설 신고’), `/reports`(내 신고)는 운영 API를 호출하며 그 밖의 관리자 탭은 메모리 데모입니다. 운영 API 탭의 조치는 메모리 데모 조회(댓글·캐릭터챗 등)의 로딩·실패와 무관하게 실행됩니다. 관리자 작품 탭은 운영 작품 API로 공개·비공개·운영 제한 작품 전체를 읽어 '운영 제한'·'제한 해제'를 요청하며(`--mode mockup`은 데모 작품 메모리), 분류·검색·정렬은 받은 목록에서 화면이 계산합니다([계약](../docs/design/operations-work-contract.md)). 관리자 활동 로그 탭은 운영 활동 기록 API로 관리자 변경 조치 최신 100건을 최신순으로 읽어 시각·수행자(닉네임, 없으면 ID)·조치·대상·내역을 보이며 서버가 정렬·권한(`admins`)을 맡고 `--mode mockup`은 데모 조치 메모리를 보입니다([계약](../docs/design/operations-admin-activity-contract.md)). 신고 버튼은 남의 공개 작품에서만 보이고(본인·비공개 작품은 숨김이며 접수 권한은 서버가 검사), `--mode mockup`의 메모리 작품 신고는 메모리에만 기록됩니다. 브라우저는 상대 URL·기존 Bearer/쿠키/CSRF를 유지하며 내부 인증 endpoint·AI·DB·모델을 직접 호출하지 않습니다. 소스 연결과 hosted CI·실제 DB 전환·배포는 구분하며 운영·알림 데모를 서버 완료로 간주하지 않습니다.

## 실행

Node **24.x**, pnpm **11.22.x** (`packageManager: pnpm@11.22.0`)가 필요합니다.

```bash
pnpm install --frozen-lockfile
pnpm dev
```

네이티브 web/Core/Content는 `http://localhost:5173`/8080/8081입니다. 콘텐츠는 같은 origin의 상대 `/api`로 호출하며 `VITE_DEV_PROXY_TARGET`과 `VITE_CONTENT_DEV_PROXY_TARGET`이 각각 Core/Content를 지정합니다.
직접 실행할 때는 공개 `VITE_CORE_API_BASE_URL` 등 필요한 변수만 터미널에 설정합니다. 루트 `.env`는 자동으로 읽지 않습니다.
루트 설정 자동 전달은 Compose를 사용하며 서비스별 `.env`는 만들지 않습니다.
`VITE_*`는 브라우저에 노출되므로 비밀값을 넣지 않습니다. 백엔드는 별도로 실행합니다.

루트의 [Compose 안내](../infrastructure/README.md)는 공통 `docker-compose.yaml`에 prod 또는 dev를 병합합니다.
prod는 소스에서 정적 배포 이미지를 빌드해 기본 `http://127.0.0.1:8088`로 검증하고, dev는 현재 개발 배포 서버에서 CI의 `:develop` 이미지를 pull·실행합니다.
두 조합 모두 Nginx가 정적 화면과 works 경로 → `content-service:8081`, 나머지 `/api` → `core-api:8080` 프록시를 제공합니다. 소스/HMR Compose는 제거했으며 hot reload는 위 `pnpm dev`를 사용합니다.
loopback 검증용이며 인터넷 운영 준비를 뜻하지 않습니다.

## 프론트엔드 구조와 상태 소유

- `app/di`에서 Repository·UseCase와 Health·알림 SSE 외부 함수를 조립합니다. Presentation은 Data 함수를 직접 import하지 않으며, 공유 Health·SSE 계약은 Domain에 둡니다. HTTP 응답의 Zod 검증은 Data에 남깁니다.
- Redux `session`은 인증·로그인 안내와 기존 조회 무효화 신호를, `ui`는 테마·화면 ID·읽기 설정·홈 표시 상태를 소유합니다. UI 상태는 로그인·로그아웃 때 유지하며 브라우저 저장소에 영속화하지 않습니다. `dataVersion`은 여전히 데모 전역 재조회 신호이며 기능별 캐시로 바꾸지 않았습니다.
- 관계 패널의 draft 상태·적용 handler는 `useRelationPairViewModel`, 순수 초기화·방향 변환은 Domain의 `relationDraft`가 담당합니다. 최초 baseline을 유지하고 기존 `applyRelationChanges`로 검증하며, 저장 전 편집과 실제 저장을 구분합니다.
- 집필실·서재가 함께 쓰는 `PublishSettingsSheet`는 `presentation/shared`에, Wiki 편집 화면은 `StudioWikiView`에 둡니다. 데모 피드백함과 실제 알림함의 ViewModel은 별도 파일입니다.
- 서버 집필실(`/studio/{UUID}`)은 왼쪽 회차 목록·버전 그래프 / 가운데 원고 / 오른쪽 AI 채팅의 3단입니다. 그래프 행의 순서·라벨·배지는 Domain의 `versionGraph`가 계산하고, 채팅은 이후 캐릭터챗도 쓰는 표시용 `presentation/shared/chat/ChatPanel`입니다. ChatPanel은 API를 부르지 않으며 메시지·전송·첨부는 호출하는 화면이 넘기고, 집필실의 AI 전송·첨부는 아직 연결하지 않아 "준비 중"으로 잠겨 있습니다. 창이 1200px 이하면 AI 채팅은 접힌 채로 시작하고, 900px 이하에서는 회차 목록이 한 줄 가로 스크롤 띠가 됩니다. 자동 저장은 화면을 잠그거나 알림을 띄우지 않고 상단 저장 상태만 바꾸며, 버전 저장 같은 완료 안내는 그 상태 줄에 이어 적습니다.
- 서버 집필실 본문은 Toast UI Editor 3(`@toast-ui/editor`, 마크다운 쓰기 모드) 기반 `ManuscriptEditor`이고 `LazyManuscriptEditor`로 늦게 불러옵니다(원작 기준 회차는 편집기 없이 공용 `ManuscriptBody`로 읽기 전용 본문을 그립니다). 툴바는 `굵게 · 기울임 | 소제목 · 인용 · 구분선 | 이미지` 여섯 개이고 `쓰기 | 미리보기`의 미리보기는 `ManuscriptBody`가 그립니다. 저장 글은 편집 영역의 글자 그대로이며(왕복 무손실) 서식 기호는 그릴 때만 해석합니다([계약](../docs/design/manuscript-format-contract.md), DEC-48). 편집 영역의 구문 강조는 계약의 서식만 보이도록 Toast의 강조를 다시 정했고, 이미지 표식 줄은 `widgetRules`와 포털로 실제 이미지로 보입니다. 40,000자 한도·잠금·이미지 줄 보호는 Toast의 `dispatchTransaction` 앞에서 거르고, 계약에 없는 서식을 넣는 Toast 단축키(취소선 Ctrl+S, 목록 Ctrl+U·O, 코드 Ctrl+Shift+C·P)는 받지 않습니다. Toast의 알려진 결함(열자마자 되돌리기로 글이 지워짐, 일부 글에서 구문 강조 예외, 줄 사이 편집에서 줄바꿈을 잃음)은 `presentation/shared/toastFixes.ts`가 막고 카드 편집기(`shared/MarkdownEditor`)도 같은 보정을 씁니다. 글자 수·공개 분량(5,000자, 서버가 검사하지 않는 화면 규칙) 판정은 `manuscriptLength`가 맡습니다. 화면 테스트는 `test/manuscriptEditorFake`(textarea 대역)를 쓰고 실제 편집기 동작은 `ManuscriptEditor.test.tsx`가 실제 Toast로 검증합니다.
- 순수 함수라도 Presentation 소유의 테스트는 해당 feature 옆에 둡니다. 현재 CI는 경로 기준으로 분류하므로 이 테스트는 Domain/Data 단위 명령이 아니라 기존 통합 선택에서 발견됩니다.

## 실제 호출 흐름

`/status`의 연결 확인은 `App → CoreApiConnectionStatus → useCoreApiHealth → DI 외부 함수 → Fetch·Zod → 공개 Core API`입니다. 해당 화면의 Health 전용 안내가 앱 전체의 구현 상태를 뜻하지는 않습니다.

- Core: `GET /api/v1/health`, `storyfork-core-api`와 `up` 검증.
- AI: `GET /api/v1/health/ai-service`, `storyfork-ai-service`와 `up` 검증.
- AI 내부 주소나 OpenAI를 브라우저에서 직접 호출하지 않습니다.
- Health는 OpenAI 키·모델 접근 검증이 아닙니다.

인증·계정 기능은 View → ViewModel → UseCase → Repository → Core API 흐름으로 요청합니다.

| UI 경로·진입점 | 화면·동작 | Core endpoint |
|---|---|---|
| `/me/signup` | 가입 요청 → 이메일 확인 대기 (자동 로그인 없음) | `POST /api/v1/auth/signup` |
| `/auth/resend-verification`, 로그인·가입·인증 실패 화면의 안내 | 이메일 1항목으로 확인 메일 재발송 (계정 존재 여부를 구분하지 않는 안내) | `POST /api/v1/auth/resend-verification` |
| `/auth/verify-email#token=…` | 메일 링크의 이메일 확인 → 로그인 | `POST /api/v1/auth/verify-email` |
| `/login` | 이메일·비밀번호 로그인, Core가 반환한 사용자·권한 반영. 빈 값·이메일 형식 오류는 요청을 보내지 않고 화면 오류로 안내하며 쓰던 비밀번호를 지우지 않음(요청을 보낸 뒤에만 지움). 403 + `code: "ACCOUNT_RESTRICTED"`는 이용 제한 안내(로그인 문의 링크 가리킴), 코드 없는 403은 일반 오류 | `POST /api/v1/auth/login` |
| 앱 시작 | HttpOnly refresh 쿠키를 통한 세션 복원 | `POST /api/v1/auth/refresh` |
| 상단 계정 메뉴 | 현재 기기 로그아웃 | `POST /api/v1/auth/logout` |
| 상단 계정 메뉴 | 보유 크레딧 한 줄(메뉴가 열릴 때 잔액만 조회, 닫히면 취소). 운영자 계정에는 `/admin` 바로가기 | `GET /api/v1/me/credits` |
| `/me/profile` | 서버 프로필 조회·오류 재시도, 닉네임 저장 | `GET /api/v1/me`, `PATCH /api/v1/me` |
| `/me/profile`의 이메일 저장 | 새 주소로 확인 메일 요청, 확인 전 기존 이메일 유지 | `POST /api/v1/me/email-change` |
| `/auth/verify-email-change#token=…` | 이메일 변경 확인 → 프로필로 돌아가 새로 조회 또는 로그인 | `POST /api/v1/auth/verify-email-change` |
| `/auth/forgot-password`, 프로필의 계정 보안 | 비밀번호 재설정 메일 요청 (계정 존재 일반화) | `POST /api/v1/auth/forgot-password` |
| `/auth/reset-password#token=…` | 새 비밀번호 검증·저장 → 로그인, 만료 시 새 링크 요청 | `POST /api/v1/auth/reset-password` |
| `/me/profile`의 로그인 기기 | 기기 조회·오류 재시도·개별 연결 종료 | `GET /api/v1/auth/sessions`, `DELETE /api/v1/auth/sessions/{id}` |
| `/me/profile`의 모든 기기 로그아웃 | 서버 성공 후 현재 세션 해제 | `POST /api/v1/auth/logout-all` |

- 변경 요청 전에 `GET /api/v1/auth/csrf`로 CSRF 토큰을 받습니다. 인증 링크의 fragment는 읽은 즉시 주소에서 제거하며, 토큰을 로그나 브라우저 저장소에 남기지 않습니다.
- access token은 메모리에만 두고 refresh 쿠키는 Core가 HttpOnly로 관리합니다. 인증 변경은 기존 Web Locks와 계정 소유자 검증을 사용하고, 보호된 요청의 401은 세션 갱신 후 한 번만 재시도합니다.
- 가입·비밀번호 재설정은 공백뿐인 비밀번호를 거부하고 8자 이상·UTF-8 72바이트 이하를 확인합니다. 재설정 입력 오류는 해당 필드에 안내하며 입력을 보존하고, 완료되거나 만료된 토큰은 다시 제출하지 않습니다.
- 프로필·기기 조회는 화면 이탈·재시도 시 AbortController로 취소합니다. 로그인·가입의 늦은 응답은 화면 이탈 후 상태나 자동 이동을 덮어쓰지 않도록 무시합니다. 이미 서버에 전달한 요청을 되돌린다는 뜻은 아닙니다.
- 로딩·실패·완료·빈 목록을 구분하고 중복 요청을 막습니다. Health 조회는 별도로 20초 제한과 취소를 사용합니다. 내부 예외는 화면에 노출하지 않습니다.
- 로그인·가입·재발송·복구·이메일 확인은 같은 인증 화면을 사용합니다. 데스크톱의 기존 STORYFORK 브랜드는 보존하고 모바일은 작은 로고와 현재 입력부터 표시합니다. 테마 전환은 일반 문서 흐름에 두며 페이지 이동은 링크를 사용합니다.
- 가입 오류는 해당 필드에 연결하고 첫 오류로 초점을 이동합니다. 복구·재발송 접수 후 입력한 주소와 스팸함 안내, 주소 수정·재요청 경로를 표시합니다. 이 주소 문맥은 화면 상태에만 두고 브라우저 저장소에 보관하지 않습니다.
- 상태 알림은 live region, 버튼은 키보드 포커스를 지원하고 애니메이션은 reduced-motion을 따릅니다. 기존 색상·타이포그래피·상태 스타일을 재사용합니다.
- 터치 대상 44px 보정은 `storyfork.css` 맨 끝의 `@media (max-width:600px),(pointer:coarse)` 블록 한 곳에서 하고 터치 기기에서는 입력 글자를 16px로 올립니다. 기능 CSS가 같은 속성을 다시 정하면 그 화면이 직접 보정합니다. 맨 위 스크롤은 다른 화면으로 넘어가는 이동(경로가 바뀌거나, 같은 경로에서 화면 내용이 통째로 바뀌는 쿼리 — 관리자 `tab`, 공지·이벤트 `id`, 작품 관리 `work`, 검색 `q` — 가 바뀌는 PUSH·REPLACE)에서만 하고(`GlobalChrome`의 `SCREEN_QUERY`), 뒤로·앞으로와 그 밖의 쿼리(탭·필터·정렬) 변경은 보던 위치를 지킵니다. 토스트는 `role=status` 노드 하나를 유지하며 글자 수에 비례해 2.6~8초 머뭅니다.

실제 약관 동의·계정탈퇴·소셜 로그인·운영 메일 서비스·비용 정책은 이 연결 범위에 포함하지 않습니다. 계정탈퇴 UI는 기존 데모이며 실제 계정을 삭제하지 않습니다.

## 공개 열람 (기능 20)

- `/read/:id`·`/read/:id/:n`은 비회원도 로그인 없이 공개 회차를 읽습니다(UC-01). 세션 복원이 끝난 뒤 열어 로그인 회원이 새로 고칠 때 두 번 불러오지 않습니다. 포크 등 회원 전용 동작은 해당 화면(`RequireRole`)의 로그인 안내를 그대로 쓰고, 메모리 데모 작품 회차 화면의 댓글·댓글 좋아요·피드백도 비회원이 누르면 같은 로그인 화면으로 보내며 메모리에 저장하지 않습니다(`useReaderViewModel.requireMember`). 비회원의 열람은 서버 조회 기록을 보내지 않습니다.
- 서버(정본) 작품의 작품 상세는 `설정 위키` 링크로 `/work/:id/wiki` 페이지(U45)를 열어 `readWorld`가 채운 공개 설정을 읽기 전용으로 보여 주고, 회차 화면 상단 `설정` 링크도 같은 페이지를 `?upto=n`으로 엽니다(돌아가기는 그 회차로). 서버가 기준 회차(작품 상세는 최신 공개 회차, 회차 화면은 그 회차)까지 공개한 설정만 주므로 화면은 거르지 않고 분류별로 묶어 표시하고, 없으면 "공개된 설정이 없어요"를 보입니다. 메모리 데모 작품에는 링크가 없고 위키 주소는 작품 상세로 돌려보냅니다.
- 작품에 연결된 세계관이 있으면(DEC-46, [계약](../docs/design/public-world-contract.md)) U45는 그 세계관의 **독자 공개 설정 카드**로 채웁니다. `useWorkWikiViewModel`이 작품을 읽은 뒤 `ReadingUseCase.linkedWorldCards` → `HttpWorkRepository.readWorldCards`로 `GET /api/v1/public/works/{id}/world-cards`를 Bearer 없이 읽고(주소에 `?upto=n`이 있을 때만 그 값을 보내며 없으면 생략해 서버가 발행된 마지막 회차로 정함), 응답의 `worldId`가 있으면 `reading/viewmodel/worldCardWiki.ts`가 카드를 같은 나무위키 형식의 문서로 바꿉니다: 카드 유형 8가지 순서의 묶음, 본문은 `CardMarkdown`(`## 제목`은 문서 제목 아래 소제목), 정보 상자에 별칭·태그·'N화부터', 관계는 양 끝 문서의 `연결`(상대 문서로 가는 링크와 라벨). `worldId`가 null이면 위의 기존 작품 설정 위키 그대로입니다. "N화까지 공개된 설정만 보여요"와 회차로 돌아가기는 서버가 적용한 `upto`를 쓰고, 관계를 불러오지 못한 응답(`relationshipStatus: unavailable`)은 "설정 사이의 연결을 불러오지 못했어요"로 빈 연결과 구분해 알리며, 카드 조회가 실패하면 빈 위키로 바꾸지 않고 로드 실패(다시 시도)를 보입니다. 서버가 독자 공개 회차로 이미 걸러 주므로 화면은 거르지 않습니다.

## 서버 이미지·파일 (#92)

`MediaPanel / useMediaViewModel → MediaUseCase → MediaRepository → HttpMediaRepository`를 Awilix에서 조립합니다. 실제 작품·설정 UUID만 허용하고 데모 ID·실패 시 메모리 성공 fallback을 보내지 않습니다.

- `/content`: 작품 설정 전용 관리 화면이며 **주소가 화면을 정합니다**. `/content`는 새 작품 만들기(소설 상세 히어로 모양의 입력 화면, 만들면 `/content?work=<새 ID>`로 바꿔 관리 화면을 보임), `/content?work=<작품ID>`(서재 카드의 '관리하기')는 그 내 작품의 관리 화면이며 내 작품이 아니면 '작품을 찾을 수 없어요'와 서재 링크를 보입니다. 작품 목록·고르기는 서재(`/lib?tab=write`)가 맡아 이 화면에는 사이드바와 공개 작품 둘러보기가 없고, 상단 '내가 쓰는 소설'이 서재로 돌아갑니다. 관리 화면은 소설 상세 페이지처럼 상단 히어로(표지·제목·장르·유형·공개 상태·소개·해시태그)와 그 아래 카드(원작은 분기 정책, 분기 작품은 포크 정보), 탭(공개 원고·세계관·설정집·이야기 분기·저장·AI·발행 이력은 읽기 전용)으로 구성합니다. 작품 정보(제목·소개·장르 1~2개·해시태그 10개까지, `PUT /works/{id}`)·표지·분기 정책(`PUT /works/{id}/policy`)은 영역마다 '편집' 버튼이 하나씩이며 저장/취소로 바꿉니다(한 번에 한 영역, 저장이 성공해야 읽기 표시로 돌아가고 실패하면 입력을 남김). 장르·해시태그는 생성 화면과 같은 선택지·검증을 쓰고 서버 값과 달라진 쪽만 본문에 실으며(생략하면 서버가 유지, 빈 배열은 비움) 장르가 없던 옛 작품도 제목만 고쳐 저장할 수 있습니다. 작품 유형은 등록 때 정해져 읽기 전용이고 공개 상태는 회차 공개 흐름이 정합니다. 공개 회차 행에는 그 회차에서 갈라진 공개 포크 수가 소설 상세와 같은 작품 목록(`ReadingUseCase`, 새 API 없음)으로 계산돼 branch 아이콘과 함께 보이고, 0편이거나 읽지 못하면 숨깁니다(0으로 채우지 않음). '받은 피드백' 탭은 작가 피드백함과 같은 조회에 `?workId=`를 보내 서버가 이 작품의 제보·수정 제안만 주며(`/inbox`는 쿼리 없이 전체) 화면이 다시 거르지 않습니다. 분기 작품은 포크 정보(분기 기준·방향, 원작으로 가기 — 원작이 삭제됐으면 안내만, 공개 중일 때 '포크 공개 중단' `DELETE /works/{id}/fork-publication`, '포크 삭제' `DELETE /works/{id}` 뒤 서재로 이동)를 보이고, 이야기 분기를 만들면 새 분기의 관리 화면으로 이동합니다. 원고 작성·AI 이어쓰기·회차 공개는 `/content`에서 제거됐고(집필실 이전은 후속), 히어로와 각 공개 회차의 '회차 작성하기'가 집필실(`/studio/{id}`, 회차는 `?ep=n`)로 보냅니다(실서버 집필실은 `?ep=n`의 회차를 처음에 열고, 없거나 범위 밖이면 첫 회차를 엽니다). 작품 만들기·분기 만들기의 실패 사유는 그 폼 안(버튼 위)에 보이고, 그 밖의 요청은 맨 위 알림에 보이며 화면 밖이면 보이는 데까지 스크롤합니다. 이력 탭의 저장 버전 본문은 '원고 보기'로 펼칠 때만 그립니다.
- `/content` 세계관 연결(DEC-46): 세계관·설정집 탭 맨 위의 `세계관 연결` 카드(`LinkedWorldPanel`)가 이 소설과 내 세계관(WorldStudio)의 1:1 연결을 맡습니다. 연결돼 있으면 `연결된 세계관: {이름}`(→ `/worldstudio/<id>`)과 `연결 해제`(확인 뒤)를, 아니면 다른 소설에 연결되지 않은 내 세계관을 고르는 `세계관 연결`을 보이고 `PUT /api/v1/works/{id}/world-studio`(`EpisodeUseCase.linkWorldStudio`, `worldId: null`이 해제)로 바로 적용하며 응답의 연결로 열린 작품의 `worldStudioId`를 바꿉니다(작품 revision은 그대로). 내 세계관 목록(`worldStudioUseCase.list()`의 `linkedWorkId`)은 탭을 열 때 한 번 읽어 불러오는 중·실패(다시 불러오기)·고를 세계관 없음(세계관 만들기 링크)을 따로 보이고, 남의 것·없는 세계관(404)이나 이미 다른 소설에 연결된 세계관(409 `WORLD_ALREADY_LINKED`)은 서버 문구를 그 카드 안에 그대로 알리고, 연결·해제 완료 안내도 카드 안에 보입니다. 그 아래 설정집 요약 카드는 작품 설정집의 이름·상태·최초 분기 기준만 보입니다.
- `/content` 표지: 작품 생성 시 PNG/JPEG 표지 선택(생성 화면도 같은 히어로 모양), 생성된 작품의 표지 조회·교체(편집에서 고른 파일은 '저장'을 눌러야 올라감)·삭제·새로고침. 작품만 생성되고 표지 업로드가 실패하면 생성된 작품을 유지하며 표지만 재시도합니다. 표지 편집과 생성 화면의 'AI로 생성'은 아직 연결 전이라 비활성이며 보이는 글자로 '준비 중'을 알리고 API를 호출하지 않습니다.
- `/content` 설정집: 서버에 설정 초안을 먼저 저장한 뒤 이미지·TXT/MD/CSV/PDF 목록/업로드/다운로드/교체/이름 변경/삭제. 이름 변경은 확장자를 고정하고 서버의 거부 사유를 그대로 보이며 실패하면 입력을 남깁니다. following 설정은 로컬 독립 전 첨부하지 않습니다. 공개 설정도 첨부 자체는 소유자 전용입니다.
- `/studio/{UUID}`: 실제 회차 본문의 커서/선택 영역에 불변 이미지 `[[image:<UUID>]]` 참조 삽입, 초안·버전 저장/재진입/복원/발행 및 읽기 미리보기. 업로드 후 초안이나 버전을 저장해야 참조가 보존됩니다. 과거 버전을 위해 원본을 지우지 않으므로 회차당 업로드 총 10개는 marker 삭제로 반환되지 않습니다.
- 같은 출처의 Bearer/CSRF multipart 요청을 사용하며 JSON Content-Type을 강제하지 않습니다. 비공개 이미지 bytes를 인증 fetch 후 Blob URL로 표시하되 같은 이미지를 함께 그리는 곳들은 한 번 받은 주소를 나눠 쓰고 마지막 사용처가 사라질 때 revoke하며, 화면 가까이 올 때까지는 내려받지 않습니다. 토큰·스토리지 URL·base64를 서버 원고에 저장하지 않습니다.
- 중복 요청을 막고 취소·이탈 뒤 늦은 결과를 적용하지 않습니다. 취소/네트워크 응답 유실은 서버 rollback을 의미하지 않으므로 목록 새로고침으로 실제 상태를 확인합니다. 실패하면 기존 파일/원고를 유지합니다.
- PNG/JPEG 표지·본문 및 설정 파일은 파일당 10 MiB 이하입니다. 서버가 바이트·픽셀·권한·한도를 최종 검증합니다. 집필실 원고 내보내기는 아래 절처럼 서버가 만든 TXT(이미지 제외)·EPUB(이미지 포함)입니다.

실서버에서는 내 서재의 **새 소설 쓰기**와 기존 주소 `/new`가 `/content`의 작품 만들기로 연결됩니다. 세계관 작업실 헤더의 소설 버튼은 한 자리입니다: 그 세계관에 연결된 소설이 있으면 그 작품 관리(`/content?work=<id>`)로 가는 **소설 작성하기**, 없으면 같은 자리의 **소설 연결하기**이고 그 시트의 `새 소설 만들기`가 작품 만들기(`/content`)로 갑니다(만든 소설은 자동으로 연결되지 않아 돌아와서 연결합니다). 작품을 만들면 전용 설정집과 첫 회차 초안이 함께 생성됩니다. 만들 때 세계관을 고르는 입력·조합, 연재 요일, 연령 제한, 생성 시 인물 입력은 데모 폼에서만 제공되고, 실서버의 세계관 연결은 만든 뒤 작품 관리의 세계관·설정집 탭이나 세계관 작업실 헤더에서 합니다. `--mode mockup`에서는 `/new`의 기존 새 소설 폼이 브라우저 메모리에서 동작하고 세계관 작업실의 `소설 작성하기`도 그 폼으로 갑니다.

이름 기반 `/studio/starlight` 등의 개요·Wiki 이미지 선택은 브라우저 메모리 데모입니다. 인접 안내·toast에서 서버 미저장을 알리고 `/content`로 연결합니다. 표지 논리 삭제·미참조 원본 보존과 API/권한/운영 한계는 [Core 계약](../backend/core-api/README.md#작품-표지원고-이미지-92)을 참고하세요.

## 공개 세계관 둘러보기

상단 Gnb의 **세계관**은 `/worlds`(홈과 같은 구성의 공개 세계관 추천 대시보드: 장르 칩 → 홈 상단과 같은 2단(왼쪽 'STORYFORK 세계관 지도', 오른쪽 '실시간 인기' 세계관 순위) → '새로 공개된 세계관' 가로 선반(10개까지, 서버에 인기 지표가 없어 '인기 세계관' 선반은 없음) → 세계관 모아 보기, 추천이 아닌 칩은 2단과 그 장르 목록 하나)와 `/worlds/:id`(제목·작가 아래 설정 그래프·인물관계도·설정집·개요 네 탭을 읽기만 하는 상세)를 엽니다. 로그인 없이 볼 수 있고 이 화면에서 편집하지는 않습니다. 로그인한 회원에게는 가져오기 진입점 둘이 보입니다(DEC-46, 아래): 설정집 게시판의 `선택한 설정 가져오기`, 설정 카드 페이지의 `이 설정 가져오기`(상세 헤더의 `내 세계관으로 가져오기`는 없앴고, 설정과 관계를 함께 가져오는 길은 내 세계관 관리 화면의 `다른 세계관에서 가져오기`입니다).
**데이터**는 Content 공개 세계관 API([계약](../docs/design/public-world-contract.md))입니다. `View → useWorldsViewModel → PublicWorldUseCase → HttpPublicWorldRepository`를 Awilix에서 조립하고, 목록 `GET /api/v1/public/world-studios?genre=&page=&size=`(공개 + 저장 버전이 있는 세계관, 최근 공개 순)와 상세 `GET /api/v1/public/world-studios/{id}`(마지막 저장 버전의 **공개** 설정 카드 + 그 카드끼리의 현재 관계. 설정 카드는 기본 비공개이고 서버가 공개 카드만 주므로 화면은 거르지 않습니다, DEC-46)를 Bearer·CSRF 없이 읽고 Zod로 검증합니다(Vite·nginx는 `public/world-studios`를 Content로). UseCase는 목록을 24개씩 최대 4쪽까지 이어 붙이고(그보다 많으면 최근 공개 순 앞쪽만 보이며 지도 통계 줄과 모아 보기 머리가 전체 수를 알림), 지도·'실시간 인기'·'새로 공개된' 선반은 늘 전체 목록으로 만들고 장르 칩은 `genre` 쿼리(칩 라벨 ↔ 서버 코드 `worldGenres.ts`)로 '모아 보기' 목록만 다시 읽습니다. 불러오는 중·실패(다시 시도)·공개된 세계관 없음("아직 공개된 세계관이 없어요 · 내 서재에서 세계관을 공개해 보세요", `/lib?tab=worlds` 링크)·비공개/없는 세계관(404 → "찾을 수 없는 세계관")을 실제 조회 결과대로 그리고, 화면을 떠나거나 장르·세계관이 바뀌면 이전 요청을 취소하며 늦은 응답은 버립니다(`useAsyncData`). 파생·조합은 서버에 없고(설정 가져오기가 대신합니다, DEC-46) 공개 세계관 응답에는 연결된 소설도 없어, 실제 모드는 해당 표시를 숨기거나 준비 중으로 둡니다(아래 각 항목). 실제 모드의 목록 위에는 가져오기를 어디서 하는지 한 줄로 알립니다(로그인 회원 "설정 가져오기는 각 세계관 상세에서 할 수 있어요", 비로그인 "로그인하면 각 세계관 상세에서 공개 설정을 내 세계관으로 가져올 수 있어요"). `--mode mockup`은 같은 계약을 `data/mock/InMemoryPublicWorldRepository`가 `demoPublicWorlds.ts`의 데모 세계관 26개(파생 12·조합 6, 카드 점·카드 연관·작품·한 줄 소개 포함)로 답하고 칩 줄 아래에 "데모" 안내를 띄웁니다. 서버에 없고 데모에만 있는 값은 `domain/entities/publicWorld.ts`의 "데모 전용" 선택 필드입니다.
**세계관 지도**는 홈 히어로가 있던 왼쪽 칸(`.herow`, 캔버스 높이 데스크톱 380px·모바일 340px)에 놓인 노드 그래프(`react-force-graph-2d`, 라이트·다크 모두 어두운 캔버스, 통계 줄·범례는 카드 아래쪽)로, 공개 세계관이 장르별로 모인 모습을 보여 줍니다. 노드는 장르(큰 고정 크기)·세계관(설정 카드 수만큼 커짐)이고 장르→세계관은 옅은 선입니다. 서버 목록은 장르와 카드 수만 주므로 실제 모드의 지도는 여기까지이고 범례도 장르 색뿐입니다. 파생(한 세계관을 가져다 새로 만듦)·조합(여러 세계관을 섞어 만듦)과 설정 카드 점(작은 점, WorldStudio 지도와 같은 유형 색)은 메모리 데모에만 있습니다(세계관 크기에 파생·조합된 횟수가 더해지고, 세계관→카드는 옅은 선, 원본→파생은 실선 화살표, 원본들→조합은 점선 화살표, 통계 줄과 범례에 파생·조합). 세계관·카드 노드를 누르면 그 세계관 상세로, 장르 노드를 누르면 그 장르 칩이 골라지며(장르가 없는 세계관의 '미지정' 노드는 칩이 없어 누르지 않음), 장르 칩이 골라지면 그 장르(데모는 파생·조합으로 바로 이어진 노드까지)만 밝고 나머지는 흐려집니다. 캔버스에 늘 그리는 이름은 장르뿐이고 세계관·카드 이름은 마우스를 올린 노드 하나만 그립니다(HTML 툴팁이 아니라 캔버스에 직접 그리며 확대 정도와는 연동하지 않습니다). 터치 기기(`pointer: coarse`)에서는 한 손가락 끌기가 페이지 스크롤이 되도록 지도 이동·노드 끌기를 끄고(`worlds/view/useNodePointer.ts`), 이름이 숨은 노드는 첫 탭에 이름을 보인 뒤 다음 탭에 엽니다. 캔버스 아래 컨트롤(`MapControls`)의 방향 이동 버튼 넷(한 번에 보이는 영역의 4분의 1, `worlds/view/mapPan.ts`)은 터치 기기와 키보드로 컨트롤에 들어온 동안에만 보이며, 세계관 상세의 두 그래프도 같은 규칙입니다. 선반 화살표의 부드러운 스크롤은 동작 줄이기를 따릅니다. 마우스 휠이 페이지 스크롤을 가로채지 않도록 Ctrl(⌘)+휠일 때만 확대합니다. `prefers-reduced-motion`이면 배치를 미리 계산해 움직이지 않습니다. 지도는 눈으로 훑는 용도라 캔버스는 `role="img"`와 요약 `aria-label`로 알리고, 이름 탐색은 오른쪽 순위와 아래 선반·모아 보기가 맡습니다.
**세계관 상세**(`/worlds/:id`)는 제목·(데모만 한 줄 소개)·작가만 위에 두고 그 아래에 네 탭(설정 그래프·인물관계도·설정집·개요, `role="tablist"`, 좌우 화살표·Home·End로 이동, 선택은 `?tab=graph|people|book|overview`에 남아 새로고침·공유해도 그대로이며 기본은 설정 그래프, 탭을 옮길 때는 기록을 쌓지 않음)을 둡니다. **설정 그래프**는 세계관을 중심으로 설정 카드(WorldStudio 지도와 같은 유형 색)가 이어진 노드 그래프이고 중심→카드는 옅은 선, 카드끼리의 연관은 진한 선이며 노드가 30개 이하라 이름을 늘 캔버스에 그립니다(HTML 툴팁 없음). **인물관계도**는 인물 카드만 노드로 하고 인물 사이의 관계를 라벨 있는 선(캔버스 텍스트)으로 그리며, 인물이 2명 미만이면 빈 상태 문구를 보이고, 서버가 관계를 불러오지 못했다고 알리면(`relationshipStatus: unavailable`, 카드는 그대로 오고 관계만 비어 옴) 빈 그래프와 구분해 "관계를 불러오지 못했어요"를 보이며(설정 그래프의 연결 수도 0 대신 그렇게 알림), 메모리 데모만 위에 "데모 · 공개 범위 확정 전"을 둡니다. 두 그래프는 세계관 지도와 같은 어두운 캔버스 카드·컨트롤(`useMapCanvas`·`MapControls`)을 쓰고 캔버스 높이만 데스크톱 460px·모바일 340px이며, 노드를 누르면 그 설정 카드의 페이지(`/worlds/:id/cards/:cardId`)로 이동합니다(세계관 중심 노드는 설정집 탭). 캔버스는 `role="img"`와 요약 `aria-label`로 알리고 같은 내용은 설정집 게시판과 카드 페이지가 글로 대신합니다. **설정집**은 설정 카드를 카테고리별로 보는 게시판입니다: 위에 한 줄 요약(장르·작가·설정 카드 수, 데모는 파생·조합된 세계관 수), 왼쪽에 분류 메뉴(전체·카드가 있는 유형별 장수, 선택은 `aria-current`이고 `?tab=book&type=<유형>`에 남음), 오른쪽에 검색(제목·본문)·정렬(설정집 순·연결 많은 순·가나다순)·결과 수 도구와 게시판 표(`<table>`, 번호 · 분류(유형 색 점) · 제목(굵은 링크, 옆에 인물은 관계·그 밖은 연결 수 `[3]`) · 요약(한 줄 말줄임) · 연결 수)를 둡니다. 행 전체가 아니라 제목 링크가 카드 페이지로 가는 주 링크이고, 좁은 화면(720px 이하)에서는 분류 메뉴가 가로 스크롤 칩이 되고 표는 번호·요약 열을 숨깁니다. 설정집 탭에는 개요를 두지 않습니다. **개요** 탭(`view/WorldOverview.tsx`)이 세계관 설명(비어 있으면 '아직 세계관 설명이 없어요.')과 정보 상자(작품 설정 위키(`PublicWikiArticle`)와 같은 `nw-*` 클래스·CSS(`reading/view/publicWiki.css`): 세계관 이름·표지·장르·작가·설정 카드 수, 데모는 파생·조합 출처)를 보이고, 계보가 있는 데모는 설명 아래에 출처 한 줄과 이 세계관에서 파생·조합된 세계관 줄이 붙습니다. 600px 이하에서는 네 탭이 사이 간격 없이 폭을 나눠 한 줄에 들어갑니다. 필터·정렬·번호(`bookRows`)·분류 장수·`?type=` 해석은 `features/worlds/worldDetail.ts`의 순수 함수이고 단위 테스트가 있습니다. 카드와 관계는 서버 응답의 카드 id·현재 관계(양 끝 카드 id)로 만들고, 같은 두 카드 사이의 서로 다른 관계 여럿은 첫 관계만 보입니다(`ponytail:` 주석). 상세 헤더에는 가져오기 버튼을 두지 않습니다. 로그인한 회원은 설정집 게시판에서 줄마다 체크박스(머리 칸은 `보이는 설정 모두 선택`)로 고른 뒤 **`선택한 설정 가져오기 (N)`**(`WorldAddMenu`, 공용 `PopMenu`)를 엽니다: 열 때 내 세계관(`worldStudioUseCase.list()`, 원본 세계관 자신은 제외)을 읽어 불러오는 중·실패(다시 시도)·가져갈 세계관 없음(세계관 만들기 `/worldstudio`)을 따로 보이고, 내 세계관을 고르면 이동 없이 고른 설정만 그 세계관 **초안에 바로 추가·저장**합니다(`worlds/viewmodel/useWorldImport.ts`: `worldStudioUseCase.read` → 공용 `presentation/shared/importCards.ts`의 `importCards`·`appendImported` → `save`. 관계 제외·비공개·출처 기록). 진행·결과와 실패 사유·`다시 시도`는 그 자리에 보이고 실패를 성공으로 바꾸지 않습니다.
**설정 카드 페이지**(`/worlds/:id/cards/:cardId`, 로그인 없이 읽기만, `cardId`는 서버 카드 id이고 데모는 카드 위치)는 카드 한 장이 나무위키 형식 문서 한 편입니다: 빵부스러기(세계관 › 유형 › 카드, 유형은 설정집의 그 분류로 돌아감) → 분류 상자 → 문서 제목 → 오른쪽 정보 표(맨 위 유형 색 칩, 인물은 소속(이어진 조직)·관계 수, 그 밖은 연결 수, 세계관) → 번호 목차 → 번호 매긴 접이식 문단(본문은 마크다운(`react-markdown`+`remark-gfm`, 원시 HTML·이미지는 렌더하지 않음)이고 `## 제목`마다 문단이 나뉘며 첫 `##` 앞은 개요(`shared/cardSections.splitCardSections`), 이어서 관계(인물), 3. 연관 설정, 4. 이 카드를 가리키는 설정, 5. 같은 유형의 다른 설정 — 내용이 없는 문단은 빠지고 번호는 끊기지 않음). 인물의 다른 인물과의 관계는 '관계'에만 나오고 한 카드는 한 목록에만 나오며 모든 목록은 설정집 순서입니다. 아래에 설정집 순서의 이전·다음 설정과 세계관으로 돌아가기(`/worlds/:id?tab=book`)가 있고, 그 세계관에 없는 카드 id·비공개/없는 세계관은 "찾을 수 없는 설정"·"찾을 수 없는 세계관"으로, 읽는 동안·실패는 불러오는 중·다시 시도로 따로 알리며 같은 세계관의 다른 카드로 옮겨도 세계관을 다시 읽지 않습니다. 목차 링크는 기본 이동을 막고 `scrollIntoView`와 `focus({preventScroll:true})`로 이동합니다(`prefers-reduced-motion`이면 부드럽게 스크롤하지 않음, 공용 `shared/Jump`). 내용 구성(`cardPage`)은 `worldDetail.ts`의 순수 함수입니다. 로그인한 회원에게는 빵부스러기 아래에 `이 설정 가져오기`가 보이고, 내 세계관을 고르면 이 카드 하나를 그 세계관 초안에 바로 추가·저장합니다(이동 없음, 관계 제외, 진행·결과·실패는 버튼 아래).
**세계관 상세 하단**(어느 탭이든 탭 영역 아래)에는 홈 선반(`sec`·`sec-h`·`shelf`·책 카드)과 같은 마크업의 선반이 있습니다. '이 세계관을 쓴 작품'은 소설-세계관 1:1 연결은 생겼지만(DEC-46) 공개 세계관 API가 연결된 소설을 주지 않아 실제 모드는 "연결된 소설 표시 준비 중"만 보이고, 메모리 데모는 `works`(상위 8개 세계관에 1~3편)의 작품 카드(표지 아트·제목·작가·n화)를 링크 없이 표지에 "데모 작품"을 달아 보이며 작품이 없으면 "아직 이 세계관으로 쓴 작품이 없어요"를 보입니다. '연결된 세계관'은 서버에 파생·조합이 없어(설정 가져오기가 대신합니다) 실제 모드에서는 그리지 않고, 계보가 있는 데모만 원본(이 세계관이 파생·조합된 출처)과 파생·조합된 세계관(응답의 `lineage`)을 표지 알약("원본"·"파생"·"조합")과 함께 한 선반에 보이고 카드를 누르면 `/worlds/:id`로 가며 이어진 세계관이 없으면 섹션을 그리지 않습니다.
**실시간 인기**는 홈 `Top10`과 같은 마크업·클래스(`aside.t10`·`t10h`·`live` 배지)의 순위 패널입니다. 서버 목록에는 조회수가 없어 최근 공개(`publishedAt`) 순 TOP10이고 배지 '최근 공개 순'이 그 기준을 알리며(파생·조합이 있는 데모는 파생·조합된 횟수 순, 같으면 설정 카드 수 순이고 배지 '파생·조합 순'), 항목(순위·이름·작가)을 누르면 `/worlds/:id`로 갑니다. 이동할 곳이 없는 '더보기 ›'는 아래 '세계관 모아 보기'로 스크롤하고 포커스를 옮깁니다. 좁은 화면에서는 홈과 같은 규칙으로 두 칸이 세로로 쌓이고 순위는 3위까지만 보입니다. 노드·링크 변환, 순위(`liveRank`·`rankByRecent`·`rankByLineage`), 장르 하이라이트는 `features/worlds/worldAtlas.ts`의 순수 함수이고 단위 테스트가 있습니다.
**한계·후속**: 파생·조합(`world_lineage`, 기능표 57)은 서버 계약에 없고 카드 단위 설정 가져오기(DEC-46)가 대신합니다(남의 세계관을 참조·추종하는 이용은 DEC-35대로 없음). 소설-세계관 1:1 연결은 생겼지만 공개 세계관 응답이 연결된 소설을 주지 않아 '이 세계관을 쓴 작품'은 데모에만 있습니다. 서버가 주게 되면 계약에 필드를 더하고 데모 전용 선택 필드(`derivedFrom`·`combinedFrom`·`lineage`·`works`)를 그 응답으로 바꿉니다. 인기 지표가 없어 '인기 세계관' 선반은 두지 않고(조회수 API가 생기면 서버 순위로), 표지는 소유자가 올린 이미지(`hasCover`일 때 공개 cover 주소 `/api/v1/public/world-studios/{id}/cover`를 `<img>`로 직접 씁니다)이거나 장르별 테마 아트입니다. 세계관의 공개 여부·장르·표지를 정하는 화면은 세계관 작업실 쪽입니다.
세계관 만들기·편집은 내 서재의 '내가 만드는 세계관' → `/worldstudio`에서 합니다. 그 탭의 카드는 작품 카드처럼 오른쪽 '관리하기'로 작업실을 열고, 아래 '새로 시작하기'의 점선 카드 셋은 '새 세계관 만들기'·'원고로 세계관 정리하기'가 `/worldstudio`, '공개 세계관 둘러보기'가 `/worlds`로 갑니다(AI 후보 검토는 작업실 안의 도구라 직접 진입 주소가 없고 입력도 에피소드 원고가 아닌 저장한 세계관 초안이라, 둘째 카드는 작업실로 보내며 그렇게 안내합니다). 세계관의 공개 범위·장르와 설정 카드마다의 공개는 작업실에서 정하고, 공개로 바꾼 세계관은 `/worlds`에서 누구나 읽을 수 있되 공개로 둔 설정 카드만 보입니다(아래).
**세계관 관리·작성**(`/worldstudio/:id`)은 `/content` 작품 관리와 같은 틀(공용 `episode-app`·`ep-*`)입니다. 맨 위에 서재(`/lib?tab=worlds`)로 돌아가는 링크, 공개 세계관 상세와 같은 모양의 헤더(표지(올린 이미지, 없으면 생성 표지 아트)·이름·소개, 칩: 설정 수·저장 버전·공개 범위·장르·저장 상태)와 연결된 소설 한 줄이 있고, 화면은 두 모드입니다. **작성 모드**는 세계관을 처음 만든 직후(만들기 화면이 이동하는 `/worldstudio/{id}?new=1`, 새로고침해도 유지)에만 보이며 보기 전환 줄 없이 번호 스텝 4단계 마법사(기본 정보(이름·설명·공개 설정) → 설정 카드 → 관계 연결(선택) → 검토·저장) 카드로 처음 씁니다. 마법사의 첫 저장이 성공하거나 헤더의 '관리 화면으로'를 누르면 `new` 쿼리를 `replace`로 지워 **관리 모드**로 바뀌고 초점이 헤더 제목으로 갑니다(쓰던 입력은 그대로 남습니다). 판정은 `worldstudio/viewmodel/worldStudioFlow.ts`의 순수 함수 `studioMode`(주소의 쿼리, 단위 테스트가 있습니다)입니다. 그 밖의 모든 진입(서재 '관리하기'·직접 주소, 저장 버전이 0인 세계관 포함)은 **관리 모드**로, 단계 없이 두 화면입니다. **설정집 화면**(기본)은 `/content` 작품 관리처럼 헤더 아래 보기 전환 줄로 설정집(기본)·인물 관계도·시간선을 나눕니다(주소 `?view=people|timeline`으로 유지·복원, 설정 카드를 열면(주소 `?card=<id>`) 집필실과 같은 3단으로 이 화면을 대신합니다(아래). 보기 이동은 같은 화면 이동이라 저장하지 않은 입력과 적용하지 않은 관계 입력을 잃지 않고 이탈 확인도 하지 않습니다(이탈 가드는 같은 경로의 이동을 막지 않고 다른 화면으로 나갈 때만 묻습니다). 보기 전환 줄 오른쪽에는 `AI 후보 검토 (대기 N)` 버튼(시트)·`집필 메모 추가`(새 메모를 초안에 더하고 그 편집 화면을 엽니다. 보기 전환 줄이 없는 작성 모드에서는 헤더 행동 줄에 있습니다)·`확정 버전 남기기`(편집 화면 버전 그래프와 같은 확정 버전 시트, 저장하지 않은 변경이 있으면 이유와 함께 잠김)와 **상시 저장 영역**이 순서대로 있습니다: 바뀐 것이 있으면 '저장하지 않은 변경 있음'과 채로 시작하고, 설정집 화면은 900px 이하에서 열면 뒤 화면을 막는 대화 상자 서랍(공용 `Sheet`, Esc·배경으로 닫힘)이며 편집 화면은 그 폭에서 편집기 아래 영역입니다, 추천 문구 '인물 카드 아이디어'·'이 설정의 모순 찾기'·'관계 제안', 전송·첨부는 연결 전이라 '준비 중'으로 잠기고 가짜 응답은 없습니다). **설정집** 보기(작성 모드는 설정 카드 단계)는 공개 설정집과 같은 게시판입니다: 왼쪽 분류 메뉴(전체·인물·장소·조직·규칙·사건·기타와 개수) + 오른쪽에 검색(placeholder가 잘리지 않을 폭)·정렬(라벨 한 줄)·결과 수·`다른 세계관에서 가져오기`(가져오기 시트, 아래)·`+ 새 설정`(유형을 고르면 그 카드를 초안에 더하고 편집 화면을 엽니다) 도구줄이 위, 공개 범위를 한 번에 바꾸는 줄(`선택 공개`·`선택 비공개`·`전체 공개`)이 그 아래, 선택·번호·분류·제목[연결 수]·요약·공개·연결 7칸 표가 맨 아래입니다(제목 열은 줄바꿈하지 않고 요약은 말줄임). 게시판은 뷰포트가 아니라 자기 폭(컨테이너 `worlds-board`, 760px 이하)으로 좁은 배치를 고르고, 그때 숨는 분류·요약은 제목 아래 한 줄로 보입니다. 표는 공개 범위 말고는 보기만 합니다: 제목을 누르면 그 카드의 **편집 화면**이 열리고(돌아오면 그 행에 초점), 카드가 없으면 안내는 표 안 빈 행 한 줄뿐입니다. **설정 카드 공개**(DEC-46)는 카드 단위이고 기본은 비공개입니다. 게시판에서는 맨 앞 체크박스로 고른 줄(지금 보이는 줄만 셉니다)을 `선택 공개`·`선택 비공개`로, 설정집의 카드 전부를 `전체 공개`로 바꾸고(집필 메모·관계는 건드리지 않음) `공개` 칸이 카드마다 공개/비공개를 보이며(바꾼 뒤에는 결과를 상태 문구로 알리고 초점을 표 머리 체크박스로 옮김), 편집 화면에서는 `이 설정 공개` 스위치로 바꿉니다. 규칙은 `worldstudio/viewmodel/cardVisibility.ts`의 순수 함수(`setCardVisibility`·`publishAllCards`·`publicCardCount`, 단위 테스트)입니다. 공개 세계관(또는 공개로 고른 세계관)인데 초안에 공개 카드가 없으면 경고 "공개로 둔 설정이 없어요. 세계관을 공개해도 공개 화면에는 설정이 보이지 않아요."와 `전체 공개`(`PublicCardsNotice`)를 관리 헤더(정보 편집 패널이 닫혀 있을 때)·정보 편집 패널(공개를 고른 때)·작성 모드 공개 설정에 보이되 공개 설정 저장은 막지 않습니다. 카드 공개·독자 공개 회차·가져온 카드는 모두 **초안 값**이라 세계관 저장과 `확정 버전 남기기`를 거쳐야 공개 세계관 화면과 독자 설정 위키에 반영되고, 화면이 도움말로 그렇게 알립니다(공개 0개 경고도 초안 기준입니다). **설정 가져오기**(DEC-46, `WorldImportSheet`)는 서버 API 없이 공개 조회 응답을 복사합니다: ① 공개 세계관 목록(`PublicWorldUseCase.list`, 대상 세계관 자신은 제외, 공개 설정이 0개인 세계관은 고를 수 없고 목록은 UseCase가 주는 최근 공개분까지) → ② 그 세계관의 공개 설정을 체크(전체 선택)하고 `같이 가져온 카드 사이 관계 포함`(기본 꺼짐, 관계를 불러오지 못한 응답이면 비활성)을 정해 `설정 N개 가져오기`를 누르면 초안 끝에 새 id·비공개·독자 공개 회차 없음의 카드로 더하고 출처 `importedFrom{worldId, worldName, authorNickname, revisionNo, cardId}`를 기록합니다(공개 세계관 화면의 바로 추가와 함께 쓰는 `presentation/shared/importCards.ts`의 `importCards`·`appendImported`·`importableWorlds`, 단위 테스트. 시트의 공개 세계관 조회는 `worldstudio/viewmodel/useWorldImport.ts`). 관계는 양 끝을 모두 가져온 것만 옮기고, 공개 상세가 이름만 주므로 원본의 양 끝 순서를 지킨 사용자 정의 방향 관계(`custom_relation_directed`)로 넣습니다(방향·종류·부정 여부는 알 수 없음). 활성 카드 1,000개 한도를 넘기면 아무것도 더하지 않고 이유를 보이며, 불러오는 중·실패(다시 시도)·가져올 세계관 없음·찾을 수 없는 세계관(비공개 전환 등)을 따로 보입니다. 시트는 게시판의 `다른 세계관에서 가져오기`로만 열고 늘 세계관 고르기부터 시작합니다(공개 세계관 상세에서 주소 `?import=`로 넘어오던 길은 없앴습니다). 가져온 카드는 게시판 행과 편집 화면에 `가져옴`과 출처 `참고: {세계관 이름} 세계관 · {작가}`를 보이고, 가져온 뒤 원본의 변경·비공개 전환·삭제는 따라가지 않습니다. 편집 화면은 집필실(`WritingStudio`)과 같은 3단입니다: 왼쪽 레일에 설정 카드 목록(검색·분류 필터·현재 카드 강조·`+ 새 설정`·항목 ⋮ 메뉴의 삭제)과 크기 조절선 아래 버전 그래프(작업 초안과 확정 버전 줄, 확정 버전은 시트에서 읽기 전용으로 보고 `확정 버전 남기기`로 남기며 관계는 회차별로 기록하고 확정 버전에는 포함되지 않음), 가운데 편집기(큰 이름 입력·설명(인물 카드는 아래의 인물 문서, 그 밖은 Toast UI Editor 3 마크다운 편집기, 편집 화면에서만 지연 로딩, WYSIWYG·이미지 업로드·사용 통계 끔. Tab은 들여쓰기이고 Esc 다음 Tab으로 편집기를 벗어나며(안내 한 줄) 쓰기·미리보기 탭은 ←→·Enter·Space로 바꿈)·공개 범위·유형·이어진 설정·관계 읽기 전용 요약·상세 설정, 글자 수·삭제 하단 바), 오른쪽 AI 채팅입니다. 편집기의 **공개 범위** 구획(DEC-46, 관계 행에는 없음)에는 `이 설정 공개` 스위치(기본 꺼짐)와 `독자 공개 [ ]화부터`(숫자만 받는 글자 칸, 비우면 독자에게 숨김, 쓸 수 없는 값이면 입력 아래에 이유)가 있습니다. 독자 공개 회차는 연결된 소설(`linkedWorkId`)이 있을 때만 입력할 수 있고 없으면 "소설을 연결하면 설정할 수 있어요"(`--mode mockup`은 "데모에서는 소설 연결을 지원하지 않아 설정할 수 없어요.")로 알리며, 1 이상의 정수가 아니면 저장 전 확인(`worldWritingIssues`)과 `WorldStudioUseCase.save`가 같은 문구("독자 공개 회차는 1 이상의 정수로 입력해 주세요.")로 막습니다(발행된 회차를 넘는 값인지는 화면이 검사하지 않고, 서버가 발행된 회차 안에서만 독자에게 보입니다). **인물 문서**(DEC-47, `view/CharacterDocs.tsx`·`viewmodel/useCharacterDocs.ts`, 규칙은 `domain/entities/characterDocs.ts`의 순수 함수)는 인물 카드를 설명 하나 대신 문서 네 종류로 쓰게 합니다: 설명 자리에 문서 목록(`IDENTITY.md`·`SOUL.md`·`MEMORY.md`, `memory/` 아래 `NN회차.md`, 고른 문서는 `aria-current`)과 고른 문서의 마크다운 편집기(문서·카드가 바뀌면 다시 만듦), 문서마다의 작성 안내 한 줄이 있고, `회차 기억 추가`(회차 번호 0 이상의 정수, 이미 있으면 그 문서를 고름)·`회차 기억 삭제`(확인 후)·`.md 파일 불러오기`(여러 파일, 파일 이름으로 문서를 정하고 알아볼 수 없는 이름은 가져오지 않고 알림, 내용이 있는 문서는 덮어쓰기 전 확인)가 있습니다. `IDENTITY.md`가 카드 본문(`item.text`)이라 공개 세계관·독자 설정 위키·게시판 요약에는 이 문서만 나가고 나머지는 작가용입니다(화면이 한 줄로 알림). 세 고정 문서 중 빈 것은 문서 버튼과 게시판의 그 인물 줄에 `정리 필요`로 알리되 저장·확정을 막지 않고, 3,000자를 넘은 문서(IDENTITY.md 포함)와 0 이상의 정수가 아닌 회차 번호는 저장 전 확인과 `WorldStudioUseCase.save`가 문서 이름을 붙인 같은 문구로 막습니다. 인물에서 다른 유형으로 바꾼 카드에 문서가 남아 있으면 저장할 때 사라진다고 경고합니다. 서버 매핑(`HttpWorldStudioRepository`)은 카드 `visibility`를 행 값(없으면 `private`)으로 보내고, 독자 공개 회차·출처·인물 문서는 카드 `semanticMetadata`의 최상위 키 `revealFromEpisode`·`importedFrom`·`characterDocs{soul, memory, episodes}`에 행 필드를 정본으로 둡니다(`studio` 안에 넣지 않고, 값이 없으면 키를 넣지 않으며, 읽을 때 어긋난 값은 버리고 세계관 로드는 계속). 삭제는 유형과 상관없이 이어진 관계 수를 확인한 뒤 함께 지우고(다른 설정이 아직 참조하면 막습니다. 확인 영역은 열릴 때 초점·스크롤이 가고 닫히면 연 버튼으로 돌아옵니다) 설정집 화면에서 되돌릴 수 있으며, 세계관 저장으로 서버에 반영합니다. 위 상단 바의 `← 설정집`과 브라우저 뒤로가기는 설정집 화면으로 돌아옵니다. 분류·정렬·번호 규칙은 공개 설정집과 함께 쓰는 `presentation/shared/worldBoard.ts`, 편집 중 설정을 게시판 줄로 바꾸는 규칙은 `worldstudio/viewmodel/settingBoard.ts`의 순수 함수이고 단위 테스트가 있습니다. **인물 관계도** 보기(작성 모드는 관계 연결 단계)는 공개 인물관계도와 같은 어두운 면 위의 카드 그래프(범례 포함)에서 카드를 차례로 두 번 누르면 오른쪽 '관계 추가' 폼의 주체·대상이 채워지고 관계 작성이 열리며(`relationPick.ts`), `관계 기준 회차` 칸(DEC-51: 소설을 연결한 서버 세계관만, 비우면 최신 — 고르면 그 회차 시점의 관계를 다시 읽고 저장도 그 회차로 기록하며, 저장하지 않은 변경·AI 후보 검토·확정 버전 요청 중·데모·소설 미연결이면 이유와 함께 잠기고, 지난 회차를 연 채 저장하면 저장 영역이 `관계는 N화 기준으로 저장돼요`를 알리며, 회차를 고른 동안은 설정 삭제가 잠기고(삭제는 최신 회차에서만) 삭제된 설정을 끝점으로 하는 지난 회차 관계는 `삭제된 설정: 이름`으로 읽기 전용), 관계 목록 표(주체·관계·대상, 편집·삭제)와 관계 작성은 기존 초안·적용 흐름 그대로 '편집본에 적용'·세계관 저장으로 반영합니다(목록의 삭제는 확인 뒤 편집본에서만 지우고 저장해야 서버에 반영됩니다). `/worldstudio`(세계관 없음)는 새 작품 만들기와 같은 모양의 새 세계관 만들기 화면이고, 내 세계관 목록은 그 아래에 작게 남아 다른 세계관 열기에 쓰입니다. 이 만들기·목록 화면은 `/worldstudio`에서만 그리며 관리 주소(`/worldstudio/:id`)에는 숨겨서라도 두지 않습니다. '세계관 만들기'가 성공하면 `/worldstudio/{id}?new=1`로 이동해 마법사로 엽니다.

## 원고 가져오기·내보내기 (기능 17·18)

[계약](../docs/design/manuscript-import-export-contract.md)대로 `ManuscriptRepository`·`ManuscriptUseCase`·`HttpManuscriptRepository`를 Awilix에서 조립합니다.

- `/import`(실제 모드): 내 작품 선택(`?work=<UUID>`로 사전 선택) → 권리 확인 3가지 → `.txt`·`.epub` 파일 → 서버 미리보기(회차별 제목 수정·제외·다음 회차와 합치기·경고) → 확정 → 회차별 성공·일부 성공·실패 결과. 작품이 없으면 `/content`에서 만들고, **세계관 만들기**는 `/worldstudio`를 엽니다(만든 세계관은 작품과 연결되지 않음). 가져오기 입력이 있으면 두 링크로 이동하기 전에 입력을 버릴지 확인합니다. 확정 회차 번호는 조정 목록의 순서이고 제외한 회차도 번호를 차지합니다. 실패 항목은 확정 응답에만 있어 화면을 떠나면 다시 볼 수 없습니다. `--mode mockup`은 기존 데모 가져오기 화면(`ImportPage`)을 그대로 씁니다.
- `/studio/{UUID}` 내보내기: 형식(TXT·EPUB)·범위(현재 회차·작품 전체)·원본(초안·발행본)을 골라 서버 GET을 Blob으로 받고 `Content-Disposition`의 `filename*`로 저장합니다. 서버에 저장된 원고를 내보내므로 입력 중·저장 중에는 잠급니다.
- `--mode mockup`의 가져오기·EPUB/발행본 내보내기·첨부 이름 변경은 성공을 흉내 내지 않고 "데모에서는 지원하지 않아요" 오류를 냅니다. 데모 집필실의 TXT 초안 내보내기만 메모리 원고로 실제 파일을 만듭니다(`createMockupManuscriptRepository`).
- nginx(`frontend/nginx.conf`, `infrastructure/nginx.dev.conf`)의 `/api/v1/works/`는 요청 본문을 51MB까지 받습니다.

## 회차 이미지 설명·본문에서 빼기 (기능 16-C)

[계약 5절](../docs/design/manuscript-import-export-contract.md)대로 `MediaRepository`에 회차 이미지 목록·대체 텍스트 PATCH·공개 대체 텍스트 조회를 두고 응답은 Zod로 검증합니다(소유자 목록의 `url`은 기존 다운로드 경로와 같아야 합니다).

- `/studio/{UUID}`의 `EpisodeImagePanel`: 현재 회차에 올린 이미지(파일명·크기·본문 사용 여부), 이미지별 설명(최대 300자) 저장, '본문에서 빼기'. 빼기는 현재 초안에서 `[[image:ID]]` 표식(과 앞뒤 빈 줄)만 지우고 기존 초안 저장(`PUT .../draft`, revision 검사)으로 저장한 뒤 집필실의 `reload`로 최신 초안을 다시 읽습니다. 저장하지 않은 입력이 있거나 저장 중이면 막고 먼저 저장하도록 안내하며, 저장이 실패(revision 충돌 등)하면 서버 사유와 다시 불러오기 안내를 보이고 입력한 설명은 그대로 둡니다. 이미지 파일은 저장 버전·발행본이 참조할 수 있어 지우지 않습니다.
- 독자 화면: 회차 열람(`/read`)은 발행본을 원고 기본 서식(DEC-48, [계약](../docs/design/manuscript-format-contract.md))대로 그립니다. `ReadingUseCase.openEpisode`가 `domain/entities/feedback.ts`의 `readerBody`로 그릴 블록(`blocks`: 문단·인용·소제목·구분선·이미지·빈 줄)과 고를 문장(`paragraphs`)을 함께 주고, 문장의 `t`(댓글 인용·피드백·수정 제안에 보내는 글)는 줄 안 기호를 포함한 원문 조각입니다(줄 맨 앞 `## `·`> `·`\`는 빼고, 인용은 줄마다 나눔). 문단·인용 안의 줄바꿈은 줄바꿈으로 보입니다. 본문 이미지는 공개 작품이면 공개 경로와 `GET /api/v1/public/works/{id}/episodes/{n}/images`의 대체 텍스트로(이미지가 있을 때만 익명으로 읽음), 작가가 자기 비공개 작품을 미리 읽을 때는 소유자 경로로 받으며 설명이 없거나 읽지 못하면 `본문 이미지 N`을 씁니다. 저장 버전 보기·버전 비교·체크포인트·작품 관리 '원고 보기'·집필실 미리보기는 공용 `ManuscriptBody`가 같은 문법(`domain/entities/manuscriptFormat.ts`의 `manuscriptLine`·`inlineParts`·`manuscriptBlocks`)으로 그립니다. 한 줄의 내용이 2,000자를 넘으면 그 줄의 굵게·기울임은 해석하지 않습니다(길이 상한).
- `--mode mockup`에서는 목록·설명 저장·공개 설명 조회가 "데모에서는 지원하지 않아요" 오류입니다(성공을 흉내 내지 않음).

## 검증

로컬 개발은 변경·직접 영향 범위의 **단위 테스트 파일만** 지정합니다. 전체 suite·빌드·React 조립·브라우저/E2E는 로컬 개발 검증으로 실행하지 않습니다.

```bash
pnpm exec vitest run src/domain/__tests__/LibraryUseCase.test.ts
# Data 단위 테스트도 실제 서버 대신 fetch 대역을 사용합니다.
pnpm exec vitest run src/data/api/auth.test.ts
```

CI는 [공통 검증 정책](../docs/development.md#검증)에 따라 web 서비스의 단위(Domain/Data/HTML)와 나머지 React/Hook/App 통합을 분리 실행하고 lint/build도 수행합니다.
워크플로가 이 디렉터리에서 `pnpm exec vitest run src/domain src/data src/index-html.test.js`와 해당 파일들을 `--exclude`한 통합 명령을 직접 호출합니다. 별도 테스트 runner나 shell wrapper는 없습니다.
앱·라우트 횡단 통합 테스트는 `src/test/integration/`에, 기능별 테스트는 기존 기능 파일 옆에 둡니다. 공통 테스트 도구는 `src/test/`에 두고, HTML 단위 테스트는 CI 명시 경로인 `src/index-html.test.js`에 유지합니다.
Core API 변경 시 web 소비자 회귀도 선택합니다. 실제 HTTP 시스템 시나리오는 CI Compose에서 실행하며 브라우저 UI 검증이 아닙니다.
Aside는 별도 요청·승인 시에만 사용합니다. hosted `Required CI` 결과 확인 전에는 검증 대기로 보고합니다.

서버 작품은 `/studio/{UUID}`에서 회차별 실제 저장 API를 사용합니다. 데모 세션 대신 Core의 인증 결과를 따르며, 기존 이름 기반 데모 집필실과 구분합니다. 자동저장·버전 저장·복원과 검증 범위는 [이슈 #50 대응](../docs/issue-50-alignment.md)을 참고하세요.
