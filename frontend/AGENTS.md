# Frontend 구현 지침

`frontend/**`에 적용한다. [루트 공통 지침](../AGENTS.md)을 함께 따른다.
nginx/Vite는 `/api/v1/works`·`/api/v1/public/works`·`/api/v1/world-studios`·`/api/v1/public/world-studios`와 하위 경로를 Content, `/api/v1/operations/{reports,members,admins,support,works,comments,admin/notices,public/notices,admin/events,public/events,admin/activities}`와 하위 경로를 Operations, 나머지 `/api`를 Core로 라우팅한다(서비스 토큰용 `/api/v1/operations/{notices,events,inquiries}`는 열지 않는다).
`/content`·UUID `/studio/{id}`와 작품 목록·상세·회차 열람·공개 wiki·Fork 생성은 Content API(`HttpWorkRepository`)를 쓰고,
실제 작품(canonical) 회차 열람의 댓글은 `HttpEpisodeCommentRepository`([계약](../docs/design/episode-comment-contract.md))를, 메모리 데모 작품의 댓글은 메모리 저장소를 쓴다. 소설 상세 아래의 작품 전체 댓글(읽기 전용, `GET /public/works/{id}/comments`)도 같은 Repository의 `listByWork`를 쓰며 데모 작품은 "데모에서는 지원하지 않아요"로 알린다. 실제 작품의 문장 피드백(제보)·회차 제보 목록·내 제보·작가 피드백함 제보는 `HttpFeedbackReportRepository`를 쓴다([계약](../docs/design/feedback-report-suggestion-contract.md)). 실제 작품의 문장 수정 제안·작가 피드백함 수정 제안 승인·내 제안은 `HttpEditSuggestionRepository`를 쓴다([계약](../docs/design/feedback-report-suggestion-contract.md)). 소설 상세 소식 탭(작품 공지)의 목록·작성·수정·고정·삭제는 실제 작품이면 `HttpWorkNoticeRepository`([계약](../docs/design/work-notice-contract.md))를, 메모리 데모 작품이면 "데모 소식" 안내와 함께 메모리 저장소를 쓴다.
`/content` 작품 관리의 작품 정보 편집은 제목·소개와 함께 서버 값과 달라진 장르·해시태그만 `PUT /works/{id}`에 싣고(생략하면 서버가 유지), '받은 피드백' 탭은 작가 피드백함과 같은 조회에 `workId` 쿼리를 보내 서버가 그 작품 것만 주며(화면이 다시 거르지 않는다), 회차별 포크 수는 새 API 없이 소설 상세와 같은 `ReadingUseCase` 작품 목록으로 센다(읽지 못하면 수를 감춘다). 표지의 'AI로 생성'은 연결 전이라 비활성·'준비 중'이다. 실서버 집필실(`/studio/{UUID}?ep=n`)은 n화를 처음에 열고, 활성 회차가 바뀌면(목록 선택·새 회차·삭제·다시 읽기) 주소의 `?ep=n`도 `replace`로 따라 바뀌어 새로 고침이 보던 회차로 열린다(`WritingStudio`가 맡고, 처음 연 회차는 주소를 건드리지 않는다). 세계관·설정집 탭 맨 위의 `세계관 연결`(`LinkedWorldPanel`)은 이 소설과 내 세계관(WorldStudio)의 1:1 연결·해제를 `PUT /works/{id}/world-studio`(`EpisodeUseCase.linkWorldStudio`, `worldId: null`이 해제)로 바로 적용하고 응답의 연결로 작품의 `worldStudioId`를 바꾸며, 404·409(`WORLD_ALREADY_LINKED`)는 서버 문구를 그 카드 안에 그대로 알린다(작품 만들기·분기 만들기의 실패도 각 폼 안에, 그 밖은 화면 맨 위 알림: `useEpisodeViewModel`의 `origin`)(DEC-46, [계약](../docs/design/public-world-contract.md)). 연결할 세계관 드롭다운의 기본값은 `선택 안 함`이고 고르기 전에는 연결 버튼이 잠겨 이유를 알린다(UC-24 E1: 세계관을 고르지 않으면 연결하지 않는다).
설정 위키(`/work/:id/wiki`, U45)는 작품에 연결된 세계관이 있으면 `GET /public/works/{id}/world-cards?upto=`가 주는 독자 공개 설정 카드(`ReadingUseCase.linkedWorldCards` → `reading/viewmodel/worldCardWiki.ts`)로 채우고, 없으면(`worldId: null`) 기존 `readWorld` 경로 그대로다. 독자 공개 회차는 서버가 발행된 회차 안에서 거르므로 화면은 카드를 거르지 않고(공개 세계관·가져오기·Fork 이어받기·공개 MCP도 같다: 카드 공개 기준은 DEC-53으로 하나이고 서버가 기준 회차 이하로 공개된 카드만 주며, 본문 링크의 대상이 숨어 있으면 서버가 글자만 남기므로 화면은 공개 응답을 거르거나 되살리지 않는다. 기준 회차 규칙과 본문 링크 치환은 서버 소스 구현·로컬 단위 테스트 통과, #485. 본문의 설정 링크는 `CardMarkdown`의 `cardLink`로 같은 위키 안 그 카드의 문서로 건너가게 그리고 위키에 없는 카드는 글자만 그린다), 관계를 불러오지 못한 응답(`relationshipStatus: unavailable`)은 빈 연결과 구분해 알리며, 조회 실패를 빈 위키로 바꾸지 않는다. 카드에 `imageId`가 있으면 정보 상자 맨 위에 `GET /public/works/{id}/world-card-images/{imageId}?upto=`(위키가 받은 기준 회차 그대로)를 `<img>`로 직접 읽고 읽지 못하면 감춘다(`Doc.cardImage`, 기존 작품 위키 문서의 `img`는 그리지 않는다).
좋아요·관심 작품·독서 기록은 Content API(`HttpWorkLikeRepository`·`HttpWorkInterestRepository`·`HttpReadingRecordRepository`, [계약](../docs/design/reading-management-contract.md))를 쓰고, 나머지 데모는 별도 메모리 저장소다. 관리자 이벤트 탭과 회원 `/me/event`는 운영 이벤트 API(`HttpEventRepository`)를 쓴다([계약](../docs/design/operations-event-contract.md)). 관리자 작품 탭은 운영 작품 API(`HttpOperationsWorkRepository`)를 쓴다([계약](../docs/design/operations-work-contract.md)). 관리자 댓글 탭은 운영 댓글 API(`HttpOperationsCommentRepository`)를 쓰고, 회차 댓글은 운영 숨김(`hidden`)을 자리표시로 그린다([계약](../docs/design/operations-comment-contract.md)). 관리자 활동 로그 탭은 운영 활동 기록 API(`HttpAdminActivityRepository`)를 쓴다([계약](../docs/design/operations-admin-activity-contract.md)). 화면 존재와 서버 기능 완료를 구분한다.
계정 '결제 내역'(`/me/pay`)의 보유 크레딧·지급/사용/소멸 내역은 Core 크레딧 API(`HttpCreditLedgerRepository`)를 쓴다([계약](../docs/design/credit-ledger-contract.md)). 상단 계정 메뉴의 '보유 크레딧' 줄도 같은 API의 잔액만 읽는다(`useCreditBalance`, 읽지 못하면 0으로 채우지 않는다). 스튜디오 데모 AI 차감(`CreditUseCase`)은 별도 메모리 상태이며 바꾸지 않는다.
계정 프로필의 회원탈퇴(U30)는 Core 탈퇴 API(`HttpWithdrawalRepository`, `/api/v1/me/withdrawal`)로 30일 유예 탈퇴를 요청·복구하고, 요청이 받아지면 서버가 모든 세션을 끊으므로 이 브라우저도 로그아웃한다. `--mode mockup`은 요청 없음 상태만 보이고 탈퇴·복구는 데모 미지원 오류로 답한다.
홈 실시간 인기·급상승·최신 포크·방금 업데이트·이번 주 인기와 `/rank`는 Content 기간별 랭킹 API(`/public/works/rankings`)를, 홈 장르 칩과 `/search`는 공개 검색 API(`/public/works`, 인기 순·페이지)를 쓴다(`--mode mockup`은 시드 메모리 작품·검색).
계약은 [작품 검색·랭킹](../docs/design/work-search-ranking-contract.md)이다.
작품·세계관 표지는 화면마다 달리 그리지 않고 한 규칙(`shared/cover.ts`의 `coverSrc`)이다(#432): 올린 표지가 있으면 그 표지, 없으면 `/default-work-cover.svg`이며 테마·장르 SVG(`Art`)는 표지로 쓰지 않는다(`Art`는 작품 상세 띠·홈 히어로 배경·로그인 그림 같은 장식에만). 작품 표지(`CoverOf`·`Cov`)는 `Work.coverImg`(데모 메모리 작품만 가짐)를 쓰고, **서버 작품은 목록·상세 응답에 표지 유무가 없어 새 요청을 늘리지 않는 한 홈·상세·탐색·랭킹·챗 등에서 올린 표지가 있어도 기본 표지로 보인다**(서재 '집필 중인 작품'만 카드마다 소유자 읽기로 올린 표지를 보이며, 목록 응답에 표지 유무가 생기면 그 값으로 `coverImg`(공개 cover 주소)를 채워 이 한계를 없앤다). 세계관은 공개 화면이 `hasCover`로, 관리 헤더와 서재 '내가 만드는 세계관' 카드가 소유자 읽기(`shared/useWorldCoverImage`)로 올린 표지를 보이며 읽는 동안 서재 카드는 비워 둔다.
실제 모드 `/import`·집필실 원고 내보내기·설정 첨부 이름 변경·회차 이미지 목록과 대체 텍스트는 Content 원고 가져오기·내보내기 API(`HttpManuscriptRepository`·`HttpMediaRepository`)를 쓴다.
`--mode mockup`은 기존 데모 가져오기 화면을 유지하고, 데모 집필실의 TXT 초안 내보내기만 메모리로 만들며 나머지는 "데모에서는 지원하지 않아요" 오류를 낸다.
계약은 [원고 가져오기·내보내기](../docs/design/manuscript-import-export-contract.md)다.
`/worlds`(공개 세계관 추천 대시보드: 장르 칩 아래 홈과 같은 2단(왼쪽 장르→세계관 지도(노드 그래프), 오른쪽 최근 공개 순 '실시간 인기' 순위)과 '새로 공개된 세계관' 선반·모아 보기)·`/worlds/:id`(제목·작가 아래 설정 그래프·인물관계도·설정집·개요 네 탭, `?tab=graph|people|book|overview`; 설정집은 왼쪽 분류 메뉴(`?type=`)와 오른쪽 게시판 표(번호·분류·제목·요약·연결, 검색·정렬)이고 개요 탭(`view/WorldOverview.tsx`)이 세계관 설명과 `nw-*` 나무위키 정보 상자·표지를 보이며(설정집 탭에는 개요를 두지 않는다), 서버 `relationshipStatus`가 `unavailable`이면 인물관계도가 "관계를 불러오지 못했어요"로 알리며, 어느 탭이든 하단 홈 선반 형식의 '이 세계관을 쓴 작품'은 실제 모드에서 서버가 준 연결된 공개 소설(상세 응답의 `linkedWork`: 작품 id·제목·작가·`hasCover`, 소설이 공개 작품일 때만이고 연결 없음·비공개는 `null`, #329)을 책 카드 하나로 보이고 누르면 `/work/:id`로 가며(표지는 `hasCover`이면 공개 작품 표지 `/api/v1/public/works/{id}/cover/content`, 아니면 기본 작품 표지) 없으면 "이 세계관으로 공개된 소설이 아직 없어요"를 보이고, 데모(`works`)는 링크 없는 '데모 작품' 카드를 그대로 두며 '연결된 세계관'은 계보가 있는 데모에서만 그리고, 상세 헤더에는 가져오기 버튼을 두지 않는다)·`/worlds/:id/cards/:cardId`(설정 카드 한 장의 나무위키 형식 페이지, `cardId`는 서버 카드 id: 빵부스러기·정보 표·번호 목차·접이식 문단(본문 `#`·`##`·`###` 제목마다(하위는 상위 안, 번호 `1`·`1.1`·`1.1.1`, `####` 이하는 본문 소제목)·관계·연관 설정·가리키는 설정(본문 링크로 이 카드를 가리킨 카드도 들어간다)·같은 유형, 목차도 이 문단이며(본문의 설정 링크는 응답에 있는 카드의 페이지로 가는 링크로 그리고 응답에 없는 카드는 글자만 그린다) 첫 제목 앞의 글은 '개요'를 지어 붙이지 않고 제목 없이 목차 아래에 그린다)·이전/다음; 대표 이미지(카드의 `imageId`가 있을 때만)는 정보 상자 맨 위에 공개 `…/card-images/{imageId}`를 `<img>`로 직접 읽고 읽지 못하면 감추며 설정집 게시판 줄에는 제목 앞 작은 썸네일이 붙는다; 그래프·지도의 카드 노드를 누르면 열리고 로그인한 회원에게는 그 카드를 내 세계관 초안에 바로 더하는 `이 설정 가져오기`가 보임)는 비로그인도 읽는 Content 공개 세계관 API(`HttpPublicWorldRepository`, `GET /public/world-studios?genre=&page=&size=`·`GET /public/world-studios/{id}`, [계약](../docs/design/public-world-contract.md))를 `PublicWorldUseCase`로 읽는다(목록은 24개씩 최대 4쪽을 이어 붙이고, 장르 칩은 `genre` 쿼리로 모아 보기만 다시 읽으며, 불러오는 중·실패(다시 시도)·공개된 세계관 없음(`/lib?tab=worlds` 안내)·비공개/없는 세계관(404)을 실제 결과대로 그린다). 설정 카드는 기본 비공개이고 서버가 확정 버전의 공개 카드와 그 카드끼리의 관계만 주므로 화면은 카드를 거르지 않는다(DEC-46). 공개 화면에서 내 세계관 관리 화면의 가져오기 시트를 여는 버튼(`내 세계관으로 가져오기`)과 그 주소(`?import=`)는 없앴다: 설정과 그 사이의 관계를 함께 가져오려면 관리 화면의 `다른 세계관에서 가져오기`를 쓴다. 설정집 게시판의 `선택한 설정 가져오기 (N)`(줄 체크박스·`보이는 설정 모두 선택`)와 설정 카드 페이지의 `이 설정 가져오기`(`WorldAddMenu`)는 이동 없이 `worlds/viewmodel/useWorldImport.ts`로 고른 설정만 내 세계관 초안에 바로 추가·저장한다(`worldStudioUseCase.read` → 공용 `presentation/shared/importCards.ts`의 `importCards`·`appendImported` → `save`, 관계 제외·비공개. 대상은 `useImportTargets`가 내 세계관에서 원본 자신을 뺀 것). 진행·결과·실패 사유와 `다시 시도`는 그 자리에 보이고 실패를 성공으로 바꾸지 않는다. 지도·그래프 캔버스는 터치 기기(`pointer: coarse`)에서 지도 이동·노드 끌기를 꺼 한 손가락 끌기가 페이지 스크롤이 되게 하고(`view/useNodePointer.ts`, 이름이 숨은 노드는 첫 탭에 이름·다음 탭에 열기) 방향 이동 버튼(`MapControls`, `view/mapPan.ts`)은 터치 기기와 키보드로 컨트롤에 들어온 동안에만 보인다. 실제 모드의 `/worlds` 목록 위에는 가져오기를 어디서 하는지 한 줄로 알린다. `--mode mockup`은 `data/mock/InMemoryPublicWorldRepository`가 데모 세계관 26개(파생·조합·작품·카드 점은 이 데모에만 있고 "데모" 안내를 띄움)로 같은 계약을 답한다. 내 세계관 `/worldstudio/:id`는 `/content` 작품 관리와 같은 틀(`episode-app`·`ep-*`)의 관리 화면(서재 `/lib?tab=worlds`로 돌아가는 링크·공개 상세 모양 헤더)이고 `/worldstudio`는 새 세계관 만들기다. 만들기 화면과 내 세계관 목록은 세계관 없는 주소 `/worldstudio`에서만 그리며 `/worldstudio/:id`에는 숨겨서라도 두지 않는다. 세계관을 처음 만든 직후(만들기 화면이 이동하는 `/worldstudio/{id}?new=1`, 새로고침해도 유지)만 **작성 모드**로 보기 전환 줄 없이 기본 정보(이름·설명·공개 설정)부터 4단계 마법사 카드를 보인다. 마법사의 첫 저장이 성공하거나 '관리 화면으로'를 누르면 `new` 쿼리를 `replace`로 지워 **관리 모드**로 바뀌고(초점은 헤더 제목, 쓰던 입력은 그대로) 판정은 `worldStudioFlow.studioMode`(주소의 쿼리)다. 그 밖의 모든 진입(서재 '관리하기'·직접 주소, 저장 버전 0인 세계관 포함)은 관리 모드로, 단계 없이 두 화면이다. **설정집 화면**(기본)은 헤더 아래 보기 전환 줄(설정집·관계도·시간선, 주소 `?view=people|timeline`로 유지·복원, 보기 이동은 같은 화면 이동이라 미저장 변경을 잃지 않고 이탈 확인도 하지 않는다)과 줄 오른쪽의 `AI 검토` 버튼(이름에 설정집 검토 의견 수·후보 대기 수가 붙는다, 예 `AI 검토 · 의견 5 · 후보 2`, 시트 맨 위 '설정집 검토'(OpenAI 전송 동의 → `설정집 검토 요청` → `POST /api/v1/world-studios/{id}/reviews`, 소설 연결 불필요, 저장하지 않은 변경이 있으면 잠김, 결과는 저장하지 않는 화면 상태) 아래 기존 후보 검토, [계약](../docs/design/world-review-contract.md))·`집필 메모 추가`(관리 모드에서는 헤더가 아니라 이 줄에 두고, 이 줄이 없는 작성 모드에서만 헤더 행동 줄에 둔다)·`확정 버전 남기기`(편집 화면 버전 그래프와 같은 확정 버전 시트를 연다, 저장하지 않은 변경이 있으면 이유와 함께 잠긴다)·상시 저장 영역을 이 순서로 보인다. 옛 `?tab=`은 인물 관계도→`?view=people`(관계도), AI 후보 검토→AI 검토 시트, 그 밖(설정집·확정 버전·세계관 탐색)→설정집으로 `replace`한다(세계관 탐색 탭은 없다: 미리보기는 헤더의 '공개 화면 보기', 시간선은 보기 전환). **편집 화면**(주소 `?card=<id>`, 게시판 행의 제목·`+ 새 설정`·집필 메모 추가로 열고 `← 설정집`·브라우저 뒤로가기로 돌아오며 돌아오면 그 카드의 행에 초점이 간다, 불러온 초안에 없는 카드를 가리키는 `?card=`(새로고침으로 사라진 미저장 카드, 지운 카드의 옛 기록)는 설정집 화면으로 보고 기록을 쌓지 않고 주소에서 지운다(#470), 설정집 화면은 숨겨 두어 필터·입력·후보 검토 상태를 지킨다)은 집필실(`WritingStudio`)과 같은 3단이다: 왼쪽 레일(설정 카드 목록·검색·분류 필터·현재 카드 강조·항목 ⋮ 메뉴의 삭제·`+ 새 설정` 아이콘)과 크기 조절선 아래 버전 그래프(작업 초안(저장 안 됨 표시)과 확정 버전 줄, 확정 버전을 누르거나 `확정 버전 남기기`를 누르면 확정 버전 시트에서 읽기 전용 카드를 보거나 확정하고, 관계는 회차별로 기록하며 확정 버전에는 포함되지 않는다는 안내), 가운데 편집기(큰 이름 입력·설명(Toast UI Editor 3 마크다운, 지연 로딩, 공개 카드 페이지는 `## 제목` 문단으로 렌더)·공개 범위(소설이 연결된 세계관은 `공개 회차 [ ]화부터 공개` 입력 하나, 연결되지 않은 세계관은 `이 설정 공개` 스위치 하나, 아래 DEC-53 규칙)·유형·연관 설정·상세 설정과 글자 수·카드 삭제가 있는 하단 바), 오른쪽 AI 채팅이다. 저장 영역은 바뀐 것이 있으면 '저장하지 않은 변경 있음'과 세계관 저장 버튼(저장 전 확인 문제가 있으면 첫 사유·건수를 버튼 옆에 알리고 저장을 막는다. 사유에는 어느 설정인지 이름이 붙고(`writingIssueLabel`) 누르면 그 설정의 편집 화면으로 간다(`vm.openIssue`)), 없으면 '저장됨'이며 저장 버전이 0이면 바꾼 것이 없어도 첫 저장을 할 수 있다. 관리 모드 헤더의 '편집'은 세계관 정보 편집 패널(이름·설명·공개 범위·장르·표지)을 소개 자리에 열고 저장·취소·Esc로 닫는다. 저장은 바뀐 것만 이름·설명(기존 초안 저장) → 공개 범위·장르(`PUT /api/v1/world-studios/{id}/publication`, Content, 세계관 단위, 비공개에서 공개로 바꿀 때만 저장 시점에 확인) → 표지 순으로 보내고, 하나라도 실패하면 닫지 않고 오류와 입력을 그대로 둔다(헤더에는 공개 범위·장르 칩만 있다). 저장하지 않은 수정이나 저장 전 확인 항목이 있으면(`vm.infoLocked`) 헤더 '편집'이 잠기고 '작성 중인 변경을 먼저 저장하세요'로 알리며, 열린 패널의 저장은 이름·설명을 바꿨을 때만 같은 이유로 잠긴다(그 수정이 이름·설명 저장에 딸려 가지 않게, 공개 범위·장르·표지만 바꾸는 저장은 막지 않는다). 공개 목록에 나오는지는 저장한 세계관의 확정 버전 유무로 판정한다(`worldPublication.listingOf`): 공개이고 확정 버전이 있으면 헤더에 '공개 화면 보기'(`/worlds/:id`, 미리보기를 겸한다)가, 공개인데 확정 버전이 없으면 링크 대신 '저장한 뒤 확정 버전 남기기로 확정 버전을 한 번 남기면 나타난다'는 안내가 보이고 확정 버전을 남기면 저절로 사라진다. `--mode mockup`은 메모리에만 반영해 링크 없이 데모 안내를 띄운다. 표지는 PNG·JPEG·WebP 5 MiB 이하를 고르는 순간 검사하고 저장하면 `PUT /api/v1/world-studios/{id}/cover`(multipart)로 올리며(교체 포함, 삭제는 확인 뒤 `DELETE`, 소유자 화면은 Bearer로 읽은 이미지를 객체 주소로 보이고 해제한다) 'AI로 생성'은 준비 중으로 잠그고 표지 저장소가 없는 데모는 지원하지 않는다고 알린다. 공개 화면(`/worlds` 카드·상세)은 `hasCover`이면 공개 cover 주소(`/api/v1/public/world-studios/{id}/cover`)를 `<img>`로 쓰고 없으면 기본 표지(`/default-work-cover.svg`)를 쓴다. 설정집 보기(작성 모드는 설정 카드 단계)는 공개 설정집과 같은 게시판으로, 왼쪽 분류 메뉴 + 오른쪽 검색·정렬·결과 수·`다른 세계관에서 가져오기`(가져오기 시트)·`+ 새 설정`(유형 8가지를 고르면 그 유형의 카드를 초안에 더하고 편집 화면을 연다) 도구줄 위 / 공개 범위 일괄 줄(`선택 공개`·`선택 비공개`·`전체 공개`) / 표(선택·번호·분류·제목·요약·공개·연결 7칸) 아래이고 표는 공개 범위 말고는 보기만 한다(제목을 누르면 편집 화면, 삭제는 편집 화면에서만, 카드가 없으면 안내는 표 안 한 줄뿐). 삭제는 유형과 상관없이 초안 변경이라 이어진 관계 수를 확인한 뒤 함께 지우고(다른 설정이 아직 참조하면 막는다) 설정집 화면으로 돌아와 `되돌리기` 알림을 보이며, 세계관 저장으로 서버에 반영한다. 화면 오른쪽에는 설정집 화면·편집 화면·단계와 무관하게 늘 집필실과 같은 공용 `ChatPanel`의 AI 채팅 레일이 있다(설정집 화면은 본문 | 채팅 2열에 채팅 350px 고정·상단바 아래 sticky, 편집 화면은 집필실과 같은 3단의 오른쪽 열이되 면은 설정집 화면 채팅과 같은 주변 배경 `--tbg`다(`world-studio.css`가 `.writing-studio.world-card-studio .writing-chat`의 `--chat-bg`만 덮어쓰고 집필실 `writing.css`는 고치지 않는다), 접기·열기, 전송이 잠긴 동안 1200px 이하에서는 닫힌 채로 시작하고 설정집 화면은 900px 이하에서 열면 뒤 화면을 막는 대화 상자 서랍(공용 `Sheet`, Esc·배경으로 닫힘)이며 편집 화면은 그 폭에서 편집기 아래 영역이다, 채팅은 집필실과 같은 공용 `shared/chat/WritingChat`(집필 AI, 아래)이며 세계관에 연결된 소설(`linkedWorkId`)의 대화와 그 소설의 가장 뒤 발행 회차를 근거로 쓰고(`worldstudio/viewmodel/useLinkedWorkBasis`), 연결 소설이 없으면 사유와 함께 잠기며 가짜 응답은 없다). 관계도 보기(작성 모드는 관계 연결 단계, 주소 값은 그대로 `?view=people`)는 인물·장소·조직·능력·사물·규칙·사건·기타 카드를 모두 노드로 그리는 어두운 관계도 + 관계 추가·목록 표이고, 그래프 위 `관계도 유형 필터`(전체 + 노드가 있는 유형만 개수와 함께 토글, 마지막 보이는 유형은 끌 수 없음)는 숨긴 유형의 노드와 닿는 관계선만 그래프에서 빼는 화면 보기 상태다(주소·초안·저장 무관, 관계 주체·대상 선택지와 관계 목록은 거르지 않음, 선택·연결 중인 카드가 숨으면 그 모드를 푼다)(인물 삭제도 같은 삭제 흐름), 관계는 회차별로 기록하므로(DEC-51, [계약](../docs/design/worldstudio-independent-schema.md#회차별-관계--dec-51)) 이 보기 위의 `관계 기준 회차`(`RelationEpisodePicker`)에서 연결된 소설의 회차를 고르면(비우면 최신, 주소에는 남기지 않고 AI 반영·확정 버전 뒤 재조회는 최신으로 돌아감) `WorldStudioUseCase.read(id, signal, episode)`가 그 회차 시점의 관계를 다시 읽고 세계관 저장도 같은 회차를 본문 `episode`로 보내며(설정 카드 변경은 회차와 무관, 지난 회차를 연 채라면 저장 영역·검토·저장 단계가 `관계는 N화 기준으로 저장돼요`를 알린다(`episodeSaveNote`)), 소설 미연결·데모(메모리)·AI 후보 검토·확정 버전 요청 중·저장하지 않은 변경에서는 이유와 함께 잠기고(`episodeLock`, 이유는 `role="status"` 문구로 읽히며 데모·미연결이면 '저장하면 이 회차로 기록' 도움말은 숨김) 회차를 고른 동안에는 카드 삭제가 최신 저장에서만 되므로(서버도 회차를 지정한 저장의 카드 삭제는 422) 설정 삭제(편집 화면 삭제·레일 ⋮ 삭제·인물 삭제)가 이유와 함께 잠기고 `deleteCard`도 거절하며(`deleteLock`), 지난 회차 관계의 끝점이 삭제된 설정이면 `삭제된 설정`(서버가 알려 준 이름이 있으면 `삭제된 설정: 이름`, `deletedTitles`)으로 읽기 전용이고 그 행은 읽기 전용인 이유에 `aria-describedby`로 이어진다(`isDeletedCard`). 시간선 보기는 저장한 설정의 사건만 기존 시간선(`WorldTimeline`)으로 보인다. 설정집 게시판 상태 칸은 `정리 필요`(인물 IDENTITY·SOUL·GOAL 중 빈 문서)·`연결 필요`(사건·사물 카드가 승인된 관계로 어느 인물과도 이어지지 않음)·`공개 순서 확인`(이 카드의 글에 더 늦게 공개되는 카드의 이름이 나옴, DEC-53)·`AI 의견 N`(마지막 설정집 검토의 지적 수)을 함께 보이고(규칙은 `domain/entities/worldReview.ts`), 분류 메뉴에 `보완 필요` 필터와 빈 영역 `비어 있음`이 있다. 편집 화면은 그 카드의 지적과 수정안(`수정안 보기` → `초안에 반영`·`반영하지 않기`)을 보이고, 반영은 편집 초안의 그 칸만 바꿔 세계관 저장으로 서버에 보내며 검토 뒤 그 칸이 바뀌었으면 잠근다. 편집기 아래에는 '공개 순서 확인' 절(`WorldCardOrder`)이 그 카드의 어느 글(본문·링크 글자·관계 문구)에 어떤 이름이 나오는지 알리고 이름이 나온 카드로 옮겨 갈 수 있으며 저장·확정은 막지 않는다(모델 없이 초안에서 계산한다, `publicationOrderIssues`). AI 후보 검토 시트는 상태 필터 칩(검토 대기·승인·거절, 보류는 검토 대기에 든다)과 후보 카드(승인·거절·보류(보조 스타일)·내용 수정, 근거는 `근거 보기`)·`승인한 후보 N개 초안에 반영` 고정 바로 한 장씩 넘겨 본다. 게시판 규칙(분류·정렬·번호)은 `presentation/shared/worldBoard.ts`를 두 화면이 함께 쓴다. 관리 화면의 게시판은 뷰포트가 아니라 자기 폭(컨테이너 `worlds-board`, 760px 이하)으로 좁은 배치를 고르고(공개 설정집은 뷰포트 720px 규칙 그대로) 그때 숨는 분류·요약을 제목 아래 한 줄로 보이며, 일괄 공개·비공개 뒤에는 결과를 상태 문구로 알리고 초점을 표 머리 체크박스로 옮긴다. 본문 편집기(`shared/MarkdownEditor`)에서 Tab은 들여쓰기이고 Esc 다음 Tab으로 벗어나며(안내 한 줄) 쓰기·미리보기 탭은 ←→·Enter·Space로 바꾼다. 카드 본문(인물은 IDENTITY.md) 편집기에는 편집기 바로 위 줄에 `설정 링크` 버튼이 있어(`cardLinks`, Toast 도구 줄은 좁으면 끝 항목을 더보기로 숨기므로 도구 줄 밖에 둔다) 그 아래에 같은 세계관 카드를 이름·별칭으로 찾는 패널을 열고 고르면 선택한 글자(없으면 제목)로 `[글자](card:<id>)`를 커서 위치에 넣으며, 미리보기의 링크를 누르면 그 카드의 편집 화면으로 간다(Toast의 sanitizer가 `card:` 주소를 지워 링크 렌더러가 해시 주소·data 속성으로 바꾼다). 링크로 그리는 것은 원문(`CardMarkdown`은 `position`, 미리보기는 `sourcepos`)이 공유 정규식에 맞는 것뿐이고 `<card:id>`·제목이 붙은 링크 같은 모양은 글자만 보인다. 인라인 `[[` 자동완성은 없다. 편집 화면의 연관 설정에는 본문 링크로 이어진 카드도 들어가고 게시판 연결 수에 센다. 삭제 확인은 열릴 때 초점·스크롤이 가고 닫히면 연 버튼으로 돌아온다. **설정 카드 공개·가져오기·소설 연결(DEC-46·53, [계약](../docs/design/public-world-contract.md#카드-공개-기준-일원화--dec-53))**: 설정 카드의 공개 설정은 하나다('N화부터 공개' 또는 '작가 전용', 기본은 작가 전용, #485 2단계). 화면은 `revealFromEpisode`만 정하고 `visibility`는 회차가 있으면 public, 없으면 지워 맞춘다(`worldstudio/viewmodel/cardVisibility.ts`의 `setCardReveal`, 유효 공개 회차는 `domain/entities/studioWorld.ts`의 `cardRevealEpisode`: 회차 값, 없고 `visibility`가 공개면 1화, 그 밖은 작가 전용). 건드리지 않은 카드(옛 공개 카드·회차 값만 있는 카드)는 다시 쓰지 않고, 키가 있는데 값이 잘못된(JSON `null` 포함) 카드는 서버처럼 작가 전용으로 읽어(`HttpWorldStudioRepository`가 그 카드의 `visibility`를 가져오지 않는다) 저장하면 비공개로 맞춘다. 편집 화면의 `공개 범위`는 소설이 연결된 세계관(`linkedWorkId`)이면 `공개 회차 [ ]화부터 공개`(숫자만 받는 글자 칸, 비우면 작가 전용, 1 이상의 정수가 아니면 입력 아래에 이유를 보이며 저장 전 확인과 `WorldStudioUseCase.save`가 같은 문구로 막는다) 입력 하나만, 연결되지 않은 세계관·데모는 `이 설정 공개` 스위치(공개 = 1화부터) 하나만 보인다. 게시판의 `공개` 칸은 `N화부터`·`작가 전용`(미연결 1화는 `공개`)을 보이고(`revealLabel`), `선택 공개`·`전체 공개`는 소설이 연결된 세계관이면 `일괄 공개 회차`를 한 번 입력받아(기본 1화) 고른 카드 모두에 같은 `N화부터 공개`를 정하며 미연결 세계관은 `공개`(1화)다(`setCardReveal`·`publishAllCards(settings, episode)`, 0·빈 값은 이유를 알리고 공개 버튼만 잠근다). 공개(로 고른) 세계관인데 초안에 공개된 카드가 없으면 `PublicCardsNotice`가 경고와 `전체 공개`(1화부터)를 관리 헤더·정보 편집 패널·작성 모드 공개 설정에 보이되 공개 설정 저장은 막지 않는다. 카드 공개 설정·가져온 카드는 모두 초안 값이라 세계관 저장과 `확정 버전 남기기`를 거쳐야 공개 세계관 화면·독자 설정 위키에 반영되며 화면은 그 사실을 도움말로 알린다. 공개 기준 필터는 서버가 하므로 화면에서 거르는 코드를 두지 않는다. 설정 가져오기(`WorldImportSheet`)는 서버 API 없이 `PublicWorldUseCase`로 읽은 공개 세계관의 공개 카드를 공용 `presentation/shared/importCards.ts`(`importCards`·`appendImported`·`importableWorlds`, 공개 세계관 화면의 바로 추가와 함께 쓴다)로 새 id의 비공개 카드로 복사하고 출처(`importedFrom{worldId, worldName, authorNickname, revisionNo, cardId}`)를 기록한다: 대상 세계관 자신은 목록에서 빼고, 관계는 양 끝을 모두 가져온 것만 사용자 정의 방향 관계로 옮기며(공개 상세가 이름만 준다), 본문 링크는 같이 가져온 카드끼리만 새 카드 id로 다시 잇고 나머지는 글자로 바꾸고, 활성 카드 1,000개 한도를 넘기면 아무것도 더하지 않는다. 시트는 게시판의 `다른 세계관에서 가져오기`로만 열고 늘 세계관 고르기부터 시작한다(주소 `?import=`로 여는 길은 없앴다). 시트의 공개 세계관 조회는 `viewmodel/useWorldImport.ts`, 소설 연결의 조회·연결은 `viewmodel/useWorldNovelLink.ts`가 맡는다(View는 `appContainer`를 부르지 않는다). 가져온 카드는 게시판 행과 편집 화면에 `가져옴`과 `참고: {세계관 이름} 세계관 · {작가}`를 보인다. 서버 매핑(`HttpWorldStudioRepository`)은 카드 `visibility`를 행 값으로 보내고, `revealFromEpisode`·`importedFrom`·`characterDocs`·`imageId`는 카드 `semanticMetadata`의 **최상위 키**에 행 필드를 정본으로 둔다(`semanticMetadata.studio` 안에 넣지 않고 값이 없으면 키를 넣지 않으며, 읽을 때 어긋난 값은 버리되 세계관 로드를 실패시키지 않는다). **카드 대표 이미지**(#401): 편집 화면 머리 오른쪽의 큰 타일(세계관 헤더 표지와 같은 `.cov`, 이미지가 없으면 점선 빈 타일 전체가 `이미지 추가`, 있으면 이미지 + 아래 `바꾸기`·`빼기`, 머리 폭 460px 미만(컨테이너 쿼리)은 88px 타일을 이름 아래로)의 `이미지 추가`·`바꾸기`가 고른 파일(PNG·JPEG·WebP 5 MiB 이하)을 곧바로 `POST /world-studios/{id}/card-images`(`WorldStudioUseCase.uploadCardImage`)로 올려 초안 카드의 `imageId`만 새 id로 바꾸고(저장 전 수정, 저장과 `확정 버전 남기기`를 거쳐야 공개 화면에 나옴, 실패는 서버 이유 그대로), `빼기`는 서버 호출 없이 키만 지운다. 소유자 이미지는 인증 읽기를 `useCardImages`가 imageId마다 한 번만 읽어 객체 주소로 바꿔 게시판·레일 썸네일과 미리보기가 나눠 쓰고 바꾸기·빼기·화면 이탈 때 해제한다. 설정 가져오기는 이미지를 복사하지 않고(`importCards`가 `imageId`를 옮기지 않음), 카드 이미지 저장소가 없는 데모(`--mode mockup`)는 올리기를 잠그고 발표용 인물 초상만 보인다.  인물 카드는 문서 네 종류로만 쓴다(DEC-47): `IDENTITY.md`가 카드 본문(`item.text`)이고 `SOUL.md`·`GOAL.md`·`memory/NN회차.md`는 `StudioSetting.characterDocs{soul, goal, episodes}`(작가용, 공개 응답에 없음)다. `MEMORY.md`는 없앴고, 서버의 옛 `memory` 값은 읽을 때 `migrateCharacterDocs`가 00회차 앞에 빈 줄로 이어 붙이며(공백뿐이면 빈 것) 저장에는 `memory` 키를 쓰지 않는다. `MEMORY.md` 파일 불러오기는 00회차로 받는다. 문서 이름·빠진 문서(`정리 필요`, 저장을 막지 않음)·저장을 막는 문구(문서마다 3,000자, 회차 번호 0 이상의 정수)·파일 이름 해석은 `domain/entities/characterDocs.ts`의 순수 함수가 정하고 `worldstudio/viewmodel/useCharacterDocs.ts`·`view/CharacterDocs.tsx`가 화면을 맡으며, 전부 비었거나 인물이 아닌 카드에는 `characterDocs` 키를 넣지 않는다. 화면 테스트의 편집기 대역(`test/markdownEditorFake`)은 인물 문서를 파일 이름(`IDENTITY.md` 등)으로, 그 밖의 카드는 `설명`으로 찾고, 편집기마다 받은 `cardLinks`를 `LazyMarkdownEditor.cardLinks`(label별)에 남긴다. 연결된 소설(`WorldLinkedWork.tsx`)은 헤더에 두 조각이다: 상태 줄 `WorldLinkedLine`은 정보만(`연결된 소설: {제목}` / `연결된 소설이 없어요.` / 확인 중·제목 읽기 실패 안내) 보이고 링크·버튼을 두지 않으며, 행동 줄의 `WorldNovelButton`이 소설 버튼 **한 자리**를 맡는다(연결돼 있으면 `/content?work=<id>`로 가는 `소설 작성하기`, 없으면 같은 자리의 `소설 연결하기` → 내 소설 중 `worldStudioId`가 없는 것만 고르는 시트 → `episodeUseCase.linkWorldStudio`로 초안 저장과 별개로 바로 연결, 실패는 서버 문구, 연결되면 같은 자리가 `소설 작성하기`로 바뀌고 초점도 옮긴다). 같은 곳으로 가는 링크를 두 개 두지 않는다. 시트의 `새 소설 만들기`는 작품 만들기(`/content`)로 갈 뿐 만든 소설을 자동으로 연결하지 않고, 해제는 작품 관리 화면이 맡는다. `--mode mockup`은 상태 줄 없이 `소설 작성하기`(→ `/new`)만 두고 독자 공개 회차 입력을 잠근다.

집필실과 세계관 관리 화면의 AI 채팅(#331)은 공용 `presentation/shared/chat/WritingChat`·`useWritingChatViewModel` → `WritingChatUseCase` → `HttpWritingChatRepository`로 Content `/api/v1/works/{id}/chat/sessions…`를 쓴다. 대화 원본은 AI의 LangGraph 체크포인터이며 화면은 저장하지 않는다. 전송은 fetch 스트림으로 SSE(`plan`·`started`·`step`·`waiting`·`done`·`error`)를 읽어 단계 진행을 그리고(병렬 호출(#474)로 `started`가 여러 개 겹칠 수 있어 결과 `step`이 오기 전의 기능은 모두 진행 중으로 보인다), 끝나거나 실패하면 이력을 다시 읽어 저장된 상태를 그대로 보인다(`done` 없이 끊기면 실패로 알린다). 승인·입력 대기(`waiting`)는 대화 끝의 카드에서 `초안에 반영`·`반영하지 않기` 또는 빠진 입력(고증 질문·장면 계획)을 채워 resume하고, 승인 전에는 원고가 바뀌지 않는다. 대화 고르기·새 대화·제목 바꾸기(대기 중 잠김)·삭제, 메시지 `수정`(그 뒤 대화를 지우고 다시 실행)·`여기부터 지우기`를 제공한다. **근거 회차(지식 상한)와 반영 회차는 따로다**: 근거는 발행된 판본이 필요해 집필실은 열린 회차가 발행돼 있으면 그 회차, 발행 전 초안이면 그 앞의 가장 뒤 발행 회차를 쓰고(`domain/entities/writingChat.chatBasis`, 서버가 `targetEpisode ≥ episode`만 받으므로 근거는 열린 회차보다 뒤가 되지 않는다), 결과를 반영할 회차(초안이어도 된다)는 열린 회차 번호를 요청의 `targetEpisode`로 따로 보낸다(없으면 서버가 근거 회차와 같게 본다: 세계관 작업실 채팅). 반영·승인 문구와 집필 입력 대기(`쓸 장면 계획 · N화`)는 열린 회차 기준이고 근거≠반영이면 시뮬레이션 시작 양식이 `근거: M화까지 / 반영: N화 초안`을 알리며, 열린 회차 앞에 발행 회차가 없으면 잠근다. 승인을 기다리는 장면·제안의 반영 회차(서버가 승인 질문에만 싣는 `approvalEpisode`)가 편집기에 열린 회차와 다르면 집필실이 편집기를 그 회차로 한 번 맞춘다(새로 고친 뒤 주소의 `?ep=n`이 다른 회차일 때. 승인 회차가 새로 오거나 목록이 준비될 때만 맞추므로 그 뒤 작가가 고른 회차는 되돌리지 않고, 목록에 없는 회차는 건너뛴다). 장면 대기(`awaitingScene`) 응답에는 반영 회차가 없어 그때는 주소의 회차가 그대로 열린다. OpenAI 전송·비용 동의에 체크해야 보낸다. `--mode mockup`은 `writingChatUseCase`가 null이라 잠긴다.

세계관 관리(`/worldstudio/:id`)의 확정 버전 시트는 열어 본 버전의 `이 버전으로 초안 되돌리기`(`useWorldRevisions.restore` → `WorldStudioUseCase.restoreRevision`)를 둔다. 카드만 초안으로 되돌리고 관계·이름·새 확정 버전은 그대로이며, 저장하지 않은 변경·미확인 확정/AI 요청이 있으면 이유와 함께 잠그고 성공하면 서버 초안을 다시 읽는다. 헤더 정보 편집 패널의 `세계관 삭제`(`useWorldStudioViewModel.deleteWorld`)는 확인 뒤 소프트 삭제하고 `/lib?tab=worlds`로 이동하며, 연결된 소설이 있으면 이유와 함께 잠그고 서버 거절(409)은 이유를 그대로 보인다. 서버 계약은 [WorldStudio 설계](../docs/design/worldstudio-independent-schema.md#확정-버전으로-카드-되돌리기와-세계관-삭제-2026-11-17)를 따른다.

**집필실 고급 모드(#374)**: `WritingStudio`가 embedded `useStoryPlanViewModel`을 소유하고 `StoryPlanPanel`을 원고 옆에 둔다. 기본/고급 전환은 숨기기만 하며 원고·계획 입력을 유지한다. 패널은 열린 회차를 기본으로 다른 회차·미정·전체를 선택하고, 여러 플롯의 같은 회차 장면을 위로/아래로 이동한다. 기존 PUT의 선택적 `position`과 revision으로 순서를 영구 저장하며 이웃 revision도 바뀌므로 목록을 다시 읽는다. `useWritingPlanNavigation`은 실제 링크·뒤로가기·공용 이탈 이벤트를 확인하고, `useWritingViewModel`의 회차 이동 확인은 계획 확인 후 원고 확인을 하되 계획 입력은 지우지 않는다. 상단 원고 저장 버튼은 계획 이탈이 아니다. `?view=narrative`는 단독 페이지로 유지한다. [고급 모드·순서 계약](../docs/design/writing-plan-panel-contract.md).

**인물 시뮬레이션 무대(#58)**: 집필실(`WritingStudio`)이 `useWritingChatViewModel`을 직접 만들어 채팅(`WritingChat`)과 무대(`shared/chat/SimulationStage`·`useSimulationStageViewModel`)에 함께 내려 주므로 채팅을 접어도 진행 중인 장면이 이어진다. 상단 `시뮬레이션` 버튼이 편집기(숨기기만 해 입력을 지킨다) 자리에 무대를 열고, 진행 중이거나 답을 기다리는 장면이 있으면 저절로 열리며(초점은 사용자가 연 때만 무대 제목으로 옮기고 닫으면 버튼으로 돌려준다), 장면이 이미 끝났으면 새 시작 양식을 연다. 시작 양식은 모드를 고른다: **IF**(전제 500자 이내 + 인물 1~6명) 또는 **흐름**(열린 회차의 장면 계획 `kind=scene`을 `제목: 내용` 200자·최대 8개 비트로 쓰고, 참여 인물은 그 비트 문장에 이름(별칭)이 나오는 인물 카드를 미리 고르며, 없으면 "이 회차의 장면 계획이 없어요"와 집필실 플롯 패널 열기 버튼을 보이고 비트를 한 줄씩 직접 적는다). **인물 후보는 이 작품에 연결된 WorldStudio 세계관의 인물 카드**다: `useSimulationSetupViewModel`이 `WorldStudioUseCase.list`에서 `linkedWorkId`가 이 작품인 세계관을 찾아 `read`의 인물 카드를 읽고 카드 id를 `characterIds`로 보낸다(서버가 연결 세계관의 활성 인물 카드 id로 검증하므로 레거시 설정집 `StoryPlanUseCase.references`나 장면 계획의 `characterIds`는 쓰지 않는다). **연결한 세계관이 없는 Fork는 원작 세계관을 읽기 전용으로 이어받는다**(#365, [계약](../docs/design/public-world-contract.md#fork가-이어받는-원작-세계관-dec-3237-365)): 소유하지 않은 세계관이라 `list/read`가 아니라 `EpisodeUseCase.inheritedWorld`(`GET /works/{id}/inherited-world?upto=<여는 회차>`)로 서버가 공개 카드·Fork 기준 회차로 거른 카드를 받아 `inheritedCharacters`(`worldCharacters`와 같은 규칙)로 후보를 만들고, 서버가 같은 카드 집합으로 `characterIds`를 검증한다. 연결한 세계관이 있으면 그것이 우선이라 이어받은 세계관은 묻지 않고, 이어받은 인물은 "원작 세계관에서 N화까지 공개된 인물을 이어받았어요(읽기 전용)."로 알린다. 제목이 `나레이터`로 시작하는 카드(NFC 정규화·앞뒤 공백 제거 뒤 시작 일치, 카드 유형 무관)는 서버가 인물이 아닌 서술 문체 지침으로 보고 스냅샷에서 빼므로 후보에서도 뺀다(`worldCharacters`, 서버 `NARRATOR_CARD`와 같은 규칙). 연결된 세계관도 이어받은 세계관도 없으면 `연결된 세계관이 없어요`로, 인물 카드가 없으면(이어받은 세계관은 `이어받은 원작 세계관에 공개된 인물 카드가 없어요`) 그 사유로 시작을 잠근다. 이어받은 세계관을 읽지 못하면 연결 없음으로 바꾸지 않고 불러오기 실패와 `다시 불러오기`로 알린다. 장면 계획은 기존 `StoryPlanUseCase.list`로 읽고, 둘 다 양식을 열 때와 계획 저장·삭제·순서 변경 뒤 다시 읽으며(갱신 중·실패·미저장 입력에서는 시작 잠금), 읽지 못하면 사유와 `다시 불러오기`를 보인다. 시작 양식은 첫 장면이 올 때 닫히므로 요청이 실패하면 옛 장면이 아니라 입력한 양식이 남는다. 시작은 채팅 메시지 전송이며 `operation:'character_simulation'`(의도 분류를 건너뜀)과 `simulation{mode, premise?, beats?, characterIds}`를 싣고(규칙은 `domain/entities/characterSimulation`의 `simulationIssue`·`planBeats`, `WritingChatUseCase`가 서버 한도로 다시 검사한다) 요청 문장은 `IF 모드 시뮬레이션: …`·`흐름 모드 시뮬레이션: 장면 계획 N개`다. 무대는 나레이션(이탤릭 회색 지문)·독백(시점 인물 이름 + `속마음`)·인물 줄(이름 + 말풍선)을 SSE `step`의 누적 결과로 이어 붙이고(`aria-live="polite"`, 맨 아래에서 읽는 중일 때만 자동 스크롤) 시점이 바뀌는 줄 앞에 `시점: 전지적 / ○○ 시점(3인칭) / ○○ 1인칭` 구분선을 두며, 서버가 장면에 붙이는 선택 안내(`notice`: 원고 발췌를 쓸 수 없어 세계관 설정만으로 만들었을 때 등)는 대본 위에 `role="status"` 한 줄로 보이고 없으면 숨긴다. 장면이 턴마다 멈추면(`waiting.awaitingScene`) 자동 재생이 `resume.scene = next`를 보내고(`approved:true`를 함께 보낸다), 서버 응답이 `waiting`으로 끝난 턴만 이어 가므로 실패한 턴·일시정지·새로 고친 뒤 이어진 장면은 저절로 보내지 않고, 서버가 별도 오류 없이 멈춘(`stopped`·`failed`) 장면을 장면 대기로 돌려줘도 같은 실패를 되풀이하며 호출만 쓰지 않도록 재생을 눌러야 이어 간다. `일시정지`는 진행 중인 턴을 마치고 멈추고, `장면 끝내기`는 `stop`(턴을 만드는 중이면 그 턴 뒤), 줄 `수정`은 `edit`(모델 호출 없음·`작가 수정` 표시·검사 결과 없음, 저장 요청 중에는 입력을 잠그고, 고치는 줄이 열려 있는 동안은 승인 대기의 `원고에 반영`을 잠가 이유를 알린다: 새 글은 아직 서버 장면에 없다), `다시 말하기`는 `redo`(뒤 줄이 지워져 확인), `끼어들기`는 다음 `next`·`redo`의 `note`(300자 이내)로 한 번만 싣고(반영·반영하지 않기 답에는 실리지 않아 승인 대기 중에는 그렇게 안내하며, 새 시뮬레이션을 시작하거나 다른 대화를 열면 지운다) 오류로 멈추면 `오류로 멈춤`으로 알리고 재생으로 다시 시도한다. 멈춘·실패한 장면의 이유는 서버가 사람이 읽을 문장으로 주는 단계 `error`를 보이고(`stopReason`은 `check_failed`·`beat_rejected`·`turn_limit`·`call_limit` 코드값이라 그대로 찍지 않는다), 문장이 없을 때만 코드를 문구로 바꾸며 모르는 코드는 `장면이 멈췄어요`로 보인다. 끝난 장면은 `원고에 반영`·`반영하지 않기`(승인 응답)·`장면 이어 가기`를 묻고 반영은 `onApplied`로 그 회차 초안을 다시 읽는다(`useWritingViewModel.aiApplied`는 늦게 불려도 호출 시점이 아니라 지금 열린 회차·입력 상태를 보고, 다른 회차로 옮겨 입력 중이면 덮어쓰지 않고 목록만 갱신한다). 채팅에는 장면 카드·승인 카드 대신 `시뮬레이션 진행 중 · N턴` 한 줄과 `무대 열기`만 있고, 무대가 없는 화면(세계관 작업실)은 집필실에서 열라고 안내한다. 승인 대기 장면은 서버가 승인을 물었고(`awaitingApproval`) 실패가 아니며 줄이 있을 때만 반영을 묻는다.

화면은 세 규칙을 함께 쓴다. **Clean Architecture**는 계층 의존 방향을, **MVVM**은 화면 책임 분리를,
**Flux**는 상태 변경·전달 순서를 정한다. 하나가 다른 것을 대신하지 않는다.

## 구조와 의존성

TypeScript(`.ts`·`.tsx`)로 작성하고 `any`·타입 단언 남용을 피한다. 외부 응답은 Zod로 검증한 뒤 사용한다.
업무 기능은 **업무 규칙이 외부 구현을 직접 참조하지 않게** 의존 방향을 정한다.

```text
실행 흐름: View → ViewModel → UseCase → Repository 구현 → HTTP API
코드 의존: Presentation → Domain ← Data
객체 조립: app/di에서 Domain UseCase와 Data 구현체를 연결
```

| 위치 | 역할 | 예 |
|---|---|---|
| `presentation/features/<기능>/view` | JSX·스타일·ARIA와 순수 표시용 포맷만. ViewModel이 반환한 상태·handler 사용 | `WorkPage` |
| `presentation/features/<기능>/viewmodel` | Custom Hook ViewModel. 화면 상태·동작·요청 수명 관리 | `useReaderViewModel` |
| `presentation/features/<기능>/state` | 화면 이동 후에도 유지할 Redux slice | `library/state/newWorkSlice` |
| `presentation/shared` | 여러 feature가 공유하는 화면 요소 | `shell`, `session` |
| `domain/entities` | 업무 데이터 타입 | |
| `domain/usecases` | 사용자 기능 실행. Repository interface만 생성자로 받고 HTTP를 import하지 않음 | `LibraryUseCase` |
| `domain/repositories` | 데이터 접근 계약(interface) | `WorkRepository` |
| `data` | Repository 구현·Fetch·HTTP DTO의 Zod 검증과 Entity 변환. API 형식 변경은 여기서 흡수 | `HttpEpisodeRepository` |
| `app` | Awilix 등록, Redux Store | `app/di`, `store.ts` |

- Domain은 Data·Presentation·React를 import하지 않는다. 요청 취소용 Web 표준 `AbortSignal`은 Domain 계약에 둘 수 있다.
- feature끼리 다른 feature의 ViewModel·Store를 참조하지 않는다. 공유가 필요하면 `presentation/shared`로 옮긴다.
- 브라우저는 상대 `/api` 경로만 사용하고 기존 URL·Bearer·쿠키·CSRF 계약을 유지한다. AI·그래프 DB·외부 모델을 직접 호출하지 않는다.
- 기존 Tailwind CSS·디자인 토큰을 재사용한다. 읽기 토큰(`--t*`)은 `:root`에 기본값이 있어 어디서나 쓸 수 있고, 독서 화면(`.reader`)에서는 전역 토큰(`--surface`·`--ink`·`--sub`·`--line*`·`--pri*`)이 읽기 토큰으로 재연결되므로 전역 부품을 그대로 써도 보기 설정을 따른다. `.calm`·`.reader`에서 `--t*` 색 토큰과 `--bg`를 다시 선언하지 않는다. 입력·선택 테두리는 `--line3`, 위험 채움 위 글자는 `--on-danger`를 쓴다. 전역 CSS(`storyfork.css`)는 `@layer(base)`라 기능 CSS가 늘 이기므로, 전역 터치 보정(44px·입력 16px)과 같은 속성을 기능 CSS가 다시 정하면 그 화면이 직접 보정한다.
- 원고는 저장 문자열을 그대로 두고 **그릴 때만** 기본 서식(굵게·기울임·소제목·인용·구분선, DEC-48)을 해석한다. 문법은 `domain/entities/manuscriptFormat.ts` 한 곳이며 마크다운 라이브러리를 쓰지 않는다(표준 마크다운과 다르다: 한 줄 = 한 문단, 서식은 한 줄 안에서만, 내용 2,000자 초과 줄은 해석하지 않음). 문법을 바꾸려면 [계약](../docs/design/manuscript-format-contract.md)의 검증 표와 서버 구현(`ManuscriptFormat.kt`)을 함께 바꾼다. 본문을 그리는 화면은 공용 `ManuscriptBody`(미리보기류)나 `readerBody`(독자 화면)를 쓰고 본문 문자열을 직접 잘라 그리지 않는다. 독자 화면 문장의 `t`(인용·수정 제안에 보내는 글)는 원문 그대로의 조각이어야 한다(서버가 발행본에서 글자 그대로 찾는다).
- 서버 집필실 본문 편집기(`studio/view/ManuscriptEditor`, Toast UI Editor 3 마크다운 쓰기 모드, `LazyManuscriptEditor`로 지연 로딩)는 저장 글을 편집 영역의 글자 그대로 둔다(열기만 해서는 `onChange`를 부르지 않는다). 원작 기준 회차는 읽기 전용 본문이고 사용자가 누른 요청 중에만 편집기를 잠근다(`inert`). Tab은 들여쓰기이고 Esc 다음 Tab으로 벗어난다(`shared/tabEscape`, 카드 편집기와 공용). Toast 편집기를 새로 쓰거나 고칠 때는 `shared/toastFixes`의 보정(`loadMarkdown`·`forToast`)을 함께 걸고, 우회의 근거는 `ManuscriptEditor.tsx` 주석과 테스트에 있다. 화면 테스트는 `vi.mock('./LazyManuscriptEditor', () => import('…/test/manuscriptEditorFake'))`로 textarea 대역을 쓴다.

## MVVM과 DI

- View는 ViewModel 하나가 반환한 상태를 렌더링하고 사용자 이벤트를 반환된 handler에 연결한다. 업무 판단·API 호출을 하지 않는다.
- ViewModel은 UseCase 실행, 화면 상태 조합, 입력 가능 여부 검사, 포커스·스크롤 같은 화면 제어를 맡는다.
- `app/di`의 `register*Services`가 `asFunction(({ repo }) => new XUseCase(repo)).singleton()`처럼 Repository를 UseCase 생성자에 넣는다(생성자 DI).
- ViewModel만 `appContainer.resolve(...)`로 UseCase를 조회한다(Service Locator). View는 `appContainer`를 조회하지 않고,
  ViewModel은 Repository를 직접 생성·조회하지 않는다.
- Awilix는 UseCase·Repository 같은 **협력 객체**를, Redux는 **화면 상태**를 관리한다. 둘을 섞지 않는다.
- 업무 규칙이 없는 연결 확인(Health)은 `View → Hook → DI 외부 함수 → Fetch·Zod`를 유지하고 빈 UseCase·Repository를 만들지 않는다.

## Flux 단방향 흐름 (Redux Toolkit)

```text
View 이벤트 → ViewModel handler → UseCase 메서드 호출
  → 결과에 따라 dispatch(sliceActions.x(payload))      // Action
  → Reducer가 새 상태 계산 → Store 갱신
  → useAppSelector 구독 → ViewModel 반환값 → View 재렌더링
```

- 상태는 Action → Reducer → Store → Selector 한 방향으로만 바뀐다. View·HTTP 코드가 Store 상태를 직접 고치지 않는다.
  (예: `useReaderViewModel`이 UseCase 호출 후 `dispatch(sessionActions.dataChanged())`, 상태는 `useAppSelector`로 읽음)
- 비동기 HTTP는 ViewModel이나 Thunk에서 UseCase로 호출한다. Reducer에는 상태 변경 규칙만 두고 부수 효과를 넣지 않는다.
- slice 안의 `state.x.push(...)` 표기는 Redux Toolkit(Immer)의 불변 갱신이다.
- 컴포넌트에서는 `app/store`의 `useAppDispatch`·`useAppSelector`만 쓴다.

## 상태 위치와 요청

| 상태 | 저장 위치 | 수명 |
|---|---|---|
| 한 화면에서만 쓰는 입력·결과·ref | ViewModel Hook 로컬 상태 | 화면 이탈 시 해제, 진입 시 재조회 |
| 화면을 옮겨도 이어져야 하는 작업 | Redux slice + ViewModel | 앱 실행 동안 유지(새로 고치면 초기화) |

- 같은 상태를 Hook과 Redux에 중복 저장하지 않는다. Redux에는 직렬화 가능한 값만 넣고 `AbortController`·타이머는 넣지 않는다.
- 진행 중 중복 전송을 막고, 새 요청·화면 이탈·로그아웃 시 이전 요청을 취소하며 요청 ID로 늦은 응답을 무시한다.
- 로딩·실패·완료 표시는 실제 API 결과와 일치시킨다. AI 제안 도착을 저장·승인·발행 완료로 표시하지 않는다.
- 시트 안에서 보낸 요청의 거절·실패는 시트가 열려 있는 동안 시트 안 `role="alert"`에 남기고 이미 닫았으면 토스트로 알린다(`reading/viewmodel/useInlineFailure.ts`). 접수 결과는 `role="status"`로 알리고 '확인'에 초점을 둔다. 곧 사라지는 토스트만으로 결과를 알리지 않는다(서재 '내 제보'는 `shared/feedbackReports/useReportSender`의 `notice`를 그 카드 안에 남긴다).
- 같은 목록 안의 필터·선택을 바꿔 다시 읽을 때는 `useAsyncData`의 `refresh`로 이전 목록을 유지한 채 읽고(`/chat` 목록 필터, `/inbox?i=` 선택), 조회 중·실패(다시 불러오기)는 그 화면의 틀 안에서 알린다.

## 데모 화면과 실제 기능

- 실제 API가 없는 기능은 메모리 Repository(`data/mock`, `--mode mockup`의 `registerMockupServices`)로 화면만 시연한다.
  데모 입력·이동을 서버 저장 성공으로 표시하지 않고, 미연결 동작은 준비 중으로 비활성화한다.
- 서버 기능이 없는데 형식적인 UseCase·Repository 계층을 추가하지 않는다. 버튼 숨김으로 서버 권한 검사를 대신하지 않는다.

## 검증

- 패키지 관리는 `pnpm`과 기존 lockfile을 사용한다.
- 로컬: `pnpm exec vitest run src/domain/__tests__/<대상>.test.ts`처럼 변경 범위의 **단위 테스트 파일만** 지정한다.
  `src/domain`, `src/data`의 대역 기반 테스트와 `src/index-html.test.js`가 단위 범위이고, React 렌더·Hook·App 조립은 CI 통합 계층이다.
- UseCase 테스트는 Fake Repository, ViewModel 테스트는 Fake UseCase나 격리 컨테이너를 사용한다(운영 컨테이너를 바꾸지 않음).
- 상세는 [Frontend README](README.md)를 본다.
- 집필실 자동 저장은 실패한 입력만 재시도 대기 상태로 두고 다음 편집 또는 `초안 저장 다시 시도`에서 초안 저장을 재개한다(#406). 이 버튼은 다시 시도할 미저장 입력이 있을 때만 오류 상자에 보이고(그때는 복사 안내를 빼며 로그인 링크와 한 묶음이다) 버전이 아니라 초안만 저장한다. 누르면 버튼이 있던 오류 상자가 사라지므로 초점은 상단 저장 상태 줄이 이어받는다. 사용자가 누른 요청(버전 저장·발행 등)이 실패한 입력도 같은 대기 상태라 2초 뒤 자동 저장이 그 실패 안내를 지우거나 같은 입력을 되풀이하지 않는다. 실패한 요청 중 추가된 입력도 저장하며, 복구 때문에 새 저장 버전을 만들지 않는다.
- 집필실 저장 중·실패·성공 시각·버전은 실제 원고 저장 결과를 표시한다(#416). 없는 회차 주소는 오류와 회차 목록으로 안내하며 임의로 첫 회차를 열지 않는다(회차가 하나도 없는 작품은 오류 없이 첫 회차 만들기 안내를 보인다). `저장 실패` 상태는 다시 시도할 미저장 입력이 있을 때만 알린다. 실제 UUID 집필실은 `RestoreContext`로 로그인 복구를 기다린 뒤 원고를 요청한다. 인용 Enter는 기호 자동 삽입 없이 일반 문단으로 이동한다. End는 브라우저가 계산한 화면 줄 끝을 ProseMirror 선택에 즉시 반영해 원문을 보존한다(문단 끝으로 건너뛰지 않음).

작품 관리의 작성 중 개수·제목은 소유자 회차 조회 결과를 사용한다. 공개 회차 목록과 구분하며 공개 기준은 공백 포함이다.

수정 제안의 발행 반영 표시는 서버가 확인한 현재 발행본 계보를 따르고, 초안에만 반영된 제안은 해당 회차 집필실로 연결한다.
