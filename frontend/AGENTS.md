# Frontend 구현 지침

`frontend/**`에 적용한다. [루트 공통 지침](../AGENTS.md)을 함께 따른다.
nginx/Vite는 `/api/v1/works`·`/api/v1/public/works`·`/api/v1/world-studios`·`/api/v1/public/world-studios`·`/api/v1/public/genres`·`/api/v1/public/card-categories`와 하위 경로를 Content, `/api/v1/operations/{reports,members,admins,support,works,comments,genres,credits,world-studios,card-categories,admin/notices,public/notices,admin/events,public/events,admin/activities,dashboard,llmops,alerts,jobs}`와 하위 경로를 Operations, 나머지 `/api`를 Core로 라우팅한다(서비스 토큰용 `/api/v1/operations/{notices,events,inquiries}`는 열지 않는다).
`/content`·UUID `/studio/{id}`와 작품 목록·상세·회차 열람·공개 wiki·Fork 생성은 Content API(`HttpWorkRepository`)를 쓰고,
실제 작품(canonical) 회차 열람의 댓글은 `HttpEpisodeCommentRepository`([계약](../docs/design/episode-comment-contract.md))를, 메모리 데모 작품의 댓글은 메모리 저장소를 쓴다. 소설 상세 아래의 작품 전체 댓글(읽기 전용, `GET /public/works/{id}/comments`)도 같은 Repository의 `listByWork`를 쓰며 데모 작품은 "데모에서는 지원하지 않아요"로 알린다. 실제 작품의 문장 피드백(제보)·회차 제보 목록·내 제보·작가 피드백함 제보는 `HttpFeedbackReportRepository`를 쓴다([계약](../docs/design/feedback-report-suggestion-contract.md)). 실제 작품의 문장 수정 제안·작가 피드백함 수정 제안 승인·내 제안은 `HttpEditSuggestionRepository`를 쓴다([계약](../docs/design/feedback-report-suggestion-contract.md)). 소설 상세 소식 탭(작품 공지)의 목록·작성·수정·고정·삭제는 실제 작품이면 `HttpWorkNoticeRepository`([계약](../docs/design/work-notice-contract.md))를, 메모리 데모 작품이면 "데모 소식" 안내와 함께 메모리 저장소를 쓴다.
`/content?work=<id>` 작품 관리는 세계관 관리와 같은 사이드바 화면이다 — **공용 상단바(Gnb)와 푸터를 그리지 않고**(작품을 읽는 동안·찾지 못했을 때도 같다, 그때는 상단 줄의 `내가 쓰는 소설` 링크만 있다) 왼쪽 사이드바가 상단바 역할을 한다. 사이드바(공용 `ManageMenu`, `shared/shell`)는 위에서 아래로 맨 위 줄(STORYFORK 로고 + 접기 토글)·`내가 쓰는 소설` 돌아가기 링크·메뉴(`aria-label` '작품 메뉴': 개요·공개 회차·세계관·설정집·이야기 분기·AI 집필·받은 피드백·내 댓글·제보·운영 설정·저장·AI·발행 이력)·맨 아래 줄(알림·테마·계정 아바타, 계정 메뉴는 위로 열린다)이고(도구 묶음은 없다: `ManageMenu`의 `tools`는 선택이라 세계관 관리만 쓴다)(검색 버튼은 없다: Ctrl K 전역 단축키), 오른쪽 내용 열은 맨 위 오류·상태 알림(비어 있으면 자리를 차지하지 않는다)과 고른 메뉴의 내용이고, 히어로(표지·제목·소개)는 모든 탭 위가 아니라 맨 앞 `개요` 탭(기본 탭)의 내용이다. 히어로는 쉴 때 88px 표지 썸네일 + 제목·칩·소개(두 줄까지)·태그·통계 한 덩어리로 줄어(`.ep-hero-compact`), 작품 정보·표지를 편집하는 동안만 옛 큰 히어로(240px 표지)로 펴진다. 분기 정책(분기 작품은 포크 정보)과 작품 삭제는 모든 탭 위가 아니라 `운영 설정` 탭 안에 있다(운영 설정 아래 분기 정책, 맨 끝이 작품 삭제 위험 구역, 정책·작품 정보·표지 편집 폼이 열려 있는 동안은 다른 탭을 잠가 열린 폼을 잃지 않게 한다). 탭 구획의 폭은 모두 내용 열 폭이고 읽기 폭 제한은 분기 폼·안내문에만 있다. 각 탭 본문의 제목(h2)은 메뉴 탭 이름과 똑같은 글이고(`공개 회차 · N`처럼 개수도 같다, 탭 안의 묶음 제목은 h3, 받은 피드백 수신함의 제목도 `workId`가 있으면 h3), 집필실로 가는 길은 공개 회차 탭 머리의 `집필실 열기`와 회차별 `수정하기`·작성 중인 초안 링크뿐이고(사이드바·접힌 상단 줄에는 없다. 회차가 0개여도 `집필실 열기`로 가서 집필실의 `새 회차` 버튼으로 1화를 만든다), `내 댓글·제보`는 메뉴 탭이다(`MyCommentsReports embedded`: 쪽 제목 h1 없이 구획 제목은 h3이고 틀은 받은 피드백 탭과 같다. `/content?view=reports` 화면과 계정 메뉴 링크는 그대로다). 901px 이상에서 사이드바는 화면 맨 위·왼쪽 끝에 붙어 화면 높이를 쓰고(내용 열의 글·표는 1072px까지만 쓰고 가운데에 둔다) 맨 위 토글로 접을 수 있다(접으면 돌아가기 링크가 상단 줄로 옮겨 가 두 곳에 동시에 두지 않는다). 900px 이하에서는 로고·알림·테마·계정이 맨 위 한 줄이고 메뉴는 그 아래에서 줄바꿈해 탭이 모두 보인다. 사이드바 맨 앞의 '본문으로 바로가기'(공용 상단바의 링크를 대신한다)가 내용 열(`#ep-content`)로 초점을 옮긴다(세계관 관리도 같다. 사이드바는 `<main>` 안에 있고 메뉴는 이름 붙은 `nav` 하나다). 공용 틀(`.ep-manage`·`.ep-menu`·`.ep-menu-*`·`.ep-content`)과 위치·접기·좁은 화면 규칙은 `shared/episode.css` 한 곳이고 세계관 관리와 함께 쓴다(사이드바가 없는 `/content` 새 작품 만들기·내 댓글·제보는 공용 Gnb·Footer 그대로다). 메뉴를 눌러 탭이 바뀌면 그 내용 머리로 스크롤하고(첫 렌더·새로 고침은 그대로, 초점은 누른 버튼에 남는다). `/content` 작품 관리의 작품 정보 편집은 제목·소개와 함께 서버 값과 달라진 장르·해시태그만 `PUT /works/{id}`에 싣고(생략하면 서버가 유지), '받은 피드백' 탭은 작가 피드백함과 같은 조회에 `workId` 쿼리를 보내 서버가 그 작품 것만 주며(화면이 다시 거르지 않는다), 회차별 포크 수는 새 API 없이 소설 상세와 같은 `ReadingUseCase` 작품 목록으로 센다(읽지 못하면 수를 감춘다). 표지의 'AI로 생성'은 연결 전이라 비활성·'준비 중'이다. 실서버 집필실(`/studio/{UUID}?ep=n`)은 n화를 처음에 열고, 활성 회차가 바뀌면(목록 선택·새 회차·삭제·다시 읽기) 주소의 `?ep=n`도 `replace`로 따라 바뀌어 새로 고침이 보던 회차로 열린다(`WritingStudio`가 맡고, 처음 연 회차는 주소를 건드리지 않는다). 세계관·설정집 탭의 `세계관 연결`(`LinkedWorldPanel`, 그 위에 `원고로 세계관 만들기` 카드)은 이 소설과 내 세계관(WorldStudio)의 1:1 연결·해제를 `PUT /works/{id}/world-studio`(`EpisodeUseCase.linkWorldStudio`, `worldId: null`이 해제)로 바로 적용하고 응답의 연결로 작품의 `worldStudioId`를 바꾸며, 404·409(`WORLD_ALREADY_LINKED`)는 서버 문구를 그 카드 안에 그대로 알린다(작품 만들기·분기 만들기의 실패도 각 폼 안에, 이력 탭의 불러오는 중·실패는 그 구획 안에, 그 밖은 화면 맨 위 알림: `useEpisodeViewModel`의 `origin`)(DEC-46, [계약](../docs/design/public-world-contract.md)). 연결할 세계관 드롭다운의 기본값은 `선택 안 함`이고 고르기 전에는 연결 버튼이 잠겨 이유를 알린다(UC-24 E1: 세계관을 고르지 않으면 연결하지 않는다). 자기 세계관이 없는 Fork에서 이어받는 원작 세계관이 있으면 같은 탭이 그 카드(유형별 수·제목)·관계 수를 읽기 전용으로 보이고 `내 세계관으로 만들어 수정하기`(확인 뒤 `EpisodeUseCase.detachInheritedWorld` → `POST /works/{id}/inherited-world/detach`, 성공하면 `/worldstudio/{id}`, 실패는 그 카드 안 알림)를 둔다(#583, [계약](../docs/design/public-world-contract.md#fork-세계관-독립--dec-37)).
AI 자율 연재(UC-18, [계약](../docs/design/ai-serial-contract.md))는 Content API(`HttpSerialRepository`·`SerialUseCase`)를 쓴다. 작품 관리 메뉴에는 `이야기 분기` 다음에 `AI 집필` 탭(`AiSerialPanel`·`useAiSerialViewModel`)이 있고 하위 탭 `연재 설정 | 게시판 기록`(`.libtabs` ARIA 탭, 연재 설정이 처음, 저장·실행 알림은 요청을 보낸 탭에서만 보인다)으로 나뉜다. `연재 설정`은 요일(켜져 있을 때만 1개 이상)·시각(한국시간 HH:mm)·연재 방향을 저장하고(켜기·끄기는 이 탭이 아니라 운영 설정의 집필 방식 `AI 자율 집필`(`autonomous`) 저장이 하므로 요청에 `enabled`를 싣지 않고 꺼져 있으면 그 길을 안내한다. 세계관 연결은 묻지 않고, 응답 본문은 쓰지 않고 서버가 저장한 값을 다시 읽는다). `게시판 기록`은 `지금 마감·실행`(꺼짐·열린 게시판 없음·이미 실행 중이면 이유와 함께 잠기고 202 뒤 기록을 다시 읽는다)·`기록 새로 고침`과 게시판 기록 표(대기·실행 중인 행이 있는 동안 5초마다 갱신, 실패 사유는 서버 문구 그대로)를 보인다. 소설 상세는 서버(정본) 공개 작품일 때만 게시판을 한 번 읽어(`useSerialBoardRead`, `WorkPage`가 호출) `enabled`이면 탭 `회차 | 정보 | 소식` 옆에 `다음 회차` 탭을 두고(꺼진 작품·데모 작품은 읽지 않고 탭도 없으며 페이지 아래의 의견 영역은 없다), 탭 안(`SerialBoard`·`useSerialBoardViewModel`, 작품이 바뀌면 `key`로 새로 만든다)은 하위 탭 `투표 | 제안 게시판`이다. `투표`는 대상 회차와 선택지 4개(번호·글·득표·내 선택)를 라디오로 골라 투표·옮기기·취소하고(선택지가 없으면 `선택지를 준비하고 있어요`, 열린 게시판이 없으면 `다음 회차를 쓰고 있어요`와 마지막 종합 문장), `제안 게시판`은 목록(제목·작성자·추천 수·작성 시각, 최신순·추천순)·글쓰기 폼(일반·시뮬레이션, 시뮬레이션은 전제·비트 5개까지와 크레딧 차감 안내)·글을 누르면 펼쳐지는 본문·미리보기·추천 토글을 보이고 소유자는 글을 숨긴다. 비로그인은 읽기만 하고 투표·글쓰기·추천 자리에 로그인 안내를 본다. 첫 조회 실패는 정상 비활성(탭 없음)과 구별해 탭 줄 위에서, 쓴 뒤 다시 읽기 실패는 탭 안 배너에서(이전 게시판을 둔 채) 다시 불러오기를 보인다. 쓰기 뒤에는 서버가 지금 보는 값을 다시 읽는다(설정 저장은 PUT이 성공하면 곧바로 저장 완료로 알리고 설정·기록 다시 읽기는 따로 해 읽기 실패를 따로 알린다). 오류 `code`는 `HttpEpisodeRepository.request`가 `Error.cause`로 싣고, `INSUFFICIENT_CREDIT`만 `HttpSerialRepository`가 고정 한국어 문구로 바꾸며 나머지 409(`SERIAL_*` 등)는 서버가 준 한국어 `detail`을 그대로 보인다(기록 표의 실패 사유 `크레딧 상한을 넘었습니다.`도 서버 문구 그대로). 시뮬레이션 제안 글 제출만 AI 장면 미리보기를 기다려 제한 시간이 150초다(`request`의 `timeoutMs`, 기본 80초는 그대로). 설정 카드 제안은 범위 밖이고 `--mode mockup`에는 대역이 없어 탭은 '데모에서는 지원하지 않아요'만 보인다. AI 자율 집필이 켜져 있는 동안(소유자 `GET /works/{id}/ai-serial`의 `enabled`, `useSerialLock`) 작가는 1화만 쓰고 서버가 2화부터의 원고 쓰기를 409 `SERIAL_LOCKED`로 막으므로(도메인 `serialEpisodeLocked`·`serialNewEpisodeLocked`), 집필실은 1화가 아니면 위쪽 안내와 함께 제목·본문·작가의 말을 읽기 전용으로 두고 버전 저장·발행·복원·체크포인트 되돌리기·예약 발행·공개 중단·삭제를 잠그며(1화는 그대로 열린다. 회차 항목 ⋮ 메뉴의 회차 삭제는 그 항목의 회차로 판단한다), 새 회차는 회차가 하나라도 있으면 잠근다(1화 만들기만 열린다). 작품 관리는 회차 목록의 `수정하기`·작성 중인 초안을 1화만 집필실로 보내고 이유는 회차 목록 머리에 한 번 알린다(화면 잠금은 보조라 읽는 중·읽기 실패는 잠그지 않고 서버 판정에 맡긴다. 이미지 설명·가져오기·집필 AI 쓰기 도구는 서버 409 `detail`을 그대로 보인다). 운영 설정의 집필 방식 select에 `AI 자율 집필`이 있고, 저장하면 서버가 AI 집필을 켜므로 `EpisodePage`가 켜짐 여부를 다시 읽는다(실행 중 다른 방식으로 바꾸는 저장의 409 `SERIAL_RUNNING`은 서버 문구 그대로 보인다). `AI 자율 집필`을 새로 저장할 때(저장값이 `autonomous`가 아닐 때)는 곧바로 보내지 않고 확인 대화 상자(`useWorkSettingsViewModel`의 `confirming`, 공용 `Sheet`에 `role="alertdialog"`·`describedBy`)가 회차 집필이 연결된 세계관의 인물 카드로 인물 시뮬레이션을 돌리니 세계관을 연결하고 인물 카드(성격·말투·목표·관계)를 작성해 달라고(없으면 회차 실행이 실패한다고) 경고하고, `세계관·설정집으로`(저장 없이 작품 관리 세계관·설정집 탭으로 이동하며 메뉴가 잠긴 동안은 잠긴다)·`계속 저장`·`취소`(저장하지 않는다)를 고르게 한다(처음 초점은 저장이 아닌 `세계관·설정집으로`. 경고일 뿐 저장을 막지 않고, 직접·협업 집필 저장과 AI 자율 집필을 끄는 저장, 이미 `autonomous`라 저장이 잠긴 경우에는 뜨지 않는다).
설정 위키(`/work/:id/wiki`, U45)는 작품에 연결된 세계관이 있으면 `GET /public/works/{id}/world-cards?upto=`가 주는 독자 공개 설정 카드(`ReadingUseCase.linkedWorldCards` → `reading/viewmodel/worldCardWiki.ts`)로 채우고, 없으면(`worldId: null`) 기존 `readWorld` 경로 그대로다. 독자 공개 회차는 서버가 발행된 회차 안에서 거르므로 화면은 카드를 거르지 않고(공개 세계관·가져오기·Fork 이어받기·공개 MCP도 같다: 카드 공개 기준은 DEC-53으로 하나이고 서버가 기준 회차 이하로 공개된 카드만 주며, 본문 링크의 대상이 숨어 있으면 서버가 글자만 남기므로 화면은 공개 응답을 거르거나 되살리지 않는다. 기준 회차 규칙과 본문 링크 치환은 서버 소스 구현·로컬 단위 테스트 통과, #485. 본문의 설정 링크는 `CardMarkdown`의 `cardLink`로 같은 위키 안 그 카드의 문서로 건너가게 그리고 위키에 없는 카드는 글자만 그린다), 관계 `A → B 「관계명」`은 'B는 A의 관계명'으로 읽어 보내는 쪽 문서에 `상대 — 관계명` 소제목(상대는 그 문서로 가는 링크)과 관계 설명(마크다운) 문단을, 받는 쪽 문서에는 '이 설정을 가리키는 관계' 줄의 `상대(관계명)` 링크를 두며(방향이 대칭이거나 없으면 양쪽 문단, 「동일 인물」도 같다, 링크는 보내는 쪽 문단의 관계 id 기반 앵커(`shared/relationParagraph.ts`)로 이동해 초점을 옮기고 짧게 강조, DEC-54), 관계가 회차에 따라 바뀌었으면(응답의 `history`에서 관계명이 달라진 변화가 둘 이상이고, 관계명이 같은 연속 변화는 처음 회차로 합친다: `shared/relationParagraph.ts`의 `relationHistoryLine`) 문단 소제목 아래에 `경계(1화) → 보호(3화)`처럼 변화를 한 줄로 쌓아 보이며, 관계를 불러오지 못한 응답(`relationshipStatus: unavailable`)은 빈 연결과 구분해 알리며, 조회 실패를 빈 위키로 바꾸지 않는다. 카드에 `imageId`가 있으면 정보 상자 맨 위에 `GET /public/works/{id}/world-card-images/{imageId}?upto=`(위키가 받은 기준 회차 그대로)를 `<img>`로 직접 읽고 읽지 못하면 감춘다(`Doc.cardImage`, 기존 작품 위키 문서의 `img`는 그리지 않는다).
좋아요·관심 작품·독서 기록은 Content API(`HttpWorkLikeRepository`·`HttpWorkInterestRepository`·`HttpReadingRecordRepository`, [계약](../docs/design/reading-management-contract.md))를 쓰고, 나머지 데모는 별도 메모리 저장소다. 관리자 이벤트 탭과 회원 `/me/event`는 운영 이벤트 API(`HttpEventRepository`)를 쓴다([계약](../docs/design/operations-event-contract.md)). 이벤트의 선택 칸 `linkPath`(DEC-57, 이벤트 안내(`/me/event`)의 목록 카드와 상세는 사이트 안 경로일 때만 '바로 가기'(앱 안 이동)를 그린다. 관리자 작품 탭은 운영 작품 API(`HttpOperationsWorkRepository`)를 쓴다([계약](../docs/design/operations-work-contract.md)). 행을 누르거나 ⋮ 메뉴의 `상세`를 고르면 작품 상세 드로어(`AdminWorkDetail`·`useWorkDetailViewModel`)가 화면 오른쪽에 열린다(모달이 아니라 뒤 표는 그대로 쓰고, 열면 제목으로 초점이 가며 Esc·닫기로 닫으면 그 줄의 ⋮로 돌아온다). 회차(번호·제목·발행 상태·제한·상속 여부)와 연결 세계관(운영 세계관 목록의 `linkedWorkId`)을 보이고 회차 `운영 제한`(확인 뒤)·`제한 해제`(바로)를 `PUT|DELETE /works/{id}/episodes/{n}/restriction`으로 요청하며, 상속 회차는 서버가 409 `EPISODE_INHERITED`로 거절해 버튼을 잠그고 원작 회차를 제한하게 안내한다. 행의 ⋮ 메뉴의 `소설 보기`(`/work/{id}`)·`집필실 보기`(`/studio/{id}`)로 운영자는 소유권 없이 모든 작품(비공개 포함)을 열람한다(`canView`·`ReadingUseCase.load`: admin이면 목록에 없는 서버 작품 ID를 `GET /works/{id}`로 읽는다). 남의 작품 집필실은 `useOperatorViewOnly`(소유자 확인 전·실패 포함)가 열람 모드로 바꿔 쓰기 버튼을 잠그거나 숨기고 본문을 읽기 전용으로 두며 배너는 확인 결과를 따른다(확인 중에는 없고, 남의 작품이면 '다른 작가의 작품' 안내, 읽지 못하면 그 사실과 `다시 시도` 버튼). 회차 이동·버전 보기·내보내기·발행 이력은 그대로이고 플롯·시뮬레이션 무대·세계관 하위 패널의 쓰기는 서버 거절 문구로 알린다. 서버도 운영자의 쓰기는 소유자만 받고 자기 소유 작품은 일반 작가처럼 수정한다(2026-11-23 사용자 결정). 관리자 댓글 탭은 운영 댓글 API(`HttpOperationsCommentRepository`)를 쓰고, 회차 댓글은 운영 숨김(`hidden`)을 자리표시로 그린다([계약](../docs/design/operations-comment-contract.md)). 관리자 활동 로그 탭은 운영 활동 기록 API(`HttpAdminActivityRepository`)를 쓴다([계약](../docs/design/operations-admin-activity-contract.md)). 관리자 크레딧 탭은 운영 크레딧 API(`HttpOperationsCreditRepository`, [계약](../docs/design/operations-funnel-credit-contract.md#2-크레딧-운영-core-정본--운영-중계), DEC-57)로 회원의 잔액(지급 종류별)·내역을 읽고 수동 지급·회수를 요청한다. 탭을 열면 사용자 탭과 같은 `MemberUseCase.listMembers`(`users` 권한)로 전체 회원을 최신 가입순으로 읽고 행마다 보유 크레딧(묶음 잔액 `POST /credits/balances`, 회원 id를 100명씩 나눠 조회하고 서버가 모르는 회원은 '—')을 보이며(검색은 목록을 좁힌다) 행의 ⋮ 메뉴로 회원을 고르고, 크레딧 조회·변경은 `credits` 권한이며 어느 쪽이든 403이면 권한 안내만 보인다. 지급·회수 폼은 금액·사유를 먼저 검사해 확인 대화 뒤 요청하고 처리 중 입력·버튼을 잠그며(중복 방지 키는 없다), 잔액 초과 회수(409 `CREDIT_INSUFFICIENT`)와 연결 실패(502, 반영 여부를 단정하지 않음)는 한국어로 안내하고, 성공하면 잔액·내역을 다시 읽는다. 내역 `type`의 `revoke`는 회원 `/me/pay`에도 '회수'로 보인다. `--mode mockup`에는 크레딧 대역이 없다(회원 검색도 서버 저장소). 관리자 개요(`data`)·LLM Ops(`llm`)·정기 작업(`jobs`) 탭은 운영 대시보드·LLMOps·작업 감시 API(`HttpOperationsDashboardRepository`·`HttpLlmOpsRepository`·`HttpJobMonitorRepository`, 목록 경로는 끝 슬래시 없이 호출, [계약](../docs/design/operations-llmops-contract.md), DEC-55)를 쓴다. 개요 카드는 출처를 읽지 못한 칸을 0으로 채우지 않고 '불러오지 못함'으로 보이며(응답의 `unavailable`은 안내 줄로) '미확인 경고' 카드는 LLM Ops로 잇는다. '서비스 지표(전체 기간)'(DEC-57, `ServiceMetrics`)는 응답의 `funnel`(Content 집계)을 단계 막대 4묶음(독자 조회→1화 이상→이어 읽기, 독자→Fork, Fork→저장→발행, AI 채택·수정 제안 승인)·회차당 반응·Fork 기준 회차 분포로 그린다. 비율은 `domain/entities/operationsFunnel.ts`의 순수 함수가 직전 단계를 분모로 계산해 오차 ±1/√n(%p)와 n을 함께 적고(분모 0은 —, 회차당 반응은 평균이라 n만), `funnel`이 null이면 0으로 채우지 않고 '불러오지 못함'을 보이며, 차트는 `AdminCharts.tsx`가 그린다. 개요는 위에서부터 요약 카드 띠, '서비스 지표(전체 기간)'(DEC-57 퍼널: 비율·±오차·n 목록은 각 차트 위), '최근 7일 AI 사용' 순이다. '최근 7일 AI 사용' 차트 둘(날짜별 요청 수·실패율, 날짜별 사용자·플랫폼 부담 비용)은 카드와 따로 지표 API(`GET /llmops/metrics?groupBy=day`, `LlmOpsUseCase.weeklyMetrics`)를 읽어, `llm` 권한이 없으면(403) 차트 대신 권한 안내 한 줄을 보이고 실패는 0으로 채우지 않고 다시 불러오기를 보이며 요청이 없던 날은 그리지 않는다. LLM Ops는 사이드바 'LLM Ops' 묶음의 네 메뉴로 나뉘며(주소 `?tab=llm&view=`의 `view`가 쪽을 정하고 없거나 모르는 값은 경고, 쪽마다 패널을 위아래로 쌓고 상세를 열면 그 상세만 보이며 쪽을 옮기면 상세는 닫는다) '경고'는 운영 경고 목록을 읽어(운영 경고 알림 `targetType: 'alert'`의 이동 대상이 `/admin?tab=llm`이며 `noticeTarget`이 정한다) `llm`·`jobs` 권한이 없으면(403) 실패 대신 필요한 권한을 안내하고 확인·조치 완료를 메모와 함께 기록하고 그 아래에 경고 기준을 두며, '추적·지표'는 추적(기간·기능·상태·회원·요청 ID 조건, 단계 표 상세)와 지표(날짜·기능·모델별 표 위에 날짜별은 요청 수·p95 지연·실패율 차트, 기능·모델별은 비용 가로 막대 차트, 데이터가 없는 비율은 '데이터 없음')을, '프롬프트·모델'은 위쪽 보기 전환(주소 `&sub=`, 없거나 모르는 값은 전체)으로 전체·프롬프트·모델 중 하나만 보이고(프롬프트 상세를 열면 전환은 숨고 상세만 보임), '프롬프트' 보기는 프롬프트(새 버전 등록, production 승격·복원이 평가 미통과로 409 `EVALUATION_REQUIRED`가 되면 서버의 영문 문구 대신 정해진 한국어 문구를 보임)를, '모델' 보기는 모델(단가는 100만 토큰당 USD로 받아 토큰당으로 보냄)을 보이며, '전체'(AI 파이프라인, DEC-58, [계약](../docs/design/operations-ai-pipeline-contract.md))는 집필 AI 파이프라인을 `react-force-graph-2d` 고정 좌표 캔버스(`AdminPipelineCanvas.tsx`, 보기를 열 때만 내려받고 jsdom에서는 틀(role=img)만 그린다)로 보인다. 노드 목록은 서버 고정 목록(`GET /llmops/pipeline`, 기본 최근 7일에 기간 선택)이고 `domain/entities/llmOpsPipeline.ts`의 `layoutPipeline`이 요청 흐름 노드를 왼→오 칸에, 단독 기능 노드를 그 아래 줄에 놓으며(업무 Agent→메인 같은 되돌아가는 선은 칸을 정하는 데 세지 않고 점선으로 따로 그리며, 업무 Agent 열은 읽기·검토 묶음이 위·작성 묶음이 아래로 묶음 라벨을 달고 두 묶음 사이 빈칸이 요청·Guard·메인 줄에 와 메인→도구 직접 선이 그 사이를 지난다. 모르는 id의 노드는 연결(next)대로 놓인다. 끌기·이동·확대는 끈다) 노드 이름·건수·오류 수를 그리고 오류가 있으면 위험 색으로 알린다. 캔버스는 보조라 같은 노드를 키보드로 고르는 버튼 목록을 캔버스 아래에 두고, 노드를 고르면 캔버스·노드 버튼 아래에 전체 폭으로 그 노드의 기록 패널(`GET /llmops/pipeline/{nodeId}/records`, 최신순 20건, 서버가 최신 1,000건까지만 주므로 그 밖의 쪽은 막고 안내)이 열린다. 결과 필터(전체·통과·거절/오류)는 서버 level(DEFAULT·ERROR)로 거르되 Guard는 거절이 level이 아니라 `decision_guard` 출력의 `allowed=false`라 서버 조건 없이 받은 쪽 안에서 가린다. 기록 줄을 펼치면 입력·출력·메타데이터를 받은 그대로(칸마다 앞 8,000자) 보이고, Guard는 결과 칸에 허용·거절과 이유·필요한 기능(집필 채팅과 같은 기능 표시 이름 `featureLabel`, 모르는 코드는 그대로)을(출력에 판정이 없던 이전 기록은 metadata에서), 메인 에이전트는 출력({text, toolCalls})의 도구 호출(이름·인자)을 보이며, NovelBrain 기억 회상(`novelbrain.recall`, 인물 시뮬레이션 다음 노드) 기록은 출력의 `recalled` 목록을 '회상한 기억' 제목 목록으로 더하고(카드 항목은 제목, 관계·원고 항목은 제목이 없어 ref), 줄의 ⋮ 메뉴 '실행 흐름 보기'는 그 작업의 observation 트리(`GET /llmops/traces/{id}`의 `parentObservationId`, 단계마다 입력·출력)를, '프롬프트 보기'는 프롬프트 보기로 옮겨 그 프롬프트 상세를 연다. '평가·누설 검사'는 평가(목록·지표 표 위의 점수와 기준 막대 차트·실행)와 누설 검사 기록·표본 비율을 보이고, 정기 작업은 실행 기록(상태·종류 조건, 진행률, 실패 작업 재실행은 확인 뒤(회귀 평가 실행은 종류 '회귀 평가'·출처 'AI 평가'로 같은 기록에 보이지만 평가 화면에서 새로 실행하므로 실패해도 재실행 메뉴가 없다), 출처(원고 전처리·AI 평가)를 읽지 못하면 출처 라벨로 안내, 서버가 앞쪽 1,000건까지만 읽게 해 그 밖의 쪽 이동은 막음)과 일정 등록·변경·취소(수정은 기존 종류를 담은 `{kind, cron, enabled, params}` 전체 본문)를 보인다. 정기 작업(`jobs`)과 LLM Ops의 조회는 권한이 없으면(403) 일반 실패 문구·다시 불러오기 대신 필요한 권한만 안내한다(`orNullIfForbidden`이 403을 null로 바꾸고, `LiveState`의 `forbidden` 안내가 그리며, 정기 작업은 필터·일정 폼 없이 안내 하나만 보이고, 모델 등록·평가 실행 폼은 목록이 403이면 숨긴다). 이 화면들의 변경 요청 오류 400·404·409·422는 서버의 영문 고정 문구 대신 한국어 안내를 보이고 상위 서비스가 준 안내(한글 문구나 code `UPSTREAM…`)는 그대로 보인다. 관리자는 Langfuse 웹에 들어가지 않으므로 Langfuse 링크는 두지 않는다. 차트는 Recharts(production 의존성)로 `presentation/features/admin/view/AdminCharts.tsx` 한 파일에서만 그리고, 색은 전역 CSS 변수(`--pri`·`--danger`·`--acc-ink`·`--faint`)를 쓰며, 값은 `domain/entities/llmOpsCharts.ts`의 순수 함수(날짜 정렬·한국시간 날짜 라벨·비어 온 값은 0이 아닌 null이라 선이 끊김)로 바꾸고, 실패율·평가 점수 축 범위는 같은 파일의 `RATIO_DOMAIN`(0~1)으로 고정한다(자동 범위에 맡기면 값이 모두 0일 때 0~400%가 된다). 각 차트는 `role="img"`와 요약 `aria-label`(`llmOpsCharts.ts`의 요약 함수)을 가지고 키보드 초점을 받지 않으며, 같은 값이 차트 아래 표·카드에 있어 차트는 보조다. 크기를 못 재는 jsdom에서는 그림 없이 이 틀만 렌더돼 렌더 테스트는 틀과 상태 분기(권한 없음·실패·빈 상태)를 확인한다. `--mode mockup`은 같은 계약의 예시 메모리(`InMemoryLlmOpsRepositories`)다. 화면 존재와 서버 기능 완료를 구분한다.
계정 '결제 내역'(`/me/pay`)의 보유 크레딧·지급/사용/회수/소멸 내역은 Core 크레딧 API(`HttpCreditLedgerRepository`)를 쓴다([계약](../docs/design/credit-ledger-contract.md)). 상단 계정 메뉴의 '보유 크레딧' 줄도 같은 API의 잔액만 읽는다(`useCreditBalance`, 읽지 못하면 0으로 채우지 않는다). 스튜디오 데모 AI 차감(`CreditUseCase`)은 별도 메모리 상태이며 바꾸지 않는다.
계정 프로필의 회원탈퇴(U30)는 Core 탈퇴 API(`HttpWithdrawalRepository`, `/api/v1/me/withdrawal`)로 30일 유예 탈퇴를 요청·복구하고, 요청이 받아지면 서버가 모든 세션을 끊으므로 이 브라우저도 로그아웃한다. `--mode mockup`은 요청 없음 상태만 보이고 탈퇴·복구는 데모 미지원 오류로 답한다.
홈 실시간 인기·급상승·최신 포크·방금 업데이트·이번 주 인기와 `/rank`는 Content 기간별 랭킹 API(`/public/works/rankings`)를, 홈 장르 칩과 `/search` 작품 탭은 공개 검색 API(`/public/works`, 인기 순·페이지)를 쓴다(`--mode mockup`은 시드 메모리 작품·검색). `/search`는 `?type=all|work|world|card|chat` 탭(기본 전체, `f`·`sort`가 있으면 작품)이며 세계관·카드 탭은 번호 페이지, 빠른 이동도 세계관·설정 카드를 함께 찾으며 세계관 탭은 공개 세계관 목록 `q`, 설정 카드 탭은 `GET /public/world-studios/cards`(`PublicWorldUseCase`)를 쓰고 캐릭터챗 탭은 `/chat` 목록 안내뿐이다(#505). 검색 결과 카드의 소설 신고는 카드 안 더보기 메뉴다(#507).
계약은 [작품 검색·랭킹](../docs/design/work-search-ranking-contract.md)이다.
**장르**(작품·세계관·홈 칩)의 정본은 Content `genre`이고 하드코딩 목록은 없다([계약](../docs/design/genre-management-contract.md), DEC-56). 작품 등록·수정(`TaxonomyFields`·새 소설 데모 `NewWorkPage`)과 세계관 공개 설정(`PublishFields`·헤더 장르 칩)의 선택지, `/worlds` 칩(추천 + 세계관이 하나 이상 있는 활성 장르), 홈 칩(`ReadingUseCase.homeChips`: 추천 · 홈에 보이는 장르(최대 6개) · 무료 · 포크 많은)은 공개 장르 목록 `GET /public/genres`(`GenreUseCase`·`useGenres`, 활성 장르만 표시 순서)를 읽고 읽지 못하면 빈 목록으로 채우지 않고 실패와 다시 불러오기를 보인다. 작품 장르 값은 장르 이름, 세계관 장르 값은 장르 코드(`genre-NN`)이며 세계관의 이름(`genreName`)은 `PublicWorldUseCase`가 공개 목록으로 붙인다(숨긴 장르의 세계관은 이름을 알 수 없어 '미지정'처럼 그리고 코드를 보이지 않는다). 관리자 `콘텐츠 관리 > 장르`(`/admin?tab=genres`, `useGenresViewModel`·`AdminGenres`)가 운영 장르 API(`HttpOperationsGenreRepository`, `/api/v1/operations/genres`)로 추가·이름·아이콘·숨김·홈 노출·순서를 관리하며 행 조치는 ⋮ 메뉴 하나(`PopMenu`)이고 `works` 권한이 없으면(403) 권한 안내만 보인다. `--mode mockup`은 같은 계약의 메모리 목록(`InMemoryGenreRepositories`)이다.
**세계관 카드 카테고리**(운영자 콘텐츠 관리 결정 E)의 정본은 Content `card_category`이고, 기본 8종(`character`·`location`·`organization`·`ability`·`object`·`rule`·`event`·`other`)에 운영자가 `category-NN` 코드를 더한다. 카드의 `cardType`(`CardType`)은 이 코드의 문자열이라 서버 응답 스키마가 코드 목록을 고정하지 않고, 카드 판정은 `isCard`·묶음은 `kindOf`가 맡는다. 공개 `GET /public/card-categories`(`CardCategoryUseCase`·`useCardCategories`)는 숨긴 카테고리까지 `active` 플래그와 position 순서로 주고, 작가의 카드 생성·수정 선택지(`+ 새 설정` 메뉴·관계도 설정 추가 패널·우클릭 메뉴·편집 화면 `유형`)는 `categoryChoices`가 활성 카테고리만 보인다(이미 쓰는 숨긴 카테고리는 그 카드에 그대로 남아 이름이 보이고 새로는 고를 수 없으며 서버가 422로도 거절한다). 목록을 읽는 동안·읽지 못했을 때는 기본 8종으로 대신하지 않는다(`useCardCategories`는 `categories`가 비고 `isLoading`·`isError`·`retry`를 주며 `useGenres`와 같은 규칙이다): `+ 새 설정` 메뉴는 항목 대신 '불러오는 중'·'불러오지 못했어요 + 다시 시도'를 메뉴 안에 보이고, 편집 화면 `유형`은 잠그며(실패는 `CardCategoryNotice`로 다시 시도), 관계도 `+ 설정 추가` 패널은 목록 대신 같은 안내를 보이고 우클릭 메뉴의 추가는 잠근다. 이름만 보이는 설정집 게시판·세계관 검토는 실패(다시 시도)만 알린다. 게시판 행의 유형 이름과 관계도 유형 필터 이름은 목록의 이름(바뀐 이름 포함)이다. 설정 분류 메뉴·그래프 색은 공개 설정집과 같은 6묶음이라 기본 8종이 아닌 카테고리의 카드는 '기타' 묶음에 들고, 공개 화면(공개 세계관·소설 위키)에는 카테고리 이름 대신 '기타'로 보인다(한계). 관리자 `콘텐츠 관리 > 카드 카테고리`(`/admin?tab=cardCategories`, `useCardCategoriesViewModel`·`AdminCardCategories`)가 운영 API(`/api/v1/operations/card-categories`)로 추가·이름·아이콘(8글자까지)·숨김·순서를 관리하며 장르 탭과 같은 틀이고 `works` 권한이 없으면(403) 권한 안내만 보인다. 관리자 `콘텐츠 관리 > 세계관`(`/admin?tab=worlds`, `AdminWorlds`)은 `GET /api/v1/operations/world-studios`로 지우지 않은 전체 세계관(작가·공개 상태·연결 작품)을 읽고 `PUT|DELETE …/{id}/restriction`으로 공개 경로(목록·상세·카드 검색·이미지·가져오기)의 운영 제한·해제를 요청한다(연결된 소설 위키·Fork 이어받기는 건드리지 않는다). `--mode mockup`은 카드 카테고리 메모리 목록(`InMemoryCardCategoryRepositories`)이고 세계관 탭 대역은 없다.
**신고 대상**(결정 D)은 작품·회차·공개 세계관이다(`ReportTarget`, 작품은 `targetType`을 생략). 소설 상세 `소설 신고`·독자 회차 화면 머리의 `신고`(`EpisodeReportSheet`)·공개 세계관 상세의 `세계관 신고`(`WorldReportSheet`)가 같은 `ReportWorkForm`(`target` 속성)으로 접수하고 셋 다 로그인한 회원만 보낸다(비회원은 안내와 함께 로그인으로). 세계관 신고는 작품 정보 없이(`workId`·`workTitle`·`workOwnerId` null) 접수·조회되고, 관리자 신고 표와 `/reports`(내 신고)는 대상·대상 종류를 보이며 처리의 제한·해제는 그 대상에 적용된다.
알림 설정에는 읽기·작가 소식·`AI·외부 도구 변경`(`ai-tool`, #553) 켬·끔이 있고, `ai-tool` 알림은 대상에 따라 `/worldstudio/{id}`·`/studio/{id}`로 가며(다른 분류의 work는 `/work/{id}`), 실서버 집필실과 세계관 관리는 `useMcpChangeWatch`(`presentation/shared`)가 알림 스트림 신호(`noticeVersion`)마다 최근 알림 한 쪽을 읽어 열린 대상의 `ai-tool` 알림 시각(서버 시각끼리 `mcpChange`로 비교, 화면을 열 때 읽은 값이 기준선)이 기준선보다 뒤면 확인 없이 `refresh`로 다시 읽고, 저장하지 않은 수정이 있으면 덮지 않고 `McpChangeBanner`('다른 곳에서 바뀌었어요 · 다시 불러오기', 누르면 확인 없이 서버 값으로)만 띄운다(알림 조회 실패는 조용히 다음 신호까지 대기, 운영자 조치 알림(`result`)·mockup은 새로고침하지 않음, 플롯 패널은 제외, [계약](../docs/design/mcp-change-notice-contract.md)).
작품·세계관 표지는 화면마다 달리 그리지 않고 한 규칙(`shared/cover.ts`의 `coverSrc`)이다(#432): 올린 표지가 있으면 그 표지, 없으면 `/default-work-cover.svg`이며 테마·장르 SVG(`Art`)는 홈 히어로 배경·로그인 그림 같은 장식에만 쓴다. 소설 상세(`/work/:id`) 상단은 `.calm`의 배경색 위에 작품 표지와 정보를 표시한다(#508). Fork 소설이면 그 상단에 원작으로 가는 링크 칩(`「원작」 N화에서 분기`)을 두고, 원작 상세의 포크 목록은 전제 문장이 아니라 포크 제목을 굵게 보인다(#623). 작품 표지(`CoverOf`·`Cov`)는 `Work.coverImg`(데모 메모리 작품만 가짐)를 쓰고, **서버 작품은 목록·상세 응답에 표지 유무가 없어 새 요청을 늘리지 않는 한 홈·상세·탐색·랭킹·챗 등에서 올린 표지가 있어도 기본 표지로 보인다**(서재 '집필 중인 작품'만 카드마다 소유자 읽기로 올린 표지를 보이며, 목록 응답에 표지 유무가 생기면 그 값으로 `coverImg`(공개 cover 주소)를 채워 이 한계를 없앤다). 세계관은 공개 화면이 `hasCover`로, 관리 헤더와 서재 '내가 만드는 세계관' 카드가 소유자 읽기(`shared/useWorldCoverImage`)로 올린 표지를 보이며 읽는 동안 서재 카드는 비워 둔다.
실제 모드 `/import`·집필실 원고 내보내기·설정 첨부(작품 관리 세계관·설정집 탭의 `설정 첨부` 카드: 설정 하나를 골라 올리기·다운로드·이름 변경·삭제, 소유자 전용)·회차 이미지 목록·대체 텍스트·다운로드는 Content 원고 가져오기·내보내기 API(`HttpManuscriptRepository`·`HttpMediaRepository`)를 쓴다.
`--mode mockup`은 기존 데모 가져오기 화면을 유지하고, 데모 집필실의 TXT 초안 내보내기만 메모리로 만들며 나머지는 "데모에서는 지원하지 않아요" 오류를 낸다.
계약은 [원고 가져오기·내보내기](../docs/design/manuscript-import-export-contract.md)다.
가져오기(`/import`·작품 관리 `회차 파일 일괄 업로드` 시트)는 회차를 하나 이상 저장하면 서버가 같은 요청에서 세계관 추출 접수를 시도하고 응답의 필수 키 `worldBuild`(`started`·`rejected`, 접수하지 않았으면 null, 키가 없으면 응답 전체를 검증 실패)에 싣는다([계약](../docs/design/initial-build-storage-contract.md)). 화면은 확인 체크·확인창 없이 등록·저장 버튼 곁 한 줄로 OpenAI 전송을 알리고, 결과에 started(`role="status"`, `/import`는 작품 관리 세계관 탭 `/content?work=<id>&tab=world` 링크도, 시트는 문구만)·rejected(서버 `message` 그대로 `role="alert"`)를 보이며 null이면 그리지 않는다(일괄은 묶음 요청 중 마지막 묶음에만 `startWorldBuild: true`를 실어 그 응답의 `worldBuild`만 보인다: 앞 묶음에서 접수하면 그때 저장된 회차만 작업에 들어가고, 실패 묶음 재시도도 그 전송의 마지막 묶음만 true다).
작품 관리 세계관 탭의 `원고로 세계관 만들기`(`ManuscriptBuildPanel`, [계약](../docs/design/initial-build-storage-contract.md))는 조회가 작업 없음(404·`recovery: new_request`)이면 접수 전에 `localStorage`에 남긴 요청 기록(worldId·key)을 지우고, 실패(`failed`)한 작업에는 항상 `같은 작업 재개`와 함께 동의 뒤 `새로 시작`(기록을 버리고 새 key로, 세계관은 지금 작품에 연결된 세계관을 먼저 쓰고 없으면 실패한 작업의 세계관)을 보이며, 2초 자동 조회는 `busy`·상태 문구를 켜지 않고(사용자가 누른 버튼이 자동 조회를 중단시킨다) 완료 응답의 `skippedItems`(없으면 응답 전체를 검증 실패로 본다)가 0보다 크면 '근거를 확인하지 못한 항목 N개는 초안에 넣지 않았어요'를 알린다. `같은 작업 재개`는 이 브라우저의 요청 기록이 없거나 그 key가 조회 응답의 `requestKey`와 다르면(업로드가 서버에서 시작한 작업·다른 브라우저) 응답의 `worldId`·`requestKey`와 `consent: true`로 보내고(응답에 `requestKey`가 없으면 응답 전체를 검증 실패로 본다) 요청 기록은 바꾸지 않는다. 작품 관리 `공개 회차` 머리의 `세계관 추출 중`·`세계관 업데이트 중` 배지(`WorkManagement`의 `WorldBuildBadge`, 판정은 `domain/entities/manuscriptBuild.ts`의 `worldBuildBadge`)는 같은 `useManuscriptBuild` 조회를 그대로 써 queued·running·loading일 때만 보이고(조회 응답 최상위의 `update`=가장 최근 발행 회차 업데이트 작업 `{jobId, status, episodes, failureCode}`가 진행 중이면 `세계관 업데이트 중`이고, 없거나 서버가 아직 보내지 않으면 null이며 값이 있는데 모양이 틀리면 응답 전체를 검증 실패로 본다. 둘 다 진행 중이면 `세계관 추출 중`이 먼저이고 2초 조회는 둘 중 하나가 진행 중인 동안 이어진다·busy 없음, 작업 없음·조회 실패·끝난 작업·목업은 배지 없음, 실패를 완료로 표시하지 않음) 일괄 업로드 시트가 회차를 저장하고 닫히면 다시 읽으며, 주소 `?tab=world`는 세계관 탭부터 연다.

`save`, 관계 제외·비공개. 대상은 `useImportTargets`가 내 세계관에서 원본 자신을 뺀 것). 진행·결과·실패 사유와 `다시 시도`는 그 자리에 보이고 실패를 성공으로 바꾸지 않는다. 지도·그래프 캔버스는 터치 기기(`pointer: coarse`)에서 지도 이동·노드 끌기를 꺼 한 손가락 끌기가 페이지 스크롤이 되게 `data/mock/InMemoryPublicWorldRepository`가 데모 세계관 26개(파생·조합·작품·카드 점은 이 데모에만 있고 "데모" 안내를 띄움)로 같은 계약을 답한다. 내 세계관 `/worldstudio/:id`는 `/content` 작품 관리와 같은 틀(`episode-app`·`ep-*`)의 관리 화면(서재 `/lib?tab=worlds`로 돌아가는 링크·공개 상세 모양 헤더, 모든 보기(개요 포함)와 작성 모드에서는 헤더(`data-view`는 보기 이름 또는 `wizard`)가 72px 표지 썸네일 + 제목·칩 한 덩어리로 줄고 소개는 숨는다)이고 `/worldstudio`는 새 세계관 만들기다. 만들기 화면과 내 세계관 목록은 세계관 없는 주소 `/worldstudio`에서만 그리며 `/worldstudio/:id`에는 숨겨서라도 두지 않는다. 세계관을 처음 만든 직후(만들기 화면이 이동하는 `/worldstudio/{id}?new=1`, 새로고침해도 유지)만 **작성 모드**로 사이드바 없이 기본 정보(이름·설명·공개 설정)부터 4단계 마법사 카드를 보인다. 마법사의 첫 저장이 성공하거나 '관리 화면으로'를 누르면 `new` 쿼리를 `replace`로 지워 **관리 모드**로 바뀌고(초점은 헤더 제목, 쓰던 입력은 그대로) 판정은 `worldStudioFlow.studioMode`(주소의 쿼리)다. 그 밖의 모든 진입(서재 '관리하기'·직접 주소, 저장 버전 0인 세계관 포함)은 관리 모드로, 단계 없이 두 화면이다. **설정집 화면**(기본)은 `/content` 작품 관리와 같은 2열 틀(왼쪽 사이드바 + 오른쪽 내용 열: 헤더 + 고른 보기의 내용)이고, 사이드바의 보기 전환 메뉴(개요·설정집·관계도·시간선·소설 연결 다섯 개, 기본 보기는 설정집이라 `?view=`가 없거나 모르는 값이면 설정집이고 나머지는 주소 `?view=overview|people|timeline|novel`로 유지·복원, 보기 이동은 같은 화면 이동이라 미저장 변경을 잃지 않고 이탈 확인도 하지 않는다. 메뉴를 누르면 누른 버튼을 가로 줄 안에 보이게 하고 바뀐 내용 카드 머리로 스크롤하되 처음 열 때·같은 메뉴를 다시 누를 때는 하지 않고 초점은 누른 버튼에 남는다. 게시판·관계 편집기·(한 번 연) 개요 폼은 다른 보기에서도 숨길 뿐 지우지 않아 필터·선택·적용하지 않은 관계 입력·쓰던 이름과 고른 표지 파일이 남는다)와 그 아래 구분선 뒤의 `AI 검토` 버튼(이름에 설정집 검토 의견 수·후보 대기 수가 붙는다, 예 `AI 검토 · 의견 5 · 후보 2`, 시트 맨 위 '설정집 검토'(OpenAI 전송 동의 → `설정집 검토 요청` → `POST `자세히`에 경고마다, `groupOrderIssues`). 고른 화면은 주소 `?card=<id>&pane=overview|doc|relations|versions|order`가 정본이다(문서는 기본이라 `pane`이 없고, 바꿀 때 기록을 쌓지 않으며 다른 카드로 옮겨도 유지되고 카드를 닫으면 함께 지운다. `vm.pane`·`vm.setPane`). 이름 입력은 모든 화면 위에 고정이고(개요는 큰 제목, 나머지는 작은 제목) 공개 순서 문제가 있으면 이름 아래 `공개 순서 확인 N` 배지가 공개 순서 화면으로 간다. 하단 바(글자 수·카드 삭제)는 모든 화면 공통이다. 저장 영역은 바뀐 것이 있으면 '저장하지 않은 변경 있음'과 세계관 저장 버튼(저장 전 확인 문제가 있으면 첫 사유·건수를 버튼 옆에 알리고 저장을 막는다. 사유에는 어느 설정인지 이름이 붙고(`writingIssueLabel`) 누르면 그 설정의 편집 화면으로 간다(`vm.openIssue`)), 없으면 '저장됨'뿐이고(잠긴 버튼을 따로 그리지 않는다) 저장 버전이 0이면 바꾼 것이 없어도 첫 저장 버튼이 있다. 관리 모드의 '개요' 탭(`WorldInfoPanel`)이 세계관 정보 편집 폼(이름·설명·공개 범위·장르·표지, 맨 앞에 지금 표지, 맨 아래 `.ep-delete` 구획의 세계관 삭제)을 보인다: 탭 본문이라 열어도 입력으로 초점을 옮기지 않고 Esc로 닫히지도 않으며, 저장해도 탭은 그대로 두고 '저장했어요.'를 알리고(고치면 사라짐) `되돌리기`가 바뀐 입력·고른 표지를 저장값으로 되돌린다(바뀐 것이 없으면 잠김). 저장은 바뀐 것만 이름·설명(기존 초안 저장) → 공개 범위·장르(`PUT /api/v1/world-studios/{id}/publication`, Content, 세계관 단위, 비공개에서 공개로 바꿀 때만 저장 시점에 확인) → 표지 순으로 보내고, 하나라도 실패하면 오류와 입력을 그대로 둔다(헤더에는 공개 범위·장르 칩만 있고 편집 버튼은 없다). 저장하지 않은 수정이나 저장 전 확인 항목이 있으면(`vm.infoLocked`) 폼의 저장은 이름·설명을 바꿨을 때만 '작성 중인 변경을 먼저 저장하세요'로 잠긴다(그 수정이 이름·설명 저장에 딸려 가지 않게, 공개 범위·장르·표지만 바꾸는 저장은 막지 않는다). 공개 목록에 나오는지는 저장한 세계관의 확정 버전 유무로 판정한다(`worldPublication.listingOf`): 공개이고 확정 버전이 있으면 헤더에 '공개 화면 보기'(`/worlds/:id`, 미리보기를 겸한다)가, 공개인데 확정 버전이 없으면 링크 대신 '저장한 뒤 확정 버전 남기기로 확정 버전을 한 번 남기면 나타난다'는 안내가 보이고 확정 버전을 남기면 저절로 사라진다. `--mode mockup`은 메모리에만 반영해 링크 없이 데모 안내를 띄운다. 표지는 PNG·JPEG·WebP 5 MiB 이하를 고르는 순간 검사하고 저장하면 `PUT /api/v1/world-studios/{id}/cover`(multipart)로 올리며(교체 포함, 삭제는 확인 뒤 `DELETE`, 소유자 화면은 Bearer로 읽은 이미지를 객체 주소로 보이고 해제한다) 'AI로 생성'은 준비 중으로 잠그고 표지 저장소가 없는 데모는 지원하지 않는다고 알린다. 공개 화면(`/worlds` 카드·상세)은 `hasCover`이면 공개 cover 주소(`/api/v1/public/world-studios/{id}/cover`)를 `<img>`로 쓰고 없으면 기본 표지(`/default-work-cover.svg`)를 쓴다. 설정집 보기(작성 모드는 설정 카드 단계)는 공개 설정집과 같은 게시판으로, 왼쪽 분류 메뉴 + 오른쪽 검색·정렬·결과 수·`다른 세계관에서 가져오기`(가져오기 시트)·`+ 새 설정`(유형 8가지를 고르면 그 유형의 카드를 초안에 더하고 편집 화면을 연다) 도구줄 위 / 공개 범위 일괄 줄(접힌 `공개 범위 한 번에 바꾸기` 한 줄이고 행을 고르면 펼쳐진다: `선택 공개`·`선택 비공개`·`전체 공개`) / 표(선택·번호·분류·제목·상태·요약·공개·연결 8칸) 아래이고 표는 공개 범위 말고는 보기만 한다(제목·행을 누르면 그 줄 바로 아래에 미리보기가 열리고(한 번에 하나, 열릴 때 그 구획이 화면 안에 들어오게 가장 가까운 만큼만 스크롤, 편집 화면에 다녀와도 열린 채, 닫으면·Esc로 제목으로 초점) 미리보기의 `수정하기`가 편집 화면을 연다. 미리보기는 공개 카드 페이지와 같은 위키 모양이다: `WorldCardPreview`가 지금 초안의 그 카드를 공용 `shared/cardWiki`(정보 상자 `WikiInfoBox`·번호 목차·접이식 문단, 문단 트리는 `cardWikiSections.wikiSections`)로 그린다. 정보 상자는 유형·설정 영역·내 분류(편집 화면 개요의 두 분류 칸)·별칭·공개 범위(`작가 전용`·`17화부터 공개`)·관계(인물)/연결 수·태그·대표 이미지이고, 이어서 카드별 관계도(`CardRelationMap`: 간단 목록·접힌 `함께한 사건 N`)·번호 목차·첫머리와 접이식 본문 문단·접힌 `관계 자세히 보기 (N)`(이 카드를 끝점으로 하는 승인된 관계마다 `상대 — 관계 이름` 문단)다. 공개로 거르지 않아 작가 전용 카드도 그대로 보이고, 본문의 설정 링크·관계도 이웃·관계 문단의 상대는 그 카드의 편집 화면을 열며(편집기는 미리보기 탭으로 시작), 높이는 CSS가 제한해 긴 문서는 안에서 스크롤한다. 아래에 `수정하기`·`공개 화면 보기`(공개된 설정이고 세계관이 공개 목록에 있을 때만 새 탭 링크)·`닫기`가 있다. **상태 칸**은 `정리 필요`·`연결 필요`·`공개 순서 N`·`AI 의견 N` 칩을 모으고(없으면 —, 제목 옆에는 두지 않는다) 칩을 누르면 미리보기를 거치지 않고 그 카드의 편집 화면이 칩에 맞는 활동 막대 탭(정리 필요·AI 의견은 문서, 연결 필요는 관계, 공개 순서는 공개 순서, 주소 `?card=<id>&pane=`)으로 열린다. 정렬에 `보완 필요 많은 순`(네 칩을 센 수가 많은 카드부터, 같은 수는 설정집 순서)이 있다. 선택 체크박스·상태 칩은 미리보기를 열지 않는다. 760px 이하 본문은 상태 칸이 숨고 같은 칩이 제목 아래 한 줄(`.world-row-status`)로 보인다. 600px 미만 본문은 분류·연결 칸을 숨기고 제목 아래 한 줄로 보이며 600px부터 요약 칸이 돌아와 분류·제목·요약·공개·연결이 한 줄 행이다(상태 칸은 761px부터). 숨기는 칸은 `display:none`이 아니라 폭 0의 보이지 않는 칸으로 남아(열 수가 늘 8개라 미리보기 줄 `colSpan=8`을 열고 닫아도 열 폭이 그대로다) 제목 열은 26%이고, 분류 칩 줄로 바뀌는 기준은 이 화면에서만 게시판 폭 1000px 이하다(공용 게시판은 760px 그대로). 삭제는 편집 화면에서만, 카드가 없으면 안내는 표 안 한 줄뿐. 공개 설정집 `/worlds/:id`의 행 동작은 그대로다). 삭제는 유형과 상관없이 초안 변경이라 이어진 관계 수를 확인한 뒤 함께 지우고(다른 설정이 아직 참조하면 막는다) 설정집 화면으로 돌아와 `되돌리기` 알림을 보이며, 세계관 저장으로 서버에 반영한다. 화면 오른쪽에는 설정집 화면·편집 화면·단계와 무관하게 늘 집필실과 같은 공용 `ChatPanel`의 AI 채팅 레일이 있다(설정집 화면은 본문 | 채팅 2열에 채팅 350px 고정·화면 높이를 쓰는 sticky로 상단바가 없어 화면 맨 위부터(상단바가 있는 작성 모드는 그 아래), 편집 화면은 집필실과 같은 3단의 오른쪽 열이되 면은 설정집 화면 채팅과 같은 주변 배경 `--tbg`다(`world-studio.css`가 `.writing-studio.world-card-studio .writing-chat`의 `--chat-bg`만 덮어쓰고 집필실 `writing.css`는 고치지 않는다), 접기·열기, 전송이 잠긴 동안 1200px 이하에서는 닫힌 채로 시작하고 설정집 화면은 900px 이하에서 열면 뒤 화면을 막는 대화 상자 서랍(공용 `Sheet`, Esc·배경으로 닫힘, 닫힌 열기 버튼은 그 폭에서 떠 있는 대신 보기 메뉴 줄의 오른쪽 끝에 놓인다)이며 편집 화면은 그 폭에서 편집기 아래 영역이다, 채팅은 집필실과 같은 공용 `shared/chat/WritingChat`(집필 AI, 아래)이며 세계관에 연결된 소설(`linkedWorkId`)의 대화와 그 소설의 가장 뒤 발행 회차를 근거로 쓰고(`worldstudio/viewmodel/useLinkedWorkBasis`), 연결 소설이 없으면 사유와 함께 잠기며 가짜 응답은 없다). 관계도 보기(작성 모드는 관계 연결 단계, 주소 값은 그대로 `?view=people`)는 **옵시디언 그래프 뷰처럼 점과 이름뿐인 캔버스**다: 관계는 캔버스에서만 만들고 고치며 캔버스 아래에는 관계 추가 폼도 관계 목록 표도 없다(중심 카드 보기·이웃 쪽 이동·`전체 관계도로`도 없고 모든 설정을 한 그래프에 그린다. 저장 흐름은 그대로여서 모든 변경은 초안이고 세계관 저장으로만 서버에 간다). **그래프는 `react-force-graph-2d` 캔버스다**(production 의존성으로 /worlds의 지도·상세 그래프와 같은 라이브러리이고 `worlds/worldAtlas.ts`의 `aspectGravity`·`CANVAS_FONT`를 가져다 쓴다. `RelationGraph.tsx` 한 파일이 import하고 물리는 react-force-graph 안의 `d3-force-3d`가 돌린다):
- **모양**: 점은 이어진 관계 수(묶기 전 관계 한 줄마다 센다)의 제곱근에 비례해 반지름 4~18(크기 슬라이더 배수)의 채운 원(유형 색), 선은 가는 회색 직선이고 같은 두 설정 사이의 관계는 선 하나로 묶인다(`viewmodel/graphModel.ts`의 `buildGraph`: 관계마다 자기 방향을 남기고 선은 방향 있는 관계가 하나라도 있으면 방향 있다). 선 굵기는 확대 배율과 상관없이 화면 1px(설정의 배수, 올린·고른 선은 1.8배·강조색)이고 화살표는 설정 패널에서 켤 때만 방향 있는 선에 목적지 노드 가장자리 앞에 그린다. 배경은 평평한 한 색(격자·그라데이션 없음)이고 모든 확대 배율에서 점과 이름뿐이다(카드 모양 단계는 없다).
- **배치**: 힘 시뮬레이션이 실시간으로 돈다(끄는 노드를 이웃이 따라오고 놓으면 고정이 풀리며 식으면 멈춘다, `prefers-reduced-motion`이면 한 번에 계산해 멈춘다). 중심력(가로세로비를 따르는 중력)·반발력·연결 힘·연결 거리는 설정 패널의 슬라이더(기본값 중심 0.5·반발 6·연결 힘 0.7·거리 60은 옵시디언 기본 비율을 홍길동전 57노드·146관계 모양으로 맞춘 값이고 `viewmodel/graphForces.ts`가 슬라이더 값을 d3 힘의 세기로 바꾼다)이며 바꾸면 시뮬레이션을 다시 데운다. 겹침은 이름표 상자를 포함한 우리 사각형 충돌 힘(`labelCollide`)이 풀고 이어지지 않은 설정(외톨이)은 약한 중력이 붙잡는다. 좌표는 화면 상태일 뿐 저장하지 않고 설정이 바뀌어 그래프를 다시 만들어도 같은 설정은 같은 객체라 배치를 잇는다. 첫 화면은 첫 틱에 곧바로 전체를 맞추고(`zoomToFit`, 무리 가운데) 배치가 처음 멈출 때 한 번 더 맞추되 그 사이 사용자가 휠·눌러 움직였으면 두며 `배치 정돈`은 중심 나선에서 다시 펼친다.
- **이름**: 노드 바로 아래 화면 4px에 12px 이상(관계가 많으면 13·14px)으로 어느 배율에서나 그린다(`view/graphPaint.ts`). 텍스트 표시 임계값(기본 0.7)보다 멀리 가면 서서히 사라지고 관계 상위 8~12개 이름만 남으며(`view/graphPaint.ts`의 `labelPlan`, 확대 배율은 `viewmodel/graphModel.ts`의 `textAlpha`) 이름표 상자끼리 겹치면 관계가 적은 노드부터 숨긴다(`viewmodel/labelLayout.ts`의 `placeLabels`: 다른 점은 가려도 된다. 강조 중에도 같고 강조 중심·고른 노드·연결 주체는 겹쳐도 보인다). 선 위 관계 이름은 올린 선·키보드 초점이 간 관계의 선·관계 작성 중인 선에만 선 가운데에 그린다.

JSON은 `schemaVersion` 하나와 카드(id·type·title·aliases·tags·text·revealFromEpisode)·관계(id·source·target·name·description·fromEpisode), Markdown은 세계관 제목·설명 아래 유형별 `## 인물` → 카드마다 `### 이름`·본문(카드 링크는 글자만)·`- 상대 — 관계명 (N화부터)`(들어오는 관계는 `- ← 상대`)이다(`viewmodel/worldExport.ts`). **한계**: 내보낸 파일을 다시 가져오는 기능은 없다(JSON은 보관용이다). 양 끝 카드가 없는 관계는 내보내지 않는다.

`cardRelations.css`)를 쓴다. 입력은 순수 데이터(`RelationEntry`: 상대 카드·유형·관계 이름 이력 `steps`(이름·회차·본문 `body`))이고 어댑터가 만든다: 작가 `worldstudio/viewmodel/cardRelationEntries.ts`(이 카드를 끝점으로 하는 승인된 관계의 짧은 이름(`domain`의 `relationShortName`: 서버에서 읽은 자유 관계는 항목 이름(label)이 관계 이름이고 본문(text)은 설명이라 본문 문장이 이름으로 나오지 않는다 — 전체 관계도의 이름·내보내기·시간선 참여 판정도 같다)·본문·시작 회차 `fromEpisode`와 관련 설정·앞뒤 사건·본문 링크로 이어진 카드), 공개 `worlds/cardRelationEntries.ts`(`CardPage.relations`와 관계 id가 있는 `backlinks`, `history`는 `relationName`으로 이름을 맞춘다. 본문은 싣지 않는다: 카드 페이지의 관계 문단과 겹친다). 그림은 물리 없는 고정 좌표 SVG(`aria-hidden`, 좌우 이웃의 이름이 상자 밖으로 잘리지 않고(왼쪽 이웃은 end·오른쪽은 start 맞춤, 길면 말줄임) 선은 1px)이고 **글자는 어느 화면에서도 축소되지 않는다**: `CardRelationMap`이 상자 폭을 재서(`useElementSize`) viewBox 가로를 그 화면 px 그대로(최대 640, 1:1) 그리므로 이웃 이름 12px·선 이름 11px이 CSS 크기 그대로 보이고, 좁으면 둘레 반지름과 둘레 이웃 수를 줄인다(`cardRelations.mapGeometry`: 306px이면 8명, 가운데 글은 둘레 점 안쪽 폭으로 말줄임·선 이름은 가운데 글을 피해 숨김, 폭을 모르면 640×360). 가운데 카드(유형 색 원·이름·공개 배지)와 사건이 아닌 이웃 최대 16개(관계 수·바뀐 횟수 많은 순으로 뽑아 유형별로 모음, 인물 먼저)이고 넘치면 `외 N개는 아래 목록에서`, 같은 상대의 여러 관계는 선 하나이고 선 위 글자는 가장 늦은 회차의 관계 이름뿐이며(8자 넘으면 말줄임, 선의 바깥쪽 65% 지점에 놓고 겹치면 숨긴다 — 목록에 모두 있다), 이웃·선의 말풍선은 `상대 — 이름 외 N · 이력(경계(1화) → 보호(3화))`과 본문 앞부분이다. 사건은 `함께한 사건 N`(회차순, 접힘). 회차 탭(`role=tablist`, ←→·Home·End)은 관계가 생기거나 바뀌는 회차(앞 6개 + `더보기`)이고 N화 탭은 그 시점까지의 관계만 보이는 화면 필터이며, 작가 화면은 가운데 카드의 공개 회차보다 앞선 탭에 `숨김`(독자에게 숨김)을 단다. 이웃을 누르면 작가는 그 카드의 편집 화면(`openLinked`, 버튼), 공개는 그 카드 페이지(링크)로 간다. 아래 간단 목록(`상대 — 관계 이름 · N화부터 · 외 N`, 50개씩 쪽, 이름 위주 이력과 관계 본문 문장은 줄의 `자세히`를 펼칠 때만)이 키보드·낭독기 경로이고 이웃이 없으면 `아직 연결된 설정이 없어요`(작가 화면은 `관계 추가`)다. **작가 편집 화면**: 관계 탭(활동 막대의 그래프 아이콘, 배지=관계 수)의 머리 줄이 `연관 설정·관계 관계 N`과 `관계 편집`(모든 유형, 기존 `openRelations`)이고 그 아래 전체 폭 관계도·회차 탭과 관계 종류별 묶음 목록(`CardRelationMap`의 `quietKinds`: 의미 있는 종류가 위에 열려 있고 `알고 있음 (N)` 같은 조용한 종류는 기본 접힘, 묶음마다 50개씩 쪽)이다. 공개 안내는 개요 탭 공개 범위 제목 옆 배지 한 개(`3화부터 공개`·`작가 전용`·미연결 1화는 `공개`)와 관계도의 회차 탭으로 모았으며 '공개 순서 확인'(`WorldCardOrder`)은 공개 순서 탭에서 카드별 한 줄로 묶어 보이고(문제가 없으면 개요 공개 범위 칸의 한 줄 `공개 순서 문제 없음`) 문서 탭 이름 아래에는 문제가 있을 때만 `공개 순서 확인 N` 배지가 있다. **공개 카드 페이지**: 정보 상자 아래에 관계도가 있고 긴 관계 문단은 지우지 않고 `관계 자세히 보기 (N)` 한 묶음으로 기본 접혀 있으며 목차·앵커(`#rel-…`) 이동(`jumpTo`)이 묶음을 펼친다(DEC-54). 독자 설정 위키(`/work/:id/wiki`)는 손대지 않았다.

**캔버스 위는 한 줄뿐이다**: 관계 기준 회차 줄이고(알림이 있을 때만 `.relationship-bar` 한 줄이 더 생긴다: `삭제된 설정과 이어진 관계 N개는 저장 시 그대로 유지돼요`·`삭제 되돌리기`) 캔버스 위쪽에는 겹치는 것이 없다. 안내문은 캔버스 아래 가운데에 겹친 작은 글(`.relationship-notes`: 연결 취소 버튼만 누를 관계 기준 회차 칸은 편집기가 다시 열려도 초점이 남도록 편집기 바깥에 있다. 관리 모드(`/worldstudio/:id`)에는 푸터가 없다(작성 모드·만들기 화면은 그대로).** 관계 작성 패널은 가운데에 뜨는 시트(720px, `Sheet`, 첫 입력으로 초점, 실제 관계 문구는 여러 줄 칸, Esc·닫기·배경은 적용하지 않은 입력이 있으면 확인한 뒤 닫고 닫으면 열기 전의 초점으로 돌아간다)이며, 관계는 회차별로 기록하므로(DEC-51, [계약](../docs/design/worldstudio-independent-schema.md#회차별-관계--dec-51)) 관계 편집 행(작성 창)에 `[ ]화부터` 입력이 있어 관계마다 그 내용이 보이기 시작하는 회차를 정하고('이 회차의 기록으로 저장해요' 필요` 필터와 빈 영역 `비어 있음`이 있다. 원고로 세계관을 만들거나 업데이트할 때 이름이 같은 카드가 둘 이상이라 서버가 `semanticMetadata.manuscriptBuild.needsReview: true`로 남긴 카드(어댑터가 true일 때만 카드의 `needsReview`로 읽고, 저장 때 `studio`에 쓰지 않으며 `manuscriptBuild`는 서버 메타데이터로 그대로 돌려보낸다)는 같은 `상태` 칸에 `확인 필요` 칩(눌러 문서 탭으로 연다)이 붙고 편집 화면 설정 카드 목록 패널의 항목(읽는 이름 `… 확인 필요`)에도 칩이 붙는다(`cardStatuses`가 아니라 카드의 `needsReview`로 그려 `보완 필요` 필터·건수에는 넣지 않고, 칩을 끄는 작가 동작은 계약에 없다). 편집 화면은 그 카드의 지적과 수정안(`수정안 보기` → `초안에 반영`·`반영하지 않기`)을 보이고, 반영은 편집 초안의 그 칸만 바꿔 세계관 저장으로 서버에 보내며 검토 뒤 그 칸이 바뀌었으면 잠근다. 편집기 아래에는 '공개 순서 확인' 절(`WorldCardOrder`)이 그 카드의 어느 글(본문·링크 글자·관계 문구)에 어떤 이름이 나오는지 알리고 이름이 나온 카드로 옮겨 갈 수 있으며 저장·확정은 막지 않는다(모델 없이 초안에서 계산한다, `publicationOrderIssues`). 관계 글이 독자에게 보이는 회차는 `max(두 끝 설정의 공개 회차, min(관계의 기록 회차, 기록된 시작 회차))`로 계산하고(기록 회차는 행의 `[ ]화부터`, 없으면 1화, 늦춘 값은 기록된 시작 회차를 따른다, [계약](../docs/design/world-review-contract.md#공개-순서-규칙--dec-53)) 본문과 같은 문구('이 글은 N화부터 독자에게 보여요')로 알린다. AI 후보 검토 시트는 상태 필터 칩(검토 대기·승인·거절, 보류는 검토 대기에 든다)과 후보 카드(승인·거절·보류(보조 스타일)·내용 수정, 근거는 `근거 보기`)·`승인한 후보 N개 초안에 반영` 고정 바로 한 장씩 넘겨 본다. 게시판 규칙(분류·정렬·번호)은 `presentation/shared/worldBoard.ts`를 두 화면이 함께 쓴다. 관리 화면의 게시판은 뷰포트가 아니라 자기 폭(컨테이너 `worlds-board`, 760px 이하)으로 좁은 배치를 고르고(공개 설정집은 뷰포트 720px 규칙 그대로) 그때 숨는 분류·요약을 제목 아래 한 줄로 보이며, 일괄 공개·비공개 뒤에는 결과를 상태 문구로 알리고 초점을 표 머리 체크박스로 옮긴다. 본문 편집기(`shared/MarkdownEditor`)에서 Tab은 들여쓰기이고 Esc 다음 Tab으로 벗어나며(안내 한 줄) 쓰기·미리보기 탭은 ←→·Enter·Space로 바꾼다. 카드 본문(인물은 IDENTITY.md) 편집기에는 편집기 바로 위 줄에 `설정 링크` 버튼이 있어(`cardLinks`, Toast 도구 줄은 좁으면 끝 항목을 더보기로 숨기므로 도구 줄 밖에 둔다) 그 아래에 같은 세계관 카드를 이름·별칭으로 찾는 패널을 열고 고르면 선택한 글자(없으면 제목)로 `[글자](card:<id>)`를 커서 위치에 넣으며, 미리보기의 링크를 누르면 그 카드의 편집 화면으로 간다(Toast의 sanitizer가 `card:` 주소를 지워 링크 렌더러가 해시 주소·data 속성으로 바꾼다). 링크로 그리는 것은 원문(`CardMarkdown`은 `position`, 미리보기는 `sourcepos`)이 공유 정규식에 맞는 것뿐이고 `<card:id>`·제목이 붙은 링크 같은 모양은 글자만 보인다. 인라인 `[[` 자동완성은 없다. 편집 화면의 연관 설정에는 본문 링크로 이어진 카드도 들어가고 게시판 연결 수에 센다. 자유 관계의 긴 문구(관계 본문 전체)는 제목과 한 줄에 안 들어가면 제목 아래 줄로 내려 줄바꿈한다. 삭제 확인은 열릴 때 초점·스크롤이 가고 닫히면 연 버튼으로 돌아온다. **설정 카드 공개·가져오기·소설 연결(DEC-46·53, [계약](../docs/design/public-world-contract.md#카드-공개-기준-일원화--dec-53))**: 설정 카드의 공개 설정은 하나다('N화부터 공개' 또는 '작가 전용', 기본은 작가 전용, #485 2단계). 화면은 `revealFromEpisode`만 정하고 `visibility`는 회차가 있으면 public, 없으면 지워 맞춘다(`worldstudio/viewmodel/cardVisibility.ts`의 `setCardReveal`, 유효 공개 회차는 `domain/entities/studioWorld.ts`의 `cardRevealEpisode`: 회차 값, 없고 `visibility`가 공개면 1화, 그 밖은 작가 전용). 건드리지 않은 카드(옛 공개 카드·회차 값만 있는 카드)는 다시 쓰지 않고, 키가 있는데 값이 잘못된(JSON `null` 포함) 카드는 서버처럼 작가 전용으로 읽어(`HttpWorldStudioRepository`가 그 카드의 `visibility`를 가져오지 않는다) 저장하면 비공개로 맞춘다. 편집 화면의 `공개 범위`는 소설이 연결된 세계관(`linkedWorkId`)이면 `공개 회차 [ ]화부터 공개`(숫자만 받는 글자 칸, 비우면 작가 전용, 1 이상의 정수가 아니면 입력 아래에 이유를 보이며 저장 전 확인과 `WorldStudioUseCase.save`가 같은 문구로 막는다) 입력 하나만, 연결되지 않은 세계관·데모는 `이 설정 공개` 스위치(공개 = 1화부터) 하나만 보인다. 게시판의 `공개` 칸은 `N화부터`·`작가 전용`(미연결 1화는 `공개`)을 보이고(`revealLabel`), `선택 공개`·`전체 공개`는 소설이 연결된 세계관이면 `일괄 공개 회차`를 한 번 입력받아(기본 1화) 고른 카드 모두에 같은 `N화부터 공개`를 정하며 미연결 세계관은 `공개`(1화)다(`setCardReveal`·`publishAllCards(settings, episode)`, 0·빈 값은 이유를 알리고 공개 버튼만 잠근다). 공개(로 고른) 세계관인데 초안에 공개된 카드가 없으면 `PublicCardsNotice`가 경고와 `전체 공개`(1화부터)를 관리 헤더·개요 탭 폼·작성 모드 공개 설정에 보이되 공개 설정 저장은 막지 않는다. 카드 공개 설정·가져온 카드는 모두 초안 값이라 세계관 저장과 `확정 버전 남기기`를 거쳐야 공개 세계관 화면·독자 설정 위키에 반영되며 화면은 그 사실을 도움말로 알린다. 공개 기준 필터는 서버가 하므로 화면에서 거르는 코드를 두지 않는다. 설정 가져오기(`WorldImportSheet`)는 서버 API 없이 `PublicWorldUseCase`로 읽은 공개 세계관의 공개 카드를 공용 `presentation/shared/importCards.ts`(`importCards`·`appendImported`·`importableWorlds`, 공개 세계관 화면의 바로 추가와 함께 쓴다)로 새 id의 비공개 카드로 복사하고 출처(`importedFrom{worldId, worldName, authorNickname, revisionNo, cardId}`)를 기록한다: 대상 세계관 자신은 목록에서 빼고, 관계는 양 끝을 모두 가져온 것만 사용자 정의 방향 관계로 옮기며(공개 상세가 이름만 준다), 본문 링크는 같이 가져온 카드끼리만 새 카드 id로 다시 잇고 나머지는 글자로 바꾸고, 활성 카드 1,000개 한도를 넘기면 아무것도 더하지 않는다. 시트는 게시판의 `다른 세계관에서 가져오기`로만 열고 늘 세계관 고르기부터 시작한다(주소 `?import=`로 여는 길은 없앴다). 시트의 공개 세계관 조회는 `viewmodel/useWorldImport.ts`, 소설 연결의 조회·연결은 `viewmodel/useWorldNovelLink.ts`가 맡는다(View는 `appContainer`를 부르지 않는다). 가져온 카드는 게시판 행과 편집 화면에 `가져옴`과 `참고: {세계관 이름} 세계관 · {작가}`를 보인다. 서버 매핑(`HttpWorldStudioRepository`)은 카드 `visibility`를 행 값으로 보내고, `revealFromEpisode`·`importedFrom`·`characterDocs`·`imageId`는 카드 `semanticMetadata`의 **최상위 키**에 행 필드를 정본으로 둔다(`semanticMetadata.studio` 안에 넣지 않고 값이 없으면 키를 넣지 않으며, 읽을 때 어긋난 값은 버리되 세계관 로드를 실패시키지 않는다). **카드 대표 이미지**(#401): 편집 화면 머리 오른쪽의 큰 타일(세계관 헤더 표지와 같은 `.cov`, 이미지가 없으면 점선 빈 타일 전체가 `이미지 추가`, 있으면 이미지 + 아래 `바꾸기`·`빼기`, 머리 폭 460px 미만(컨테이너 쿼리)은 88px 타일을 이름 아래로)의 `이미지 추가`·`바꾸기`가 고른 파일(PNG·JPEG·WebP 5 MiB 이하)을 곧바로 `POST /world-studios/{id}/card-images`(`WorldStudioUseCase.uploadCardImage`)로 올려 초안 카드의 `imageId`만 새 id로 바꾸고(저장 전 수정, 저장과 `확정 버전 남기기`를 거쳐야 공개 화면에 나옴, 실패는 서버 이유 그대로), `빼기`는 서버 호출 없이 키만 지운다. 소유자 이미지는 인증 읽기를 `useCardImages`가 imageId마다 한 번만 읽어 객체 주소로 바꿔 게시판·레일 썸네일과 미리보기가 나눠 쓰고 바꾸기·빼기·화면 이탈 때 해제한다. 설정 가져오기는 이미지를 복사하지 않고(`importCards`가 `imageId`를 옮기지 않음), 카드 이미지 저장소가 없는 데모(`--mode mockup`)는 올리기를 잠그고 발표용 인물 초상만 보인다.  인물 카드는 문서 네 종류로만 쓴다(DEC-47): `IDENTITY.md`가 카드 본문(`item.text`)이고 `SOUL.md`·`GOAL.md`·`memory/NN회차.md`는 `StudioSetting.characterDocs{soul, goal, episodes}`(작가용, 공개 응답에 없음)다. `MEMORY.md`는 없앴고, 서버의 옛 `memory` 값은 읽을 때 `migrateCharacterDocs`가 00회차 앞에 빈 줄로 이어 붙이며(공백뿐이면 빈 것) 저장에는 `memory` 키를 쓰지 않는다. `MEMORY.md` 파일 불러오기는 00회차로 받는다. 문서 이름·빠진 필수 문서(IDENTITY·SOUL, `정리 필요`이자 시뮬레이션 참여 인물 잠금의 기준, 저장을 막지 않음. 목표는 선택이라 탭 이름이 '목표 · 선택'이고 비어도 알리지 않는다)·저장을 막는 문구(문서마다 3,000자, 회차 번호 0 이상의 정수)·파일 이름 해석은 `domain/entities/characterDocs.ts`의 순수 함수가 정하고 `worldstudio/viewmodel/useCharacterDocs.ts`·`view/CharacterDocs.tsx`가 화면을 맡으며, 전부 비었거나 인물이 아닌 카드에는 `characterDocs` 키를 넣지 않는다. 화면 테스트의 편집기 대역(`test/markdownEditorFake`)은 인물 문서를 파일 이름(`IDENTITY.md` 등)으로, 그 밖의 카드는 `설명`으로 찾고, 편집기마다 받은 `cardLinks`를 `LazyMarkdownEditor.cardLinks`(label별)에 남긴다. 연결된 소설(`WorldLinkedWork.tsx`)은 관리 모드에서는 헤더가 아니라 '소설 연결' 탭(`WorldNovelTab`: 제목 `연결된 소설` 아래 원작 행(제목 + `원작`, Fork 행과 같은 모양으로 `/work/<id>`로 가는 링크, 제목을 읽는 중·못 읽음은 그렇게 알리는 글)·소설 버튼 한 자리와 `Fork 소설 N편` 목록)에 있고, 작성 모드(마법사) 헤더는 지금처럼 두 조각이다: 상태 줄 `WorldLinkedLine`은 정보만(`연결된 소설: {제목}` / `연결된 소설이 없어요.` / 확인 중·제목 읽기 실패 안내) 보이고 링크·버튼을 두지 않으며, 행동 줄의 `WorldNovelButton`이 소설 버튼 **한 자리**를 맡는다(연결돼 있으면 `/content?work=<id>`로 가는 `소설 작성하기`, 없으면 같은 자리의 `소설 연결하기` → 내 소설 중 `worldStudioId`가 없는 것만 고르는 시트 → `episodeUseCase.linkWorldStudio`로 초안 저장과 별개로 바로 연결, 실패는 서버 문구, 연결되면 같은 자리가 `소설 작성하기`로 바뀌고 초점도 옮긴다). 같은 곳으로 가는 링크를 두 개 두지 않는다. 시트의 `새 소설 만들기`는 작품 만들기(`/content`)로 갈 뿐 만든 소설을 자동으로 연결하지 않고, 해제는 작품 관리 화면이 맡는다. `--mode mockup`은 상태 줄 없이 `소설 작성하기`(→ `/new`)만 두고 독자 공개 회차 입력을 잠근다. Fork 목록은 연결된 소설에서 갈라진 **공개 Fork만**(숨김·비공개가 아니고 자체 회차가 1개 이상, `ReadingUseCase.forksOf` = 소설 상세·`/ifs`·회차별 포크 수와 같은 목록, 새 API 없음)이고 행은 그 Fork 소설(`/work/<id>`)로 가며 보조 글에 작가·N화에서 분기·자체 M화를 적는다(같은 목록이 이 탭에 다 보여 모아 보기 링크는 두지 않는다). 0편이면 그 기준을 문구로 알리고 읽지 못하면 `다시 시도`를 보인다(빈 목록으로 채우지 않는다). 소설 목록·Fork 목록은 탭을 열 때만 읽고 mockup은 Fork를 그리지 않는다.

`/worlds/:id` 공개 상세 규칙: 그래프는 카드·관계선을 페이지로 나누지 않고 한 캔버스에 모두 그리며 `설정 찾기` 하나로 최대 8개 후보를 키보드로 골라 강조한다. 개요는 줄바꿈을 보존한 설명, 유형별 수의 설정집 링크, 관계 수 기준 주요 설정(관계가 없으면 설정집 순서), 세 탭 둘러보기, 기존 정보 상자와 관계 수를 응답 데이터만으로 보이고, 관계 0개와 `relationshipStatus: unavailable`은 서로 다르게 알린다.

집필실과 세계관 관리 화면의 AI 채팅(#331)은 공용 `presentation/shared/chat/WritingChat`·`useWritingChatViewModel` → `WritingChatUseCase` → `HttpWritingChatRepository`로 Content `/api/v1/works/{id}/chat/sessions…`를 쓴다. 대화 원본은 AI의 LangGraph 체크포인터이며 화면은 저장하지 않는다. 전송은 fetch 스트림으로 SSE(`plan`·`started`·`answer`·`step`·`waiting`·`done`·`error`)를 읽어 쓰는 중인 답변 본문(`answer`, `domain/entities/writingChat.streamedAnswer`: `null`·실패면 비우고 조각마다 읽어 주지 않게 `aria-live=off`, 맨 아래에서 읽을 때만 따라 스크롤, #618)과 단계 진행을 그리고(병렬 호출(#474)로 `started`가 여러 개 겹칠 수 있어 결과 `step`이 오기 전의 기능은 모두 진행 중으로 보인다), 끝나거나 실패하면 이력을 다시 읽어 저장된 상태를 그대로 보인다(`done` 없이 끊기면 실패로 알린다). 보내기를 누르면 요청은 진행 중 말풍선에 보이고 입력창은 즉시 빈다. 전송이 실패하면 기다리는 동안 새로 입력한 내용이 없을 때만 요청을 입력창에 복구한다(#591). 승인·입력 대기(`waiting`)는 대화 끝의 카드에서 `초안에 반영`·`반영하지 않기` 또는 빠진 입력(고증 질문·장면 계획)을 채워 resume하고(입력 카드도 같은 턴에 끝난 작업을 보이며 취소 안내는 `cancelNotice`, #661), 승인 전에는 원고가 바뀌지 않는다. World `enrich` 제안(`awaitingApproval: world`)은 같은 카드가 `설정집 초안에 반영`·`반영하지 않기`로 묻고, 세계관 관리 화면은 반영이 끝나면 저장하지 않은 변경이 없을 때만 초안을 다시 읽고 있으면 덮어쓰지 않고 안내만 한다(#546, [계약](../docs/design/world-review-contract.md#world-agent-채팅-작업-546291-2026-11-19-사용자-결정)). 대화 고르기·새 대화·제목 바꾸기(대기 중 잠김)·삭제, 메시지 `수정`(그 뒤 대화를 지우고 다시 실행)·`여기부터 지우기`를 제공한다. **화면 맥락(#554, DEC-59)**: 새 메시지(보내기·수정해 다시 보내기)마다 요청의 `page`에 지금 보는 화면을 싣는다(승인·입력·장면 조작 같은 이어가기에는 싣지 않는다). 조립은 `domain/entities/writingChat.chatPage`(경로 300자·선택한 글 5,000자 이하만(넘으면 전송을 멈추고 선택 범위를 줄이거나 해제하라고 안내한다, #589)·저장하지 않은 편집 본문 10,000자까지 `truncated`)이고 `useWritingChatViewModel`의 `getPage`가 보내는 순간, 첨부 읽기·새 대화 열기보다 먼저 읽는다(반영 회차와 같은 시점 #635). 보내기가 거절되면 뒤이은 이력 조회 실패(새 대화는 404)가 그 사유를 덮지 않는다. 집필실은 열린 회차·편집기의 선택 글(`ManuscriptEditorHandle.selectedText`)·`vm.dirty`일 때의 원고를(선택은 초점을 잃어도 실리므로 편집기의 `onSelectionChange` → `selectionNote`로 실릴 글자 수를 입력 카드 위 `sendNote`에 보인다, #636), 세계관 화면은 `useWorldChatPage`가 세계관·열린 카드(서버에 저장된 카드만 id를 싣는다)·보기·저장하지 않은 카드 이름·설명을 싣는다. 메인 에이전트가 Content 쓰기 도구를 실행하려면 승인 카드(`PendingActionCard`)가 모델의 요약이 아니라 실제 도구 이름·인자와 카드 수정 전·후(`pendingChanges`)를 보이고 제목 아래에 같은 턴에 먼저 끝난 단계(`reply.steps`)를 '같이 끝난 작업' 목록으로 보이며(#587), 세계관 화면에 저장하지 않은 변경이 있으면 승인 버튼을 막고 '먼저 저장해 주세요'를 알린다. 집필실은 잠그지 않는다(#687): 쓰기 도구가 원고를 바꾸지 않고, 원고를 저장하면 작품 revision이 올라 이미 뜬 `work_update` 제안이 반드시 409가 되기 때문이다. 제안 뒤 원고가 저장되면 그 409는 실패로 보이고 같은 요청을 다시 보낸다(제안 다시 받기는 세계관 카드 수정만, `work_update`는 #701). 카드를 들고 있지 않은 집필실은 카드 수정을 '새 설정'이라 단정하지 않고 '설정 카드'와 수정 전을 볼 수 없다는 안내를 보인다(#639). 작품 정보 수정(`work_update`) 승인은 원고를 바꾸지 않아 회차 초안을 다시 읽지 않는다(#639). 고쳐 보낸 메시지의 수정 폼은 전송이 시작되면 닫고 보내기 전에 막힌 때(`inputError`)만 남긴다(#639, 2026-11-23 사용자 결정 A). 무대 시작이 보내기 전에 막히면 직전 답 대신 그 이유를 보인다(#639). 저장 뒤 초안 revision이 달라진 카드 수정 제안은 `저장한 초안으로 제안 다시 받기`로 요청을 다시 실행하지 않고 멈춘 자리에서 제안만 다시 받고(`vm.refreshProposal`, #662), 새 제안에서 승인을 다시 묻는다(#588). 승인한 세계관 카드 수정이 반영되면 `onWorldApplied`로 설정집을 다시 읽는다(`content_action` 단계). **근거 회차(지식 상한)와 반영 회차는 따로다**: 근거는 발행된 판본이 필요해 집필실은 열린 회차가 발행돼 있으면 그 회차, 발행 전 초안이면 그 앞의 가장 뒤 발행 회차를 쓰고(`domain/entities/writingChat.chatBasis`, 서버가 `targetEpisode ≥ episode`만 받으므로 근거는 열린 회차보다 뒤가 되지 않는다), 결과를 반영할 회차(초안이어도 된다)는 열린 회차 번호를 요청의 `targetEpisode`로 따로 보낸다(없으면 서버가 근거 회차와 같게 본다: 세계관 작업실 채팅). 입력 대기 카드(`쓸 장면 계획 · N화`·구간 고르기·고칠 지적·검수 종류)는 열린 회차가 아니라 멈춘 턴의 `approvalEpisode`에 고정되며(모르면 열린 회차로 대신하지 않는다, 이 값으로 편집기를 맞추지도 않는다 #635) 근거≠반영이면 시뮬레이션 시작 양식이 `근거: M화까지 / 반영: N화 초안`을 알리며, 열린 회차 앞에 발행 회차가 없으면 잠근다. 승인을 기다리는 장면·제안의 반영 회차(입력 대기는 제외, 서버가 승인 질문과 장면 대기에 싣는 `approvalEpisode`)가 편집기에 열린 회차와 다르면 집필실이 그 회차로 한 번 맞춘다(새로 고친 뒤 주소의 `?ep=n`이 다른 회차일 때. 승인 회차가 새로 오거나 목록이 준비될 때만 맞추므로 그 뒤 작가가 고른 회차는 되돌리지 않고, 목록에 없는 회차는 건너뛴다). 장면 대기(`awaitingScene`)도 같은 값을 싣고 턴마다 요청 중(값 없음)을 거쳐 돌아오므로, 같은 대화의 같은 반영 회차는 한 번만 맞춘다(#364). 첨부(#617)는 입력 카드의 메뉴·끌어다 놓기로 고르고(끌어다 놓은 파일을 브라우저가 열지 않게 채팅 열 어디에 놓아도(머리줄·대화 고르기 줄·대화·입력, `ChatPanel`의 `keepFiles`를 머리줄·대화 고르기 줄에도 건다) 기본 동작을 막되 첨부로 받는 곳은 입력 카드뿐이다) `domain/entities/chatAttachment.ts`의 `checkAttachment`(한 메시지 3개, PNG·JPEG·WEBP·.txt·.md, 빈 파일 불가, 5MB 이하)가 고를 때, `readAttachments`가 읽은 뒤(텍스트 20,000자·UTF-8, 어긋나면 UTF-8로 다시 저장하라고 알린다) 거르며 거절 사유는 `role="alert"`로 알리고(읽기 오류 안내는 그 칩을 빼면 사라진다) 고른 파일은 칩(× 제거)으로 보여 `send`의 `files`로 보낸다(서버가 같은 한도를 다시 확인한다). `task=patch` 입력 대기의 구간 고르기 카드(#497)는 반영 회차 초안(`useEpisodeDraft`)을 읽기 전용 칸으로 보여 고른 구간을 `inputs.writing_editing.span`으로 보내며, 초안에 CRLF가 있거나 5,000자를 넘게 고르면 보내지 않는다(고른 구간은 안내 줄에 글자 수와 앞 20자 미리보기로 남아 수정 지시 칸으로 초점을 옮겨도 보이고, 초안이 늦게 도착하면 `이어서 실행` 줄이 보이게 한 번 스크롤한다). 입력·승인·구간 카드의 '같이 끝난 작업'은 끝난 단계의 '사용한 계획'·'확인 못 함' 줄을 본문 앞에 함께 보인다. 동의 체크 없이 보낸다(#542). `--mode mockup`은 `writingChatUseCase`가 null이라 잠긴다.

세계관 관리(`/worldstudio/:id`)의 확정 버전 시트는 열어 본 버전의 `이 버전으로 초안 되돌리기`(`useWorldRevisions.restore` → `WorldStudioUseCase.restoreRevision`)를 둔다. 카드만 초안으로 되돌리고 관계·이름·새 확정 버전은 그대로이며, 저장하지 않은 변경·미확인 확정/AI 요청이 있으면 이유와 함께 잠그고 성공하면 서버 초안을 다시 읽는다. 헤더 정보 편집 패널의 `세계관 삭제`(`useWorldStudioViewModel.deleteWorld`)는 확인 뒤 소프트 삭제하고 `/lib?tab=worlds`로 이동하며, 연결된 소설이 있으면 이유와 함께 잠그고 서버 거절(409)은 이유를 그대로 보인다. 서버 계약은 [WorldStudio 설계](../docs/design/worldstudio-independent-schema.md#확정-버전으로-카드-되돌리기와-세계관-삭제-2026-11-17)를 따른다.

**집필실 고급 모드(#374)**: `WritingStudio`가 embedded `useStoryPlanViewModel`을 소유하고 `StoryPlanPanel`을 원고 옆에 둔다. 기본/고급 전환은 숨기기만 하며 원고·계획 입력을 유지한다. 패널은 열린 회차를 기본으로 다른 회차·미정·전체를 선택하고, 여러 플롯의 같은 회차 장면을 위로/아래로 이동한다. 기존 PUT의 선택적 `position`과 revision으로 순서를 영구 저장하며 이웃 revision도 바뀌므로 목록을 다시 읽는다. `useWritingPlanNavigation`은 실제 링크·뒤로가기·공용 이탈 이벤트를 확인하고, `useWritingViewModel`의 회차 이동 확인은 계획 확인 후 원고 확인을 하되 계획 입력은 지우지 않는다. 상단 원고 저장 버튼은 계획 이탈이 아니다. `?view=narrative`는 단독 페이지로 유지한다. [고급 모드·순서 계약](../docs/design/writing-plan-panel-contract.md).

**인물 시뮬레이션 무대(#58)**: 집필실(`WritingStudio`)이 `useWritingChatViewModel`을 직접 만들어 채팅(`WritingChat`)과 무대(`shared/chat/SimulationStage`·`useSimulationStageViewModel`)에 함께 내려 주므로 채팅을 접어도 진행 중인 장면이 이어진다. 상단 `시뮬레이션` 버튼이 편집기(숨기기만 해 입력을 지킨다) 자리에 무대를 열고, 진행 중이거나 답을 기다리는 장면이 있으면 저절로 열리며(초점은 사용자가 연 때만 무대 제목으로 옮기고 닫으면 버튼으로 돌려준다), 끝난 장면은 저절로 열지 않고 버튼은 진행 중이거나 답을 기다리는 장면이 없으면 새 시작 양식부터 연다(사용자 결정 2026-11-23, #420 변경). 대화에 남은 가장 최근 끝난 장면(마지막 턴이 일반 채팅이어도)은 채팅 장면 줄의 `무대 열기`가 읽기 전용 기록으로 열고, 그 기록의 `새 시뮬레이션`이 시작 양식을 연다(`useSimulationStageViewModel.show(form)`). 시작 양식은 모드를 고른다: **IF**(전제 500자 이내 + 인물 1~6명) 또는 **흐름**(비트는 번호 붙은 칸(`비트 1`…, `비트 추가`로 최대 8칸, Enter는 아래에 새 칸, 빈 칸은 보내지 않는다)이다. 열린 회차의 장면 계획 `kind=scene`이 있으면 `제목: 내용` 200자·최대 8개로 칸을 채우고 "N화 장면 계획 N개를 불러왔어요"를 알리며 이 양식에서 고쳐 보낼 수 있다(플롯의 계획은 바뀌지 않고, 고치면 `장면 계획으로 되돌리기`가 보이며 요청 문장은 `비트 N개`. 계획이 다시 읽힐 때 고치지 않은 칸만 새 계획으로 바뀐다). 계획이 없으면 빈 두 칸과 "이 회차의 장면 계획이 없어요" 안내·집필실 플롯 패널 열기 버튼을 보인다. 참여 인물은 장면 계획 비트 문장에 이름(별칭)이 나오는 인물 카드를 미리 고른다). **인물 후보는 이 작품에 연결된 WorldStudio 세계관의 인물 카드**다: `useSimulationSetupViewModel`이 `WorldStudioUseCase.list`에서 `linkedWorkId`가 이 작품인 세계관을 찾아 `read`의 인물 카드를 읽고 카드 id를 `characterIds`로 보낸다(서버가 연결 세계관의 활성 인물 카드 id로 검증하므로 레거시 설정집 `StoryPlanUseCase.references`나 장면 계획의 `characterIds`는 쓰지 않는다). **필수 인물 문서(`IDENTITY.md`=카드 본문·`SOUL.md`)가 빈 인물은 선택이 잠기고**(체크 `disabled`, 이름 옆에 `비어 있는 문서: SOUL.md · 세계관 관리 화면에서 채워 주세요`) 흐름 모드가 비트 문장의 이름으로 미리 채우는 인물에서도 빠진다. `GOAL.md`는 선택이라 비어도 된다(`SimulationCharacter.missing`. 「동일 인물」 다른 이름 카드는 본체와 합친 문서로, 이어받은 원작 세계관의 인물은 `IDENTITY.md`만 판정하며 서버 시작 검증도 같은 규칙으로 422 거절, [계약](../docs/design/character-simulation-contract.md#필수-인물-문서와-시작-검증--357624)) **연결한 세계관이 없는 Fork는 원작 세계관을 읽기 전용으로 이어받는다**(#365, [계약](../docs/design/public-world-contract.md#fork가-이어받는-원작-세계관-dec-3237-365)): 소유하지 않은 세계관이라 `list/read`가 아니라 `EpisodeUseCase.inheritedWorld`(`GET /works/{id}/inherited-world?upto=<여는 회차>`)로 서버가 공개 카드·Fork 기준 회차로 거른 카드를 받아 `inheritedCharacters`(`worldCharacters`와 같은 규칙)로 후보를 만들고, 서버가 같은 카드 집합으로 `characterIds`를 검증한다. 연결한 세계관이 있으면 그것이 우선이라 이어받은 세계관은 묻지 않고, 이어받은 인물은 "원작 세계관에서 N화까지 공개된 인물을 이어받았어요(읽기 전용)."로 알린다. 제목이 `나레이터`로 시작하는 카드(NFC 정규화·앞뒤 공백 제거 뒤 시작 일치, 카드 유형 무관)는 서버가 인물이 아닌 서술 문체 지침으로 보고 스냅샷에서 빼므로 후보에서도 뺀다(`worldCharacters`, 서버 `NARRATOR_CARD`와 같은 규칙). 연결된 세계관도 이어받은 세계관도 없으면 `연결된 세계관이 없어요`로, 인물 카드가 없으면(이어받은 세계관은 `이어받은 원작 세계관에 공개된 인물 카드가 없어요`) 그 사유로 시작을 잠근다. 이어받은 세계관을 읽지 못하면 연결 없음으로 바꾸지 않고 불러오기 실패와 `다시 불러오기`로 알린다. 장면 계획은 기존 `StoryPlanUseCase.list`로 읽고, 둘 다 양식을 열 때와 계획 저장·삭제·순서 변경 뒤 다시 읽으며(갱신 중·실패·미저장 입력에서는 시작 잠금), 채팅에서 승인한 계획 저장(`revise_plan`·Content 도구 `story_plan_create`·`story_plan_update`)도 `onPlanApplied` → `plans.reloadAfterAi`로 같게 다시 읽고(회차 초안은 안 읽는다. 미저장 계획 입력이 있으면 확인 창 없이 입력을 지키고 `AI가 계획을 바꿨어요` 안내만 남기며 양식은 다시 읽는다, #637), 읽지 못하면 사유와 `다시 불러오기`를 보인다. 시작 양식은 첫 장면이 올 때 닫히므로 요청이 실패하면 옛 장면이 아니라 입력한 양식이 남는다. 시작은 채팅 메시지 전송이며 `operation:'character_simulation'`(의도 분류를 건너뜀)과 `simulation{mode, premise?, beats?, characterIds}`를 싣고(규칙은 `domain/entities/characterSimulation`의 `simulationIssue`·`planBeats`, `WritingChatUseCase`가 서버 한도로 다시 검사한다) 요청 문장은 `IF 모드 시뮬레이션: …`·`흐름 모드 시뮬레이션: 장면 계획 N개`다. 무대는 나레이션(이탤릭 회색 지문)·독백(시점 인물 이름 + `속마음`)·인물 줄(이름 + 말풍선)을 SSE `step`의 누적 결과로 이어 붙이고(`aria-live="polite"`, 맨 아래에서 읽는 중일 때만 자동 스크롤) 시점이 바뀌는 줄 앞에 `시점: 전지적 / ○○ 시점(3인칭) / ○○ 1인칭` 구분선을 두며, 서버가 장면에 붙이는 선택 안내(`notice`: 원고 발췌를 쓸 수 없어 세계관 설정만으로 만들었을 때 등)는 대본 위에 `role="status"` 한 줄로 보이고 없으면 숨긴다. 장면이 턴마다 멈추면(`waiting.awaitingScene`) 자동 재생이 `resume.scene = next`를 보내고(`approved:true`를 함께 보낸다), 서버 응답이 `waiting`으로 끝난 턴만 이어 가므로 실패한 턴·일시정지·새로 고친 뒤 이어진 장면은 저절로 보내지 않고, 서버가 별도 오류 없이 멈춘(`stopped`·`failed`) 장면을 장면 대기로 돌려줘도 같은 실패를 되풀이하며 호출만 쓰지 않도록 재생을 눌러야 이어 간다. `일시정지`는 진행 중인 턴을 마치고 멈추고, `장면 끝내기`는 `stop`(턴을 만드는 중이면 그 턴 뒤), 줄 `수정`은 `edit`(모델 호출 없음·`작가 수정` 표시·검사 결과 없음, 저장 요청 중에는 입력을 잠그고, 고치는 줄이 열려 있는 동안은 승인 대기의 `원고에 반영`을 잠가 이유를 알린다: 새 글은 아직 서버 장면에 없다), `다시 말하기`는 `redo`(뒤 줄이 지워져 확인), `끼어들기`는 다음 `next`·`redo`의 `note`(300자 이내)로 한 번만 싣고(반영·반영하지 않기 답에는 실리지 않아 승인 대기 중에는 그렇게 안내하며, 새 시뮬레이션을 시작하거나 다른 대화를 열면 지운다) 오류로 멈추면 `오류로 멈춤`으로 알리고 재생으로 다시 시도한다. 멈춘·실패한 장면의 이유는 서버가 사람이 읽을 문장으로 주는 단계 `error`를 보이고(`stopReason`은 `check_failed`·`beat_rejected`·`turn_limit`·`call_limit` 코드값이라 그대로 찍지 않는다), 문장이 없을 때만 코드를 문구로 바꾸며 모르는 코드는 `장면이 멈췄어요`로 보인다. 비트 거부(`beat_rejected`)로 멈춘 장면은 '이대로 진행' 없이 그 이유 아래에 `설정집에서 고치기`(거부한 비트의 `rejectedBy` 인물 카드 편집 화면 `/worldstudio/{연결 세계관 id}?card=<카드 id>`, 새 탭, `useLinkedWorldId`. 연결한 내 세계관이 없거나 거부 인물을 모르면 없다)와 `흐름 고치기`(호스트가 넘긴 `plotLink` 버튼의 글자만 바꾼 플롯 패널 열기)를 보이고(`beatRejection`), 고친 뒤 `재생`하면 서버가 세계관을 새로 읽어 쌓은 턴을 지킨 채 그 비트부터 다시 시도한다. 흐름(장면 계획)을 고쳤다면 장면 끝내기 → 반영하지 않기 → 새 시뮬레이션이다. 끝난 장면은 `원고에 반영`·`반영하지 않기`(승인 응답)·`장면 이어 가기`를 묻고 반영은 `onApplied`로 그 회차 초안을 다시 읽는다(`useWritingViewModel.aiApplied`는 늦게 불려도 호출 시점이 아니라 지금 열린 회차·입력 상태를 보고, 다른 회차로 옮겨 입력 중이면 덮어쓰지 않고 목록만 갱신한다). 채팅에는 장면 카드·승인 카드 대신 `시뮬레이션 진행 중 · N턴` 한 줄과 `무대 열기`만 있고, 무대가 없는 화면(세계관 작업실)은 집필실에서 열라고 안내한다. 승인 대기 장면은 서버가 승인을 물었고(`awaitingApproval`) 실패가 아니며 줄이 있을 때만 반영을 묻는다.

화면은 세 규칙을 함께 쓴다. **Clean Architecture**는 계층 의존 방향을, **MVVM**은 화면 책임 분리를,
**Flux**는 상태 변경·전달 순서를 정한다. 하나가 다른 것을 대신하지 않는다.

## 구조와 의존성

TypeScript(`.ts`·`.tsx`)로 작성하고 `any`·타입 단언 남용을 피한다. 외부 응답은 Zod로 검증한 뒤 사용한다.
업무 기능은 **업무 규칙이 외부 구현을 직접 참조하지 않게** 의존 방향을 정한다.

```text
실행 흐름: View → ViewModel → UseCase → Repository 구현 → HTTP API
코드 의존: Presentation → Domain ← Data
객체 조립: app/di에서 Domain UseCase와 Data 구현체를 연결
```

| 위치 | 역할 | 예 |
|---|---|---|
| `presentation/features/<기능>/view` | JSX·스타일·ARIA와 순수 표시용 포맷만. ViewModel이 반환한 상태·handler 사용 | `WorkPage` |
| `presentation/features/<기능>/viewmodel` | Custom Hook ViewModel. 화면 상태·동작·요청 수명 관리 | `useReaderViewModel` |
| `presentation/features/<기능>/state` | 화면 이동 후에도 유지할 Redux slice | `library/state/newWorkSlice` |
| `presentation/shared` | 여러 feature가 공유하는 화면 요소 | `shell`, `session` |
| `domain/entities` | 업무 데이터 타입 | |
| `domain/usecases` | 사용자 기능 실행. Repository interface만 생성자로 받고 HTTP를 import하지 않음 | `LibraryUseCase` |
| `domain/repositories` | 데이터 접근 계약(interface) | `WorkRepository` |
| `data` | Repository 구현·Fetch·HTTP DTO의 Zod 검증과 Entity 변환. API 형식 변경은 여기서 흡수 | `HttpEpisodeRepository` |
| `app` | Awilix 등록, Redux Store | `app/di`, `store.ts` |

- Domain은 Data·Presentation·React를 import하지 않는다. 요청 취소용 Web 표준 `AbortSignal`은 Domain 계약에 둘 수 있다.
- feature끼리 다른 feature의 ViewModel·Store를 참조하지 않는다. 공유가 필요하면 `presentation/shared`로 옮긴다.
- 브라우저는 상대 `/api` 경로만 사용하고 기존 URL·Bearer·쿠키·CSRF 계약을 유지한다. AI·그래프 DB·외부 모델을 직접 호출하지 않는다.
- 기존 Tailwind CSS·디자인 토큰을 재사용한다. 읽기 토큰(`--t*`)은 `:root`에 기본값이 있어 어디서나 쓸 수 있고, 독서 화면(`.reader`)에서는 전역 토큰(`--surface`·`--ink`·`--sub`·`--line*`·`--pri*`)이 읽기 토큰으로 재연결되므로 전역 부품을 그대로 써도 보기 설정을 따른다. `.calm`·`.reader`에서 `--t*` 색 토큰과 `--bg`를 다시 선언하지 않는다. 입력·선택 테두리는 `--line3`, 위험 채움 위 글자는 `--on-danger`를 쓴다. 전역 CSS(`storyfork.css`)는 `@layer(base)`라 기능 CSS가 늘 이기므로, 전역 터치 보정(44px·입력 16px)과 같은 속성을 기능 CSS가 다시 정하면 그 화면이 직접 보정한다.
- 원고는 저장 문자열을 그대로 두고 **그릴 때만** 기본 서식(굵게·기울임·소제목·인용·구분선, DEC-48)을 해석한다. 문법은 `domain/entities/manuscriptFormat.ts` 한 곳이며 마크다운 라이브러리를 쓰지 않는다(표준 마크다운과 다르다: 한 줄 = 한 문단, 서식은 한 줄 안에서만, 내용 2,000자 초과 줄은 해석하지 않음). 문법을 바꾸려면 [계약](../docs/design/manuscript-format-contract.md)의 검증 표와 서버 구현(`ManuscriptFormat.kt`)을 함께 바꾼다. 본문을 그리는 화면은 공용 `ManuscriptBody`(미리보기류)나 `readerBody`(독자 화면)를 쓰고 본문 문자열을 직접 잘라 그리지 않는다. 독자 화면 문장의 `t`(인용·수정 제안에 보내는 글)는 원문 그대로의 조각이어야 한다(서버가 발행본에서 글자 그대로 찾는다).
- 서버 집필실 본문 편집기(`studio/view/ManuscriptEditor`, Toast UI Editor 3 마크다운 쓰기 모드, `LazyManuscriptEditor`로 지연 로딩)는 저장 글을 편집 영역의 글자 그대로 둔다(열기만 해서는 `onChange`를 부르지 않는다). 원작 기준 회차는 읽기 전용 본문이고 사용자가 누른 요청 중에만 편집기를 잠근다(`inert`). Tab은 들여쓰기이고 Esc 다음 Tab으로 벗어난다(`shared/tabEscape`, 카드 편집기와 공용). Toast 편집기를 새로 쓰거나 고칠 때는 `shared/toastFixes`의 보정(`loadMarkdown`·`forToast`)을 함께 걸고, 우회의 근거는 `ManuscriptEditor.tsx` 주석과 테스트에 있다. 화면 테스트는 `vi.mock('./LazyManuscriptEditor', () => import('…/test/manuscriptEditorFake'))`로 textarea 대역을 쓴다.

## MVVM과 DI

- View는 ViewModel 하나가 반환한 상태를 렌더링하고 사용자 이벤트를 반환된 handler에 연결한다. 업무 판단·API 호출을 하지 않는다.
- ViewModel은 UseCase 실행, 화면 상태 조합, 입력 가능 여부 검사, 포커스·스크롤 같은 화면 제어를 맡는다.
- `app/di`의 `register*Services`가 `asFunction(({ repo }) => new XUseCase(repo)).singleton()`처럼 Repository를 UseCase 생성자에 넣는다(생성자 DI).
- ViewModel만 `appContainer.resolve(...)`로 UseCase를 조회한다(Service Locator). View는 `appContainer`를 조회하지 않고,
  ViewModel은 Repository를 직접 생성·조회하지 않는다.
- Awilix는 UseCase·Repository 같은 **협력 객체**를, Redux는 **화면 상태**를 관리한다. 둘을 섞지 않는다.
- 업무 규칙이 없는 연결 확인(Health)은 `View → Hook → DI 외부 함수 → Fetch·Zod`를 유지하고 빈 UseCase·Repository를 만들지 않는다.

## Flux 단방향 흐름 (Redux Toolkit)

```text
View 이벤트 → ViewModel handler → UseCase 메서드 호출
  → 결과에 따라 dispatch(sliceActions.x(payload))      // Action
  → Reducer가 새 상태 계산 → Store 갱신
  → useAppSelector 구독 → ViewModel 반환값 → View 재렌더링
```

- 상태는 Action → Reducer → Store → Selector 한 방향으로만 바뀐다. View·HTTP 코드가 Store 상태를 직접 고치지 않는다.
  (예: `useReaderViewModel`이 UseCase 호출 후 `dispatch(sessionActions.dataChanged())`, 상태는 `useAppSelector`로 읽음)
- 비동기 HTTP는 ViewModel이나 Thunk에서 UseCase로 호출한다. Reducer에는 상태 변경 규칙만 두고 부수 효과를 넣지 않는다.
- slice 안의 `state.x.push(...)` 표기는 Redux Toolkit(Immer)의 불변 갱신이다.
- 컴포넌트에서는 `app/store`의 `useAppDispatch`·`useAppSelector`만 쓴다.

## 상태 위치와 요청

| 상태 | 저장 위치 | 수명 |
|---|---|---|
| 한 화면에서만 쓰는 입력·결과·ref | ViewModel Hook 로컬 상태 | 화면 이탈 시 해제, 진입 시 재조회 |
| 화면을 옮겨도 이어져야 하는 작업 | Redux slice + ViewModel | 앱 실행 동안 유지(새로 고치면 초기화) |

- 같은 상태를 Hook과 Redux에 중복 저장하지 않는다. Redux에는 직렬화 가능한 값만 넣고 `AbortController`·타이머는 넣지 않는다.
- 진행 중 중복 전송을 막고, 새 요청·화면 이탈·로그아웃 시 이전 요청을 취소하며 요청 ID로 늦은 응답을 무시한다.
- 로딩·실패·완료 표시는 실제 API 결과와 일치시킨다. AI 제안 도착을 저장·승인·발행 완료로 표시하지 않는다.
- 시트 안에서 보낸 요청의 거절·실패는 시트가 열려 있는 동안 시트 안 `role="alert"`에 남기고 이미 닫았으면 토스트로 알린다(`reading/viewmodel/useInlineFailure.ts`). 접수 결과는 `role="status"`로 알리고 '확인'에 초점을 둔다. 곧 사라지는 토스트만으로 결과를 알리지 않는다(서재 '내 제보'는 `shared/feedbackReports/useReportSender`의 `notice`를 그 카드 안에 남긴다).
- 같은 목록 안의 필터·선택을 바꿔 다시 읽을 때는 `useAsyncData`의 `refresh`로 이전 목록을 유지한 채 읽고(`/chat` 목록 필터, `/inbox?i=` 선택), 조회 중·실패(다시 불러오기)는 그 화면의 틀 안에서 알린다.

## 데모 화면과 실제 기능

- 실제 API가 없는 기능은 메모리 Repository(`data/mock`, `--mode mockup`의 `registerMockupServices`)로 화면만 시연한다.
  데모 입력·이동을 서버 저장 성공으로 표시하지 않고, 미연결 동작은 준비 중으로 비활성화한다.
- 서버 기능이 없는데 형식적인 UseCase·Repository 계층을 추가하지 않는다. 버튼 숨김으로 서버 권한 검사를 대신하지 않는다.

## 검증

- 패키지 관리는 `pnpm`과 기존 lockfile을 사용한다.
- 로컬: `pnpm exec vitest run src/domain/__tests__/<대상>.test.ts`처럼 변경 범위의 **단위 테스트 파일만** 지정한다.
  `src/domain`, `src/data`의 대역 기반 테스트와 `src/index-html.test.js`가 단위 범위이고, React 렌더·Hook·App 조립은 CI 통합 계층이다.
- UseCase 테스트는 Fake Repository, ViewModel 테스트는 Fake UseCase나 격리 컨테이너를 사용한다(운영 컨테이너를 바꾸지 않음).
- 상세는 [Frontend README](README.md)를 본다.
- 집필실 자동 저장은 실패한 입력만 재시도 대기 상태로 두고 다음 편집 또는 `초안 저장 다시 시도`에서 초안 저장을 재개한다(#406). 이 버튼은 다시 시도할 미저장 입력이 있을 때만 오류 상자에 보이고(그때는 복사 안내를 빼며 로그인 링크와 한 묶음이다) 버전이 아니라 초안만 저장한다. 누르면 버튼이 있던 오류 상자가 사라지므로 초점은 상단 저장 상태 줄이 이어받는다. 사용자가 누른 요청(버전 저장·발행 등)이 실패한 입력도 같은 대기 상태라 2초 뒤 자동 저장이 그 실패 안내를 지우거나 같은 입력을 되풀이하지 않는다. 실패한 요청 중 추가된 입력도 저장하며, 복구 때문에 새 저장 버전을 만들지 않는다.
- 집필실 저장 중·실패·성공 시각·버전은 실제 원고 저장 결과를 표시한다(#416). 없는 회차 주소는 오류와 회차 목록으로 안내하며 임의로 첫 회차를 열지 않는다(회차가 하나도 없는 작품은 오류 없이 첫 회차 만들기 안내를 보인다). `저장 실패` 상태는 다시 시도할 미저장 입력이 있을 때만 알린다. 실제 UUID 집필실은 `RestoreContext`로 로그인 복구를 기다린 뒤 원고를 요청한다. 인용 Enter는 기호 자동 삽입 없이 일반 문단으로 이동한다. End는 브라우저가 계산한 화면 줄 끝을 ProseMirror 선택에 즉시 반영해 원문을 보존한다(문단 끝으로 건너뛰지 않음).

작품 관리의 작성 중 개수·제목은 소유자 회차 조회 결과를 사용한다. 공개 회차 목록과 구분하며 공개 기준은 공백 포함이다.

수정 제안의 발행 반영 표시는 서버가 확인한 현재 발행본 계보를 따르고, 초안에만 반영된 제안은 해당 회차 집필실로 연결한다.
