# AI Service 구현 지침

`backend/ai-service/**`에 적용한다. [루트 공통 지침](../../AGENTS.md)을 함께 따른다.
현재 실행 기능은 내부 Health뿐이며, STORYFORK 생성·시뮬레이션 기능은 아직 미구현이다.

## 단순성 우선

- 사용자가 요청한 현재 기능만 구현한다. 미래 요구를 추측해 구조를 추가하지 않는다.
- 가장 단순하게 현재 요구와 테스트를 만족하는 구현을 우선한다.
- 기본적으로 구체 클래스와 직접적인 함수 호출을 사용한다.
- 하나의 기능을 불필요하게 여러 계층, 클래스 또는 파일로 분리하지 않는다.
- 새 클래스나 파일은 현재 책임을 한 문장으로 설명할 수 있을 때만 추가한다.
- "나중에 필요할 수 있다"는 이유만으로 코드를 추가하지 않는다.

## 추상화 제한

- 사용자가 명시적으로 요청하지 않는 한 새로운 `Protocol`, ABC, port, provider abstraction,
  registry, base class, 범용 factory를 만들지 않는다.
- 다음 조건 중 하나도 충족하지 않으면 추상화를 추가하지 않는다.
  1. 현재 production 구현체가 2개 이상이다.
  2. 현재 production 코드에서 같은 로직이 실제로 반복된다.
  3. 외부 시스템 경계를 격리해야 하는 명확한 장애 또는 보안 이유가 있다.
  4. 사용자가 해당 추상화를 명시적으로 요청했다.
- 테스트 편의를 이유로 production 추상화를 추가하지 않는다. 테스트에서는 `monkeypatch`,
  `AsyncMock` 또는 구체 클래스의 테스트 대역을 우선한다.
- 공통 코드는 실제 production 사용처가 2개 이상 생겼을 때만 추출한다. 단, 사용자가 공통화를
  명시적으로 요청한 경우에는 바로 적용한다.

## LLM 사용 및 Agent 구성

- MVP의 모델·제공사·에이전트 프레임워크는 미정이다(DEC-28). 이전 LangChain·LangGraph·OpenAI 제안은 확정 기술로 취급하지 않는다. 현재 `openai-agents` 의존성은 Health에서 쓰지 않으며 구현 전에는 의존성·lockfile을 미리 바꾸지 않는다.
- Langfuse는 MVP 이후다(DEC-18). 향후 도입해도 원고 원문·개인정보·비밀값을 추적 시스템에 보내지 않는다.
- 장애를 정상 응답으로 숨기는 fallback을 만들지 않는다. 장애는 명시적인 오류로 반환한다.
- 다중 인물 역할은 필요할 때만 분리한다. 단일 호출에 다중 에이전트 프레임워크를 강제하거나 역할마다 서버를 만들지 않는다.
- 현재는 `router → HealthResponse`뿐이다. AI 기능을 구현할 때 실제 필요한 계층과 자원만 추가한다.
  상세는 [AI README](README.md)와 [Agent 구조](docs/agent-structure.md)를 참고한다.

## STORYFORK 생성 경계

- 허용 문맥과 작업 범위로 조회를 제한한다. Core 경유 읽기 전용 조회 도구는 후보 경로이며 AI의 저장소 직접 접근 여부는 미정이다. 어느 쪽이든 정본을 직접 수정하거나 권한·승인·과금을 확정하지 않는다. 설정 문서·원고와 그래프 관계를 같은 기준 버전에 맞춰 사용한다.
- 캐릭터별 성격·목표·허용 기억·관찰 정보를 분리한다. 다른 인물의 비밀이나 미래 사건을 누출하지 않는다.
  같은 구현에 인물별 문맥을 주입하며 인물마다 클래스나 서버를 만들지 않는다.
- 스토리 계획·캐릭터 판단·설정 검토·집필·피드백 역할은 실제 입력·출력·책임이 다를 때 나눈다.
  시뮬레이션 상태를 정본·다른 실행과 혼합하지 않으며 초안과 실행 결과는 제안으로 반환한다.
- 피드백 유형은 독자가 고르며 AI로 분류하지 않는다(BR-15). AI는 단순 오류 수정안과 질문 답변,
  독자가 고른 스토리 오류 검증 시뮬레이션만 처리한다. 공개 근거로 답하고, 근거 부족이나 창작 판단이 필요한 사안은 작가 검토가 필요함을 표시한다.
- 오타·맞춤법·명백한 수치 오류도 수정안까지만 생성한다. 개인적 해석을 오류로 단정하거나
  제안 생성을 반영 완료로 표현하지 않는다. 독립 창작 의도가 있을 때만 허용된 Fork를 선택적으로 안내한다.
- AI 자율 연재의 일정·중지·발행 판단은 Core가 한다(UC-18). AI Service는 요청받은 회차 생성만 하며 승인·발행·과금을 확정하지 않는다.

## 변경 범위와 검증

- 요청 범위 밖의 패턴 통일, 파일 재배치 또는 미래 대비 리팩터링을 하지 않는다.
- 새로운 production 의존성, 외부 서비스 또는 실행 계층을 추가하기 전에 사용자에게 알린다.
- 구현 후 실제 호출 흐름과 OpenAI 호출 유무를 구분해 설명한다.
- 로컬: `backend/ai-service`에서 `uv run --locked --extra dev python -m pytest <대상 테스트 경로>`로 관련 테스트를 실행한다.
  필요하면 `-k`로 범위를 좁히고, 유료 API 호출 없는 단위·스텁 검증을 우선한다.
- CI: `uv lock --check`와 `uv run --locked --extra dev python -m pytest` 전체 실행.
  문서만 변경한 경우는 루트의 문서 검증 기준을 따른다. 실제 OpenAI 호출 없이 검증한 범위를 구분해 보고한다.
