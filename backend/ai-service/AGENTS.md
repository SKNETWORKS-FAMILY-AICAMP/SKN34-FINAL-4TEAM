# AI Service 구현 지침

`backend/ai-service/**`에 적용한다. [루트 공통 지침](../../AGENTS.md)을 함께 따른다.
현재 내부 Health, 이어쓰기 제안, 초기 세계관 후보 추출, 원고 임베딩과 Story Context Q&A(`app/story_qa/`), Research의 웹 조사(`app/research/`, OpenAI `web_search`)와 플랫폼 내부 조사(`platform`, 공개 세계관을 Content MCP로 읽어 참고안 제시, #547), 새 원고·부분 수정(`app/writing/`) API, 작가 초안을 Content MCP로 읽어 Mechanical·Semantic 한 가지로 검수하는 원고 검수(`app/manuscript_review/`, #59) API, 회차 초안이 19세 이용가인지만 판별하는 심의 등급(`app/rating/`, 기준은 `guidelines/*.md`를 프롬프트에 주입, [설계](../../docs/writing-ai-architecture/03-rag-simulation-design.md#5-rating-agent)) API, Decision Guard(`app/intent/`, OpenAI Decisions `gpt-6-luna`, 범위 + 기능별 yes/no 판정), Content 내부 검색 API를 부르는 공통 Retrieval(`app/retrieval/`), 설정집 AI 검토와 집필 채팅 World Agent(`app/world_review/`: `check`·`enrich`·`impact`, [계약](../../docs/design/world-review-contract.md)), 인물 시뮬레이션의 기억 추론 라이브러리 NovelBrain(`app/novelbrain/`, [계약](../../docs/design/character-simulation-contract.md))과 인물별로 격리된 턴을 이어 가는 인물 시뮬레이션(`app/simulation/`: LangChain `create_agent` + 미들웨어의 장면 에이전트, 오케스트레이션 `character_simulation` 단계), Q&A·Writing·웹 조사·Manuscript Review 업무 Agent의 공통 실행 틀(`app/agent_runtime.py`: LangChain `create_agent` + 커스텀 미들웨어, #373)과 이를 `ask_*` 도구로 부르고 답을 종합하는 메인 에이전트와 바깥 LangGraph 오케스트레이션(`app/orchestration/`, #473), 작가가 승인한 Writing 결과·World 보강안·계획 수정안(#578)을 작가 권한으로 초안·저장된 계획에 반영하는 Content MCP 클라이언트(`app/content_mcp/`), Langfuse 평가 세트로 프롬프트 버전을 채점하는 회귀 평가와 누설 판정(`app/evaluation/`), 운영 정기 작업의 실행 요청을 Celery 큐(jobs)에 올리는 작업 접수(`app/jobs/`), 시뮬레이션 지시문(act·narrate)의 새 버전을 GEPA로 만드는 프롬프트 자동 개선(`app/optimization/`, #823), Content가 부르는 AI 자율 연재의 장면 미리보기·다음 회차 생성·검수(`app/serial/`, #659)가 있다. AI 실행 체크포인트는 전용 PostgreSQL DB에 저장한다. 콘텐츠 정본은 Content API와 MCP로만 읽고 쓴다. 콘텐츠 정본·인가·발행은 Content, 크레딧·알림은 Core가 판단한다.
현재 호출 흐름과 기능별 코드 구조는 [AI Service 구현 경계](docs/agent-structure.md)를 본다.

## 구조

- 기능마다 `app/<기능>/` 패키지를 두고 `app/main.py`에서 기능별 Router를 조립한다. 모듈·엔드포인트에 한국어 docstring을 단다.
- 패키지 파일은 `router.py`(내부 인증·HTTP 입출력·오류의 HTTP 변환), `models.py`(DTO와 불변식), `prompt.py`(모델 지시),
  `agent.py`(모델 SDK 호출·timeout·제공사 오류 변환), `service.py`(입력·결과 검증, 근거 대조, 모델 밖 계산), `errors.py`(기능 실패)로 나눈다.
  에이전트가 부르는 도구가 있는 기능은 `tools.py`(도구 인자·입력 연결·결과 요약, 예: 오케스트레이션의 `ask_*`)를 둔다.
  `router.py`·`models.py`만 필수이며 나머지는 그 책임이 있을 때만 만든다. 통과만 하는 service·빈 파일을 만들지 않는다. 계층 규칙은 [구현 경계](docs/agent-structure.md#계층-규칙)를 따른다.
- 요청·응답은 Pydantic DTO(`Request`·`Payload`·`Response`·`Result`)로 정의한다. 임의 `dict`·외부 SDK 응답을 계약으로 노출하지 않는다.
- 프롬프트에 맡긴 규칙(식별자·근거·URL·점수 범위)은 `models`·`service`에서 다시 검증하고, 어긋난 결과는 보정하지 않고 오류로 반환한다. 단 회차 원고 전처리(`app/manuscript_extraction/`)는 근거가 어긋난 항목(대상·진술·관계·정체 링크) 하나만 값을 고치지 않고 빼서 코드별 건수를 추출 결과 `skipped`에 남기고, 모델 호출이 실패했거나 제안은 있었는데 검증된 대상이 하나도 없는 회차만 오류로 끝낸다.
- 임베딩·색인·검색 같은 모델 밖 처리는 service가 직접 수행한다. 파일을 나누려고 Agent를 만들지 않는다.
- 그래프는 반복 상태 갱신·조건 분기·중단 및 재개가 실제로 필요한 기능에서 [집필 AI 설계](../../docs/writing-ai-architecture/02-ai-architecture.md)에 따라 검토한다. 단순 호출과 조회는 직접 실행한다.
- 구체 클래스와 직접 함수 호출을 기본으로 한다. production 구현체가 둘 이상이거나 사용자가 요청하지 않으면
  `Protocol`·ABC·provider·registry·factory·bootstrap 추상화를 만들지 않는다. 테스트 편의를 위해 production 추상화를 추가하지 않는다.
- 집필 AI의 업무 Agent(2026-11-19 구조: Q&A·Manuscript Review·World(`check`·`enrich`·`impact`)·Writing(플롯 포함)·Research(`web`·`platform`)·Rating, [목표 구조](../../docs/writing-ai-architecture/02-ai-architecture.md#목표-구조-여섯-업무-agent-2026-11-19))의 목표 모델은 사용자 결정으로 OpenAI `gpt-6-luna`이고, 시뮬레이션은 인물 대사(act)만 `gpt-6.1-terra`(사용자 결정 2026-11-23, 근거 [원문 평가 §14](../../docs/evaluation/simulation-original.md))이며 나머지 인물 행동·장면 요약은 `gpt-6-luna`다. Decision Guard도 OpenAI Decisions(`gpt-6-luna`)를 쓴다. 기존 구현의 모델 설정과 실제 검증 기록은 구분한다. 집필 AI 복합 실행은 사용자 요청으로 LangGraph를 쓰고, 인물 시뮬레이션의 실행 틀은 사용자 결정(2026-11-14, #362)으로 LangChain `create_agent` + 미들웨어이며 연출 결정은 `langchain-typesafe`로 OpenAI Decisions를 부른다(의존성 `langchain`·`langchain-typesafe==0.0.1a3`). 업무 Agent(Q&A·Writing·웹 조사·Manuscript Review·Rating)는 사용자 결정(2026-11-16, #373)으로 `create_agent`(`langchain-openai`의 `ChatOpenAI`) + 공통 미들웨어(`app/agent_runtime.py`)로 실행한다. Decision Guard는 `create_agent` 위에서 입력 가드레일 미들웨어(`PIIMiddleware`·`OpenAIModerationMiddleware` 상속)를 먼저 거친다(#373). 메인 에이전트는 사용자 결정(2026-11-17, #473)으로 `create_agent`(`ChatOpenAI`)이고 모델 호출은 턴당 8회까지다(#554: 화면 맥락 `page`와 Content MCP 도구 10개(읽기 6 자동·쓰기 4 HITL, [DEC-59](../../docs/design/decisions.md))를 메인이 직접 쓴다). 그 밖의 모델·프레임워크와 상세 도입은 미정이며 의존성·lockfile을 미리 바꾸지 않는다. lockfile은 `ai-service/Dockerfile`의 uv 버전(0.12.5)으로 갱신한다.
- 추적은 `app/tracing.py`가 맡는다(DEC-55 v4, [계약](../../docs/design/operations-llmops-contract.md#ai-서비스-계측-규칙)). AI 요청 하나는 Router가 `tracing.request('<기능 키>', …)`로 여는 trace 하나이고, 그 **요청 루트 관측 하나**(이름·trace 이름 = 기능 키)가 요청 전체(SSE는 `done`까지)를 덮고 가장 마지막에 끝난다. 루트와 안의 모든 observation에 `propagate_attributes`로 회원 UUID(Router가 선택으로 받는 헤더 `X-User-Authorization`의 작가 Bearer sub를 `tracing.member_id`로 읽는다. 없거나 읽을 수 없으면 회원 없이 처리한다)·세션(대화·작업 ID)·태그 `feature:<키>`·metadata `request_id`·`fork`(true/false)·`work_id`·`credit_reservation_id`(있을 때)를 붙인다. 상태는 끝나야 알 수 있어 **루트에만** metadata `status`(`success|failed|timeout`)로 남기고 실패면 level ERROR다(대기 턴·취소·끊김은 상태 없음). 단계 observation은 현재 문맥(요청 루트)의 하위로 붙으므로 trace id를 직접 넘기지 않는다(새 턴은 루트의 trace id가 `runId`이고, 대화를 이어 가는 resume 요청은 그 턴의 trace에 새 루트로 붙는다). 모델 호출은 generation(모델·사용량·프롬프트 버전)이다. 집필 오케스트레이션은 운영 파이프라인 화면(DEC-58, [계약](../../docs/design/operations-ai-pipeline-contract.md))이 노드 기록으로 보이도록 `decision_guard` span의 output에 판정 결과(`allowed`·`reason`·`capabilities`), `main_agent` generation의 output에 `{text, toolCalls:[{name, args}]}`를 남기고, 메인이 실행하지 않고 돌려보낸 도구 호출은 `main_agent.blocked` span(input 이름·output 이유)으로 남긴다. NovelBrain 회상(`novelbrain.service.recall`)은 `novelbrain.recall` retriever span으로 인물·회차·단계·질문 앞 500자와 찾은 항목의 ref·점수·카드 제목만 남긴다(본문 없음). `observe`로 단계·근거 참조·실패와 질문·원고·답변 본문을 남기고(팀 결정 2026-11-13), 설정·현재 관계 발췌 본문은 `tracing.excerpts`로 참조만 남기며, 이메일·닉네임·키는 어떤 속성에도 넣지 않는다. 앱 종료(`app/main.py`의 lifespan)는 `tracing.client().flush()`로 아직 보내지 않은 span을 보낸다. SDK의 atexit 전송에 맡기지 않는다: uvicorn이 SIGTERM으로 정상 종료한 뒤 그 시그널을 다시 올려 프로세스를 끝내므로(컨테이너는 `init: true`) atexit이 돌지 않아, 요청 뒤 SDK 전송 주기(5초) 안에 재시작하면 마지막 요청의 trace가 사라진다.
- 모델 지시문은 `tracing.prompt('<기능>.<용도>', <코드 문자열>)`로 Langfuse Prompt Management의 `production` 버전을 읽어 쓰고 generation에 `prompt=`로 연결한다. 코드 문자열은 시드다: 없을 때 버전 1로 등록하고, 바뀌면 읽을 때 `seed` 라벨의 새 버전으로 올라가(기동 때 `app/prompts.py`의 모든 프롬프트를 한 번 읽어 등록하므로 새 지시문은 이 목록에도 넣는다) 운영 화면에서 평가·승격한다(#705, production을 직접 바꾸지 않으니 이름을 새로 짓지 않아도 된다). 모델은 `tracing.prompt`가 준 `managed.model`(버전 `config.model`)이 먼저이고 없으면 환경 변수 기본 모델이다(Decisions API 호출은 고정 모델). Langfuse 키가 없으면 코드 문자열을 쓰고, 키가 있는데 읽을 수 없고 캐시도 없으면 기능의 고정 문구 503으로 모델 호출 전에 끝낸다. 새 모델 호출·지시문은 이 규칙으로 감싼다. 평가가 지정한 프롬프트 버전 본문을 직접 돌리는 호출만 예외로 `agent_runtime.run`에 `prompt_name`을 주지 않는다(production 버전을 읽지도 generation에 연결하지도 않고 넘긴 본문을 그대로 쓴다). 시뮬레이션 평가는 `agent.act`·`narrate`의 `instructions` 인자가, 추출 평가는 `manuscript_extraction.agent.extract`의 `instructions`·`model` 인자가 같은 일을 한다.
- 회귀 평가·누설 판정(`app/evaluation/`, DEC-55, [계약](../../docs/design/operations-llmops-contract.md)): `POST /internal/v1/evaluations`는 Langfuse 평가 세트(Dataset)의 항목마다 요청한 프롬프트 버전의 본문을 지시문으로 업무 Agent와 같은 실행 틀(`app/agent_runtime.py`)에 실어 실행하고, 세트 이름이 `qa.`로 시작하면 Ragas(faithfulness·context precision), 그 밖은 DeepEval GEval(항목 `metadata.criteria`)로 채점해 Run(experiment)에 항목 점수와 Run 수준 점수(지표 평균·`passed`)를 남긴다. 예외로 **시뮬레이션 평가 세트**(`simulation.act`·`simulation.narrate`, `app/evaluation/simulation.py`)는 업무 Agent 틀이 아니라 실제 서비스 호출(`app/simulation/agent`의 `act`·`narrate`에 그 버전 본문, act는 terra·구조화 출력)로 응답을 만들고 원문 평가 루브릭(`app/evaluation/rubric.py`, 항목 `metadata.judge`의 인물·직전 장면·시점 위반 정답표)으로 한 번에 채점해 `voice`·`intent`(act)·`style`·`info`(narrate)·`pov_ok`를 0~1로 남기며(1~5점은 (점수−1)/4, `pov_ok`는 그대로), 짝이 아닌 지시문이면 422다. **추출 평가 세트**(`extraction.extract`, `app/evaluation/extraction.py`, #824)도 업무 Agent 틀이 아니라 실제 서비스 호출(`manuscript_extraction.agent.extract`에 그 버전 본문·모델, 결과는 `service.extract`와 같은 원문 인용 검증)로 만들고, 채점 모델 없이 정답표(상위 모델이 서로 다른 지시문으로 두 번 뽑은 결과)와 코드로 대조해 `recall`·`quote_ok`를 0~1로 남기며 짝은 `manuscript_extraction.extract`뿐이다([세트 문서](../../docs/evaluation/extraction-set.md)). 세트 파일은 게이트 30회차(`datasets/extraction.extract.jsonl`)이고 나머지 회차는 자동 개선용 최적화 풀(`datasets/optimize/extraction.extract.jsonl`, seed가 올리지 않고 게이트와 겹치지 않는다)이며, 해리 포터 원문 세트는 `eval/extraction/.data`(git 무시)에만 두는 로컬 전용이다. 채점 모델은 `EVALUATION_JUDGE_MODEL`(비면 `OPENAI_MODEL`)이다. Langfuse v4(`events_only`)는 Dataset Run API(`/datasets/{name}/runs`, `/dataset-run-items` GET)가 404라서 Run 생성·항목 실행은 SDK의 Experiment runner(`dataset.run_experiment`, `POST /dataset-run-items`는 우리 코드가 부르지 않는다), Run 조회는 Experiments API(`GET /api/public/experiments`)로 하고, Run 수준 점수는 그 실험 id(`Experiment.id`)를 `datasetRunId`로 달아 남긴다(읽는 법과 점수 이름은 [README](README.md)). 통과 기준은 실패한 항목이 없고 모든 지표가 기준 Run(현재 production 버전의 가장 최근에 끝나고 지표 평균이 남은 Run) 평균 − `EVAL_TOLERANCE`(기본 0.1) 이상인 것이며 기준 Run이 없으면 지표를 비교하지 않는다. 실패 항목은 0점이 아니라 점수 없는 실패다. 모든 항목이 실패해 SDK가 실험 id를 알려 주지 못하면 Experiments API에서 Run 이름으로 실제 실험을 찾아(이벤트 수집이 비동기라 최대 약 30초 다시 묻는다) `passed=false`를 남기고, 못 찾으면 점수 없이 고정 문구 오류 로그만 남긴다. 실행은 Celery 태스크 `evaluation.run`(큐 `jobs`, 계약 §4)이다: Router가 `prepare`로 확인을 마친 계획을 JSON 인자(`service.to_job`: 프롬프트 본문·기준 Run·허용 오차. 평가 세트 항목은 싣지 않고 워커가 `service.run_job`에서 이름으로 다시 읽는다)로 큐에 올리고 202 `{runName}`만 먼저 돌려주며(올리지 못하면 고정 문구 503) `ai-jobs-worker`가 실행해 재시작해도 큐에 남아 이어 실행된다. 인자의 프롬프트 본문은 로그에 남기지 않는다. `POST /internal/v1/evaluations/leak-check`는 응답이 비공개 참조(설정 카드·미발행 회차 제목)를 드러내는지 GEval 한 번으로 판정하며, 선택 `question`(사용자 질문 원문)을 입력에 함께 주면 질문에 이미 나온 이름을 되풀이하거나 근거가 없다고 답한 응답은 누설로 보지 않는다. 평가 세트는 `app/evaluation/datasets/*.jsonl`(저작권 만료 작품이고 시뮬레이션 세트는 CC BY-SA 3.0 SCP 이야기도 섞인다. 출처·라이선스는 항목 `metadata.source`·`license`)이고 `python -m app.evaluation.seed`가 Langfuse Dataset으로 멱등 등록한다. 채점 입력(질문·응답·참조)은 오류·로그에 남기지 않고, `ragas`·`deepeval`은 `--extra eval`이며 단위 테스트는 두 라이브러리를 `sys.modules` 대역으로 두어 설치 없이 통과한다.
- 프롬프트 자동 개선(`app/optimization/`, #823, [계약](../../docs/design/operations-llmops-contract.md#프롬프트-자동-개선-823-2026-11-24-사용자-결정), [평가 문서](../../docs/evaluation/prompt-optimization.md)): `POST /internal/v1/optimizations`가 접수만 하고(지원 대상 `service.OPTIMIZABLE`이 아니면 422, 같은 프롬프트가 실행 중이면 409 — AI 체크포인트 DB의 Postgres advisory lock) Celery `jobs` 큐의 `optimization.run`(**`acks_late=False`**: 수십 분 걸려 30분 확인 제한에 중복 배달되면 과금이 두 번 된다)이 실행한다. 한 trace `prompt_optimization` 안에서 풀·gepa·반성 게이트웨이(짧은 확인 호출 1회, `agent.check`)를 먼저 확인하고, production 기준 Run이 없으면 평가하며(기준·회귀 평가 Run은 `_evaluate`가 새 스레드에서 돌려 정식 평가처럼 자기 trace를 갖고 최적화 trace에는 Run 이름만 남는다), GEPA(`gepa`는 `--extra eval`이라 실행할 때 읽고 단위 테스트는 `sys.modules` 대역)가 `app/evaluation/datasets/optimize/`의 풀로 지시문을 고치며, 최고 후보가 시드보다 0.05 이상 나아야 하고 `SAFETY` 문장·길이 2배 이하를 지킬 때만 새 버전(**라벨 없음**)으로 저장한 뒤 게이트 세트 회귀 평가 Run 1회로 끝난다(후보 등록·서비스 반영은 사람). 안쪽 평가는 Langfuse Dataset Run 없이 `simulation.generate`·`simulation.grade`를 직접 부르고(`adapter.py`) 생성·채점 실패가 20%를 넘으면 중단한다. 반성 모델만 `PROMPT_OPTIMIZER_*`의 로컬 게이트웨이로 가고 생성·채점은 기존 OpenAI 키다(`agent.py`). GEPA 0.1.4는 반성 호출의 Exception을 삼키고 반복을 이어 가므로 반성 실패는 `BaseException` 하위 `_Stop`으로 끝낸다(`service.py`). 풀은 `eval/simulation/orig_cli.py export --pool`로 다시 만든다.
- 회차 원고 전처리(`app/preprocessing/`의 접수·worker, `app/manuscript_extraction/`의 추출·정체 통합)는 Content가 접수한 작업을 Celery 태스크(`preprocessing.run`, 큐 `preprocessing`)로 실행한다: 접수 API가 태스크를 큐에 올리고 202를 돌려주며(올리지 못하면 고정 문구 503) ai-service와 같은 이미지의 `ai-worker`가 `AI_PREPROCESSING_CONCURRENCY`(Compose 기본 3)만큼 작업을 동시에 실행하고(브로커는 Core와 같은 RabbitMQ 자격의 `AI_CELERY_BROKER_URL`), 작업당 미저장 회차는 최대 4개씩 동시에 추출한다. `acks_late`를 사용하며 회차 결과·구조화·적재는 순서대로 Content 내부 콜백(`/internal/v1/ai/manuscript-build/{job}/…`)으로 기록한다. AI는 정본 DB에 쓰지 않고, MCP 적재는 이 구현의 필수 의존성이 아니다(DEC-50, [최초 구축 저장 계약](../../docs/design/initial-build-storage-contract.md#업로드-자동-시작과-celery-큐-2026-11-20-사용자-결정), [전처리 계약](../../docs/design/manuscript-preprocessing-contract.md)). 그 밖의 기능에 Celery를 쓰려면 먼저 문서로 정하며, 회귀 평가와 운영 정기 작업은 [운영 계약 §4](../../docs/design/operations-funnel-credit-contract.md#4-작업-실행을-celery로-이관-리팩터링-2026-11-20-사용자-결정)로 정했다.
- 작업 실행(`app/jobs/`, [계약 §4](../../docs/design/operations-funnel-credit-contract.md#4-작업-실행을-celery로-이관-리팩터링-2026-11-20-사용자-결정)): `ai-jobs-worker`(ai-service와 같은 이미지, `-Q jobs`, 동시성 `AI_JOBS_CONCURRENCY` 기본 4)가 jobs 큐의 태스크 둘(회귀 평가 `evaluation.run`, 운영 정기 작업 `operations.run_job`)을 실행한다. Celery 앱·설정(`acks_late`·prefetch 1·결과 저장 없음)은 `app/preprocessing/worker.py`의 것을 가져다 쓰며 전처리 `ai-worker`(`-Q preprocessing`, `AI_PREPROCESSING_CONCURRENCY` 기본 3)와 큐를 분리한다. `POST /internal/v1/jobs {runId, kind}`는 운영 스케줄러가 접수시킨 실행을 큐에 올리고 202를 돌려주며(내부 토큰 `X-Internal-Token`, 올리지 못하면 고정 문구 503이라 운영이 그 기록을 failed로 남긴다), 태스크는 운영 내부 `POST /internal/v1/jobs/runs/{runId}/execute`(`X-Internal-Token`, 주소는 `OPERATIONS_SERVICE_BASE_URL`)를 불러 운영 서버가 기존 handler를 실행하고 상태를 기록하게 한다. 작업 기록·`queued` 선점·중복 배달 거절은 운영이 맡고 AI는 실행 기록을 갖지 않는다. 운영이 거절·장애로 답하면 태스크를 실패로 남길 뿐 자동으로 다시 하지 않는다.
- AI 자율 연재(`app/serial/`, #659, [계약](../../docs/design/ai-serial-contract.md)): Content가 넘긴 문맥(작품 소개·최근 회차 원문 `episodes`·이전 회차 요약 `summaries`·설정 카드·회차 실행의 관련 장면 인용 `related`)만 쓰고(Content MCP·검색·색인 없음, 사용자 토큰은 시뮬레이션의 선택 `X-User-Authorization`이 추적의 회원 식별에만) 다음 전개 선택지 4개(`serial.choices_v2`), 발행 회차의 줄거리 요약 400자 이하(`POST /internal/v1/serial/summaries`, `serial.episode_summary`), 제안 글의 장면 미리보기(`serial.simulation_v2`), 다음 회차(1위 선택지가 중심 전개: 투표·제안 종합 `serial.vote_summary` → `app/writing` 기획 → **인물 시뮬레이션**(`app/simulation` 엔진을 반드시 거친다: 요청의 `world`(MCP `world_studio_read` 모양 + `identity`)로 `simulation.world_from`이 만든 `World`에서 엔진 계획 모델이 1위 선택지·추천 상위 제안 글로 계획을 세우고 장면 1개를 `pausing=False`로 끝까지 쓴다. 인물 카드 없음·계획 오류·장면 미완료는 대체 없이 엔진의 문구 그대로, 시간 초과(`SIMULATION_TIMEOUT` 1,200초)는 504로 실패) → 그 장면을 뼈대로 집필 `serial.episode_draft`(최소 5,000자이고 모자라면 모델 검수 없이 실패) → 검수 `serial.episode_review_v3`(설정 충돌·개연성·19세 이용가·1위 선택지 반영·시뮬레이션 장면 반영), 검수 실패는 장면을 다시 돌리지 않고 1회 재작성 뒤 422 `SERIAL_REVIEW_FAILED`)를 만든다. 회차 실행 라우트는 `async def`다: 연출 분류기의 HTTP 클라이언트가 앱 이벤트 루프에 묶여 있어 요청마다 새 루프를 만들면 두 번째 요청부터 깨지고, 블로킹 모델 호출은 스레드로 보낸다. 요청의 `creditLimit`을 `agent_runtime.CreditMiddleware`에 주어 요청 안 모든 모델 호출의 토큰(1 크레딧 = 1,000 토큰)을 누적하고(`create_agent` 호출은 미들웨어가, 시뮬레이션 엔진의 호출은 호출마다 알리는 `MODEL_EVENT`를 `CreditLedger`가 더한다), 상한 이상이면 다음 호출 전에 402 `CREDIT_LIMIT_EXCEEDED`로 끝내며 응답 `credits`(상한 이하)로 Content가 정산한다. 선택지·시뮬레이션·검수 프롬프트는 `summaries`로 전체 흐름을, `related`로 이어 쓸 옛 장면을 참고하되 그대로 베끼지 않게 하며, Writing 기획 지시는 그대로라 같은 안내를 요청 자료에 싣는다. 지시문이 바뀐 프롬프트는 Langfuse에 이미 있는 production 버전이 코드 시드를 가리므로 이름을 새로 짓는다(`serial.summary`·`serial.review`는 더 쓰지 않고, 문맥 개편 때 `serial.choices`·`serial.simulation`·`serial.episode_review`에 `_v2`를 붙였고 인물 시뮬레이션 개편 때 검수는 `_v3`, 집필은 새 프롬프트 `serial.episode_draft`다).
- 장애는 명시적 오류로 반환하고 fallback·자동 재시도로 숨기지 않는다. 입력·원고·모델 응답을 오류 메시지나 로그에 넣지 않는다. 역할·인물마다 서버나 클래스를 만들지 않는다.
- 이미지 생성은 [이미지 계약](../../docs/design/image-generation-contract.md)에 따라 별도 `storyfork.images` Celery 큐와 워커를 사용한다. `observe`에는 모델·규격·용도·템플릿 버전·사용량·실패 유형만 남긴다. 프롬프트 원문·이미지 바이트·base64·키·제공사 예외 본문은 추적 input/output에도 넣지 않는다.

## 생성 경계

- 허용 문맥과 작업 범위로만 조회하고 정본 수정·권한·승인·과금을 확정하지 않는다. 결과는 제안으로 반환한다.
- 콘텐츠 생성의 기준 버전·조회 범위·제안 저장과 채택은 Content가 소유한다. Content 조회·작업 도구는 Content MCP 창구(DEC-49)를 호출한 사용자의 토큰으로만 쓰고, 모델이 제시한 식별자는 인가 근거로 사용하지 않는다.
- 설정 카드 본문 링크(`[글자](card:<uuid>)`, DEC-53)는 Content MCP 응답을 스냅샷·요청으로 바꾸는 곳(`novelbrain.world_snapshot`, `world_review`의 채팅 경로)에서 `app/card_links.strip_card_links`로 모두 글자로 벗기고 링크가 아닌 모양에 남은 `card:<uuid>`도 지운다. 모델 입력과 BM25에 카드 id가 섞이지 않게 하는 입력 경계라, 스냅샷을 두고 응답 원본에서 카드·관계 본문을 따로 읽지 않는다([링크 규칙](../../docs/design/worldstudio-independent-schema.md#카드-본문-링크--dec-53)).
- 실행용 상태·색인은 해당 기능의 설계 계약을 따른다. 실행 완료·제안 채택·원고 반영·과금 확정은 각각 소유 서비스가 검증한다.
- 캐릭터별 허용 기억·관찰 정보를 분리하고 다른 인물의 비밀이나 미래 사건을 누출하지 않는다.
- 피드백 유형은 독자가 고르며 AI로 분류하지 않는다(BR-15). 오류 수정도 수정안까지만 생성한다.

## 변경 범위와 검증

- 테스트는 `tests/<기능>/`에 계층별 `test_models.py`·`test_agent.py`·`test_service.py`·`test_router.py`로 두고 각 디렉터리에 `__init__.py`를 둔다.
  TestClient 경계는 같은 디렉터리의 `test_http.py`(integration marker)에 둔다. [테스트 배치](docs/agent-structure.md#테스트-배치)
- 로컬: `backend/ai-service`에서 `uv run --locked --extra dev python -m pytest -m 'not integration' <대상 파일> -k '<대상>'`로 단위만 실행한다.
  제공사는 monkeypatch 대역을 쓰고 FastAPI TestClient는 통합(`integration` marker)으로 분류해 CI에서 실행한다.
- 기본 단위 테스트와 CI는 모델 대역을 사용한다. 집필 AI 기능별 수용은 사용자가 요청한 개발 방식에 따라 개발용 데이터·키·호출 상한을 정하고 실제 OpenAI API로 별도 검증한다. 키·원고를 로그나 저장소에 남기지 않는다. 상세는 [집필 AI 로드맵](../../docs/writing-ai-architecture/05-implementation-roadmap.md)을 본다.
