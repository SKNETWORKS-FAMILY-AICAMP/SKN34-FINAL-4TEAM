# 세계관 직접 작성·저장·재조회 (첫 공유 단위)

현재 사용자 확인 URL은 http://127.0.0.1:5175/worlds 이며, Core 8086의 새 preview-db를 사용한다. 기존 합성 QA 자료는 Core 8087/qa-db에 보존했다. 아래 이전 기능 검증과 현재 환경 분리 기록을 구분한다.

최신 develop `b70cbb9`에서 분리한 `feature/world-studio-direct`의 미커밋 변경이다. React `/worlds/:worldId?`에서 목록·이름/선택 설명 생성·항목 이름/내용/내 분류/태그 작성·수정·확정 저장·재조회를 수행한다. 새 소설 화면은 저장한 서버 세계관만 선택한다. 기존 가져오기·작품·회차·Fork의 메모리 데모는 보존한다.

Core `/api/v1/studio/session`, `/api/v1/studio/worlds`, `/api/v1/studio/worlds/{id}`를 사용한다. 생성 POST, 저장 PUT, 조회 GET이다. 소유자 기준 조회·저장과 버전 비교를 검사하고 모든 저장본을 별도 revision에 보존한다. 항목 ID와 여러 줄·구분자를 포함한 원문을 그대로 보관한다. 기존 항목의 파괴적 제거는 차단한다.

이 단위에는 AI 클라이언트·분석/승인 엔드포인트·후보·LLM topics·Wiki·관계도·시간선이 없다. 인물·장소는 entity/character·location, 설정집 영역은 fact, 집필 메모는 note로 직접 작성한다. 분류 영역과 대상 종류를 저장하며 AI 계약은 후속 단위에서 확장한다. AI 서비스가 없어도 동작한다.

루트 `.env`의 `STUDIO_ENABLED=true`, 독립 `STUDIO_DB_URL=jdbc:h2:file:<개인 로컬 경로>`를 Core에만 전달한다. 기본값은 기능 비활성화·메모리 H2이며, 영속 로컬 실행에는 파일 URL을 지정한다. native launcher는 `python infrastructure/scripts/run-native.py core-api|web`이다. `.env`·DB 파일은 공유하지 않는다.

로컬 session은 loopback/Origin 제한과 author/reader1/reader2 테스트 식별자를 사용한다. 운영 계정 인증이 아니다. PostgreSQL·그래프 DB·항목별/회차별 공개·이미지/URL·초안 자동저장·이력/revert UI·Fork 동기화는 미구현이다. 기본 비공개이며 화면을 저장한 것을 공개·발행으로 처리하지 않는다. 작성 메뉴는 원본 InitialWorld·SettingBook의 UI를 계승한 것이며 최신 기획의 의무 입력 목록으로 확정하지 않는다. 내 분류는 자유 입력이고 태그와 함께 AI topics와 별개다.

검증: 관련 프런트엔드 21개, Core 5개 테스트 통과. `tsc -b`와 Vite production build 통과(기존 단일 번들 500KB 경고). `oxlint` 변경 경로 및 impeccable detector 통과. 독립 실행 URL과 브라우저 증거는 공유 준비 문서에서 관리한다. 원격 Required CI는 게시 승인 전이므로 검증 대기다.

기존 Issue #7/#29/#30/#33 수정은 독립 후속 단위다. 이 PR이 해당 Issue 전체를 해결한다고 주장하지 않는다. 새 Core 경로의 소유자·충돌·오류 보존 검증은 첫 단위 자체의 책임이다.

## 원본 메뉴 복원

상단 세계관 작업실에서 `/worlds` 목록으로 바로 진입한다. 세계관 화면의 세계관 작업실 버튼도 같은 목록으로 이동하며, 내 서재의 세계관 진입 카드도 세계관 작업실로 표시한다. 별도 작품/회차 집필 화면의 작품 작업실 명칭은 유지한다. 인물·장소 입력과 설정집 목차를 통합해 인물, 장소, 기본 설정, 시공간·장소, 역사, 사회·조직, 문화·기술, 특수 규칙, 주요 갈등, 집필 메모를 메뉴로 제공한다. 각 메뉴에서 목록·추가·수정·확정 저장·재조회가 가능하다. 인물·장소는 이름만 필수이며 소개는 비워둘 수 있다. 7개 영역/27 topics를 채우도록 강제하지 않는다.

기존 fact JSON은 category=basic, entityType=null, topics=[] 기본값으로 계속 읽는다. 기존 world/item ID와 revision은 보존하며 DB 재생성이나 초기화를 수행하지 않는다. 메뉴 간 이동은 저장하지 않은 입력을 버리지 않는다. 새 메뉴는 kind/category/entityType에 따라 항목을 표시하며 사용자 분류·태그로 대상을 추정하지 않는다.

Aside CLI E2E에서는 10개 메뉴별 생성·수정·저장·새로고침과 동일 ID/종류/영역/원문/분류/태그 재조회를 확인했다. 빈 본문 오류에도 기존 DB는 유지됐고 기존 QA 세계관은 바뀌지 않았다. 실제 950px·488px 화면 캡처에서 메뉴 표시와 가로 넘침 없음을 확인했다. 태그 값을 바꾸지 않은 Tab/blur도 저장 완료 상태를 유지한다. 증거는 로컬 output/world-studio-direct/menu-*이며 공유 patch에서 제외한다. 최신 테스트·빌드·관련 lint가 통과했고, 원격 Required CI는 여전히 검증 대기다.

기존 QA 2개 세계관/8개 이력은 3개 허용 actor 전체를 조사해 합성 ID로 확인했다. 미분류 또는 사용자 작성 world는 없었다. 기존 QA 파일은 삭제·초기화·이름 필터링하지 않았다. 사용자 확인 DB는 새 독립 파일이며 자동 예시/seed를 넣지 않는다. 알려진 QA ID 3164a5b4-6b5c-4193-9212-a3bb601e62a5는 이 환경에 없으며, 상세 조회 실패 시 ‘이 환경에서 세계관을 찾을 수 없습니다. 세계관 작업실로 돌아가 목록에서 선택하거나 새로 만들어 주세요.’를 표시한다. 화면의 세계관 작업실 버튼은 /worlds로 이동한다. 새 확인 URL은 /worlds이며 이전 QA 상세 URL을 사용자 시작 주소로 배포하지 않는다.

로컬 runtime helper는 `--profile preview core`(8086/preview-db)와 `--profile qa core`(8087/기존 qa-db)를 필수로 구분한다. 5175의 Vite proxy는 계속 8086만 사용한다. profile별 jar/PID/log/config를 분리하고, 점유 port 재사용과 QA의 web 시작을 거부한다. 이 helper·DB·보존 사본·로그·JAR·PID·브라우저 증거는 output 아래 로컬 산출물로 PR에 넣지 않는다. 공유 환경 예시는 STUDIO_DB_URL=jdbc:h2:file:./local-world-studio-user이며 QA는 ./local-world-studio-qa 같은 별도 파일 URL을 명시한다. 실제 .env는 수정하지 않았다.

이번 환경/404 수정 후 양쪽에서 HTTP Repository·ViewModel·App 메뉴 회귀 9개씩 통과했다. 이전 명칭 변경 13개 및 이전 기능/Core 검증과 구분한다. 404 안내의 경로 제한 후 HTTP 5개씩도 재확인했다. 실행 profile 분리/명시 인자/QA web 거부는 assert로 검사했다. Core 소스/계약 변경이 없어 Core 테스트·유료 AI 호출은 새로 실행하지 않았다. 원격 Required CI는 대기다.

이번 환경 전환 후 Aside CLI에서는 사용자 확인 DB에 world 생성/저장 요청을 보내지 않고, /worlds 빈 목록·필수 이름 검사·폼 입력 가능·입력값 비우기를 확인했다. 이전 QA 상세 ID는 명확한 ‘이 환경에서 찾을 수 없음’ 안내가 나오고, 화면의 세계관 작업실 버튼으로 /worlds 빈 목록에 복귀했다. 사용자 DB는 최종 GET에서도 0개다. 생성 후 10개 메뉴/저장은 보존된 기존 QA 환경 증거와 이번 격리 App 메뉴 회귀에서 확인한 범위이며 사용자 DB를 시험 데이터로 오염시키지 않았다. 새 사용자 확인 화면은 preview-final.png, 이전 QA 링크 안내는 preview-old-qa-link.txt, 사전 입력 보존은 preserved/pre-environment-*에 기록했다. 실제 QA/preview DB와 런타임 파일은 manifest 제외를 별도로 검사했다.

## 사용자용 화면 문구 정리

세계관 화면의 ‘DB 저장본 · 버전 N’과 목록 버전을 제거하고 ‘저장됨 / 저장하지 않은 변경사항’, ‘저장’으로 정리했다. 항목 UUID 표시와 기본 분류 ‘설정’의 반복 노출을 제거했으며 내부 ID·버전·저장 계약은 유지한다. ‘세계관 편집’ legend는 접근성 그룹 이름으로 유지하되 실제 숨김 CSS를 명시해 이름 레이블 앞에 붙어 보이지 않게 했다. 이 화면의 W01/화면 ID 조작은 노출하지 않는다. 체험용 연결은 접힌 ‘체험 환경 안내’ 안의 ‘작업실 연결’로 제공하고 실제 계정 로그인이 준비 중인 사실은 사용자 언어로 설명한다.

양쪽에서 App 메뉴/저장 회귀, ViewModel, HTTP 9개씩을 통과했다. UI 회귀는 저장 상태·버튼, 항목 ID/개발 문구 부재, 중복 제목의 숨김 표시와 10개 메뉴 저장/재조회를 확인한다. 실제 사용자 확인 DB에는 생성/저장을 호출하지 않고 Aside CLI로 조회·화면·computed style·스크린샷만 확인한다. 현재 사용자가 만든 world가 존재하므로 앞선 ‘빈 DB’는 환경 전환 당시의 결과이며, 이후 사용자 작성 데이터는 그대로 유지한다. 기존 QA는 별도 8087/qa-db에서 보존한다.

### 작성 메뉴·자유 분류·LLM topics의 구분

원본의 인물·장소 입력, 7개 영역 목차, 집필 메모를 합친 **10개 작성 메뉴는 탐색/작성 UX**다. `kind/entityType/category`는 현재 의미 표현·정리용 데이터이며, `userCategory`는 자유 입력이고 `tags`는 자유 태그다. 이들을 #48의 확정된 고정 카테고리 목록으로 선언하지 않는다. 고정 카테고리 하나를 선택·검증하는 제품 계약은 목록 합의 후 별도로 정리해야 한다.

LLM `topics`(7개 영역/27개 세부 점검)는 선택적 AI의 의미 점검 메타데이터이며 사용자 분류·태그와 별개다. 필수 입력이 아니고 첫 PR의 직접 작성은 AI 없이 동작한다. 첫 PR에는 AI 요청/승인 기능을 넣지 않으며 AI 호출은 #48의 필수 완료 조건이 아니다. 후속 AI 단위도 #48 전체 완료를 의미하지 않는다.
