# 초기 세계관 AI 추출 5-B

상태: 내부 API와 실제 Responses API 코드 경로 구현, 제공사 대역으로 검증. 유료 모델 호출·실제 추출 품질·배포 검증은 미실행이다. #219 → #225 선행 병합 순서를 유지하며 #235와의 Content 연결은 5-C다. #122 회차 추출과 별도 범위다.

## 호출 계약

`POST /internal/v1/initial-world/extractions`, `X-Internal-Token`은 기존 `INTERNAL_TOKEN`과 대조한다. 요청 본문은 #219 `Input`, 성공 본문은 #219 `Output` 그대로다. 분석 ID/세계관 ID/기준 버전은 입력을 변경 없이 모델에 전달하며 별도 실행 봉투나 신규 공개 DTO를 만들지 않는다. 5-C Content 호출자가 요청의 analysisId·basis와 반환 Output을 연결해야 한다.

`OPENAI_API_KEY`·`OPENAI_MODEL`을 기존 방식으로 요청 시 읽는다. 새 환경변수·의존성·프레임워크는 없다. `responses.create`, `store=False`, 60초 timeout, SDK 재시도 0회, 최대 출력 8,000 token과 strict JSON Schema를 사용한다. 지정 모델이 Structured Outputs를 지원하지 않으면 명시적 제공사 오류다. 8,000 token에서 잘린 응답을 성공으로 처리하거나 보정 재호출하지 않는다. [OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)를 따른다.

## 검증과 근거

- 입력 sourceId/ownerId/field, 출처·엔터티 ID 유일성, Unicode, 출처 해시와 #219 정규 입력 해시를 검증한다. Content가 소유권·실제 DB 원문·최신성 검증을 담당한다. AI는 저장소를 조회하지 않는다.
- 모델에는 기존 ID·원문을 데이터로 전달한다. 원문의 명령·역할 변경은 지시가 아니며 도구를 제공하지 않는다. 프롬프트 테스트는 이 분리와 검증 경계를 확인할 뿐 실제 모델의 공격 저항성을 증명하지 않는다.
- 중간 모델 출력은 sourceId/quote만 가진다. 좌표·해시 필드는 금지한다. 프로그램이 정확한 인용을 검색하고 유일한 위치에서 UTF-16 `[start,end)`와 UTF-8 SHA-256을 계산한다. CRLF·공백·Unicode를 정규화하지 않는다. 원문에 없거나 두 번 이상 등장하는 인용은 실패한다.
- 최종 Output은 #219 DTO로 재검증한다. 7종 유형, provenance, 고유 localRef, 기존 UUID 참조, 관계 양 끝·종류·방향, goal/plan 주체, 근거 필수 조건을 검사한다.
- 모델은 미등록 대상·모호한 참조를 diagnostics로 보고하고 후보에서 제외한다. 검증에서 잘못된 후보가 발견되면 일부만 버리고 성공하는 대신 요청 전체를 오류로 반환한다.
- 인용에 나타난 이름/별칭이 여러 ID와 겹치고 고유 이름으로 구별되지 않으면 참조를 거부한다. 프로그램은 일반적인 대명사 해소나 모든 동명이인 추론을 증명하지 않는다.
- 명시적 한국어 계획·예정·추측·추정·가능성·욕구 표현이 포함된 인용 문장을 fact/event로 승격하는 것은 보수적으로 거부한다. 이는 제한된 문자열 보조 검사이며 언어 전체의 의미 판정이 아니다. '계획을 취소했다' 같은 실제 사건도 거부할 수 있다. 실제 품질 평가 후 보완하며 후보의 의미적 사실성·작가 승인을 선언하지 않는다.

## 실패 응답

| 상태 | 의미 |
|---|---|
| 403 | 내부 토큰 누락·불일치 또는 서버 내부 토큰 설정 누락 |
| 422 | 입력 DTO·출처·해시 검증 실패 |
| 502 | 잘린/잘못된 모델 출력, 근거·ID·유형·모호성 검증 실패 |
| 503 | 모델 설정 누락 또는 제공사 API 오류 |
| 504 | 제공사 timeout |

오류에 후보 부분 결과나 제공사 내부 오류 원문을 포함하지 않는다. 진단만 있는 빈 candidates는 명시적 미해결 결과이며 저장·승인·확정 성공이 아니다. JSON Schema 일치는 형식 검증이고 모델 정확도 보증이 아니다.

## 검증·후속

#219 Input/Output 및 하위 `$defs`와 생성 Schema를 비교하고 홍길동전 정상 7유형 fixture를 실제 검증 경로에 통과시킨다. 선택 단위 테스트는 제공사 대역, HTTP 테스트는 integration marker로 CI에서만 실행한다. 기존 `/internal/v1/proposals` 코드는 변경하지 않는다.

5-C: Content 인증/소유권 입력 구성, #225 분석 결과 저장, 요청 멱등성·deadline·실행 상태·부분 실패/트랜잭션 연결. 작가 검토·승인·초안 반영·확정은 그 이후이며 이번 API는 DB/Neo4j/UI를 수정하지 않는다. 실제 모델 비용 발생 테스트와 품질 평가는 별도 승인/작업이다.
