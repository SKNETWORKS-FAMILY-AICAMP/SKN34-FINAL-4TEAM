# 초기 세계관 분석 입력 스냅샷 (5-A)

이 구현은 저장된 세계관 초안을 분석 입력으로 고정하는 내부 준비 단계다. 분석 API, AI 호출, 후보 저장·반영은 제공하지 않는다. 입력 계약은 검토 중인 [PR #219](https://github.com/SKNETWORKS-FAMILY-AICAMP/SKN34-FINAL-4TEAM/pull/219)을 기준으로 하며, `6c5ed7d8`의 실제 JSON Schema 및 공유 fixture로 호환성을 검사한다.

- 소유자 확인을 거친 초안의 `draftRevision`, `relationshipVersion`, `currentRevisionId`를 기준으로 기록한다. 관계 저장이 미완료면 스냅샷을 만들거나 사용하지 않는다.
- 세계관 설명과 활성 카드의 제목·본문을 가공하지 않고 출처와 UTF-8 SHA-256으로 기록한다. 활성 인물·장소·단체·능력·사물의 기존 카드 ID와 이름·별칭은 엔터티로 제공한다. 규칙·사건 등 다른 활성 카드도 원문 출처에는 남는다.
- 근거의 출처, UTF-16 구간, 원문과 UTF-8 해시를 검증하며 surrogate 쌍을 자르는 인용은 거부한다. 유효하지 않은 Unicode도 거부한다. 근거 검증만으로 저장된 초안의 소유권·진위를 확인할 수 없으므로 반드시 아래의 잠금과 재검증 안에서 사용한다.
- 입력 해시는 분석 ID와 해시 필드를 제외하고 출처·엔터티를 ID순으로 정렬해 Python 계약의 정규 JSON으로 계산한다. 원본 문자열은 정규화하거나 편집하지 않는다.
- 사용 직전 같은 세계관의 소유권과 기준 버전 및 원문을 트랜잭션의 세계관 잠금 안에서 다시 검증한다. 후속 저장 작업이 이 잠금 안에서 수행돼야 하며 콜백 안에 외부 호출을 넣지 않는다. 이 단계에서는 후속 저장이나 외부 호출을 연결하지 않는다.

## 계약 호환 검증

`InitialWorldInputContractTest`는 실제 Jackson/Kotlin 직렬화 출력을 #219의 `$defs/Input` 스키마로 검사한다. 홍길동전 공유 Input의 왕복 직렬화, 기존 ID·원문·7종 후보 근거 보존, UTF-16 경계·해시와 잘못된 JSON 필드/UUID 거부를 확인한다. JSON Schema는 구조 검증이며 출처·원문·해시는 기존 Kotlin 검증으로 함께 검사한다.

#219 미병합 상태에서도 재현 가능하도록 해당 커밋의 JSON 두 파일을 Content 테스트 리소스에 원본 그대로 고정했다. 출처·해시는 리소스 README에 기록한다. 정식 문서 경로가 생기면 테스트는 그 파일을 사용하고 고정본과의 차이를 실패로 드러낸다. 테스트 실행 중 네트워크로 계약을 받지 않는다. 공유 fixture는 카드 body 하나만 포함하지만 저장 초안은 설명과 모든 활성 카드 title/body를 포함하므로 두 입력의 전체 해시가 같다고 가정하지 않는다.

JSON Schema 검증기는 testImplementation에만 추가하며 실제 서비스 의존성은 변경하지 않는다. #219 → #225 병합 순서는 유지한다. #219 계약 변경 시 고정본 재검토, #225 병합 후 실제 저장·PostgreSQL 동시성/롤백 검증은 여전히 필요하다. 이 단위 검증을 실제 분석 요청이나 DB 통합 완료로 간주하지 않는다.
