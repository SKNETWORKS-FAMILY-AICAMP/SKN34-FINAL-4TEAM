# STORYFORK 시스템 아키텍처 설계 — PostgreSQL·관계 그래프 기반 MVP

[메인 README](../../README.md) · [문서 목록](../README.md)

> **DEC-41 목표 경계 · 분리 구현 전.** [Core·콘텐츠·운영·AI 책임](service-boundaries.md)에 맞춰 아래 본문을 구분합니다. 현재 `core-api`의 인증·콘텐츠·첨부 공존과 기존 URL·데이터·Flyway 이력은 유지하며 별도 콘텐츠·운영 앱과 DB 이전은 아직 실행하지 않았습니다.

> **상태: 목표 설계 · 일부 업무 구현, 서비스 분리 미실행.** [결정 기록](decisions.md)의 DEC-41과 DEC-36~40 및 이전 최신 결정들이 충돌하는 기존 MVP 설계보다 우선합니다. 사용자가 수정한 [시스템 구상도](../deliverables/SKN34-final-4Team_시스템%20구상도.pdf)의 그림은 방향 참고 자료이며 PDF 본문·기존 [유스케이스](../usecase.md)와 [상세 명세](../usecase-spec/README.md) 중 옛 저장소·공개 정책과 충돌하는 부분은 현행 MVP 계약이 아닙니다. 이전 [RDB 단독 MVP 설계](archive/rdb-mvp/design.md)와 [KAG 설계](archive/kag-design/design.md)는 보관본에 남깁니다.

## Overview

### 목표

작가는 단일 세계관에서 설정집·스토리 설계·원고를 관리하고 직접 집필하거나 선택적으로 AI 도움을 받습니다. 독자는 발행 회차를 읽고 허용된 작품을 Fork해 독립적으로 이어 씁니다. AI 시뮬레이션은 집필 보조이며 채택하지 않은 결과는 작품 상태를 바꾸지 않습니다.

### 표기

| 표기 | 의미 |
|---|---|
| `현재` | 코드 또는 실행 설정으로 확인된 상태 |
| `확정` | 사용자가 정한 MVP 방향 |
| `제안` | 검토할 구현 후보, 미확정 |
| `미정` | 결정 전에는 계약·스키마로 단정할 수 없는 사항 |

### 현재와 목표

| 영역 | 현재 | MVP 방향 |
|---|---|---|
| Frontend | Health·인증/프로필, 선택적 콘텐츠 작업실과 서버 집필실. 나머지 목업과 구분 | 작가·독자 화면에서 단일 공개 진입점으로 각 업무 API 사용 |
| Core Service | 기존 `core-api`에 인증·세션·프로필 및 콘텐츠·첨부 구현 공존 | 회원·인증·세션·크레딧·정산·회원 알림 정본. 기존 앱 재사용 |
| 콘텐츠 서비스 | 별도 앱 없음. 현재 콘텐츠·첨부는 `core-api`에서 실행 | 별도 Kotlin/Spring Boot 앱에 작품·세계관·회차·버전·Fork·발행·독서·검색·작품 피드백·파일 및 콘텐츠 인가·채택·반영 |
| 운영 서비스 | 별도 앱 및 고객지원·신고 사건 등 업무 기능 미구현 | 별도 Kotlin/Spring Boot 앱에 문의·공지·이벤트·신고·소명·판단·감사·작업 감시·LLMOps 영역 |
| AI Service | 내부 Health·선택적 `/internal/v1/proposals` 모델 실행·FixtureContent 전용 `/internal/v1/ai/runs` | Python/FastAPI 실행. Run의 실제 Content·모델·저장 연결은 미구현. [TASK 09](../writing-ai-architecture/task09-handoff.md) |
| 저장소 | PostgreSQL·Flyway 인증 및 선택적 콘텐츠/첨부 저장, 선택 MinIO 구성. 그래프 DB 없음 | 서비스별 정본·쓰기·migration 소유 분리. PostgreSQL 원문·버전·체크포인트·Fork와 관계 그래프 역할 유지 |

`Core Service`는 설계상 서비스 명칭이며 현재 디렉터리·컨테이너·패키지·HTTP 경로의 `core-api`를 지금 변경한다는 뜻은 아닙니다. `Core API`는 공개·내부 HTTP 인터페이스를 뜻할 때만 씁니다. DEC-41은 별도 콘텐츠·운영 앱을 목표로 확정하지만 실제 앱·포트·DB 소유 전환은 후속 작업입니다. [현재 실행 구조](../architecture.md)를 구분해 읽습니다.

## MVP 범위

MVP는 팀 시연용 핵심 흐름입니다. [DEC-22~25](decisions.md#결정-목록) 중 새 결정과 충돌하지 않는 범위는 유지합니다. 아래 시연 흐름은 동작 순서 예시이며 스토리 설계 단계와 AI 실행을 모든 집필의 필수 절차로 정하지 않습니다. 실제 화면 수·입력 필수 단계·API 계약은 미정입니다.

### 시연 흐름

1. 작가가 단일 세계관을 만들고 항목마다 카테고리 하나와 여러 태그를 두어 설정 문서를 작성하며 관계를 기록합니다. 인물의 기본 설정과 회차별 상태·지식은 세계관과 함께 이어집니다. 플롯의 예정 사건은 원고에서 확정된 사실이나 현재 관계로 자동 반영하지 않습니다(DEC-31·33).
2. 큰 줄거리·회차별 플롯·장면 계획을 거쳐 원고를 직접 쓰거나 선택적으로 AI 제안·인물 시뮬레이션을 사용합니다. 원작 원고를 회차별로 등록해 요청한 범위를 설정 후보로 추출·검토하는 기존 흐름도 유지합니다(DEC-24).
3. 작가가 채택한 제안만 권한과 기준 버전을 확인해 반영합니다. 콘텐츠 확정 변경·되돌리기는 과거 버전을 지우지 않고 새 버전으로 남깁니다. 회차에 당시 세계관·관계를 묶는 체크포인트를 둡니다(범위·시점은 미정).
4. 독자가 발행 회차를 읽고 허용된 기준 지점에서 작품을 Fork해 자기 이야기를 만듭니다. 기준 회차까지 공개된 원작 설정을 이어받고 수정 전에는 원본의 허용된 변경을 따라갑니다. 최초 설정 수정 시 세계관 전체를 독자 소유로 Fork하고, 이후 원본 변경은 알림을 보고 독자가 반영 여부를 정합니다(DEC-32·34). 원작 원고 옆 AI 채팅·설정 안내는 선택적이며, 대화만으로 변경하지 않습니다. 댓글·제보와 작가 확인은 기존 MVP 범위를 유지합니다.

### 포함과 제외

| 기능 | MVP 방향 | MVP 이후·미정 |
|---|---|---|
| 설정·집필 | 단일 세계관, 고정 카테고리 하나·자유 태그 여러 개, 인물 상태·지식·관계, 스토리 설계·원고·발행. 설정·관계 이력은 revert로 정정. 설정 이미지는 항목당 최대 10개 MinIO 업로드·RDB URL, 외부 참고 URL 지원. 설정 초안은 덮어쓰고 확정 저장은 새 버전(DEC-39·40) | 고정 목록·이미지 접근·정리·동시 수정·현재 포인터 `미정`; 타인 세계관 직접 이용·여러 세계관 결합·원고 파일 업로드는 MVP 이후(시점 미정) |
| 관계 | 인물 및 엔티티 간 관계를 그래프 DB에서 저장·조회 | 그래프 DB 제품·버전 정합성·관계 정본 여부 `미정` |
| 체크포인트·Fork | 회차와 당시 상태 연결, 작품 Fork 시 기준에 공개된 세계관 전체 상속. 해당 회차에 영향을 주는 원본 변경 추종, 첫 수정 시 전체 세계관 Fork, 이후 변경 알림·선택 반영 | 공개 범위·본문 판정의 구현, 관계 정합성, 복사와 rebase의 세부·충돌 처리 `미정` |
| AI | 선택적 집필 보조·인물 시뮬레이션, 사용자 검토·채택. 수동 원고 설정 추출(DEC-24) | 대화 상태 저장은 LangGraph PostgresSaver `후보`; 도입 여부·버전, AI 조회 경로·모델·프레임워크 `미정`. 자동 발행·자동 추출은 이후 |
| 공개·권한 | 설정은 항목별 공개·비공개와 회차별 공개 범위를 두며 기본 비공개. Fork 생성·공개는 별도 허용, 공개 Fork에 원작·원작자 표시(DEC-36·38) | 권한 판정의 물리 구현과 상세 화면 `미정`. 등록자 권리 확인만으로 법적 권리 확보가 보장되지는 않음 |
| 계정·피드백 | 가입·로그인, 독자 댓글·제보와 작가 확인(DEC-22) | 갱신 토큰·이메일 인증, AI 피드백 응대·크레딧 등 기존 제외 범위 |
| 인프라 | PostgreSQL·Flyway, 관계 그래프 DB, 설정 이미지용 MinIO(S3 호환) | Gitea는 사용하지 않음; `pg_git`(seanwevans/pg_git)·KAG·Langfuse·pgvector는 MVP 미적용 |

게시판 방식은 **항목별 문서를 작성·목록화·분류한다**는 뜻이지 댓글·좋아요 등 설정집 커뮤니티 기능을 추가한다는 뜻이 아닙니다. 설정 문서 변경을 매번 댓글 행으로만 저장한다는 옛 규칙도 확정하지 않습니다.

## Architecture

### 구성과 호출 방향

```text
작가·독자 → Frontend → 단일 공개 진입점 (기존 nginx 확장 후보)
                        ├─ Core: 회원·인증·크레딧·알림
                        ├─ 콘텐츠: 작품·세계관·회차·Fork·독서·검색·피드백·파일
                        │    ├─ PostgreSQL·MinIO·관계 그래프 (각 저장 역할·제품 결정에 따름)
                        │    ├─ Core: 공통 사용자 업무·정산·알림 사건
                        │    └─ AI: 허용 문맥에서 생성·추출·시뮬레이션
                        └─ 운영: 문의·공지·이벤트·신고·판단·감시·LLMOps
                             ├─ Core: 회원 제한·보상·알림 사건
                             ├─ 콘텐츠: 허용된 조회·콘텐츠 제한 적용 요청
                             └─ AI: 운영 검사·평가 (연동 계약 미정)
```

- 위는 목표 흐름입니다. 현재는 `web`·`core-api`·`ai-service`가 실행되며 콘텐츠는 `core-api` 안에 있습니다. 공개 URL·쿠키·CSRF·응답 계약은 이전 전 보존합니다. Core를 모든 업무 요청의 중앙 프록시로 만들지 않습니다.
- Core는 인증·크레딧·회원 알림, 콘텐츠는 콘텐츠 인가·사용자 채택·저장·발행, 운영은 사건·판단·조치 요청/결과를 소유합니다. 운영이 회원·콘텐츠 정본을 직접 수정하지 않고 소유 서비스가 실제 조치를 적용합니다.
- AI 문맥의 대상·기준 버전·공개·인물별 인지 범위는 콘텐츠 서비스가 판단합니다. 콘텐츠 경유 읽기 전용 도구는 후보이며 직접 DB 조회 여부와 접근 제어 계약은 미정입니다. AI에는 정본 쓰기 권한을 부여하지 않습니다.
- PostgreSQL 서버 공동 사용·서비스별 소유 범위 분리를 출발안으로 삼고 각 서비스의 계정·스키마·Flyway 전환을 후속 설계합니다. 다른 서비스 테이블 쓰기·교차 소유 JPA 트랜잭션은 사용하지 않으며 HTTP 호출의 원자성을 가정하지 않습니다.
- 예약 발행·자율 연재는 콘텐츠, 크레딧 소멸·탈퇴는 Core, 운영 기록·LLM 평가 관리는 운영 업무입니다. 실제 실행·중복 방지·복구는 업무 소유 서비스, 감시·재실행 요청은 운영에 둡니다. 중앙 스케줄러·별도 Start 서버·공통 starter는 선제 추가하지 않습니다.
- LLMOps는 운영 영역입니다. Langfuse는 도입 시 별도 제품 서비스로 배포하며 Spring Boot로 재구현하지 않습니다. 자체 UI와 우리 운영 화면 API 통합, 평가 실행·보관 계약은 미정입니다. MVP 이후라는 기존 범위는 유지합니다.
- 현재 Compose는 TLS 없는 로컬 검증용입니다. 기존 Core↔AI 인증 유예(DEC-19)는 이 경계에 한정되며 포트 비공개가 인증은 아닙니다. 분리 후 서비스 인증·세션 폐기 전파는 후속 계약입니다.

## Data Models

### 데이터 소유

| 대상 (목표 콘텐츠 정본) | 저장 역할 | 제약 |
|---|---|---|
| 설정 문서·소설 본문·플롯 | PostgreSQL 원문 | 문서와 회차·작품을 연결. 확정된 변경은 새 버전으로 보존 |
| 문서 버전·되돌리기·체크포인트·Fork | PostgreSQL | 확정 이력을 덮어쓰지 않음. 설정 초안 자동저장은 같은 초안을 덮어씀(DEC-40) |
| 설정 이미지 | MinIO(S3 호환) 파일, RDB에 URL | 항목당 최대 10개. 이미지 이전 파일 이력은 보존하지 않음(DEC-39). 접근·정리 방식 미정 |
| 인물·세계관 엔티티 간 관계 | 그래프 DB | 원본 문서와 버전 추적 필요. 체크포인트 기준의 일치성과 실패 복구는 미정 |
| 콘텐츠 AI 작업·제안·댓글·제보 | PostgreSQL 방향 | AI 실행 상태와 업무 결과를 구분. 운영 목적 작업은 운영, 정산은 Core |

AI 대화·실행 상태 저장은 **LangGraph PostgresSaver를 후보로 검토**합니다. 라이브러리가 관리하는 체크포인트는 회차·세계관의 업무 체크포인트와 별개이며, 사용자·작품 권한을 자동으로 보장하지 않습니다. 실제 테이블과 연결 후보는 [Saver 참고 ERD](erd/ai-service/postgres-saver.md#3-langgraph-postgressaver의-실제-테이블)에 정리했습니다. 도입·보관 정책은 미정입니다.

### 설정집·버전·관계

세계관·인물·장소·세력·아이템·마법 규칙 등을 항목별 문서로 다룹니다. 항목마다 카테고리는 하나이며 태그는 여러 개 가능합니다. 인물의 기본 설정과 회차별 상태·지식은 세계관과 함께 이어집니다(DEC-31·33). 관계도는 문서 전문이 아닌 **관계 정보**로 다루고, 플롯의 미래 사건은 확정 관계가 아닙니다. 세계관·설정·상태·관계의 삭제 대신 기존 이력을 보존하는 revert로 정정합니다. 문서 ID·버전 ID와 그래프 관계를 잇는 키, 시점별 정보의 물리 표현, 반영 시점·불일치 복구 방식은 미정입니다.

`pg_git`은 MVP에 사용하지 않습니다. MVP 이후 `seanwevans/pg_git`의 도입을 신중하게 추진하되, 재사용 범위와 기존 테이블 이력 연계·동시 작업 격리는 검토가 필요합니다(DEC-30). 포크·설치·개발은 아직 하지 않았고, 확장이 우리 테이블의 이력을 자동 관리한다고 가정하지 않습니다. 버전·체크포인트·Fork가 PostgreSQL에 있다는 것은 확정 방향입니다. 최초 세계관 수정 시 전체 복사는 DEC-32로 정했으며, 이력 테이블 구조·실제 복사 처리·동시 작업 제어는 아직 설계하지 않았습니다.

### Fork 창작 화면과 설정 변경

독자가 원작을 보며 소설을 어떻게 바꿀지 설명할 수 있도록 **원작 원고 옆에 AI 채팅을 두는 화면**을 기본 방향으로 합니다(DEC-29). 시스템이 변경 가능한 설정 목록부터 고르게 하는 흐름은 아닙니다. AI는 대화를 돕고 변경 방향을 제안하며, 설정 변경과 관련된 요청이면 독자가 해당 세계관·인물·관계 설정으로 이동해 내용을 확인·수정할 수 있게 안내합니다. 바로 원고를 작성할 수도 있고 설정을 먼저 변경할 수도 있습니다. AI 채팅·시뮬레이션 사용은 선택적이며 대화나 제안 생성은 저장·발행이 아닙니다.

원작은 수정하지 않으며 사용자 확인 후 허용된 변경만 자신의 Fork에 반영합니다. 원작 원고를 보여 주는 범위와 AI 문맥은 권리·독자 접근 권한·기준 회차를 적용하고, 미발행 원고·미래 회차·다른 인물의 지식을 누설하지 않습니다. Fork 생성 전후 화면 진입 시점, 기준 이전 장면의 편집 여부와 설정 변경의 물리 저장 방식은 미정입니다. 현재 선택적 콘텐츠 화면과 일부 동작은 구현돼 있으나 이 전체 목표 흐름의 구현·수용 검증 완료를 뜻하지 않습니다.

### 작품 Fork와 세계관 Fork (`확정` 사용자 흐름)

작품 Fork는 기준 회차·원고 버전과 그때까지 공개된 세계관 설정, 인물의 기본 설정·회차별 상태·지식을 이어받습니다. **기준 기록**은 보존하되, 세계관을 아직 수정하지 않은 동안에는 원본을 참조해 허용 범위의 원본 변경을 따라갑니다. 독자가 최초로 설정을 수정하면 세계관 전체를 독자 소유로 Fork한 뒤 자기 세계관을 변경합니다(DEC-32·33).

독립된 세계관을 만든 후 원본이 바뀌면 독자에게 알리고 변경을 반영할지 선택하게 합니다(DEC-34). 선택 전 자동 반영하지 않습니다. 작품 Fork 없이 타인의 세계관을 직접 이용하는 기능은 MVP 이후이며 시점은 미정입니다(DEC-35).

**경계:** 각 설정 항목은 기본 비공개이며 작가가 공개·비공개와 회차별 공개 범위를 지정합니다(DEC-36). 10화 작업에서 추가한 설정이라도 5화에 적용·공개되면 5화 Fork에 영향을 줍니다. 독립 전에는 그 변경을 따르고 독립 후에는 알림과 사용자 선택으로 반영하며, 거절한 변경도 나중에 반영할 수 있습니다(DEC-37). 해당 회차에 공개되지 않은 내용이나 권한 밖 본문·관계는 참조·복사·검색·알림·AI 문맥에 노출하지 않습니다. 실제 이력 표현과 필터 구현은 미정이며 이력이 부족하거나 저장·관계 반영이 실패한 경우 성공으로 가장하지 않습니다.

복사·선택적 rebase의 구체 구현과 충돌 처리, 그래프 상태의 시점 일치·복구는 미정입니다. 단일 PostgreSQL 트랜잭션만으로 별도 그래프 DB의 원자성이 보장되지는 않습니다.

## Components and Interfaces

### AI 도구 조회 (`제안`)

기존 `search_items`·`get_item`·`get_relations`와 `/internal/v1/ai-tasks/...`는 분리 전 명칭을 가진 조회 **후보**이며 목표는 콘텐츠 소유 조회이며 API 명세나 구현 완료가 아닙니다. AI는 관계만이 아니라 해당 작업에 필요한 설정 문서와 원고도 참고합니다. 요청하는 사용자·작품·기준 회차/버전·인물별 지식에 맞춰 허용 문맥을 제한해야 하며, 모델이 준 ID만으로 권한을 인정하지 않습니다.

AI가 반환한 시뮬레이션·원고·상태 변화는 후보입니다. 작가의 채택과 실제 버전 생성, 관계 반영, 발행을 별개 상태로 처리합니다. 근거 ID 확인은 출처 확인일 뿐 사실성이나 누설 방지의 보증이 아닙니다.

### 검색의 한계

이름·별칭과 관계 탐색의 한국어 품질·범위는 표본으로 검증해야 합니다. 그래프 DB를 사용한다고 문서 본문 검색이나 KAG 추론이 자동 제공되지는 않습니다.

## Error Handling

- 저장·버전 충돌·관계 반영 실패는 이전 확정 버전을 보존하고 성공으로 표시하지 않습니다. PostgreSQL과 그래프 DB 사이 동기화·재시도·복구 방식은 미정입니다.
- Fork 생성 시 원작·Fork의 기준 버전과 관계 상태가 어긋난 경우 부분 성공을 완료로 표시하지 않습니다.
- AI 연결 실패·모델 오류·중단·근거 부족은 실제 상태로 구분하며 제안 도착을 정본 반영으로 표시하지 않습니다.

## Security Considerations

- 세계관 설정의 항목별 공개·비공개와 회차별 공개 범위를 적용하고, 권한 밖 작품·미발행 원고·인물만 아는 사실의 누출을 막습니다(DEC-36). 이미지 URL을 알거나 ID·그래프 경로를 알거나 AI에 요청했다고 접근 권한이 생기지 않습니다.
- 외부 IP 등록자에게 2차 창작 권리 확인 여부를 묻되 플랫폼이 작품별 권리를 직접 검증한다고 가정하지 않습니다. 등록자의 확인·등록 자체가 적법한 권리를 보장하지 않으며, 권리 침해 신고·법적 제한은 별도 처리합니다(DEC-38). 원고·사용자 입력을 모델 지시로 신뢰하지 않습니다.
- 모델 API 키는 AI 런타임에만 전달하며 Frontend·Core·콘텐츠·운영 런타임에 포함하지 않습니다. 로컬 Compose를 운영 배포로 취급하지 않습니다.

## Testing Strategy

다음은 **구현 시 검증 계획**이며 현재 실행한 테스트가 아닙니다: 새 버전 생성·복원 이력 보존, 체크포인트/Fork 고정, 플롯의 예정 사건과 공식 관계 분리, 관계 반영 실패 시 부분 성공 방지와 복구, 인물별 AI 문맥 격리, 제안·채택·반영 구분. 유료 모델 호출은 별도 승인을 따릅니다.

## 위험·미정 사항

1. 체크포인트 생성 시점·포함 자료의 검증, 설정 초안 자동저장의 동시 수정과 확정 버전 구분.
2. 기준 회차에 영향을 주는 공개 설정을 실제로 판정하고 비공개 정보 누출을 막는 구현, 세계관 복사·선택적 rebase 충돌 처리.
3. 그래프 DB 제품·관계 정본 여부·문서/버전 연결 키·동기화·실패 복구·백업.
4. AI 조회 경로·모델·프레임워크·결과 채택 계약, API·ERD·그래프 모델.
5. 한국어 검색 품질, 분리 서비스 인증·세션 폐기 전파·정산·알림·조치·복구 계약, 로컬 이외 배포 조건. 현재 인증 보안 계약은 이전 전 보존합니다.
6. 기존 Draft #86·#91의 상세 제안은 채택 미확정 상태를 유지하며 DEC-41이 자동 채택하지 않습니다.
