# Fork 정합성 운영 점검 (기능 83)

- 운영 작품 목록에서 Fork의 점검을 요청한다. `GET /api/v1/operations/works/{id}/fork-integrity`는 기존 운영자 인증과 `works` 권한을 검사하고 Content 내부 API에 위임한다.
- Content는 `GET /internal/v1/works/{id}/fork-integrity`로 읽기 전용 결과만 반환한다. 원작의 현재 발행본 대신 Fork를 만들 때 고정한 원작 체크포인트의 원고 버전과 Fork의 상속 원고 버전을 SHA-256으로 비교한다.
- 회차 번호, 콘텐츠 버전 ID, 원고 버전 번호, 제목·본문·작가의 말을 비교한다. 원고 자체는 응답에 포함하지 않는다. 결과는 기준 회차, 두 해시, 일치 여부, 인물 상태 비교 상태다.
- 저장된 회차별 인물 상태가 없으므로 현재는 비교 불가다. 관계의 과거 상태, 독립 이후 설정 변경, 자동 보정은 이 점검 범위 밖이다.

## 오류와 화면

- Content는 점검할 수 없는 포크를 `404`(`포크 작품을 찾을 수 없어요.`)·`409`(`원작의 고정 기준 기록을 확인할 수 없어요.`)로 답하며 본문은 `{ detail }`이다.
- 운영 API는 이 점검 호출에서만 Content의 `400`·`404`·`409` 안내 문구를 `message`에 그대로 전한다(코드는 기존 `INVALID_REQUEST`·`NOT_FOUND`·`CONFLICT`). 본문에 문구가 없으면 기존 일반 문구다.
  그 밖의 Content 호출의 오류 문구, `403`·`502`는 기존 일반 문구 그대로다(Content 원문이나 내부 예외를 노출하지 않는다).
- 화면은 `404`·`409`를 실패가 아니라 다시 시도해도 같은 **영구 상태**로 보고 서버 문구를 그대로 보이며 다시 시도 버튼을 두지 않는다. 그 밖의 실패(`502`·네트워크)는 일반 오류와 다시 시도 버튼을 보인다.
  `--mode mockup`은 점검을 지원하지 않아 같은 영구 상태로 `데모에서는 포크 정합성 점검을 지원하지 않아요.`를 보인다.
- 점검 결과 영역은 열리면 결과 제목에, 닫으면 누른 점검 버튼에 포커스를 둔다. 점검 중인 행은 선택 표시(`tr.sel`)되고, 버튼 이름은 `「작품 제목」 포크 정합성 점검`이다. 판정은 `일치`(`chip ok`)·`불일치`(`chip wait`)로 보인다.
