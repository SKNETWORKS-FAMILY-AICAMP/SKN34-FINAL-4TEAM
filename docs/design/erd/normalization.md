# ERD 전체 검토·정규화 근거

> [목차](README.md) · [전체 ERD](overview.md) · [테이블 가이드](tables.md) · [119개 요구사항 추적표](requirements-matrix.md)
>
> 기준: 저장소의 현재 요구사항 정의서 엑셀·Markdown 색인, UC-01~28, 최신 DEC-26~40. **설계 문서 변경만 수행했으며 업무 DB·애플리케이션은 미구현입니다.** 정규화 후보와 확정 업무 정책을 구분합니다. 원본 엑셀·요구사항·UC·아키텍처 정책은 이번 범위에서 수정하지 않았습니다.

## 전체 검토 결과

- 엑셀의 고유 기능 ID **116개**, Markdown 사용자 추가 **3개**, 합계 **119개**와 **UC 28개**를 대조했습니다. 기능별 대응과 미해결 범위는 추적표에 하나씩 기록합니다.
- 종전 전체 ERD는 **41개**였지만 README·가이드 일부에는 27개로 적혀 있었습니다. 실제 엔티티에서 개수를 산출하여 **143개 논리 후보·10개 소유 영역**으로 동기화했습니다.
- 늘어난 테이블은 정규화뿐 아니라 **기존 그림에 누락된 전체 서비스 요구사항**을 반영한 결과입니다. 전부 MVP에 도입하거나 테이블 수 자체를 최대화하지 않습니다.
- 초안·확정 버전·발행, AI 제안·선택·실제 반영, 최초 Fork 기준·현재 추종, 검증 개인기록·제출 증거, 신고·판정·실제 제한을 분리했습니다.
- DB 권한·트랜잭션·삭제·성능을 실제 검증한 것은 아닙니다. 실제 관계 그래프 스키마 및 외부 LLMOps 데이터 모델은 이 RDB 모델 밖이며 미해결입니다.

## 분해 기준

| 분해 | 이유 | 적용 사례 |
|---|---|---|
| 1NF·반복 관계 | 태그·장르·참여자·근거·요일처럼 항목 수가 변하는 집합을 독립 행으로 | WORK_GENRE, WORK_HASHTAG, SIMULATION_PARTICIPANT, PROPOSAL_EVIDENCE, AUTOSERIAL_SLOT |
| 2NF·연결과 정의 | 복합 연결키 일부에만 종속하는 설명·이름을 정의 테이블로 | GENRE↔WORK_GENRE, SETTING_TAG↔SETTING_DOCUMENT_TAG |
| 3NF·독립 사실 | 약관 정의·동의, 작업·모델 호출, 구독·기간·지급을 각각의 결정자에 배치 | TERMS_VERSION↔MEMBER_CONSENT, AI_JOB↔AI_MODEL_CALL, CREDIT_GRANT↔CREDIT_LEDGER_ENTRY |
| 현재값 중복 제거 | 최신 이력과 같은 이름·분류·공개값·허용값을 두 군데 원천으로 저장하지 않음 | SETTING_DOCUMENT에서 현재 이름/분류 제거, WORK에서 genre/Fork boolean 제거, EPISODE에서 현재 제목/발행 포인터 제거 |
| 보존 수명·변경 주기 | 정규화 위반이 아니어도 다른 주기로 수정/삭제되면 분리 | 초안↔저장 버전, 원고 파일↔버전 배치, 개인 검증↔제보 첨부 |
| 행위·결과 분리 | 선택·승인·실행·발행은 일치하지 않으므로 이력과 실패를 각각 표현 | PROPOSAL_DECISION↔APPLICATION↔EPISODE_CHANGE, RIGHTS_DECISION↔RESTRICTION_APPLICATION |

본문 TEXT는 문서 값이며 문장/단어마다 테이블로 나누지 않습니다. 모든 단일 문자열을 사전 테이블로 바꾸는 것도 정규화의 요구가 아닙니다. 후보 키·정책이 미확정인 부분이 있어 전체를 BCNF/4NF 충족이라고 단정하지 않습니다.

## 정규화 예외와 멈춘 지점

1. **체크포인트의 항목 ID+버전 ID:** 버전→항목 함수 종속이 있지만 (기준점,항목)당 하나를 보장하고 소속 검증을 명시하기 위한 중복입니다. 버전 FK만으로는 같은 항목의 다른 버전 중복을 막을 수 없습니다. 복합 FK/UNIQUE 또는 동등한 원자적 검증을 구현해야 합니다. 엄격 BCNF라고 부르지 않습니다.
2. **소속 확인용 키:** READING_PROGRESS의 작품+회차버전, 원고 반영 결과의 회차+선택 결과버전 등은 직접 소속 검증 후보입니다. 단일 FK 둘만으로 일치가 보장되지 않으며 복합 제약/트랜잭션 검증이 필요합니다.
3. **당시 내용 스냅샷:** 요청 원문, 승인 내용, 제출 증거와 원고 버전은 시간과 소유/삭제 경계가 다른 사실입니다. 현재 내용과 같더라도 단순 중복이라고 지우지 않습니다. 개인 AI 기록 삭제는 제출 증거·발행 버전으로 전파하지 않습니다.
4. **파생 합계:** 좋아요수·조회합계·크레딧잔액·작업 토큰합계·정기작업 건수는 원천 행에서 계산합니다. 성능을 측정하기 전 캐시/집계 테이블을 추가하지 않습니다. 현재 포인터도 필요할 때 검증된 비정규화로 별도 결정합니다.
5. **동일한 구조 재사용:** 검토 발견은 AI_PROPOSAL, 판단은 PROPOSAL_DECISION, 시뮬레이션 후보는 제안 하위관계, 장면/플롯/줄거리는 STORY_PLAN으로 재사용합니다. 상태 enum·행동 종류·문장마다 테이블을 만들지 않습니다.
6. **작은 역할·외부 도구:** 운영자는 현재 단일 역할로 MEMBER 속성을 사용합니다. 불필요한 역할정의/권한할당 프레임워크, Langfuse/Saver 내부 테이블 복제, 결제사·큐·락·캐시·worker 스키마를 추가하지 않습니다.
7. **다형 대상:** 신고·입력스냅샷·정기대상은 소수의 명시적 FK와 정확히 하나의 조건을 사용합니다. 모든 도메인을 포괄하는 범용 ENTITY/EAV 레지스트리를 만들지 않습니다. 외부 그래프 키는 FK로 위장하지 않습니다.
8. **단일 생명주기:** 하나의 장르 이름을 별도 name 테이블로 나누거나 회원 프로필의 각 단일 속성을 분리하지 않습니다. 구독 상품은 계약 조건 행 하나로 두고 미정인 상품 버전 계층을 추가하지 않습니다.


### 개인 기록 삭제와 업무 증빙 보존

개인 대화·시뮬레이션·제안·입력 원문/스냅샷의 삭제 선택과, 이미 제출한 증거·확정 원고·정산에 필요한 최소 증빙의 보존은 다른 수명주기입니다. 개인 기록 삭제를 이유로 `CREDIT_SETTLEMENT`·`CREDIT_SETTLEMENT_LINE`·지급 장부·제보 반영 결과·저장/발행 원고를 CASCADE 삭제하지 않습니다. 반대로 정산 FK가 있다는 이유만으로 개인 원문을 무기한 남기는 것도 아닙니다. 필요한 최소 작업 식별/사용량과 반영 계보만 별도 수명으로 유지하는 후보이며, 삭제된 콘텐츠에 재접근할 수 없게 해야 합니다. 물리 분리·비식별화·FK 삭제 동작 및 법적 보관기간은 구현 전에 결정하고, 사용자에게 표시하는 개인 기록 삭제 완료와 실제 업무 증빙 잔존을 구분합니다. 새로운 보관기간을 확정한 것은 아닙니다.

## 구현 전 남은 사항

- **정책/논리:** 공개 시점과 실제 적용 시점의 표현, 인물 지식 단위·그래프 스키마, 조합의 관계/상태 복사, 세계관 템플릿/성인등급·연령확인, 직접세계관이용, 자동추출 이후정책, 사용자중단/미보고/동시초과 정산.
- **물리:** ID/타입/NULL/CHECK, 복합소속 FK, 작품-세계관 현재 유일성, 원작당1회 Fork의 동시성, 버전 불변·안전한 삭제/익명화, 그래프 일치·복구, 현재값/집계 성능, 파일 참조 정리.
- **권리/운영:** 법적 보관·삭제 의무, 신고 묶음 재편, 모더레이션 실패/오판, 세계관/항목 신고 파급, 비회원 조회 집계 개인정보, 자동작업 멱등성·다중서버 제어.
- **별도 책임:** LLMOps 평가·프롬프트 저장은 외부 도구 후보라 Core 테이블을 중복 생성하지 않았습니다. 모바일은 클라이언트 계약이며 모바일 전용 업무테이블을 추가하지 않았습니다.

## 검증

- **문서 구조:** Python 검사로 전체 143개 테이블·300개 FK 관계, 10개 부분 뷰의 정의/관계 일치와 합집합, 143개 가이드의 컬럼 일치, 119개 기능 ID·UC-01~28의 누락/중복 없음을 확인했습니다.
- **링크:** 변경 문서의 로컬 경로·앵커 1,278개와 코드펜스·공백을 검사했습니다. 원본의 기존 끊어진 엑셀 경로를 따라 복제하지 않고 추적표는 실제 `docs/deliverables/` 원본에 연결합니다. 추적표 밖 요구사항/UC의 기존 링크는 이번 변경 범위가 아닙니다.
- **Mermaid:** 로컬에서 기존 설치 번들을 재사용하여 전체도+부분 뷰 **11개 모두 파싱·SVG 렌더링**했습니다. 전체도는 파서 143노드/300관계, 렌더 SVG 143개 엔티티가 일치했습니다. 리뷰 후 영향받은 5개 다이어그램을 다시 렌더링했고, 임시 검증 탭·서버는 종료했습니다. 이후 Saver 참고까지 **12개**를 일반 Mermaid API와 VS Code 미리보기 번들로 재검증해 모두 표시됐습니다. 픽셀 기반 전체 시각 품질 검사와 애플리케이션 E2E는 아닙니다.
- **한계:** 검증 결과는 위와 같으며 로컬 임시 증거 파일은 저장소에 포함하지 않았습니다.
- **Graphify:** 기존 그래프를 먼저 질의했지만 2026-10-27 그래프에는 현재 요구사항·UC·ERD 원문이 포함되지 않아 원문 대조로 보완했습니다. 문서만 변경하여 AST 갱신을 문서 의미 갱신으로 가장하거나 그래프 전체를 임의 재생성하지 않았습니다.
- **제외:** 문서만 변경하여 애플리케이션 E2E·DB 마이그레이션·성능·유료 모델 호출·전체 빌드는 수행하지 않았습니다. 문서 검증 통과를 SQL 무결성이나 제품 구현 검증으로 표현하지 않습니다.

## Ponytail 리뷰

범위 내 과잉 분해를 검토하여 운영자 전용 다중역할 이력 테이블과 별도 구독 상품 버전 계층을 제거했습니다. 같은 데이터로 만들 수 있는 조회합계·보드/타임라인·내보내기·도구 내부 테이블은 추가하지 않았습니다. 남은 테이블은 반복 관계 또는 실제 보존/수명주기·확정 요구에 연결됩니다. 독립 리뷰의 7개 지적도 반영했습니다: Fork의 집필 전 기준점 소유 문맥, 작품 없는 세계관 검사, 저장의 발행 사건 제외, 설정 제거를 새 버전으로 표현, 개인 기록과 업무 증빙의 삭제 경계, 차감 회원/동의/합계 일치, 제출 검증 대상당 0..1. 테이블은 더 추가하지 않고 컬럼·카디널리티·제약으로 보정했습니다. 미반영 지적은 없으며 미정 정책을 새로 확정하지 않았습니다.
