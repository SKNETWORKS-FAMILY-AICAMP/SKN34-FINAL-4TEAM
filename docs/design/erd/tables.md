# STORYFORK 업무 ERD — 테이블별 설명

> **읽기 전:** 아래 27개는 [전체 업무 ERD](overview.md)에 그린 **테이블 후보**입니다. 업무 정책이 정해진 것과 실제 테이블·컬럼·관계가 확정되거나 구현된 것은 다릅니다. 이 문서는 그림을 설명하며 새로운 테이블이나 정책을 확정하지 않습니다. 인물관계도는 세계관의 일부이지만 관계 저장·조회는 그래프 DB 방향이며, 그래프 모델은 이 그림에 아직 없습니다.

## 읽는 방법

- **역할:** 이 테이블이 어떤 정보를 구분하기 위한 후보인지 설명합니다.
- **그림의 주요 항목:** 현재 ERD에 실제로 그려진 컬럼을 뜻합니다. 이름 끝의 `_id`는 다른 대상을 가리키는 식별자 후보입니다.
- `PK`는 행을 구별하는 기본키, `FK`는 다른 테이블을 가리키는 외래키 표기입니다. 둘 다 여기서는 **논리 설계 후보**입니다. 여러 컬럼에 함께 `PK`가 붙으면 그 조합으로 행을 구별한다는 뜻입니다.
- 각 예시는 설명용 가상 사례입니다. 실제 저장된 데이터가 아닙니다. 모든 컬럼의 PostgreSQL 자료형·필수 여부·인덱스·제약과 동작은 아직 확정되지 않았습니다.
- 부분 뷰마다 다른 영역의 테이블이 함께 보일 수 있습니다. 이는 연결을 설명하기 위한 **참조**이지 같은 테이블을 두 번 만든다는 뜻이 아닙니다.

## 회원·인증

<a id="member"></a>
### `MEMBER` — 회원

- **역할:** 가입한 사람을 식별하는 회원 정보입니다. 같은 회원이 작품의 독자이면서 자신의 작품이나 Fork의 창작자일 수 있습니다. 공개 작품 열람은 비회원도 가능하지만 Fork·피드백은 로그인이 필요합니다.
- **그림의 주요 항목:** `id`(회원 식별자), `email`, `password_hash`(비밀번호 해시), `nickname`, `created_at`.
- **예:** 한 회원이 원작을 읽고 Fork를 만들면 같은 회원 정보로 Fork의 소유자와 피드백 작성자를 연결할 수 있습니다. 대상별 소유권·접근 권한은 별도로 확인해야 합니다. 비밀번호는 평문으로 저장하지 않습니다.

<a id="member-consent"></a>
### `MEMBER_CONSENT` — 회원의 약관 동의

- **역할:** 회원이 어떤 약관에 언제 동의했는지 구분하기 위한 후보입니다.
- **그림의 주요 항목:** `member_id`(회원), `terms_type`(약관 종류), `terms_version`(약관 버전), `agreed_at`(동의 시각).
- **예와 한계:** 회원이 이용약관에 동의한 정보를 연결합니다. 별도 테이블 사용 여부, 약관 버전과 보존 방식은 미정입니다. 작품의 2차 창작 권리를 플랫폼이 직접 확인했다는 기록이 아닙니다.

## 세계관·설정

<a id="world"></a>
### `WORLD` — 세계관

- **역할:** 인물·장소·규칙 등 설정을 묶어 소유자가 관리하는 세계관의 단위입니다. Fork 창작자가 설정을 처음 수정할 때 만들어지는 독립 세계관도 이 개념으로 설명합니다.
- **그림의 주요 항목:** `id`, `owner_id`(소유 회원), `name`, `description`, `created_at`.
- **예:** 작가의 ‘푸른 왕국’ 세계관 아래에 인물과 장소 설정을 둡니다. **인물관계도도 세계관의 일부**지만 그래프 DB에 어떤 형태로 저장할지는 미정입니다. 행 하나만으로 전체 복사와 소유권 분리가 보장되지는 않습니다.

<a id="setting-category"></a>
### `SETTING_CATEGORY` — 고정 설정 분류

- **역할:** 인물·장소·광물처럼 설정을 나누는 고정 카테고리 후보입니다. 설정 항목은 카테고리를 하나 고릅니다.
- **그림의 주요 항목:** `id`, `name`(카테고리 이름).
- **예와 한계:** ‘인물’ 카테고리를 골라 주인공 설정을 작성합니다. 실제 고정 목록과 관리 방식은 미정입니다.

<a id="setting-document"></a>
### `SETTING_DOCUMENT` — 개별 설정 항목

- **역할:** 세계관 안의 설정 하나를 식별합니다. 인물·장소 같은 각 항목과 현재 분류·공개 상태를 연결하는 후보입니다.
- **그림의 주요 항목:** `world_id`(소속 세계관), `category_id`(선택한 카테고리), `name`(항목 이름), `visibility_status`(현재 공개 상태), `source_setting_document_id`(복사한 원본 항목의 출처 후보).
- **예와 한계:** ‘카일’이라는 인물 설정 항목을 만들면 기본 비공개이고 생성 시나 나중에 공개 여부를 정합니다. 내용의 확정 이력은 `SETTING_VERSION`, 회차별 공개 이력은 `SETTING_VISIBILITY_HISTORY` 후보에서 다룹니다. 출처 ID만으로 독립 복사·권한 검증이 자동 보장되지는 않습니다.

<a id="setting-draft"></a>
### `SETTING_DRAFT` — 설정 작성 중 초안

- **역할:** 아직 저장 버튼으로 확정하지 않은 설정 초안을 같은 항목에서 자동저장으로 덮어쓰기 위한 후보입니다.
- **그림의 주요 항목:** `setting_document_id`(설정 항목이자 후보 PK), `content`(작성 중 내용), `updated_at`(최근 갱신 시각).
- **예와 한계:** 카일의 소개를 수정하는 동안 초안은 갱신되지만, 확정 저장을 누르면 새 `SETTING_VERSION`을 남깁니다. 초안이 공개·발행되었다는 뜻은 아닙니다. 새 항목의 최초 생성 순서, 자동저장 간격·동시 수정 처리는 미정입니다.

<a id="setting-version"></a>
### `SETTING_VERSION` — 확정된 설정 내용의 버전

- **역할:** 저장 버튼으로 확정한 설정 내용을 이전 확정 내용을 덮어쓰지 않고 버전별로 구분하기 위한 후보입니다.
- **그림의 주요 항목:** `setting_document_id`(설정 항목), `revision_no`(버전 번호), `name_snapshot`(당시 이름), `category_id`(당시 분류 참조 후보), `content`(내용), `created_at`.
- **예와 한계:** 카일의 소개를 확정한 뒤 정정하면 이전 버전은 남기고 새 버전을 기록합니다. 되돌리기도 새 버전으로 남기는 방향입니다. 과거 이미지 복원은 보장하지 않으며 태그 이력·관계 이력과의 연결은 별도 설계가 필요합니다.

<a id="setting-image"></a>
### `SETTING_IMAGE` — 현재 설정 이미지

- **역할:** 설정 항목에 현재 연결된 이미지의 URL과 순서를 나타내는 후보입니다. 이미지 파일 자체는 MinIO(S3 호환)에 두고 RDB에는 URL만 저장합니다.
- **그림의 주요 항목:** `setting_document_id`(설정 항목), `object_url`(이미지 URL), `position`(표시 순서 후보).
- **예와 한계:** 카일의 설정에 현재 이미지 최대 10개를 붙입니다. 10개 제한은 서비스가 검증해야 하며 그림만으로 강제되지 않습니다. 과거 이미지 이력은 보존하지 않습니다. 사용 중인 다른 항목이나 Fork의 참조가 깨지지 않도록 접근·파일 정리 방식은 별도 설계합니다.

<a id="setting-reference"></a>
### `SETTING_REFERENCE` — 외부 참고 URL

- **역할:** 설정을 작성할 때 참고할 외부 주소를 설정 항목과 연결하는 후보입니다. MinIO에 업로드한 이미지와 구분합니다.
- **그림의 주요 항목:** `setting_document_id`(설정 항목), `external_url`(참고 주소).
- **예와 한계:** 장소 설정에 참고 자료의 웹 주소를 기록합니다. 참고 URL의 개수·검증·접근과 안전한 전달 방식은 미정이며, URL이 있다고 접근 권한이나 이용 권리가 생기지는 않습니다.

<a id="setting-tag"></a>
### `SETTING_TAG` — 자유 태그

- **역할:** 창작자가 설정에 붙일 태그 이름을 표현하는 후보입니다. 고정 카테고리와 달리 필요한 태그를 자유롭게 붙일 수 있습니다.
- **그림의 주요 항목:** `id`, `owner_id`(태그 소유 회원 후보), `name`(태그 이름).
- **예와 한계:** 인물 설정에 ‘마법사’, ‘왕국’이라는 태그를 붙일 수 있습니다. 사용자별 소유라는 물리 표현, 이름 중복과 태그 변경 이력은 미정입니다.

<a id="setting-document-tag"></a>
### `SETTING_DOCUMENT_TAG` — 설정과 태그의 연결

- **역할:** 설정 항목 하나에 태그 여러 개를 연결하고, 태그 하나를 여러 항목에 붙이기 위한 연결 테이블 후보입니다.
- **그림의 주요 항목:** `setting_document_id`와 `setting_tag_id`의 조합이 후보 PK입니다.
- **예와 한계:** ‘카일’에 ‘마법사’와 ‘왕국’을 붙이면 연결을 각각 표현할 수 있습니다. 현재 연결을 나타내는 그림이며 이전 버전의 태그를 어떻게 보존할지는 미정입니다.

<a id="setting-visibility-history"></a>
### `SETTING_VISIBILITY_HISTORY` — 설정 공개 범위 변경 이력

- **역할:** 설정 항목의 공개·비공개와 그 회차 범위가 바뀐 기록을 표현하기 위한 후보입니다.
- **그림의 주요 항목:** `setting_document_id`, `visibility_status`, `start_episode_id`·`end_episode_id`(회차 범위 후보), `changed_at`(변경 기록 시각).
- **예와 한계:** 작가가 비공개 설정을 5화에 공개되도록 지정한 변경을 나타낼 수 있습니다. 어떤 회차에서 누구에게 보이는지는 별도 권한 검증이 필요합니다. 내용의 유효 시점과 공개 시점을 별도 필드로 둘지, 범위·이력의 물리 표현은 미정입니다. 이 테이블만으로 본문이나 이미지의 과거 버전이 복원되지는 않습니다.

## 작품·회차·집필

<a id="work"></a>
### `WORK` — 작품

- **역할:** 원작 또는 독자의 Fork 작품을 식별하고 소유자·세계관과 연결하는 후보입니다.
- **그림의 주요 항목:** `owner_id`, `world_id`, `title`, `description`, `genre`, `work_type`, `visibility_status`, `allow_fork_creation`, `allow_fork_publication`, `created_at`.
- **예와 한계:** 작가는 작품의 Fork 생성 허용과 Fork 작품 공개 허용을 각각 정할 수 있습니다. 현재 설정값 후보와 변경 기록 후보는 `FORK_POLICY_HISTORY`로 구분합니다. 공개 Fork의 원작·원작자 표시를 위한 출처는 `FORK`의 기준점과 그 원작을 통해 확인하는 후보이며, 필드만으로 공개 권한이 보장되지는 않습니다.

<a id="fork-policy-history"></a>
### `FORK_POLICY_HISTORY` — 작품 Fork 조건 변경 이력

- **역할:** 최초 조건과 각 변경 시점의 Fork 생성·공개 허용과 Fork 가능 회차 범위를 한 묶음으로 기록하는 이력 후보입니다. 현재 조건도 최신 이력과 확인할 수 있도록 후보로 연결합니다.
- **그림의 주요 항목:** `work_id`, `allow_fork_creation`, `allow_fork_publication`, `episode_scope`(범위 선택 후보), `start_episode_id`(시작 회차 후보), `changed_at`.
- **예와 한계:** `episode_scope`는 전체 공개 회차, 특정 회차 이후, 회차별 선택을 표현하는 후보입니다. 5화 이후라면 `start_episode_id`, 회차별 선택이라면 `FORK_POLICY_EPISODE` 연결을 사용합니다. 허용하지 않을 때도 공개 허용 설정은 별도로 남깁니다. 값·기본값과 현재 포인터의 물리 방식은 미정입니다.
- **변경 시 주의:** 이미 공개된 Fork는 공개 허용 철회 후에도 계속 공개·발행하고 미공개 Fork의 새 공개만 막습니다. 이 후보가 확인한 조건의 보존이나 권한을 자동으로 보장하지 않습니다. 확정 이력과 연결된 회차 선택은 나중에 덮어쓰지 않아야 합니다.

<a id="fork-policy-episode"></a>
### `FORK_POLICY_EPISODE` — 회차별로 선택한 Fork 허용 회차

- **역할:** 특정 조건 이력에서 작가가 개별적으로 고른 Fork 가능 회차를 연결하는 후보입니다. 전체 공개 회차·특정 회차 이후 선택을 회차마다 복사하는 테이블은 아닙니다.
- **그림의 주요 항목:** `fork_policy_history_id`(조건 이력), `episode_id`(선택한 원작 회차)의 조합이 후보 PK입니다.
- **예와 한계:** 작가가 3화와 5화만 고르면 같은 조건 이력에 각 회차를 연결합니다. 조건을 바꾸면 이전 이력의 목록은 보존하고 새 이력에 새 목록을 둡니다. 선택한 회차가 해당 원작에 속하는지, 실제 Fork 대상 회차가 열람 가능한 발행 회차인지 Core가 각각 확인해야 합니다. 작가가 미발행 회차를 미리 선택할 수 있는지, 기본값·물리 저장 및 승인 방식은 미정입니다.

<a id="episode"></a>
### `EPISODE` — 작품의 회차

- **역할:** 작품의 각 회차와 순서, 현재 발행 상태를 구분하는 후보입니다.
- **그림의 주요 항목:** `work_id`(소속 작품), `sequence`(회차 순서), `title`, `publication_status`, `published_version_id`(발행 버전 후보).
- **예와 한계:** 한 작품에 1화와 2화를 만들고 각각 발행 상태를 관리합니다. `published_version_id`가 있다면 반드시 이 회차에 속한 `EPISODE_VERSION`을 가리켜야 합니다. 발행 이력과 상태값의 상세 방식은 미정입니다.

<a id="episode-draft"></a>
### `EPISODE_DRAFT` — 회차 작업 초안

- **역할:** 회차별 작업 중인 원고를 자동저장으로 갱신하는 별도 논리 후보입니다. 회차당 최대 하나이며 저장 버튼을 누르면 새 `EPISODE_VERSION`을 남깁니다.
- **그림의 주요 항목:** `episode_id`(회차, 후보 PK·FK), `title`, `content`, `updated_at`.
- **예와 한계:** 3화를 쓰는 중에는 초안이 갱신되고 저장 버튼으로 버전 1을 남깁니다. 다시 수정해 저장하면 버전 2가 생기며 발행은 별도입니다. 복원은 새 버전으로 남기고 발행본을 자동 변경하지 않습니다. 저장 실패·동시 편집은 기존 저장본을 보호해야 하며 간격·동시성·물리 구현은 미정입니다.

<a id="episode-version"></a>
### `EPISODE_VERSION` — 회차 원고 버전

- **역할:** 회차의 제목과 본문을 버전별로 구분하는 후보입니다.
- **그림의 주요 항목:** `episode_id`, `revision_no`, `title_snapshot`(당시 제목), `content`(원고), `created_at`.
- **예와 한계:** 5화의 원고를 저장하거나 이전 내용을 복원하면 새 버전을 남기고 기존 버전은 보존합니다. **버전 저장과 독자에게 발행하는 것은 별개**입니다. 실제 발행 이력 구현은 미정입니다.

<a id="story-plan"></a>
### `STORY_PLAN` — 줄거리·플롯·장면 계획

- **역할:** 집필을 돕는 큰 줄거리, 회차 플롯 또는 장면 계획을 하나의 개념으로 표현한 후보입니다. 사용은 선택적입니다.
- **그림의 주요 항목:** `work_id`, `episode_id`(회차 연결 후보), `parent_plan_id`(상위 계획 후보), `kind`, `title`, `sequence`, `content`.
- **예와 한계:** 작품의 큰 줄거리 아래에 5화의 장면 계획을 둘 수 있습니다. 계획한 미래 사건은 확정된 세계관 관계가 아니며 자동 적용되지 않습니다. 실제 계층·버전·저장 방식은 미정입니다.

## 기준점·Fork

<a id="checkpoint"></a>
### `CHECKPOINT` — STORYFORK 업무 기준점

- **역할:** 어떤 회차 원고 버전을 기준으로 당시 설정·관계를 연결할지 설명하는 업무 기준점 후보입니다. Fork의 최초 기준 기록과 이후 원본 추종 상태를 구분하는 데 사용합니다.
- **그림의 주요 항목:** `episode_version_id`(기준 원고 버전), `graph_state_ref`(관계 상태 식별자 후보), `status`(준비·실패 구분 후보), `created_at`.
- **예와 한계:** 5화 기준 Fork의 기준점을 가리킵니다. 관계 식별자만으로 그래프의 과거 상태 보존이나 PostgreSQL과 그래프 DB의 일치가 보장되지는 않습니다. 생성 시점·완전성·실패 복구는 미정입니다. LangGraph의 소문자 `checkpoints`와는 **서로 다른 대상**입니다.

<a id="checkpoint-episode"></a>
### `CHECKPOINT_EPISODE` — 기준점에 연결한 회차 버전

- **역할:** 하나의 기준점에 어떤 회차와 그 원고 버전이 연결되는지 나타내는 후보입니다.
- **그림의 주요 항목:** `checkpoint_id`와 `episode_id`의 조합이 후보 PK이고, `episode_version_id`가 선택한 버전을 가리킵니다.
- **예와 한계:** 5화 기준점에 1화~5화의 필요한 원고 버전을 연결하는 데 사용할 수 있습니다. 선택 버전이 해당 회차와 허용된 원작에 속하는지, 기준 회차가 포함될 때 기준점의 버전과 일치하는지 검증해야 합니다. 연결만으로 목록이 완전하다는 보장은 없습니다.

<a id="checkpoint-setting"></a>
### `CHECKPOINT_SETTING` — 기준점에 연결한 설정 버전

- **역할:** 기준점에 어떤 설정 항목의 어떤 버전을 연결할지 나타내는 후보입니다.
- **그림의 주요 항목:** `checkpoint_id`와 `setting_document_id`의 조합이 후보 PK이고, `setting_version_id`가 해당 항목의 기준 버전을 가리킵니다.
- **예와 한계:** 5화 기준으로 공개된 ‘카일’ 설정의 버전을 연결합니다. 후보 PK는 같은 기준점에서 같은 항목에 버전을 최대 하나만 두려는 표현입니다. 버전이 해당 항목과 허용된 원작에 속하는지, 공개 세계관 전체와 그래프의 시점이 빠짐없이 일치하는지는 별도로 검증해야 합니다.

<a id="fork"></a>
### `FORK` — 원작에서 갈라진 작품의 출처와 세계관 상태

- **역할:** Fork 작품이 어떤 원작 기준점에서 갈라졌는지와 세계관을 참조 중인지 독립했는지 표현하기 위한 후보입니다. 작품 자체의 제목·소유자는 `WORK`에 있습니다.
- **그림의 주요 항목:** `work_id`(Fork 작품이자 후보 PK), `source_checkpoint_id`(원작 기준점), `confirmed_policy_history_id`(창작자가 확인한 조건 이력), `conditions_confirmed_at`(확인 시각), `world_mode`(참조·독립 구분 후보), `independent_world_id`(독립 세계관 참조 후보), `created_at`.
- **예와 한계:** 독자가 원작 5화에서 Fork하면 기준점과 확인한 조건을 기록하는 후보입니다. 확인 화면 이후 조건이 달라졌다면 현재 조건을 재확인해야 합니다. 확인 기록은 당시 안내의 근거이지 변경 후 공개를 무조건 허용한다는 뜻은 아닙니다. 처음 설정 수정 시 공개된 세계관 전체를 독립시키며, 이 필드만으로 복사·동시성·권한 또는 `WORK.world_id`와의 일관성이 보장되지는 않습니다.

<a id="fork-source-change"></a>
### `FORK_SOURCE_CHANGE` — 독립 Fork에 알려줄 원본 변경

- **역할:** 독립한 Fork의 기준 회차에 영향을 주는 원본 변경과 반영 선택을 연결하기 위한 후보입니다.
- **그림의 주요 항목:** `fork_work_id`(대상 Fork), `source_change_ref`(원본 변경 식별 후보), `decision_status`(선택 상태 후보), `notified_at`(알림 시각 후보).
- **예와 한계:** 원작의 5화 설정 변경을 독립 Fork 소유자에게 알리고 반영 여부를 선택하도록 돕습니다. 거절한 변경도 나중에 다시 반영할 수 있습니다. 실제 알림 전달·보관, 재선택 이력, 충돌 처리는 이 컬럼만으로 확정되지 않았고 권한 밖 내용을 알림에 노출하지 않아야 합니다.

## AI 작업·대화의 업무 연결

<a id="chat-session"></a>
### `CHAT_SESSION` — 사용자와 작품 문맥의 대화 연결

- **역할:** Core가 회원의 대화와 작품 문맥을 연결하기 위한 후보입니다. AI Service 내부의 실제 대화 저장 테이블을 확정하는 것은 아닙니다.
- **그림의 주요 항목:** `thread_id`(대화 식별자 후보), `owner_id`, `context_work_id`, `target_fork_work_id`(Fork 연결 후보), `base_checkpoint_id`(기준점 후보), `created_at`.
- **예와 한계:** 원작 옆에서 시작한 대화를 사용자·작품 문맥에 연결할 수 있습니다. 대화 보관 방식과 Fork 연결 시점은 미정입니다. `thread_id`를 아는 것만으로 인증이나 작품 접근 권한이 생기지 않습니다.

<a id="ai-job"></a>
### `AI_JOB` — AI 작업 요청·상태

- **역할:** 설정 추출·시뮬레이션·집필 지원 같은 AI 작업의 요청자와 처리 상태·실패·사용량을 Core에서 구분하기 위한 후보입니다.
- **그림의 주요 항목:** `requester_id`, `work_id`, `thread_id`·`base_checkpoint_id`(선택적 연결 후보), `kind`, `status`, `model`, `input_tokens`·`output_tokens`, `failure_code`, `created_at`·`finished_at`.
- **예와 한계:** 작가가 5화 설정 추출을 요청하면 작업의 진행·실패와 보고된 사용량을 구분합니다. 미보고 사용량을 0으로 간주하지 않습니다. 크레딧 정산 테이블이 아니며, 이 필드만으로 요청 회차 범위·인물 조건이나 전체 시뮬레이션 결과가 표현되지는 않습니다.

<a id="ai-proposal"></a>
### `AI_PROPOSAL` — AI가 제시한 후보와 처리 상태

- **역할:** AI 작업의 제안 내용과 사용자의 선택, 실제 적용 결과를 구분하기 위한 후보입니다.
- **그림의 주요 항목:** `job_id`, `kind`, `content`, `evidence`, `selection_status`, `application_status`, `base_episode_version_id`·`base_setting_version_id`, `applied_episode_version_id`·`applied_setting_version_id`, `created_at`.
- **예와 한계:** AI가 원고에서 새 인물 설정을 제안하면 작가가 검토·선택하고 실제 반영 결과는 별도로 구분합니다. 채택이나 저장이 자동 발행을 뜻하지 않습니다. 복수 대상·근거 표현과 제안 보관 여부는 미정입니다.

## 독자 피드백

<a id="feedback"></a>
### `FEEDBACK` — 회차에 남긴 댓글·제보

- **역할:** 독자가 읽은 회차 버전에 남긴 댓글이나 제보와 작성자를 연결하기 위한 후보입니다.
- **그림의 주요 항목:** `author_id`, `episode_version_id`, `kind`, `content`, `target_excerpt`(대상 구절 후보), `is_spoiler`(스포일러 표시 후보), `created_at`, `author_checked_at`(개별 확인 시각 후보).
- **예와 한계:** 독자가 5화에서 발견한 오류를 제보하고 작가가 목록을 확인합니다. MVP는 댓글·제보 등록과 작가 확인까지이며 AI 응대·수정안·보상은 이후입니다. 댓글과 제보의 접근 범위를 구분해야 하고, 대상 구절·개별 확인 상태의 실제 보관은 미정입니다.

<a id="feedback-status-event"></a>
### `FEEDBACK_STATUS_EVENT` — 처리 상태 이력
- **그림의 항목:** `id`, `feedback_id`, `status`, `created_at`. 예: 접수·검토 상태. 실제 전이는 미정입니다.

<a id="feedback-response"></a>
### `FEEDBACK_RESPONSE` — 피드백 응답
- **그림의 항목:** `id`, `feedback_id`, `source_kind`, `content`, `is_public`, `created_at`. 예: 작가가 공개한 답변. 제보 원문 공개 권한과 별개입니다.

<a id="feedback-verification"></a>
### `FEEDBACK_VERIFICATION` — 제출된 검증 첨부
- **그림의 항목:** `feedback_id`, `result_snapshot`, `evidence_snapshot`. 예: 제보에 첨부된 검증 결과·근거. 개인 기록 삭제 후에도 첨부를 보존합니다.

<a id="feedback-moderation"></a>
### `FEEDBACK_MODERATION` — 신고·필터·숨김·복원
- **그림의 항목:** `id`, `feedback_id`, `actor_id`, `action`, `created_at`. 예: 신고 후 숨김과 작가의 복원. 자동 판정의 행위자는 없을 수 있으며 상세 정책은 미정입니다.

<a id="feedback-like"></a>
### `FEEDBACK_LIKE` — 댓글 좋아요
- **그림의 항목:** `feedback_id`, `member_id`, `created_at`. 예: 한 회원의 좋아요. 복합 키는 중복 제한 후보이며 댓글에만 허용하고 수만 공개합니다.

## 외부 라이브러리 테이블은 별도

[LangGraph PostgreSQL Saver 참고](ai-service/postgres-saver.md#3-langgraph-postgressaver의-실제-테이블)에 `checkpoints`, `checkpoint_blobs`, `checkpoint_writes`, `checkpoint_migrations` 네 테이블의 역할과 기본키를 따로 설명했습니다. 이들은 조사한 라이브러리 스키마이지 위 Core 업무 테이블이 아닙니다. Saver 도입과 DB 배치는 아직 미정이고, 실제 STORYFORK DB에서 `setup()`을 실행한 것은 아닙니다.

## 특히 그림만으로 판단할 수 없는 부분

- **세계관 전체:** 기준 회차에 공개된 설정·인물 기본 정보·상태·지식·관계 전체를 이어받는 업무 원칙은 확정입니다. 인물별 상태·지식의 물리 저장 모델과 관계 그래프의 상세 스키마·시점 일치·복구 방식은 아직 그려져 있지 않습니다.
- **공개와 권한:** 항목 기본 비공개, 회차별 공개, Fork 생성·공개 별도 허용과 그 변경 이력은 확정입니다. 권리 확인 여부를 작품 등록 시 묻는 정책도 확정이지만 그 확인 결과를 어디에 기록할지는 그림에 정해지지 않았습니다. 실제 접근·필터·철회 후 예외 판정은 테이블 이름이나 FK만으로 보장되지 않습니다.
- **기준 및 변경 이력:** 체크포인트에서 설정·관계가 누락 없이 같은 시점인지, 첫 독립 복사와 선택적 반영의 충돌·실패를 어떻게 처리할지는 후속 설계가 필요합니다. 사용 중인 이미지 참조의 안전한 정리도 별도로 다룹니다.
