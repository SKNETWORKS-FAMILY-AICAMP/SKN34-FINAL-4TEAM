# STORYFORK ERD 문서 목차

> **정규화 논리 후보 · 서비스 분리 구현 전.** 전체 요구사항을 검토하여 기존 41개에서 **143개 테이블 후보**로 분리했습니다. 테이블 수는 목표가 아니라 반복 관계·의존성·보존 수명이 달라진 결과입니다. 전체 서비스 설계이며 MVP 이후·보류 범위를 구분합니다.

## DEC-41 적용과 현재 구현

[서비스 경계](../service-boundaries.md)를 따릅니다. 현재 `backend/core-api`에는 인증·콘텐츠·첨부 코드와 PostgreSQL/Flyway 저장이 함께 있습니다. [현행 물리 대응](../../content-erd-migration.md)의 일부 논리 후보는 이미 이식됐지만 이 143개 전체 모델·그래프·운영 기능·크레딧이 구현된 것은 아닙니다. 별도 Kotlin 콘텐츠·운영 앱과 DB 소유 전환은 미실행이며 기존 경로·데이터·migration을 보존합니다.

이 문서 작업은 엔티티·컬럼·Mermaid 관계·물리 테이블을 변경하지 않고 정본 책임만 구분합니다. PostgreSQL 서버 공동 사용을 출발안으로 소유 범위·계정·Flyway 이력을 분리하며 물리 배치·writer 전환·인증·정산·알림·조치·복구 계약은 후속 설계합니다. 문의·공지·이벤트 등 운영 목표 기능은 현재 143개 ERD에 모두 그려져 있지 않으므로 완전한 서비스 스키마라고 주장하지 않습니다.

## 전체와 서비스 경계

- [전체 업무 ERD](overview.md): 143개 엔티티와 전체 FK 관계 후보.
- [정규화 근거·검증·명세 충돌](normalization.md): 분해 이유, 의도적 예외, 남은 정책과 검증 결과.
- [143개 테이블 설명](tables.md): 모든 테이블의 역할·실제 필드·PK/FK·제약·가상 예시.
- [119개 요구사항과 UC-01~28 추적](requirements-matrix.md): 연결 모델, 외부 책임, 미해결 항목.
- [AI Service — LangGraph PostgresSaver](ai-service/postgres-saver.md): 기존에 조사한 외부 라이브러리 스키마. Core·콘텐츠·운영 정본과 별개이며 도입은 미정.
- Frontend는 DB 정본을 소유하지 않습니다. 관계 그래프 DB의 실제 스키마는 미설계이며 RDB 후보와 동일시하지 않습니다.

각 부분 뷰는 전체 ERD와 같은 엔티티 정의를 사용합니다. 표의 중심 후보 수는 기존 문서 분류이며 서비스별 소유 테이블 수와 같지 않습니다. `core/` 경로는 호환성을 위해 유지하며 각 표에서 실제 목표 소유를 구분합니다. 다른 영역 테이블은 **참조**이며 중복 생성하지 않습니다. 기존 뷰 중심 테이블의 관계만 표시하여 선을 줄이고, 다른 영역 참조 테이블의 추가 관계는 전체도에서 확인합니다. 영역 이름이 별도 서비스·실행 계층을 뜻하지 않습니다.

| 표기 | 의미 |
|---|---|
| MVP | 현재 핵심 흐름의 논리 후보. 구현 완료나 모든 컬럼 확정이 아님 |
| MVP 이후 | 명세에 있으나 최신 설계에서 시연 이후로 미룬 기능 |
| 전체·범위확인 | 전체 요구사항에 필요하지만 MVP 상세 포함 여부를 별도 확인 |
| 보류·재설계 | 최신 정책과 과거 상세 흐름 충돌 때문에 계약 확정 불가 |
| 테스트 전용 | 운영 기능이 아닌 검증 환경용 |
