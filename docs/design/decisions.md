# STORYFORK 아키텍처 결정 기록

> 상위 문서: [RDB 기반 MVP 설계](design.md). 2026-10-28~29의 DEC-01~15 상세, 대안 X-01~18, 조사·시험 R-01~08과 V-01~04는 [이전 결정 기록](archive/kag-design/decisions.md)에 원문을 보관합니다. 이전 연구 결과가 이번 RDB 방식의 품질을 증명하지는 않습니다.

## 결정 목록

| ID | 결정 | 상태와 이전 결정의 관계 |
|---|---|---|
| DEC-16 | **MVP에서는 KAG·지식 그래프를 쓰지 않고 세계관을 RDB에 저장.** 서비스는 기존 세 개(web·Core·AI) | `확정`(사용자 결정, 2026-10-30). 이전 다섯 서비스·KAG·knowledge/lakeFS/Neo4j 설계(DEC-01·02·04·06·07·09·10)를 MVP에서 제외. MVP 이후 도입 여부는 별도 판단 |
| DEC-17 | **PostgreSQL + Flyway.** 정본을 Core 소유 PostgreSQL 하나에 두고 스키마는 core-api 안의 Flyway 버전 파일로 관리. MVP에서 pgvector·임베딩은 쓰지 않음 | `확정`(사용자 결정). 이전 DEC-03·13의 선택을 Core DB 하나로 좁혀 이어받음 |
| DEC-18 | **Langfuse는 MVP 이후.** MVP에는 Langfuse·Redis·ClickHouse 묶음을 두지 않고, AI 사용량·상태·실패는 Core의 AI 작업 기록으로 확인 | `확정`(사용자 결정). UC-26·AI Service 지침 갱신. 이전 DEC-12·14·15는 도입 때 참고 |
| DEC-19 | **Core ↔ AI 내부 통신 인증은 MVP 이후.** MVP에서는 AI Service와 Core 내부 조회 API를 호스트에 공개하지 않음 | `확정`(사용자 결정). 포트 비공개는 인증이 아니므로 로컬 검증 범위를 넘는 배포 전에 결정 |
| DEC-20 | **Gitea를 쓰지 않고 세계관 갱신을 게시판 방식으로 기록.** 항목은 게시글, 회차별 갱신은 댓글처럼 추가만 하는 기록. Fork는 분기 시점의 허용 내용을 DB 안에서 복사 | `확정`(사용자 결정, 멘토 의견 반영). 유스케이스 6.2의 Gitea 저장·Fork 커밋 ID 고정을 대체 |
| DEC-21 | **AI는 도구로 Core 조회 API를 호출해 세계관을 읽음.** 조회 범위(작품·기준 회차·인물)는 Core가 작업 생성 때 고정하고 모델은 검색어·항목 ID만 정함 | `확정`(사용자 결정). AI → Core 읽기 전용 호출을 추가. AI는 DB에 직접 접근하지 않음 |
| DEC-22 | **MVP 범위 축소.** 이메일 인증(SMTP·Mailpit) 제외. 독자 피드백은 댓글·제보 등록과 작가 확인만(UC-14), AI 분석·응대(UC-15)·수정안(UC-16)·크레딧(UC-17 지급·정산·보상)은 MVP 이후 | `확정`(사용자 결정). 기존 유스케이스의 해당 정책은 MVP 이후 범위로 유지 |
| DEC-23 | **MVP는 팀 시연용 핵심 기능만.** 단계는 MVP 하나만 두고 1차·2차 계획은 세우지 않음. 범위는 [MVP 범위](design.md#포함과-제외) | `확정`(사용자 결정). DEC-22보다 더 줄임: 1차 필터·갱신 토큰·저장 버전 이력·세계관 이용/Fork·앱 내 요청 제한 제외 |

### 이전 결정을 어떻게 읽을까

- DEC-05의 **Core가 권한을 판단한다는 원칙**은 유지합니다. 이전 설계의 지식 서비스용 범위·쓰기 토큰과 공개키 배포는 쓰지 않으며, 내부 통신 인증은 DEC-19에 따라 MVP 이후에 정합니다.
- DEC-08의 이미지 객체 저장소(MinIO)는 MVP에서 원고 이미지를 빼므로 함께 미룹니다(`제안`). 이미지 기능을 넣을 때 다시 결정합니다.
- 이전 X-03은 PostgreSQL 버전 테이블만 쓰는 단계를 유효한 대안으로 기록했습니다. DEC-20은 이를 게시판 방식으로 단순화한 것이며 검색 품질 시험 결과는 아닙니다.

## 보존할 제품 규칙

1. 세계관과 작품의 정본·권한·공개·변경 이력을 구분하고, 작가 비공개 정보·작품별 독자 공개·인물별 인지를 섞지 않습니다.
2. Fork는 기준 회차까지의 원고와 분기 시점에 독자에게 공개된 정보만 고정하고 원작 후속 변경을 유입하지 않습니다.
3. AI 출력은 제안이며 승인·반영·발행·실패를 구분합니다. AI는 정본을 고치거나 권한을 판단하지 않습니다.
4. ID를 알아도 비공개 본문을 우회 열람할 수 없도록 Core가 모든 조회에서 범위를 적용합니다. AI 도구 조회도 같습니다.
