# STORYFORK 아키텍처 결정 기록

[메인 README](../../README.md) · [문서 목록](../README.md)

> 상위 문서: [MVP 설계](design.md). DEC-36~40은 세계관·Fork의 최신 사용자 결정이며, 충돌하는 DEC-28·31~35 및 이전 기획의 해당 범위를 대체하거나 구체화합니다. DEC-26~35도 충돌하는 DEC-16~25보다 우선합니다. 2026-11-05 #132의 최신 사용자 결정인 [관계 현재 상태 MVP 예외](#관계-현재-상태-mvp-예외--132)는 관계에 한해 DEC-27·33 및 과거 시점/복원 요구보다 우선합니다. DEC-16~25의 당시 문구는 [RDB 단독 MVP 결정 보관본](archive/rdb-mvp/decisions.md), 2026-10-28~29의 DEC-01~15 상세·대안·조사·시험은 [KAG 결정 보관본](archive/kag-design/decisions.md)에 남깁니다. 과거 조사 결과가 새 구성을 검증한 것은 아닙니다.

## 결정 목록

| ID | 결정 | 상태와 이전 결정의 관계 |
|---|---|---|
| DEC-16 | 과거 MVP에서는 KAG·지식 그래프를 제외하고 세계관을 RDB에 저장 | `대체`(DEC-26). KAG 미도입은 유지하되, MVP에 관계용 그래프 DB를 사용 |
| DEC-17 | PostgreSQL + Flyway. PostgreSQL 스키마는 core-api의 Flyway 파일로 관리. MVP에서 pgvector·임베딩 제외 | `부분 유지`(DEC-26). PostgreSQL만 쓰는 구성은 대체; 그래프 DB 제품·스키마 관리 방식은 미정 |
| DEC-18 | **Langfuse는 MVP 이후.** MVP에는 Langfuse·Redis·ClickHouse 묶음을 두지 않고, AI 사용량·상태·실패는 Core의 AI 작업 기록으로 확인 | `확정`(사용자 결정). UC-26·AI Service 지침 갱신. 이전 DEC-12·14·15는 도입 때 참고. **2026-11-12 사용자 요청(#302)으로 AI Service의 집필 AI RAG 추적 SDK 계측만 앞당겨 구현**(키가 없으면 꺼짐). 서버는 사용자 결정으로 로컬 self-host 별도 Compose(`infrastructure/docker-compose.langfuse.yaml`, 필요할 때만 켬)이며 개발 배포 서버 배치와 Content 검색 단계 계측은 미정 |
| DEC-19 | **Core ↔ AI 내부 통신 인증은 MVP 이후.** MVP에서는 AI Service와 채택될 경우 Core 내부 조회 API를 호스트에 공개하지 않음 | `확정`(로컬 시연 전제). 포트 비공개는 인증이 아니므로 로컬 검증 범위를 넘는 배포 전에 결정; AI 조회 경로 자체는 미정(DEC-28) |
| DEC-20 | 과거 결정: Gitea 대신 세계관 항목을 게시글, 회차별 갱신을 댓글처럼 추가만 하는 기록으로 두고 Fork 허용 내용을 DB에서 복사 | `부분 대체`(DEC-27·28·32). Gitea 제거와 항목별 문서 작성·분류는 유지; 댓글 형태의 이력은 미정이며 세계관은 최초 수정 시 전체 Fork |
| DEC-21 | 과거 결정: AI는 도구로 Core 조회 API를 호출하고 작업 생성 때 작품·기준 회차·인물 범위를 고정 | `제안으로 변경`(DEC-28). Core 경유 조회는 후보이고 AI의 DB 직접 접근 여부·접근 제어 방식은 미정 |
| DEC-22 | **MVP 범위 축소.** 이메일 인증(SMTP·Mailpit) 제외. 독자 피드백은 댓글·제보 등록과 작가 확인만(UC-14), AI 분석·응대(UC-15)·수정안(UC-16)·크레딧(UC-17 지급·정산·보상)은 MVP 이후 | `확정`(사용자 결정). 기존 유스케이스의 해당 정책은 MVP 이후 범위로 유지 |
| DEC-24 | 과거 결정: 원고를 회차별로 붙여 넣어 등록하고(UC-03), 요청 회차의 AI 설정 추출 후보를 작가가 채택해 갱신 기록·관계로 저장(UC-04 수동 모드). 파일 업로드·발행 시 자동 추출 제외 | `부분 유지`(DEC-26·27). 후보 검토와 수동 추출 범위 유지, 댓글식 기록·관계 RDB 저장 대체. 채택한 후보를 새 문서 버전·그래프 관계에 반영하는 방식은 미정 |
| DEC-25 | 과거 결정: 세계관 항목은 카테고리·이름·별칭·본문(Markdown)의 문서이고, 관계(유형·감정)는 회차별로 별도 기록 | `부분 유지`(DEC-26). 카테고리별 고정 필드 없이 문서로 다루는 방향 유지; 관계 저장은 그래프 DB로 변경, 관계의 시점·버전 모델과 카테고리 목록은 미정 |
| DEC-23 | MVP는 팀 시연용 핵심 기능만. 단계는 MVP 하나. 범위는 [MVP 범위](design.md#포함과-제외) | `부분 유지`(DEC-27·28). 저장 버전·체크포인트·되돌리기는 이번 MVP 방향에 포함; 나머지 제외 범위는 유지 |
| DEC-26 | **MVP는 PostgreSQL에 설정·원고 원문과 문서 버전·체크포인트·Fork를 저장하고, 그래프 DB에 관계 정보를 저장·조회.** 소설 본문·설정 문서 전문은 그래프 DB에 두지 않음 | `확정`(사용자 결정). DEC-16·17의 RDB 단독 방향 대체. #132에서 관계의 유일 정본은 Neo4j 현재 상태, 연결 키는 world/card/relation UUID로 구체화. PG 요청 상태 + Neo4j CAS + PG finalization을 사용하며 실제 이관·운영 복구/백업은 대기; KAG 도입은 결정하지 않음 |
| DEC-27 | **MVP에서 pg_git 미적용.** 별도 Gitea도 사용하지 않음. 콘텐츠 변경과 되돌리기는 이전 버전을 덮어쓰지 않고 새 버전으로 남기며, 회차와 당시 설정·관계를 묶는 체크포인트와 독자의 작품 Fork를 지원 | `확정`(사용자 결정). pg_git(seanwevans/pg_git)의 포크·설치·개발은 MVP에 하지 않음. 이후 도입 방향은 DEC-30. 체크포인트 시점·구성과 현재 포인터, 다른 콘텐츠 초안의 처리는 `미정`. 설정 초안은 DEC-40, 세계관 상속과 원본 변경은 DEC-32~34·37이 구체화. #132 관계 현재 상태 MVP에서는 관계 이력/시점 복원을 제외하므로 관계까지 포함한 과거 체크포인트·Fork 지원을 뜻하지 않음 |
| DEC-28 | **Frontend는 작가·독자 전체 화면, 작가 도구는 그 하위 기능. 논리적 명칭은 Core Service·AI Service.** AI 시뮬레이션은 선택적 집필 보조이고 채택 전에는 공식 설정을 바꾸지 않음. 과거 MVP에서는 세계관 설정의 공개·비공개 구분을 제외 | `부분 대체`(DEC-36): 서비스 경계와 선택적 AI는 유지하지만, 설정 항목의 공개·비공개 및 회차별 공개 범위는 MVP에 포함. 기존 실행 디렉터리·패키지·URL의 `core-api`는 당장 바꾸지 않음. 집필 AI의 여섯 업무 Agent·시뮬레이션 행동/요약 목표 모델은 사용자 결정으로 OpenAI `gpt-6-luna`; 그 밖의 모델·프레임워크·조회 경로·배포 단위는 `미정` |
| DEC-29 | **Fork 창작의 기본 화면 방향은 원작 원고와 AI 채팅을 함께 보여 주는 것.** 독자는 소설을 어떻게 바꿀지 대화로 설명하고, 세계관·인물·관계 설정 변경이면 관련 설정 위치로 안내받을 수 있다. 바로 원고를 쓰는 것뿐 아니라 자기 Fork의 설정을 바꾸고 시작할 수 있다 | `확정`(사용자 방향), 업무 기능은 `미구현`. AI는 선택적 보조이며 대화만으로 원작·Fork를 자동 수정하지 않는다. 화면 진입 시점·원고 편집 범위·권한 세부는 `미정`. 세계관 상속과 수정 시점은 DEC-32~34가 구체화 |
| DEC-30 | **`seanwevans/pg_git`은 MVP 이후 신중히 도입을 추진한다.** MVP에 적용하지 않는 DEC-27은 유지한다 | `확정`(사용자 방향). 실제 도입 시점·재사용 범위·테이블 이력 연계·동시 작업 격리는 별도 검토; 포크·설치·개발은 아직 하지 않았다 |
| DEC-31 | **설정 항목마다 카테고리는 하나이고, 태그는 여러 개 붙일 수 있다.** 인물·광물·장소는 카테고리의 예다 | `확정`(사용자 결정). 고정 카테고리·자유 태그는 DEC-39가 구체화하고, 물리 저장은 별도 설계 |
| DEC-32 | **작품 Fork는 기준 회차까지 공개된 원작 세계관 설정을 이어받는다.** 독자가 수정하기 전에는 원본을 참조하고 원본 변경을 따라가며, 최초 설정 수정 시 세계관 전체 단위로 복사해 자기 세계관을 만든 뒤 수정한다 | `확정`(사용자 결정). 작품 Fork와 세계관 Fork를 구분한다. 미발행·권한 밖 정보는 제외. 나중에 만든 변경이라도 기준 회차에 적용·공개되면 추종 또는 알림으로 처리(DEC-37). 실제 복사·관계 정합성 구현은 미정 |
| DEC-33 | **인물의 기본 설정과 회차별 상태·지식은 세계관과 함께 이어진다.** 세계관·설정·상태·관계와 그 이력은 삭제하지 않고, 잘못된 내용의 제거·정정은 이전 이력을 보존하는 되돌리기(revert)로 처리한다 | `부분 예외`(#132 최신 사용자 변경 결정). 인물·설정·원고의 기존 버전/이력은 유지. 이번 MVP의 관계만 Neo4j 현재 상태 하나로 교체·제거하며 변경 이력·과거 snapshot·복원을 만들지 않음. 기존 SQL·관계 과거 데이터는 삭제하지 않고 미전환 상태를 명시. 회원·작품 등 다른 대상의 삭제 정책은 DEC-42(소프트 삭제)를 따름 |
| DEC-34 | **독자 전용 세계관을 만든 뒤 원본이 바뀌면 알리고, 독자가 변경 반영 여부를 선택한다.** 원본 변경은 선택 전 독립 세계관에 자동 반영하지 않는다 | `확정`(사용자 결정). rebase는 사용자가 변경 반영을 선택하는 업무 개념이며 알고리즘·충돌 처리·알림 전달 방식은 미정 |
| DEC-35 | **작품 Fork와 무관한 타인의 세계관 직접 이용은 MVP에서 제외한다.** 1차 개발 이후의 시점은 아직 정하지 않는다 | `확정`(사용자 결정). 허용된 작품을 Fork하며 그 원작 세계관을 이어받는 DEC-32는 유지 |
| DEC-36 | **설정은 항목별 공개·비공개와 회차별 공개 범위를 둔다.** 새 항목의 기본값은 비공개이고 생성 시 또는 이후에 직접 변경할 수 있다. 한 항목 안에 숨길 내용이 있으면 별도 항목으로 나눈다. AI는 변경 후보를 제시하고 작가가 확인한 뒤 반영한다 | `확정`(사용자 결정). DEC-28의 설정 공개 구분 제외를 대체. 설정의 실제 적용 시점과 공개 시점을 별도 값으로 기록할지의 상세 모델은 `미정`; 권한 밖 내용은 보여 주지 않음 |
| DEC-37 | **기준 회차의 공개 세계관 전체를 이어받고, 그 회차에 영향을 주는 원본 변경을 판정한다.** 내용·상태·지식·인물관계도가 세계관에 함께 속한다. 독자 수정 전에는 원본을 따라가고, 최초 수정 때 전체를 독자 소유로 복사한다. 독립 후 원본 변경은 알리고 선택적으로 반영하며, 거절한 변경도 나중에 다시 반영할 수 있다 | `확정`(사용자 결정). 예: 10화 작업 중 추가했어도 5화에 적용·공개되는 변경은 5화 Fork에 영향. 최초 기준 기록과 현재 참조는 구분; 원본의 미공개·권한 밖 정보는 제외. 실제 비교·충돌 처리와 이력 표시 방식은 `미정`. 범위는 세계관(설정·상태·지식·관계)이며, 원고 회차의 Fork 기준은 DEC-43(생성 시점 체크포인트 고정, 원작 갱신 미추종)을 따른다 |
| DEC-38 | **원작자는 작품 Fork 생성 허용과 Fork 작품 공개 허용을 각각 설정한다.** Fork 창작자는 이어받은 설정을 자유롭게 수정하며 설정별 수정 제한이나 별도의 AI 사용 허용 스위치를 두지 않는다. 공개 Fork에는 원작과 원작자를 표시한다 | `확정`(사용자 결정). 생성 허용 철회는 새 Fork만 막고 기존 Fork 창작은 유지. 공개 허용 철회는 미공개 Fork의 새 공개만 막고 이미 공개한 Fork는 계속 공개·발행. 변경 이력은 보존하며 권리 침해·법적 제한은 별도 처리. 등록자에게 2차 창작 권리를 정확히 확인했는지 묻되 플랫폼이 작품별 권리까지 직접 확인하지 않으며, 확인만으로 권리가 생기지는 않음. 외부 플랫폼 게시는 현재 범위 밖 |
| DEC-39 | **설정 항목은 고정 카테고리 하나와 창작자가 붙이는 여러 태그를 사용한다.** 이미지는 항목당 최대 10개를 MinIO(S3 호환)에 업로드하고 RDB에는 URL만 저장한다. 외부 참고 URL도 등록할 수 있다. 과거 이미지 파일은 변경 이력으로 보존하지 않는다 | `확정`(사용자 결정). DEC-31 구체화. 설정 이미지 복원은 텍스트 이력 복원에서 보장되지 않으며, 사용 중인 이미지의 참조 안전성·접근 제어·정리 시점 및 참고 URL의 개수·보안은 `미정`. 원고 이미지나 특정 배포 사업자는 이 결정의 범위가 아님 |
| DEC-40 | **설정 작성 중 자동저장은 같은 초안을 덮어쓰고, 사용자가 저장 버튼으로 확정하면 새 콘텐츠 버전을 만든다.** 저장은 공개·발행과 다르다 | `확정`(사용자 결정). DEC-27의 확정 이력 보존을 유지하되 설정 초안 자동저장 방식을 구체화. 자동저장 간격·동시 수정·물리 스키마는 `미정`; 다른 종류의 초안에 확대하지 않음 |
| DEC-41 | Core(회원·인증·크레딧·알림) / 콘텐츠 / 운영 / AI의 4개 백엔드 서비스로 분리. LLMOps는 운영 영역, Langfuse UI/API 통합 방식 미정 | `확정` 목표 구조. 분리 전 실행과 구분; [상세](#dec-41-4개-백엔드-서비스-분리) |
 DEC-42 | **사용자 결과물과 다른 데이터가 참조하는 데이터의 삭제는 소프트 삭제다.** 삭제 요청은 행을 지우지 않고 삭제 시각만 기록하며, 삭제된 데이터는 목록·검색·랭킹·읽기와 새 행위에서 제외한다. 하드 삭제(물리 삭제)와 보관 기간 후 자동 정리는 정하지 않는다 | `확정`(2026-11-09 사용자 결정). 소프트 대상: 작품·회차·세계관·Fork·댓글·피드백, 회원 탈퇴 후 콘텐츠, 운영 데이터(공지·문의 답변 등). 원작을 삭제해도 Fork는 원작 행을 그대로 참조하고 "삭제된 원작"으로 표시한다. 복구 화면은 MVP 범위 밖. 하드 삭제 예외: 설정·회차 초안(작업용 사본, DEC-40), 참조가 없는 첨부의 DB 행과 MinIO 파일(저장 버전·발행 원고가 참조하는 파일은 삭제 금지), 본인 알림함의 알림, 세션·토큰 폐기, Neo4j 관계 현재 상태의 교체·제거(#132). 다른 하드 삭제가 필요해지면 불변 이력 trigger의 예외 범위와 함께 별도로 결정한다 |
| DEC-43 | **회차 체크포인트는 발행본이다.** 작가가 회차의 저장 버전 하나를 골라 발행하면 그 회차의 체크포인트가 생긴다. 독자는 회차마다 현재 활성 체크포인트 하나만 보고, 작업 버전·초안·이전 체크포인트는 보지 않는다. 작가는 발행한 회차를 이전 체크포인트로 되돌릴 수 있다. Fork 기준은 체크포인트로만 정하며, 생성 시점의 기준 회차까지 각 회차의 활성 체크포인트를 가리킨다 | `확정`(2026-11-09 사용자 결정). 되돌리기는 이전 체크포인트를 다시 활성으로 만드는 새 기록이며 체크포인트 이력은 지우지 않는다. 원작이 이후 새 체크포인트를 발행하거나 되돌려도 Fork 원고는 처음 가리킨 체크포인트를 유지하고 불일치를 맞추지 않는다(원고 회차 한정, 세계관은 DEC-37 유지). 저장 버전 생성만으로 체크포인트를 만들지 않는다. 체크포인트는 기존 `publication_event`(publish/replace/republish·applied)로 표현하고 새 테이블을 두지 않는다. 되돌리기는 기존 회차 발행 API로 이전 체크포인트 버전을 다시 발행한다. 기존 DB에 남은 버전 저장 시점 체크포인트 행은 지우지 않는다 |
| DEC-44 | **작가의 말은 선택 입력(일반 텍스트, 최대 2,000자)이며 회차 초안·저장 버전·발행본에 함께 보존한다.** 저장만으로 공개하지 않고 발행 시 본문 뒤에 표시한다. 빈 값은 숨긴다. 복원·Fork도 해당 버전의 작가의 말을 유지하며 AI 문맥에서는 제외한다 | `확정`(2026-11-10 사용자 결정). 상속 회차 수정 제한 유지. [기능 62 상세](../usecase-spec/UC-10.md#회차-작가의-말--기능-62-2026-11-10-확정) |

### 이전 결정을 어떻게 읽을까

- DEC-05의 **서버가 권한을 판단한다는 원칙**은 유지합니다. DEC-41 이후 회원 인증·계정 제한은 Core, 콘텐츠 인가·발행은 콘텐츠, 운영 권한·판단은 운영 서비스가 담당합니다. 이전 Core 통합 소유 표기는 분리 전 구조입니다. 이전 설계의 지식 서비스용 범위·쓰기 토큰과 공개키 배포는 쓰지 않으며, 내부 통신 인증은 DEC-19에 따라 MVP 이후에 정합니다.
- DEC-08의 MinIO는 과거에 원고 이미지 제외와 함께 미루는 것으로 제안됐으나, DEC-39에 따라 설정 이미지용 MinIO(S3 호환)를 사용합니다. 원고 이미지 범위와 배포 방식은 별도입니다.
- 이전 X-03의 PostgreSQL 버전 테이블 대안은 새 버전 방향을 설계할 때 참고하되, 구현 방식이 확정됐다는 뜻은 아닙니다.
- 기존 문서의 `Core API`는 당분간 현재 실행 모듈·HTTP 경로를 가리킬 때만 사용합니다. 설계상 서비스 명칭은 `Core Service`입니다. DEC-16·20·21·23의 오래된 세부 흐름과 유스케이스·보조 다이어그램의 공개 구분·Gitea·버전 관련 문구는 이번 결정과 충돌하는 한 현재 MVP 기준이 아닙니다.

## 보존할 제품 규칙

1. 사용자 권한과 초안·발행본·Fork의 경계를 유지합니다. 세계관 설정은 항목별 공개·비공개와 회차별 공개 범위를 적용합니다(DEC-36). 미발행 원고·다른 사람의 작품·인물별 인지 정보도 구분합니다.
2. 작품 Fork의 기준 회차·원고 버전과 당시 허용 범위를 보존합니다. 세계관은 수정 전 원본 변경을 따라가고, 최초 수정으로 독립한 뒤에는 변경 알림과 선택적 반영을 따릅니다(DEC-32·34). 기준 기록과 현재 참조 상태를 혼동하지 않습니다.
3. AI 출력은 제안이며 승인·반영·발행·실패를 구분합니다. AI는 승인 없이 정본을 고치거나 권한을 판단하지 않습니다.
4. 그래프 DB의 관계를 조회할 때도 권한과 기준 회차·버전의 범위를 검증합니다. 저장소 간 반영 실패를 성공으로 숨기지 않습니다.

## 관계 현재 상태 MVP 예외 — #132

2026-11-05 사용자가 관계 이력 요구를 변경했다. **관계 내용은 Neo4j 현재 상태 하나만 저장하고 PG에 이중 저장하지 않는다.** 현재 token은 동시성·정합성 검사용이며 과거 버전이 아니다. 관계 삭제는 현재 payload/edge 제거이고 과거 snapshot·이력/복원 API는 만들지 않는다. 인물·설정·원고의 기존 버전 기능과 기존 SQL 바이트·데이터는 보존한다.

과거 카드 revision에는 `relationships=null`, `relationshipStatus=not_recorded`를 반환하며 현재 관계를 과거처럼 표시하지 않는다. 관계를 포함하는 세계관 전체 restore는 명시적 미지원이다. DEC-32·37의 전체 과거 세계관/Fork 목표를 현재 관계로 충족했다고 간주하지 않는다. 실제 기존 데이터 변환은 승인·실행하지 않았으며 미전환·미완료·저장소 불일치는 실패로 표시한다. 상세 API·저장 순서·원래 입력 재시도/새로고침 복구 한계·검증 범위는 [현재 계약](worldstudio-independent-schema.md#현재-관계-mvp-계약--132)을 따른다.

## DEC-41 4개 백엔드 서비스 분리

**상태: 확정 — 목표 서비스 경계. 실제 분리 구현·배포 전.**

- Core: 회원·인증·세션·크레딧·정산·회원 알림.
- 콘텐츠: 작품·세계관·회차·원고·버전·Fork·발행·독서·검색·작품 피드백·콘텐츠 첨부.
- 운영: 고객지원·공지·이벤트·신고 사건·소명·운영 판단·감사·작업 감시·LLMOps 운영 영역.
- AI: 요청된 생성·추출·시뮬레이션·검토 등 모델 실행.
- 콘텐츠·운영은 별도 Kotlin/Spring Boot 앱으로 분리하고 기존 Core·AI 구현을 재사용한다. 실행 전체를 위한 별도 Start 서버나 공통 starter 프레임워크는 선제 추가하지 않는다.
- LLMOps는 운영 영역에 분류한다. Langfuse 도입 시 별도 제품 서비스로 배포하는 방향이며, 자체 UI 사용 또는 운영 화면 API 통합은 미정이다. 도입 시점·상세 기능·평가 실행 계약은 이 결정으로 확정하지 않는다.
- 회원 제한은 Core, 콘텐츠 제한은 콘텐츠 서비스가 적용한다. 운영 서비스는 결정·요청·적용 결과를 관리하며 타 서비스 소유 테이블을 직접 수정하지 않는다. 정기 작업의 실행은 업무 소유 서비스, 감시는 운영 영역이다.
- 기존 서비스 책임과 `Frontend → Core → AI` 단일 경로의 목표 해석을 이 결정으로 대체한다. 현재 core-api의 URL·실행·데이터는 이전 전까지 유지한다. 기존 공개 범위·Fork·버전 정책과 MVP 제외 범위를 일괄 변경하지 않는다.
- DB는 PostgreSQL 서버 공동 사용·소유 범위 분리를 출발안으로 하되 스키마·계정·migration 전환은 미정이다. 기존 데이터·Flyway 이력을 보존한다.

상세: [서비스 경계·실행 구조](service-boundaries.md). 서비스 간 인증·정산·알림·조치·복구 계약은 후속 설계다. 이 결정은 코드 이동·인프라 설치·배포 승인이 아니다.
