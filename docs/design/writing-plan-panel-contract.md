# 집필실 고급 모드와 장면 순서 (#374)

2026-11-16 사용자 승인 범위: 집필실 내부 플롯·장면 계획, 미저장 입력 보호, 시뮬레이션 연계와 **기존 API 계약 확장을 통한 회차별 장면 순서 영구 저장**. 단독 `?view=narrative` 주소는 유지한다. 새 엔드포인트·production 의존성은 추가하지 않는다.

## 화면과 입력

- 기본 모드는 원고 중심, 고급 모드는 원고(또는 시뮬레이션) 옆 계획 패널이다. 좁은 화면에서는 아래로 배치한다. 계획 편집 폼은 패널 안에 있고, 기본 모드로 전환해도 패널을 숨길 뿐 편집 상태를 버리지 않는다.
- 패널은 열린 회차를 기본으로 표시하고 다른 회차·회차 미정·전체를 선택할 수 있다. 플롯 선택은 상세 조회와 새 장면의 소속 선택이다. 고급 패널의 장면 목록은 선택한 회차 전체(여러 플롯 포함)를 보여 주며 각 장면에 소속 플롯을 표시한다.
- 새 장면은 패널에서 선택한 회차를 기본으로 쓴다(전체 보기에서는 열린 원고 회차). 계획 회차 선택은 원고 회차를 이동시키지 않는다.
- 집필실의 플롯 버튼과 시뮬레이션의 계획 없음 안내는 고급 패널을 열고 초점을 옮긴다. 페이지 이동은 없다.
- '모든 회차' 목록은 회차 번호(미정은 마지막)·position 순으로 묶어 보인다. 인라인 편집을 닫거나 순서를 옮긴 뒤에는 누른 버튼(잠겼으면 같은 줄의 다른 버튼, 회차를 옮겨 목록에서 빠졌으면 장면 계획 추가)으로 초점을 돌려준다.
- 회차 이동 전에 계획과 원고의 미저장 상태를 확인한다. 확인 단계에서는 입력을 지우지 않는다. 원고 이동을 취소하면 양쪽 모두 유지되고, 회차 이동을 허용해도 계획 편집 입력과 원래 연결 회차는 유지된다. 실제 페이지 이탈만 마운트 해제로 입력을 버린다.
- 원고 저장 버튼은 계획을 닫거나 버리지 않는다. 계획 저장 실패·409도 입력을 남긴다. 저장 성공 뒤 목록 재조회만 실패한 경우에는 저장 성공과 재조회 실패를 구분한다.
- 미저장 계획 또는 처리 중 계획, 미저장/처리 중 원고가 있으면 시뮬레이션 시작 양식을 잠그고 이유를 보인다. 원고는 기존 자동 저장을 유지한다. 계획은 명시적으로 저장하거나 편집을 취소한다.

## 기존 API 확장

기존 `/api/v1/works/{workId}/story-plans`의 POST/GET 및 `/{id}`의 GET/PUT을 그대로 쓴다.

- 요청: 선택적 `position: integer >= 0`. **장면만** 지정할 수 있다. 0부터 시작하며 지정 가능한 최댓값은 대상 회차의 다른 활성 장면 수다. 플롯에 지정하거나 범위를 벗어나면 422다.
- 응답: `position: integer >= 0`. 기존 클라이언트가 요청에서 생략하면 새 장면·다른 회차로 옮긴 장면은 끝에 추가하고, 같은 회차의 내용 수정은 상대 순서를 유지한다.
- 순서는 작품+회차 단위로 여러 플롯의 장면을 함께 정한다. 회차 미정(null) 장면은 별도 그룹이다. 플롯끼리의 순서 변경은 이번 범위가 아니다. 같은 회차 번호라도 삭제된 이전 회차에 묶인 장면(`episodeMissing`)은 순서 계산에서 빠진다(화면 `scenePlans`와 같은 기준).
- 순서 이동은 기존 PUT 한 번으로 요청한다. `WorkAccessService.own`의 작품 잠금 안에서 대상 장면과 밀리는 이웃을 같은 트랜잭션으로 정렬한다. 위치가 바뀐 이웃도 revision을 올리므로 오래된 편집 요청은 409다. 화면은 이동 저장 성공을 먼저 알리고 목록을 따로 다시 읽어 모든 revision을 갱신한다. 재조회만 실패하면 저장 성공과 재조회 실패를 구분해 보이고, 옮긴 장면은 저장 응답으로 갱신하며 `다시 불러오기`로 최신 revision을 받기 전까지 순서 이동을 잠근다.
- 삭제는 기존 논리 삭제다. 남은 순번의 빈자리는 허용하며, 내용 수정 때문에 상대 순서가 바뀌지 않는다. 회차를 바꿔도 이전 회차의 남은 장면 순서는 유지된다.
- 일반 편집은 조회 응답을 그대로 재전송하지 않고 `position`을 생략한다. 순서 이동 때만 현재 회차 목록의 목적지 인덱스를 요청에 넣는다. 응답의 저장 순번에 빈자리가 있어도 그대로 이동 인덱스로 사용하지 않는다.
- 목록은 position 순으로, 동률은 기존 createdAt·id 순으로 반환한다. 서로 다른 회차 사이의 순서는 의미가 없다.
- 기존 참조·삭제된 회차 재연결 방지·소유권·CSRF·revision 검사는 유지한다. 계획 변경은 원고·설정 정본을 수정하지 않는다.

`plan/V38__story_plan_scene_position.sql`은 position 열과 음수 금지 제약을 추가하고, 기존 활성 장면을 작품+회차별 created_at·id 순으로 채운다. 기존 migration 파일은 변경하지 않는다. 실제 공유 DB migration은 이 작업에서 실행하지 않는다.

## 시뮬레이션 연결

- 시작 양식은 집필실에서 열린 회차의 저장된 장면을 position 순으로 읽는다. 계획 패널의 조회 회차와 시뮬레이션 대상 회차를 혼동하지 않는다.
- 저장·삭제·이동·`다시 불러오기` 이후 양식의 목록을 다시 읽는다(응답을 잃은 저장도 다시 불러오면 반영된다). 갱신 중/실패 시 오래된 비트로 시작하지 못한다. 양식 입력·인물 선택은 유지하며, 아직 직접 고르지 않은 흐름 참여 인물만 새 비트에서 다시 추천한다.
- 기존 `제목: 내용`, 최대 8개·각 200자 규칙을 유지하고 화면에도 안내한다. 끊긴 회차의 계획은 비트에서 제외한다.
- 시작 양식을 닫고 다시 열어도 입력을 유지하며 최신 목록을 재조회한다. 실행 중인 시뮬레이션 비트는 계획 변경으로 소급 수정하지 않는다.
- WorldStudio 인물·장소 ID 이관(#363), AI 계획 제안, 추가 고급 도구는 제외한다.
