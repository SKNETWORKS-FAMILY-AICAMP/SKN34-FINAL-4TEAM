# AI Service 설계 (현재 실행 모듈: `ai-service`)

[메인 README](../../../README.md) · [문서 목록](../../README.md)

> **DEC-41 서비스 경계.** 현재 Content는 콘텐츠 권한·기준 버전과 제안 저장·채택을 담당하고 내부 HTTP로 AI Service에 생성을 요청합니다. Core는 AI Health를 확인합니다. [서비스 책임](../service-boundaries.md)과 [AI 구현 경계](../../../backend/ai-service/docs/agent-structure.md)를 따릅니다.

> **상태: 선택적 원고 생성 구현 · 전체 AI 업무는 목표 설계.** [상위 설계](../design.md)와 [결정 기록](../decisions.md#결정-목록), 특히 DEC-41을 따릅니다. 이전 [KAG 설계](../archive/kag-design/services/ai-service.md)는 현행 MVP가 아닙니다.

## 목적과 현재 상태

AI Service는 작가가 요청한 원고 설정 추출, 선택적 집필 지원과 다중 인물 시뮬레이션의 **후보**를 돌려줍니다. 작가는 후보를 검토·수정·채택할 수 있으며 AI 실행 자체는 정본 변경이나 발행이 아닙니다. 직접 집필과 독자의 Fork에 AI 실행을 필수로 넣지 않습니다.

`현재` FastAPI는 `GET /internal/v1/health`와 선택적 콘텐츠 생성 `/internal/v1/proposals`를 제공하며 명시적 요청 시 설정된 OpenAI 모델을 호출합니다. 전체 시뮬레이션·운영 검사 기능이 구현됐다는 뜻은 아닙니다. 현재 `openai-agents` 의존성이 있다는 사실이 MVP 모델·프레임워크를 확정하지 않습니다. 이전 문서의 OpenAI·LangChain·LangGraph는 검토할 수 있지만 이번 방향에서는 **미정**입니다. 새 의존성이나 유료 API 호출은 구현 요청·선정 전에는 추가하지 않습니다.

## 책임과 문맥 경계

| AI Service (Python 실행) | 콘텐츠 서비스 및 사용자 |
|---|---|
| 인물별 행동·대화와 전개, 원고 문장·상태 변화의 제안 생성 | 작품·문서·회차·버전·Fork 정본, 권한·발행·채택의 최종 판단 |
| 요청에 허용된 설정 문서·원고·관계 정보만 사용 | 대상 작품·기준 시점·인물별 인지 범위를 정하고 접근을 통제 |
| 구조화 결과·근거·사용량·실패를 실제 상태로 반환 | 결과 검토, 기준 버전 재검증, 새 버전 및 관계 반영 |

AI가 그래프 관계만 읽고 원고·설정 문서를 무시해서는 안 됩니다. 목표 콘텐츠 서비스의 읽기 전용 내부 조회 도구가 **제안 경로**이며 AI의 저장소 직접 접근 여부는 미정입니다. 어떤 경로든 원고·문서의 기준 버전과 해당 회차의 관계 상태를 맞추고, 권한과 인물별 인지 범위를 조회 **본문과 관계 모두**에 적용해야 합니다. 모델이 보내는 항목 ID나 다른 작업의 ID는 권한 증명이 아닙니다. 조회 오류를 빈 결과로 바꾸지 않습니다.

운영 목적 검사·평가는 운영 서비스의 요청으로 구분하며 콘텐츠 제한은 콘텐츠, 회원 제한은 Core가 적용합니다. AI 모델 판정은 운영의 최종 판단이나 정본 반영 성공을 뜻하지 않습니다. 브라우저는 내부 AI를 직접 호출하지 않고 서비스 간 인증·알림 사건 계약은 후속 설계합니다.

## 선택적 시뮬레이션과 설정 추출

- 진행자 역할은 장면과 사건 흐름을 조율하고, 인물 역할은 자신의 성격·목표·그때 알고 있는 사실과 관계를 바탕으로 행동·대사를 제안합니다. 인물마다 서버나 에이전트 구현을 복제한다는 뜻이 아닙니다.
- 한 인물만 아는 사실, 관찰하지 않은 대사·사적인 생각이나 미래 사건을 다른 인물의 입력으로 섞지 않습니다. 실행 중 임시 상태는 다른 실행이나 확정 관계에 자동 반영하지 않습니다.
- 플롯에 **예정된** 관계 변화는 실제로 확정된 사건·현재 관계와 구분합니다. 시뮬레이션의 상태 변화 역시 채택 전에는 후보입니다.
- 작가가 요청한 원고 회차의 설정 추출은 문서·관계·상태 변화 **후보**와 근거를 제시합니다(DEC-24). 사용자가 검토 후 채택·수정 승인한 후보만 콘텐츠 서비스가 확정하며 추출 실패는 기존 문서·관계를 바꾸지 않습니다.
- 독자의 Fork 창작 화면에서는 허용된 원작 원고를 바탕으로 소설을 바꾸려는 대화를 돕습니다. 세계관·인물·관계 설정 변경과 관련되면 해당 설정 위치를 안내하는 방향입니다(DEC-29). 대화·안내만으로 원작이나 Fork 정본을 변경하지 않으며, 실제 수정·저장과 권한 확인은 콘텐츠 서비스 및 사용자 책임입니다. 채팅·설정 안내의 구체 계약과 보관 정책은 미정입니다.
- 인물 정보가 부족하거나 모델 출력이 검증을 통과하지 못하면 성공을 꾸미지 않고 근거 부족 또는 실패를 구분합니다. 제안의 근거 ID가 허용 범위에 속해도 사실성과 누설 방지가 입증되는 것은 아닙니다.

## API·구현 후보

`현재` Health와 선택적 원고 생성 API를 제공합니다. 현행 원고 생성 계약을 보존하며 추가 추출·시뮬레이션 API의 DTO·경로는 미정입니다. 이전 `search_items`·`get_item`·`get_relations` 및 기존 명칭 `/internal/v1/ai-tasks/...`는 목표 콘텐츠 소유 조회를 제공할 경우의 후보이지 확정 API가 아닙니다. 대화·실행 상태 저장은 [LangGraph PostgresSaver를 후보로 조사](../erd/ai-service/postgres-saver.md#3-langgraph-postgressaver의-실제-테이블)했으며 도입 여부는 미정입니다. 모델·제공사·프레임워크, 호출·분량 한도도 정하지 않았습니다. 단일 작업에 무조건 다중 에이전트 프레임워크를 쓰거나 역할마다 서버를 만들지 않습니다.

## 실패·보안·관측

- 모델 실패·시간 초과·거부·취소·근거 부족·스키마 위반을 성공으로 숨기거나 부분 결과를 확정하지 않습니다. 관계 저장소와 문서 버전이 맞지 않으면 그 상태를 성공한 응답으로 사용하지 않습니다.
- 원고·피드백·조회 결과는 신뢰할 수 없는 데이터로 다룹니다. 비밀값·원고 전문·개인정보·모델 출력 본문을 로그나 브라우저에 노출하지 않습니다.
- 콘텐츠 요청의 작업·기준 버전·허용 문맥·제안·채택·저장은 콘텐츠 서비스, 운영 검사·평가 작업은 운영 서비스, 크레딧 원장·최종 정산은 Core가 소유합니다. AI는 필요한 실행 상태·사용량·결과를 반환하며 추가 기능의 호출·정산·복구 계약은 해당 기능에서 정합니다.
- LLMOps는 운영 영역이며 Langfuse는 MVP 이후입니다(DEC-18·41). 도입 시 별도 제품 서비스로 배포하고 Spring Boot로 재구현하지 않습니다. 자체 UI 사용 또는 우리 운영 화면 API 통합, 평가 실행 위치·버전 적용·보관 책임은 미정입니다. 모델 API 키는 AI 런타임에만 주입합니다.
- 기존 Core↔AI 내부 인증 유예(DEC-19)는 로컬 시연 경계에 한정됩니다. 포트 비공개는 인증이 아닙니다.

## 검증 계획·미정

구현 시 인물별 문맥 격리, 미래 회차·다른 작품의 문서/관계 누출 차단, Fork 시점 고정, 예정 사건과 확정 관계 분리, 제안·채택·관계 반영의 상태 구분과 각 실패 경로를 확인합니다. 현재 E2E·모델 품질 검증은 수행하지 않았습니다. 모델·프레임워크, DB 조회 경로, 관계 버전 일치, 구체 API·한도는 후속 결정입니다.
