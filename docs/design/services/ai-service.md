# ai-service (`storyfork-ai-service`)

> **문서 상태: RDB 기반 MVP 상세 설계 초안 — 업무 기능 미구현.** 상위 [시스템 설계](../design.md)와 [결정 기록](../decisions.md#결정-목록)(DEC-16~23)을 따릅니다. 이전 안은 [보관 문서](../archive/kag-design/services/ai-service.md)에 있습니다. 표기(`현재`·`확정`·`제안`·`미정`)는 [상위 설계](../design.md#표기)를 따릅니다.

## 목적과 현재 상태

AI Service는 **Core가 만든 AI 작업을 받아 집필 제안과 다중 인물 시뮬레이션 결과를 제안으로 반환**합니다. 필요한 세계관 정보는 **도구로 Core 내부 조회 API를 호출**해 읽으며, 조회 범위는 Core가 작업 생성 때 고정합니다(DEC-21).

- `현재`: `app/main.py → health/router.py → HealthResponse`의 `GET /internal/v1/health`만 제공합니다. 모델·Agent·생성 API는 없습니다. Health는 OpenAI 키나 모델을 쓰지 않으며 모델 접근 검증이 아닙니다.
- `목표`: `Frontend → Core API → AI Service → OpenAI`. AI → Core는 작업 범위로 제한된 읽기 전용 조회만 합니다. 역할마다 별도 서비스를 만들지 않습니다.
- AI 결과 생성은 저장·승인·발행이 아닙니다. 반영·발행은 사용자 선택 후 Core가 판단합니다(BR-01).

## 책임과 경계

| AI Service가 할 일 | Core가 소유하는 일 |
|---|---|
| 집필 제안, 다중 인물 시뮬레이션 | 작품·세계관·회차·Fork 정본, 권한·권리 판단 |
| 도구로 필요한 항목을 검색·조회 | 작업의 조회 범위(작품·기준 회차·목적·인물) 고정과 범위 적용 |
| 역할별 입력·임시 상태 격리, 구조화 출력 검증, 실패를 명시적으로 전달 | 작업 상태·사용량 기록, 근거 확인, 제안의 채택·반영·발행 |

AI Service는 DB에 직접 접근하지 않고 정본을 고치지 않으며 권한·발행을 확정하지 않습니다. 도구는 작업 ID와 검색어·항목 ID만 Core에 보내고, 작품·회차·인물 범위를 요청에 넣지 않습니다. 임시 실행 상태는 요청별로 분리하고 요청이 끝나면 남기지 않습니다([F-OPS-04](../../requirements.md#f-ops-04)).

## 기술과 구성

| 항목 | 내용 | 상태 |
|---|---|---|
| 런타임 | Python 3.11 이상 3.15 미만, FastAPI·Pydantic·Uvicorn | `현재` |
| LLM | LangChain으로 OpenAI 연동과 도구 호출. 다중 인물 시뮬레이션처럼 여러 역할이 필요한 경우에만 LangGraph | `확정`(AI Service 지침), 미구현 |
| 의존성 | 현재 `openai-agents`는 첫 AI 기능 구현 시 LangChain·LangGraph로 교체. 그 전에는 lockfile을 미리 바꾸지 않음 | `확정` |
| 모델 | OpenAI LLM. 모더레이션 모델은 시연 이후. 구체 모델·한도는 구현 시 결정. 다른 provider나 규칙 기반 fallback 없음 | `확정`, 미구현 |
| 추적 | Langfuse는 MVP 이후(DEC-18). MVP에서는 사용량·결과 상태를 응답으로 Core에 전달 | `확정` |

구성은 `router → service → (필요할 때만 LangGraph) → LangChain OpenAI 모델`입니다. 범용 오케스트레이터·큐·worker를 만들지 않습니다. 자세한 기준은 [AI Agent 구현 경계](../../../backend/ai-service/docs/agent-structure.md)입니다.

## MVP 기능

| 기능 | AI가 하는 일 | 관련 UC |
|---|---|---|
| 협업 집필 | 장면·대화·원고 초안·문장 개선 제안 | [UC-11](../../usecase-spec/UC-11.md) |
| 다중 인물 시뮬레이션 | 사건 진행, 인물별 행동·대화, 전개 후보 생성 | [UC-09](../../usecase-spec/UC-09.md) |

**시연 이후:** 모더레이션(UC-14 1차 필터), 설정 추출(UC-04), 설정 검토(UC-12), 독자 스토리 오류 검증(UC-09 A5), 피드백 응대(UC-15), 자율 연재(UC-18), 일러스트·캐릭터 챗(기존 MVP 제외).

## 도구 조회 (`확정`, DEC-21)

| 도구(가칭) | 입력 | Core 응답 |
|---|---|---|
| `search_items` | 검색어(이름·별칭) | 작업 범위 안에서 일치하는 항목 ID·이름 목록 |
| `get_item` | 항목 ID | 작업 범위 기준의 현재 내용. 범위 밖이면 "없음" |
| `get_relations` | 항목 ID | 범위 안의 직접 관계(1단계) |

- **범위:** 집필은 작가의 해당 작품 권한 범위, 시뮬레이션 인물 역할은 그 인물이 기준 회차에 아는 사실만 돌려받습니다. Fork 작품은 분기 시점 복사본과 분기 이후 자료만 돌려받습니다. 빌린 세계관의 비노출 항목은 응답에 없습니다.
- **미리 보낸 문맥:** Core는 회차의 `@` 연결 항목처럼 확실히 필요한 정보를 요청에 함께 보낼 수 있습니다. 도구는 그 밖의 정보가 필요할 때 씁니다.
- **한도:** 작업당 도구 호출 횟수와 응답 분량을 제한합니다. 구체 값은 구현 시 정합니다(`제안`).
- **조회 실패:** Core 조회 실패는 빈 결과로 바꾸지 않고 작업 실패로 처리합니다.

## 입력·출력 계약 (`제안`)

구체 DTO·경로는 아직 정하지 않았습니다.

**입력:** AI 작업 ID, 작업 목적, 요청 입력(집필 지시·시뮬레이션 조건), 미리 보낸 문맥, 시간·인물 수·진행 횟수·출력 분량 한도. 시뮬레이션은 인물별 기본 정보를 구분해 보냅니다. 사용자 식별자·연락처는 보내지 않습니다.

**출력:** 구조화된 제안, 사용한 근거 항목 ID, 모델 사용량, 결과 상태와 실패 분류.

- AI는 이 작업에서 받은 항목 ID만 인용합니다. 근거가 부족하면 추측하지 않고 `근거 부족`으로 표시합니다.
- Core는 인용된 ID가 작업 범위 안인지 확인하고, 범위 밖이면 결과를 쓰지 않습니다.
- **ID가 범위 안이라는 사실만으로 답변의 진실성이나 비공개 정보 누설이 없음을 보장하지 않습니다.** 누설 시험은 아래 검증 계획에 따릅니다.
- 입력·출력 스키마를 검증하며 잘못된 모델 출력을 임의로 보정해 성공으로 만들지 않습니다.

## 다중 인물 실행 경계 (`제안`)

인물·스토리 계획 역할은 같은 서비스에서 입력과 출력 책임을 구분한 역할이며 인물마다 별도 구현을 만들지 않습니다.

| 역할 | 할 일과 허용 입력 |
|---|---|
| 인물 | 해당 인물이 아는 사실·성격·목표와 관찰 가능한 상황으로 행동·대화 제안. 도구 조회도 그 인물 범위로 제한 |
| 스토리 계획 | 작가 권한 범위의 사건·조건으로 진행·차례·종료 관리 |

1. Core는 작업을 만들 때 인물별 조회 범위를 함께 고정합니다. 인물 역할의 도구 호출은 그 인물 범위로만 응답받습니다.
2. 계획 역할이 받은 정보를 인물 역할에 그대로 넘기지 않습니다. 인물에게는 실제로 관찰할 수 있는 상황만 전달합니다.
3. 진행 중의 대사·행동은 실행 단위의 임시 정보입니다. 다른 인물에게는 그 인물이 보고 들은 내용만 전달하고 사적인 생각은 전달하지 않습니다.
4. 결과는 제안으로만 반환합니다. 사용자가 집필 재료를 선택·수정·폐기하고, Core가 반영합니다(UC-09, BR-01).

인물 정보가 부족하면 Core가 안내하고 진행 여부를 묻습니다(UC-09 E3). 한도 초과나 중단된 부분 결과를 완료로 표시하지 않습니다.

## 제공 API와 호출 대상

`GET /internal/v1/health`만 `현재` 제공됩니다. 아래는 Core → AI의 가칭 범주입니다.

| 범주 | 용도 | 작업 시간 기준 |
|---|---|---|
| `writing-suggestions` | 집필 제안 | 3분 |
| `simulations` | 다중 인물 시뮬레이션 | 10분 |

AI → Core 호출은 [Core 내부 조회 API](core-api.md#제공-api)뿐입니다. 시간 기준은 [UC-21](../../usecase-spec/UC-21.md)의 업무 기준이며 구현 시 조정합니다.

## 실패·보안

| 상황 | 처리 원칙 |
|---|---|
| 입력·출력 스키마 위반, 범위 밖 ID 인용 | 결과를 쓰지 않고 명시적 실패 |
| 근거 부족 | 실패와 구별해 근거 부족 표시 |
| Core 조회 실패 | 빈 결과로 바꾸지 않고 작업 실패 |
| OpenAI 오류·시간 초과·안전 정책 거부 | 사유를 구분해 실패로 반환. fallback이나 부분 결과를 완료로 대체하지 않음 |
| 실행 중 취소 | 완료·실패와 구분하고 부분 결과를 확정하지 않음 |

- **내부 통신:** Core ↔ AI 인증은 MVP 이후입니다(DEC-19). MVP에서는 AI Service와 Core 내부 조회 API를 호스트에 공개하지 않으며, 이것은 인증이 아닙니다.
- **프롬프트 주입:** 원고·피드백·도구 응답을 지시가 아닌 데이터로 다루고, 모델에 쓰기 도구를 주지 않습니다. 모델이 다른 작업 ID나 범위를 지정하는 도구 인자는 두지 않습니다.
- **비밀값:** OpenAI 키는 AI 런타임에만 둡니다. `OPENAI_API_KEY`·`OPENAI_MODEL`은 현재 Health에서 읽지 않는 예약 설정입니다.

## 관측성

Langfuse는 MVP 이후입니다(DEC-18). MVP 동안 AI Service는 모델·토큰 사용량·결과 상태를 응답에 담고 Core가 작업 기록으로 남깁니다. 원고·프롬프트·모델 출력 본문, 비공개 설정, 개인정보, 비밀값은 로그에 남기지 않습니다. 도입할 때는 이전 설계의 추적 규칙(DEC-15)을 참고합니다.

## 구현 전 검증 시나리오

아래는 **향후 테스트 계획**이며 이번 문서 작업에서 실행된 테스트가 아닙니다.

1. **인물 격리:** A만 아는 비밀을 심고, B 역할의 도구 응답·모델 입력·최종 결과에 나오지 않는지 확인합니다.
2. **조회 범위:** 미래 회차·비노출 항목·다른 작품 ID를 도구로 요청하면 "없음"이 오는지, 종료된 작업 ID의 조회가 거절되는지 확인합니다.
3. **근거:** 받지 않은 ID 인용을 거부하고, 허용된 ID로 비공개 사실을 재구성하는 사례를 별도로 시험합니다.
4. **실패 구분:** 공급자 오류·시간 초과·잘못된 출력·취소·근거 부족이 서로 섞이지 않는지 확인합니다.

테스트 대역을 쓴 계약 검증과 실제 모델의 한국어 품질·누설 시험은 별도로 보고합니다.

## 미정

- 도구 호출 횟수·응답 분량 한도, 인물 수·진행 횟수 한도, 장편 문맥 처리.
- 시연 이후: pgvector(DEC-17), Langfuse(DEC-18), 내부 통신 인증(DEC-19), 모더레이션·피드백 응대·설정 추출·검토·자율 연재(DEC-22·23).
