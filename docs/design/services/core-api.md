# core-api (`storyfork-core-api`)

> **문서 상태: RDB 기반 MVP 설계 초안 — 업무 기능·저장소 미구현.** 현재는 Core·AI Health와 안전한 통신 오류 처리만 제공한다. 이 문서의 모듈·저장·API·흐름은 구현 사실이 아니다.

>
> 근거: [공통 지침](../../../AGENTS.md), [Core 지침](../../../backend/core-api/AGENTS.md), [현재 아키텍처](../../architecture.md), [유스케이스](../../usecase.md), [유스케이스 명세·공통 규칙](../../usecase-spec/README.md). 표기(`현재`·`확정`·`제안`·`미정`)는 [상위 설계](../design.md#표기)를 따른다.

## 목적과 책임

Core API는 **세계관·작품·회차 버전·Fork의 정본과 권한·승인·발행 판단 및 저장**을 소유한다. 기본 경로는 `Frontend → Core API → AI Service → OpenAI`다. 프런트엔드는 공개 Core API만 호출하고, AI Service는 Core가 범위를 정한 조회 API로만 세계관을 읽으며 정본·권한·발행을 확정하지 않는다.

| Core가 할 일 | 하지 않는 일 |
|---|---|
| 사용자 인증, 대상별 소유·이용 권한과 공개·권리 제한 판단 | 클라이언트나 모델이 제시한 ID·범위를 권한의 근거로 신뢰 |
| 세계관 항목·갱신 기록, 작품별 회차 기록, 원고·발행본·Fork의 저장과 조회 | AI 제안, 임시 시뮬레이션 상태를 승인 없이 정본으로 취급 |
| AI 작업 생성 때 조회 범위 고정, AI 도구 조회에 범위 안의 내용만 응답, 반환된 근거 확인 | AI Service에 DB 자격 증명·쓰기 권한을 주거나 Core에 OpenAI 키를 전달 |
| AI 작업 상태·사용량 기록, 댓글·제보 등록 | 생성 성공만으로 저장·승인·발행이 성공했다고 표시 |

## 기술 스택과 현재 상태

| 항목 | 내용 | 상태 |
|---|---|---|
| Core 런타임 | Kotlin 2.4, Spring Boot 4.1, JDK 21. 현재 webmvc·restclient·validation과 Jackson Kotlin 사용 | `현재` |
| 정본 저장 | Core 전용 PostgreSQL(core-postgres의 core DB) | `확정`(DEC-17), 미구현 |
| 스키마 관리 | Flyway. 버전 파일은 core-api 안에 둠. DB 접근 라이브러리는 첫 구현 때 결정 | `확정`(DEC-17), 미구현 |
| 검색 | 이름·별칭 텍스트 검색과 직접 관계 조회. pgvector·임베딩 없음 | `확정`(DEC-17). 한국어 처리 방식 `미정` |
| 사용자 인증 | 이메일·비밀번호 로그인, JWT 접근 토큰만. 갱신 토큰·이메일 인증은 시연 이후 | `확정`(DEC-22·23), 라이브러리 `미정` |
| 내장 스케줄러 | 자율 연재·정기 작업용. MVP 이후 | `제안` |

Langfuse는 MVP 이후다(DEC-18). MVP에서는 Core의 AI 작업 기록(작업 ID·유형·모델·토큰·지연·결과 상태)으로 사용량과 실패를 확인하며, 원고·비공개 설정·개인정보·비밀값을 기록에 남기지 않는다.

## 내부 구조

패키지 `ai.storyfork.core` 아래에 기능이 실제로 필요할 때만 디렉터리를 둔다. Core 지침의 `controller → service → repository` 또는 `controller → service → (필요할 때만 facade) → client`를 따른다. 공개 계약은 `controller/dto`, 외부 계약은 `client/dto`, 내부 결과는 `service/dto`, 업무 모델은 `domain`에 둔다. 아래 이름은 책임을 설명하는 가칭이며 폴더나 공통 추상화의 선생성을 요구하지 않는다.

## 소유 데이터와 저장소

아래는 **논리적 소유와 개념 설계**이지 확정된 테이블·ERD가 아니다. 단일 DB는 원자적 저장을 설계할 수 있게 할 뿐 그 자체로 격리·권한·동시성을 보장하지 않는다.

| 데이터 | Core의 소유·보존 범위 |
|---|---|
| 세계관 | 소유자·공개/이용/Fork 조건, 카테고리 문서와 문서별 갱신 기록, 회차별 관계(유형·감정) |
| 작품별 기록 | 작품과 연결, 설정 유효 회차, 독자 공개 회차, 인물별 인지 회차, 작품별 인물 상태·`@` 연결. 세계관 기록과 구분 |
| 회차 | 초안, 발행본 |
| Fork | 원작·기준 회차, 고정된 발행본, 분기 시점에서 복사한 Fork 전용 세계관과 작품별 기록 |
| 기타 | 계정, AI 작업·제안·사용량, 댓글·제보 |

### 세계관 갱신 기록 (`확정`, DEC-20)

| 개념 | 규칙 |
|---|---|
| 항목 | 게시글처럼 안정적인 ID를 가진다. 이용자 노출 여부를 갖는다 |
| 갱신 기록 | 댓글처럼 항목 아래에 추가만 한다. 내용·반영 회차·작성 방식을 담는다. 고치거나 지우지 않으며 정정·복원도 새 기록이다(BR-10) |
| 현재 내용 | 항목의 마지막 갱신 기록 |
| 고정 | 이용 허가 철회 등으로 고정할 때 그 시점의 마지막 기록 ID를 연결에 저장하고 그 ID까지만 읽는다 |
| 충돌 | 저장 요청에 읽은 마지막 기록 ID를 받아, 그 사이 새 기록이 있으면 덮어쓰지 않고 충돌을 알린다(CE-07) |

| 원고 개념 | 규칙 |
|---|---|
| 초안 | 회차마다 작가가 저장하는 작업본. 저장하면 덮어쓴다(시연용 단순화, 저장 버전 이력은 시연 이후) |
| 발행본 | 발행할 때 초안 내용을 복사해 둔 독자용 본문. 다시 발행하면 새 발행본으로 바꾸고, 실패하면 기존 발행본을 유지한다. 독자는 초안을 보지 않는다 |

MVP에서는 작가가 자기 세계관 하나를 작품 하나에 연결한다. 다른 작가 세계관 이용·세계관 Fork·작품당 여러 세계관 연결은 시연 이후이며 정책은 [UC-02](../../usecase-spec/UC-02.md)·[UC-05](../../usecase-spec/UC-05.md)·[UC-24](../../usecase-spec/UC-24.md)에 있다.

## 인증·권한·정보 범위

### 인증과 내부 통신

- MVP 계정은 이메일·비밀번호 가입·로그인과 JWT 접근 토큰이다. 시연 편의를 위해 접근 토큰 만료를 늘릴 수 있으며 만료되면 다시 로그인한다. 갱신 토큰·기기 관리(UC-22의 30분·14일 정책), 이메일 인증·비밀번호 재설정은 시연 이후다(DEC-22·23). 비밀번호는 해시로만 저장한다. 브라우저 보관·CSRF/XSS 대책, 실패 잠금과 운영자 계정 부여 방식은 `미정`이다([UC-22](../../usecase-spec/UC-22.md)).
- Core는 대상별 소유·이용 권한, 공개 상태와 권리 제한을 판단한다. 비공개 대상은 존재 여부가 노출되지 않도록 응답하며, 운영자도 비공개 원고를 임의로 열람하지 않는다.
- Core ↔ AI 내부 통신 인증은 MVP 이후다(DEC-19). MVP에서는 AI Service와 Core 내부 조회 API를 호스트에 공개하지 않으며, 이것이 인증을 대체하지 않으므로 로컬 검증 범위를 넘는 배포 전에 정한다. 사용자 토큰·DB 자격 증명은 AI에 넘기지 않고 OpenAI 키는 AI 런타임에만 둔다.
- 작품·세계관 등록이나 공개만으로 외부 IP의 AI 처리·Fork·재공개 권리가 생기지 않는다. 권리 제한 중인 공개·AI·Fork 요청은 막는다(BR-03·CE-06).

### 서로 다른 정보 축

| 구분 | 기준과 의미 |
|---|---|
| 세계관 공개 및 이용자 노출 | 세계관 전체의 다른 작가 이용 허용과, 그 작가에게 보여 줄 항목의 노출 여부는 별개다 |
| 작가 비공개와 독자 공개 | 어떤 작품에서 몇 회부터 독자에게 공개되는지 작품별로 기록한다. 다른 작품에서 공개됐다는 사실만으로 이 작품의 독자에게 공개되지 않는다 |
| 각 인물의 인지 | 작품·인물·회차별로 무엇을 아는지 기록한다. 독자 공개 범위나 다른 인물의 지식과 독립적이다 |
| 원고·발행 시점 | 편집 중 초안, 발행본, 피드백이 참조한 발행본을 구분한다 |

공개·인지는 **항목 단위**로 기록한다(`제안`). 한 항목 본문에 공개 시점이 다른 사실이 섞이면 작가에게 항목을 나누도록 안내하며, 항목의 공개 상태만으로 본문 전체가 안전하다고 추정하지 않는다.

### AI 조회 범위 (목적별, `제안`)

Core는 AI 작업을 만들 때 인증과 대상 권한·권리 제한을 확인하고 작품·기준 회차·목적·대상 인물을 작업에 고정한다. AI 도구의 조회 요청은 이 범위로만 걸러 응답하며, DB에서 읽을 수 있다는 사실은 사용자나 AI가 볼 수 있다는 뜻이 아니다.

| 목적 | 응답할 수 있는 범위 | 제외할 범위 |
|---|---|---|
| 집필 제안(UC-11) | 작가의 해당 작품 권한 범위의 설정·이전 원고·선택한 시뮬레이션 결과 | 빌린 세계관의 이용자 비노출 항목 |
| 다중 인물 시뮬레이션(UC-09) | 기준 회차의 사건과 상황. 각 인물 역할에는 그 인물이 그 시점에 아는 사실만 | 다른 인물만 아는 비밀·미래 사건·비노출 항목, 버린 실행 상태 |
| Fork 작품의 모든 목적 | 분기 시점에 복사한 자료와 분기 이후 Fork 소유자의 자료 | 원작의 분기 이후 변경과 분기 시점 미공개 내용 |

AI 결과의 근거 항목 ID가 그 작업 범위 안인지 Core가 다시 확인하고, 범위 밖이면 해당 결과를 쓰지 않는다. **ID 확인은 출처 검사이지 내용의 진실성이나 누설이 없다는 보장이 아니다.** 원고·피드백은 지시가 아닌 데이터로 취급한다.

## 작품 Fork 고정 (`제안`)

업무 기준은 [UC-08](../../usecase-spec/UC-08.md)·BR-04·BR-14를 따른다.

1. 로그인, 원작 여부(Fork의 Fork 금지), 원작별 독자 1회, 회차 열람·Fork 허용, 공개 중단·권리 제한을 확인한다. 원작 세계관의 공개는 필요하지 않다. 기준은 선택한 회차의 끝이며 스포일러 경고를 표시한다.
2. 기준 회차까지의 발행 원고 버전을 고정한다.
3. 원작에서 기준 회차까지 독자에게 공개된 항목만 골라 분기 시점의 마지막 갱신 내용을 **Fork 전용 세계관의 첫 기록으로 복사**하고, 해당 범위의 작품별 회차 기록·인지 기록도 복사한다. 비공개 항목·이후 기록·작가 초안은 복사하지 않는다. 원작 데이터를 참조하지 않으므로 Fork에서 원작 비공개 내용을 ID로 조회할 경로가 없다.
4. 회차별 설정 이력이 없는 원작은 **현재 독자 공개 상태만** 복사하고, 나중 설정이 섞일 수 있음을 경고·동의받는다(BR-14).
5. 1~4를 한 DB 트랜잭션으로 처리하고, 원작별 독자 1회는 유일 제약으로 막는다. 실패하면 부분 Fork를 남기지 않고 원작을 변경하지 않는다.
6. 작품 운영 설정·공개 조건은 복사하지 않는다. 분기 이후 수정은 Fork 전용 세계관에 쌓고 다른 작품에 연결하거나 공개하지 않는다. 원작이 빌린 타인 세계관 항목은 그 소유자의 세계관 Fork 허용이 있어야 고칠 수 있다.

원작 삭제·작가 탈퇴 뒤에도 Fork는 복사본을 쓰므로 유지된다. MVP에는 작품 삭제·탈퇴 기능이 없으며, 도입 시 UC-08의 `삭제된 원작` 표시와 분기 전 본문 숨김을 따른다. 원작 비공개·Fork 허용 철회·회차 공개 중단은 기존 Fork를 유지하고 새 행위만 막는다.

세계관 Fork·조합(BR-12)은 시연 이후이며, 도입 시 이용자에게 노출된 항목의 현재 내용만 복사하고 출처를 기록한다.

## 제공 API

`/api/v1` 경로는 아래 **자원 범주의 가칭**이며 실제 요청·응답 계약이 아니다. 현재 제공되는 것은 Core·AI 연결 Health뿐이다.

| 범주(가칭) | 주요 기능 | 인증 |
|---|---|---|
| `health` | Core·AI 연결 확인 | 없음, `현재` |
| `auth` | 가입·로그인 | 없음 |
| `me` | 본인 정보, 내 작품·세계관 | 필요 |
| `works`, `episodes/{id}` 읽기 | 공개 작품 목록·발행 회차 열람 | 비회원 허용 |
| `worldviews` | 세계관·항목·관계·갱신 기록 | 필요 |
| `works` | 작품·세계관 연결·Fork 허용 설정·작품별 회차 기록 | 필요 |
| `works/{id}/episodes` | 초안 저장·발행 | 필요 |
| `works/{id}/forks` | 허용 회차 조회·Fork 생성 | 필요 |
| `ai-tasks` | 집필 제안·시뮬레이션 작업 생성·상태·결과·취소·채택 | 필요 |
| `episodes/{id}/feedback` | 댓글·제보 등록, 작가의 제보 목록 | 필요. 공개 댓글 읽기는 예외 |

**내부 조회 API (`제안`, DEC-21):** AI Service 도구 전용 `/internal/v1/ai-tasks/{taskId}/world/...`(항목 검색·항목 조회·관계 조회). 읽기 전용이며 작업 ID로 범위를 찾는다. 범위 밖 ID는 존재하지 않는 것과 같은 응답을 주고, 완료·실패·취소된 작업의 조회는 거절한다. 호스트에 공개하지 않는다.

세계관 변경은 권한과 마지막 기록 ID를 저장 직전에 확인하고, 바뀌었으면 덮어쓰지 않고 충돌을 안내한다(CE-07). 발행·Fork·작업 시작의 중복 요청 처리 방식은 `미정`이다. 현재 Core의 연결 불가 503·시간 초과 504·잘못된 응답 502와 안전한 ProblemDetail 경계를 업무 기능에도 적용하는 것을 `제안`한다.

## 주요 흐름

### 1. 세계관 갱신

1. 작가가 항목을 직접 편집하면 Core가 세계관 소유 권한, 권리 제한과 마지막 기록 ID를 확인한다.
2. 새 갱신 기록을 추가한다. 독자 공개·인물 인지 회차를 함께 바꾸면 같은 트랜잭션으로 작품별 회차 기록도 갱신한다. 충돌·실패 시 기존 기록은 그대로다.

### 2. 원작 전처리 (DEC-24)

1. 작가가 원작 텍스트를 회차별로 붙여 넣어 등록한다. 권리 확인 안내(UC-03 2단계)를 거친다.
2. 작가가 추출할 회차를 고르면 Core가 그 회차 원고와 대조용 기존 문서만 담아 AI 추출 작업을 만든다.
3. AI가 카테고리·이름·별칭·본문 후보, 관계(유형·감정) 후보, 근거 위치를 돌려주면 Core가 제안으로 저장한다.
4. 작가가 후보를 채택·수정·거절한다. 채택한 것만 그 회차의 갱신 기록·관계로 저장하며, 기존 내용과 충돌하면 나란히 보여 주고 작가가 고른다(UC-04 A2). 추출 실패는 원고와 기존 설정을 바꾸지 않는다.

발행 시 자동 추출(UC-04 자동 모드)은 시연 이후다.

### 3. AI 작업

1. Core가 권한을 확인하고 조회 범위를 고정한 AI 작업을 만든다. 비용 상한은 OpenAI 프로젝트 예산 한도에 맡긴다(시연용).
2. Core가 AI Service를 호출한다. AI는 필요하면 도구로 내부 조회 API를 호출하고, 제안·근거 항목 ID·사용량을 반환한다.
3. Core가 구조와 근거 범위를 확인해 제안으로 저장하고 사용량을 작업 기록에 남긴다. 실패·시간 초과·확인 실패는 실패로 알린다.
4. 제안 저장은 정본 반영이 아니다. 사용자가 채택한 내용만 현재 권한과 마지막 기록 ID를 재확인해 반영한다.

작업 상태는 `실행 중 → 완료/실패/취소됨`이다. AI 호출 동안 DB 트랜잭션을 열어 두지 않으며, 서버 재시작 시 실행 중으로 남은 작업은 실패로 정리한다(`제안`). 기존 시간 기준은 집필 지원 3분, 시뮬레이션 10분이며 구현 시 조정한다.

### 4. 집필·발행·피드백

- 직접 집필과 Fork 생성에는 AI 사용이 필수가 아니다. 초안 저장과 발행을 구분하고, 발행 전 Core가 작품 권한을 확인한다.
- 독자가 피드백 유형(댓글·단순 오류·스토리 오류·제안·질문)을 고른다. 댓글은 공개, 제보는 제보자와 작가에게만 보인다. 1차 유해 필터는 시연 이후이며 MVP에서는 검사 없이 저장한다(시연 참가자가 팀원이라는 전제, DEC-23).
- 작가는 제보 목록을 보고 직접 원고를 고친다. 피드백은 세계관을 바꾸지 않는다(BR-11). AI 응대·수정안·보상은 MVP 이후다.

## 실패 처리와 정합성

| 상황 | Core의 처리 |
|---|---|
| 권한 없음·권리 제한 | 수행하지 않음. 비공개 대상 존재를 노출하지 않음 |
| 갱신 충돌·동시 편집 | 덮어쓰지 않고 충돌·재확인 |
| 세계관·원고 저장 또는 Fork 생성 실패 | 실패를 표시하고 직전 정본·발행본·원작을 보존. 부분 Fork 없음 |
| 발행 실패 | 이전 발행 상태 유지 |
| AI 연결 실패·시간 초과·잘못된 응답·근거 범위 위반 | 실패를 표시하고 결과 미사용. 범위 안에 근거가 없는 정상 결과는 실패와 구별해 근거 부족으로 안내 |

권한 확인과 저장 사이의 경쟁, Fork 생성과 원작 수정·삭제의 경합은 해당 작업을 한 트랜잭션에 넣고 조건을 재확인해 막는다. 격리 수준·잠금·제약은 구현하며 시험으로 확인한다. AI 호출은 DB 밖이므로 같은 트랜잭션에 포함하지 않는다.

## 관측성·보안·성능

- 오류 로그와 AI 작업 기록에는 비공개 원고 전문, 작가 비공개 설정, 토큰·비밀번호·키, 다른 회원의 개인정보를 남기지 않는다.
- 작품 탐색 검색은 공개 제목·작가 닉네임·해시태그·장르를 대상으로 하고 원고 본문은 제외한다. 세계관 조회는 권한·공개·회차 조건을 먼저 적용한다.
- 원고 입력은 MVP에서 에디터 입력·붙여넣기(원작 회차별 등록 포함)만 받는다. 파일 업로드·이미지는 시연 이후다.
- 실제 `.env`는 공유·덮어쓰지 않고, 루트 설정에서 각 런타임에 허용된 값만 전달한다. 인증·TLS 없는 현재 Compose는 로컬 검증용이다.

## 위험·미정과 후속 결정

1. DB 접근 라이브러리, 테이블·인덱스는 첫 구현 때 Flyway로 정한다.
2. 이름 검색·1단계 관계로 문맥이 충분한지 장편 표본으로 확인한다. 부족하면 MVP 이후 pgvector를 검토한다(DEC-17).
3. 사용자 토큰 보관 위치와 중복 요청 처리 방식은 `미정`이다.
4. 시연 이후: [MVP 범위](../design.md#포함과-제외)에서 제외한 기능, Langfuse(DEC-18), 내부 통신 인증(DEC-19). 해당 정책은 [유스케이스](../../usecase.md)와 명세에 남아 있다.
