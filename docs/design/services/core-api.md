# Core Service 설계 (현재 실행 모듈: `core-api`)

[메인 README](../../../README.md) · [문서 목록](../../README.md)

> **DEC-41 목표 경계 · 분리 구현 전.** [Core·콘텐츠·운영·AI 책임](../service-boundaries.md)에 맞춰 아래 본문을 구분합니다. 현재 `core-api`의 인증·콘텐츠·첨부 공존과 기존 URL·데이터·Flyway 이력은 유지하며 별도 콘텐츠·운영 앱과 DB 이전은 아직 실행하지 않았습니다.

> **상태: 일부 업무 구현 · Core 재사용 및 콘텐츠 이전 목표.** [상위 설계](../design.md)·[결정 기록](../decisions.md#결정-목록)(특히 DEC-41)을 따릅니다. `core-api`는 기존 패키지·컨테이너·경로 이름이며 지금 변경하지 않습니다. 이전 [KAG 설계](../archive/kag-design/services/core-api.md)는 현행 MVP가 아닙니다.

## 목적과 책임

Core Service는 회원·인증·세션·크레딧·정산·회원 알림 정본을 담당하며 기존 Kotlin/Spring Boot 앱을 재사용합니다. 작품·문서·회차·버전·체크포인트·Fork·발행·독서·검색·작품 피드백·첨부와 콘텐츠 인가·채택·반영은 별도 Kotlin/Spring Boot 콘텐츠 서비스의 목표 책임입니다. 아래 콘텐츠 정책은 이전 대상의 보존 계약이지 Core의 목표 소유권이 아닙니다. 운영의 문의·공지·이벤트·신고 사건·소명·판단·감사·감시는 별도 운영 앱으로 분리합니다.

Frontend는 단일 공개 진입점을 통해 Core·콘텐츠·운영 API를 사용하며 Core를 중앙 프록시로 만들지 않습니다. AI는 업무 소유 서비스가 허용한 문맥에서 제안·결과·사용량을 반환합니다. 콘텐츠 조회 도구는 콘텐츠 서비스 책임의 후보이며 직접 DB 접근 여부·접근 제어 방식은 미정입니다. 어떤 경로든 콘텐츠가 정한 작품·회차/버전·인물별 인지 범위를 우회할 수 없습니다.

`현재` `backend/core-api`에는 Health·AI Health 중계 외에 이메일 가입·인증·로그인·세션·복구·프로필과 선택적 콘텐츠·첨부 API 및 PostgreSQL/Flyway 저장이 있습니다. 콘텐츠 생성은 AI `/internal/v1/proposals`를 호출합니다. 그래프 DB·별도 콘텐츠/운영 앱·크레딧·정산·신고 사건 등 전체 모델이 구현된 것은 아닙니다. [현재 실행 구조](../../architecture.md)와 [콘텐츠 물리 대응](../../content-erd-migration.md)을 구분해 읽습니다.

## 현행 저장과 콘텐츠 이전 경계

| 항목 | 방향 | 상태 |
|---|---|---|
| PostgreSQL | Core의 회원·인증·크레딧·알림과 콘텐츠의 원문·버전·Fork·업무 기록을 소유별 분리 | 인증·선택 콘텐츠 저장은 적용. 서버 공동 사용 출발안, 스키마·계정·Flyway 소유 전환 미정(DEC-41) |
| 그래프 DB | 인물·엔티티 간 관계 정보의 저장·조회. 문서·원고 전문은 넣지 않음 | `확정` 역할, DB 제품·관계 정본·연동 방식 `미정` |
| MinIO | 설정 이미지 파일. RDB에는 URL을 저장하고 항목당 최대 10개 | 설정/표지/회차 첨부의 선택 구현 존재. DEC-39의 설정 과거 이미지 미보존과 원고 버전 파일 보존은 구별. 추가 접근·정리 계약 `미정` |
| Gitea / `pg_git` | 별도 Gitea를 쓰지 않고, seanwevans/pg_git도 MVP에 적용하지 않음. MVP 이후 도입을 신중히 추진 | `확정` 방향(DEC-27·30); 포크·설치·개발은 아직 하지 않음 |
| 모델·조회 | AI가 문서·원고와 관계를 허용된 범위에서 참고 | 목표 콘텐츠 경유 도구는 `제안`; 모델·프레임워크와 직접 DB 접근 여부는 `미정` |
| 현재 런타임 | `backend/core-api`, `ai.storyfork.core`, `storyfork-core-api`, 기존 HTTP `/api/v1` | 실행 식별자·현행 Auth/Content/Attachment 데이터와 migration 이력 유지. 콘텐츠는 단계적 이전 대상 |

이 표는 확정 ERD나 그래프 스키마가 아닙니다. 콘텐츠의 **확정 변경은 기존 버전을 덮어쓰지 않고 새 버전**으로 남기며, 되돌리기도 과거 내용을 반영하는 새 버전입니다. 초안·자동저장·현재 버전 포인터에 동일한 UPDATE 금지를 적용하지 않습니다. 어느 시점에 체크포인트를 생성하고 원고·설정·상태·관계·플롯 중 무엇을 묶을지 정해야 합니다. 설정 항목은 카테고리별로 작성·목록화하되, 게시판 비유가 댓글·좋아요 기능이나 특정 이력 테이블을 확정하는 것은 아닙니다.

인물의 기본 설정과 회차에 따라 변하는 상태·지식은 세계관과 함께 이어집니다(DEC-33). 설정 항목은 카테고리 하나·태그 여러 개로 분류합니다(DEC-31). 세계관·설정·상태·관계와 그 이력은 삭제 대신 과거 이력을 보존하는 revert로 정정합니다. 플롯의 예정 사건은 확정 관계·상태로 자동 승격하지 않습니다.

### 관계 버전·정합성

관계에는 원본 문서와 버전을 추적할 수 있어야 합니다. 문서/버전 ID의 연결 키, 그래프 반영 시점, 관계 정본 여부, 조회 시 버전 선택, 두 저장소의 실패 복구·백업은 아직 결정하지 않았습니다. PostgreSQL 트랜잭션만으로 그래프 DB의 쓰기까지 원자적으로 완료됐다고 주장하지 않습니다. 저장·Fork·발행에서 관계 반영이 실패했다면 사용자에게 부분 성공을 완료로 알리지 않도록 상태와 복구 계약을 먼저 정해야 합니다.

## 인증과 콘텐츠 인가·정보 범위

- Core가 인증·세션 정본을 소유합니다. 현재 이메일 가입/인증·JWT Bearer·refresh 쿠키·CSRF 계약은 이전 전 유지하며 옛 MVP 제외 목록을 코드 부재로 해석하지 않습니다. 서비스 간 토큰 검증·키 배포·세션 폐기 전파는 미정입니다. 비밀번호는 해시만 저장합니다.
- 콘텐츠 서비스가 검증된 주체의 작품 소유·공개·Fork·회차별 접근과 채택·발행을 판단하고 운영 서비스가 운영 권한을 검사합니다. 운영의 회원 제한 요청은 Core, 콘텐츠 제한 요청은 콘텐츠 서비스가 적용하며 결정과 실제 적용 결과를 구별합니다.
- 설정은 항목별 공개·비공개와 회차별 공개 범위를 둡니다. 생성 시 기본은 비공개이며, 작품 발행본·미발행 초안·Fork 허용·인물별 인지 정보는 별도로 확인합니다(DEC-36).
- 작품·세계관 등록만으로 외부 IP의 AI 처리·Fork·공개 권리가 생기지 않습니다. 모델에 전달하는 범위는 해당 작업의 허용 문맥으로 제한합니다.
- 내부 Core↔AI 인증은 MVP 이후(DEC-19)라는 기존 시연 전제가 있지만 포트 비공개는 인증이 아닙니다. 로컬 검증 범위를 넘는 배포 전에는 다시 결정해야 합니다.

## 콘텐츠 이전 시 보존할 Fork·세계관 정책 (`확정` 원칙, 세부 `미정`)

독자는 허용된 원작 회차를 기준으로 작품을 Fork하고 기준 회차·버전과 그때까지 공개된 세계관·인물 정보를 이어받습니다. 세계관 수정 전에는 허용된 원본 변경을 따라가고 최초 수정 시 전체 세계관을 독자 소유로 Fork합니다. 독립 후 원본 변경은 알림과 사용자 선택으로만 반영합니다(DEC-32~34). 작품 Fork 없이 타인 세계관을 직접 이용하는 기능은 MVP 이후입니다(DEC-35).

기준 회차에 적용·공개되는 원본 변경은 수정 전 참조에서 반영하고 독립 후에는 알림으로 안내합니다(DEC-37). 참조·복사·검색·알림·AI 입력에 비공개·권한 밖 정보가 노출되지 않도록 해야 합니다. 판정 구현, 복사·rebase 충돌 처리와 관계 그래프 정합성·복구는 후속 설계입니다. 체크포인트 ID만으로 누출 방지나 저장소 간 원자성을 주장하지 않습니다.

Fork 창작 화면에서 원작 원고 표시, AI 채팅, 관련 설정 안내와 사용자의 자기 Fork 수정은 권한·기준 버전 범위를 공유해야 합니다(DEC-29). 안내는 저장이 아니며 사용자 확인 없이 정본을 변경하지 않습니다. 화면 진입 시점과 편집 범위는 미정입니다.

## 제공 API

`현재` Health·인증/프로필·선택 콘텐츠/첨부의 실제 URL·DTO는 [현행 Core 계약](../../../backend/core-api/README.md)에 있습니다. 아래는 **목표 소유별 가칭 범주**이며 새 라우트나 이전 완료를 뜻하지 않습니다. 기존 공개 경로는 소비자와 계약 전환 전 유지합니다.

| 범주 | 목표 소유 | 목적 |
|---|---|---|
| `auth`, `me` | Core | 가입·로그인·프로필·세션. 내 작품·세계관 조회 정본은 콘텐츠 |
| 크레딧·회원 알림 | Core | 지급·차감·정산·알림함·수신 설정·전달 |
| `worldviews`, `works`, `episodes` | 콘텐츠 | 설정·작품·플롯·원고·버전·체크포인트·발행·독서·검색 |
| `works/{id}/forks` | 콘텐츠 | 허용 지점 확인과 Fork 생성 |
| `ai-tasks` | 콘텐츠 (운영 목적은 운영) | 집필·시뮬레이션·추출 요청·후보 검토·채택. AI는 실행 |
| `episodes/{id}/feedback`, 첨부 | 콘텐츠 | 댓글·작품 제보·작가 확인·파일 참조 |
| 문의·공지·이벤트·신고 사건·감사·감시 | 운영 | 사건·판단·조치 요청/결과. 타 서비스 정본 직접 수정 금지 |

AI용 `/internal/v1/ai-tasks/{taskId}/world/...` 및 `search_items`·`get_item`·`get_relations`는 기존 이름을 보존한 **제안 경로**이며 목표 콘텐츠 소유 조회입니다. 과거 DEC-21처럼 Core 경유나 DB 접근 방식이 확정됐다고 해석하지 않습니다. 클라이언트가 보낸 ID·버전은 권한 증명이 아닙니다.

## 콘텐츠 흐름과 서비스 간 실패 처리

1. 작가는 세계관 하나에 항목 문서, 스토리 설계와 원고를 작성합니다. 설정 추출은 작가가 선택한 원고 회차를 대상으로 후보를 제시하고 채택한 것만 반영합니다(DEC-24). 직접 집필·Fork에는 AI가 필수가 아닙니다.
2. 시뮬레이션 결과·원고·상태 변화는 제안입니다. 사용자 채택 뒤 현재 권한과 기준 버전을 다시 확인하여 콘텐츠의 새 버전으로 확정합니다. 결과 생성·저장·관계 반영·발행을 별도 성공 상태로 구별합니다.
3. 회차 체크포인트가 기준 버전과 당시 관계를 일치시켜 조회할 수 있어야 합니다. 기준이 바뀌면 덮어쓰지 않고 충돌로 처리합니다. 두 저장소의 동기화·재시도·복구 방식은 미정이며, 실패를 빈 결과나 성공으로 바꾸지 않습니다.
4. 독자의 작품 Fork는 수정 전 원본 세계관의 허용된 변경을 따라가고, 독립 세계관 생성 후에는 알림에 따른 사용자의 선택으로만 반영합니다. 그래프 반영이 지연·실패한 상태를 성공으로 노출하지 않도록 생성·조회 상태 계약을 설계합니다.

콘텐츠 업무 결과·사용량은 합의된 작업 ID로 Core 정산에 전달하고 알림 사건은 Core에 제공합니다. 알림 실패로 원래 성공 업무를 취소하지 않습니다. 운영 결정→제한 적용, AI 결과→정산은 부분 실패가 가능하므로 멱등성·대기/실패·재시도/복구 계약을 후속 설계합니다. 공유 PostgreSQL이나 `@Transactional`이 HTTP 상대 서비스까지 원자적으로 묶지는 않습니다. 정기 실행은 각 업무 소유 서비스, 감시·재실행 요청은 운영입니다.

공개 응답·로그에 원고 전문·토큰·자격 증명·내부 오류를 넣지 않습니다. 현재 Core의 연결 불가 503·타임아웃 504·잘못된 응답 502와 안전한 ProblemDetail 경계를 업무 기능에 확장할지는 API 명세에서 결정합니다.

## 위험·미정과 검증 기준

ERD는 [전체 업무 초안](../erd/overview.md)과 [서비스별 정본 소유와 업무 영역별 문서](../erd/README.md#업무-영역별-erd)에서 검토하되 확정·마이그레이션 전에 체크포인트 구성, 기준 회차까지 공개된 설정의 본문 판정, 참조·복사·rebase 충돌 처리, 초안/자동저장/확정 버전, 관계 정본/버전 연결·동기화·복구, AI 조회 경로와 인물 범위를 정해야 합니다. 이후 새 버전·되돌리기 이력 보존, 체크포인트/Fork 시점 격리, 관계 반영 실패, 예정 사건의 미반영, AI 제안과 채택 분리를 시험합니다. 이 문서 변경으로 구현·E2E 검증이 끝난 것은 아닙니다.
