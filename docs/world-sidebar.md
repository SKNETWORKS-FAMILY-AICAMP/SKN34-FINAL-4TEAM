# 세계관 작업실 목록 접기

모든 작업실 탭에서 내 세계관 목록을 기본 펼침으로 유지한다. 인물 관계 편집·전체 지도 전용 외부 레이아웃 규칙을 제거하고 공통 페이지의 `listOpen` 상태로 제어한다. 사용자가 접거나 펼친 상태는 탭 이동 중 유지하며 새로 페이지를 열면 기본 펼침이다. DB와 관계 데이터는 변경하지 않는다.

데스크톱은 목록과 본문 사이의 세로 경계에 44px 버튼을 두고 스크롤 시 화면 가운데 높이에 유지한다. 목록을 접으면 버튼과 경계는 남고 본문이 여유 폭을 사용한다. 760px 이하는 기존 세로 배치를 유지해 목록 아래 경계에 버튼을 배치한다. 버튼은 세계관 목록 접기/펼치기 접근성 이름, aria-expanded, aria-controls, 기본 키보드 동작과 포커스 테두리를 제공한다.

## 로컬 검증

- 버튼이 없어 실패하는 회귀 테스트를 먼저 확인한 뒤 구현했다. 모든 7개 탭의 기본 펼침, 접은 상태 유지, 재펼침과 포커스를 자동 검사했다.
- 관련 테스트 2파일 2개, TypeScript 빌드 검사, 변경 영역 oxlint, Vite 빌드 통과. 기존 메인 번들 500kB 경고는 남는다.
- Aside CLI로 `http://127.0.0.1:5181/worlds/6f25bf17-15ac-4370-a6d9-6600ec3e34a5` 합성 세계관에서 설정 작성→관계 편집→접기→설정집→관계 편집→Enter 펼치기를 확인했다. 데이터 입력·저장은 하지 않았다.
- 실제 CSS 폭 1440/390px에서 목록과 경계 버튼 노출을 확인했다. 문서 clientWidth/scrollWidth는 각각 1421/1421, 371/371로 가로 넘침이 없었다. 증거는 로컬 `output/world-relations/sidebar-open-1440.png`, `sidebar-closed-1440.png`, `sidebar-open-390.png`에 있다.
- Ponytail 리뷰: 별도 저장소나 공통 상태 계층 없이 페이지 상태 하나와 공통 CSS만 사용한다. 카드 및 전체 지도는 기존 ResizeObserver로 남은 폭을 다시 측정한다. 숨긴 목록은 DOM에 유지하되 hidden으로 키보드·접근성 탐색에서 제외한다.

원격 Required CI는 미실행이다. 이번 변경은 공통 레이아웃 후속 패치이며 첫 PR 직접 작성·저장·재조회 분리 패치는 유지한다. 실제 PR 생성·병합·develop push는 하지 않는다.

## 탭별 공통 레이아웃 정정

사용자 녹화 `20261103-0322-39.1017705.mp4`의 프레임을 확인했다. 전체 지도에서 시간선/AI 탭으로 바뀌며 작업실이 가운데로 좁아지는 현상이 보였다. 기존 수정에서 남긴 `.world-studio:has(.world-map)`의 전용 max-width가 원인이었다. 일반 탭은 1120px, 그래프 탭은 1600px으로 달라 같은 뷰포트에서도 제목과 목록이 이동했다.

컨테이너 최대 폭 1600px을 공통 `.world-studio`로 옮기고 마지막 탭별 외부 레이아웃 오버라이드를 제거했다. 탭 버튼의 기존 -1px 아래 여백과 선택 상태별 밑줄 차이를 정리해 탭바 내부의 세로 스크롤이 생기지 않게 했다. 작업실이 있을 때 루트 scrollbar-gutter를 stable로 예약해 긴/짧은 콘텐츠 사이 페이지 스크롤바 전환으로 생기는 가로 이동도 방지한다. 화면 높이를 강제하거나 새 overflow hidden으로 콘텐츠를 자르지 않는다. 콘텐츠 길이에 따른 자연스러운 세로 높이 차이는 유지한다.

1440px 수정 전 측정:

| 항목 | 설정 작성/읽기 탭 | 그래프 탭 |
|---|---:|---:|
| 컨테이너 폭 | 1120 | 1421 |
| 본문 시작 x | 482.5 | 332 |
| 탭바 높이 | 63 | 44 |

수정 후 같은 뷰포트의 탭 순회에서 공통 컨테이너 폭·목록 표시·제목·저장 상태·저장 버튼·탭바 위치를 비교한다. 검증은 작업실의 같은 합성 세계관을 쓰며 사용자 데이터 입력/저장과 모델 호출은 하지 않는다. 원본 측정과 결과 JSON은 로컬 `output/world-relations/layout-*.json`에 보관한다.

관련 기존 회귀 테스트 2파일·2개 및 Vite 빌드 통과. 이번 변경은 CSS만 수정하므로 TypeScript 로직 테스트를 추가하지 않고 실제 브라우저 좌표 비교를 회귀 검사로 사용한다. 수정 전에는 공통 도구 모음 x/탭바 높이 비교가 실패함을 확인했다. Impeccable 레이아웃 검사에서 지적은 없었고 Ponytail 리뷰에서 공통 폭 규칙 한 곳·밑줄/여백 정정·스크롤 여백 예약만 사용하는 것을 확인했다. 원격 Required CI는 미실행이다.

최종 Aside 좌표 검증: 실제 CSS 폭 1440/800/390px 각각 목록 펼침·접힘 상태에서 7개 탭을 순회한 총 42개 화면 상태가 통과했다. 같은 폭과 펼침 상태 안에서 컨테이너/목록 폭, 제목·저장 상태·저장 버튼·탭바의 좌표와 크기가 0.5px 이내로 일치했다. 문서 가로 넘침과 탭바 세로 넘침은 없었다. 1440px의 본문 x=332(펼침)/80(접힘), 탭바 높이=45px이며 800/390px은 가로 스크롤을 포함한 탭바 높이=64px로 탭에 따라 변하지 않았다. 결과 요약은 `output/world-relations/layout-summary.json`이다.
