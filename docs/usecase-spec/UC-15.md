# UC-15 피드백 AI 분석·맞춤형 응대

> [명세 목차·공통 규칙(CE·BR)](./README.md) · [유스케이스 문서](../usecase.md)
| 항목 | 내용 |
|---|---|
| 주 액터 | 독자(UC-14에서 제보할 때 시작) |
| 보조 액터 | 외부 LLM API |
| 처리 주체 | 플랫폼(집필 및 피드백 응대 에이전트, 세계관·설정 검토 에이전트) |
| 구분 | 핵심 |
| 관련 기능 ID | F-FBK-02~06, F-FBK-08, F-FBK-09, F-FBK-12 |
| 근거 | 기획서 7·12·19쪽, 그림 14 |
| 관계 | UC-14를 extend(단순 오류·질문 제보일 때). 생성한 검토 대기 항목은 UC-16의 입력 |
- **목표:** 단순 오류와 질문에 근거를 갖춘 수정안·답변을 자동으로 제공하고, 작가 판단이 필요한 건만 작가에게 넘깁니다.
- **사전조건:** 제보 접수 완료(1차 필터 통과). 응대에 쓸 공개 원고·설정 범위가 확인되었습니다.
- **트리거:** UC-14 6단계에서 독자가 고른 유형이 단순 오류 또는 질문입니다. 스토리 오류·제안은 이 유스케이스를 거치지 않고 UC-16 작가 검토로 갑니다. 댓글은 분석하지 않습니다.
**기본 흐름**
1. 시스템이 독자가 고른 유형(단순 오류·질문)에 맞는 처리를 정합니다. 유형을 AI로 다시 분류하지 않습니다.
2. 시스템이 피드백에 고정된 발행본 버전을 기준으로, 독자가 본 대상 회차까지 공개된 원고·설정·사건·인물 정보만 근거 범위로 정합니다. 그 뒤 회차는 이미 공개됐더라도 쓰지 않습니다.
3. 세계관·설정 검토 에이전트가 근거 범위에서 관련 내용을 찾습니다.
4. 집필 및 피드백 응대 에이전트가 유형별 응답을 구성합니다.
   - 단순 오류: 기준 버전, 변경 전·후, 근거를 담은 수정안(PR)을 만듭니다.
   - 질문: 근거가 충분하면 근거 회차·구절과 함께 답합니다.
5. 시스템이 응답과 현재 처리 상태를 독자에게 표시합니다.
**대안 흐름**
- A1 (4단계) 근거 부족·창작 판단 필요: 단정하지 않고 한계를 안내한 뒤 UC-16 작가 검토 요청으로 넘깁니다.
- A2 (4단계) 수정안 생성: 작품 설정이 "자동 승인·발행"이면 UC-16의 자동 처리로 넘기고, 아니면 작가 검토 대기로 넘깁니다. 피드백 상태는 "수정 진행 중"이 됩니다.
- A3 (4단계) 단순 오류가 아님: 고치면 표기가 아니라 내용(설정·전개)이 바뀌는 경우에는 수정안을 만들지 않고, 스토리 오류로 다시 제보할 수 있다고 안내한 뒤 작가 검토로 넘깁니다.
**예외 흐름**
- E1 (2~4단계) AI 실패: CE-04. 즉시 "처리 실패"로 알리고 대기 상태로 두지 않습니다. 허구의 인용이나 정상 응답으로 대체하지 않으며 운영자에게 경고합니다(UC-21).
- E2 (3단계) 근거를 찾을 수 없음: 그 한계를 표시하고 A1에 따라 작가 검토로 넘깁니다.
- E3 (2~5단계) 기준 시간 초과: 응대 시작 후 2분(기준 값, 구현 시 조정)이 지나면 실패로 전환하고 E1과 같이 처리합니다.
- **성공 보장:** 유형에 맞는 응답이 근거와 함께 제공되고, 필요한 건만 작가 검토로 넘어갑니다.
- **최소 보장:** 작가 비공개 설정·비공개 후속 회차와 독자가 보지 않은 후속 회차가 응답에 노출되지 않습니다(BR-02). AI 응답이 원작 변경이나 작가 승인을 대신하지 않습니다.
- **업무 규칙:** 피드백 분석은 공개 근거를 대조하는 검증이며 세계관·설정을 바꾸지 않습니다(BR-11). 독자 의견을 무조건 옳거나 그르다고 판정하지 않습니다. 근거가 부족한 오류 제보를 자동 승인 경로로 보내지 않습니다. 운영자는 개별 응대 내용을 작성하지 않습니다. 이 유스케이스의 AI 비용은 플랫폼이 부담합니다(BR-08). 신뢰도는 검증 시뮬레이션(UC-09 A5)을 거친 스토리 오류에만 표시하며, 이 유스케이스의 응답에는 숫자 신뢰도를 붙이지 않고 근거 회차·구절을 보여 줍니다.
- **미정:** 없음. (WBS 3.2~3.6의 자체 분류 모델 작업은 유형을 독자가 고르게 되면서 필요성 재검토 대상입니다.)
