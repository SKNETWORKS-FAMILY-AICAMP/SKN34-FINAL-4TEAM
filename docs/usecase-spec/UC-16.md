# UC-16 작가 검토 요청·수정안 승인·반영

> [명세 목차·공통 규칙(CE·BR)](./README.md) · [유스케이스 문서](../usecase.md)
| 항목 | 내용 |
|---|---|
| 주 액터 | 작품 소유자 |
| 구분 | 핵심 |
| 관련 기능 ID | F-FBK-06~08, F-FBK-10, F-WRT-11, F-SET-01 |
| 근거 | 기획서 7·19쪽, 그림 14 |
| 관계 | 독립 시작. UC-15가 만든 검토 대기 항목과 UC-14에서 바로 넘어온 스토리 오류·제안을 입력으로 받음(주 액터가 달라 extend로 표기하지 않음) |
- **목표:** 수정안과 작가 판단이 필요한 피드백을 검토하고 처리 방향을 정합니다.
- **사전조건:** 대상 작품의 승인 권한. UC-15에서 넘어온 수정안·검토 요청, 또는 UC-14의 스토리 오류·제안 제보가 있습니다.
- **트리거:** 소유자가 검토 대기 목록에서 항목을 엽니다. 또는 작품 설정이 "표기 오류 자동 승인·발행"인 작품에서 표기 오류 수정안이 생성됩니다.
**기본 흐름 (수정안, 작가 검토)**
1. 시스템이 검토 대기 목록을 유형별로 표시합니다. 스토리 오류는 "검증됨(신뢰도·근거 포함)"과 "미검증"을 구분해 보여 줍니다.
2. 소유자가 수정안을 엽니다.
3. 시스템이 원문, 변경 전·후, 제보 내용, 근거를 나란히 보여 줍니다.
4. 소유자가 승인·거절·보류 중 하나를 고르거나 수정안을 고쳐 승인합니다.
5. 승인한 경우 시스템이 권한과 대상 원고의 기준 버전을 다시 확인합니다.
6. 시스템이 승인 범위의 변경만 편집 초안에 반영하고 새 초안 버전으로 기록합니다.
7. 대상이 발행된 회차이면 시스템이 UC-13 발행으로 진행할지 묻습니다. 소유자가 발행해야 독자에게 보입니다.
8. 시스템이 독자에게 승인 여부, 초안 반영, 발행 반영 상태를 구분해 안내합니다.
**대안 흐름**
- A1 (2단계) 작가 검토 요청·스토리 오류·제안: 근거 부족·창작 판단이 필요한 피드백, 스토리 오류, 제안을 열어 답변을 작성하거나, 보류·종료합니다. 스토리 오류가 맞다고 보면 작가가 UC-10에서 고치고 A3으로 연결합니다. 미검증 스토리 오류는 작가가 원하면 UC-09로 직접 검증할 수 있습니다(작가 부담). 결과는 UC-14 상태에 반영됩니다.
- A2 (4단계) 거절: 사유(선택 입력)와 함께 거절 상태로 기록합니다.
- A3 (2·4단계) 직접 수정: 작가가 수정안 대신 UC-10에서 직접 고치고 UC-13으로 발행한 뒤, 고친 회차 버전을 이 제보에 연결합니다. 연결하면 수정안은 "거절됨"(사유: 작가 직접 수정)으로 닫히고 제보는 "처리 완료"가 됩니다.
- A4 (트리거) 표기 오류 자동 승인·발행: 수정안 유형이 오타·맞춤법·명백한 숫자 표기 오류일 때만, 시스템이 4단계를 자동 승인으로 처리하고 5~6단계를 거쳐 UC-13으로 자동 발행합니다. 결과는 변경 이력에 남기고 소유자에게 알립니다. 설정 충돌 의심이나 창작 판단이 필요한 건은 자동 처리하지 않습니다.
- A5 (2단계) 보류 항목 재검토: 보류한 수정안을 다시 열면 시스템이 기준 버전을 재확인하고 4단계부터 진행합니다. 기준 버전이 바뀌었으면 CE-07을 따릅니다.
- A6 (A4 이후) 자동 처리 되돌리기: 소유자가 변경 이력에서 자동 반영 직전 버전을 골라 새 초안 버전으로 복원하고(UC-10 A4) UC-13으로 다시 발행합니다. 자동 반영된 버전을 지우지 않습니다.
- A7 (A1) 스토리 오류 반영 보상: 검증된 스토리 오류 제보를 A3으로 연결해 반영하면 시스템이 UC-14 업무 규칙에 따라 제보자에게 보상 크레딧을 지급합니다. 작가가 비용을 부담하지 않습니다.
**예외 흐름**
- E1 (5단계) 기준 버전 변경: CE-07. 이전 버전 기준 수정안을 그대로 적용하지 않고 재검토로 돌립니다. 자동 처리 중이면 멈추고 작가 검토 대기로 전환합니다.
- E2 (6단계) 초안 반영 실패: 수정안을 "반영 실패"로 표시하며 반영 완료로 안내하지 않습니다.
- E3 (2단계) 권한 없음: CE-02. Fork 소유자는 자신의 Fork 항목만 처리합니다.
- E4 (7단계·A4) 발행 보류·실패: 수정안을 "발행 대기" 또는 "발행 실패"로 표시하며 원작 반영 완료로 안내하지 않습니다. 자동 발행이 실패하면 작가 검토 대기로 전환합니다.
- **성공 보장:** 승인 주체(작가 또는 자동 설정)·결정·실제 변경 결과가 구분되어 기록됩니다.
- **최소 보장:** 승인되지 않은 수정은 원고에 반영되지 않습니다.
- **업무 규칙:** 자동 승인·발행 설정은 사전 승인으로 봅니다(BR-01). 원작 수정이 기존 Fork의 고정 기준에 반영되지 않습니다(BR-04). 수정안 반영에 따른 재발행은 세계관 자동 업데이트를 실행하지 않습니다(BR-11). 새 검토 대기 항목은 사이트 안 알림과 검토 대기 목록의 배지로 알립니다. 이메일 알림은 범위 밖입니다.
- **미정:** 세부 상태명, 보류의 최대 기간.
