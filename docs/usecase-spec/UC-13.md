# UC-13 회차 발행·공개 관리

> [명세 목차·공통 규칙(CE·BR)](./README.md) · [유스케이스 문서](../usecase.md)

| 항목 | 내용 |
|---|---|
| 목표 서비스 책임(DEC-41) | 콘텐츠 서비스 — 콘텐츠 인가·정본·저장·발행의 소유자. Core는 회원·정산·알림, AI는 요청된 생성·검토만 담당 |
| 주 액터 | 작품 소유자 |
| 구분 | 핵심 |
| 관련 기능 ID | [F-PUB-02](../requirements.md#f-pub-02), [F-RGT-03](../requirements.md#f-rgt-03) |
| 근거 | 기획서 12·18·20쪽 |
| 관계 | UC-16 자동 처리와 UC-18이 자동 실행 |
- **목표:** 검토한 회차를 허용된 범위에서 독자에게 공개합니다.
- **사전조건:** 발행할 저장된 원고 버전과 공개 권한이 있고, Fork라면 원작의 Fork 작품 공개 조건을 충족합니다.
- **트리거:** 소유자가 발행 또는 공개 상태 변경을 선택하거나 예약 발행을 설정합니다. 또는 자동 발행(UC-16 표기 오류 자동 승인·발행, UC-18 자율 연재)이 요청됩니다.
**기본 흐름**
1. 소유자가 발행할 회차와 저장된 원고 버전을 선택합니다. 작업 초안을 발행하려면 먼저 저장해 새 버전을 만듭니다.
2. 시스템이 발행 미리보기와 공개 범위(무료·유료 공개 여부, 유료는 MVP 범위 밖)를 표시합니다.
3. 콘텐츠 서비스가 공개 권한, Fork 원작 조건, 권리 제한 여부를 확인합니다. 외부 2차 창작물이면 유료 공개를 허용하지 않습니다(BR-09).
4. 소유자가 최종 발행을 확인합니다.
5. 콘텐츠 서비스가 선택한 버전으로 그 회차의 체크포인트(발행본)를 만들어 활성으로 지정하고 독자 열람(UC-01)에 노출합니다(DEC-43).
6. 시스템이 실제 공개 결과를 안내합니다.
7. MVP에서는 발행만으로 세계관을 자동 갱신하지 않습니다. 작가가 UC-04를 수동 요청하고 추출 후보를 검토·채택합니다(DEC-24·26). 기존 전체 서비스 기획의 선택적 자동 모드는 MVP 이후이며, 유지 여부는 별도 확인합니다.
**대안 흐름**
- A1 (1단계) 비공개 유지: 초안으로만 보관합니다. 연재 작가에게 공개를 강제하지 않습니다.
- A2 (1단계) 공개 중단: 소유자가 회차 하나의 공개를 중단합니다. 작품 전체를 숨기려면 UC-07에서 작품을 비공개로 바꿉니다. 공개를 중단해도 기존 Fork는 유지하며, 중단된 회차는 새 Fork의 분기 기준으로 고를 수 없습니다(BR-04, UC-08).
- A3 (1단계) 발행본 수정: 새 초안 버전을 발행해 새 체크포인트로 교체합니다. UC-16에서 승인·반영한 수정 초안도 이 경로로 발행합니다.
- A4 (트리거) 자동 발행: UC-16 자동 처리나 UC-18이 요청하면 1·4단계 없이 진행하되, 3단계 확인은 똑같이 거칩니다.
- A5 (트리거) 예약 발행: 소유자가 저장된 원고 버전과 발행 시각을 지정합니다. 예약 및 실제 발행 결과를 구분합니다. 서버 중단으로 지연되면 재기동 후 권한·권리 및 공개 조건을 다시 확인해 충족할 때 발행하고 지연 결과를 소유자에게 알립니다(UC-28). 상세 변경·취소·실패 처리와 MVP 포함 여부는 미정입니다.
- A6 (1단계) 이전 체크포인트로 되돌리기: 소유자가 이미 발행한 회차의 이전 체크포인트를 골라 다시 활성으로 만듭니다. 3·4단계 확인을 거치고, 되돌리기는 새 기록으로 남기며 체크포인트 이력을 지우지 않습니다. 기존 Fork의 기준은 바뀌지 않습니다(DEC-43).
**예외 흐름**
- E1 (3단계) 권한·조건 미충족: CE-02. 발행하지 않습니다. 자동 발행이면 초안으로 보관하고 소유자에게 알립니다.
- E2 (3단계) 권리 제한: CE-06.
- E3 (5단계) 발행 실패: 완료로 안내하지 않고 이전 발행 상태를 유지합니다.
- **성공 보장:** 발행본(체크포인트)과 작업 중 초안·저장 버전이 구분되어 독자에게 회차마다 현재 활성 체크포인트 하나만 보입니다. 발행·발행본 교체·되돌리기·공개 중단·재공개 이력은 작품 소유자가 확인할 수 있으며, 이전 체크포인트는 독자에게 공개하지 않습니다(DEC-43). 기존 Fork의 기준 체크포인트는 공개 중단·교체 후에도 보존합니다.
- **최소 보장:** 실패 시 기존 공개 상태가 바뀌지 않습니다.
- **업무 규칙:** AI 생성이나 수정안 승인만으로 발행본이 바뀌지 않습니다. 예외는 작품 소유자가 켠 자동 처리(표기 오류 자동 승인·발행, 자율 연재)이며, 그 설정을 사전 승인으로 봅니다(BR-01). 외부 연재 플랫폼에 자동 게시하지 않습니다.
- **미정:** 유료 열람·정산(MVP 범위 밖), 예약 발행의 상세 정책과 MVP 포함 여부, MVP 이후 세계관 자동 업데이트 유지 여부.

## 현재 구현 계약 — 회차 공개 중단·재공개·발행 이력

- 콘텐츠 서비스의 `PUT /api/v1/works/{id}/episodes/{number}/visibility`는 `{revision, visible, rightsConfirmed}`를 받는다. `revision`은 회차 초안 기준이며, `visible: false`는 공개 중단, `true`는 중단 직전 발행본의 재공개다. 재공개는 권리 재확인이 필요하다.
- 작품 소유자와 기존 작품 잠금을 사용한다. 원작에서 상속한 회차는 변경할 수 없고, 상태·revision 충돌은 409다. 권리 제한 작품은 재공개할 수 없으며 기존 Fork 최초 공개 조건을 그대로 적용한다. 실패하면 트랜잭션 전체를 되돌려 기존 상태를 보존한다.
- `publication_event`의 성공 사건 `publish / replace / unpublish / republish`로 상태를 계산한다. V22는 기존 이력을 수정하지 않고 `episode_current`에 `publication_status`를 추가한다. 중단은 버전·초안·체크포인트를 삭제하지 않으며 초안이 없는 회차도 수정 번호를 증가시킨다.
- 회차 응답의 `publicationStatus`는 `draft / published / suspended`다. 중단 회차는 공개 원고·이미지·세계관 조회 및 새 Fork 기준 선택에서 제외한다. 기존 Fork는 고정된 원고를 유지한다. 중간 회차가 빠져도 뒤 회차 번호는 유지하며, 다음 작성 번호는 공개 중단 이력을 포함한 마지막 발행 회차 다음이다. 소유자 작품 응답의 `writingEpisodeNumber`를 기존 작성 화면에서도 사용한다.
- `GET /api/v1/works/{id}/history`의 `publicationHistory`는 회차·버전·시각(`publishedAt`, 중단 사건에서는 중단 시각)·`action`을 반환한다. 소유자만 조회하며 성공한 사건을 시간순으로 표시한다. 기존 `publish` 기록은 당시 기록 그대로 표시하고 과거 교체 사건으로 추정해 고치지 않는다.
- 집필실에서 공개 중단·재공개 및 발행 이력 조회를 제공하고 기존 콘텐츠 이력 화면에도 발행 사건을 표시한다. 요청 중 중복 조작을 막고, 실패를 성공 상태로 표시하지 않는다.
- 체크포인트 목록은 성공한 `publish / replace / republish` 사건을 버전별 최초 한 건으로 표시한다. 공개 중단 시 기존 목록은 보존하고 활성 표시는 해제하며, 재공개·되돌리기는 선택한 버전만 활성으로 표시한다. 관심 작품의 신규 회차 알림은 최초 `publish`에서만 요청하고 교체·중단·재공개·되돌리기에는 보내지 않는다.
- 예약 발행·작품 전체 비공개·자동 발행·유료 공개는 이 구현에 포함하지 않는다. 로컬 검증은 관련 단위 테스트만 실행하며, DB 상태 전이·Fork 보존은 `PublicationVisibilityPostgresTest`, Hook 응답 상태는 `useWritingViewModel.test.tsx`의 CI 통합 검증 대상이다.

검증(2026-11-10): 관련 백엔드 단위 52개·프론트 Domain/Data 단위 119개 통과. DB/Flyway·Hook 통합 및 브라우저·빌드는 로컬에서 실행하지 않았으며 CI 검증 대상이다. 기능표 체크는 작업 브랜치 구현 기준이며 PR 병합·배포 완료를 뜻하지 않는다.
