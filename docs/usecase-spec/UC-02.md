# UC-02 세계관 생성·관리

> [명세 목차·공통 규칙(CE·BR)](./README.md) · [유스케이스 문서](../usecase.md)
>
> **MVP 사용자 방향:** 설정은 고정 카테고리 하나·자유 태그 여러 개로 분류하고, 항목별 공개·비공개와 회차별 공개 범위를 정합니다. 작품 Fork는 세계관을 참조하다가 최초 설정 수정 시 전체를 독자 소유 세계관으로 Fork하며, 그 뒤 기준 회차에 영향을 주는 원본 변경은 알림과 사용자 선택으로 반영합니다(DEC-31~40). AI는 선택적이고 원작은 수정하지 않습니다. 아래 과거 기획 중 충돌하는 부분은 [최신 설계](../design/design.md)를 우선합니다.

## 최신 MVP 흐름 — 세계관과 설정 항목

**목표 서비스 책임(DEC-41):** 콘텐츠 서비스가 설정·인물·관계의 인가·정본·버전·실제 반영을 소유합니다. Core는 회원 인증·크레딧·알림, AI는 허용 문맥의 제안·검토를 담당합니다. 현재 콘텐츠 구현은 `core-api` 안에 있으며 별도 Kotlin/Spring Boot 앱으로의 분리는 미완료입니다.

**목표:** 창작자가 자기 작품에 사용할 세계관과 항목별 설정을 만들고 관리합니다. 독자의 Fork 설정 변경도 이 흐름의 적용 대상이며, 원작 설정을 직접 바꾸지 않습니다.

**사전조건:** 로그인. 기존 세계관이나 설정을 수정할 때는 해당 대상의 수정 권한이 필요합니다. 세계관을 먼저 만들 수 있으며, 설정을 추가하기 위해 반드시 AI를 사용할 필요는 없습니다.

**현재 세계관 연결·조합 규칙**

- 작품 하나는 세계관 하나에 연결되며, 세계관 하나는 동시에 최대 한 작품에 연결됩니다. 아직 연결되지 않은 세계관은 있을 수 있습니다(UC-24).
- 이용 권한이 있는 **원본 세계관 최대 5개**에서 작가가 허용된 설정을 선택·복사해 새 세계관 하나를 만듭니다. 원본별 출처를 남기고 새 세계관은 독립적으로 관리하며 이후 원본 변경을 자동 반영하지 않습니다. 비공개·권한 밖 내용은 복사하지 않습니다. 구체적인 관계·회차 상태의 선택 범위는 미정입니다.
- 작품과 세계관 모두 원본에서 한 단계만 Fork할 수 있습니다. 이미 Fork된 세계관은 다시 Fork하거나 조합 원본으로 선택할 수 없습니다. 원본에서 여러 창작자가 각각 첫 단계 Fork를 만드는 것과는 구분합니다.
- 세계관 자체의 삭제 요청은 소프트 삭제입니다(DEC-42). 행을 보존하므로 참조 중인 작품 Fork는 원본 참조를 그대로 유지하고 독립 전환을 강제하지 않습니다. 확정 설정·상태·관계 이력의 정정은 이전 이력을 지우지 않는 되돌리기입니다.

**세계관 생성**

1. 창작자가 새 세계관 만들기를 선택하고 이름을 입력합니다. 설명도 작성할 수 있으며, 기존 기획에서 이름은 필수입니다.
2. 시스템이 입력과 생성 권한을 확인하고 세계관을 저장한 뒤 결과를 보여 줍니다. 설정을 함께 입력할 수 있는지와 화면 구성·저장 순서는 후속 설계 사항입니다.

**설정 항목 작성·관리**

1. 창작자가 편집할 세계관을 선택하고 인물·광물·장소 같은 카테고리로 분류된 설정 항목을 확인하거나 항목을 추가합니다. 게시판 방식은 **항목을 분류·작성·목록화한다는 의미**입니다.
2. 창작자가 설정 항목의 이름·내용을 작성하고 고정 카테고리 하나를 고르며 필요한 태그를 자유롭게 붙입니다. 설정마다 최대 10개의 이미지를 업로드하고 외부 참고 URL을 등록할 수 있습니다. 이미지 파일은 MinIO(S3 호환)에, URL만 RDB에 저장합니다(DEC-31·39).
3. 설정 항목은 기본 비공개이며 창작자는 생성 시 또는 나중에 공개 여부와 회차별 공개 범위를 직접 지정할 수 있습니다. 항목 안에서 숨길 내용은 별도 항목으로 나눕니다. AI 분석 결과는 변경 후보이며 작가가 확인한 뒤에만 반영합니다(DEC-36).
4. 시스템은 작성 중 같은 초안을 자동저장으로 덮어쓰고, 사용자가 저장 버튼을 눌러 확정하면 권한을 확인해 기존 버전을 덮어쓰지 않는 새 버전을 남깁니다. 확정 저장은 별도 공개·발행이 아닙니다(DEC-27·40).
5. 창작자는 이전 설정 버전을 확인하고 되돌리기를 선택할 수 있습니다. 확정 설정·상태·관계의 이력을 지우지 않으며, 제거·정정은 이전 이력을 보존하는 새 버전의 되돌리기(revert)로 처리합니다(DEC-33). 세계관 자체의 삭제 요청은 위 삭제 규칙을 따릅니다. 단, 이미지는 과거 파일을 이력으로 보존하지 않으므로 텍스트를 되돌려도 당시 이미지 복원은 보장하지 않습니다(DEC-39).
6. 인물의 기본 설정과 회차별 상태·지식·인물관계도는 세계관과 함께 이어집니다([UC-06](./UC-06.md), DEC-33·37).
7. 작품 Fork 창작자는 수정 전 원작 세계관을 참조합니다. 최초 수정 시 기준 회차에 공개된 세계관 전체를 자기 소유로 Fork해 수정하며, 이후 기준 회차에 영향을 주는 원본 변경은 알림을 보고 반영 여부를 선택합니다([UC-08](./UC-08.md), DEC-37).

**예외·경계**

- 수정 권한이 없으면 저장하지 않고 권한이 없는 정보나 그 존재를 노출하지 않습니다(CE-02). 저장 실패나 다른 곳의 변경으로 인한 충돌은 완료로 표시하지 않고 기존 저장본을 보존합니다(CE-03·07).
- 설정 원문·콘텐츠 버전은 PostgreSQL, 관계 정보 저장·조회는 그래프 DB 방향입니다. 저장소 간 관계와 버전이 일치하지 않거나 반영이 실패했을 때 정상 완료로 표시하지 않습니다. 동기화·복구 방식은 미정입니다(DEC-26·27).
- 설정 항목별 공개·비공개와 회차별 공개 범위, 작품 접근 권한, 미발행 원고와 인물별 지식을 구분합니다(DEC-36). 첨부 이미지·URL과 관계를 포함해 권한 밖 내용을 조회·복사·AI 문맥에 노출하지 않습니다.
- 이미지 과거본을 이력으로 남기지 않되 사용 중인 참조가 있는 파일을 임의로 지워 다른 항목이나 Fork를 깨뜨려서는 안 됩니다. 접근·파일 정리 방식은 후속 설계입니다.

**범위·미정:** 작품 Fork 없이 타인의 세계관을 직접 이용하는 기능은 MVP 이후이며 시점은 미정입니다(DEC-35). 고정 카테고리 목록·자동저장 간격·참고 URL 세부, 공개 및 실제 적용 시점의 표현, revert·복사·rebase 충돌과 관계의 시점 일치 구현은 미정입니다.

## 기존 기획 상세 — 최신 MVP와 대조 필요

아래 내용은 이전 기획을 보존한 것입니다. 공개 항목·회차 관리, 여러 세계관 연결, 댓글식 갱신·자동 반영과 삭제·Fork 세부는 위 최신 흐름과 [결정 기록](../design/decisions.md)을 우선하며, 충돌하는 기존 문구를 현행 MVP 계약으로 취급하지 않습니다.

| 항목 | 내용 |
|---|---|
| 주 액터 | 창작자(세계관 소유자) |
| 구분 | 핵심 |
| 관련 기능 ID | [F-WLD-01](../requirements.md#f-wld-01), [F-WLD-02](../requirements.md#f-wld-02), [F-RGT-01](../requirements.md#f-rgt-01), [F-SET-02](../requirements.md#f-set-02), [F-SET-03](../requirements.md#f-set-03) |
| 근거 | 기획서 14쪽, 그림 9 |
| 관계 | UC-24의 선행 조건(작품은 세계관이 있어야 생성) |

- **목표:** 작품과 별도로 세계관을 만들고, 설정집과 인물관계도를 관리합니다.
- **사전조건:** 로그인. 기존 세계관 편집 시 해당 세계관의 수정 권한.
- **트리거:** 새 세계관 만들기 또는 기존 세계관 편집을 선택합니다.

**기본 흐름**
1. 창작자가 새 세계관 만들기를 선택합니다.
2. 창작자가 세계관 이름(필수)과 설명을 입력합니다.
3. 창작자가 설정집 항목(장소, 시대/역사, 세력/조직, 설정 규칙, 주요 사건, 참고 자료)을 추가합니다.
4. 창작자가 인물관계도에 등장인물과 인물 간 관계를 등록합니다. 인물별 시점 상태는 UC-06에서 관리합니다.
5. 창작자가 항목마다 이용자 노출 여부(노출 또는 비노출, 기본 노출)를 지정합니다. 비노출 항목은 세계관을 공개해도(UC-07) 다른 작가에게 보이지 않습니다. 독자 공개는 세계관이 아니라 연결된 작품에서 작품별로 몇 화부터 공개할지 정합니다(A2, BR-10).
6. 시스템이 세계관을 저장하고 변경 이력에 기록합니다.
7. 시스템이 세계관 공개 범위 설정(UC-07)과 작품 만들기(UC-24)를 안내합니다.

**대안 흐름**
- A1 (1단계) 기존 세계관 편집: 세계관을 선택해 항목을 수정합니다. 저장할 때마다 항목에 새 갱신 기록이 추가됩니다(BR-10). 이 세계관을 쓰는 자신의 작품이 여럿이면, 시스템이 저장 전에 함께 반영될 작품 목록을 안내합니다. 원고와의 충돌 확인은 선택 기능인 UC-12로 합니다.
- A2 (5단계) 떡밥 공개: 작품이 진행되어 독자에게 숨겨 온 항목이 드러나면, 창작자가 그 작품의 해당 회차부터 공개로 전환합니다(UC-06 A3). 시스템은 전환 회차를 작품별로 기록합니다. 작품의 세계관 자동 업데이트(UC-04)가 실행될 때도 같은 방식으로 공개 전환이 반영됩니다.
- A3 (6단계) 이력 확인·되돌리기: 변경 이력에서 이전 상태를 확인하고 되돌립니다. 되돌린 결과도 새 이력으로 남습니다.
- A4 (1단계) 기존 원고에서 시작: 이름만 넣어 세계관을 만든 뒤, UC-24 → UC-03 → UC-04로 설정을 채웁니다.
- A5 (1단계) 세계관 삭제: 세계관을 소프트 삭제합니다(DEC-42). 삭제된 세계관은 목록·검색·새 연결에서 제외하지만 행과 버전은 보존하므로, 참조 중인 작품 Fork는 원본 참조를 그대로 유지하고 독립 전환을 강제하지 않습니다. 원본 소유자의 연결 작품과 작품 Fork 외 참조는 기존 E3 및 안내 규칙을 따릅니다.
- A6 (1단계) 기존 세계관 조합: 이용 권한이 있는 원본 세계관 최대 5개에서 허용된 설정을 선택·복사해 새 세계관 하나를 만듭니다. Fork된 세계관은 조합 대상으로 선택할 수 없습니다. 결과 세계관은 작가 소유로 원본별 출처를 보존하며 원본의 이후 변경을 자동 반영하지 않습니다. 관계·회차 상태의 상세 복사 범위는 미정입니다.
- A7 (4단계) 인물관계도만 새로 만들기: 인물관계도는 세계관의 일부입니다. 세계관은 마음에 들지만 인물관계도를 바꾸고 싶다면, 기존 세계관은 그대로 연결하고 인물관계도만 담은 새 세계관을 만들어 함께 연결합니다. 소유·권한·버전·연결 제한은 세계관 규칙을 따르며, 같은 인물이 겹치면 UC-12로 확인합니다.
- A8 (1단계) 장르 기본 세계관에서 시작: 창작자가 장르를 고르면 시스템이 플랫폼이 제공하는 기본 세계관을 복사해 작가 소유의 새 세계관으로 만듭니다. 원본 관계가 없으며, 플랫폼이 기본 세계관을 바꿔도 반영되지 않습니다. 기본 세계관은 플랫폼 운영자가 만들고 관리하며, 권리가 확인된 내용만 담습니다(BR-03). 내용은 시대·규칙 같은 틀 중심으로 두고 특정 작품의 인물·사건은 넣지 않습니다.
- A9 (1단계) 연결한 다른 사용자 세계관 수정: 창작자가 작품에 연결한 다른 사용자 세계관을 고치려 하면, 시스템이 이후 원본 변경이 반영되지 않는다는 점을 안내하고 확인을 받은 뒤 그 시점의 이용자 노출 항목만 세계관 Fork로 복사하고(비노출 항목·원작 작품의 회차 기록은 제외) 작품의 연결을 Fork로 교체합니다(BR-12). 연결 수는 그대로이며 첫 회차 발행 후에도 할 수 있습니다(UC-24 A3).

**예외 흐름**
- E1 (6단계) 저장 실패: CE-03.
- E2 (6단계) 다른 곳에서 수정됨: CE-07.
- E3 (A5) 원본 소유자의 연결 작품 또는 작품 Fork가 아닌 연결 작품이 있는 세계관 삭제 요청: 기존 제한을 유지하고 연결된 작품을 안내합니다. 참조 중인 작품 Fork는 원본 참조를 유지합니다(A5).
- E4 (A9) 원본 소유자가 세계관 Fork를 허용하지 않음: 복사하지 않고, 원본을 그대로 참조해야 한다는 점을 안내합니다(UC-07).

- **성공 보장:** 설정집과 인물관계도가 저장되고 변경 이력이 남습니다.
- **최소 보장:** 실패 시 직전 버전이 유지됩니다.
- **업무 규칙:** 세계관 생성만으로 다른 사용자에게 공개되거나 Fork가 허용되지 않습니다(UC-07). 설정집·인물관계도 갱신은 기본 수동이며, 작품의 세계관 자동 업데이트(UC-04)를 켠 경우에만 자동으로 갱신됩니다. 변경 이력은 BR-10을 따르며 무기한 보관합니다. 설정 값과 인물 기본 정보를 포함한 세계관은 Core DB에 항목과 갱신 기록으로 저장하고, 작품별 회차 기록은 DB에 둡니다(BR-10). 한 세계관에 연결할 수 있는 작품 수는 제한하지 않습니다.
- **미정:** 장르 기본 세계관의 장르 목록. (세계관 Fork는 원본 업데이트 사실만 알림으로 받고 원본 변경을 가져오지 않습니다(UC-27, BR-12).)
