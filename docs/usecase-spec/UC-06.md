# UC-06 캐릭터·관계·시점별 지식 관리

> [명세 목차·공통 규칙(CE·BR)](./README.md) · [유스케이스 문서](../usecase.md)
>
> **MVP 사용자 방향:** Fork 창작자가 인물·관계 변경을 요청하면 관련 설정 위치로 안내받아 자기 Fork의 내용을 직접 확인·수정할 수 있습니다(DEC-29). 원작은 변경하지 않고 권한·기준 시점·인물별 지식 경계를 유지합니다. 설정은 항목별 공개·비공개와 회차별 공개 범위를 적용합니다(DEC-36). 아래 과거 공개 전환·회차 기록의 세부 모델은 [최신 설계](../design/design.md)를 우선합니다.

## 최신 MVP 흐름 — 인물·관계·시점별 지식

**목표 서비스 책임(DEC-41):** 콘텐츠 서비스가 설정·인물·관계의 인가·정본·버전·실제 반영을 소유합니다. Core는 회원 인증·크레딧·알림, AI는 허용 문맥의 제안·검토를 담당합니다. 현재 콘텐츠 구현은 `core-api` 안에 있으며 별도 Kotlin/Spring Boot 앱으로의 분리는 미완료입니다.

**목표:** 창작자가 인물 설정과 관계를 관리하고, 특정 이야기 시점에서 인물이 알고 있는 범위를 구분해 직접 집필이나 선택적 시뮬레이션에 활용합니다.

**사전조건:** 로그인 및 대상 설정·관계를 수정할 권한이 필요합니다. 작품과 기준 회차가 필요한 조회·시뮬레이션에서는 해당 작품에 접근할 권한과 적용할 기준도 확인해야 합니다. 세계관이나 인물 항목을 처음 만드는 시점에 회차가 반드시 있어야 하는지는 미정입니다.

**기본 흐름**

1. 창작자가 세계관의 인물 설정 항목을 열거나 새로 작성합니다([UC-02](./UC-02.md)). 성격·목표·능력 등은 인물 설정의 예시이며 필수 입력 항목은 미정입니다.
2. 창작자가 인물 간 관계 또는 관계 변화를 입력하고 확인합니다. 관계는 그래프 DB에서 저장·조회하는 방향이나 구체적인 입력 화면과 관계 모델은 미정입니다(DEC-26).
3. 창작자는 필요할 때 대상 작품과 기준 회차를 확인하고, 그 시점의 인물 상태와 알고 있는 내용을 기록합니다. 인물의 기본 설정과 회차에 따라 변하는 상태·지식은 세계관과 함께 이어집니다(DEC-33). 다른 인물의 비밀이나 미래 사건은 허용되지 않은 문맥에 제공하지 않습니다.
4. 시스템이 수정 권한과 기준 버전을 확인한 후 사용자가 확정한 설정·관계 변경을 반영합니다. 인물 설정 문서의 확정 변경은 기존 버전을 덮어쓰지 않는 새 버전으로 남기는 방향입니다. 관계의 버전 표현과 저장소 간 동기화는 미정입니다.
5. 창작자는 허용된 범위에서 인물 설정과 관계를 확인하고, 필요한 경우 선택적으로 시뮬레이션을 실행합니다([UC-09](./UC-09.md)). 시뮬레이션의 임시 결과는 채택·반영 전까지 정본을 바꾸지 않습니다.

**대안·예외**

- 원고에서 추출한 후보나 시뮬레이션 결과를 참고할 수 있습니다([UC-04](./UC-04.md)·[UC-09](./UC-09.md)). 후보를 만드는 것과 사용자가 선택해 실제 반영하는 것은 별개입니다.
- Fork 창작자는 인물·관계를 수정하기 전 원본 세계관의 허용된 변경을 따라갑니다. 최초 수정 시 세계관 전체를 자기 소유로 Fork해 수정하고, 이후 원본 변경은 알림을 보고 반영 여부를 선택합니다. 원작은 수정하지 않습니다([UC-08](./UC-08.md), DEC-32·34).
- 권한 부족, 기준 충돌, 저장 실패 또는 관계 반영 실패는 성공으로 표시하지 않습니다. 이전 확정 버전을 보존하고, 저장소 간 부분 반영이 생기면 그 상태와 복구 방식을 확인해야 합니다. 기준 정보가 불충분하면 과거의 확정 상태인 것처럼 표시하지 않습니다(CE-02·03·07).

**경계·미정:** 설정 항목별 공개 범위, 작품 접근·독자가 볼 수 있는 발행본·인물별 지식은 구분합니다(DEC-36). 상태·지식이 세계관과 이어진다는 원칙은 확정이며, 물리 저장과 입력·조회 단위, 관계 이력·시점 비교 및 그래프와 문서 버전 동기화는 미정입니다. 설정·상태·관계 이력은 삭제 대신 revert로 정정합니다(DEC-33).

## 기존 기획 상세 — 최신 MVP와 대조 필요

아래 내용은 이전 기획을 보존한 것입니다. 항목별 독자 공개 전환, 댓글식 이력·RDB 단독 관계 저장과 여러 세계관 연결은 위 최신 흐름과 [결정 기록](../design/decisions.md)을 우선하며, 충돌하는 기존 문구를 현행 MVP 계약으로 취급하지 않습니다.

| 항목 | 내용 |
|---|---|
| 주 액터 | 창작자 |
| 구분 | 핵심 |
| 관련 기능 ID | [F-CHR-01](../requirements.md#f-chr-01)~[06](../requirements.md#f-chr-06), [F-OPS-02](../requirements.md#f-ops-02) |
| 근거 | 기획서 15쪽, 그림 10 |
| 관계 | UC-04 추출 후보·UC-09 선택 결과를 입력으로 받음(UML 관계 아님) |

- **목표:** 인물의 기본 특성과 회차 진행에 따른 관계·상태·지식을 일관되게 관리합니다.
- **사전조건:** 세계관(UC-02)과 작품(UC-24)이 있고 대상 정보의 편집 권한이 있습니다.
- **트리거:** 캐릭터 등록 또는 특정 회차 시점의 상태 편집을 선택합니다.

**기본 흐름**
1. 창작자가 캐릭터를 추가하고 성격·목표·기억·능력·역할 등 프로필을 입력합니다.
2. 창작자가 인물관계도에서 다른 인물과의 관계와 감정을 정의합니다.
3. 창작자가 기준 회차를 선택합니다. 시점은 회차 단위로 관리합니다.
4. 창작자가 그 시점의 관계·감정·보유 정보 변화를 기록합니다.
5. 창작자가 각 정보마다 두 속성을 따로 지정합니다.
   - 독자 공개 범위: 비공개, 또는 독자에게 공개되는 회차
   - 인물별 인지: 어떤 인물이 어느 시점부터 그 사실을 아는지

   두 속성은 독립적이므로 "독자는 알지만 주인공은 모르는 사실"과 "인물은 알지만 독자에게 아직 숨긴 사실"을 모두 표현할 수 있습니다.
6. 창작자가 인물의 행동 가능 범위(지식·목표·능력에서 오는 제약)를 정리합니다.
7. 시스템이 변경 내용을 확인하고 저장하며 변경 이력에 기록합니다.
8. 창작자가 회차 기준으로 인물의 상태 이력을 조회합니다.

**대안 흐름**
- A1 (1단계) 추출·시뮬레이션 결과 참고: UC-04 후보나 UC-09 선택 결과를 불러오되, 창작자가 채택한 항목만 반영합니다. 세계관 자동 업데이트가 켜진 작품은 UC-04가 반영한 변경도 이력에서 확인합니다.
- A2 (8단계) 특정 시점 비교: 두 시점의 상태 차이를 비교합니다.
- A3 (5단계) 떡밥 공개: 비공개였던 사실을 특정 회차부터 독자 공개로 전환하고, 시스템이 전환 회차를 기록합니다(BR-10).

**예외 흐름**
- E1 (4단계) 시점·근거 불명확: 과거 사실로 확정하지 않고 창작자 확인을 요청합니다.
- E2 (7단계) 저장 실패: CE-03.
- E3 (7단계) 다른 곳에서 수정됨: CE-07.

- **성공 보장:** 시점별 인물 정보가 이력과 함께 저장되어 집필·검토·시뮬레이션에서 해당 시점 기준으로 쓰입니다.
- **최소 보장:** 실패 시 기존 상태가 유지됩니다.
- **업무 규칙:** 한 인물에게 다른 인물의 비밀이나 미래 사건을 제공하지 않습니다(BR-02). 시뮬레이션의 임시 상태는 채택 없이 정본에 반영하지 않습니다([F-CHR-03](../requirements.md#f-chr-03)). 갱신은 기본 수동입니다(UC-04). 인물 기본 정보는 세계관 항목으로 Core DB에, 작품별 시점 상태·인지·독자 공개 회차는 작품별 회차 기록으로 DB에 저장합니다(BR-10, [F-WLD-08](../requirements.md#f-wld-08)). 다른 작가의 세계관을 빌려 쓰는 작품도 자기 작품의 기록만 씁니다. 인물관계도는 세계관의 일부이며, 인물관계도만 바꾸려면 인물관계도만 담은 세계관을 만들어 연결합니다(UC-02 A7).
- **미정:** 없음.
