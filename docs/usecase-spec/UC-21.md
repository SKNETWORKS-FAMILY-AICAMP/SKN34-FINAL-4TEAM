# UC-21 처리 실패·지연 경고 확인

> [명세 목차·공통 규칙(CE·BR)](./README.md) · [유스케이스 문서](../usecase.md)
| 항목 | 내용 |
|---|---|
| 주 액터 | 플랫폼 운영자 |
| 구분 | 지원 |
| 관련 기능 ID | F-OPS-05 |
| 근거 | 기획서 13쪽 |
- **목표:** 자동 처리의 실패·지연을 사용자에게 즉시 알리고, 운영자가 경고와 오류 로그로 원인을 확인해 고칩니다.
- **사전조건:** 운영자 권한.
- **트리거:** 시스템이 실패·지연 경고를 보내거나, 운영자가 운영 화면을 엽니다.
**기본 흐름**
1. AI 처리가 실패하거나 기준 시간 안에 끝나지 않으면, 시스템이 사용자에게 즉시 실패를 알리고 대기 상태로 두지 않습니다(CE-04).
2. 시스템이 오류 로그를 남기고 운영자에게 경고를 보냅니다.
3. 운영자가 경고 목록(처리 실패, 시간 초과, 권리 신고 대기)을 확인합니다.
4. 운영자가 건을 골라 로그(실패 단계, 오류 내용, 대상 기능)를 확인합니다. 원고 내용은 필요한 범위만 보여 줍니다.
5. 운영자가 원인(설정·연동 오류 등)을 고치고 조치 결과를 기록합니다.
6. 자동 재처리는 하지 않으며, 사용자는 해당 작업을 다시 요청할 수 있습니다.
**대안 흐름**
- A1 (3단계) 권리 신고 대기 건: UC-20 처리로 이동합니다.
**예외 흐름**
- E1 (2단계) 경고 전달 실패: 로그는 남기고, 운영 화면에서 확인할 수 있게 합니다.
- **성공 보장:** 실패·지연이 사용자에게 즉시 알려지고, 운영자가 원인을 확인할 수 있습니다.
- **최소 보장:** 운영자가 실패를 성공으로 바꾸거나 정본·피드백 응답을 직접 작성하지 않습니다. 로그에 비공개 원고 전문이나 비밀값을 남기지 않습니다.
- **업무 규칙:** 실패한 작업의 크레딧은 UC-17 오류 복구 기준을 따르며, 사용자 동의 없이 다시 차감하지 않습니다.
- **미정:** 지연 기준 시간, 경고 채널, 로그 보관 기간, 운영자 세부 권한.
