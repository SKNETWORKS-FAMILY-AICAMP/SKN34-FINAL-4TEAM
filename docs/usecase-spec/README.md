> [유스케이스 문서](../usecase.md)의 UC-01~25를 상세화한 명세입니다. 사전조건·흐름은 목표 업무 계약이며 구현이나 정책 확정을 뜻하지 않습니다. 정해지지 않은 값(형식, 한도, 요금, 상태 코드)은 `미정`으로 남깁니다. 상태 전이·처리 연쇄·서비스 호출은 [보조 다이어그램](../diagrams/README.md)을, UI 프로토타입과의 차이는 [UI 프로토타입 대응](../prototype-alignment.md)을 함께 봅니다.

## 0. 작성 규칙

### 0.1 명세 항목

| 항목 | 의미 |
|---|---|
| 주 액터 / 보조 액터 | 목표를 가진 액터 / 처리에 참여하는 외부 액터 |
| 관계 | include·extend ([usecase.md 2.7절](../usecase.md#27-유스케이스-간-관계)) |
| 관련 기능 ID | [요구사항 정의서](../SKN34-final-4Team_요구사항정의서.xlsx)의 기능 ID |
| 사전조건 | 시작 전 참이어야 하는 조건 |
| 트리거 | 유스케이스를 시작시키는 사건 |
| 기본 흐름 | 가장 일반적인 성공 경로. `사용자`·`시스템` 주어를 명시 |
| 대안 흐름 | `An (m단계)`: m단계에서 갈라지는 다른 성공·선택 경로 |
| 예외 흐름 | `En (m단계)`: m단계에서 목표를 이루지 못하는 경로 |

| 업무 규칙 | 이 유스케이스에 적용되는 규칙 (`BR-xx`는 0.3절 공통 규칙) |
| 미정 | 구현 전 합의가 필요한 항목 |

`시스템`은 STORYFORK 전체(Frontend·Core API·AI Service)를 뜻합니다. 권한·정본·발행·크레딧의 최종 판단은 Core API가 합니다.

| CE-05 | 비용·한도 부족 | AI 작업을 시작하지 않고 필요한 조건을 안내(UC-17). 잔여 크레딧이 예상 상한보다 적은 경우와 요청 속도 한도 초과(다시 시도할 시점 안내)를 포함 |
| CE-06 | 이용 제한 대상 | 권리 제한(UC-20) 중인 콘텐츠는 해당 기능(공개·AI·Fork)을 수행하지 않음 |

### 0.3 공통 업무 규칙

| ID | 규칙 |
|---|---|
| BR-01 | AI 결과(추출 후보·시뮬레이션·초안·검토 의견·수정안)는 제안이다. 사용자 선택·승인과 실제 저장·공개는 별도 단계다. 단, 작품 소유자가 자동 처리(세계관 자동 업데이트, 표기 오류 자동 승인·발행, AI 자율 연재)를 켠 경우 그 설정을 사전 승인으로 보며, 자동 반영 내용은 모두 변경 이력에 남겨 되돌릴 수 있게 한다 |
| BR-02 | AI에는 작업에 허용된 최소 문맥만 전달한다. 작가 비공개 정보·독자 공개 범위·인물별 지식을 섞지 않는다 |
| BR-03 | 원고 보유·등록·공개 사실만으로 AI 처리·재공개·Fork·유료 공개 권한을 추정하지 않는다 |
| BR-04 | Fork는 분기 기준 회차까지의 회차 원고와 분기 시점의 세계관·인물관계도를 불변으로 고정한다. 분기 시점에 독자에게 공개된 항목만 포함하고 비공개 항목은 제외한다. 원작의 후속 변경(공개 전환 포함)은 기존 Fork에 반영하지 않는다. 분기 이후의 회차·설정은 Fork 소유자가 수정할 수 있다. Fork는 분기 시점의 세계관·인물관계도 버전을 참조한다(BR-10). 작품 운영 설정(세계관 업데이트·표기 오류 처리·자율 연재)과 공개 조건은 Fork에 넘기지 않으며, Fork 소유자가 기본값부터 정하되 원작이 허용한 범위를 넘을 수 없다. 분기 이후 Fork 소유자가 설정을 고치면 고정본 위에 새 버전을 쌓은 Fork 작품 전용 세계관이 되며, 다른 작품에 연결하거나 공개할 수 없다. 원작자 소유 세계관 항목은 작품 Fork 허용만으로 고칠 수 있지만, 원작이 빌려 쓴 다른 작가의 세계관 항목은 그 작가가 세계관 Fork를 허용했을 때만 고칠 수 있다. 새 설정 추가는 언제나 가능하다. 빌려 온 세계관의 제한(AI 처리·유료 공개 금지 등)은 Fork에도 적용된다. 고정은 분기 시점 세계관·인물관계도의 Gitea 커밋 ID와 회차 원고 버전을 기록하는 방식으로 한다(브랜치 운용은 구현 시 결정). 기존 Fork는 고정본을 가지므로 원작이 삭제되거나 Fork 허용이 철회되어도 유지한다. 원작 삭제 시 원작 링크는 "삭제된 원작"으로 표시하고, 허용 철회는 새 Fork만 막는다. 원작 작품이 권리 신고로 조치되면 그 작품의 Fork에도 같은 조치를 적용한다(UC-20) |
| BR-05 | 처리 상태(접수·처리 중·실패·검토 대기·승인·반영 성공/실패)를 구분하고, 미완료를 완료로 표시하지 않는다 |
| BR-06 | 실패·권한 거부·한도 초과를 이유로 기존 원고·확정 설정을 덮어쓰거나 자동 삭제하지 않는다 |
| BR-07 | 권한은 계정 유형이 아니라 대상 작품·세계관별 소유권·이용 권한으로 판단한다 |
| BR-08 | AI 크레딧은 작업을 요청하거나 자동 실행을 설정한 사용자에게 청구한다. 자율 연재·세계관 자동 업데이트는 작품 소유자, 그 밖의 AI 기능은 요청자가 부담한다. 피드백(댓글·제보) 등록은 무료이며, 단순 오류 수정안·질문 답변·유해 콘텐츠 1차 필터는 플랫폼이 부담한다. 독자가 제보 전에 고른 스토리 오류 검증 시뮬레이션만 독자가 부담하고, 그 제보가 반영되면 플랫폼이 보상 크레딧을 지급한다(UC-14). 작품 Fork·세계관 Fork 생성, 직접 집필은 무료다 |
| BR-09 | 다른 플랫폼에서 가져온 외부 2차 창작물은 무료 공개만 허용한다. 권리 확인 책임은 등록자에게 있으며, 외부 2차 창작물도 Fork 원작이 될 수 있다. 원작자·저작권 문제가 제기되면 운영자가 빠르게 검토해 비공개 등 필요한 조치를 하고 소명 절차를 연다(UC-20). 조치의 상세 절차는 검토 예정이다. 같은 외부 IP는 먼저 올린 작품을 플랫폼의 원본으로 인정하고, 다른 사용자도 같은 IP로 다른 작품을 올릴 수 있다. 등록자는 외부 IP의 2차 창작 허용 범위를 따르며 플랫폼은 그 범위를 직접 확인하지 않는다. 원작 작가임이 확인된 신고는 즉시 비공개한다 |
| BR-10 | 세계관·인물관계도는 두 기준을 따로 관리한다. 변경 이력은 수정할 때마다 현재 HEAD 위에 새 버전을 만들고 HEAD를 옮기며, 이전 버전을 덮어쓰거나 삭제·머지하지 않는다. 회차 시점(설정 유효 회차·독자 공개 회차·인물별 인지 시작 회차)은 세계관이 아니라 작품별로 기록하며, 세계관에는 설정 값과 버전만 둔다. 과거 회차를 수정하면 그 작품의 회차 기록만 고친다. 자기 세계관을 고치면 그 세계관을 쓰는 자기 작품 모두에 바로 반영되며, 저장 전에 영향받는 작품 목록을 안내한다(조회만, AI 사용 없음). 작품마다 값을 달리하려면 작가가 자기 세계관을 복사한다(출처 관계 없음). 공개는 두 단계로 나눈다. 세계관 공개는 다른 작가가 그 세계관을 쓸 수 있는지(UC-07)이고, 독자 공개는 작품마다 몇 화부터 독자에게 보이는지다. 독자 공개 회차는 작품별로 기록한다. 다른 작품에서 공개된 항목도 이용 작품에는 작가만 보는 비공개 상태로 들어오며, 그 작품의 작가가 자기 회차 기준으로 공개 전환해야 독자 정보·Fork 범위·피드백 근거가 된다 |
| BR-11 | 독자 피드백과 수정안은 세계관을 바꾸지 않는다. 피드백 분석은 공개 근거를 대조하는 검증일 뿐이며, 수정안 반영에 따른 재발행은 세계관 자동 업데이트(UC-04)를 실행하지 않는다. 세계관 자동 업데이트는 작가나 자율 연재가 새 회차를 발행할 때 자동으로 반영한다. 이미 발행한 회차를 작가가 다시 발행하면 추출만 하고 작가가 확인한 항목만 반영한다(UC-04 A5) |
| BR-12 | 다른 사용자의 세계관은 고치지 않으면 원본을 그대로 참조한다. 고치려면 세계관 전체를 작가 소유의 세계관 Fork로 복사한 뒤 고치며, 작품의 연결은 원본에서 세계관 Fork로 교체한다. 세계관 Fork는 Fork 시점 HEAD의 공개 항목(인물관계도 포함)만 복사하고 비공개 항목·원작 작품의 회차 기록·원본 변경 이력은 복사하지 않는다. 원본 업데이트를 받지 않고 출처(원본 세계관·원작자·Fork 시점 버전)를 기록하며, 원본 소유자가 세계관 Fork를 허용한 경우에만 만들 수 있다(UC-07). 플랫폼이 제공하는 기본 세계관만으로 만든 세계관은 원본 관계가 없는 새 세계관이다. 세계관 Fork는 횟수 제한이 없고 다시 Fork할 수 있으며, 작품 Fork 제한(BR-14)을 따르지 않는다. 새로 추출한 설정도 작가 소유 세계관에 넣는다. 다른 작가의 세계관을 고치지 않고 빌려 쓰면서 자기 작품에 설정을 추가하는 것은 언제나 가능하며, 원본 규칙과 부딪히면 설정 검토(UC-12)로 확인한다 |
| BR-13 | AI 기능은 모두 작가가 골라 쓰는 도구다. 발행 전 설정 검토(UC-12)를 포함해 어떤 AI 기능도 필수 단계가 아니다. 단순 오류·질문 제보의 응대(UC-15), 피드백의 유해 콘텐츠 1차 필터(UC-14), 작품 소유자가 켠 자동 처리만 자동으로 실행된다 |
| BR-15 | 피드백 유형(댓글·단순 오류·스토리 오류·질문·제안)은 독자가 고르며 AI로 분류하지 않는다. 단순 오류(오탈자·맞춤법·명백한 숫자·표기)와 스토리 오류(설정 충돌·인물 모순·개연성)를 명확히 분리한다. 단순 오류만 수정안·자동 승인 경로를 타고, 스토리 오류는 언제나 작가가 판단한다. 신뢰도는 검증 시뮬레이션(UC-09 A5)을 거친 스토리 오류에만 표시한다 |
| BR-14 | 작품 Fork는 원작에서만 만들 수 있다. 한 독자는 한 원작에서 Fork를 1번만 만들 수 있고, Fork 작품을 다시 Fork할 수 없다(관리 단순화). 원작에 회차별 설정 이력이 없으면 Fork 시 현재 공개 상태의 설정을 고정하고 독자에게 경고한다 |
