# UC-22 회원 계정 관리

> [명세 목차·공통 규칙(CE·BR)](./README.md) · [유스케이스 문서](../usecase.md)

| 항목 | 내용 |
|---|---|
| 주 액터 | 회원 (가입은 아직 회원이 아닌 방문자가 시작) |
| 구분 | 지원 |
| 관련 기능 ID | [F-ACT-01](../requirements.md#f-act-01)~[09](../requirements.md#f-act-09) |
| 근거 | 요구사항 정의서 REQ01 |
| 관계 | 대부분 유스케이스의 사전조건(include로 표기하지 않음) |

- **목표:** 계정을 만들고 인증된 상태로 사용자별 기능을 이용하며, 본인 정보를 관리합니다.
- **인증 방식:** 이메일·비밀번호 로그인만 지원하며, 인증에는 JWT 접근 토큰과 갱신 토큰을 사용합니다. 소셜 로그인은 추후 연동합니다. 시연용 MVP는 가입·로그인과 접근 토큰만 제공하고 갱신 토큰·기기 관리·탈퇴는 시연 이후입니다(DEC-23).
- **사전조건:** 가입은 미가입 상태, 그 외 기능은 해당 계정의 본인 확인.
- **트리거:** 가입·로그인·로그아웃·정보 수정·계정 복구·탈퇴 중 하나를 선택합니다.

**기본 흐름 (가입·로그인)**
1. 방문자가 회원가입을 선택하고 이메일, 비밀번호, 닉네임을 입력하고 필수 약관(이용약관, 개인정보 수집·이용)에 동의합니다. 선택 동의는 가입 조건이 아닙니다.
2. 시스템이 입력 형식과 이메일 중복 여부를 확인합니다.
3. 시스템이 계정을 생성합니다. 이메일 인증은 MVP 이후이며(DEC-22), 도입 후에는 인증 메일을 보내고 방문자가 인증을 마치면 계정을 생성합니다.
4. 회원이 이메일과 비밀번호로 로그인합니다.
5. 시스템이 인증에 성공하면 접근 토큰과 갱신 토큰을 발급하고, 이후 요청마다 접근 토큰으로 사용자를 확인합니다. 접근 토큰이 만료되면 갱신 토큰으로 새 접근 토큰을 받으며, 이때 갱신 토큰도 새로 발급하고 이전 갱신 토큰은 폐기합니다.
6. 회원이 로그아웃하면 시스템이 그 기기의 갱신 토큰을 폐기합니다. 이미 발급한 접근 토큰은 짧은 만료 시간이 지나면 쓸 수 없습니다.

**대안 흐름**
- A1 (1단계) 정보 조회·수정: 로그인한 회원이 본인 정보를 조회하고, 변경 가능한 항목을 수정·저장합니다.
- A2 (4단계, 메일 발송이 필요해 MVP 이후) 계정 찾기·비밀번호 재설정: 가입한 이메일로 재설정 링크를 보내 본인을 확인한 뒤 비밀번호를 재설정합니다. 재설정하면 그 계정의 모든 갱신 토큰을 폐기합니다.
- A3 (1단계) 탈퇴: 회원이 탈퇴를 요청하면 시스템이 아래 탈퇴 데이터 기준을 안내하고, 확인 후 계정을 비활성화합니다. 탈퇴 사유는 선택 입력입니다. 30일 유예 기간 동안 작품·세계관은 숨기고, 회원이 다시 로그인해 복구하면 원래대로 돌립니다. 유예 기간이 끝나면 기준대로 처리합니다.
- A4 (6단계) 기기 관리: 회원이 로그인한 기기 목록을 보고 특정 기기 또는 모든 기기에서 로그아웃합니다. 시스템이 해당 갱신 토큰을 폐기합니다.

**예외 흐름**
- E1 (2단계) 형식 오류·중복: 계정을 만들지 않고 수정할 항목을 안내합니다.
- E2 (5단계) 인증 실패: 토큰을 발급하지 않으며 계정 존재 여부를 노출하지 않는 문구로 안내합니다.
- E3 (5단계) 토큰 만료·위조: 요청을 처리하지 않고 다시 로그인하도록 안내합니다(CE-01).
- E4 (A3) 탈퇴 처리 실패: 탈퇴 완료로 표시하지 않습니다.
- E5 (3단계, MVP 이후) 이메일 인증 미완료·인증 링크 만료: 계정을 만들지 않고 인증 메일 재발송을 안내합니다.
- E6 (5단계) 폐기된 갱신 토큰 재사용: 탈취 가능성으로 보고 그 계정의 모든 갱신 토큰을 폐기한 뒤 다시 로그인하도록 안내합니다.

- **성공 보장:**
  - 가입: 계정이 생성되어 로그인할 수 있습니다.
  - 로그인: 토큰이 유효한 동안 사용자별 기능을 이용할 수 있습니다.
  - 로그아웃: 그 기기의 갱신 토큰으로 더 이상 토큰을 받을 수 없습니다.
  - 정보 수정·복구: 변경한 정보 또는 새 비밀번호로 이용할 수 있습니다.
  - 탈퇴: 계정이 비활성화되고 안내한 기준대로 관련 데이터가 처리됩니다.
- **최소 보장:** 실패한 가입·수정은 계정 정보를 변경하지 않습니다. 비밀번호와 토큰을 응답·로그에 노출하지 않으며, 비밀번호를 평문으로 저장하지 않습니다.
- **업무 규칙:**
  - 독자·신입 작가·연재 작가는 계정 등급이 아닙니다(BR-07). 운영자 권한은 일반 가입으로 얻지 않습니다.
  - 토큰 만료 기준 값은 접근 토큰 30분, 갱신 토큰 14일이며 구현 단계에서 보안 검토 후 조정합니다. 갱신 토큰은 서버에서 폐기할 수 있도록 관리합니다. 여러 기기에서 동시에 로그인할 수 있습니다.
  - 휴대폰 본인 확인은 유료 기능 도입 시 검토합니다.
  - 인증·비밀번호 재설정 메일은 Core API가 SMTP 설정으로 보냅니다. 개발 환경은 로컬 Mailpit으로 받아 확인하고, 운영 발송사는 배포 시 정합니다. SMTP 설정은 루트 `.env`에서 Core API에만 전달합니다. MVP에서는 메일을 보내지 않으며 SMTP·Mailpit은 MVP 이후에 도입합니다(DEC-22).
  - 비회원은 공개 회차 열람과 작품 탐색만 할 수 있습니다. 피드백·Fork·권리 신고·AI 기능은 로그인이 필요합니다.
  - 탈퇴 데이터 기준: 회원의 작품·세계관·초안은 삭제합니다. 다만 다른 회원의 Fork·세계관 Fork가 참조하는 고정본은 유지하고 작성자를 "탈퇴한 회원"으로 표시합니다(BR-04, UC-08 원작 삭제 규칙). 이 경우 Fork 독자에게 분기 전 회차 본문을 보여 주지 않습니다. 회원이 만든 Fork 작품도 삭제합니다. 다른 작품에 남긴 댓글·피드백은 삭제하지 않고 작성자를 익명화합니다.
- **미정:** 약관·선택 동의 항목, 소셜 로그인 연동 시점, 탈퇴 시 남은 크레딧·결제 내역 처리, 로그인 실패 반복 시 잠금 기준.
