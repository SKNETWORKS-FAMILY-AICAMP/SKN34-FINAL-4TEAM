# UC-14 독자 피드백 등록·처리 상태 확인

> [명세 목차·공통 규칙(CE·BR)](./README.md) · [유스케이스 문서](../usecase.md)
| 항목 | 내용 |
|---|---|
| 주 액터 | 독자 |
| 구분 | 핵심 |
| 관련 기능 ID | F-FBK-01, F-FBK-10, F-FBK-11 |
| 근거 | 기획서 12쪽 시나리오 2.3, 19쪽, 그림 14 |
| 관계 | 피드백 작성은 UC-01을 extend, UC-15·UC-17을 include. 상태 확인은 독립 진입 |
- **목표:** 작품에 질문·의견·오류를 전하고 실제 처리 결과를 확인합니다.
- **사전조건:** 로그인. 대상 회차를 열람할 수 있습니다.
- **트리거:** 회차 열람(UC-01) 중 피드백 작성을 선택하거나, 내 피드백 화면을 엽니다.
**기본 흐름**
1. 독자가 피드백 유형(댓글, 오류 제보, 질문, 제안)을 선택합니다.
2. 독자가 내용을 입력하고, 필요하면 문제라고 생각한 구절을 지정합니다.
3. 시스템이 AI 분석에 필요한 크레딧을 안내하고 제보자의 동의를 받습니다(UC-17). 비용은 제보자가 부담합니다.
4. 독자가 등록합니다.
5. 시스템이 피드백을 대상 작품·회차, 독자가 본 발행본 버전, 지정 구절과 연결해 저장하고 접수 결과를 안내합니다.
6. 시스템이 UC-15 분석·응대를 시작합니다.
7. 독자가 내 피드백에서 응답과 처리 상태를 확인합니다.
**대안 흐름**
- A1 (1단계) 유형 미선택: 시스템이 UC-15에서 유형을 판단합니다.
- A2 (7단계) 작가 검토 진행 중: "작가 검토 중" 상태를 표시하고 결과가 나오면 갱신합니다.
- A3 (1단계) 상태만 확인: 독자가 내 피드백 화면에서 바로 7단계로 진행합니다.
**예외 흐름**
- E1 (3단계) 크레딧 부족: 등록하지 않고 필요한 조건을 안내합니다(CE-05).
- E2 (5단계) 접수 실패: CE-03. 접수되지 않았음을 안내합니다.
- E3 (6단계) 분석 실패·시간 초과: 접수는 유지하고, 즉시 "처리 실패"로 알리며 대기 상태로 두지 않습니다. 운영자에게 경고가 갑니다(UC-21).
- **성공 보장:** 피드백·대상 회차·발행본 버전·응답·처리 상태가 연결되어 독자가 확인할 수 있습니다.
- **최소 보장:** 검토 중이거나 반영에 실패한 제보를 해결 완료로 표시하지 않습니다(BR-05). 동의 없이 크레딧을 차감하지 않습니다.
- **업무 규칙:** STORYFORK에 접수된 피드백만 다루며 외부 플랫폼 댓글을 수집하지 않습니다. 분석 크레딧은 제보자가 부담합니다(BR-08).
- **미정:** 피드백 공개 범위(작성자만/전체), 수정·삭제 허용, 알림 채널, 악성 피드백 신고, 크레딧이 없는 독자의 제보 처리(무료 제공량 등).
