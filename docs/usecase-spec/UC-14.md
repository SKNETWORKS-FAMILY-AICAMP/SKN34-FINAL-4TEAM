# UC-14 독자 피드백 등록·처리 상태 확인

> [명세 목차·공통 규칙(CE·BR)](./README.md) · [유스케이스 문서](../usecase.md)
| 항목 | 내용 |
|---|---|
| 주 액터 | 독자 |
| 보조 액터 | 외부 LLM API (유해 콘텐츠 판정 모델) |
| 구분 | 핵심 |
| 관련 기능 ID | F-FBK-01~03, F-FBK-10·11, F-FBK-13~15, F-CRD-02 |
| 근거 | 기획서 12쪽 시나리오 2.3, 19쪽, 그림 14 |
| 관계 | 피드백 작성은 UC-01을 extend. 단순 오류·질문 제보는 UC-15가 extend(스토리 오류·제안은 UC-15를 거치지 않고 UC-16 작가 검토로 전달). 스토리 오류 검증 시뮬레이션은 UC-09 A5. 상태 확인은 독립 진입 |
- **목표:** 작품에 질문·의견·오류를 전하고 실제 처리 결과를 확인합니다.
- **사전조건:** 로그인. 대상 회차를 열람할 수 있습니다.
- **트리거:** 회차 열람(UC-01) 중 피드백 작성을 선택하거나, 내 피드백 화면을 엽니다.

**피드백 유형**

독자가 직접 고르며, 시스템이 유형을 AI로 분류하지 않습니다.

| 유형 | 정의 | 처리 |
|---|---|---|
| 댓글 | 감상·의견 | AI 분석 없이 등록. 전체 공개 |
| 단순 오류(표기 오류) | 오탈자, 맞춤법, 명백한 숫자·표기 오류 | 수정안 생성(UC-15) → 작가 검토 또는 자동 승인·발행(UC-16). 자동 승인은 오탈자·맞춤법·띄어쓰기·문장부호만 |
| 스토리 오류 | 설정 충돌, 인물 행동·지식 모순, 개연성 문제 | 작가 검토(UC-16). 독자가 고르면 제보 전에 검증 시뮬레이션(UC-09 A5) |
| 질문 | 작품 내용에 대한 질문 | 공개 근거로 답변(UC-15) |
| 제안 | 전개 선호·바람 | AI 분석 없이 작가에게 전달. Fork가 허용된 작품이면 UC-08을 함께 안내 |

**기본 흐름**
1. 독자가 피드백 유형을 선택합니다.
2. 독자가 내용을 입력하고, 필요하면 문제라고 생각한 구절(문장 단위)을 지정합니다. 댓글이면 스포일러 가리기를 켤 수 있습니다.
3. 독자가 등록합니다. 제보 등록은 무료입니다.
4. 시스템이 유해 콘텐츠 판정 모델로 내용을 검사합니다(1차 필터).
5. 통과하면 시스템이 피드백을 대상 작품·회차, 독자가 본 발행본 버전, 지정 구절과 연결해 저장하고 접수 결과를 안내합니다.
6. 제보이면 시스템이 유형에 따라 UC-15 응대 또는 작가 검토(UC-16)로 넘기고 상태를 표시합니다. 댓글은 "등록됨"으로 끝납니다.
7. 독자가 내 피드백에서 응답과 처리 상태를 확인합니다.

**대안 흐름**
- A1 (2단계) 스토리 오류 검증 후 제보: 독자가 제보 전에 검증 시뮬레이션(UC-09 A5)을 독자 크레딧으로 실행합니다. 결과를 보고 제보하면 "검증됨"과 신뢰도·근거가 함께 전달되고, 오류가 아니라고 판단하면 제보하지 않을 수 있습니다. 시뮬레이션에 쓴 크레딧은 제보 여부와 관계없이 돌려주지 않습니다. 검증 없이 제보하면 "미검증"으로 전달됩니다.
- A2 (7단계) 작가 검토 진행 중: "작가 검토 대기" 상태를 표시하고 결과가 나오면 갱신합니다.
- A3 (1단계) 상태만 확인: 독자가 내 피드백 화면에서 바로 7단계로 진행합니다.
- A4 (7단계) 반영 보상: 검증 후 제보한 스토리 오류가 작가 승인으로 원고에 실제 반영되면 시스템이 보상 크레딧을 지급합니다(업무 규칙).
- A5 (7단계) 수정·철회: 댓글은 작성자가 수정·삭제할 수 있습니다. 제보는 응대·검토가 시작되면 수정할 수 없고 철회만 할 수 있습니다.
- A6 (5단계 이후) 다른 독자의 신고: 다른 독자가 공개된 댓글을 신고하면 시스템이 즉시 다시 검사합니다. 걸리면 숨기고, 통과했던 글이면 작가·운영자 확인 목록으로 넘깁니다. 회차 본문의 유해 콘텐츠 신고는 UC-20 A5에서 처리합니다.
- A7 (5단계 이후) 숨긴 글 복원: 작가(자기 작품) 또는 운영자가 필터·신고로 숨긴 글을 확인하고 다시 공개할 수 있습니다.

**예외 흐름**
- E1 (A1) 크레딧 부족: 검증 시뮬레이션을 실행하지 않고 안내합니다(CE-05). 검증 없이 제보할 수는 있습니다.
- E2 (5단계) 접수 실패: CE-03. 접수되지 않았음을 안내합니다.
- E3 (6단계) 응대 실패·시간 초과: 접수는 유지하고, 즉시 "처리 실패"로 알리며 대기 상태로 두지 않습니다. 운영자에게 경고가 갑니다(UC-21).
- E4 (4단계) 유해 콘텐츠로 판정: 저장하되 "숨김"으로 두고 작성자에게 사유를 알립니다. 삭제하지 않습니다.
- E5 (4단계) 필터 호출 실패: 통과로 처리하지 않고 "필터 대기"로 숨겨 둔 채 다시 검사합니다. 통과하면 5단계로 진행합니다.

- **성공 보장:** 피드백·대상 회차·발행본 버전·응답·처리 상태가 연결되어 독자가 확인할 수 있습니다.
- **최소 보장:** 검토 중이거나 반영에 실패한 제보를 해결 완료로 표시하지 않습니다(BR-05). 동의 없이 크레딧을 차감하지 않습니다. 필터를 통과하지 않은 글을 공개하지 않습니다.
- **업무 규칙:**
  - STORYFORK에 접수된 피드백만 다루며 외부 플랫폼 댓글을 수집하지 않습니다.
  - 공개 범위: 댓글은 전체 공개이며 최신순·좋아요순으로 정렬할 수 있습니다. 댓글 좋아요는 수만 공개합니다. 제보와 그 응답은 제보자와 작가만 봅니다. 작가가 공개를 고른 응답만 회차 아래에 공개합니다.
  - 스포일러: 스포일러 가리기를 켠 댓글은 다른 독자에게 가려져 보이고, 독자가 펼쳐야 보입니다. AI 응답과 검증 시뮬레이션은 독자가 본 회차 이후 내용을 쓰지 않습니다(UC-15).
  - 비용: 댓글과 제보 등록은 무료입니다. 단순 오류 수정안과 질문 답변은 플랫폼이 부담하고, 독자가 고른 검증 시뮬레이션만 독자가 부담합니다(BR-08).
  - 반영 보상: 플랫폼이 부담하며 그 검증 시뮬레이션에 쓴 크레딧을 넘지 않습니다(기준 값: 50%). 자기 작품에 대한 제보는 보상하지 않고, 같은 수정에 연결된 제보가 여럿이면 먼저 검증된 1건만 보상합니다. 독자별 월 보상 상한을 둡니다.
  - 1차 필터는 OpenAI 모더레이션 모델(`omni-moderation-latest` 등)을 AI Service를 거쳐 호출합니다. 자동 판정에는 오판이 있을 수 있으므로 숨긴 글은 삭제하지 않습니다.
- **미정:** 월 보상 상한 값, 부계정을 이용한 보상 악용 탐지, 필터 재검사 주기(스케줄러 도입과 함께), 제보 횟수 한도.
