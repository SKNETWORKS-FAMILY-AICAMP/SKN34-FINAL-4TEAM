# UC-07 공개·Fork 허용 조건 설정

> [명세 목차·공통 규칙(CE·BR)](./README.md) · [유스케이스 문서](../usecase.md)
>
> **문서 상태:** 최신 MVP 방향을 반영한 목표 명세이며, 업무 기능은 아직 구현되지 않았습니다. 과거 문구와 충돌하면 [최신 결정](../design/decisions.md#결정-목록)과 아래 현재 명세를 우선합니다.

## 현재 MVP 명세

| 항목 | 내용 |
|---|---|
| 주 액터 | 작품 소유자 또는 설정 항목을 관리할 권한이 있는 창작자 |
| 구분 | 핵심 |
| 관련 기능 ID | [F-RGT-01](../requirements.md#f-rgt-01)~[03](../requirements.md#f-rgt-03), [F-FRK-01](../requirements.md#f-frk-01) |
| 근거 | 기획서 14·17·20쪽, 그림 9; DEC-35~38 |
| 관계 | UC-23이 include |

- **목표:** 작품의 공개 여부와 원작을 이용한 Fork의 생성·공개 조건을 정하고, 설정 항목의 공개 범위를 관리합니다.
- **사전조건:** 로그인하고 대상 작품 또는 설정 항목의 공개·이용 조건을 관리할 권한이 있습니다.
- **트리거:** 작품 또는 설정 항목의 공개·Fork 조건을 설정하거나 변경합니다.

### 기본 흐름 — 원작의 작품 공개와 Fork 조건

1. 작품 소유자가 관리할 원작의 공개·Fork 조건 설정을 엽니다.
2. 시스템이 현재 작품 공개 상태와 Fork 생성·Fork 작품 공개 조건, Fork 가능한 회차 범위를 각각 보여 줍니다.
3. 소유자가 작품 공개 여부를 선택합니다. 작품의 공개 여부는 Fork 생성·Fork 작품 공개 허용과 별개입니다.
4. 소유자가 **Fork 생성 허용**과 **Fork 작품 공개 허용**을 각각 선택하고 이후에도 변경할 수 있습니다. 작품 공개·Fork 조건은 여러 콤보박스 등의 선택 항목으로 조합하는 방향입니다. 신규 Fork 생성을 막더라도 기존 Fork의 공개 조건은 별도로 판단하므로 두 값을 구분해 보관합니다.
5. 소유자가 Fork 가능한 기준 회차의 범위를 정합니다. 전체 공개 회차, 특정 회차 이후, 회차별 선택으로 표현하는 방향이며, 전체 공개 회차 선택은 이후 발행되는 공개 회차에도 적용됩니다. 상세 경계와 기본값은 미정입니다.
6. 시스템이 소유·관리 권한과 입력한 대상·회차를 확인한 후 조건을 저장하고 현재 조건을 표시합니다. 공개·Fork 조건이 바뀌면 이전 조건을 덮어쓰지 않고 변경 이력을 보존합니다.
7. 시스템이 독자가 Fork하기 전에 볼 수 있는 현재 조건을 안내합니다. Fork 창작자는 생성 전 조건을 확인하며, 확인 후 조건이 바뀌었다면 새 조건을 다시 확인합니다. 시스템은 생성 시 확인한 조건을 기록하는 방향입니다([UC-08](./UC-08.md)).

### 대안 흐름

- **A1 (4단계) — 열람만 허용:** 소유자는 작품을 공개하되 신규 Fork 생성은 허용하지 않을 수 있습니다. 기존 Fork에 대한 공개 허용은 별도로 판단합니다.
- **A2 (1단계) — Fork 작품의 공개:** Fork 창작자는 자기 작품의 공개 조건을 정합니다. 최초 공개는 원작의 Fork 공개 허용을 따라야 하며, 이미 공개된 Fork는 아래 철회 규칙을 따릅니다. 기존 규칙상 Fork 작품을 다시 Fork할 수 없습니다(BR-14, UC-08).
- **A3 (트리거) — 세계관 설정 항목 공개:** 설정 항목의 기본값은 비공개입니다. 권한 있는 창작자가 항목을 만들 때 또는 나중에 공개·비공개와 회차별 공개 범위를 지정할 수 있습니다. 공개 조건 변경 이력을 보존하고, 숨길 내용은 별도 항목으로 분리합니다. AI가 제안한 변경은 창작자의 확인 후에만 반영합니다([UC-02](./UC-02.md), DEC-36). 설정 저장과 공개·발행은 별개입니다.
- **A4 (3단계) — 회차 하나만 공개 중단:** 작품 전체를 비공개로 바꾸는 대신 해당 회차의 공개를 중단합니다(UC-13).

### 예외 흐름

- **E1 (1·6단계) — 미인증·관리 권한 없음:** 요청을 처리하지 않고 로그인 또는 권한 부족을 안내합니다. 권한 밖 정보나 존재 여부를 노출하지 않습니다(CE-01·02).
- **E2 (5·6단계) — 회차 범위 부적절:** 다른 작품의 회차 등 유효하지 않은 대상을 허용 범위로 저장하지 않고 확인을 안내합니다. 실제 Fork는 열람 가능한 발행 회차를 기준으로만 만듭니다(UC-08).
- **E3 (작품 등록 시) — 등록자의 권리 확인 거부:** 작품 등록 시 등록자가 2차 창작 권리를 정확하게 확인했는지 묻습니다. 이전 기획에서는 확인을 거부하면 공개·Fork 허용 설정을 저장하지 않는 예외가 있었습니다. 등록 시 응답을 조건 저장과 어떻게 연결할지는 미정이며, 플랫폼이 각 작품의 권리를 직접 검증하지 않습니다(UC-24·DEC-38).
- **E4 (6단계) — 저장 실패·기존 조건 변경:** 저장 실패는 완료로 표시하지 않고 이전 조건을 보존합니다. 다른 변경과 충돌하면 묵시적으로 덮어쓰지 않고 재확인을 요청합니다(CE-03·07).
- **E5 (3·4·6단계) — 권리 제한:** 권리 침해 신고·법적 제한이 적용된 대상은 해당 제한을 따릅니다. 일반적인 원작자의 허용 철회와 별도로 처리하며 제한에 해당하는 공개·Fork 기능은 수행하지 않습니다(CE-06·UC-20).

### 보장과 업무 규칙

- **성공 보장:** 소유자가 선택한 현재 조건과 그 변경 이력이 구분되고, 열람·Fork 생성·Fork 공개 요청은 해당 권한과 조건에 따라 판단됩니다.
- **최소 보장:** 저장 실패 또는 권한 거부를 성공으로 표시하지 않고 이전에 저장된 조건을 보존합니다. 조회·참조·복사·알림·AI 문맥에 해당 사용자와 작업에 허용되지 않은 비공개 정보·미발행 원고·인물별 지식을 노출하지 않습니다.
- **Fork 생성 철회:** 생성 허용을 철회하면 새로운 Fork만 막고, 이미 생성된 Fork의 창작은 유지합니다(DEC-38).
- **Fork 공개 철회:** 공개 허용을 철회하면 아직 공개하지 않은 Fork의 최초 공개는 막습니다. 이미 공개한 Fork는 계속 공개하고 새 회차도 발행할 수 있습니다. 공개된 Fork에는 원작과 원작자를 표시합니다(DEC-38).
- **작품 비공개·회차 공개 중단:** 기존 기획상 작품을 비공개로 바꾸면 발행 회차를 독자 열람에서 숨기고, 다시 공개할 때 이전에 공개되던 발행 회차만 되돌립니다. 회차 하나의 공개 중단은 UC-13을 따릅니다. 기존 Fork와 이미 공개된 상태는 유지하고 비공개 원작 또는 공개 중단 회차를 기준으로 새 Fork를 만들 수 없습니다. 원작이 비공개이면 원작 링크는 ‘비공개 원작’으로 표시합니다(UC-08). 독립 전 원본 참조 자료의 접근·처리 세부는 미정입니다.
- **설정과 AI:** Fork 창작자는 이어받은 설정·인물·관계를 항목별 수정 제한 없이 자유롭게 수정합니다. AI 이용을 위한 별도 허용 스위치는 두지 않으며, AI는 선택적 도구이고 권한·공개 범위·인물별 지식을 지켜야 합니다(DEC-36~38·BR-02).
- **권리와 적용 범위:** 작품 등록·공개 또는 등록자의 확인만으로 법적 권리가 생기지는 않습니다. 조건은 STORYFORK 내 이용 조건이며, GitHub 라이선스와 유사한 선택 방식이 실제 CC·MIT 등의 법적 라이선스를 자동 적용한다는 뜻은 아닙니다. 외부 플랫폼 게시 조건은 현재 범위 밖입니다(DEC-38).
- **MVP 이후:** 유료 공개·수익 배분과 작품 Fork 없이 타인의 세계관을 직접 이용하는 기능은 MVP 범위 밖입니다(DEC-22·23·35). 작품 Fork와 별도로 타인의 세계관을 직접 이용하기 위한 과거 이용·세계관 Fork 허용 스위치와 유료 공개 스위치는 현재 설정에 적용하지 않습니다.

### 미정 사항

- 허용 회차 선택의 기본값, 특정 회차 이후에 기준 회차를 포함하는지, 미발행 회차 사전 선택 가능 여부와 화면 구성.
- 등록 시 권리 확인의 정확한 문구·저장·조건 설정과의 연계, 기존 조건과 변경 이력의 물리 저장 및 동시 변경 처리.
- 인물별 지식과 독자 공개의 세부 관리 방식은 팀 논의 사항이며, 작품·설정 공개 및 원본 참조의 물리적인 접근 판정은 별도 설계가 필요합니다.
- 최초 조건을 포함한 정책 이력과 Fork 창작자가 확인한 조건의 연결은 [Fork ERD](../design/erd/core/fork-and-checkpoint.md)의 논리 후보이며 실제 보존·판정 방식은 별도 설계입니다.

## 과거 상세 명세 원문

아래는 비교를 위해 보존한 이전 기획 원문입니다. 세계관 직접 이용·별도 세계관 Fork, 유료 공개 선택, 최초 생성 시 고정 복사 등 **최신 결정과 충돌하는 부분은 과거 기획**입니다. 충돌하지 않는 기존 규칙은 위 현재 명세와 관련 최신 결정을 따릅니다.

- **목표:** 다른 이용자에게 허용할 사용 범위를 정합니다.
- **사전조건:** 해당 콘텐츠를 관리하고 이용을 허락할 권한이 있습니다.
- **트리거:** 공개·이용·Fork 조건 설정을 선택합니다.

**기본 흐름**
1. 소유자가 대상 작품 또는 세계관을 선택합니다.
2. 시스템이 현재 조건을 표시합니다.
3. 소유자가 공개 범위(비공개 또는 공개)를 선택합니다.
4. 소유자가 대상에 맞는 권한 항목을 각각 정합니다.
   - 작품: 작품 Fork 생성, Fork 작품 공개, 유료 공개. 독자 열람 여부는 3단계 공개 범위로 정합니다.
   - 세계관: 이용, 세계관 Fork, 이 세계관을 쓴 작품의 유료 공개 허용. 세계관 Fork는 이용과 따로 허용합니다(BR-12). 세계관 자체의 판매는 범위 밖입니다.
5. 대상이 작품이면 소유자가 작품 Fork 허용 범위(허용 안 함, 특정 회차 이후, 회차별 선택, 전체 회차 허용)를 정합니다. 전체 회차 허용은 앞으로 발행할 회차에도 적용됩니다.
6. 시스템이 외부 IP 이용 권한 확인 문구를 안내하고 확인을 받습니다.
7. 시스템이 조건을 저장하고 이용자에게 표시될 안내 내용을 보여 줍니다.

**대안 흐름**
- A1 (4단계) 열람만 허용: 작품 Fork·세계관 이용을 허용하지 않는 조합으로 저장합니다.
- A2 (1단계) Fork 창작자: 자신의 Fork에 대해 공개 조건을 설정합니다. Fork 작품은 다시 Fork할 수 없으므로 Fork 허용 항목은 없습니다(BR-14). Fork 작품의 공개 조건은 원작에서 물려받지 않고 Fork 소유자가 정하되, 원작이 허용한 범위(Fork 작품 공개, 유료 공개)를 넘을 수 없습니다(BR-04).

**예외 흐름**
- E1 (1단계) 소유·허락 권한 없음: CE-02.
- E2 (6단계) 권리 확인 거부: 공개·Fork 허용을 저장하지 않습니다.
- E3 (7단계) 저장 실패: CE-03.
- E4 (3단계) 권리 제한 중: CE-06.

- **성공 보장:** 이후 열람·AI·Fork·공개 요청이 저장된 조건으로 판단됩니다.
- **최소 보장:** 실패 시 이전 조건이 유지됩니다.
- **업무 규칙:** 등록자의 확인만으로 외부 IP의 적법한 권한이 보장되지 않습니다(BR-03). Fork 허용과 유료 공개 허용은 별개입니다. 유료 공개 관련 항목(작품 유료 공개, 세계관의 유료 공개 허용)은 MVP 범위 밖이므로 MVP 화면에 표시하지 않습니다. 작품을 비공개로 바꾸면 발행된 모든 회차를 바로 숨기고, 다시 공개하면 이전에 발행돼 있던 회차만 돌아옵니다. 회차 하나만 숨기려면 UC-13의 공개 중단을 씁니다. 작품 Fork 허용을 철회하면 새 Fork만 막고, 이미 만든 Fork는 고정본으로 유지합니다(BR-04). Fork 작품 공개 허용을 철회하면 이미 공개된 Fork는 유지하고 아직 공개하지 않은 Fork만 공개할 수 없게 합니다. 유료 공개 허용을 철회하면 이미 유료로 공개된 Fork는 유지하고 새 유료 전환만 막습니다. 작품을 비공개로 바꿔도 기존 Fork는 유지하고 원작 링크를 "비공개 원작"으로 표시하며, 새 Fork는 만들 수 없습니다. AI 이용은 별도 허용 항목이 아닙니다. 작품 Fork·세계관 이용을 허용하면 그 범위에서 시뮬레이션·집필 지원 등 AI 기능을 쓸 수 있으며, 시스템은 설정 화면에서 이를 안내합니다. AI 이용을 막는 것은 권리 제한(UC-20)뿐입니다.
