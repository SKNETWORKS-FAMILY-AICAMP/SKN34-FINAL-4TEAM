# UC-18 AI 자율 연재 설정·자동 발행

> [명세 목차·공통 규칙(CE·BR)](./README.md) · [유스케이스 문서](../usecase.md)
| 항목 | 내용 |
|---|---|
| 주 액터 | 작품 소유자(원작·Fork 모두) |
| 보조 액터 | 외부 LLM API |
| 구분 | 핵심 |
| 관련 기능 ID | F-WRT-09, F-WRT-10, F-SET-01 |
| 근거 | 기획서 18쪽, 그림 13 |
| 관계 | UC-17을 include. 발행은 UC-13 확인 절차를 거침 |
- **목표:** 설정한 조건 안에서 AI가 다음 회차를 생성하고 자동으로 발행합니다.
- **사전조건:** 작품 소유자(원작이든 Fork든 무관). 권리 제한 중이 아니고, Fork라면 원작의 Fork 작품 공개 조건을 충족합니다.
- **트리거:** 작품 설정에서 자율 연재를 켜거나, 소유자가 정한 실행 일정(요일·시각)이 됩니다.
**기본 흐름**
1. 소유자가 작품 설정(UC-24)에서 자율 연재를 켜고 조건을 정합니다: 실행 일정(요일·시각, 주 1~7회, 하루 최대 1회), 1회 분량(기본값: 최근 회차 평균 분량), 방향, 독자 반응 참고 여부, 회당·월간 사용 한도, 발행 전 확인 여부(기본 꺼짐).
2. 시스템이 UC-17로 회당 예상 상한과 한도를 안내하고 동의를 받습니다. 비용은 작품 소유자 크레딧에서 차감합니다.
3. 소유자가 자율 연재를 시작합니다.
4. 실행 일정마다 시스템이 세계관 설정과, 소유자가 켠 경우 허용된 독자 반응을 참고해 다음 회차 생성을 AI에 요청합니다.
5. 시스템이 생성된 회차를 유해 콘텐츠 1차 필터와 UC-13 확인 절차(권한, Fork 원작 조건, 권리 제한)를 거쳐 자동 발행합니다.
6. 시스템이 발행 결과와 사용 크레딧을 소유자에게 알립니다.
**대안 흐름**
- A1 (3단계) 일시 중지·재개·종료: 소유자가 언제든 상태를 바꿉니다.
- A2 (6단계) 발행된 회차 수정: UC-10에서 수정한 뒤 UC-13으로 다시 발행합니다.
- A3 (1단계) Fork 작품: 같은 흐름으로 진행하며 비용은 Fork 소유자가 부담합니다.
- A4 (5단계) 발행 전 확인을 켠 경우: 생성된 회차를 초안으로 저장하고 소유자에게 알립니다. 소유자가 승인하면 UC-13으로 발행합니다. 승인하지 않은 초안이 있는 채로 다음 실행 일정이 오면 그 실행은 건너뛰어 초안이 쌓이지 않게 합니다.
**예외 흐름**
- E1 (2·4단계) 월간 한도 도달·크레딧 부족: 실행하지 않고 자율 연재를 `중단됨`으로 바꾼 뒤 소유자에게 알립니다(CE-05).
- E2 (4단계) AI 실패: CE-04. 해당 회차를 발행하지 않고 건너뜁니다. 자율 연재는 실행 중을 유지하고 소유자에게 알립니다. 연속 3회 실패하면 `중단됨`으로 바꿉니다.
- E3 (5단계) 발행 확인 실패(권리 제한 등): 발행하지 않고 초안으로 보관한 뒤, 자율 연재를 `중단됨`으로 바꾸고 소유자에게 알립니다. 소유자가 원인을 해결한 뒤 재개합니다(CE-06).
- E4 (5단계) 유해 콘텐츠 판정: 발행하지 않고 초안으로 보관한 뒤 소유자에게 알립니다. 자율 연재는 실행 중을 유지합니다.
- E5 (4단계) 실행 시점 지연(서버 중단 등): 예정 시각에서 1시간 넘게 지났으면 실행하지 않고 건너뛴 뒤 소유자에게 알립니다. 연속 실패 횟수에는 넣지 않습니다(UC-28 E2).
- **성공 보장:** 조건에 맞는 다음 회차가 자동 발행되고 결과가 소유자에게 전달됩니다.
- **최소 보장:** 한도를 넘는 실행이나 권한·조건을 충족하지 않는 발행, 필터를 통과하지 않은 발행이 일어나지 않습니다.
- **업무 규칙:** 자율 연재를 켠 것을 사전 승인으로 봅니다(BR-01). 원작·Fork 구분 없이 작품 소유자가 설정하며 비용도 작품 소유자가 부담합니다(BR-08). 외부 연재 플랫폼에 자동 게시하지 않습니다. 실행은 일정으로만 시작하며 독자 반응 수 같은 조건 트리거는 두지 않습니다. 독자 반응은 직전 회차 발행 이후 필터를 통과한 공개 댓글과 제안만 쓰고, 작성자 정보는 AI에 보내지 않으며, 단순 오류·스토리 오류 제보는 쓰지 않습니다(BR-02). 투표 기능은 범위 밖입니다. 실행 일정은 한국 시간(KST) 기준이며, Core API에 내장한 스케줄러 하나로 처리하며 별도 worker·큐를 두지 않습니다. 이 스케줄러는 새 실행 계층이므로 구현 전에 팀에 공유합니다.
- **미정:** 서버 여러 대로 늘릴 때의 중복 실행 방지.
