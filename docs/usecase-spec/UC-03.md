# UC-03 기존 원고 등록

> [명세 목차·공통 규칙(CE·BR)](./README.md) · [유스케이스 문서](../usecase.md)
>
> **MVP(DEC-24):** 회차별 붙여넣기 등록만 제공합니다. `.txt`·`.epub` 파일 업로드와 이미지는 시연 이후입니다.

| 항목 | 내용 |
|---|---|
| 주 액터 | 창작자(대표: 연재 작가) |
| 구분 | 핵심 |
| 관련 기능 ID | [F-WLD-05](../requirements.md#f-wld-05), [F-WLD-09](../requirements.md#f-wld-09), [F-SET-04](../requirements.md#f-set-04) |
| 근거 | 기획서 14쪽, 그림 9, 연재 작가 정의 |
| 관계 | UC-04가 extend. 대상 작품(UC-24) 필요 |

- **목표:** 보유한 기존 소설을 STORYFORK의 작품 회차로 등록해 창작 지원에 사용할 수 있게 합니다.
- **입력 방식:** `.txt`·`.epub` 파일 업로드, 또는 STORYFORK 에디터에 직접 입력·붙여넣기를 지원합니다. `.epub`은 DRM이 없는 파일만 읽으며, 본문의 이미지도 함께 가져옵니다. `.txt`에는 이미지가 없으므로 이미지는 등록 후 에디터(UC-10)에서 넣습니다.
- **사전조건:** 로그인. 대상 작품(UC-24)의 소유자. 등록할 원고를 STORYFORK에 저장할 권한을 갖추었습니다.
- **트리거:** 작품에서 기존 원고 등록을 선택합니다.

**기본 흐름**
1. 창작자가 원고를 등록할 작품을 선택합니다.
2. 시스템이 권리 확인 항목(본인 저작물 여부, 계약상 제한 여부, 포함된 이미지의 이용 권한)을 안내하고 확인을 받습니다. 외부 2차 창작물이면 BR-09 고지를 함께 확인합니다.
3. 창작자가 `.txt`·`.epub` 파일을 올리거나 에디터에 원고를 입력합니다.
4. 시스템이 읽은 내용, 회차 구분과 순서를 미리보기로 제시합니다. `.epub`은 챕터를 회차로 나누고 챕터 안 이미지 위치를 유지합니다. `.txt`·직접 입력은 회차 제목 줄(예: `1화`, `제1화`, `Chapter 1`)을 감지해 나누며, 감지하지 못하면 전체를 회차 1개로 둡니다.
5. 창작자가 누락·순서·회차 구분을 확인하고 필요하면 경계를 조정합니다.
6. 창작자가 등록할 범위를 확정합니다.
7. 시스템이 원고를 작품의 회차로 저장하고, 성공 항목과 실패 항목을 구분해 안내합니다.
8. 시스템이 설정 추출(UC-04) 진행 여부를 묻습니다.

**대안 흐름**
- A1 (6단계) 일부 회차만 등록: 이후 추출·검토 문맥이 등록 범위로 제한됨을 안내합니다.
- A2 (8단계) 추출 생략: 창작자가 UC-02·UC-06에서 설정을 직접 정리합니다.
- A3 (8단계) 추출 진행: UC-04로 진행합니다. 세계관 업데이트가 자동으로 설정된 작품이라도 기존 원고를 한꺼번에 등록할 때는 전체 추출 비용을 안내하고 동의를 받은 뒤 실행합니다.
- A4 (6단계) 회차·설정집·인물관계도 일괄 등록: 설정집과 인물관계도를 최종 상태로 한꺼번에 올리면 회차별 설정 이력이 생기지 않습니다. 시스템은 이 사실과 함께, 이 경우 Fork 시 현재 설정이 그대로 고정된다는 점(UC-08)을 안내합니다. 회차별 이력을 만들려면 UC-04로 회차별 추출을 실행합니다.

**예외 흐름**
- E1 (2단계) 권리 확인 거부: 등록을 진행하지 않습니다.
- E2 (3~4단계) 지원하지 않는 파일 형식(`.txt`·`.epub` 외)·DRM이 걸린 `.epub`·인코딩 판별 실패·읽기 실패: 해당 파일을 등록하지 않고 사유를 안내합니다.
- E3 (7단계) 일부 회차 저장 실패: 실패 회차를 구분 표시하며 전체 성공으로 안내하지 않습니다.
- E4 (7단계) 동일 원고 재등록: 기존 원고를 묵시적으로 덮어쓰지 않습니다. 같은 순서의 회차가 이미 있으면 그 회차의 새 초안 버전으로 추가하고, 발행본은 바꾸지 않습니다.
- E5 (3단계) 한도 초과: 파일 크기·회차 수·이미지 한도를 넘으면 등록하지 않고 한도를 안내합니다.
- E6 (4단계) 일부 이미지 읽기 실패·지원하지 않는 이미지 형식: 본문은 등록하되 빠진 이미지를 표시하고, 전체 성공으로 안내하지 않습니다.

- **성공 보장:** 확인한 원고가 회차 순서와 함께 저장되어 창작 지원의 입력으로 준비됩니다.
- **최소 보장:** 실패 항목은 저장되지 않고, 기존 원고·설정은 그대로입니다.
- **업무 규칙:** 등록은 STORYFORK 공개, 외부 플랫폼 동기화, AI 학습 동의가 아닙니다(BR-03). 외부 플랫폼 로그인·스크래핑은 제공하지 않습니다. 외부 2차 창작물은 무료 공개만 가능합니다(BR-09). 인코딩은 UTF-8을 기본으로 하고 EUC-KR·CP949를 자동 판별합니다. 한도의 기준 값은 파일당 `.txt` 10MB·`.epub` 50MB, 한 번에 최대 300회차이며 구현 단계에서 조정합니다. 이미지는 JPG·PNG·WebP를 지원하며 장당 10MB를 기준으로 합니다. 이미지는 저장 사용량(UC-19)에 포함됩니다. 이미지 파일은 MinIO(S3 호환 저장소)에 저장하고 DB에는 위치와 메타데이터만 둡니다.
- **미정:** `.pdf`·`.docx`·`.hwp` 등 추가 형식 지원(UI 프로토타입 U24에서 `.pdf` 제안).
