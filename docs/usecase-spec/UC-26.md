# UC-26 AI 품질·사용량 모니터링 (LLMOps)

> [명세 목차·공통 규칙(CE·BR)](./README.md) · [유스케이스 문서](../usecase.md)

| 항목 | 내용 |
|---|---|
| 목표 서비스 책임(DEC-41) | 운영 영역 — Langfuse는 도입 시 별도 제품 서비스, 자체 UI/API 통합은 미정. AI 런타임 계측·평가 계약은 후속 설계 |
| 주 액터 | 플랫폼 운영자 |
| 보조 액터 | 외부 LLM API |
| 구분 | 지원 · MVP 이후 |
| 관련 기능 ID | [F-LLM-01](../requirements.md#f-llm-01)~[05](../requirements.md#f-llm-05) |
| 근거 | 기획서 근거 없음 · 팀 결정(LangChain·LangGraph·Langfuse 도입). UI 프로토타입 A05 |
| 관계 | UC-21(실패·지연 경고)과 별개. 지표 이상은 UC-21 경고로 전달, 플랫폼 부담 비용 집계는 UC-28 정기 작업(UML 관계 아님) |
- **목표:** 운영자가 AI 호출의 품질·비용·안전을 추적하고, 프롬프트·모델 변경이 품질을 떨어뜨리지 않는지 확인합니다.
- **사전조건:** 운영자 권한. MVP 이후 Langfuse를 별도 제품 서비스로 도입하고 AI Service의 호출 계측을 연동한 상태를 전제로 하는 목표 흐름입니다. 현재 도입 완료를 뜻하지 않습니다.
- **트리거:** 운영자가 AI 운영 화면을 열거나, 지표가 기준을 넘어 경고가 발생하거나, 프롬프트·모델 변경을 배포하려고 합니다.

**기본 흐름**
1. 시스템이 AI 작업마다 요청 ID, 작업 유형, LangGraph 단계(스토리 계획·인물·설정 검토·집필·응대 등), 모델·프롬프트 버전, 토큰 수, 지연 시간, 비용, 결과 상태를 Langfuse에 기록합니다.
2. 운영자가 선택될 운영 접근 화면(Langfuse 자체 UI 또는 우리 운영 화면 API 통합, 방식 미정)에서 기간·작업 유형별 지표를 확인합니다: 실패율, 시간 초과율, 지연 시간, 토큰·비용(사용자 부담·플랫폼 부담 구분), 품질 지표.
3. 운영자가 특정 요청을 골라 단계별 추적(어느 단계에서 얼마나 걸렸고 무엇이 실패했는지)을 확인합니다.
4. 운영자가 원인을 기록하고, 필요하면 프롬프트 버전을 되돌리거나 개선 작업을 등록합니다.

**대안 흐름**
- A1 (트리거) 프롬프트·모델 변경 전 평가: 운영자(또는 개발자)가 변경안을 고정 평가 세트로 실행해 기존 버전과 비교합니다. 평가 항목은 설정 충돌 탐지, 근거 인용 정확도(지어낸 인용 없음), 단순 오류 수정 정확도, 인물 지식 누설, 스포일러 누설입니다. 기준보다 나빠지면 배포하지 않습니다.
- A2 (트리거) 지표 경고: 실패율·지연·플랫폼 부담 비용·전체 속도 한도 사용률이 기준을 넘으면 시스템이 UC-21 경고로 운영자에게 알립니다.
- A3 (1단계) 정보 누설 표본 검사: 시스템이 AI 응답 표본을 골라, 작가 비공개 설정이나 독자가 아직 보지 않은 회차 내용이 섞였는지 자동 검사합니다. 의심 건은 경고로 올립니다(BR-02).
- A4 (3단계) 프롬프트 버전 되돌리기: 운영자가 문제가 된 프롬프트를 이전 버전으로 되돌립니다. 이미 생성된 결과는 바꾸지 않습니다.

**예외 흐름**
- E1 (1단계) 추적 기록 실패: AI 작업 자체는 계속 진행하고 결과를 바꾸지 않습니다. 기록 누락을 운영 화면에 표시합니다.
- E2 (A1) 평가 실행 실패: 평가 통과로 보지 않으며 변경을 배포하지 않습니다.

- **성공 보장:** 운영자가 AI 호출의 품질·비용·안전 상태와 변경 영향을 확인할 수 있습니다.
- **최소 보장:** 추적 기록에는 질문·원고·답변 본문을 남깁니다(팀 결정 2026-11-13). 작가 비공개 설정·현재 관계 본문은 참조만 남기고, 회원 계정 정보와 비밀값은 남기지 않습니다. 추적 화면에 원고 본문이 보이므로 Langfuse 접근은 운영 관리자 계정으로 제한합니다.
- **업무 규칙:**
  - AI Service는 LangChain(OpenAI 모델 연동)과 LangGraph(다단계·다중 에이전트 흐름)로 구현하고, 추적·평가·프롬프트 버전·평가 데이터셋은 Langfuse로 관리합니다.
  - Langfuse는 도입 시 별도 제품 서비스로 Docker에 직접 설치(self-host)해 운영하며 추적 데이터를 외부 SaaS로 보내지 않습니다. Compose 구성은 MVP 이후 도입 때 추가합니다. Langfuse에는 메타데이터(1단계 항목)만 보냅니다. 응답 품질 확인에 원문이 필요하면 공개된 회차·평가 세트로만 확인합니다.
  - 고정 평가 세트는 저작권이 만료된 작품(기획서 22쪽 데이터셋 후보)으로 만들며, 이용 조건을 확인한 데이터만 씁니다.
  - 운영 중 품질 지표는 시뮬레이션·집필 제안 채택률(UC-09·11), 수정안 승인률(UC-16), 검증된 스토리 오류 반영률(UC-14), 필터 숨김 후 복원률(오판률 추정, UC-14), 실패율·시간 초과율(UC-21)입니다.
  - 자체 학습 모델이 없으므로 MLOps(학습·재학습·모델 배포 관리)는 범위 밖입니다. 자체 모델을 도입하면 그때 추가합니다.
  - LLMOps는 운영 영역입니다. UI 프로토타입 A05는 요구 흐름의 참고이며, Langfuse 자체 UI 사용과 우리 운영 화면의 API 통합 중 선택은 미정입니다. Spring 운영 앱으로 Langfuse의 추적·프롬프트·평가 전체를 재구현하지 않습니다. AI 런타임 계측, 평가 실행 위치와 버전 적용·저장 계약은 후속 설계합니다.
  - 이 유스케이스 전체(Langfuse 추적 포함)는 MVP 이후에 제공합니다(DEC-18). MVP 동안 모델·토큰·지연·결과 상태는 업무 소유 서비스의 AI 작업 기록 방향으로 확인합니다. 현재 콘텐츠 작업은 분리 전 `core-api`에 있으며 목표 콘텐츠 작업·채택/반영은 콘텐츠, 운영 목적 검사는 운영, 크레딧 정산은 Core 책임입니다. Langfuse 관측 성공은 정본 반영·발행·정산 성공이 아닙니다.
- **미정:** Langfuse 자체 UI 또는 우리 운영 화면 API 통합, 평가 실행·AI 런타임 버전 적용 계약, 경고 기준 값, 평가 세트 구성과 통과 기준, 표본 검사 비율, 추적 기록 보관 기간.
