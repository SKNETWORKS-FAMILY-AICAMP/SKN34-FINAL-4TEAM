# UC-27 알림 수신·설정

> [명세 목차·공통 규칙(CE·BR)](./README.md) · [유스케이스 문서](../usecase.md)
>
> **세계관 Fork 최신 방향:** 독립한 세계관의 원본에서 Fork 기준 회차에 영향을 주는 변경이 생기면 독자에게 알리고, 독자가 변경 반영 여부를 선택합니다. 거절 후에도 나중에 반영할 수 있습니다(DEC-34·37). 아래의 '업데이트 사실만 알리고 변경을 가져오지 않음'은 이 결정에 대체됩니다. 알림 전달·보관·설정과 반영 세부는 미정입니다.

| 항목 | 내용 |
|---|---|
| 목표 서비스 책임(DEC-41) | Core — 회원 알림함·수신 설정·전달의 정본. 콘텐츠·운영은 사건·대상 참조를 제공 |
| 주 액터 | 회원 |
| 구분 | 지원 |
| 관련 기능 ID | [F-NTF-01](../requirements.md#f-ntf-01)·[02](../requirements.md#f-ntf-02) |
| 근거 | 기획서 근거 없음 · 팀 결정. 각 유스케이스의 "알림" 처리를 한곳에 모음 |
| 관계 | 다른 유스케이스가 만든 알림을 표시(UML 관계 아님) |
- **목표:** 회원이 자기와 관련된 처리 결과·상태 변화를 한곳에서 확인하고, 받을 알림을 고릅니다.
- **사전조건:** 로그인.
- **트리거:** 다른 유스케이스에서 알림 대상 사건이 생기거나, 회원이 알림함·알림 설정을 엽니다.

**알림 종류**

| 종류 | 예 | 끄기 |
|---|---|---|
| 읽기 | 관심 소설 새 회차(UC-01) | 가능 |
| 창작 | 새 댓글·제보·검토 대기(UC-14·16), 자율 연재 발행 결과(UC-18), 세계관 자동 반영 요약(UC-04), 사용 중인 세계관의 변경(UC-05), 세계관 Fork 원본 업데이트(UC-05) | 가능 |
| 처리 결과 | 처리 실패(CE-04), 제보 응답·처리 상태(UC-14), 숨김 처리(UC-14) | 불가 |
| 크레딧 | 크레딧 부족·자율 연재 중단(UC-17·18), 크레딧 소멸 예정(UC-17) | 불가 |
| 권리·보안 | 권리 신고·조치·소명(UC-20), 원작 조치에 따른 Fork 조치(UC-20), 탈퇴 유예(UC-22), 다른 기기 로그아웃·토큰 폐기(UC-22) | 불가 |

**기본 흐름**
1. 업무 소유 서비스(콘텐츠·운영 또는 Core)에서 알림 대상 사건이 생기면 사건과 대상 참조를 제공합니다. Core가 수신자·종류·수신 설정을 확인해 알림을 만듭니다. 새 서비스 간 사건·수신 규칙은 후속 계약으로 정합니다.
2. Core가 회원의 알림 설정에서 끈 종류이면 만들지 않습니다(끌 수 없는 종류는 항상 만듭니다).
3. Core가 알림함에 넣고 읽지 않은 수를 표시합니다. 같은 대상·종류가 몰리면 하나로 묶어 보여 주되(예: "새 댓글 12개"), 포함된 개별 사건과 대상을 구분할 수 있도록 보존합니다.
4. 회원이 알림함을 열어 알림을 확인합니다.
5. 회원이 알림을 선택하면 Core가 읽음으로 표시하고 Frontend가 관련 화면으로 이동합니다. 콘텐츠·운영 대상은 각 소유 서비스가 현재 접근 권한을 다시 확인하며 알림 보유만으로 접근을 허용하지 않습니다.

**대안 흐름**
- A1 (4단계) 알림 설정: 회원이 끌 수 있는 종류를 켜거나 끕니다. 기본값은 모두 켜짐입니다.
- A2 (4단계) 모두 읽음: 회원이 알림함 전체를 읽음으로 표시합니다.

**예외 흐름**
- E1 (1단계) 알림 생성 실패: 원래 처리(발행·응답 등)의 결과를 바꾸지 않습니다. 실패를 오류 로그에 남기고, 끌 수 없는 종류이면 운영자에게 경고합니다(UC-21).
- E2 (5단계) 대상이 삭제·비공개됨: 이동하지 않고 볼 수 없다고 안내합니다. 비공개 내용을 알림 문구에 노출하지 않습니다.

- **성공 보장:** 회원이 자신과 관련된 알림을 확인하고 받을 종류를 고를 수 있습니다.
- **최소 보장:** 알림 문구에 비공개 원고·설정, 신고자 정보, 다른 회원의 개인정보를 넣지 않습니다.
- **업무 규칙:** 알림은 사이트 안 알림함으로만 보냅니다. 이메일은 가입 인증·비밀번호 재설정 같은 인증·보안 메일에만 씁니다(UC-22). 알림은 회원이 직접 삭제하기 전까지 보관하며 기간만으로 플랫폼이 임의 삭제하지 않습니다. 알림 삭제는 원본 제보·작업 결과·세계관 변경 제안을 삭제하지 않습니다. 끌 수 있는 원본 변경 알림을 꺼도 변경 제안과 선택 상태는 보존하며 Fork 관리 화면에서 다시 확인합니다. 독립한 작품 Fork 세계관의 원본 변경은 알림 후 사용자가 반영 여부를 선택합니다(BR-04·12). 조합 세계관에는 원본 변경을 자동 반영하지 않습니다. 운영자 경고는 UC-21 경고 목록을 따릅니다.
- **전달 방향:** 사건 발생에 따라 알림을 전달하는 이벤트 방식으로 설계합니다. 기존 #89의 RabbitMQ/SSE/SNS 방향을 활용하되 서비스 분리 이후 사건·수신 규칙·전달 상세는 후속 조율합니다. 이전 Redis 후보 표현을 신규 도입 확정으로 보지 않습니다. 전달 수단만으로 알림 보관·재접속 복구가 보장되지 않으므로 알림함 기록은 별도로 보존하고 전달 실패·중복 처리를 설계합니다.
- **미정:** 웹 푸시 제공(추후 과제), 묶음 표시 기준 시간, 이벤트 전달 수단과 실패·중복 복구 방식.
