# UC-10 직접 집필·편집

> [명세 목차·공통 규칙(CE·BR)](./README.md) · [유스케이스 문서](../usecase.md)
>
> **현재 원고 저장 결정:** 원작 작가와 Fork 창작자는 자기 작품에서 직접 집필합니다. 자동저장은 작업 초안을 갱신하고 저장 버튼은 새 버전을 만듭니다. 이전 버전 복원은 새 버전으로 남기며 발행본을 자동으로 바꾸지 않습니다. 저장과 발행은 별개입니다. 회차당 최대 하나인 별도 작업 초안은 [논리 ERD 후보](../design/erd/core/work-and-writing.md)이며 물리 구조는 후속 검토합니다. Fork 창작자는 원작 원고와 AI 채팅을 함께 참고하거나 집필 전 자기 Fork의 세계관·인물·관계를 변경할 수 있습니다(DEC-29). AI는 선택적이고 원작은 수정하지 않습니다. 내보내기 및 세부 UI는 별도 검토합니다.
>
> **원고 이미지·인물 연결 결정:** 원고 중간에 이미지를 삽입하고 저장한 원고 버전에서 당시 이미지를 조회·복원할 수 있습니다. 발행 버전의 이미지는 독자에게 표시합니다. 이는 과거 설정 이미지 파일을 보존하지 않는 DEC-39와 별개입니다. 원고에서 `@`로 현재 작품 세계관의 인물을 선택·연결하고 표시를 눌러 설정을 확인합니다. 원고 저장 버전에는 당시 인물 연결도 보존하며 복원 시 함께 복원합니다. 연결은 인물 설정·관계를 자동 변경하지 않습니다. AI 참고에는 권한과 기준 시점을 적용합니다. 사건·장소 연결은 미정입니다.

- **목표:** AI 없이도 자신의 원고를 작성·수정합니다.
- **사전조건:** 대상 원작 또는 Fork 작품의 편집 권한.
- **트리거:** 회차를 열거나 새 회차 초안을 만듭니다.

**기본 흐름**
1. 창작자가 작품과 회차를 선택합니다.
2. 시스템이 편집 초안과 참고 자료(세계관, 등장인물, 이전 회차, 선택한 시뮬레이션 결과)를 표시합니다.
3. 창작자가 원고를 작성·편집합니다. 원고는 한 줄이 한 문단인 글이며, 문단 사이에 이미지를 넣을 수 있습니다. 글자 서식은 기본 서식(굵게·기울임·소제목·인용·구분선)만 제공하고(DEC-48, [계약](../design/manuscript-format-contract.md)) 표·목록·코드·링크 등은 제공하지 않습니다.
4. 창작자가 저장을 선택합니다.
5. 시스템이 초안을 저장하고 저장 시각과 버전을 표시합니다.
6. 창작자가 이전 버전 이력을 확인합니다.

**대안 흐름**
- A1 (3단계) AI 지원 요청: UC-11로 진행 후 돌아옵니다. 일러스트 생성도 UC-11에서 요청합니다.
- A2 (3단계) 설정 검토 요청: UC-12로 진행 후 돌아옵니다.
- A3 (5단계) 공개: UC-13으로 진행합니다.
- A4 (6단계) 이전 버전 복원: 선택한 버전을 새 초안 버전으로 쌓습니다. 기존 버전을 지우거나 발행본을 바꾸지 않습니다.
- A5 (2·3단계) 집필 보조 화면: 창작자가 타임라인, 보드, 사전(세계관·인물 문서), 개요 화면으로 참고 자료를 보고 정리합니다. 원고에서 `@`를 입력해 작품 세계관의 인물 항목을 선택·연결하고 표시를 눌러 설정을 확인합니다. 동일 이름이 있어도 선택한 인물 항목을 식별합니다. 연결 자체는 설정을 바꾸지 않으며, 세계관·인물 항목 변경은 UC-02·UC-06에서 이력을 남깁니다.
- A6 (3단계) 이미지 삽입: 창작자가 이미지 파일을 올리고 이용 권한을 확인하면, 시스템이 원고의 지정 위치에 넣습니다. 형식·한도는 UC-03 업무 규칙과 같습니다.
- A7 (3단계) 자동 저장: 입력이 잠시 멈추면 시스템이 현재 초안을 자동 저장하고 `저장 중`·`저장됨(시각)`·`저장 실패` 중 하나를 표시합니다. 자동 저장은 작업 중인 초안을 갱신할 뿐 새 버전을 만들지 않으며, 버전은 4단계 저장에서만 만듭니다.
- A8 (6단계) 원고 내보내기: 창작자가 회차 하나 또는 작품 전체의 초안·발행본을 `.txt` 또는 `.epub`으로 내려받습니다. `.epub`은 회차를 챕터로, 작품 정보를 메타데이터로 담고 이미지를 포함합니다. `.txt`에는 이미지가 빠집니다. Fork 작품은 분기 이후 자기가 쓴 회차만 내보낼 수 있습니다.
- A9 (2·3단계) Fork 창작: 허용된 기준 원작 원고 옆의 채팅에서 변경 방향을 논의하거나, 관련 설정 위치로 이동해 자기 Fork의 설정을 먼저 확인·수정합니다(UC-08·UC-11, DEC-29). 채팅 없이 직접 집필할 수도 있습니다. 기준 이전 원고의 편집 범위는 미정입니다.

**예외 흐름**
- E1 (5단계) 저장 실패: CE-03.
- E2 (5단계) 발행본·다른 편집과 충돌: CE-07. 같은 소유자가 여러 탭·기기에서 편집해 기준 버전이 바뀐 경우도 묵시적으로 덮어쓰지 않고 재확인을 받습니다.
- E3 (A6) 이미지 형식·한도 초과·업로드 실패·권리 확인 거부: 이미지를 넣지 않고 사유를 안내합니다. 원고 본문은 그대로 둡니다.
- E4 (A8) 내보내기 파일 생성 실패: 완료로 안내하지 않고 다시 시도하게 합니다.

- **성공 보장:** 초안이 버전과 함께 저장됩니다.
- **최소 보장:** 저장 실패 시 기존 저장본이 유지되고 미저장 상태가 표시됩니다.
- **업무 규칙:** 초안 저장과 발행본은 구분됩니다. 직접 집필에 AI 사용을 강제하지 않습니다. Fork에도 같은 흐름을 적용합니다. 수동 저장 버전은 무기한 보관합니다. 공동 집필은 이 유스케이스 범위 밖입니다. 사전은 세계관을 보여 주는 화면이며 별도로 저장하지 않습니다. `@` 연결과 타임라인·보드·개요·메모는 작품별 기록으로 DB에 저장하고 세계관 정본으로 취급하지 않습니다. 메모는 내보내기에 포함하지 않습니다. 이미지는 원고와 함께 버전에 포함되고 발행하면 독자 화면에도 표시되며, 저장 사용량(UC-19)에 포함됩니다. 이미지 파일은 MinIO에 저장합니다(UC-03). 이미지는 AI에 전달하지 않습니다(BR-02). 내보내기는 외부 게시·동기화가 아닙니다.
- **미정:** 자동 저장 간격. (이미지 대체 텍스트는 이미지별 값으로 집필실 이미지 목록에서 입력한다 — [계약 5절](../design/manuscript-import-export-contract.md))

## 회차 작가의 말 — 기능 62 (2026-11-10 확정)

- 선택 입력인 일반 텍스트이며 최대 2,000자다. 빈 값은 허용하고 앞뒤 공백을 제거한다.
- 초안 자동저장은 현재 작업본만 갱신한다. 명시적 저장은 제목·원고·작가의 말을 함께 불변 버전으로 만든다.
- 선택한 저장 버전을 발행할 때만 본문 뒤에 공개한다. 빈 작가의 말을 발행하면 독서 화면에서 영역을 숨긴다. 초안 수정만으로 기존 공개 내용은 바뀌지 않는다.
- 이전 저장 버전 복원은 당시 작가의 말을 포함한 새 버전을 만들고 자동 발행하지 않는다. 이전 체크포인트 재발행은 해당 발행본의 작가의 말을 함께 보여 준다.
- Fork는 생성 시 기준 발행본의 작가의 말도 보존한다. 상속 회차의 수정 제한은 원고와 같고, 이후 원작 수정으로 기존 Fork 내용을 바꾸지 않는다.
- 작가의 말은 AI 원고·세계관 문맥에서 제외한다. AI 제안 채택·원고 가져오기로 본문이 바뀌어도 기존 작가의 말은 보존한다.
- Content가 저장·권한·revision 검증을 담당한다. 기존 초안/버전/발행 API에 `authorNote`를 추가하며 기존 데이터와 생략 입력은 빈 값이다. 기존 발행·Fork·체크포인트 API와 정본 경계는 유지한다.
- `episode_draft`와 `episode_version`에 새 Flyway V23으로 필드를 추가한다. 기존 migration과 불변 버전 행은 수정하지 않는다.
- 실제 집필실에서 입력·초안 자동저장·버전 저장을 연결하고 기존 독서 화면의 본문 뒤 표시를 재사용한다. 별도의 즉시 공개 API나 알림은 만들지 않는다.

## 회차 관리 (기능 10)

- 순서 변경 가능 범위는 집필실에서 조회한다. 원작 상속 회차의 후보는 비어 있다. 작성 중인 회차의 후보는 원고 이미지·저장 버전·설정 범위·AI·Fork 참조로 보호된 위치를 넘지 않는다. 실제 순서 변경 정책은 미정이다. 조회 결과(후보 `N화`와 제한 사유)는 회차 관리 영역의 버튼 바로 아래에서 읽어 주고, 조회하는 동안 버튼을 잠근다.
- 초안 삭제는 작업 사본만 제거한다. 회차와 저장 버전·발행본은 보존하고 편집 번호를 올려 지연된 자동저장이 삭제를 되돌리지 못하게 한다.
- 회차 삭제는 기존 소유권·편집 번호·참조 없는 마지막 회차 조건을 적용한다. DEC-42에 따라 삭제 시각을 기록하고 회차와 작업 초안의 행을 보존한다. 삭제된 회차는 일반 조회와 새 행위에서 제외한다. 집필실은 발행본·저장 버전이 있거나 마지막 회차가 아니면 삭제 버튼을 잠그고 그 이유를 버튼 옆에 보여 준다. 이미지·설정 공개 범위·AI·Fork 참조는 서버가 판단하며, 거절하면 409로 이유를 안내한다. 삭제를 확인할 때 되돌릴 수 없고 같은 번호로 새 회차를 만들 수 있으며 저장하지 않은 입력이 사라진다고 안내하고, 삭제가 끝나면 키보드 초점을 본문 영역으로 옮긴다. 이미지 업로드는 최초 확인한 회차 ID가 저장 직전에도 활성 회차와 일치해야 한다.
- 2026-11-10 사용자 결정에 따라 마지막 회차를 삭제한 뒤 같은 번호를 새 회차 ID로 생성할 수 있다. 이전 회차에 연결된 계획은 기존 ID를 참조하며 새 회차에 자동 연결되지 않는다. 삭제된 회차의 기준 세계관(`basis_world_*`)도 삭제된 행에 남을 뿐 새 회차로 넘어가지 않으며, 새 회차는 기준 세계관 없이 시작한다.

## 서버 집필실 화면 구성 — U13 (2026-11-11 사용자 결정)

- **3단 레이아웃:** 왼쪽은 회차 목록과 그 아래 선택 회차의 버전 그래프, 가운데는 원고 편집기, 오른쪽은 AI 채팅이다. 좁은 화면에서는 세로로 쌓고 채팅은 접을 수 있다. **상단 바는 `기본 | 고급`·`버전 저장`·`버전 · 공개`(원고 저장본·비교·공개 시트)와 `더보기`(플롯·다시 불러오기·설정 버전 이력·발행 이력, 구분선 뒤 `다크 모드`와 개발 화면의 `화면 ID 끄기`) 메뉴 네 가지만 두고, 가운데는 제목·본문과 한 줄 하단 바(글자 수·공개 분량 안내·저장 안내·`이미지 첨부`·`회차 설정`)만 둔다. 원고 외 기능인 작가의 말·이미지·원고 내보내기·기준 세계관·회차 관리(순서 확인·공개 중단·재공개·발행 이력)·초안/회차 삭제는 `회차 설정` 시트로 옮겼고 동작과 비활성 조건은 그대로다.** 삭제가 확정되면 시트를 닫고 키보드 초점을 본문 영역으로 옮긴다.
- **회차 목록:** 채팅 앱의 대화 목록처럼 회차가 쌓인다. 새 회차 제목 입력·회차 생성 폼은 없고 목록 상단의 채팅 앱 `새 글 쓰기` 아이콘(사각형 + 연필) 버튼 `새 회차` 하나로 만든다. 서버가 빈 제목을 거부하므로(UseCase 검증·`@NotBlank`) 기본 제목 `새 회차`로 만들고, 제목은 편집기 첫 줄에서 바꾼다. API 계약은 바꾸지 않는다.
- **회차 항목 메뉴:** 각 회차 항목 오른쪽에 세로 점 세 개 버튼 `N화 더보기`(호버·선택·초점일 때 보이고 키보드 Tab으로 늘 닿는다)가 있다. 메뉴는 `회차 설정`·`체크포인트`·`설정 수집`·`발행 이력`, 구분선 뒤 `회차 삭제`이고 항목은 그 회차를 먼저 고른 뒤(저장하지 않은 입력을 버리지 않을 때만) 기존 기능을 연다: 회차 설정 시트, 버전 시트의 발행 체크포인트 영역(체크포인트가 없는 회차는 잠금), 그 회차의 발행 이력만 보여 주는 시트, 기존 삭제 흐름. `설정 수집`은 아직 기능이 없어 `준비 중`으로 잠그고 가짜 동작을 만들지 않는다. `회차 삭제`는 기존 차단 조건·사유(발행본·저장 버전·마지막 회차·원작 기준)와 확인 흐름을 그대로 쓰며, 다른 회차의 삭제는 그 회차가 선택된 다음에야 시작해 선택 중이던 회차를 잘못 지우지 않는다. 데스크톱에서는 목록이 스크롤 상자라 메뉴를 화면에 고정해 띄우므로, 목록을 스크롤하면 열린 메뉴를 닫아 메뉴가 다른 회차 옆에 남지 않게 한다.
- **목록·그래프 크기 조절:** 왼쪽 레일의 회차 목록과 버전 그래프 사이에 가로 분할선(`separator`)이 있다. ↑↓·Home·End 또는 끌어서 목록이 레일 높이의 20~80%를 차지하게 조절하며, 값은 화면 로컬 상태라 새로 열면 50%로 돌아온다. 좁은 화면(900px 이하)에서는 위아래로 쌓여 분할선을 쓰지 않는다.
- **편집기 첫 줄은 회차 제목이다.** 본문 영역 맨 위의 큰 제목 입력(placeholder `제목`, 접근성 이름 `회차 제목`)이며 기존 입력 후 2초 초안 자동저장을 그대로 쓴다.
- **원고 표시(DEC-48):** 미리보기류(집필실 미리보기·저장 버전 보기·버전 비교·체크포인트·작품 관리 '원고 보기')와 독자 화면은 같은 문법([계약](../design/manuscript-format-contract.md))으로 그린다. 독자 화면의 소제목은 회차 제목 아래 제목이고 미리보기류는 굵은 문단이다. 독자는 문단·인용·소제목의 문장을 고르고 구분선·이미지는 고를 수 없으며, 고른 문장으로 보내는 글은 원문 그대로의 조각이다. 한 줄의 내용이 2,000자를 넘으면 그 줄의 굵게·기울임은 해석하지 않는다.
- **본문 편집기(Tiptap):** 서식 없는 편집기이며 접근성 이름은 `원고 본문`이다. 문단과 이미지 블록만 있고 굵게·제목·목록 같은 서식은 없으며 붙여넣은 서식은 글자만 남는다. 저장 형식은 기존 그대로 일반 텍스트 + `[[image:<id>]]` 표식이다: 한 줄이 한 문단, 표식만 있는 줄이 이미지 블록, 빈 줄은 빈 문단이며 본문 ↔ 편집기 변환은 왕복해도 한 글자도 바뀌지 않는다(줄 가운데 표식은 글자로 남긴다). 이미지는 하단 `이미지 첨부` 버튼·붙여넣기·끌어다 놓기 모두 기존 업로드 경로를 쓰며(PNG·JPEG, 10 MiB, 회차당 10개와 오류 표시는 그대로) 성공하면 커서 위치에 실제 이미지 블록을 넣고 실패하면 넣지 않고 오류를 보인다. 업로드가 넣는 `\n\n표식\n\n` 규칙 때문에 이미지 앞뒤에 빈 줄이 생긴다. 본문이 40,000자를 넘는 입력은 막고 안내하며(표식 46자도 센다), 원작 기준 회차와 저장 중에는 편집할 수 없다. 회차 전환·다시 불러오기·복원·삭제처럼 편집기 밖에서 본문이 바뀌면 편집기를 새로 만들어 되돌리기 기록이 다른 글을 되살리지 못하게 한다.
- **공개 분량 규칙(2026-11-11 사용자 확정, 화면 규칙):** 공개(발행)할 때만 본문이 5,000자 이상이어야 한다. 자동 저장·버전 저장·복원은 분량과 무관하고 상한은 서버와 같은 40,000자다. **서버는 5,000자를 검사하지 않으므로 이 규칙은 집필실 화면이 지킨다.** 글자 수는 공백·줄바꿈을 포함한 저장 본문 문자열의 길이이며 이미지 표식은 46자로 센다(서버 `Manuscript.bodyLength`·40,000자 검사와 같은 기준이라 편집기의 `N / 40,000자`와 공개 판정이 같은 숫자를 쓴다). 편집기 하단은 `N / 40,000자`와 함께 5,000자 미만이면 `공개까지 5,000자 중 M자 남음`, 이상이면 `공개 가능 분량`을 보여 준다(원작 기준 회차는 보이지 않는다). 공개 경로 중 대상 저장 버전 본문이 5,000자 미만이면 `선택한 저장 버전 공개`·체크포인트 `이 체크포인트로 되돌리기`·`발행 예약`을 사유 문구와 함께 잠근다. `회차 재공개`는 이미 공개했던 발행본을 다시 켜는 동작이고 대상 버전을 서버가 발행 이력으로 정해 화면이 그 본문을 알지 못하므로 이 검사를 하지 않는다(이 규칙 이전에 짧게 공개한 회차는 다시 공개할 수 있다).
- **버전 그래프:** 선택 회차의 버전을 세로 한 줄 커밋 그래프로 그린다. 위에서 아래로 작업 초안(현재 위치, 저장하지 않은 변경이 있으면 `저장 안 됨`) → 저장 버전(최신부터, `버전 N · 제목 · 시각`, 발행 중인 버전에 `발행본`) → 원작 기준 회차의 기준 노드다. `버전 N`은 저장 버전 선택 목록과 같은 번호이고, 복원은 새 저장 버전으로 쌓이므로 분기를 따로 그리지 않는다. 프론트가 이미 받은 값(`versions`·`publishedVersionId`·`inherited`·`hasDraft`·미저장 여부)만 쓰며 백엔드에 부모 필드를 추가하지 않는다. 저장 버전 노드를 누르면 기존 버전 시트(원고 저장본·공개)가 그 버전을 선택한 채 열리고, 비교·복원·공개는 시트의 기존 기능을 쓴다.
- **공용 AI 채팅:** 메시지 목록(사용자 = 오른쪽 말풍선, AI = 아바타 + 왼쪽 말풍선, 안내 = 가운데 작은 글씨, 첨부 칩)과 빈 상태 제목·추천 칩(누르면 입력창에 글만 채움), **Claude식 둥근 입력 카드**(자동 높이 입력창·`+` 첨부 메뉴·마이크·전송, Enter 전송·Shift+Enter 줄바꿈·한글 조합 중 Enter 무시)를 가진 표시용 컴포넌트(`presentation/shared/chat`)다. 이후 캐릭터 챗이 재사용하며 API 호출·저장은 호출하는 화면이 맡고, 응답을 기다리는 동안에는 전송 버튼을 잠가 같은 입력을 다시 보내지 않으며, 전송이 예외로 실패하면 입력을 남기고 일반 실패 안내를 보인다. 채팅을 접거나 열면 키보드 초점을 새로 보이는 버튼으로 옮긴다. 현재 집필실에서는 **전송·첨부·마이크·추천 칩을 모두 "준비 중"으로 잠그고 사유를 입력 카드 아래에 보여 주며**(첨부 안내는 `+` 메뉴 안에만 둔다), 입력 카드는 패널 맨 바닥에 붙는다(머리글 / 메시지·빈 상태 스크롤 영역 / 입력 카드의 세로 구조). 패널은 편집기와 구분되는 옅은 브랜드 틴트 면이고 머리글에 브랜드 마크와 `AI 채팅`을 두며 입력 카드는 한 단계 밝은 면 + 부드러운 그림자로 떠 보인다(본문·placeholder 글자 대비 4.5:1 이상). 기존 이어쓰기 제안 API(`POST /works/{id}/proposals`)는 작품 revision을 요구하고 제안 대상이 서버가 정한 다음 작성 회차이며 OpenAI 전송·비용 동의가 필요해, 집필실의 선택 회차·회차 revision과 맞추는 정책을 정한 뒤 연결한다. 연결하더라도 제안 도착을 원고 반영·저장으로 표시하지 않는다. 가짜 업로드·가짜 응답은 만들지 않는다.
- **떠 있는 버튼:** 집필실(U13, `/studio/{UUID}`)에서는 오른쪽 아래의 `화면 ID 끄기`·다크 모드 버튼을 숨긴다(다른 화면은 그대로). 다크 모드는 상단 `더보기`의 `다크 모드`/`라이트 모드` 항목(현재 상태에 맞는 문구, 기존 테마 전환 그대로)으로, 개발 화면의 화면 ID 표시 토글은 같은 메뉴의 `화면 ID 끄기/켜기` 항목으로 옮겼고 운영 화면에는 후자가 없다.
- **기본/고급 전환 틀:** 상단 바의 `기본 | 고급` 토글(화면 로컬 상태)이다. 기본은 지금의 단순 집필이고, 고급은 이후 문맥 선택·장면 비트·고급 플롯 도구가 들어올 자리표시(`고급 도구 준비 중`)만 둔다. AI 원고 검토는 다음 단계라 이번 범위가 아니다.
