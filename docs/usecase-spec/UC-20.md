# UC-20 권리 침해 신고·비공개·소명

> [명세 목차·공통 규칙(CE·BR)](./README.md) · [유스케이스 문서](../usecase.md)

| 항목 | 내용 |
|---|---|
| 목표 서비스 책임(DEC-41) | 운영 — 신고·증거·소명·결정·감사. 실제 회원 제한은 Core, 작품·회차·Fork 제한/해제는 콘텐츠에 요청 |
| 주 액터 | 권리 신고자·소명자, 플랫폼 운영자 |
| 구분 | 지원 · 절차 일부 미정 |
| 관련 기능 ID | [F-RPT-01](../requirements.md#f-rpt-01)~[03](../requirements.md#f-rpt-03), [F-SET-04](../requirements.md#f-set-04) ([F-RGT-01](../requirements.md#f-rgt-01)~05와 관련) |
| 근거 | 기획서 20·22쪽 |
| 관계 | 조치 적용 실패는 UC-21 경고로 전달. UC-21 경고 목록에서 진입 가능(UML 관계 아님) |
- **목표:** 권리 침해·유해 콘텐츠 신고를 접수하고 유형에 맞게 판정·조치하며, 소명과 검토를 통해 공개 여부를 결정합니다.
- **사전조건:** 신고자가 로그인한 회원이며(UC-22) 대상 콘텐츠와 근거를 제시할 수 있습니다. 검토자는 운영자 권한을 가집니다.
- **트리거:** 권리 침해 또는 회차 본문의 유해 콘텐츠(인격권 침해 포함) 신고를 접수합니다. 댓글·제보의 유해 콘텐츠 신고는 UC-14 A6에서 처리합니다.
**기본 흐름**
1. 신고자가 대상 작품·회차·세계관 또는 개별 설정 항목과 근거, 연락처를 제출합니다.
2. 운영 서비스가 접수 번호와 접수 결과를 안내하고 각 신고자·접수·근거와 검토 건을 보존합니다. AI는 허용된 신고 문맥에서 같은 사안의 묶음 결과를 반환하며 사건 정본을 직접 수정하지 않습니다.
3. 시스템이 운영자에게 알립니다. 저작권 신고는 신고나 신고자의 권리자 확인만으로 비공개하지 않고 공개 상태에서 근거를 검토합니다. 24시간 내 1차 검토를 목표로 하며 지연 시 경고합니다.
4. 대상 소유자에게 신고와 소명 절차를 알리고 소명 자료를 받습니다.
5. 운영자가 신고 근거와 제출된 소명을 검토해 침해 여부를 판단합니다. 침해로 판명되면 운영 서비스가 즉시 콘텐츠 서비스에 비공개와 관련 기능·하위 Fork 조치 적용을 요청합니다. 콘텐츠 서비스가 실제 제한을 적용합니다. AI가 법적 결론을 대신하지 않습니다.
6. 운영자가 결정과 조치 대상별 적용 결과를 기록합니다. 소명 인정 등 제한 해제 시 다른 유효한 신고 조치가 남아 있으면 공개를 복원하지 않습니다.
7. 시스템이 실제 상태를 신고자·소유자에게 안내합니다.
**대안 흐름**
- A1 (1단계) 대상·근거 누락: 접수하지 않고 보완을 요청합니다.
- A2 (4단계) 기한 내 소명 없음: 통지 후 7일이며 요청 시 한 번 7일 연장합니다. 소명이 없다는 사실만으로 침해를 확정하지 않으며, 이미 유효한 제한은 별도 판단 전까지 유지합니다.
- A3 (6단계) 소명 인정: 운영 서비스가 해당 조치 해제를 콘텐츠 서비스에 요청하고 콘텐츠 서비스가 적용 전 상태를 참고해 복원합니다. 다른 유효한 제한은 유지하며 함께 조치한 Fork도 각각 확인합니다.
- A4 (3단계) 원작자 확인: 운영자가 공식 채널 등으로 신고자의 권리자 여부를 확인하되, 확인만으로 침해를 확정하거나 자동 비공개하지 않습니다.
- A5 (1단계) 유해 콘텐츠 신고: 운영 서비스가 AI에 모더레이션 검사를 요청하고 모델이 유해하다고 판정하면 콘텐츠 서비스에 자동 숨김·비공개 적용을 요청합니다. 실제 제한은 콘텐츠 서비스가 적용하며, 유해하지 않다고 판정하면 기존 공개 상태를 유지합니다. 성인 대상 소설·세계관 지원은 전체 서비스의 추가 요구사항으로 검토하며, 성인 등급이라는 이유만으로 허용된 성인 콘텐츠를 유해 콘텐츠와 동일하게 취급하지 않습니다. 허용·금지 기준, 연령 확인, 모델 판정과 자동 조치의 구체 경계는 법률·운영 검토 후 결정합니다. 판정과 적용 결과를 기록하고 운영자가 확인할 수 있도록 합니다. 모델 오류·오판 및 소명 처리의 상세는 별도 검토합니다.
- A6 (6단계) 허위 신고 판단: 운영자가 명시적으로 허위로 판단한 기록과 신고 제한을 남깁니다. 단순 기각은 허위 판단이 아닙니다. 허위 신고가 3회 쌓이면 30일 동안 신고 기능을 제한합니다. 신고 사건·접수 제한 판단은 운영이 관리하고, 회원·세션의 실제 이용 제한이 필요하면 Core에 요청합니다.
**예외 흐름**
- E1 (5~7단계·A3·A5) 조치 적용 실패: 적용되지 않았음을 표시하고 운영자에게 경고합니다(UC-21).
- E2 (3단계) 24시간 안에 1차 검토하지 못함: 지연 경고를 운영자에게 보냅니다(UC-21).
- E3 (A5) 모더레이션 호출 실패: 유해 또는 정상으로 판정된 것처럼 표시하지 않고 운영자에게 알립니다. 공개 상태 처리 방식은 미정입니다.
- **성공 보장:** 신고·조치·소명·결정이 기록되고 콘텐츠에 실제 상태가 적용됩니다.
- **최소 보장:** 신고만으로 원고를 삭제하지 않습니다. AI가 법적 결론을 내리지 않습니다.
- **업무 규칙:** 외부 2차 창작물의 권리 책임은 등록자에게 있습니다(BR-09). 저작권 침해로 판명된 경우 하위 Fork에도 관련 조치를 적용하고 각 소유자에게 알립니다. 신고자 정보는 Fork 소유자에게 알리지 않습니다. 운영은 신고·판정·조치 요청·소명·결정과 적용 전 상태 및 실제 적용 결과를 대상별로 기록하며, 결정 저장과 Core/콘텐츠의 실제 적용 성공을 구분합니다. 타 서비스 DB를 직접 수정하지 않습니다. 기록은 기간만으로 임의 삭제하지 않으며 법적 보관·삭제 의무와 개인정보 접근 권한은 별도 검토합니다. 신고자 연락처·증빙은 필요한 권한으로 제한합니다.
- **미정:** 증빙 기준과 플랫폼 면책 범위, AI가 묶은 신고의 운영자 분리·재검토 절차, 모델 실패·오판 시 처리, 세계관·설정 항목 신고의 하위 Fork 조치 범위와 적용 방법.
