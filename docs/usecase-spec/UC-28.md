# UC-28 시스템 정기 작업·운영 감시

> [명세 목차·공통 규칙(CE·BR)](./README.md) · [유스케이스 문서](../usecase.md)
| 항목 | 내용 |
|---|---|
| 주 액터 | 플랫폼 운영자 (정기 작업은 시스템이 일정에 따라 시작) |
| 구분 | 지원 |
| 관련 기능 ID | 없음 (요구사항 정의서 추가 필요) |
| 근거 | 기획서 근거 없음 · 팀 결정. 각 유스케이스의 기한·주기 규칙을 한곳에 모음 |
| 관계 | 실패·지연은 UC-21 경고로 전달(UML 관계 아님). AI 품질·비용 지표는 UC-26 |
- **목표:** 기한·주기가 있는 업무 규칙을 시스템이 빠짐없이 실행하고, 운영자가 실행 상태를 확인해 문제를 고칩니다.
- **사전조건:** Core API 내장 스케줄러가 실행 중입니다. 운영 화면은 운영자 권한이 필요합니다.
- **트리거:** 정기 작업의 실행 시점이 되거나, 운영자가 정기 작업 화면을 엽니다.

**기본 흐름**
1. 실행 시점이 되면 시스템이 해당 정기 작업을 시작하고 시작 시각을 기록합니다.
2. 시스템이 대상(예: 만료된 크레딧, 유예가 끝난 탈퇴 계정)을 찾아 규칙대로 처리합니다.
3. 시스템이 처리 건수, 성공·실패, 종료 시각을 기록합니다.
4. 운영자가 정기 작업 화면에서 작업별 마지막 실행 시각과 결과를 확인합니다.

**대안 흐름**
- A1 (4단계) 수동 재실행: 실패한 정기 작업을 운영자가 다시 실행합니다. 이미 처리된 대상은 다시 처리하지 않습니다.
- A2 (2단계) 처리할 대상 없음: 0건으로 기록하고 정상 종료합니다.

**예외 흐름**
- E1 (2단계) 일부 대상 처리 실패: 실패 대상을 기록하고 성공으로 표시하지 않습니다. 운영자에게 경고합니다(UC-21).
- E2 (1단계) 실행 시점에 실행되지 않음(서버 중단 등): 다음 기동 때 밀린 작업을 확인해 실행하고, 지연을 운영자에게 경고합니다.

- **성공 보장:** 기한·주기 규칙이 정해진 시점에 적용되고 실행 결과가 기록됩니다.
- **최소 보장:** 정기 작업 실패를 성공으로 기록하지 않습니다. 같은 대상을 두 번 처리해 크레딧을 두 번 소멸시키거나 데이터를 중복 삭제하지 않습니다. 사용자 AI 작업은 자동으로 다시 실행하지 않습니다(UC-21).
- **업무 규칙:** 정기 작업은 Core API 내장 스케줄러 하나로 실행하며 별도 worker·큐를 두지 않습니다(UC-18). 이 스케줄러는 새 실행 계층이므로 구현 전에 팀에 공유합니다. 데이터 삭제가 따르는 작업(탈퇴 처리·로그 정리)은 처리 기록을 남깁니다.
- **미정:** 작업별 실행 주기, 서버 여러 대로 늘릴 때의 중복 실행 방지, 시간대 기준.
