**기본 흐름**
1. 실행 시점이 되면 업무 소유 서비스가 해당 정기 작업을 시작하고 작업 종류, 예정 시각과 시작 시각을 기록합니다.
2. 시스템이 대상(예: 만료된 크레딧, 유예가 끝난 탈퇴 계정)을 찾아 규칙대로 처리합니다.
3. 시스템이 처리 건수, 성공·부분 실패·실패, 종료 시각과 실패한 대상·이유를 기록합니다. 재실행 결과는 이전 실행과 구분해 기록합니다.
4. 운영 서비스가 각 소유 서비스의 실행 결과로 감시 화면을 제공하고, 운영자가 작업별 마지막 실행 시각과 결과를 확인합니다. 감시 기록과 실제 업무 결과는 구분합니다.

**대안 흐름**
- A1 (4단계) 수동 재실행: 운영자가 실패한 정기 작업의 재실행을 소유 서비스에 요청합니다. 실제 실행·권한 재확인·중복 방지는 소유 서비스가 담당하며 이미 처리된 대상은 다시 처리하지 않습니다. 요청 접수만으로 재실행 성공을 표시하지 않습니다.
- A2 (2단계) 처리할 대상 없음: 0건으로 기록하고 정상 종료합니다.

**예외 흐름**
- E1 (2단계) 일부 대상 처리 실패: 실패 대상을 기록하고 성공으로 표시하지 않습니다. 운영자에게 경고합니다(UC-21).
- E2 (1단계) 실행 시점에 실행되지 않음(서버 중단 등): 다음 기동 때 밀린 작업을 확인해 실행하고, 지연을 운영자에게 경고합니다. 단, 자율 연재는 예정 시각에서 1시간 넘게 지났으면 실행하지 않고 건너뛴 뒤 소유자에게 알립니다(UC-18 E5). 예약 발행은 재기동 후 권한·권리 및 공개 조건을 다시 확인해 충족하면 늦게 발행하고 지연 결과를 소유자에게 알립니다. 조건을 충족하지 않으면 발행하지 않습니다(UC-13).

- **성공 보장:** 기한·주기 규칙이 정해진 시점에 적용되고 실행 결과가 기록됩니다.
- **최소 보장:** 정기 작업 실패를 성공으로 기록하지 않습니다. 같은 대상을 두 번 처리해 크레딧을 두 번 소멸시키거나 데이터를 중복 삭제하지 않습니다. 사용자 AI 작업은 자동으로 다시 실행하지 않습니다(UC-21).
- **업무 규칙:** 정기 실행·중복 방지·트랜잭션·복구는 업무 소유 서비스에 둡니다(DEC-41). 운영 서비스는 감시·재실행 요청만 관리하고 모든 서비스를 묶는 중앙 스케줄러·별도 worker·큐를 이 결정만으로 추가하지 않습니다. 데이터 삭제가 따르는 작업(탈퇴 처리·로그 정리)은 처리 기록을 남깁니다. 모든 일정·기한은 한국 시간(KST) 기준이며, 크레딧 월간 초기화는 매월 1일 00:00입니다.
- **미정:** 작업별 실행 주기, 서버 여러 대로 늘릴 때의 중복 실행 방지.
