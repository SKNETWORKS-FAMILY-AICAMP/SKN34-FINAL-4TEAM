# #673 원고 전처리 브라우저·실모델 검증

2026-11-24. 포크 브랜치 `perf/673-preprocessing-concurrency`의 `86b18b54`를 별도 WSL Docker 프로젝트 `storyfork-673-qa`에서 실행했다. Chrome 157에서 테스트 작가별로 작품을 만들어 공개 회차 탭의 일괄 업로드를 사용했다. 전처리 워커 로그에서 `prefork` 동시성 3을 확인했다. 작업당 추출 상한은 4이며, 모델은 `gpt-6-luna`다. 이 스택은 코드에 포함된 추출 프롬프트를 사용했다.

[PR #665의 기준 기록](https://github.com/SKNETWORKS-FAMILY-AICAMP/SKN34-FINAL-4TEAM/pull/665#issuecomment-7076316743)과 같은 [TimeChara 공개 청크](https://github.com/ahnjaewoo/timechara#running-evaluation-on-timechara)에서 해리 포터 1권 영문 1~8장을 복원했다. SQLite의 `start_index`로 청크를 정렬하고 겹치는 문자가 서로 일치하는지 확인했다. 청크에서 빠진 공백 83자리는 줄바꿈으로 채웠다. 1~8장은 201,290자, 1~2장은 44,974자다. 세 작품에는 각각 1~2장을 올렸다. #665 당시 파일의 해시는 공개 기록에 없어 바이트 일치는 확인할 수 없었다.

## 새 키로 다시 측정

브라우저가 일괄 업로드 POST를 보낸 순간부터 Content가 종료 상태를 반환할 때까지를 측정했다. 조회 간격은 400ms였다. 각 실행은 새 작품과 새 전처리 작업으로 시작했다.

| 시나리오 | 업로드 응답 | 종료 상태 확인 | 저장된 추출 결과 | 종료 상태 |
| --- | ---: | ---: | ---: | --- |
| S1 · 1작품 × 8회차, 첫 시도 | 2.40초 | 127.57초 | 0/8 | 실패 |
| S1 · 1작품 × 8회차, 재시도 | 2.32초 | 106.66초 | 4/8 | 실패(1~4화) |
| S1 · 1작품 × 8회차, 오류 진단 | 6.07초 | 117.03초 | 4/8 | 실패(1~4화) |
| S1 · 1작품 × 8회차, 재개 성공 후 새 작업 | 1.61초 | 124.35초 | 0/8 | 실패 |
| S2 · 작품 A × 2회차 | 1.08초 | 62.50초 | 2/2 | 완료 |
| S2 · 작품 B × 2회차 | 1.07초 | 41.47초 | 2/2 | 완료 |
| S2 · 작품 C × 2회차 | 1.18초 | 62.46초 | 2/2 | 완료 |

S2의 업로드 요청 시작 시각 차이는 8ms, 가장 빠른 작업과 가장 늦은 작업의 완료 시간 차이는 21.03초였다. 워커 로그에서 추출 6건과 정체 통합 3건이 모두 OpenAI HTTP 200을 받았다. Content에서 세 작품 모두 적재 영수증 2건씩을 확인했다. 가장 늦은 작업의 완료 시간은 #665 워커 동시성 1의 294초에서 62.50초로 78.7% 줄었고, 워커 동시성만 3인 S3의 127초와 비교하면 50.8% 줄었다. 같은 스택 안에서 대조군을 재실행한 수치는 아니다.

오류 진단 실행에서 1~4화의 모델 연결은 HTTP 응답을 받기 전에 끊겼고, 워커에서 `RemoteProtocolError`를 확인했다. 운영 재개 API로 같은 작업을 다시 돌렸을 때 저장 결과 4건을 유지했고, 누락된 1~4화를 저장한 뒤 재개 요청 기준 85.12초에 8/8회차와 초안 적재가 완료됐다. 이후 새로 업로드한 작업의 8회차에서도 모델 연결이 같은 오류로 끊겼다. 한 번의 업로드로 8회차를 완료한 사례가 없어 #665의 420초와 비교할 완료 시간은 미측정이다.

Chrome에서 S2 세 작품 모두 완료 문구, `추출 결과 저장 2 / 2화`, `세계관 초안 열기` 링크를 확인했다. S1 오류 진단 실행에서는 브라우저가 인증 서비스 응답 오류를 표시한 뒤 상태 자동 조회를 멈췄다. 표의 해당 종료 상태와 시간은 Content API 조회 결과이며, 재개는 격리 스택의 운영 API로 검증했다. 마지막 실행에서는 `작업 상태 다시 확인`을 누른 뒤 실패 안내와 `같은 작업 재개` 버튼이 표시됐다.

## 최초 키로 실행한 기록

브라우저가 일괄 업로드 POST를 보낸 순간부터 Content 작업 조회에서 종료 상태를 확인할 때까지 측정했다. 조회 간격은 400ms였다. 세 작품의 업로드 요청 시작 시각 차이는 20ms였다.

| 시나리오 | 업로드 응답 | 실행 중 확인 | 실패 확인 | 저장된 추출 결과 | OpenAI 429 |
| --- | ---: | ---: | ---: | ---: | ---: |
| S1 · 1작품 × 8회차 | 2.96초 | 4.14초 | 12.15초 | 0/8 | 8건 |
| S2 · 작품 A × 2회차 | 1.54초 | 4.16초 | 8.94초 | 0/2 | 2건 |
| S2 · 작품 B × 2회차 | 1.57초 | 3.36초 | 7.02초 | 0/2 | 2건 |
| S2 · 작품 C × 2회차 | 1.39초 | 1.81초 | 4.52초 | 0/2 | 2건 |

워커 로그에서 추출 요청 14건 모두 HTTP 429를 확인했다. 같은 키로 짧은 Responses 요청을 한 번 보내 확인한 제공사 오류는 `insufficient_quota` / `credit_balance_exhausted`였다. Content는 네 작업 모두 `AI_RESPONSE_UNCONFIRMED`로 기록했다. S2에서 가장 먼저 실패한 작품 C가 종료 상태가 되기 전에 A·B도 실행을 시작했다.

이 실행은 성공 건수가 0건이었다. #665의 완료 시간은 S1 420초, S2 106/189/294초, 워커 동시성만 3인 S3 99/109/127초다.

### 실패 상태의 Chrome 확인

- 네 작품 모두 업로드 화면에서 `세계관 추출을 시작했어요`를 표시했다.
- 공개 회차 탭의 `세계관 추출 중` 배지와 세계관·설정집 탭의 실행 상태 및 실제 저장 회차 수(`0 / 8화` 또는 `0 / 2화`)를 확인했다. 상태와 회차 수는 같은 `role="status"` 영역에 표시됐다.
- 실패 시 `분석이 멈췄어요`, 응답 미확인 안내 및 `같은 작업 재개` 버튼이 표시됐다.
