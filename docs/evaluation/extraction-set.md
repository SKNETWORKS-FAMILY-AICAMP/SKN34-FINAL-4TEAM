# 회차 설정 추출 평가 세트 (`extraction.extract`)

> 상태: **구현 완료**(2026-11-24, [#824](https://github.com/SKNETWORKS-FAMILY-AICAMP/SKN34-FINAL-4TEAM/issues/824)). 운영 LLMOps의 회귀 평가·후보 등록 게이트에서 `manuscript_extraction.extract` 지시문의 짝이다([계약](../design/operations-llmops-contract.md)).
> 코드: AI `app/evaluation/extraction.py`(생성·코드 채점), 정답표 빌더·CLI [`backend/ai-service/eval/extraction/`](../../backend/ai-service/eval/extraction/README.md). 상위 문서: [회차 원고 전처리 계약](../design/manuscript-preprocessing-contract.md).

## 1. 목적과 범위

회차 원고 전처리는 회차 한 편을 모델에 보내 **대상(mentions)·진술(statements)·관계(relationships)** 를 뽑고(`manuscript_extraction.extract` 지시문), 프로그램이 원문 인용을 글자 단위로 대조해 어긋난 항목만 뺀다(`skipped`).
이 세트는 그 지시문의 **새 버전이 기준 버전보다 나빠지지 않았는지** 운영 화면에서 평가하고 후보로 올릴 수 있게 한다.

- **채점은 모델이 아니라 코드다.** 정답표(상위 모델이 두 번 뽑은 결과)와 대조해 재현율·인용 통과율을 센다. 채점 모델 호출·채점 잡음이 없고 같은 입력·같은 출력이면 점수가 같다.
- 범위는 세트·코드 채점·게이트(`extraction.extract` ↔ `manuscript_extraction.extract`)까지다. 지시문 자동 개선(GEPA)은 이 세트를 게이트로 쓰는 별도 작업이며 이 문서의 범위가 아니다.
- 같은 원문·같은 모델 호출로 돌리는 **실제 서비스 호출**이다: `manuscript_extraction.agent.extract`에 평가 대상 버전의 본문(`instructions`)·모델(`model`)을 그대로 주고(production 버전을 읽지 않는다) 결과를 서비스와 같은 검증(`service._validate`)에 통과시킨다.

## 2. 두 세트

| 세트 | 원천 | 둘 곳 | Langfuse | 용도 |
|---|---|---|---|---|
| **게이트 세트** `extraction.extract` | 저작권 만료 근대 한국 소설(위키문헌 `{{PD-old-NN}}`) | `app/evaluation/datasets/extraction.extract.jsonl`(저장소) | `python -m app.evaluation.seed`가 Dataset으로 등록 | 운영 회귀 평가·후보 등록 게이트 |
| **해리 포터 로컬 세트** | 해리 포터 번역본(저작권 있음) | `eval/extraction/.data/`(`.gitignore`, **저장소·Langfuse에 두지 않는다**) | 올리지 않는다 | 로컬 오프라인 평가 전용(CLI `score`) |

- 게이트 짝 상수(운영 `PromptService`)와 계약 문서는 **저장소에 있는 공개 세트**만 가리킨다. Langfuse는 환경(로컬·dev·prod)마다 따로이고 게이트 짝은 코드 상수라, 세트가 없는 환경에서는 그 프롬프트가 영구 409가 된다. 공개 세트는 `ai-eval-seed`가 compose를 올릴 때마다 등록한다.
- 해리 포터 원문·정답표·항목은 `.data/` 밖에 쓰지 않는다. 문서·`results/`에는 집계 수치만 둔다.

## 3. 항목 모양

한 줄이 회차 한 편이다(`id`·`input`·`expectedOutput`·`metadata`, 다른 세트와 같다).

- `input` = 운영이 모델에 보내는 값 그대로 `{number, title, body}`(`EpisodeText`). 회차 크기는 5,500자 안팎이다(운영 회차 5천~8천 자 중 호출 한도(읽기 70초·출력 16,000토큰) 안에 드는 크기. 장 하나가 평균 1.9만 자인 해리 포터도 이 크기로 자른다).
- `expectedOutput` = **정답표** `{mentions, statements, relationships}`. 항목마다 `core`(두 번 모두 뽑은 것)가 있다.
  - `mentions[]`: `{name, kind, aliases[], core}` — `aliases`는 두 번 중 다른 쪽이 쓴 호칭이다.
  - `statements[]`: `{kind, quote, core}` — `quote`는 원문의 한 문장이다(원문에 정확히 한 번 있다).
  - `relationships[]`: `{source, target, label, core}` — 끝점은 `mentions[].name`이다.
- `metadata` = `{license, source{work, author, origin, license, episode}, gold{model, runs, agreement}}`. `agreement`는 두 번의 일치도(종류별 `core ÷ 합집합`)라 정답표를 얼마나 믿을지 보여 준다.

## 4. 정답표 만드는 법

1. 원문을 회차 크기(5,500자 안팎)로 자른다(근대 소설은 문단을 묶어 작품별로 같은 크기의 회차로, 해리 포터는 장 덩어리를 줄 경계에서 5,500자 이하 조각으로 잘라 권마다 고르게 뽑는다). 위키문헌의 틀·태그·장식 줄은 걷는다.
2. 상위 모델(**ocx `gpt-6.2-sol`**, 금액 0)로 **운영 프롬프트와 다른 지시문 두 가지(A·B)** 로 회차마다 두 번 뽑는다(`eval/extraction/ex_gold.py`). 출력 틀은 운영과 같은 `ProposedExtraction`이다.
   A는 설정집 편집자, B는 독자 질문 관점으로 쓴 서로 다른 글이다(운영 지시문을 베끼지 않는다. 운영 검증 규칙은 같아서 규칙 문구는 같은 뜻으로 다시 썼다).
3. 두 결과를 각각 **서비스와 같은 검증(`service.extract`, 원문 인용 대조 포함)** 에 통과시키고 통과한 항목만 남긴다. 인용 대조가 정답표에도 공짜로 걸린다.
4. 합친다. `core` = 두 번 모두 뽑은 항목(교집합), 한 번만 뽑은 항목은 `core: false`(합집합에만 든다).
   - 대상: 종류가 같고 호칭이 같거나 포함될 때 같은 대상이다(호칭 규칙은 5.1절). 호칭이 다른 쪽은 `aliases`에 남는다.
   - 진술: 인용 위치가 겹치면 같은 진술이다(5.1절).
   - 관계: 끝점 두 대상이 같으면(방향 무관) 같은 관계다. 방향·라벨은 합칠 때 보지 않는다.
5. 대상이 하나도 `core`가 아닌 회차는 항목으로 만들지 않는다(정답이 없다). 같은 (지시문·모델·회차)의 응답은 디스크 캐시라 같은 명령을 다시 치면 부르지 않는다.
   검증에서 대상 하나가 떨어지면 그 대상을 가리키던 진술이 줄줄이 빠지는데(`UNKNOWN_ENTITY` 연쇄, 운영 검증기와 같은 동작) 두 실행(봄봄 1화 A·2화 B)이 18~21개씩 잃어 그 두 실행만 한 번 다시 뽑았다.

## 5. 코드 채점

### 5.1 맞추는 규칙

모든 규칙은 `app/evaluation/extraction.py` 한 곳이다(정답표 합치기·운영 채점·오프라인 CLI가 같은 함수를 쓴다).

- **호칭 일치**: 공백·문장부호를 없애고 소문자로 접은(NFKC) 두 호칭이 같거나, 짧은 쪽이 두 글자 이상이고 긴 쪽에 들어 있으면 같은 호칭이다(`김 첨지`=`김첨지`=`첨지`, `점순`⊂`점순이`). 별칭(`aliases`)은 모두 후보다.
- **대상 일치**: 정답 대상의 호칭·별칭 중 하나가 추출 대상의 호칭과 일치하면 맞춘 것이다. **종류는 보지 않는다**(종류 일치는 따로 잰다).
- **진술 일치**: 두 인용이 원문에서 겹치는 글자 수가 짧은 쪽의 절반 이상이면 같은 진술이다(인용은 한 문장이라 위치 겹침으로 판정한다. 진술의 종류·대상은 보지 않는다).
- **관계 일치**: 끝점 두 대상이 각각 일치하면(어느 방향이든) 맞춘 것이다.

### 5.2 지표

| 지표 | 정의 | 게이트 |
|---|---|---|
| `recall`(재현율) | **`core` 정답**(두 번 모두 뽑은 것) 중 추출이 맞춘 비율. 대상·진술·관계마다 구한 뒤 `core`가 있는 종류의 **평균**(한 종류가 값을 지배하지 않게) | **예**(`Run` 평균, 기준 − 허용 오차) |
| `quote_ok`(인용 통과율) | 통과 항목 ÷ (통과 항목 + `skipped` 건수): 모델이 낸 항목 중 원문 대조·참조·시점 검증을 통과해 남은 비율(통과 항목은 대상·진술·관계 수). 아무것도 안 냈으면 1 | **예** |
| 정밀도 | 추출 항목 중 **합집합** 정답(`core` 아닌 것 포함)과 맞는 비율. 종류별 | 참고 |
| 종류 일치 | 맞춘 대상 중 종류까지 같은 비율 | 참고 |
| 관계 방향 | 맞춘 관계 중 방향(source→target)이 같은 비율 | 참고 |
| 관계 라벨 | 맞춘 관계 중 라벨이 같거나 포함되는 비율(자유 글이라 호칭 일치 규칙을 쓴다) | 참고 |

- **재현율은 교집합, 정밀도는 합집합 기준**이다. 교집합은 쉬운 항목에 치우치지만 두 번 모두 뽑을 만큼 확실한 것만 들어 "빠뜨리면 안 되는 것"의 하한이다. 합집합은 정답표가 놓친 합당한 항목을 벌주지 않는 쪽의 상한이다.
- 진술은 "남길 만한 것만·30개 이하" 규칙이라 선택이 주관적이어서 정밀도를 게이트에 올리지 않는다. 항목마다 Run에는 `recall`·`quote_ok` 둘만 점수로 남고 참고 지표는 `recall` 점수의 `metadata`와 CLI 출력에 있다.
- 점수는 모두 0~1이고 높을수록 좋다(다른 세트와 같은 눈금이라 기준 Run 비교·허용 오차 `EVAL_TOLERANCE`를 그대로 쓴다).
- 모델·검증 오류(`PreprocessingFailure`: 시간 초과·잘린 출력·검증된 대상 0개 등)는 0점이 아니라 **점수 없는 항목 실패**이고 `passed`는 false다(다른 세트와 같다).

### 5.3 게이트

운영은 평가 세트가 있는 프롬프트만 짝을 둔다(`PromptService` 상수): `manuscript_extraction.extract` ↔ `extraction.extract`. 이 프롬프트의 새 버전은 **그 세트로 돌린 가장 최근 Run의 `passed`가 true**여야 후보로 등록된다(409 `EVALUATION_REQUIRED`).
`passed` = 실패 항목 없음 + 두 지표가 기준 Run(현재 production 버전의 가장 최근 Run) 평균 − 허용 오차 이상. 기준 Run이 없으면 지표를 비교하지 않으므로 **새 버전을 평가하기 전에 production 버전부터 한 번 평가**한다.
짝이 아닌 지시문으로 이 세트를 돌리면 422다(`service.prepare`). 평가 한 번은 운영 모델 호출이 항목 수(11)번이고 채점 모델 호출은 없다.

## 6. 명령

`backend/ai-service`에서 실행한다. 정답표 만들기는 ocx 게이트웨이(`http://127.0.0.1:10100/v1`)가 켜져 있어야 하고 OpenAI 키를 쓰지 않는다(금액 0). `ex_cli.py`는 시작 때 Langfuse 키를 지워 원문이 Langfuse로 가지 않게 한다.

```bash
# ① 게이트 세트: 공개 작품 정답표 → .data/sets/public.jsonl → 저장소 세트 파일
uv run --locked --extra dev python eval/extraction/ex_cli.py gold --source public [--raw-dir <위키문헌 원문 폴더>] [--workers 4] [--limit N]
uv run --locked --extra dev python eval/extraction/ex_cli.py export
# ② 로컬 해리 포터 세트(커밋·Langfuse 금지): 원문 폴더는 --hp-dir(기본 eval/simulation/.data/hp)
uv run --locked --extra dev python eval/extraction/ex_cli.py gold --source hp --hp-dir <.data/hp 폴더> --per-book 2
# ③ 오프라인 채점: 운영 지시문(코드 시드 또는 --instructions 파일)을 운영 모델로 돌려 채점한다(유료 OpenAI 호출: 사용자가 키 파일을 불러온 뒤)
uv run --locked --extra dev python eval/extraction/ex_cli.py score eval/extraction/.data/sets/hp.jsonl [--instructions 파일] [--model 모델] [--tag 태그] [--limit N]
```

## 7. 한계

- **정답표는 모델 두 번이라 사람 검수 전이다.** 대상·관계의 교집합은 믿을 만하지만 진술은 두 번의 선택이 갈려 `core`가 작다(8.1절 일치도). 사람이 고르려면 `.data/gold/`의 두 결과와 `metadata.gold.agreement`를 본다.
- **호칭 포함 규칙은 휴리스틱이다**(두 글자 이상 포함). 흔한 낱말이 이름인 작품에서는 잘못 맞출 수 있다. 정밀도가 합집합 기준인 것과 같은 이유로 게이트는 재현율 하락만 잡는다.
- **회차 11편은 작다.** 회차마다 재현율이 0.5~1.0으로 갈려(8.2절 표준편차 0.12~0.14) 항목 하나가 평균을 최대 약 9%포인트(1/11) 움직이고, 관계 `core`는 28개뿐이라 관계 재현율은 회차 단위로 거칠다. 회차를 늘리는 비용은 선형이다(회차당 상위 모델 2회, 8.1절 시간).
- **근대 소설은 웹소설 원고와 결이 다르다**(대사·내면 서술이 많고 설정이 적다). 같은 빌더가 다른 공개 작품·로컬 원문도 같은 모양으로 만든다.
- 평가는 같은 입력에도 모델 출력이 달라 `recall`이 흔들린다(채점 잡음은 없고 생성 잡음만 있다).

## 8. 구성과 측정 (2026-11-24)

### 8.1 게이트 세트 구성

공개 작품 5편 11회차(4,846~6,202자, 평균 5,606자)다. 정답표는 ocx `gpt-6.2-sol` 22회(회차 11 × 지시문 2)로 만들었고 병렬 4로 8분(재추출 2회는 1.5분 더), 금액 0이다.

| 작품(저자) | 회차 수 | 회차 글자 수 |
|---|---:|---|
| 운수 좋은 날(현진건) | 2 | 5,273 · 4,846 |
| 술 권하는 사회(현진건) | 2 | 5,249 · 5,229 |
| 감자(김동인) | 1 | 6,202 |
| 봄봄(김유정) | 2 | 5,582 · 5,566 |
| 레디메이드 인생(채만식) | 4 | 5,917 · 5,951 · 5,939 · 5,908 |

| 정답표 | 대상 | 진술 | 관계 |
|---|---:|---:|---:|
| 실행 A(편집자 지시문) 검증 통과 | 122 | 285 | 38 |
| 실행 B(독자 질문 지시문) 검증 통과 | 193 | 308 | 57 |
| 합집합(정밀도 기준) | 203 | 383 | 67 |
| `core`(두 번 모두, 재현율 기준) | 112 | 210 | 28 |
| 회차별 일치도 평균(`core` ÷ 합집합) | 0.55 | 0.56 | 0.48 |

- 두 지시문은 뽑는 양이 다르다: B가 대상 1.6배·관계 1.5배다(A는 설정집에 실을 것만, B는 독자 질문의 근거가 될 것을 빠짐없이). 그래서 `core`는 A의 대부분과 B의 일부다.
- 서비스 검증이 뺀 항목은 A 14건·B 21건이다(통과 항목 대비 3~4%, 인용 통과율 0.97·0.96).
- 관계 `core`는 회차마다 0~6개(한 회차는 0개)다. 재현율은 `core`가 있는 종류만 평균하므로 그 회차는 관계를 뺀 평균이 된다.

### 8.2 정답표끼리 서로 채점한 참고치

두 실행 중 하나를 후보로, 다른 쪽 **한 실행 전체**를 정답표(전부 `core`)로 삼아 `score`를 돌렸다(추가 호출 없음). 게이트의 정답표는 교집합이라 두 실행 모두 재현율 1이므로, 이 표는 "좋은 모델 두 번의 결과가 서로를 얼마나 맞추는가"의 눈금이다.

| 후보 → 정답표 | `recall` | 대상 | 진술 | 관계 |
|---|---:|---:|---:|---:|
| A → B | 0.63 | 0.60 | 0.70 | 0.57 |
| B → A | 0.82 | 0.94 | 0.75 | 0.78 |

- 회차별 `recall` 표준편차는 0.12(A → B)·0.14(B → A)다. A → B의 참고 지표는 종류 일치 0.98, 관계 방향 0.92, 관계 라벨 0.70, 정밀도(대상·진술·관계) 0.94·0.75·0.78이다.
- 지시문 둘이 뽑는 양이 달라 두 방향이 비대칭이다(많이 뽑는 B가 A의 정답은 잘 맞춘다). **절대값이 아니라 기준 Run과의 차이로 읽는다**(게이트가 하는 일).
- 운영 지시문(`manuscript_extraction.extract`)과 운영 모델(`gpt-6-luna`)의 점수는 **아직 재지 않았다**: OpenAI 유료 호출이라 이 작업에서는 돌리지 않았다. 처음 평가한 Run이 기준 Run이 된다.

### 8.3 해리 포터 로컬 세트 (집계만)

번역본 7권에서 권마다 장 덩어리 조각 2개(14회차, 5,260~5,498자, 평균 5,457자)를 같은 방법으로 뽑았다(ocx 28회, 병렬 4로 10.6분, 금액 0). 원문·정답표는 `.data/`에만 있고 저장소·Langfuse에 없다.

| 정답표 | 대상 | 진술 | 관계 |
|---|---:|---:|---:|
| 실행 A 검증 통과 | 232 | 295 | 61 |
| 실행 B 검증 통과 | 275 | 344 | 81 |
| 합집합 | 286 | 413 | 90 |
| `core` | 221 | 226 | 52 |
| 회차별 일치도 평균 | 0.75 | 0.54 | 0.54 |

- 고유명사가 많은 소설이라 대상 일치도가 근대 소설(0.55)보다 높다(0.75). 서비스 검증이 뺀 항목은 A 36건·B 19건이다. 관계 `core`가 없는 회차가 1편이다.
- 정답표끼리 서로 채점한 `recall`은 A → B 0.72, B → A 0.86이다(8.2절과 같은 방법).
- 운영 지시문의 오프라인 채점(`ex_cli.py score`)은 유료 OpenAI 호출이라 실행하지 않았다.
