## 1. 목적

인물 시뮬레이션은 턴 하나에 모델 호출을 차례로 3~8번 기다린다(연출 결정 Decisions 1~2회 → 대사·나레이션 생성 1회 → 검사 1회, 위반 시 생성·검사 최대 2회 반복). 대화 모드에서는 resume 요청마다 세계관도 다시 읽는다
(`world_studio_list` + `world_studio_read` 2회 + 원고 발췌 검색). **모델은 `gpt-6-luna`로 고정**하고(사용자 결정 2026-11-20), 대기 시간을 줄이는 설정이 품질을 얼마나 해치는지 지표로 재서 기본 설정을 정한다.
채택 설정과 그 근거는 결과가 나온 뒤 6장에 적는다.

## 2. 설정 A~E

설정은 환경 변수 스위치의 누적 조합이다. 기본값은 모두 꺼짐(지금 동작)이고 스위치는 호출 때 읽는다.

| 설정 | 환경 변수 | 뜻 |
|---|---|---|
| A | (없음) | **현재 동작.** 비교 기준 |
| B | `SIMULATION_REASONING_EFFORT=low` | 계획·인물 턴·나레이션·검사 호출에 `reasoning.effort=low` |
| C | B + `SIMULATION_SKIP_FORCED_DIRECTOR=1` | 규칙이 정한 턴(시작·메모·비트 전환·마무리, 대사 아님)은 연출 모델을 부르지 않는다. 시점은 직전 턴 시점(없으면 전지적) |
| D | C + `SIMULATION_WORLD_CACHE=1` | 목록의 `draftRevision`이 같으면 세계관 읽기를 프로세스 안에서 재사용한다. **성적표에서는 Content를 부르지 않아 효과가 0**이다(C와 같은 실행으로 기록) |
| E | D + `SIMULATION_SKIP_NARRATION_CHECK=1` | 전지적 나레이션은 검사 모델을 부르지 않는다(서버 규칙 검사는 유지) |

두 스위트가 같은 경로를 지나는 설정은 한 번만 돌리고 결과를 재사용한다(`ranAs`): **품질**은 인물 대사 턴만 지나 추론 강도만 닿으므로 **C·D·E는 B와 같다**. **속도**는 **D가 C와 같다**.
세계관 캐시의 실제 효과(Content 호출 2~3회와 원고 발췌 검색 대신 목록 1회)는 이 성적표 밖이며, 단위 테스트가 호출 수로 보증한다.

## 3. 지표

### 3.1 품질(`quality`): TimeChara 검증 세트

- **표본:** 검증 600건에서 유형(future·past-only·past-absence·past-presence)마다 50개, 시드 642로 고정(`prepare`가 `.data/sample.json`에 질문 번호를 남긴다). 200문항.
- **입력:** 질문을 *그 시점 인물에게 인터뷰어가 묻는 장면 한 줄*로 바꾼다(IF 전제는 고정 문장, 참여 인물은 그 인물 한 명, 시점은 `limited:<인물>`). 세계관은 `eval/novelbrain`과 같이 `timechara.build_world`(그 시리즈의 사실 사건 전부)로 만들고 `snapshot`을 인물의 기준 장으로 자른다. **원고 발췌 없이 카드·관계만** 입력이다(소설 청크를 쓰지 않는다).
- **경로:** 운영 인물 턴 그대로 `service.character_view` → `agent.act` → 서버 규칙(`_problem`) → `agent.check`(`service.verify`) → 위반이면 고정 안내로 다시 쓴다(최대 2번). 장면 에이전트의 도구·검사 미들웨어를 한 턴만 돌릴 수 없어 같은 함수를 같은 순서로 부르는 얇은 루프다.
- **채점:** [공개 TimeChara 기준](novelbrain.md)(`run_timechara.judge_spatiotemporal·judge_personality`)을 그대로 쓴다: future·past-only는 시간(0/1), absence·presence는 공간(먼저)×시간, 성격 1~7. 채점 모델은 `cost.MODEL`로 고정이다.

| 지표 | 정의 |
|---|---|
| 시공간 일관성(최종) | 사용자가 보게 될 응답(재생성 뒤 마지막 시도)의 유형별 평균(Wilson 95% 구간)과 공개 유형 비중(1/3·1/3·1/6·1/6)의 가중 평균. 채점하지 못한 응답은 평균에서 뺀다 |
| 시공간 일관성(첫 응답) | 검사 전 첫 응답의 같은 값. 검사·재생성이 얼마나 올렸는지 본다 |
| 성격 일관성 | 1~7 평균(성격 설명이 있는 인물만) |
| 검사 위반률 | 첫 응답을 서버 규칙·검사 모델이 위반으로 본 비율 |
| 누설 적발률 | 심판이 누설(시공간 0)로 본 첫 응답 중 우리 검사가 위반으로 걸렀던 비율. `leakRate`는 그중 `knowledge_leak` 항목으로 건 비율 |
| 오경보율 | 심판이 맞다(시공간 1)고 본 첫 응답 중 검사가 걸렀던 비율(맞는 답을 막는 대가) |
| 멈춤 비율·평균 재생성 | 세 번 모두 위반이라 턴이 멈춘 비율, 질문당 재생성 횟수 평균 |
| 짝 비교 | 같은 질문에서 B와 A의 최종 시공간 점수를 짝지은 정확 부호 검정(`B|A`) |

### 3.2 속도(`speed`): 고정 장면 10개

- **장면:** 같은 TimeChara 세계관(해리 포터)의 8개(IF 4·흐름 4, 1~5권 끝을 기준 회차로, 인물 2~3명)와 [홍길동전 시연 세계관](../../infrastructure/sample-data/simulation-demo/honggildong/README.md)의 2개(5화 장면 계획 앞의 둘을 비트로 쓴 흐름과 같은 시점의 IF). 목록은 `sim_worlds.SCENES`다.
- **실행:** `scene_agent.build_scene_agent(pausing=False)`로 장면이 끝나거나 멈출 때까지(운영 오케스트레이션과 같이 `SceneContext(loaded=World)`·`UsageLedger`) 돈다. 시점은 연출 모델이 고른다(장면마다 인물 구성이 달라 시점이 섞인다). 장면은 순서대로 돈다.

| 지표 | 정의 |
|---|---|
| 턴 p50·p95 ms | `UsageLedger`가 턴(단계)마다 남긴 모델 호출 시간의 합의 백분위. `벽시계`는 턴이 끝난 시각 사이(recall 같은 계산 포함)다 |
| 호출 수/턴 | 턴당 모델 호출 수와 종류별(`director`·`act`·`narrate`·`check`) 평균 |
| 토큰/턴 | 턴당 입력·출력 토큰 평균 |
| $/장면 | 호출별 토큰을 `cost.py` 단가로 곱한 장면당 금액. 연출 Decisions 응답이 토큰을 안 주면 0으로 세고 `unpricedCalls`로 센다 |
| 한 번에 통과율·평균 재생성 | 턴 중 `regenerated == 0`인 비율, 턴당 재생성 평균 |
| 장면 결말 | 장면 중 `completed`·`stopped:<stopReason>`(check_failed·turn_limit·beat_rejected·call_limit)·`failed`의 비율 |

## 4. 데이터와 권리

- TimeChara 검증 세트는 **CC BY-NC 4.0, 비상업 연구 한정**이고 HuggingFace gated(로그인·약관 동의)다. 코드·공개 채점 프롬프트는 MIT([`ahnjaewoo/timechara@c0032b88`](https://github.com/ahnjaewoo/timechara/tree/c0032b88a869b163035c71cb602ef5e5bb8c00d0)).
- 해리 포터 등 소설의 원문·질문·응답·세계관은 **`eval/simulation/.data`에만** 둔다(git 무시). 저장소와 이 문서에는 집계(점수·횟수·시간·토큰)만 있다.
- `run`은 Langfuse 키를 지운다: 질문·응답 본문이 팀 Langfuse(추적)에 남지 않는다.
- 한국어 세계관은 위키문헌(저작권 만료) 원문을 근거로 한 저장소의 시연 데이터다.
- 해리 포터 번역본 원문·장 나눈 글·모델이 뽑은 카드(`world.json`)·표본(`preview.md`)도 **`eval/simulation/.data/hp`에만** 둔다(git 무시). 저장소에는 코드와 집계만 있다. 로컬 스택에 적재한 작품도 로컬 전용이고 원고가 없다(§8).

## 5. 재현

```bash
cd backend/ai-service
uv run --locked --extra dev python eval/simulation/sim_cli.py prepare    # 내려받기·표본 고정(호출 없음, HuggingFace 로그인 필요)
uv run --locked --extra dev python eval/simulation/sim_cli.py estimate   # 예상 호출 수·금액(호출 없음)
set -a; . <저장소 루트 .env>; set +a                                        # OPENAI_API_KEY·OPENAI_MODEL=gpt-6-luna
uv run --locked --extra dev python eval/simulation/sim_cli.py run --suite quality --configs A,B,C,D,E --limit-usd 10   # 비용 승인 뒤에만
uv run --locked --extra dev python eval/simulation/sim_cli.py run --suite speed --configs A,B,C,D,E --limit-usd 10
uv run --locked --extra dev python eval/simulation/sim_cli.py report
```

실행 전 예상 금액과 상한: `estimate`는 설정·표본별 예상 호출 수와 금액을 호출 없이 출력하고, `run`은 시작 전에 같은 표를 출력해 예상 합계가 `--limit-usd`를 넘으면 호출 없이 멈춘다. 시작한 뒤에는 `.data/cost.jsonl` 장부의 누적 합계로 막는다: 품질은 새 질문을 '장부 + 동시 수 × 질문당 최대 금액'이 상한 안일 때만 시작하고(진행 중인 질문의 비용은 끝나야 장부에 남는다), 속도는 장면 하나의 여유(0.50달러)가 남을 때만 시작한다(끝낸 것은 `.data/runs`에 남아 이어 받는다).
`prepare` 전에는 입력 크기를 가정값(act 8,000·check 20,000토큰)으로 센다: 그 값으로 품질 A·B가 약 6달러, 속도 A·B·C·E가 약 4달러(출력을 호출당 상한 1,500토큰으로 센 상한에 가까운 값)다. 실제 입력 크기는 `prepare` 뒤 `estimate`가 잰다.

**구독 경로(`--via ocx`, 기본 `openai`):** OpenAI 금액 상한(장부 누적 $18)에 닿으면 `build-hp`·`run --suite quality`는 멈추고 같은 명령 뒤에 `--via ocx`를 붙여 이어 받는 방법을 안내한다(끝낸 호출·문항은 캐시·결과 파일에서 이어 받는다).
ocx는 로컬 OpenCodex 게이트웨이(`http://127.0.0.1:10100/v1`, 구독 경로, 모델 `gpt-6-luna`)다. 이 프로세스의 `OPENAI_BASE_URL`·키만 바꾸고(키는 아무 문자열) `sim_via.py`의 얇은 어댑터가 Responses `create`/`parse`의 문자열 input을 메시지 목록으로 바꾸고 `store=False`를 강제한다(게이트웨이의 parse가 그때만 된다). 운영 `app/**`은 고치지 않는다.
**한계:** ① `--suite speed`는 거절한다(`/v1/decisions`가 게이트웨이에 없고 지연이 OpenAI API와 달라 속도 비교가 깨진다) ② ocx 호출은 장부에 금액 0·`via: ocx`로 남아 OpenAI 합계·상한에서 빠진다 ③ 채점 모델 `gpt-5.6-luna`는 게이트웨이에 없어 ocx에서는 `gpt-6-luna`로 바뀐다 ④ 품질 결과의 문항 기록에 `via`가 남고 `report`가 설정마다 문항 수를 보인다: openai·ocx가 섞인 결과는 생성·채점 모델이 섞인 것이다 ⑤ 429·구독 한도는 지수 대기(합계 10분 안) 뒤 다시 시도하고 계속 실패하면 멈춘다.

**단가:** `eval/novelbrain/cost.py`의 gpt-5.6-luna 값(입력 $0.20·캐시 입력 $0.02·출력 $1.20 / 100만 토큰)을 쓴다. `gpt-6-luna`의 OpenAI 공식 단가는 확인하지 못했다(제3자 가격 사이트는 입력 $0.10·출력 $0.50으로 적지만 공식 페이지로 확인하지 못했다). 이 값이 맞다면 장부·예상 금액은 실제보다 높게(안전하게) 잡힌 것이다.

## 7. 읽는 법과 한계

- 표본 200문항에서 유형별 한 점대의 차이는 잡음일 수 있다(Wilson 구간·짝 부호 검정으로만 '올랐다·내렸다'를 말한다). 속도의 p95는 장면 10개의 턴 수십 개로 센 값이다.
- 품질 입력은 원고 발췌가 없고(카드·관계만), 인물 카드의 SOUL·GOAL이 비어 있다(TimeChara 사건 요약뿐). 절대 점수는 [NovelBrain 평가](novelbrain.md)의 TimeChara 점수와 같은 구도가 아니며 **설정 사이의 상대 비교**로 읽는다.
- 품질은 인물 대사 턴만 잰다. 전지적 나레이션 검사 생략(E)이 나레이션의 미래 누설을 얼마나 늘리는지는 이 성적표의 질문으로는 보이지 않는다(E의 품질 영향은 별도 평가가 필요하다).
- 추론 강도가 클수록 `max_output_tokens`(생성·검사 1,500) 안에서 추론 토큰이 늘어 응답이 잘려 502가 날 수 있다. 낮은 강도(B)에서는 이 위험이 줄지만 `high`를 쓰면 상한부터 다시 본다.
- 계획(`agent.plan`) 호출에도 같은 추론 강도가 적용된다(`_parse` 공통). 성적표는 계획 호출을 재지 않는다.
- 해리 포터 8개 장면의 인물 이름·비트는 TimeChara 데이터의 이름과 맞춰 있어야 하며, 맞지 않으면 `estimate`·`run`이 짐작하지 않고 멈춘다(`prepare` 뒤 첫 `estimate`가 확인).

## 8. 원문 기반 세계관(해리 포터)

TimeChara 행으로 만든 얇은 세계관은 사건 요약뿐이라 인물 문서(SOUL·GOAL)·회차별 기억·장소·조직이 없다. 제품이 읽는 것과 같은 모양의 세계관으로 재려고, 해리 포터 번역본 원문(7권, 한국어)에서
시연 세계관([`simulation-demo`](../../infrastructure/sample-data/simulation-demo/README.md))과 같은 형식의 `world.json` 하나를 만든다. 질문 150개 전부와 해리 포터 장면 8개가 이 세계관을 읽는다(`--world hp`). 홍길동 장면 2개와 `--world thin`(기본)은 그대로다.

```bash
# 원문(번역본 txt 22개)을 .data/hp/raw/<권 폴더>/*.txt에 푼다(저장소 밖). 아래는 backend/ai-service에서
uv run --locked --extra dev python eval/simulation/sim_cli.py estimate --world hp   # build + 품질 + 속도 예상(호출 없음)
set -a; . <저장소 루트 .env>; set +a
uv run --locked --extra dev python eval/simulation/sim_cli.py build-hp --limit-usd 18   # 장 나누기 → 추출 → 정체 정리 → 인물 IDENTITY → SOUL·GOAL → .data/hp/world.json
uv run --locked --extra dev python eval/simulation/sim_cli.py show-hp                   # .data/hp/preview.md(호출 없음)
STORYFORK_SEED_PASSWORD=<개발 작가 비밀번호> uv run --locked --extra dev python eval/simulation/sim_cli.py seed-hp   # 로컬 스택에 배치 적재·다시 실행하면 world.json과 같게 맞춤(호출 없음, localhost만)
uv run --locked --extra dev python eval/simulation/sim_cli.py run --suite quality --world hp --configs A,B --limit-usd 10   # 비용 승인 뒤에만
```

### 8.1 만드는 법

1. **장 나누기**(`hp_chapters.py`): 파일마다 장 머리 형식이 다르다(제N장·Chapter N·N장·N。제목)고 목차가 붙은 곳도 있어, 머리 후보 수집 → 가까이 붙은 번호 줄(목차) 제외 → 장 번호가 이어지는 가장 긴 열 선택 → 빠진 장은 목차 제목과 비슷한(0.8) 줄을 앞뒤 머리 사이에서 찾기 순서로 나눈다.
   회차는 7권의 모든 장을 이어 붙인 번호(1권 1장 = 1화, 7권 에필로그는 37장)이고 장 → 회차 대응표(`ordinals`)를 `world.json`에 같이 둔다. TimeChara의 `BookK-chapterN`·`cutoff`는 이 표로 회차가 된다(장 0은 앞 권의 끝).
2. **추출**(`hp_build.py`): 덩어리(장 하나 또는 묶인 장들)마다 모델 한 번(gpt-5.6-luna, 구조화 출력, 한국어, 원문 인용 없음): 사건(제목·요약·참석자)·인물(별칭·묘사·원하는 것·그 장에서 겪은 일)·설정(장소·조직·마법 물건·주문·규칙)·관계.
3. **정체 정리**: 인물 호칭을 영어 정식 이름(TimeChara 철자)으로 묶는다. 같은 영어 이름이면 한 사람이고, 이름-별칭 연결은 영어 이름이 부딪치지 않고 별칭의 주인이 하나일 때만 이어 준다. 이름이 비슷하거나 성이 같다는 이유로는 합치지 않는다(웨즐리 부인·씨).
4. **인물 문서**: IDENTITY는 처음 나온 대목만으로 모델 한 번(첫 등장 규칙). SOUL·GOAL은 원문 전체에서 모은 성격·말투·바람 기록(처지·그 장의 일은 후반 정보를 싣기 쉬워 주지 않는다)으로 모델이 한 번 다시 쓴다(`hp_traits.py`): 작가가 인물 설정을 쓰듯 이야기 내내 변하지 않는 말투·성격·가치관·습관·대표적 욕구만이다.
   `episodes[N]`은 그 장에서 겪은 일을 추출 결과 그대로 쓴다.
5. **조립**: 카드(인물·장소·조직·능력·물건·규칙·사건)와 회차별 관계(DEC-51)를 `seed.py`가 읽는 모양으로 쓴다. 설정 카드의 영역·분류는 장소=시공간, 조직=사회, 물건=문화·기술, 능력·규칙=특수 규칙이다.

### 8.2 누설 방지 규칙(제품 규칙 그대로)

- IDENTITY·별칭·설정 카드 본문은 인물·카드가 보이는 순간부터 늘 보이므로 **처음 나온 대목에서 이미 드러난 것만** 모델에 준다(`DOC_UNITS = 1`). 영어 이름은 문서 요청에 싣지 않는다(모델의 사전 지식을 끌어오지 않게).
  나중에 드러나는 것(정체·변화·비밀)은 그 회차의 `episodes[N]`·관계·사건 카드(`revealFromEpisode` = 그 장)에만 둔다.
- SOUL·GOAL도 늘 보이지만 '사람됨'이라 이야기 내내 한결같은 면만 쓴다(해리처럼 처음 나온 때가 아기여도). 쓰지 않는 것: 정체·이중첩자·충성 대상의 반전, 죽음·부상·변신 같은 결과, 나중에 밝혀지는 과거·혈연·비밀, 후반 사건의 이름과 결말(회차 기억·관계에만 둔다).
  모델이 쓴 글은 서버 쪽에서 검사한다. 금지 낱말은 ① 모든 인물에게 정한 것(호크룩스·죽음의 성물·혼혈 왕자·이중첩자·정체·알고 보니 …) ② 인물별로 정한 것(스네이프: 릴리·충성·첩자 …, 퀴렐: 볼드모트·숙주·터번 …, 페티그루: 스캐버스·웜테일·배신 …, 무디: 크라우치·가짜 …, 덤블도어: 사망·살해 …, 해리: 호크룩스 …)
  ③ 그 인물의 회차 기억에서 가운데 회차 뒤에만 나오는 세 글자 이상의 고유명사(자동 추출)다. 걸리면 그 낱말을 알려 한 번 다시 쓰게 하고, 그래도 걸리면 그 인물의 문서는 이전(첫 등장 기준) 값으로 두고 `heldBack`에 남긴다(지어내거나 숨기지 않는다).
- 별칭은 처음 나온 대목에서 적힌, 그 인물만 가리키는 이름뿐이다(둘 이상의 인물이 쓴 호칭·나중 대목의 이름은 뺀다: 설계 규칙 6). 사건 요약·관계 본문에는 그 자리의 누구나 아는 겉으로 드러난 사실만 쓰게 하고 속마음은 `episodes[N]`에만 둔다(규칙 1·2).
- 사건 참석은 '참여', 같은 사건의 참석자끼리는 '알고 있음'으로 긍정 관계를 만든다(인물이 아는 카드는 긍정 관계로 이어야 한다: 규칙 4). 관계는 값이 바뀐 회차마다 기록한다.
- 머리를 못 찾아 묶인 장의 사건·기억은 묶음의 **마지막 장** 회차로 센다(경계를 짐작하지 않고 앞 장으로 미래 정보가 새지 않게).

### 8.3 서버 한도와 선택

- 서버 한도(`WorldStudioService.validateEditRequest`·`RelationshipInputHelper`): 요청당 카드 1000개·본문 2,000,000바이트·관계 1000개, 세계관 카드 10,000개, 한 회차 시점의 활성 관계 10,000개. 그래서 `seed.py`의 회차 저장 루프를 배치로 바꾼 `hp_seed.py`로 적재한다(`seed.py` 파일은 그대로, 카드 유형은 조직·능력을 `sim_worlds.seed_module()`이 런타임에 더한다).
  배치 하나가 실패하면 2초·4초 기다려 서버를 다시 읽고(이미 들어간 것은 빼고) 그 배치만 다시 보낸다. id가 결정적(uuid5)이라 다시 실행하면 같은 값은 건너뛴다. 공개 진입점은 localhost만 허용하고 비밀번호는 환경변수 `STORYFORK_SEED_PASSWORD`로만 받는다.
- 서버는 한 회차 시점의 활성 관계를 10,000개까지만 받는다. 처음 조립한 관계는 14,337개(추출 1,735·참여 7,270·알고 있음 5,332)라 **추출한 관계 → 참여(참석자 목록 앞 3명) → 알고 있음(같은 사건에 함께 나온 횟수가 많은 쌍부터)** 순으로 9,900개까지만 담는다(참여 4,533·알고 있음 3,632).
  문서·본문은 3,000자, 관계 label은 200자로 자른다. `build-hp --max-relations N --max-attend K`로 관계 수 상한과 사건마다 '참여'를 만드는 참석자 수를 바꿔 다시 조립할 수 있다(응답은 캐시라 호출 없이 몇 초).
- **인물당 관계 상한 150**: 인물 입력에는 그 인물이 끝점인 관계가 모두 들어가 입력 크기를 정하므로, 인물 한 명이 끝점인 관계를 150개까지만 담는다(`build-hp --person-cap`). 추출한 관계(여러 번 나온 것·최근 것 먼저) → 사건 참여(최근 것 먼저) → 알고 있음(함께 나온 횟수·최근 순) 순으로 담고,
  알고 있음은 한 쌍에 방향 하나로 줄였다(한쪽이 끝점이면 두 인물이 서로 안다). 서버 한도 9,900도 그대로 지킨다.
- 세계관 장르는 Content 장르 코드(`genre-01` = 판타지, DEC-56)다.

### 8.5 프롬프트 크기(평가 비용을 키우는 쪽)

- 인물 입력(`character_view`)에는 그 인물이 끝점인 관계가 **모두** 들어간다(회상 상위 몇 개가 아니다). 그래서 인물당 관계 상한을 둔다. 상한 전 150문항의 인물 입력은 중앙값 18만 자·최대 31만 자(관계 줄이 87%)였고,
  **상한 150 뒤에는 중앙값 3.08만 자·90분위 5.2만 자·최대 6.16만 자**(JSON, `ensure_ascii=False`)다. 글자/토큰 비 2.0(한국어 본문 1.5·JSON 뼈대 3.5의 사이 어림, 실사용량으로 확인하지 못했다)으로 세면 중앙값 약 1.5만 토큰·최대 약 3.1만 토큰이다.
- `estimate --world hp`(상한 뒤, 출력을 호출당 상한으로 센 값): 품질 A·B 각 약 $2.64, 속도 A·B·C·E 각 약 $1.45·$1.45·$1.44·$1.17(D는 C와 같은 실행). 실제는 이보다 낮다.
- 더 줄이려면 `--person-cap`·`--max-attend`·`--max-relations`를 낮춰 다시 조립하고 `seed-hp`를 다시 실행한다(응답은 캐시라 호출 없이 몇 초).

### 8.6 권리와 한계

- 원문·장 나눈 글·카드·모델 응답은 `.data/hp`에만 있다(커밋하지 않는다). 적재한 로컬 작품(「해리 포터(평가용·로컬 전용)」)은 원고가 없고 공유·원격 DB에는 넣지 않는다.
- **번역본 한국어 카드 + 영어 질문**: TimeChara 질문은 영어고 카드는 한국어다. 질문에서 카드 제목을 찾는 NovelBrain 회상의 출발점(제목 일치·BM25)이 어휘가 겹치지 않아 약해질 수 있다. 이 영향은 재지 않았다.
- 해리 포터는 모델이 이미 아는 이야기라 카드가 없어도 답할 수 있어 **누설 평가를 흐릴 수 있다**(원문 기반 세계관은 카드가 얼마나 지켜지는지를 보는 것이지 모델의 사전 지식을 없애지 않는다).
- 호칭 묶기·영어 이름·문서 내용은 모델 판단이다(오합·오분리·누락 가능, 사람 검수 없음). 인물은 덩어리마다 30명, 설정은 25개, 사건은 8개까지만 뽑는다. '참여' 관계 본문은 고정 문구다.
