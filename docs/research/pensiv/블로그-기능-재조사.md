## 조사 범위와 판독 기준

목록의 글은 2026-04-14~05-19 게시된 12편이다. 전체·숨김 요소 포함 재확인에서 페이지 번호·이전/다음·더보기를 발견하지 못했다. 노출된 12편을 전수 읽었으며 추천 글은 중복 계산하지 않았다. 비노출 글의 부재를 뜻하지는 않는다.

표는 펜시브 팀의 제품 제공 주장과 글의 사용예이며 실행 검증이 아니다. 작가의 집필 조언은 별도 구분했다. 블로그 밖으로 확장하지 않았고 로그인·가입·결제·설치·수정·게시·AI 호출도 하지 않았다. 기존 조사 보고서와 대조했다.

## 이전 조사에 덧붙일 발견사항

### 1. 캐릭터 변화 추적 주장은 있으나 시점별 상태 조회는 미확인

[8]은 관계성 매핑을 “우호, 적대, 혈연 등의 관계를 정의하고 그 변화를 추적”한다고 설명한다. 등장 회차와 마지막 등장 시점도 자동화 대상으로 든다. [5]의 “속성과 등장 기록을 자동 추적”, [12]의 “등장 기록을 스스로 추적”은 단순한 정적 프로필보다 강한 제품 주장이다. 이전 조사에는 이 표현을 블로그 근거로 추가할 수 있다.

그러나 관계 변화의 전용 이력 화면, 회차별 속성 스냅샷, ‘10화 시점의 능력·소유물·지식’을 조회하는 기능, 시간에 따른 상태 재계산은 12편에 명시되어 있지 않다. [8]의 심리 변화·성장 과정 사례는 작가가 캐릭터 파일에 “꼼꼼히 기록”한 방식이다. [3]의 성장 곡선도 보드에 배치하는 활용이지 자동 측정 주장이 아니다. 따라서 ‘변화 추적을 홍보한다’와 ‘시점별 상태 엔진이 있다’를 분리해야 한다.

### 2. 설정 변경의 타 문서 영향은 연결·추적 수준으로 한정

[8]은 마법을 누가 쓰는지, 지리 설정이 향후 플롯에 어떤 제약을 주는지 문서를 넘나들며 확인한다고 설명한다. [10]은 “문서 간 설정 연결 상태를 실시간으로 추적”한다고 쓰며, 플롯 카드를 본문 문서에 연결하면 그래프에 관계가 반영된다고 한다. 즉 설정과 원고가 고립되지 않는 연결 구조를 제품 가치로 제시한다.

설정 변경 시 영향 원고 자동 목록화·타 문서 일괄 수정·의미 차이 분석은 명시하지 않는다. [8]은 작가가 관련 파일을 업데이트하고 새 설정의 파급력을 가늠하라고 권한다. 사용자 작업 지침이지 자동 전파의 증거가 아니다.

### 3. 자동 모순 검사는 명시적 홍보 주장으로 추가할 근거가 있다

가장 강한 근거는 [10]이다. “인물, 장소, 사건의 연결 고리를 시각화하여 모순을 자동 감지”, 소제목 “그래프 뷰로 설정 충돌 자동 감지”, 비교표 “AI Ask로 자동 검사”를 사용한다. 잃은 검이 뒤 회차에서 다시 등장하는 구체적 모순까지 예로 든다. [4]도 프로젝트 전체를 읽고 충돌을 경고하는 AI라고 설명하고, [12] 비교표는 그래프·캐릭터 파일로 “자동 방지”라고 표현한다. 따라서 ‘블로그에는 자동 검사 주장이 없다’고 정리하면 부정확하다.

동시에 이 글들은 그래프 시각화, 작가의 눈으로 확인, 질문한 뒤 AI가 대조하는 흐름을 혼용한다. 상시 백그라운드 검사인지, Ask 요청 시 검사인지, 어떤 문서·시간 범위인지, 알림·오탐 처리·검사 이력은 설명하지 않는다. 안전한 결론은 ‘자동 감지·검사를 제공한다고 블로그가 주장하나 실행 방식과 실제 정확도는 검증하지 않았다’이다. 그래프 자체의 의미 추론과 AI 질의 검토를 동일 기능으로 확정해서는 안 된다.

### 4. 관계·복선은 시각화 및 배치 지원과 자동 판정을 구분

[1]~[3]은 관계·세력·사건 연결을 그래프로 조망하는 예를 반복한다. [8]은 메인·서브·백그라운드 플롯을 구분하고, 타임라인에서 떡밥 투입·회수 시기와 인물 동선을 점검한다고 설명한다. [11]의 무협 사례도 칸반 에피소드 재구성으로 복선을 잊지 않고 회수했다는 서술이다.

복선 자동 추출·미회수 경고·회수 성공 판정은 명시하지 않는다. 별도 플러그인 근거는 섞지 않는다. [8]의 ‘시간적 모순 방지: 히스토리 시스템’도 설명은 10분 간격 원고 저장·비교·복원이다. 편집 이력과 이야기 내부 시간 검증은 다르다.

### 5. Ask·Plan·Agent·Review는 역할별 사용예가 구체적이다

[4]·[12]를 합치면 Ask는 프로젝트의 설정·원고·플롯 검색과 근거 있는 답변, Plan은 생성 전 의도 확인과 전개 기획, Agent는 검색·계획을 결합한 플롯 초안 보조, Review는 완성 원고의 특정 고민에 맞춘 개선 피드백이다. 특히 [12]의 ‘승인하기 전까지 원본을 건드리지 않는다’는 Agent 설명은 작가 주도권을 강조한다.

Ask는 기억 보조와 설정 확장 모두에 쓰이고 [1]·[3]·[9]은 Ask·Plan을 전개·인물 아이디어에 함께 활용한다. Review가 전체 회차·설정을 항상 읽거나 Ask와 같은 탐색 범위를 갖는다는 주장은 찾지 못했다. 네 이름을 동일한 자동 집필 기능으로 묶으면 안 된다.

### 6. 회차·감정선·성장은 제공 도구를 이용하는 설계 작업

[1]의 회차별 사건·감정선, [3]의 죽음·깨달음 시점, [10]의 5막·감정 곡선 배열은 보드를 활용하는 구체적 설계 예다. 회차·감정선·성장 설계 지원으로 설명할 수 있으나 감정 점수 자동 산출·성장 그래프 자동 생성 주장은 아니다.

### 7. 글콘티·사전기획 전용 템플릿 제공 주장은 찾지 못함

12편에 ‘템플릿’이라는 단어는 없었다. [1]의 5,500자 원고를 60~70컷으로 압축하고 감정·분위기를 지문으로 적는 방식은 노경찬 작가의 조언이다. 자동 컷 분할·글콘티 변환·전용 양식 제공 주장이 아니다. 제품 연결점은 보드의 사건·감정선 카드 배치다.

[6]·[9]의 소재와 재미 결합→주인공 목적→미래·결말 이미지 역시 소울풍 작가 등의 사전 구상 프레임워크다. 펜시브는 이를 캐릭터 파일·보드·AI 아이디어 제안으로 지원한다고 설명하지만, ‘3단계 사전기획 템플릿’을 내장·배포한다고 밝히지는 않는다. 5막·기승전결 언급도 작가가 구성할 수 있다는 설명이며 선택형 템플릿 목록의 증거가 아니다.

## 적용 시 주의와 원문 보존

이전 조사에는 자동 모순 검사·등장 기록 자동 추적·관계 변화 추적의 블로그 문구를 보강하되 실행 검증과 구분한다. 시점별 상태 조회·설정 자동 전파·자동 감정 분석·전용 기획 템플릿은 미확인이다.

생산성 2배·설정 충돌 감소 90%는 글의 주장이지 표본·원자료를 확인한 측정치가 아니다. 타사 평가도 독립 검증하지 않았다. 요금·보안 확인을 위한 범위 확대는 하지 않았다.

글별 공식 링크와 조사 범위는 [출처 색인](evidence.md)에 정리했다. 이미지·동영상 내용과 로그인 후 실제 AI 실행은 검증하지 않았다. 팀 공유본에는 원문 전체 덤프와 브라우저 실행 기록을 포함하지 않는다.
