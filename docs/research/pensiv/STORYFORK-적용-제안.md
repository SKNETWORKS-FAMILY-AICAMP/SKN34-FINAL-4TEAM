# 펜시브 기능의 STORYFORK 적용 제안

조사 기준일: 2026년 11월 2일. 펜시브 공개 기능의 사용자 경험을 STORYFORK의 세계관 작업실과 집필 흐름에 적용하는 제안이다. 기능 채택이나 MVP 범위 변경을 확정하는 문서가 아니다. 펜시브 세부 기능과 출처는 같은 폴더의 `pensiv-source-research.md`를 함께 본다.

## 핵심 판단

가장 먼저 참고할 부분은 원고·설정·플롯을 연결하는 탐색과 AI가 읽고 바꾸는 대상을 명확히 보여주는 흐름이다. STORYFORK에는 여기에 기준 회차·허용된 공개 범위·확정 버전을 결합해야 한다. 펜시브의 일반적인 파일 연결·공유·편집 승인을 우리 서비스의 회차별 설정 공개·독자 Fork·정본 승인과 같은 기능으로 취급하면 안 된다.

## 프로젝트 비교 기준

이 저장소의 [README](../../../README.md)와 [아키텍처](../../architecture.md)는 정적 프로토타입·시작 화면·Health 중심의 개발 기반을 설명한다. 개별 실험·개인 브랜치의 부분 구현은 팀 공통 구현 완료로 평가하지 않는다.

비교 기준은 [최신 MVP 설계](../../design/design.md)와 [결정 기록](../../design/decisions.md)의 DEC-26~40이다. 설정의 공개 범위·기준 회차·인물 지식·정본 승인·Fork 독립 정책을 유지하며, 아래 내용은 경쟁제품에서 참고할 제안이다. 구현 현황은 각 기능 담당 문서와 실제 코드로 확인한다.

## 우선 적용할 기능

### 1 AI가 읽을 문맥 표시

펜시브는 열려 있는 파일과 직접 고른 파일·폴더를 맥락 칩으로 표시한다. 칩을 열거나 제거할 수 있고 폴더는 전송 시 파일로 펼쳐진다. [첫 대화](https://docs.pensiv.so/ko/agent/first-run), [에이전트 개요](https://docs.pensiv.so/ko/agent/overview).

STORYFORK에서는 `현재 원고`, `참고 설정`, `기준 회차`, `대상 인물`을 AI 요청 직전에 확인하게 한다. 화면에 보이는 칩이 서버의 접근 통제를 대신하지 않는다. 콘텐츠 서비스가 사용자·작품·Fork·기준 회차·버전으로 허용 문맥을 확정하고 AI에 전달하는 경계를 유지한다.

- 사용자 흐름: 원고에서 AI 열기 → 허용된 설정을 검색해 추가 → 포함 목록 확인 → 실행 → 결과에서 참고 항목 열기.
- 수용 기준: 제거한 항목은 명시적 요청 문맥에서 빠진다. 권한 밖 항목은 이름·개수·본문으로 노출하지 않는다. 자동으로 추가되는 문맥이 있다면 별도로 표시한다. 실패 후 원고는 유지한다.
- 정책 주의: 인물의 말투·성격과 그 인물이 해당 회차에 아는 사실은 별도로 다룬다. 같은 작품 안에 있다는 이유로 미래 정보를 보내지 않는다.
- 펜시브 해석 주의: 맥락 칩은 에이전트가 접근 가능한 모든 파일을 칩 안으로만 제한한다는 보장이 아니다. 현재 작품 안의 다른 파일을 검색할 수 있는 기능과 구분해야 한다.

### 2 후보의 변경 전후 비교와 개별 채택

펜시브의 AI 문장 다듬기는 선택 영역의 원문과 수정안을 비교하고 적용·취소·재생성한다. 제안 도중 원문이 바뀌면 적용을 막는다. 일반 에이전트의 도구 실행 승인과는 별도 흐름이다. [AI 문장 다듬기](https://docs.pensiv.so/ko/writing/ai-rewrite).

STORYFORK의 설정 후보에 `추가`, `수정`, `관계 변경`을 구분하고, 기존 값과 후보 값을 나란히 보여준다. 후보마다 근거 원고·회차를 열 수 있게 한다. 선택 승인 시 콘텐츠 서비스가 기준 버전을 다시 검사하고 확정 버전을 만든다.

- 수용 기준: 후보 생성만으로 정본이 바뀌지 않는다. 거절·중단·실패 시 직접 쓴 내용이 보존된다. 오래된 버전의 후보는 무조건 덮어쓰지 않는다.
- 선행조건: 후보와 원문 근거를 연결하는 응답 계약. 출처 없는 추론은 원문에서 추출한 사실과 구별한다.
- 주의: 펜시브의 세션/항상 허용을 그대로 가져와 우리 정본의 사용자 채택을 생략하지 않는다.

### 3 원고와 설정을 동시에 확인

펜시브는 탭과 멀티 뷰로 여러 파일을 함께 연다. [탭](https://docs.pensiv.so/ko/project/tabs), [멀티 뷰](https://docs.pensiv.so/ko/project/split-view).

우리 화면에서는 집필 중 인물·장소를 누르면 옆 패널에서 설정을 읽고 다시 원고로 돌아오게 한다. 처음부터 자유로운 창 배치 시스템을 만들기보다 원고와 참고 패널의 두 영역으로 시작한다.

- 수용 기준: 참고 설정을 열고 닫아도 원고 입력과 스크롤 위치가 유지된다. 좁은 화면에서는 패널을 전환해 사용할 수 있다. 저장 중·실패·미저장 상태가 보인다.
- 확장: Fork 창작 화면에는 원작 원고와 대화를 함께 보여주는 DEC-29 방향을 적용하되, 원작에 직접 쓰기 권한을 주지 않는다.

### 4 멘션과 역참조

문서에서 설정 항목으로 이동하고 해당 설정을 참조한 문서를 다시 찾는 연결을 참고한다. [백링크와 멘션](https://docs.pensiv.so/ko/structure/backlinks), [설정 연결](https://docs.pensiv.so/ko/start/connect).

STORYFORK에서는 인물 이름 문자열 검색을 정식 연결로 취급하지 않고 설정 ID와 회차를 연결한다. 문자열 일치만으로 연결하면 동명이인·개명·부분일치 문제가 생기므로 실제 참조와 구분한다.

- 사용자 흐름: 원고에 인물 연결 → 설정 열기 → 이 인물이 등장하는 허용 회차 목록 → 해당 문단으로 복귀.
- 수용 기준: 항목 이름이 바뀌어도 연결을 유지한다. 독자에게는 비공개·미발행 회차의 역참조를 보여주지 않는다. 참조 관계와 세계관 속 인물 간 관계를 다른 의미로 표시한다.

### 5 검색과 필터

펜시브는 파일 검색, 사이드바 필터, 라벨·상태 분류를 제공한다. [검색](https://docs.pensiv.so/ko/project/search), [사이드바 필터](https://docs.pensiv.so/ko/project/sidebar-filter).

세계관 설정집에 이름·별칭 검색과 고정 카테고리·자유 태그 필터를 먼저 더할 만하다. AI를 실행하지 않고도 원하는 설정을 찾아야 한다.

- 수용 기준: 필터와 검색어를 함께 사용한다. 결과 없음과 로딩 실패를 구분한다. 현재 회차에 허용된 항목만 조회한다.
- 범위: 새 분류 체계를 도입하지 않고 DEC-31·39를 따른다. 고정 카테고리의 실제 목록은 기존 미결 정책을 임의 확정하지 않는다.

### 6 문체와 말투에 맞춘 선택 영역 수정

펜시브는 다듬기·줄이기·말투 맞추기·늘리기·문장 호흡·묘사·비문 수정과 자유 지시를 제공한다. 말투 맞추기는 주변 인물명과 해당 캐릭터 시트 속성 조건을 사용한다. 선택 구간 외에도 앞뒤 약 800자, 문체 표본, 관련 시트 속성을 보낼 수 있다. [AI 문장 다듬기](https://docs.pensiv.so/ko/writing/ai-rewrite).

우리에게는 `인물 말투 맞추기`, `짧게 다듬기`, `자유 지시` 정도로 시작하는 것이 적절하다. 사실 추가나 사건 변경을 원하지 않는 수정과 새 전개 생성을 구분한다.

- 수용 기준: 수정 대상과 추가 문맥을 사전에 설명한다. 대상 인물·기준 회차를 유지한다. 사실 보존은 모델의 성능 보장이 아니라 검토할 조건으로 삼는다.
- 선행조건: 실제 원고 저장과 선택 영역 위치·기준 버전 계약. 인물 지식 제약이 있는 시뮬레이션을 단순 말투 수정으로 대체하지 않는다.

### 문서를 정독해야 드러나는 설계 차이

- 플롯보드는 플롯 카드와 그 아래 파트 카드로 구성된다. 태그·문서·시트 등의 언급은 파트 카드에 명시돼 있다. 우리에게 적용할 때도 막·사건·장면을 무조건 같은 객체로 취급하지 않는다.
- 펜시브 타임라인은 폴더의 항목 순서를 칸으로, 라벨을 행으로 표시한다. 달력 날짜나 세계 속 절대 시각을 판정하는 시간선으로 확인된 것이 아니다. 우리 초기 역사·사건의 선후관계 모델과 구분한다.
- 본문 멘션은 방향 있는 참조이고 시트 연결 속성은 양방향 저장이다. 이 연결을 인물 사이의 감정·지식·관계로 자동 해석하지 않는다.
- AI 리뷰는 현재 문서의 감평이며 참고 문서는 최대 4개다. 다른 회차를 스스로 찾아 읽는 상시 설정 모순 검사라고 설명할 수 없다. 블로그의 일관성 관리 주장은 별도 마케팅 근거로 표시한다.
- 자동 채우기의 속성값 제안과 설명 생성은 적용 방식이 다르다. 설명은 확인 단계 없이 기존 값을 덮어쓴다고 문서가 설명하므로, 우리 정본에는 이 방식을 그대로 적용하지 않는다.
- 펜시브 버전 복원은 복원 직전의 미저장 현재 내용을 자동으로 별도 보존한다고 보장하지 않는다. 우리 서비스의 revert는 기존 확정 버전을 보존하는 새 버전이어야 한다.
- `실시간 협업`이라는 문서 제목과 달리 본문은 기기 간 클라우드 동기화 중심이다. 다중 사용자 역할·동시 커서·권한별 공동편집을 이 문서만으로 지원한다고 판단하지 않는다. [협업 문서](https://docs.pensiv.so/ko/collaborate/realtime).

## 당장 범위를 늘리지 않을 기능

### 확장 기능에서 골라낼 작은 도구

펜시브의 공개 플러그인 목록에는 기본 편집기 밖에서 제공하는 기능도 있다. 앱 내장 기능과 설치형 확장을 구분해야 개발 범위를 정확히 비교할 수 있다. [플러그인 목록](https://pensiv.so/ko/community/plugins).

| 후보 | 공식 설명에서 확인한 기능 | STORYFORK 적용 아이디어 |
|---|---|---|
| [복선](https://pensiv.so/ko/community/plugins/foreshadowing) | 문장에 복선을 표시하고 회수 지점을 연결해 미회수 항목 확인 | 복선의 심기·회수 회차와 관련 설정을 연결. Fork 뒤에도 원작과 다른 회수 결과를 구분 |
| [상태창](https://pensiv.so/ko/community/plugins/status-window) | 인물에 속한 타입 있는 능력치, 문서에서의 변화 표시, 장르별 프리셋 | 현재 수치와 해당 회차의 상태·지식을 구분해 보여주기. 전 문서의 최신 수치를 과거 회차에 소급하지 않기 |
| [단락 분석](https://pensiv.so/ko/community/plugins/paragraph-analysis) | 시작 기호에 따라 대사·독백·특수 대사·묘사를 분류하고 분량·평균 길이 표시 | 비싼 AI 분석 없이 기본 집필 통계 제공. 의미를 이해한 문장 분류나 품질 점수로 표현하지 않기 |
| [날짜 계산기](https://pensiv.so/ko/community/plugins/date-calculator) | 나이·기간·날짜 연산 결과를 원고 옆에서 확인 | 사건 날짜와 인물 나이의 수동 검산 보조. 설정 모순 자동 검출과 구분 |

이 중 복선 관리는 후속 기능 후보로 가치가 있다. 플러그인 실행 환경이나 마켓부터 만들 필요는 없다. STORYFORK의 회차·설정 연결이 갖춰진 뒤 작고 명확한 도구로 구현할 수 있다.

실시간 공동 편집, 데스크톱·모바일 앱과 오프라인 동기화, 플러그인·테마·스킬 마켓, 외부 AI 앱용 MCP, 자유 캔버스 전체 기능, 결제 플랜은 별도 제품 개발 과제다. 펜시브에 있다는 이유만으로 우리 팀 시연 MVP에 포함할 필요는 없다.

특히 로컬 전용 저장과 서버 권한·Fork를 중심으로 하는 STORYFORK는 저장 전제가 다르다. 동기화 스위치 하나를 추가해서 같은 기능을 얻을 수 없다. MCP를 제공한다면 외부 클라이언트에서도 비공개 설정과 기준 회차를 강제하는 별도 계약이 필요하다.

## STORYFORK의 차별화 검증

펜시브에도 AI·설정·관계 그래프·버전 기록이 있으므로 그것만으로 차별화했다고 설명하기 어렵다. 다음 흐름을 실제로 완성하고 검증하는 것이 더 구체적이다.

블로그 재조사에서는 펜시브가 자동 모순 감지와 AI Ask를 통한 설정 검사를 제품 기능으로 직접 주장한다는 점도 확인했다. 따라서 `설정 모순 검사` 자체를 우리만의 차별 기능으로 제시하지 않는다. 검사 기준 회차·허용된 정보·근거·독자 Fork 이후의 독립 상태까지 구체적으로 관리하는지를 비교해야 한다. [노벨라 대안 글](https://pensiv.so/ko/blog/novela-alternative), [블로그별 조사](블로그-기능-재조사.md).

1. 독자가 원작 5화에서 Fork한다. 6화 이후 비밀과 인물이 아직 모르는 정보는 읽을 수 없다.
2. 수정 전에는 5화에 영향을 주는 허용된 원본 변경을 따른다.
3. 첫 세계관 수정으로 전체 허용 세계관을 독립시키고 원작은 그대로 둔다.
4. 독립 뒤 원본이 바뀌면 차이를 보고 반영·보류하며, 보류한 변경도 나중에 선택한다.
5. AI가 제안한 변경은 근거와 함께 검토하고, 채택한 것만 새 확정 버전으로 남긴다.

이는 우리 최신 DEC-32~40의 방향이다. 펜시브가 이 흐름을 지원하지 않는다고 단정하려면 추가 검증이 필요하다. 공개 문서에서 같은 수준의 회차별 공개 범위·독자 Fork·선택 반영을 확인했는지를 기준으로 비교해야 한다.

## 추천 구현 순서와 시연

1. 설정 검색·필터와 참고 패널을 연결해 AI 없이도 원고와 설정을 오갈 수 있게 한다.
2. AI 요청에 포함한 문맥과 후보의 변경 전후·근거를 보여주고 기준 버전 검사를 유지한다.
3. 확정 이력 조회·복원과 회차별 권한 경계를 완성한다.
4. 그 위에 플롯 카드와 회차·인물을 연결한다.

시연 예: 작가가 5화를 쓰다가 인물 말투가 어긋난 문단을 고른다. 옆 패널에서 해당 인물의 허용된 설정을 확인하고 수정 요청을 보낸다. AI가 어떤 자료를 참고했는지와 수정안을 보여준다. 작가가 채택해 새 버전을 저장한다. 독자는 5화에서 분기하고 인물의 선택을 바꾸되, 8화의 비밀은 보지 못한다. 이 흐름으로 편집 편의와 STORYFORK 고유의 시점·권한 경계를 함께 검증한다.

## 검증 범위

이 작업은 경쟁제품 조사와 적용 제안이다. 구현 코드·요구사항·결정 기록은 변경하지 않는다. 브라우저에서 공개 자료를 읽은 결과와 로그인 후 직접 기능을 실행한 결과를 구분한다. 문서 변경이므로 앱 E2E나 구현 테스트를 수행한 것으로 보고하지 않는다.
