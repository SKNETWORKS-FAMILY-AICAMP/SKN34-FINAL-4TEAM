## 검증 판정 원칙

- 순차 `git apply` 성공은 적용 검사이며 빌드/동작 통과가 아닙니다.
- 전체 통합본 통과를 중간 PR 통과로 바꾸지 않습니다.
- 테스트 이후 앞 단계의 코드가 바뀌면 코드 해시를 비교하고 영향받은 단계를 다시 검증합니다.
- 실제 push 뒤 원격 CI가 실행되기 전에는 원격 CI 통과라고 쓰지 않습니다.
- 잠재 원문/DB/로그/모델 원출력은 로컬에만 둡니다. 합성 fixture·테스트 소스만 공유합니다.

## 포함/제외

코드/테스트·환경 예시·아키텍처 문서·PR 검토 본문은 위 네 단위에 배정합니다. `output/`의 diff 묶음/실행 로그/검증 DB/증거, `.env`, node_modules/venv, 원래 prototype의 Gitea/작품 서비스 실험은 포함하지 않습니다. 원래 사용자 worktree는 수정하지 않습니다. 개인 브랜치에 코드가 올라갔다는 사실과 각 기능의 구현 완료/부분 구현/검증 필요를 구분합니다.
