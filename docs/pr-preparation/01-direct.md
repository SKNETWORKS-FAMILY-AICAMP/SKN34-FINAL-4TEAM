# feat: 세계관 직접 작성과 Core 저장 연결

Refs #48

메모리 데모에 묶였던 세계관 작성 흐름을 독립 React 작업실과 Core 저장 API로 연결합니다. **#48의 부분 구현**이며 실제 인증/운영 저장/공개 범위 등 아래 남은 요구사항을 포함해 Issue 전체를 완료한 것으로 처리하지 않습니다.

## 변경

- `/worlds/:worldId?`의 목록·생성·인물/장소/설정/메모 작성·수정·재조회와 기존 View→ViewModel→UseCase→Repository→HTTP/DI 연결.
- Core의 로컬 세션·소유자 검사·JDBC/H2 저장·명시 저장마다 revision 보존·기준 버전 검사.
- 상단/서재/상세 화면의 ‘세계관 작업실’ 진입, 기존 새 소설 데모의 저장된 서버 세계관 조회 연결. 저장 상태/실패 안내를 사용자 문구로 정리.

## 동작

세계관 작업실 → 이름으로 생성(설명 선택) → 메뉴별 직접 작성 → 저장 → 수정 → 새로고침/재조회. 항목 ID·여러 줄/구분자를 포함한 원문·사용자 분류·태그를 유지합니다. 실패/충돌 시 편집 중 값과 마지막 저장본을 보존합니다. 저장은 공개·발행이 아닙니다.

## 결정

- AI 없이 동작하는 직접 작성 단위를 먼저 공유합니다. AI 호출은 #48의 필수 범위가 아니며 후보/승인/확정 읽기 화면은 이 PR에 넣지 않습니다.
- 10개 작성 메뉴는 원본 UX이며 고정 카테고리 정책이 아닙니다. 자유 분류/태그와 LLM topics는 별개이며 미정 목록을 임의 확정하지 않습니다.
- 기존 작품·회차·Fork/가져오기 데모와 사용자 데이터는 유지합니다. 별도 Issue 결함 수정과 AI/읽기 화면은 후속 분리 diff로 둡니다.

### 작성 메뉴·자유 분류·LLM topics의 구분

원본의 인물·장소 입력, 7개 영역 목차, 집필 메모를 합친 **10개 작성 메뉴는 탐색/작성 UX**다. `kind/entityType/category`는 현재 의미 표현·정리용 데이터이며, `userCategory`는 자유 입력이고 `tags`는 자유 태그다. 이들을 #48의 확정된 고정 카테고리 목록으로 선언하지 않는다. 고정 카테고리 하나를 선택·검증하는 제품 계약은 목록 합의 후 별도로 정리해야 한다.

LLM `topics`(7개 영역/27개 세부 점검)는 선택적 AI의 의미 점검 메타데이터이며 사용자 분류·태그와 별개다. 필수 입력이 아니고 첫 PR의 직접 작성은 AI 없이 동작한다. 첫 PR에는 AI 요청/승인 기능을 넣지 않으며 AI 호출은 #48의 필수 완료 조건이 아니다. 후속 AI 단위도 #48 전체 완료를 의미하지 않는다.

## 남은 일과 연계 범위

실제 인증, PostgreSQL/그래프 연계, 고정 카테고리 합의, 항목/회차 공개, 이미지 10개/MinIO·URL·참고 URL, 초안 자동저장, 사용자 이력/revert UI와 제거/복원 정책이 남습니다. 운영 준비나 UC-02 전체 구현 완료를 주장하지 않습니다.

#49는 **범위 밖, 연계 참고만**입니다. ‘새 원작에 권한 있는 세계관 하나 연결’과 현재 `/new` checkbox/누적 배열/1~5개 선택·메모리 작품 저장 데모는 다릅니다. 미선택/존재하지 않는 ID/타인 비공개는 프런트 데모에서 거부하지만 타인 public+allowUse는 기존 데모가 허용하며, 이미 다른 작품에 연결된 세계관 검사와 실제 작품 API/영속 저장/연결 유일성은 없습니다. 프런트 검증을 Core 작품 검증으로 표현하지 않습니다. 이번 PR에서는 이 정책을 수정하거나 #49 일부 해결/별도 PR 준비로 취급하지 않습니다. 기존 #48 작업실 진입/조회 연결만 유지합니다.
