# 인물 카드와 관계 편집

## 사용자 흐름

기존 세계관 작업실의 인물 입력과 인물 외 설정 메뉴를 유지한다. 인물 이름만 입력한 뒤 `관계 편집 열기`로 이동하면 동일한 ID와 소개의 카드가 생긴다. 새 카드에 선을 자동 생성하지 않으며 이미 작성한 관계는 보존한다. 관계 편집의 `인물 추가`도 같은 편집본을 사용한다.

기본 연결은 카드의 관계 연결 → 상대 카드 선택 → 실제 관계 및 주체→대상/대상→주체 감정 자유 입력 → 편집본에 적용 → 공통 저장이다. 카드 본문 드래그는 위치 이동만 하고 정보 편집/관계 연결 버튼과 분리한다. 이름·한 줄 소개와 버튼을 카드 안에 제공한다. 긴 이름·소개·관계선 문구는 화면에서만 줄여 표시하며 입력과 저장 원문은 보존한다.

그래프를 주 작업영역으로 쓰고 단일 inspector를 제공한다. 데스크톱은 오른쪽, 좁은 화면은 overlay/bottom sheet다. 상대 선택 중에는 패널을 숨긴다. Escape/취소, 키보드 인물 선택·관계선 선택, 모달 포커스 순환과 터치 버튼을 제공한다. 좁은 화면의 패널이 열리면 배경 스크롤을 잠그고 닫을 때 복원한다.

## 같은 정본과 저장 경로

카드와 기존 폼은 `useWorldStudioViewModel.editing.settings`를 공유한다. 적용은 전체 변경을 검증한 뒤 한 번에 편집본에 반영하고 공통 저장 버튼이 기존 PUT `/api/v1/studio/worlds/{id}`와 기준 version을 사용한다. 별도 그래프 API·정본·저장소는 없다. 전체 세계관 react-force-graph 탐색과 확정 설정집은 계속 `saved`를 읽는다.

두 사람 묶음은 표시일 뿐 단일 실제 관계 슬롯이 아니다. 기존의 여러 실제 관계·감정·항목 ID·출처·별도 작가 서술을 유지한다. 수정하지 않은 항목은 다시 저작 처리하지 않는다. 관계/각 방향 감정은 항목별 삭제 버튼으로만 제거하며 묶음 전체 삭제 버튼은 없다. 적용 취소는 패널의 미반영 입력만 버린다. 저장 실패·버전 충돌은 편집본과 마지막 저장본을 보존한다.

## 자유 표현과 기존 타입 호환

DB 마이그레이션은 없으나 서버 저장 계약에 자유 타입 3종과 인물·관계 삭제 허용 변경이 포함된다. 새 실제 관계는 `custom_relation`(두 사람 사이) 또는 `custom_relation_directed`(주체→대상), 방향별 감정은 `custom_emotion`으로 구조적 구분만 한다. 자유 문구는 `item.text`와 `authorText`에 원문 그대로 저장한다. 예시 문구는 datalist로 제공할 뿐 단어를 기존 enum으로 추론·변환하지 않는다. 인물 역할과 방향은 편집 패널에서 명시한다. 기존 `child_of`/`parent_of`는 누가 누구의 자녀/부모인지 표시한다.

기존 `friend_of`/`sibling_of`/`child_of`/`parent_of`/`spouse_of`/`trusts`/`wary_of`/`likes`/`hostile_to`와 부정 polarity는 호환한다. 열기/취소/수정 없는 적용만으로 기존 타입을 재분류하지 않는다. 사용자가 자유 문구를 직접 수정한 항목만 해당 자유 입력 타입으로 반영한다. 반대 방향 감정을 자동 복제하지 않는다. 정확히 같은 표현·방향·부정 값의 중복은 거부하되 같은 방향에 서로 다른 복합 감정/관계 표현은 보존한다.

기존 자동 이름·설명이 수정 전 자동 형식과 정확히 일치하면 관계 구조/인물 이름 변경에 맞춰 해당 필드만 동기화한다. 이름과 설명을 독립 비교하므로 별도 작가 서술은 보존한다. 자유 입력 본문은 자동 형식과 같아도 원문으로 취급해 다시 쓰지 않는다. 기존 enum 항목에 자동 형식 그대로 수동 작성한 문구는 구분할 수 없어 동기화 대상이다. 이미 과거 구조와 어긋난 저장 문구는 추측해 일괄 변경하지 않는다. 분석 입력은 저장한 원문을 읽는다.

## 삭제와 참조 보호

인물 삭제 전에 함께 제거될 관계·감정 목록과 개수를 표시한다. 다른 설정이 해당 인물이나 제거될 관계를 참조하면 설정 이름과 이유를 안내하고 삭제를 막는다. 다른 설정을 조용히 연쇄 삭제하지 않는다. 서버도 남은 참조와 보호 대상 항목 삭제를 검증한다. 인물·관계 제거는 새 revision으로 저장하며 이전 revision은 유지한다.

삭제 직후 되돌리기는 단일 삭제의 이전/이후 배열과 세계관 ID가 일치할 때만 허용한다. 후속 데이터 수정·세계관 전환·저장 시도 시 무효화해 이후 편집을 덮어쓰지 않는다. 저장 실패 시 삭제된 편집본 자체는 보존한다. 위치 이동·배치 정돈은 UI 위치만 바꾸며 위치 저장은 지원하지 않는다. 위치 객체는 도메인 settings와 분리한다.

## 검증과 범위

첫 PR의 직접 작성·저장·재조회 범위와 분리하는 후속 변경이다. 실제 인증·PostgreSQL·회차별 공개·그래프 DB·유료 AI 호출을 추가하지 않는다. 작업실의 기존 H2/체험 세션 한계는 유지된다.

로컬 관련 프런트 14개 파일 25개 테스트, Core 서비스 10개와 기존 minimal 계약 3개 테스트를 통과했다. 타입 검사·변경 영역 oxlint·Vite/Core JAR 빌드 통과. 기존 메인 번들의 500kB 경고는 남는다. 그래프/폼/설정집/재조회 동기화, 원문·다중 관계·참조 보호·삭제 undo·저장 실패·drag 분리를 확인한다. 후속 배치 간격 조정은 영향받는 카드·등록 회귀를 재검증한다.

합성 QA는 웹 5181 → Core 8098 → 별도 H2를 사용한다. 사용자 preview 5175/8086과 DB는 변경하지 않는다. 독립 검토에서 최신 카드의 기존 메뉴 유지·카드 연결→상대 선택→자유 감정 입력→취소를 Aside로 확인했다. 실제 1440/800/390px 전체 흐름과 최신 카드의 최종 저장·재조회·삭제 참조 보호 브라우저 통합 검증은 미완료다. 로컬 `output/world-relations/`의 이전 원형 노드 증거를 최신 카드 검증으로 취급하지 않는다. Graphify는 AST만 갱신하며 기존 문서 분석 경고를 근거 없이 해결됐다고 표시하지 않는다.

사용자 지시에 따라 기존 개인 브랜치에 commit/push하고 PR은 준비만 한다. PR 생성·변경·병합·develop 직접 push를 하지 않는다. 원격 Required CI는 미실행이며 로컬 통과를 병합 가능 판정으로 표시하지 않는다.
