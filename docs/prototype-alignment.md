# STORYFORK UI 프로토타입 ↔ 유스케이스 대응

> **문서 상태: v2 — `frontend/index.html` 프로토타입 기준**
> UI 프로토타입은 화면 흐름과 아이디어를 보여 주는 **견본**이며, 정책·업무 계약의 근거는 [유스케이스](./usecase.md)와 [유스케이스 명세](./usecase-spec/README.md)입니다. 이 문서는 두 결과물을 서로 고도화하기 위해 차이를 기록합니다. 프로토타입의 동작을 확정 정책으로 보지 않고, 문서에 없는 기능을 구현 범위로 가정하지 않습니다.

## 1. 읽는 법

| 상태 | 의미 | 다음 행동 |
|---|---|---|
| 일치 | 문서와 화면 흐름이 맞음 | 구현 시 화면 참고 |
| 문서 반영 | 프로토타입 아이디어를 문서에 대안 흐름·미정으로 반영함 | 미정 항목은 팀 합의 후 확정 |
| 프로토타입 정정 | 문서와 충돌. 문서 기준으로 화면을 고쳐야 함 | 2절 목록 참고 |
| 미구현 화면 | 문서에는 있으나 프로토타입에 화면이 없음 | 3절 목록 참고 |
| 프로토타입 전용 | 확정 범위 밖([usecase.md 7.2절](./usecase.md#72-이번-문서에서-구현확정하지-않는-것)). 시연용으로만 유지 | 구현 범위에 넣으려면 먼저 문서 개정 |

현재 `frontend/index.html`은 정적 프로토타입으로 React 진입점(`src/main.tsx`)을 불러오지 않습니다. 프로토타입은 Core API를 호출하지 않고 브라우저 메모리의 예시 데이터로만 동작합니다.

## 6. 유지 방법

- 프로토타입 화면이 바뀌면 2절의 화면 ID와 상태를 갱신합니다.
- 정정 항목을 프로토타입에서 고치면 3절에서 해당 행을 지우고 2절 상태를 `일치`로 바꿉니다.
- 프로토타입 아이디어를 채택하려면 해당 UC 명세의 미정·대안 흐름을 먼저 개정합니다. 이 문서만 고쳐서 정책을 확정하지 않습니다.
