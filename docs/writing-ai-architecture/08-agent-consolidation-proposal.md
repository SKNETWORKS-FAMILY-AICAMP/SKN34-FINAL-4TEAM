# 집필 AI 에이전트 구조 개편 제안

**상태: 미채택 이력.** 사용자는 3개 업무 역할·공통 도구로의 개편안을 채택하지 않기로 했다(2026-11-12). 아래는 당시 검토 내용이며 현행 설계나 구현 지시가 아니다. 다중 인물 Simulation은 사용자의 명시적 실행 요청이 있을 때만 실행한다.

**이전 검토 당시 상태: 검토용 제안.** 현재 여섯 업무 역할, API, Router의 operation과 구현을 바꾸거나 제거한 결정이 아니다. 통합 시에도 각 사용자 기능, 입력·출력·권한·실패 계약과 `gpt-6-luna` 목표를 보존한다. 사용자 요청에 따른 Writing의 Retrieval·Simulation 직접 호출 금지와 Content 정본·승인 경계는 변경하지 않는다. [현재 구조](02-ai-architecture.md) · [기능 계약](03-rag-simulation-design.md)

## 판단 기준

DAG 우선순위는 실제 호출 빈도나 비용 측정이 아니라 현재 유스케이스·설계의 정성적 판단이다. 임의 Agent 간 연결과 전체 유효 DAG는 허용 간선·반복·병렬 정책이 정해지지 않아 열거할 수 없다. 아래는 실제 사용자 요청과 기존 명시 경계에 근거한 우선 연결이다. Retrieval과 Simulation은 필요할 때 사용하는 공통 도구이며, Simulation 내부 인물 턴 반복은 한 도구 내부 실행이다.

| 우선도 | 흐름 | 목적과 조건 |
|---|---|---|
| 높음 | Retrieval → Q&A | 질문의 허용 근거와 출처를 조립한다. |
| 높음 | Retrieval → Review | 원고·설정의 대조 근거를 확인한다. 기계적 검사만으로 끝나는 경우 검색을 강제하지 않는다. |
| 높음 | Development → Writing | 사용자가 계획에 따른 문장 생성을 요청한 경우다. |
| 높음 | Writing → Review | 생성 후보의 검수가 필요한 경우다. 고정 후보·기준 초안 판본 계약이 먼저다. |
| 높음 | Review → Writing | 수정 요청과 유효한 지적이 함께 있을 때 후보를 만든다. |
| 높음 | Simulation → 사용자 선택 → Writing | 선택한 가상 결과만 집필 재료로 사용한다. Writing이 Simulation을 직접 호출하지 않는다. |
| 높음 | Retrieval → World & Plot | 설정·플롯 변경의 영향 분석과 후보를 분리한다. |
| 조건부 | Retrieval → Review → Simulation → Review 결과 | 인물 반응 재현이 필요한 경우만 실행하고 가상을 확정 근거로 삼지 않는다. |
| 조건부 | Web Research → Review | 현실 고증을 원고 검수에 쓰도록 요청한 경우다. URL과 확인 시점을 유지한다. |
| 후속 | Writing → Review → Writing | 같은 기능의 반복 실행과 후보 판본 연결이 필요하다. 현재 Router로는 표현하지 못한다. |

## 권장 구조: 세 업무 역할과 공통 도구

이는 **구현 단위의 통합 제안**이다. Agent 수를 줄이더라도 사용자 기능과 결과 종류는 유지한다. 이름은 설명용이며 새 서버·추상 계층을 뜻하지 않는다.

| 제안 단위 | 현재 역할 대응 | 구체적 책임과 경계 |
|---|---|---|
| **작품 분석** | Q&A + Review + World & Plot | 각각 `질문 답변`, `원고 검수`, `설정/플롯 영향 분석` 작업으로 구분한다. 공통 Retrieval과 필요한 경우 Simulation을 재사용한다. Answer·Finding·ImpactReport/변경 후보는 서로 다른 결과다. 영향 분석의 변경 후보는 Content 승인 경로를 유지한다. |
| **전개 기획** | Story Development | 기존 사건과 사용자 목표를 바탕으로 BeatPlan을 만든다. 필요할 때 Retrieval·Simulation을 쓴다. 사용자에게 문장 작성 요청이 있을 때만 집필 결과로 이어진다. |
| **문장 생성** | Writing & Editing | 새 Text와 선택 구간 Patch를 구분한다. Content가 확인한 입력을 사용하며 Retrieval·Simulation을 직접 호출하지 않는다. 필요 시 작품 분석의 검수 작업이 결과를 확인한다. |
| **공통 검색 도구** | Retrieval | 출처·판본·권한·Coverage/Gap을 확인한다. Q&A의 답변 생성은 작품 분석에 남긴다. |
| **공통 인물 시뮬레이션 도구** | Character Simulation | 인물별 지식 격리·행동 반복·별도 `gpt-6-luna` 장면 요약을 담당한다. 독립 사용자 기능도 유지한다. |
| **외부 사실 조사 도구** | Web Research | 기존 OpenAI 웹 조사 기능의 검색·출처 검증을 필요할 때 호출하는 기능으로 재사용한다. 단독 조사 요청도 유지하고, 외부 전송 동의·500자 제한·실제 검색 URL 검증을 보존한다. Simulation은 직접 호출하지 않는다. |

World & Plot은 영향 분석과 검수에 겹치는 부분이 있어 작품 분석으로 묶되, 변경 후보와 승인 경로를 일반 Review 결과에 합치지 않는다. Q&A도 답변 생성 자체를 삭제하지 않는다. Web Research는 별도 상시 Agent 역할을 없애는 제안이며 검색 기능·단독 진입점·실패 처리의 삭제가 아니다. Development와 Writing은 기획만 요청했을 때 문장이 자동 생성되지 않도록 분리한다.

## 실행 및 이행 순서

1. 현재 API와 operation을 유지한 상태로 각 기능의 입출력과 오류를 비교한다. 아직 실제 통합이나 파일 이동을 하지 않는다.
2. 생성 후보 검수의 불변 참조·원래 초안 판본·Finding 위치·승인 충돌 계약을 확정한다. 인물 지식 확인과 내부 Simulation 기록 정책도 해당 연결 전에 확정한다.
3. 실제 요청으로 Q&A·Review·영향 분석에서 공유할 검색과 검증을 확인한다. 결과 타입과 승인 경계를 유지한 채 중복만 합친다.
4. 웹 조사 단독 요청과 다른 기능의 고증 요청을 모두 검증한 뒤 도구화 여부를 결정한다. Router의 기존 사용자 기능 선택과 연결을 함께 점검한다.
5. 상위 연결이 필요해지면 고정 순서부터 연결한다. 같은 역할 재호출·병렬 처리·중단 재개가 필요할 때만 Router 및 Main StateGraph를 확장하고 기존 API 호환성과 단위 테스트·기능별 실모델 수용을 확인한다.

현재 Router는 최대 세 단계, 기능별 최대 한 번의 순차 분류만 지원한다. 위 표는 목표 흐름이며 기능 실행 연결, 반복 Agent 호출, 병렬 DAG 또는 복구가 현재 구현됐다는 뜻이 아니다. 복합 작업에서 부분 실패·권한·판본 충돌은 명시하고 실패한 단계를 성공으로 대체하지 않는다.
