# 결정과 미정 사항

이 문서의 “채택”은 이번 집필 AI 개발 순서의 결정이다. 제품 전체 정책을 새로 확정하지 않는다. 기존 [설계 결정](../design/decisions.md)과 [서비스 경계](../design/service-boundaries.md)가 우선한다.

| 항목 | 채택한 방식 | 이유·한계 |
|---|---|---|
| 개발 순서 | 정책이나 실제 DB 기반이 있는 기능부터 수직으로 구현하고 기능마다 실 OpenAI 모델로 확인 | Mock 전체 RAG를 먼저 완성해도 실제 검색·생성 품질을 증명하지 못한다. |
| 관계 정본 | Content가 확인한 Neo4j **현재 관계 하나** | 과거 관계 이력/복원은 #132 계약에서 제외. 회차 시점의 관계를 현재 그래프로 추측하지 않는다. |
| 원고 정본과 검색 | PostgreSQL 원고·버전이 정본, Elasticsearch 벡터 인덱스는 파생 검색 | 색인 결과는 권한·revision·원문 span을 다시 확인해야 한다. 색인 지연은 누락으로 표시한다. |
| 전체 RAG | 관계 Graph, 회차 Wiki Graph, 원고 Vector, 템플릿 Vector의 네 경로를 목표로 유지 | Wiki·템플릿은 실제 필요와 기반이 생길 때 구현. 공통 출처/coverage만 미리 문서화한다. |
| 실행 형태 | 단순 기능은 직접 실행, 공통 Retrieval은 필요할 때 호출, 다중 인물 Simulation은 명시적 사용자 요청 때만 실행 | 반복·분기·중단이 필요한 곳에 그래프를 사용한다. Router가 요청별 작업 수·순서·조건을 정하고 실행 코드가 계획을 검증한다. 필요할 때 Main StateGraph·검증된 DAG를 도입한다. 범용 DAG·Saver는 선행 조건이 아니다. |
| 모델과 역할 | 여섯 업무 Agent와 인물 행동·장면 요약의 목표 모델은 OpenAI `gpt-6-luna`(2026-11-12 사용자 결정) | 동일 모델을 역할별 입력으로 호출한다. 시뮬레이션의 인물별 행동과 요약은 별도 호출이며 역할별 서버나 모델 인스턴스를 뜻하지 않는다. 기존 구현의 설정·실측 기록은 그대로 둔다. |
| Router | 사용자 의도에 따라 작업 수·순서·조건을 유동적으로 선택하고 실행 전 Python이 계획을 검증 | 현재 OpenAI Decisions Router는 분류만 하고 최대 세 단계·기능당 한 번이다. 실행·권한을 부여하지 않으며 필요 시 분류·실행 계약을 함께 확장한다. 제공사 전환은 별도 평가·결정이 필요하다. |
| 답변 표시 | Router가 계획하고 Python이 실행된 Agent의 원본 결과를 실행 순서대로 묶어 표시 | 결과 종합을 위한 별도 모델 호출은 없다(2026-11-12 사용자 결정). 출처·판본·실패와 실제 후보 보관·승인·적용 상태를 구분한다. Agent와 Simulation 요약의 모델 호출은 유지한다. |
| 집필 도구 경계 | Writing & Editing은 Retrieval·Simulation 직접 호출 없이 문장·문체 생성에 집중 | Content가 허용 입력을 전달하고 필요 시 Review가 생성 결과를 검수한다(2026-11-12 사용자 결정). |
| 검수 | Mechanical과 Semantic 분리, Simulation은 사용자 명시 요청 때만 실행 | 맞춤법과 서사 판단의 근거·오류 유형이 다르다. |
| 집필과 기획 | Development는 BeatPlan, Writing은 새 Text 또는 기존 Patch | 계획을 원고 정본처럼 저장하지 않는다. |
| 제안 적용 | AI는 변경 후보, Content가 승인·현재 판본·적용 영수증 판단 | 모델 출력이 곧 저장/발행은 아니다. 저장소 간 원자성을 가정하지 않는다. |
| 외부 근거 | 웹 검색은 현실 사실의 출처, 작품 내용은 Content 정본 | 웹 텍스트는 명령이 아니며 모델 입력과 정본을 오염시키지 않는다. |
| 사용자 기록 | UC-09·11·12의 기록은 단독·복합 실행 모두 소유자가 삭제할 때까지 조회 | [기능별 보관 범위](04-infrastructure-integration.md#복합-실행-기록과-중복-요청)를 적용한다. |
| 실패와 시간 초과 | UC-21의 작업별 기준과 즉시 안내, 자동 재처리 금지 | [시간 초과와 실패](04-infrastructure-integration.md#시간-초과와-실패)를 따른다. |

## 집필 AI MVP 확정 범위

2026-11-12 사용자 결정. 아래는 목표 설계의 지원 범위다. 기능별 구현 완료 여부는 로드맵과 기능표에서 확인한다.

### 복합 실행

| 항목 | 확정 정책 |
|---|---|
| 단계별 입력 | Python이 등록된 연결 규칙으로 매핑하고 Content가 각 대상·판본·권한을 확인한다. 입력 출처나 대상이 모호하면 사용자에게 확인한다. |
| 실행 순서 | 순차 최대 세 단계·기능당 한 번. 집필 연결은 Development → Writing, Writing/Editing → Review, Review → 조건부 Editing과 이 규칙으로 이어지는 Development → Writing → Review를 지원한다. 독립 작업도 대상·입력·동의를 각각 확인한 뒤 순차 실행한다. |
| 실패와 표시 | 실패·시간 초과 후 새 단계를 시작하지 않는다. 완료 결과는 보존하고, 실행하지 않은 단계와 이유를 계획 순서로 표시한다. 조건이 거짓이어서 건너뛴 단계는 실패와 구분한다. |
| 필수 입력 | 사용자 요청이 요구한 결과는 모두 확인한다. 하나라도 없거나 검증되지 않으면 그 결과에 의존하는 작업을 시작하지 않는다. |
| BeatPlan | 바로 집필하라는 요청에는 Development가 집필용 BeatPlan 하나를 지정한다. 사용자가 비교·직접 선택을 요청하면 기획 결과를 표시한 뒤 새 집필 요청에서 선택을 받는다. |

### 공개 API와 실행 기록

| 항목 | 확정 정책 |
|---|---|
| 공개 API | 자유 입력 전용 공개 경로를 추가한다. 단일 기능 경로와 명시적 operation 계약을 유지한다. |
| 기록 | 복합 결과는 실행 응답에서 계획 순서로 표시하고, 사용자 소유 기록은 기능별 정책으로 보관한다. |
| 중복 요청 | 같은 요청 키와 같은 입력은 기존 실행 상태나 결과 참조를 반환한다. 같은 키의 다른 입력은 충돌이며, 명시적 재생성에는 새 키를 쓴다. |
| 제한 | 작업별 시간 제한만 적용한다. UC-21의 기준을 사용하고 기준이 없는 단계는 연결할 때 정한다. 공개 경로의 연결 제한 안에서 실행 가능한 조합부터 지원한다. |

### 검수와 수정

- 확정 오류와 의심이 섞이면 검증된 확정 오류만 수정에 전달한다. 의심은 검수 결과에 표시한다.
- 의심만 있으면 조건부 수정 미지원으로 안내한다. 사용자가 수정하려면 별도 편집 요청으로 받는다.
- 여러 구간에 유효 Finding이 있으면 사용자가 지정한 한 구간만 수정한다. 지정된 구간이 없으면 선택을 요청한다. 실패·부분 검수·근거 부족은 조건을 충족하지 않는다.
- 웹 조사·World & Plot 직후 조건부 수정과 가상 결과를 확정 오류로 사용하는 흐름은 지원하지 않는다.

[조건부 수정 계약](02-ai-architecture.md#조건부-수정-if_issues_found)

### 시뮬레이션

- 전용 UI에서 선택한 실행은 그 선택을 확인한다. 자유 입력에서 Simulation을 분류한 경우 별도 실행 확인을 받는다.
- 후보 선택 또는 부족 정보의 확인 뒤에는 선택한 후보나 확인 내용을 담은 새 요청으로 진행한다. 이후 작업의 권한·대상·판본을 다시 확인한다.
- Simulation 결과 생성 단계가 허용된 정본 근거와 대조한다. Python은 인용이 입력 근거에 포함되는지 확인하고, 근거가 없으면 비교 불가로 표시한다. 별도 Review 요청은 저장된 가상 후보를 사용한다.
- 독자 검증은 오류 가능성 판정·근거와 함께 신뢰도 등급을 표시한다. 등급은 직접 근거 있음, 간접 근거만 있음, 근거 부족으로 구분한다. 공개 범위와 제보 경계는 [UC-09 A5](../usecase-spec/UC-09.md)를 따른다.

### 데이터와 적용

- Content가 확인한 회차와 WorldStudio world 연결만 사용한다. 없거나 불명확하면 관계 근거를 제외하고 이유를 표시한다.
- 인물과 습득 시점을 출처로 확인할 수 있는 지식만 사용한다. 필수 정보가 부족하면 [UC-09 E3](../usecase-spec/UC-09.md)에 따라 진행 여부를 확인한다.
- 원고 검색은 [v1과 개발 표본](07-retrieval-contract-and-mocks.md#원고-벡터-인덱스-v1)을 기준선으로 유지한다. 권한·판본 필터, 원문 대조, 검색 누락 표시를 우선 확인한다.
- 한 번의 승인에서 단일 문서 또는 단일 관계를 적용한다. 여러 대상의 영향은 한 보고서로 보여 주고 적용은 각각 승인받는다.

## 후속 검토와 구현 시 정할 사항

- 병렬 실행·분기 합류, 반복 호출, 네 단계 이상, 실패 후 독립 작업 계속, 필수·보조 입력 구분은 후속 검토한다. 추가 연결은 입력·출력과 권한 계약을 먼저 정한다.
- 같은 실행의 영속 재개, 복합 실행 이력 화면, 전체 실행 시간 제한, 다중 구간·저장소 일괄 적용은 후속 검토한다.
- 공개 경로명·DTO, 요청 키의 유효 기간과 저장 방식, 기준이 없는 단계의 시간 제한, 인물 지식 근거의 저장·조회 방식은 기능 연결 시 정한다.
- 검색 수치 목표는 개발 표본 확대 뒤 정한다. 실제 모델 검증에는 개발용 자료·키·호출 상한을 사용하고 관찰 결과를 기록한다.
