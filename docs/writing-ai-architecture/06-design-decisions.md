# 결정과 미정 사항

이 문서의 “채택”은 이번 집필 AI 개발 순서의 결정이다. 제품 전체 정책을 새로 확정하지 않는다. 기존 [설계 결정](../design/decisions.md)과 [서비스 경계](../design/service-boundaries.md)가 우선한다.

| 항목 | 채택한 방식 | 이유·한계 |
|---|---|---|
| 개발 순서 | 정책이나 실제 DB 기반이 있는 기능부터 수직으로 구현하고 기능마다 실 OpenAI 모델로 확인 | Mock 전체 RAG를 먼저 완성해도 실제 검색·생성 품질을 증명하지 못한다. |
| 관계 정본 | Neo4j 하나가 관계의 정본이며 회차별 연결로 기록한다([DEC-51](../design/worldstudio-independent-schema.md#회차별-관계--dec-51)) | 이전 #132는 현재 상태 하나만 저장했다. Manuscript Review·Rating·시뮬레이션은 Content MCP로 기준 회차 시점 관계를 읽는다. Q&A만 아직 최신 관계를 쓴다(#490에서 전환). 회차 시점의 관계를 최신 그래프로 추측하지 않는다. |
| 원고 정본과 검색 | PostgreSQL 원고·버전이 정본, Elasticsearch 벡터 인덱스는 파생 검색 | 색인 결과는 권한·revision·원문 span을 다시 확인해야 한다. 색인 지연은 누락으로 표시한다. |
| 전체 RAG | 관계 Graph, 회차 Wiki Graph, 원고 Vector, 템플릿 Vector의 네 경로를 목표로 유지 | Wiki·템플릿은 실제 필요와 기반이 생길 때 구현. 공통 출처/coverage만 미리 문서화한다. |
| 실행 형태 | 단순 기능은 직접 실행, 공통 Retrieval은 필요할 때 호출, 다중 인물 Simulation은 명시적 사용자 요청 때만 실행 | 2026-11-17 사용자 결정, #473 구현: **메인 에이전트 하나**(`create_agent`)가 요청별 작업 순서·조건을 정해 `ask_*` 서브 에이전트 도구를 부르고, 코드가 노출·한도·입력·승인을 지킨다. 바깥 LangGraph는 메인 에이전트·시뮬레이션 장면(`scene`)·승인(`apply`)·종료와 체크포인트만 맡는다. 전환 전에는 Router 계획을 기능 노드가 실행했다(2026-11-12 사용자 요청). 범용 DAG·Registry는 두지 않는다. [구조](02-ai-architecture.md#메인-에이전트-오케스트레이션-473) |
| 모델과 역할 | 일곱 업무 Agent·메인 에이전트와 인물 행동·장면 요약의 목표 모델은 OpenAI `gpt-6-luna`(2026-11-12·2026-11-17 사용자 결정) | 동일 모델을 역할별 입력으로 호출한다. 시뮬레이션의 인물별 행동과 요약은 별도 호출이며 역할별 서버나 모델 인스턴스를 뜻하지 않는다. 기존 구현의 설정·실측 기록은 그대로 둔다. |
| 범위 판정과 기능 할당 | 2026-11-17 사용자 결정, #473 구현: Intent Router를 없애고 **Decision Guard**(OpenAI Decisions `gpt-6-luna`)가 턴당 1회 서비스 범위(`guard`)와 필요한 기능(기능별 yes/no)을 판정한다. 판정된 기능의 서브 에이전트만 메인 에이전트에 노출한다 | 참고 프로젝트(SKN34-4th-5Team)의 JEV 가드 역할이다. 판정은 1차 필터이며 실행·권한을 부여하지 않는다. 순서·조건·검사 종류는 메인 에이전트가 정하고 코드가 검증한다. 공통 입력 가드레일 미들웨어와 Decisions 응답 검증은 그대로 쓴다. 전환 전에는 Decisions Router가 기능 순서를 분류했다. |
| 답변 표시 | 2026-11-17 사용자 결정, #473 구현: 메인 에이전트가 이번 턴 서브 에이전트 결과로 최종 답변을 종합하고, Python은 원본 결과를 단계별로 함께 반환 | 2026-11-12의 "결과 종합 모델 호출 없음"을 대체한다. 종합은 표시용이며 결과에 없는 사실을 만들지 않고 원고 본문을 다시 쓰지 않는다. 출처·판본·실패와 실제 후보 보관·승인·적용 상태를 구분한다. 메인 모델 호출만큼 비용·지연이 는다(턴당 최대 5회). |
| 업무 Agent | Story Context / Q&A·Manuscript Review(원고 검수)·World Review(설정집 검토)·Writing & Editing·World & Plot·Web Research·Rating의 일곱(2026-11-18 사용자 결정). 원고 검수 Agent의 이름은 Manuscript Review(2026-11-18 사용자 결정, 코드 이름 변경은 #499) | 설정집 검토는 Decision Guard 기능·`ask_world_review` 도구·`app/world_review/`를 따로 가져 원고 검수와 단위가 다르다. 계약은 [설정집 검토](../design/world-review-contract.md). 이전의 3역할 통합안은 미채택([이력](08-agent-consolidation-proposal.md)) |

[설계](03-rag-simulation-design.md#5-rating-agent) |
| 제안 적용 | AI는 변경 후보, Content가 승인·현재 판본·적용 영수증 판단 | 모델 출력이 곧 저장/발행은 아니다. 저장소 간 원자성을 가정하지 않는다. |
| 외부 근거 | 웹 검색은 현실 사실의 출처, 작품 내용은 Content 정본 | 웹 텍스트는 명령이 아니며 모델 입력과 정본을 오염시키지 않는다. |

Writing/Editing → Manuscript Review는 같은 턴의 Manuscript Review가 저장된 초안을 읽어 승인 전 결과를 검수하지 못하므로 후속이다(2026-11-18 사용자 결정). 기획 → 집필은 Writing & Editing 한 단계 안에서 처리한다(#387). 대상·입력·동의가 각각 확인된 독립 조회형 작업(Q&A·웹 조사·Rating·설정집 검토·Manuscript Review)은 한 모델 턴에 병렬로 실행하고, Writing·시뮬레이션과 입력이 빠진 호출, 앞 결과가 필요한 호출은 순차로 실행한다(#474). |

### 검수와 수정

- 확정 오류와 의심이 섞이면 검증된 확정 오류만 수정에 전달한다. 의심은 검수 결과에 표시한다.
- 의심만 있으면 조건부 수정 미지원으로 안내한다. 사용자가 수정하려면 별도 편집 요청으로 받는다.
- 여러 구간에 유효 Finding이 있으면 사용자가 지정한 한 구간만 수정한다. 지정된 구간이 없으면 선택을 요청한다. 실패·부분 검수·근거 부족은 조건을 충족하지 않는다.
- 웹 조사·World & Plot 직후 조건부 수정과 가상 결과를 확정 오류로 사용하는 흐름은 지원하지 않는다.
- 이번 턴에 Manuscript Review가 있으면 부분 수정은 그 Manuscript Review의 확정 지적만 고친다. 다른 구간 수정은 새 요청으로 받는다(2026-11-18 사용자 결정).
- 선택 구간이 없는 부분 수정은 입력 대기에서 채팅 카드로 구간을 골라 이어 간다(2026-11-18 사용자 결정, 미구현, #497). [채팅 구간 입력](02-ai-architecture.md#입력-대기와-승인-hitl)
- SSE `plan`의 판정 기능 중 메인 에이전트가 부르지 않은 것은 완료 뒤 화면에서 사라진다(2026-11-18 사용자 결정, 현행 유지).

[조건부 수정 계약](02-ai-architecture.md#조건부-수정-if_issues_found)

### 시뮬레이션

- 전용 UI의 선택과 시작 양식이 실행 확인이다. 자유 입력은 Decision Guard의 "실행을 명시적으로 요청했는가" 판정이 yes일 때만 실행하며, 별도 확인 단계 없이 첫 턴을 실행하고 턴마다 멈춰 작가가 이어 가거나 끝낸다(2026-11-18 사용자 결정).
- 후보 선택 또는 부족 정보의 확인 뒤에는 선택한 후보나 확인 내용을 담은 새 요청으로 진행한다. 이후 작업의 권한·대상·판본을 다시 확인한다.
- Simulation 결과 생성 단계가 허용된 정본 근거와 대조한다. Python은 인용이 입력 근거에 포함되는지 확인하고, 근거가 없으면 비교 불가로 표시한다. 별도 Manuscript Review 요청은 저장된 가상 후보를 사용한다.
- 독자 검증은 오류 가능성 판정·근거와 함께 신뢰도 등급을 표시한다. 등급은 직접 근거 있음, 간접 근거만 있음, 근거 부족으로 구분한다. 공개 범위와 제보 경계는 [UC-09 A5](../usecase-spec/UC-09.md)를 따른다.

### 데이터와 적용

- Content가 확인한 회차와 WorldStudio world 연결만 사용한다. 없거나 불명확하면 관계 근거를 제외하고 이유를 표시한다.
- 인물과 습득 시점을 출처로 확인할 수 있는 지식만 사용한다. 필수 정보가 부족하면 [UC-09 E3](../usecase-spec/UC-09.md)에 따라 진행 여부를 확인한다.
- 원고 검색은 [v1과 개발 표본](07-retrieval-contract-and-mocks.md#원고-벡터-인덱스-v1)을 기준선으로 유지한다. 권한·판본 필터, 원문 대조, 검색 누락 표시를 우선 확인한다.
- 한 번의 승인에서 단일 문서 또는 단일 관계를 적용한다. 여러 대상의 영향은 한 보고서로 보여 주고 적용은 각각 승인받는다.

## 후속 검토와 구현 시 정할 사항

- 메인 에이전트의 병렬 도구 호출(#474)에서 정한 것(2026-11-17 사용자 결정): 조회형(Q&A·웹 조사·Rating·설정집 검토·Manuscript Review)만 한 모델 턴에 함께 실행하고 Writing·시뮬레이션은 단독, 묶음 안 입력 대기 호출은 미뤄 단독으로 다시 부르게 함(동시 interrupt 없음), 실패해도 함께 시작한 호출은 끝까지 실행해 보존하고 이후 호출 차단, 한도는 호출마다 1회, `steps[]`는 호출 순서·SSE는 발생 순서, 비용·rate limit 별도 제어 없음. [병렬 서브 에이전트 호출](02-ai-architecture.md#병렬-서브-에이전트-호출-474)
- 분기 합류(두 결과를 모아 다음 서브 에이전트에 넘김), 반복 호출(같은 기능 재호출, 예: Writing → Manuscript Review → Editing), 네 단계 이상, 실패 후 독립 작업 계속, 필수·보조 입력 구분은 후속 검토한다. 추가 연결은 입력·출력과 권한 계약을 먼저 정한다.
- 메인 에이전트 전환(#473)에서 정한 것: 메인 모델 호출 상한 턴당 5회(마지막은 도구 없이 종합), 도구를 부르지 않고 끝난 턴은 `clarify`, 시뮬레이션 계획 되묻기는 고정 문구 `clarify`, 장면은 바깥 `scene` 노드(2026-11-17 사용자 결정). 서브 에이전트 결과 요약(ToolMessage `content`)은 기능·상태·핵심 결과(지적 번호 `fix`·확정/의심·근거 id·`gaps`)이고 원고·수정안·기획안 본문은 넣지 않는다. 종합 답변은 기존 응답의 `message`에 담는다.
- 승인·적용 뒤 같은 실행의 영속 재개(단계 입력 대기의 재개는 사용자 요청으로 HITL 구현), 복합 실행 이력 화면, 전체 실행 시간 제한, 다중 구간·저장소 일괄 적용은 후속 검토한다.
- 요청 키 중복 처리(같은 소유자·기능 범위에서 같은 키·같은 입력이면 기존 상태·결과 참조를 반환, 같은 키의 다른 입력은 충돌)를 도입할지와 키 유효 기간·저장 방식, 기준이 없는 단계의 시간 제한, 인물 지식 근거의 저장·조회 방식은 기능 연결 시 정한다.
- 검색 수치 목표는 개발 표본 확대 뒤 정한다. 실제 모델 검증에는 개발용 자료·키·호출 상한을 사용하고 관찰 결과를 기록한다.
- 실모델 평가 표본(Decision Guard 27건·메인 에이전트 대표 시나리오)을 저장소에 고정하는 위치·실행 방법·통과 기준·비용 상한은 #476에서 정한다. 기본 CI에는 넣지 않는다.
- 같은 턴 Writing 뒤 Manuscript Review 호출은 막지 않고, 종합 답변이 저장된 초안 기준 검수임을 밝힌다(2026-11-18 사용자 결정, 메인 에이전트 지시 규칙 7, 미구현, #498). Writing 결과를 Manuscript Review로 넘기는 연결은 후속이다.
