# STORYFORK 유스케이스 명세서

> **문서 상태: 기획 기반 초안 v1 — 업무 기능 미구현**
> [유스케이스 문서](./usecase.md)의 UC-01~23을 상세화한 명세입니다. 사전조건·흐름은 목표 업무 계약이며 구현이나 정책 확정을 뜻하지 않습니다. 정해지지 않은 값(형식, 한도, 요금, 상태 코드)은 `미정`으로 남깁니다.

## 0. 작성 규칙

### 0.1 명세 항목

| 항목 | 의미 |
|---|---|
| 주 액터 / 보조 액터 | 목표를 가진 액터 / 처리에 참여하는 외부 액터 |
| 관계 | include·extend ([usecase.md 2.7절](./usecase.md#27-유스케이스-간-관계)) |
| 관련 기능 ID | [요구사항 정의서](./SKN34-final-4Team_요구사항정의서.xlsx)의 기능 ID |
| 사전조건 | 시작 전 참이어야 하는 조건 |
| 트리거 | 유스케이스를 시작시키는 사건 |
| 기본 흐름 | 가장 일반적인 성공 경로. `사용자`·`시스템` 주어를 명시 |
| 대안 흐름 | `An (m단계)`: m단계에서 갈라지는 다른 성공·선택 경로 |
| 예외 흐름 | `En (m단계)`: m단계에서 목표를 이루지 못하는 경로 |
| 성공 보장 / 최소 보장 | 성공 시 상태 / 실패해도 지켜지는 상태 |
| 업무 규칙 | 이 유스케이스에 적용되는 규칙 (`BR-xx`는 0.3절 공통 규칙) |
| 미정 | 구현 전 합의가 필요한 항목 |

`시스템`은 STORYFORK 전체(Frontend·Core API·AI Service)를 뜻합니다. 권한·정본·발행·크레딧의 최종 판단은 Core API가 합니다.

### 0.2 공통 예외 흐름

각 명세에서 `CE-xx`로 참조합니다.

| ID | 상황 | 처리 |
|---|---|---|
| CE-01 | 미인증·세션 만료 | 요청을 처리하지 않고 로그인(UC-22)으로 안내. 작성 중 입력은 가능한 범위에서 보존 |
| CE-02 | 권한 없음 | 요청을 거부하고 사유를 안내. 대상의 비공개 정보·존재 여부를 노출하지 않음 |
| CE-03 | 저장 실패 | 완료로 표시하지 않고 미저장 상태를 안내. 기존 저장본 보존 |
| CE-04 | AI 실패·시간 초과·중단 | 실패를 성공·빈 결과로 대체하지 않음. 부분 결과를 확정 결과로 반영하지 않음. 재시도·복구 여부는 UC-17 정책을 따름 |
| CE-05 | 비용·한도 부족 | AI 작업을 시작하지 않고 필요한 조건을 안내(UC-17) |
| CE-06 | 이용 제한 대상 | 권리 제한(UC-20) 중인 콘텐츠는 해당 기능(공개·AI·Fork)을 수행하지 않음 |
| CE-07 | 대상 버전 변경 | 작업 기준 버전이 바뀌었으면 묵시적으로 덮어쓰지 않고 재확인을 요청 |

### 0.3 공통 업무 규칙

| ID | 규칙 |
|---|---|
| BR-01 | AI 결과(추출 후보·시뮬레이션·초안·검토 의견·수정안)는 제안이다. 사용자 선택·승인과 실제 저장·공개는 별도 단계다 |
| BR-02 | AI에는 작업에 허용된 최소 문맥만 전달한다. 작가 비공개 정보·독자 공개 범위·인물별 지식을 섞지 않는다 |
| BR-03 | 원고 보유·등록·공개 사실만으로 AI 처리·재공개·Fork·유료 공개 권한을 추정하지 않는다 |
| BR-04 | Fork는 기준 회차 시점의 버전과 허용 문맥을 고정하며 원작의 후속 변경을 자동 반영하지 않는다 |
| BR-05 | 처리 상태(접수·처리 중·실패·검토 대기·승인·반영 성공/실패)를 구분하고, 미완료를 완료로 표시하지 않는다 |
| BR-06 | 실패·권한 거부·한도 초과를 이유로 기존 원고·확정 설정을 덮어쓰거나 자동 삭제하지 않는다 |
| BR-07 | 권한은 계정 유형이 아니라 대상 작품·세계관별 소유권·이용 권한으로 판단한다 |

## 1. 계정·열람

### UC-22 회원 계정 관리

| 항목 | 내용 |
|---|---|
| 주 액터 | 회원(비회원 포함 가입 전 사용자) |
| 구분 | 지원 · 인증 정책 미정 |
| 관련 기능 ID | F-ACT-01~08 |
| 근거 | 요구사항 정의서 REQ01 |
| 관계 | 대부분 유스케이스의 사전조건(include로 표기하지 않음) |

- **목표:** 계정을 만들고 인증된 상태로 사용자별 기능을 이용하며, 본인 정보를 관리합니다.
- **사전조건:** 가입은 미가입 상태, 그 외 기능은 해당 계정의 본인 확인.
- **트리거:** 가입·로그인·로그아웃·정보 수정·계정 복구·탈퇴 중 하나를 선택합니다.

**기본 흐름 (가입·로그인)**
1. 사용자가 회원가입을 선택하고 필수 정보를 입력합니다.
2. 시스템이 입력 형식과 중복 여부를 확인합니다.
3. 시스템이 본인 확인 절차를 수행하고 계정을 생성합니다.
4. 사용자가 등록한 계정 정보로 로그인합니다.
5. 시스템이 인증에 성공하면 세션을 발급하고 사용자별 기능을 제공합니다.
6. 사용자가 로그아웃하면 시스템이 현재 세션을 종료합니다.

**대안 흐름**
- A1 (1단계) 정보 조회·수정: 로그인한 사용자가 본인 정보를 조회하고, 변경 가능한 항목을 수정·저장합니다.
- A2 (4단계) 계정 찾기·비밀번호 재설정: 본인 확인 후 계정을 안내하거나 비밀번호를 재설정합니다.
- A3 (1단계) 탈퇴: 사용자가 탈퇴를 요청하면 시스템이 작품·Fork·피드백 등 관련 데이터의 처리 방식을 안내하고, 확인 후 탈퇴를 처리합니다.

**예외 흐름**
- E1 (2단계) 형식 오류·중복: 계정을 만들지 않고 수정할 항목을 안내합니다.
- E2 (5단계) 인증 실패: 로그인하지 않으며 계정 존재 여부를 노출하지 않는 문구로 안내합니다.
- E3 (A3) 탈퇴 처리 실패: 탈퇴 완료로 표시하지 않습니다.

- **성공 보장:** 인증된 세션이 있는 동안 사용자별 기능을 이용할 수 있습니다.
- **최소 보장:** 실패한 가입·수정은 계정 정보를 변경하지 않습니다. 비밀번호 등 인증 정보를 응답·로그에 노출하지 않습니다.
- **업무 규칙:** 독자·신입 작가·연재 작가는 계정 등급이 아닙니다(BR-07). 운영자 권한은 일반 가입으로 얻지 않습니다.
- **미정:** 필수 항목, 인증 방식(자체·소셜), 본인 확인, 세션 만료·다중 기기, 탈퇴 시 작품·Fork·피드백 보존/삭제 기준, 비회원 이용 범위.

### UC-01 작품·회차 열람

| 항목 | 내용 |
|---|---|
| 주 액터 | 독자 |
| 구분 | 지원 |
| 관련 기능 ID | F-PUB-01, F-PUB-03, F-PUB-04 |
| 근거 | 기획서 12·20쪽 |
| 관계 | UC-08·UC-14가 이 유스케이스를 extend |

- **목표:** 허용된 작품·회차를 읽고 공개 설정·Fork 가능 여부를 확인합니다.
- **사전조건:** 대상 작품·회차가 공개 상태이고 독자에게 열람 조건이 충족됩니다.
- **트리거:** 작품 목록이나 검색 결과에서 작품을 선택합니다.

**기본 흐름**
1. 독자가 작품 목록을 엽니다.
2. 시스템이 열람 가능한 작품을 원작과 Fork 작품으로 구분해 표시합니다.
3. 독자가 작품을 선택합니다.
4. 시스템이 작품 정보, 공개 회차 목록과 순서, 회차별 Fork 허용 여부를 표시합니다.
5. 독자가 회차를 선택합니다.
6. 시스템이 열람 권한을 확인하고 발행본 원고를 표시합니다.
7. 독자가 이전·다음 회차로 이동하며 읽습니다.

**대안 흐름**
- A1 (6단계) Fork: Fork가 허용된 회차이면 Fork 선택지를 표시하고, 독자가 선택하면 UC-08로 진행합니다.
- A2 (6단계) 피드백: 독자가 질문·오류 제보를 선택하면 UC-14로 진행합니다.
- A3 (2단계) Fork 작품 열람: Fork 작품은 기준 원작·기준 회차 정보를 함께 표시합니다.

**예외 흐름**
- E1 (6단계) 비공개·삭제·접근 불가 회차: 원고를 표시하지 않습니다. 비공개 회차 내용을 목록·미리보기에 노출하지 않습니다.
- E2 (6단계) 권리 제한 콘텐츠: CE-06.
- E3 (6단계) 유료 회차: 열람 조건을 안내하며, 결제 방식이 정해지기 전에는 결제 처리를 수행하지 않습니다.

- **성공 보장:** 독자가 허용된 발행본을 읽습니다.
- **최소 보장:** 편집 중 초안·비공개 설정·기준 시점 이후 비공개 내용은 노출되지 않습니다.
- **업무 규칙:** 열람했다는 사실로 AI 처리·Fork·수정 권한을 얻지 않습니다(BR-03).
- **미정:** 비회원 열람 범위, 유료 열람·결제, 작품 검색·정렬 기준.

## 2. 창작 기반

### UC-02 작품·세계관 생성·관리

| 항목 | 내용 |
|---|---|
| 주 액터 | 창작자 |
| 구분 | 핵심 |
| 관련 기능 ID | F-WLD-01~04, F-WLD-08 |
| 근거 | 기획서 14쪽, 그림 9 |
| 관계 | UC-05가 extend |

- **목표:** 새 이야기의 세계관과 작품을 만들고, 회차 구성과 함께 관리합니다.
- **사전조건:** 로그인. 기존 대상 편집 시 해당 작품·세계관의 수정 권한.
- **트리거:** 새 작품 만들기 또는 기존 작품·세계관 편집을 선택합니다.

**기본 흐름**
1. 창작자가 새 세계관 만들기를 선택합니다.
2. 창작자가 세계관 이름과 설명을 입력합니다.
3. 창작자가 장소·시대/역사·세력/조직·설정 규칙·주요 사건·참고 자료 항목을 추가합니다.
4. 시스템이 입력 내용을 확인하고 세계관을 저장합니다.
5. 창작자가 작품을 만들고 제목·장르·소개를 입력합니다.
6. 창작자가 작품에 연결할 세계관을 선택합니다.
7. 시스템이 세계관 사용 권한을 확인하고 작품을 저장합니다.
8. 창작자가 회차를 추가하고 회차별 제목, 관련 장소·인물·사건을 등록합니다.
9. 시스템이 회차 순서와 함께 저장 결과를 표시합니다.

**대안 흐름**
- A1 (1단계) 기존 세계관 사용: 자신이 소유한 세계관을 선택해 6단계로 진행합니다.
- A2 (6단계) 공개 세계관 이용: UC-05로 진행합니다.
- A3 (1단계) 기존 원고에서 시작: UC-03으로 진행합니다.
- A4 (3단계) 일부만 입력: 필수 항목만으로 저장하고 나중에 보완합니다.
- A5 (8단계) 회차 편집: 회차 순서·제목·관련 요소를 수정합니다. 원고 작성은 UC-10입니다.

**예외 흐름**
- E1 (4·7·9단계) 저장 실패: CE-03.
- E2 (7단계) 세계관 사용 권한 없음: CE-02. 작품은 세계관 미연결 상태로만 저장할 수 있습니다.
- E3 (전 단계) 다른 곳에서 수정됨: CE-07.

- **성공 보장:** 세계관·작품·회차 구성이 저장되고 서로 연결됩니다.
- **최소 보장:** 실패 시 기존 저장본이 유지됩니다.
- **업무 규칙:** 생성·저장만으로 독자 공개나 Fork 허용이 되지 않습니다(UC-07, UC-13). 공유 세계관에서 작품에 일어난 사건·설정 변화는 해당 작품에만 저장합니다(F-WLD-08).
- **미정:** 세계관 필수 항목, 세계관-작품 관계(1:N 여부), 세계관 삭제 시 연결 작품 처리.

### UC-03 기존 원고 등록

| 항목 | 내용 |
|---|---|
| 주 액터 | 창작자(대표: 연재 작가) |
| 구분 | 핵심 |
| 관련 기능 ID | F-WLD-05 |
| 근거 | 기획서 14쪽, 그림 9, 연재 작가 정의 |
| 관계 | UC-04가 extend |

- **목표:** 보유한 기존 소설을 STORYFORK의 창작 지원에 사용할 수 있게 준비합니다.
- **사전조건:** 로그인. 등록할 원고를 보유하고 저장·AI 처리에 필요한 권한을 갖추었음을 확인했습니다.
- **트리거:** 기존 원고 등록을 선택합니다.

**기본 흐름**
1. 창작자가 대상 작품을 선택하거나 새로 만듭니다.
2. 시스템이 원고의 권리 확인 항목(본인 저작물 여부, 계약상 제한 여부)을 안내하고 확인을 받습니다.
3. 창작자가 원고 파일을 제공합니다.
4. 시스템이 읽은 내용, 회차 구분과 순서를 미리보기로 제시합니다.
5. 창작자가 누락·순서·회차 구분을 확인하고 필요하면 조정합니다.
6. 창작자가 등록할 범위를 확정합니다.
7. 시스템이 원고를 작품의 회차 원고로 저장하고, 성공 항목과 실패 항목을 구분해 안내합니다.
8. 시스템이 설정 추출(UC-04) 진행 여부를 묻습니다.

**대안 흐름**
- A1 (6단계) 일부 회차만 등록: 이후 추출·검토 문맥이 등록 범위로 제한됨을 안내합니다.
- A2 (8단계) 추출 생략: 창작자가 UC-02·UC-06에서 설정을 직접 정리합니다.
- A3 (8단계) 추출 진행: UC-04로 진행합니다.

**예외 흐름**
- E1 (2단계) 권리 확인 거부: 등록을 진행하지 않습니다.
- E2 (4단계) 읽기 실패·지원하지 않는 형식: 해당 파일을 등록 완료로 처리하지 않고 사유를 안내합니다.
- E3 (7단계) 일부 회차 저장 실패: 실패 회차를 구분 표시하며 전체 성공으로 안내하지 않습니다.
- E4 (7단계) 동일 원고 재등록: 기존 원고를 묵시적으로 덮어쓰지 않습니다(처리 정책 미정).

- **성공 보장:** 확인한 원고가 회차 순서와 함께 저장되어 창작 지원의 입력으로 준비됩니다.
- **최소 보장:** 실패 항목은 저장되지 않고, 기존 원고·설정은 그대로입니다.
- **업무 규칙:** 등록은 STORYFORK 공개, 외부 플랫폼 동기화, AI 학습 동의가 아닙니다(BR-03). 외부 플랫폼 로그인·스크래핑은 제공하지 않습니다.
- **미정:** 지원 형식(TXT·DOCX는 기획서 예시), 직접 붙여넣기 지원, 크기·회차 수 한도, 회차 구분 규칙, 중복·재등록 정책.

**예외 흐름**

- E2 (3~4단계) AI 실패·시간 초과: CE-04. 원고 등록 상태와 구분해 안내합니다.
- E3 (8단계) 저장 실패: CE-03.

- **성공 보장:** 창작자가 채택한 설정만 정본으로 저장되고, 후보와 확정 설정이 구분됩니다.
- **최소 보장:** 추출 실패가 등록 원고나 기존 확정 설정을 바꾸지 않습니다(BR-06).
- **업무 규칙:** AI가 추출했다는 이유만으로 정본이 되지 않습니다(BR-01).
- **미정:** 추출 항목 구조, 후보 보관 기간, 추출 비용 부담 기준.

- **업무 규칙:** 등록자의 확인만으로 외부 IP의 적법한 권한이 보장되지 않습니다(BR-03). Fork 허용과 유료 공개 허용은 별개입니다.

**기본 흐름**
1. 독자가 원작에서 Fork 가능한 회차를 확인합니다.
2. 독자가 분기 기준 회차(해당 회차 종료 시점)를 선택합니다.
3. 시스템이 원작의 이용 조건(AI 처리, Fork 작품 공개, 유료 공개 허용 여부)을 안내합니다.
4. 독자가 조건을 확인하고 Fork 작품의 제목을 입력합니다.
5. 시스템이 Fork 권한과 기준 회차의 허용 여부를 다시 확인합니다.
6. 시스템이 기준 회차까지의 정확한 원고 버전, 당시 공개된 세계관·인물 상태·사건 범위를 고정합니다.
7. 시스템이 기준 원작·회차와 연결된 Fork 작품을 만들고 독자를 소유자로 지정합니다.
8. 시스템이 Fork 작품 화면을 열고 다음 행동(새 전개 입력, 시뮬레이션, 직접 집필)을 안내합니다.
9. 독자가 새로운 사건과 전개 방향을 입력합니다.

**대안 흐름**
- A1 (8단계) 시뮬레이션: UC-09로 진행합니다.
- A2 (8단계) 직접 집필: UC-10으로 진행합니다. AI 없이 무료로 진행할 수 있습니다.
- A3 (1단계) 피드백 응대에서 진입: UC-15의 Fork 안내로 들어오면 2단계부터 진행합니다.

**예외 흐름**
- E1 (5단계) 허용되지 않은 회차·조건 변경: 생성하지 않고 사유를 안내합니다.
- E2 (5단계) 권리 제한 원작: CE-06.
- E3 (6단계) 기준 정보 불완전: 생성하지 않으며 성공으로 안내하지 않습니다.
- E4 (7단계) 생성 실패: CE-03. 부분 생성된 Fork를 남기지 않습니다.

- **성공 보장:** 원작과 분리된 Fork 작품이 고정된 기준 정보와 함께 생성됩니다.
- **최소 보장:** 원작 데이터는 어떤 경우에도 변경되지 않습니다.
- **업무 규칙:** 원작 비공개 정보와 기준 시점 이후 내용은 복제하지 않습니다. 원작의 후속 수정·새 회차가 자동 유입되지 않습니다(BR-04). Fork 생성은 무료 방향입니다.
- **미정:** 기준 정보의 전체 복사 또는 불변 버전 참조 방식, 독자 1인당 Fork 수 한도, 원작 삭제 시 Fork 처리.

- A2 (9단계) 조건 변경 재실행: 2단계로 돌아갑니다.
- A3 (10단계) 집필 연결: 선택 결과를 가지고 UC-10 또는 UC-11로 이동합니다.
- A4 (9단계) 인물 상태 반영: 창작자가 원하면 결과의 상태 변화를 UC-06에서 채택합니다.

**예외 흐름**

- E2 (5~6단계) AI 실패·시간 초과·중단: CE-04. 일부만 생성된 결과를 완료로 표시하지 않습니다.
- E3 (4단계) 인물 정보 부족: 부족한 항목을 안내하고 진행 여부를 묻습니다.

- **성공 보장:** 창작자가 고른 결과가 집필 재료로 남습니다.
- **최소 보장:** 시뮬레이션의 임시 기억·관계 변화는 원작·Fork 정본에 자동 반영되지 않습니다. 폐기한 실행 데이터가 다른 실행에 섞이지 않습니다(F-OPS-04).
- **업무 규칙:** 인물 에이전트에는 해당 인물이 그 시점에 아는 사실만 제공합니다(BR-02).
- **미정:** 인물 수·진행 횟수·분량 한도, 취소 방식, 부분 결과·실행 기록 보관 정책.

### UC-13 회차 발행·공개 관리

| 항목 | 내용 |
|---|---|
| 주 액터 | 작품 소유자 |
| 구분 | 핵심 |
| 관련 기능 ID | F-PUB-02, F-RGT-03 |
| 근거 | 기획서 12·18·20쪽 |

- **목표:** 검토한 회차를 허용된 범위에서 독자에게 공개합니다.
- **사전조건:** 발행할 초안과 공개 권한이 있고, Fork라면 원작의 Fork 작품 공개 조건을 충족합니다.
- **트리거:** 발행 또는 공개 상태 변경을 선택합니다.

**기본 흐름**
1. 소유자가 발행할 회차와 초안 버전을 선택합니다.
2. 시스템이 발행 미리보기와 공개 범위(무료·유료 공개 여부)를 표시합니다.
3. 시스템이 공개 권한, Fork 원작 조건, 권리 제한 여부를 확인합니다.
4. 소유자가 최종 발행을 확인합니다.
5. 시스템이 선택한 버전을 발행본으로 지정하고 독자 열람(UC-01)에 노출합니다.
6. 시스템이 실제 공개 결과를 안내합니다.

**대안 흐름**
- A1 (1단계) 비공개 유지: 초안으로만 보관합니다. 연재 작가에게 공개를 강제하지 않습니다.
- A2 (1단계) 공개 중단: 소유자가 발행 회차의 공개를 중단합니다(기존 Fork 영향은 미정).
- A3 (1단계) 발행본 수정: 새 초안 버전을 발행해 교체합니다.

**예외 흐름**
- E1 (3단계) 권한·조건 미충족: CE-02. 발행하지 않습니다.
- E2 (3단계) 권리 제한: CE-06.
- E3 (5단계) 발행 실패: 완료로 안내하지 않고 이전 발행 상태를 유지합니다.

- **성공 보장:** 발행본과 작업 중 초안이 구분되어 독자에게 발행본만 보입니다.
- **최소 보장:** 실패 시 기존 공개 상태가 바뀌지 않습니다.
- **업무 규칙:** AI 생성이나 수정 승인만으로 발행되지 않습니다. 외부 연재 플랫폼에 자동 게시하지 않습니다.
- **미정:** 유료 열람·정산, 공개 중단과 기존 Fork의 관계, 발행 후 수정 이력 노출, 예약 발행.

### UC-18 AI 자율 연재 설정·실행 · 조건부

| 항목 | 내용 |
|---|---|
| 주 액터 | 작품 소유자 |
| 보조 액터 | 외부 LLM API |
| 구분 | 조건부 |
| 관련 기능 ID | F-WRT-09, F-WRT-10 |
| 근거 | 기획서 18쪽, 그림 13 |
| 관계 | UC-17을 include |

- **목표:** 설정한 조건 안에서 AI가 다음 회차를 생성하도록 맡깁니다.
- **사전조건:** 작품 소유자, AI 처리 권한, 자율 연재 정책 확정.
- **트리거:** AI 자율 연재 설정을 선택합니다.

**기본 흐름**
1. 소유자가 연재 조건(분량, 방향, 참고할 독자 반응 범위, 사용 한도)을 설정합니다.
2. 시스템이 UC-17로 예상 비용·한도를 안내하고 동의를 받습니다.
3. 소유자가 자율 연재를 시작합니다.
4. 시스템이 세계관 설정과 허용된 독자 반응을 참고해 다음 회차 초안 생성을 AI에 요청합니다.
5. 시스템이 생성된 초안을 검토 대기 상태로 저장하고 소유자에게 알립니다.
6. 소유자가 초안을 검토하고 발행 여부를 결정합니다(UC-13).

**대안 흐름**
- A1 (3단계) 일시 중지·재개·종료: 소유자가 언제든 상태를 바꿉니다.
- A2 (6단계) 수정 후 발행: UC-10에서 수정한 뒤 발행합니다.

**예외 흐름**
- E1 (2·4단계) 한도 도달: 생성을 멈추고 안내합니다(CE-05).
- E2 (4단계) AI 실패: CE-04.

- **성공 보장:** 조건에 맞는 다음 회차 초안이 검토 대기 상태로 준비됩니다.
- **최소 보장:** 한도를 넘는 실행이나 승인 없는 공개가 일어나지 않습니다.
- **업무 규칙:** 자동 생성과 자동 발행을 구분합니다. 이 명세는 6단계에서 소유자 확인을 거치는 보수적 흐름이며, 기획서 18쪽의 "자동 연재"(무인 발행)를 허용할지는 팀 합의가 필요합니다([usecase.md 7.1절](./usecase.md#71-후속-합의가-필요한-사항)).
- **미정:** 실행 주기·트리거, 무인 발행 허용 여부, 독자 반응 반영 기준, 투표 기능, 스케줄러 도입.

## 5. 독자 피드백

### UC-14 독자 피드백 등록·처리 상태 확인

| 항목 | 내용 |
|---|---|
| 주 액터 | 독자 |
| 구분 | 핵심 |
| 관련 기능 ID | F-FBK-01, F-FBK-10, F-FBK-11 |

| 관계 | UC-01을 extend, UC-15를 include |

- **목표:** 작품에 질문·의견·오류를 전하고 실제 처리 결과를 확인합니다.
- **사전조건:** 로그인. 대상 회차를 열람할 수 있습니다.
- **트리거:** 회차 열람(UC-01) 중 피드백 작성을 선택합니다.

**기본 흐름**
1. 독자가 피드백 유형(댓글, 오류 제보, 질문, 제안)을 선택합니다.
2. 독자가 내용을 입력하고, 필요하면 문제라고 생각한 구절을 지정합니다.
3. 독자가 등록합니다.
4. 시스템이 피드백을 대상 작품·회차·구절과 연결해 저장하고 접수 결과를 안내합니다.
5. 시스템이 UC-15 분석·응대를 시작합니다.
6. 독자가 내 피드백에서 응답과 처리 상태를 확인합니다.

**대안 흐름**
- A1 (1단계) 유형 미선택: 시스템이 UC-15에서 유형을 판단합니다.
- A2 (6단계) 작가 검토 진행 중: "작가 검토 중" 상태를 표시하고 결과가 나오면 갱신합니다.

**예외 흐름**
- E1 (4단계) 접수 실패: CE-03. 접수되지 않았음을 안내합니다.
- E2 (5단계) 분석 실패: 접수는 유지하고 "처리 실패" 상태로 표시합니다(UC-21 확인 대상).

- **성공 보장:** 피드백·대상 회차·응답·처리 상태가 연결되어 독자가 확인할 수 있습니다.
- **최소 보장:** 검토 중이거나 반영에 실패한 제보를 해결 완료로 표시하지 않습니다(BR-05).
- **업무 규칙:** STORYFORK에 접수된 피드백만 다루며 외부 플랫폼 댓글을 수집하지 않습니다.
- **미정:** 피드백 공개 범위(작성자만/전체), 수정·삭제 허용, 알림 채널, 악성 피드백 신고.

### UC-15 피드백 AI 분석·맞춤형 응대

| 항목 | 내용 |
|---|---|
| 주 액터 | 독자(UC-14에 포함되어 시작) |
| 보조 액터 | 외부 LLM API |
| 처리 주체 | 플랫폼(집필 및 피드백 응대 에이전트, 세계관·설정 검토 에이전트) |
| 구분 | 핵심 |
| 관련 기능 ID | F-FBK-02~06, F-FBK-08, F-FBK-09, F-FBK-12 |
| 근거 | 기획서 7·12·19쪽, 그림 14 |
| 관계 | UC-14에 include됨, UC-16이 extend |

- **목표:** 피드백의 성격에 맞는 근거와 안내를 자동으로 제공하고, 작가 판단이 필요한 건만 작가에게 넘깁니다.
- **사전조건:** 피드백 접수 완료. 응대에 쓸 공개 원고·설정 범위가 확인되었습니다.
- **트리거:** UC-14 4단계에서 접수가 끝납니다.

**기본 흐름**
1. 시스템이 피드백의 유형과 의도를 분류합니다: 질문, 표기 오류(오타·맞춤법·명백한 숫자 표기), 설정 충돌 의심, 개인적 해석, 전개 선호. 섞여 있으면 항목별로 나눕니다.
2. 시스템이 대상 회차까지 공개된 원고·설정·사건·인물 정보만 근거 범위로 정합니다.
3. 세계관·설정 검토 에이전트가 근거 범위에서 관련 내용을 찾습니다.
4. 집필 및 피드백 응대 에이전트가 유형별 응답을 구성합니다.
   - 질문·설정 충돌 의심: 근거가 충분하면 근거 회차·구절과 함께 답합니다.
   - 표기 오류: 기준 버전, 변경 전·후, 근거를 담은 수정안(PR)을 만듭니다.
   - 해석·전개 선호: 오류로 단정하지 않고 확인 가능한 설정과 해석의 영역을 나눠 답합니다.
5. 시스템이 응답과 현재 처리 상태를 독자에게 표시합니다.

**대안 흐름**
- A1 (4단계) 근거 부족·창작 판단 필요: 단정하지 않고 한계를 안내한 뒤 UC-16 작가 검토 요청으로 넘깁니다.
- A2 (4단계) 수정안 생성: UC-16으로 넘기고 독자에게 "수정 검토 중"을 표시합니다.
- A3 (4단계) 독립 창작 의도: 다른 전개를 직접 쓰려는 의도가 보이고 Fork가 허용되면 UC-08·UC-09를 선택적으로 안내합니다.

**예외 흐름**
- E1 (1~4단계) AI 실패: CE-04. "처리 실패"로 표시하며 허구의 인용이나 정상 응답으로 대체하지 않습니다. UC-21 확인 대상이 됩니다.
- E2 (3단계) 근거를 찾을 수 없음: 그 한계를 표시합니다.

- **성공 보장:** 유형에 맞는 응답이 근거와 함께 제공되고, 필요한 건만 작가 검토로 넘어갑니다.
- **최소 보장:** 작가 비공개 설정·비공개 후속 회차가 응답에 노출되지 않습니다(BR-02). AI 응답이 원작 변경이나 작가 승인을 대신하지 않습니다.
- **업무 규칙:** 독자 의견을 무조건 옳거나 그르다고 판정하지 않습니다. 근거가 부족한 오류 제보를 자동 승인 경로로 보내지 않습니다. 운영자는 개별 응대 내용을 작성하지 않습니다.
- **미정:** 공개 후속 회차의 스포일러 허용 범위, 답변 공개 수준, 분류 방식(외부 LLM 또는 자체 분류 모델), 신뢰도 표시 여부, 응대 비용 부담 주체.

### UC-16 작가 검토 요청·수정안 승인·반영

| 항목 | 내용 |
|---|---|
| 주 액터 | 작품 소유자 |
| 구분 | 핵심 |
| 관련 기능 ID | F-FBK-06~08, F-FBK-10, F-WRT-11 |
| 근거 | 기획서 7·19쪽, 그림 14 |
| 관계 | UC-15를 extend |

- **목표:** 수정안과 작가 판단이 필요한 피드백을 검토하고 처리 방향을 정합니다.
- **사전조건:** 대상 작품의 승인 권한. UC-15에서 넘어온 수정안 또는 검토 요청이 있습니다.
- **트리거:** 소유자가 검토 대기 목록에서 항목을 엽니다.

**기본 흐름 (수정안)**
1. 시스템이 검토 대기 목록을 유형별로 표시합니다.
2. 소유자가 수정안을 엽니다.
3. 시스템이 원문, 변경 전·후, 제보 내용, 근거를 나란히 보여 줍니다.

5. 승인한 경우 시스템이 권한과 대상 원고의 기준 버전을 다시 확인합니다.
6. 시스템이 승인 범위의 변경만 원고에 반영하고 새 버전으로 기록합니다.
7. 대상이 발행본이면 시스템이 발행본 반영 결과를 확인합니다.
8. 시스템이 독자에게 승인 여부와 실제 반영 상태를 구분해 안내합니다.

**대안 흐름**
- A1 (2단계) 작가 검토 요청: 근거 부족·창작 판단이 필요한 피드백을 열어 답변을 작성하거나, 보류·종료합니다. 결과는 UC-14 상태에 반영됩니다.
- A2 (4단계) 거절: 사유(선택 입력)와 함께 거절 상태로 기록합니다.
- A3 (4단계) 직접 수정: 수정안 대신 UC-10에서 직접 고칩니다.

**예외 흐름**
- E1 (5단계) 기준 버전 변경: CE-07. 이전 버전 기준 수정안을 그대로 적용하지 않고 재검토로 돌립니다.
- E2 (6~7단계) 반영 실패: "승인됨, 반영 실패"로 표시하며 반영 완료로 안내하지 않습니다.
- E3 (2단계) 권한 없음: CE-02. Fork 소유자는 자신의 Fork 항목만 처리합니다.

- **성공 보장:** 승인 주체·결정·실제 변경 결과가 구분되어 기록됩니다.
- **최소 보장:** 승인되지 않은 수정은 원고에 반영되지 않습니다.
- **업무 규칙:** 원작 수정이 기존 Fork의 고정 기준에 반영되지 않습니다(BR-04).
- **미정:** 보완된 수정안의 재승인 절차, 발행본 반영 시점, 세부 상태명, 검토 대기 알림.

## 6. 비용·저장

### UC-17 AI 이용 비용·한도 확인

| 항목 | 내용 |
|---|---|
| 주 액터 | 창작자 |
| 구분 | 지원 · 금액 정책 미정 |
| 관련 기능 ID | 없음 (요구사항 공백) |
| 근거 | 기획서 20~21쪽 |
| 관계 | UC-04, UC-09, UC-11, UC-12, UC-18에 include됨 |

- **목표:** AI 실행 전에 필요한 비용·한도를 확인하고 실행 여부를 고릅니다.
- **사전조건:** 로그인. AI 작업 요청이 있거나 이용 현황 조회를 선택했습니다.
- **트리거:** AI 작업 실행을 요청하거나 크레딧 현황을 엽니다.

**기본 흐름**
1. 시스템이 요청한 작업의 범위(작업 유형, 인물 수, 진행 횟수, 생성 분량)를 정리합니다.
2. 시스템이 필요한 크레딧과 현재 잔여 크레딧·한도를 표시합니다.
3. 창작자가 실행에 동의합니다.
4. 시스템이 기반 유스케이스의 AI 작업을 진행합니다.
5. 작업이 끝나면 시스템이 실제 사용량과 결과 상태를 기록합니다.

**대안 흐름**
- A1 (3단계) 범위 조정: 인물 수·분량 등을 줄여 1단계로 돌아갑니다.
- A2 (1단계) 현황 조회: 사용 내역과 잔여 크레딧만 확인합니다.

**예외 흐름**
- E1 (2단계) 크레딧·한도 부족: 실행하지 않고 안내합니다.
- E2 (4단계) 서비스 오류로 미완료: 성공과 구분하고 재처리 또는 크레딧 복구 기준에 따라 처리합니다.

- **성공 보장:** 동의한 범위 안에서만 AI가 실행되고 사용량이 기록됩니다.
- **최소 보장:** 동의 없는 차감이 없습니다.
- **업무 규칙:** Fork 생성·직접 집필은 무료 방향입니다. 작품 구매는 AI 무제한 이용권이 아닙니다. 재생성·재시뮬레이션은 별도 사용입니다.
- **미정:** 가격, 무료 제공량, 차감 시점(선차감·후정산), 오류 복구, 충전·결제, 보상 크레딧 구분, UC-04·UC-15 비용 부담 주체.

|---|---|
| 주 액터 | 창작자 |
| 구분 | 조건부 |
| 관련 기능 ID | 없음 (요구사항 공백) |
| 근거 | 기획서 20~21쪽 |

- **목표:** 저장 한도와 사용량을 확인하고 공간 관리 방법을 고릅니다.
- **사전조건:** 로그인.
- **트리거:** 저장 공간 화면을 열거나 한도 도달 안내를 받습니다.

**기본 흐름**
1. 시스템이 기본 용량, 현재 사용량, 항목별 사용량을 표시합니다.
2. 한도에 가까우면 시스템이 사전 안내합니다.
3. 창작자가 정리 또는 확장을 선택합니다.
4. 정리를 선택하면 창작자가 삭제할 항목을 고르고 시스템이 삭제 전 확인을 받은 뒤 처리합니다.
5. 시스템이 처리 결과와 변경된 사용량을 표시합니다.

**대안 흐름**
- A1 (3단계) 확장: 확장 옵션을 안내하고, 결제 정책이 확정된 뒤 처리합니다.

**예외 흐름**
- E1 (4단계) 삭제 실패: 삭제 완료로 표시하지 않습니다.
- E2 (A1) 확장 결제 실패: 용량이 늘어난 것으로 안내하지 않습니다.
- E3 (2단계) 한도 초과: 새 저장을 제한하되 기존 작품을 자동 삭제하지 않습니다(BR-06).

- **성공 보장:** 창작자가 선택한 방식으로 공간이 정리되거나 확장됩니다.
- **최소 보장:** 확인 없는 삭제가 없습니다.
- **미정:** 용량·계산 단위, 확장 요금, 삭제 보관·복원, 결제 방식.

## 7. 운영

### UC-20 권리 침해 신고·이용 제한·소명

| 항목 | 내용 |
|---|---|
| 주 액터 | 권리 신고자·소명자, 플랫폼 운영자 |
| 구분 | 지원 · 절차 미정 |
| 관련 기능 ID | 없음 (요구사항 공백, F-RGT-01~05와 관련) |
| 근거 | 기획서 20·22쪽 |

- **목표:** 권리 문제를 접수하고 적법한 절차에 따라 공개·이용을 처리합니다.
- **사전조건:** 신고자가 대상 콘텐츠와 근거를 제시할 수 있습니다. 처리자는 운영자 권한을 가집니다.
- **트리거:** 권리 침해 신고를 접수합니다.

**기본 흐름**
1. 신고자가 대상 작품·회차와 침해 근거, 연락처를 제출합니다.
2. 시스템이 접수 번호와 접수 결과를 안내합니다.
3. 운영자가 신고 내용과 근거를 검토합니다.
4. 운영자가 필요한 범위의 조치(공개 중단, AI 처리 제한, Fork 생성 제한)를 결정합니다.
5. 시스템이 조치를 적용하고 작품 소유자와 신고자에게 결과를 알립니다.
6. 작품 소유자가 소명 자료를 제출합니다.
7. 운영자가 소명을 검토하고 제한 유지 또는 재개를 결정합니다.
8. 시스템이 결정을 적용하고 관련자에게 실제 상태를 안내합니다.

**대안 흐름**
- A1 (3단계) 근거 불충분: 추가 자료를 요청하거나 조치 없이 종결합니다.
- A2 (6단계) 소명 없음: 기한(미정) 이후 제한을 유지합니다.

**예외 흐름**
- E1 (5·8단계) 조치 적용 실패: 적용되지 않았음을 표시하고 재처리 대상으로 남깁니다.

- **성공 보장:** 신고·조치·소명·결정이 기록되고 콘텐츠에 실제 상태가 적용됩니다.
- **최소 보장:** 신고만으로 원고를 삭제하지 않습니다. AI가 법적 결론을 내리지 않습니다.
- **미정:** 접수 자격(비회원 포함 여부), 증빙 기준, 처리 기한, 제한 범위, 소명·재개 기준, 기존 Fork에 대한 영향.

### UC-21 운영 처리 상태 확인

| 항목 | 내용 |
|---|---|
| 주 액터 | 플랫폼 운영자 |
| 구분 | 지원 · 상세 미정 |
| 관련 기능 ID | F-OPS-05 |
| 근거 | 기획서 13쪽 |

- **목표:** 자동 처리가 끝나지 않은 건과 신고 처리 현황을 확인하고 필요한 후속 처리로 연결합니다.
- **사전조건:** 운영자 권한.
- **트리거:** 운영 현황 화면을 엽니다.

**기본 흐름**
1. 시스템이 처리 상태별 건수(AI 처리 실패, 장기 미처리, 권리 신고 대기)를 표시합니다.
2. 운영자가 목록에서 건을 선택합니다.
3. 시스템이 처리 이력과 실패 사유를 표시합니다. 원고 내용은 처리에 필요한 범위만 보여 줍니다.
4. 운영자가 후속 처리를 고릅니다: AI 재처리 요청, 작품 소유자에게 검토 요청, UC-20 처리로 이동.
5. 시스템이 후속 처리를 실행하고 결과 상태를 기록합니다.

**예외 흐름**
- E1 (5단계) 재처리 실패: 실패 상태를 유지하고 이력을 남깁니다.

- **성공 보장:** 미처리·실패 건이 확인되어 적절한 처리 경로로 넘어갑니다.
- **최소 보장:** 운영자가 실패를 성공으로 바꾸거나 정본·피드백 응답을 직접 작성·수정하지 않습니다.
- **미정:** 운영자 세부 역할, 조회 항목, 장기 미처리 기준 시간, 재처리 권한, 운영 화면.
