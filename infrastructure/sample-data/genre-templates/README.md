# 장르별 독립 샘플 패키지

## 이 템플릿의 목적

처음부터 이야기를 만들기 막막할 때 참고하는 **자유롭게 수정·삭제하는 예시용 디폴트 템플릿**입니다. 장르에서 익숙한 클리셰와 주인공·배경·세계관·도입 장면을 통해 “대략 이런 재료로 이렇게 시작할 수 있다”를 보여줍니다. 완성된 작품이나 반드시 지켜야 할 장르 규칙이 아닙니다.

이름, 관계, 능력, 배경, 갈등과 결말을 자유롭게 바꾸고 필요 없는 항목은 삭제하세요. 설정집 안의 “규칙”이나 “제약”도 예시 작품을 위한 제안이며, 사용자가 자기 이야기에 맞게 수정할 수 있습니다. 모든 설정을 채우거나 예시 원고를 이어 써야 하는 것은 아닙니다.

## 기본 템플릿·확장 설정·도입 예시

| 구분 | 역할 | 사용하는 방법 |
|---|---|---|
| 기본 템플릿 | 주인공·배경·핵심 갈등 등 이야기의 뼈대를 보여 주는 시작안 | 마음에 드는 요소부터 선택해 수정합니다. |
| 확장 설정 | 인물·세력·능력·장소 등 이야기를 구체화하는 참고 재료 | 필요한 항목만 골라 추가합니다. 전부 채택할 필요는 없습니다. |
| 도입 예시 | 설정을 첫 장면과 문장으로 옮기는 방법을 보여 주는 예시 | 문체와 전개를 참고하거나 고쳐 씁니다. 새 장면으로 시작해도 됩니다. |

기본형과 확장형은 함께 참고하는 예시이며 세부 내용이 다를 수 있습니다. 확장형이 자동으로 정답이 되는 것은 아닙니다. 실제 작품에는 사용할 내용을 골라 하나의 일관된 설정으로 정리하세요. 도입 예시 역시 사용자가 채택하기 전에는 실제 작품에서 이미 일어난 사건으로 취급하지 않습니다.

[서비스 표시용 안내 문구와 자료 구분](./TEMPLATE_GUIDE.md)을 함께 제공합니다. 이 문서는 안내 문구 제안이며, 실제 화면 연결은 별도입니다.

**장르를 하나 선택한 뒤 그 하위 디렉터리의 CSV/SQL만 사용합니다. 장르의 설정을 하나의 작품 또는 세계관으로 병합하지 않습니다.**

루트에는 일괄 적재용 core/content/sql을 두지 않습니다. 기존 일괄 준비본은 이 디렉터리에서 제외했습니다. 각 하위 폴더는 기존 sample-data 스키마와 호환되는 CSV 32개, 단일 작품·세계관, 비공개 설정, 미발행 1화와 원문을 포함합니다.

샘플 소유 계정만 공통이며 작품·세계관·설정·회차는 장르별로 별도 ID를 가집니다. 작품·세계관 ID와 원문을 유지하며, 서비스가 계산하는 회차·설정·태그 ID는 실제 계산 규칙에 맞췄습니다. 변경 전후 ID는 각 source-inventory.json의 id_corrections에 기록했습니다. 공통 안내는 이야기 설정으로 적재하지 않습니다.

## 적용 경계

부모 sample-data/load.py를 그대로 실행하면 기존 샘플 migration을 대상으로 하므로 사용하지 않습니다. 선택한 장르의 `sql/core.sql`과 `sql/content.sql`만 검토해 서비스별 새 migration으로 적용하는 별도 작업이 필요합니다. 이 준비 작업에서는 실제 DB·기존 migration·공개 화면을 변경하지 않았습니다.

다른 장르를 선택할 때 기존 작품의 world_id에 내용을 덧붙이지 말고 그 장르 고유의 work_id/world_id를 유지하세요. LLM 입력에도 선택한 장르의 문서만 전달하세요.

## 저장 흐름과 SQL 재생성

[저장 흐름 검증 및 한계](./SAVE_FLOW.md)를 확인하세요. 추가된 episode_draft를 지원하는 이 폴더의 load.py를 사용합니다. 예: `python load.py wuxia`. 지정한 장르의 준비 SQL만 갱신하며 DB나 migration에는 접근하지 않습니다. 부모 loader는 테이블 31개만 허용하므로 이 32개 패키지에 직접 사용하지 않습니다.

검증 재실행: `python -B test_saved_flow.py -v` (오프라인 단위 검증).

## 원문 보존과 CI 공백 검사

원문의 Markdown 줄바꿈용 끝 공백과 마지막 빈 줄은 그대로 보존합니다.
루트 `.gitattributes`는 장르별 `source/original.md`에만 줄 끝 공백·마지막 빈 줄 검사 예외를,
원문을 담은 `setting_version.csv`, `episode_version.csv`, `episode_draft.csv`, `work.csv`, `sql/content.sql`에는
줄 끝 공백 검사 예외만 적용합니다. 로더·테스트·안내 문서와 그 외 파일의 공백 검사는 유지합니다.
CI의 `git diff --check` 자체와 테스트 선택·실행 규칙은 변경하지 않습니다.
원문·콘텐츠 CSV·SQL에는 `-text`를 적용해 Windows 체크아웃에서도 Git이 줄바꿈 바이트를 변환하지 않도록 합니다.
원문 비교 테스트는 JSON의 CRLF와 Git에 저장된 원문의 LF만 동일하게 취급하며, 본문·끝 공백·빈 줄은 비교합니다.
