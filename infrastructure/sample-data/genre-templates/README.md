# 장르별 독립 샘플 패키지

## 이 템플릿의 목적

처음부터 이야기를 만들기 막막할 때 참고하는 **자유롭게 수정·삭제하는 예시용 디폴트 템플릿**입니다. 장르에서 익숙한 클리셰와 주인공·배경·세계관·도입 장면을 통해 “대략 이런 재료로 이렇게 시작할 수 있다”를 보여줍니다. 완성된 작품이나 반드시 지켜야 할 장르 규칙이 아닙니다.

이름, 관계, 능력, 배경, 갈등과 결말을 자유롭게 바꾸고 필요 없는 항목은 삭제하세요. 설정집 안의 “규칙”이나 “제약”도 예시 작품을 위한 제안이며, 사용자가 자기 이야기에 맞게 수정할 수 있습니다. 모든 설정을 채우거나 예시 원고를 이어 써야 하는 것은 아닙니다.

## 기본 템플릿·확장 설정·도입 예시

| 구분 | 역할 | 사용하는 방법 |
|---|---|---|
| 기본 템플릿 | 주인공·배경·핵심 갈등 등 이야기의 뼈대를 보여 주는 시작안 | 마음에 드는 요소부터 선택해 수정합니다. |
| 확장 설정 | 인물·세력·능력·장소 등 이야기를 구체화하는 참고 재료 | 필요한 항목만 골라 추가합니다. 전부 채택할 필요는 없습니다. |
| 도입 예시 | 설정을 첫 장면과 문장으로 옮기는 방법을 보여 주는 예시 | 문체와 전개를 참고하거나 고쳐 씁니다. 새 장면으로 시작해도 됩니다. |

기본형과 확장형은 함께 참고하는 예시이며 세부 내용이 다를 수 있습니다. 확장형이 자동으로 정답이 되는 것은 아닙니다. 실제 작품에는 사용할 내용을 골라 하나의 일관된 설정으로 정리하세요. 도입 예시 역시 사용자가 채택하기 전에는 실제 작품에서 이미 일어난 사건으로 취급하지 않습니다.

[서비스 표시용 안내 문구와 자료 구분](./TEMPLATE_GUIDE.md)을 함께 제공합니다. 이 문서는 안내 문구 제안이며, 실제 화면 연결은 별도입니다.

**장르를 하나 선택한 뒤 그 하위 디렉터리의 마이그레이션만 선택합니다. 장르의 설정을 하나의 작품 또는 세계관으로 병합하지 않습니다.**

공통 migrations 폴더에는 계정·카테고리만 두고, 장르별 콘텐츠는 각 하위 폴더에 분리합니다. 각 하위 폴더는 기존 sample-data 스키마와 호환되는 CSV 32개, 단일 작품·세계관, 비공개 설정, 미발행 1화와 원문을 포함합니다.

샘플 소유 계정만 공통이며 작품·세계관·설정·회차는 장르별로 별도 ID를 가집니다. 작품·세계관 ID와 원문을 유지하며, 서비스가 계산하는 회차·설정·태그 ID는 실제 계산 규칙에 맞췄습니다. 변경 전후 ID는 각 source-inventory.json의 id_corrections에 기록했습니다. 공통 안내는 이야기 설정으로 적재하지 않습니다.

## Flyway 마이그레이션

Python 로더 대신 Flyway 규격 `V<버전>__<설명>.sql`을 적용 입력으로 사용합니다. [적용 순서](./FLYWAY.md)에서 공통 마이그레이션과 선택한 장르의 경로를 확인하세요. CSV는 내용 확인용 스냅샷이며 Python 실행은 필요 없습니다.

기존 적용 마이그레이션은 수정하지 않습니다. 패키지 SQL은 선택 적용용이며 서비스 시작 시 11개 장르를 자동으로 일괄 적재하도록 등록하지 않았습니다. 실제 사용자 소유권·템플릿 선택 화면 연결은 별도입니다.

## 설정 카테고리

모든 항목을 규칙으로 넣던 방식을 없애고 인물·장소·규칙·상태·지식·관계로 분류했습니다. 사건·조직·전개안처럼 기존 카테고리가 없는 항목과 복합 보관 자료는 기타입니다. 기존 광물 카테고리도 유지하지만 해당 내용의 독립 항목이 없으면 억지로 배정하지 않습니다.

[분류 기준과 장르별 건수](./CATEGORY_MAPPING.md), 각 장르의 category-mapping.json에서 전체 대응표를 확인할 수 있습니다. 원문과 장르별 독립 구조는 유지합니다.

## 검증 및 원문 보존

저장 계약은 [SAVE_FLOW.md](./SAVE_FLOW.md), 검증 결과는 validation.json에 기록합니다. 실제 DB·Flyway·브라우저 실행 검증은 포함하지 않습니다.

원문의 Markdown 줄바꿈용 끝 공백과 빈 줄을 보존합니다. .gitattributes는 원문을 포함하는 CSV·마이그레이션 SQL에만 줄바꿈 보존과 끝 공백 검사 예외를 적용합니다. 안내 문서와 일반 코드의 공백 검사는 유지합니다.
